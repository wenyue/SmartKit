# Project Skill dependency contracts

**Release: 1.2.29.** Earlier Setup allowed reference cycles to be completed through a later correction pass. Existing Skills authored from SmartKit blueprints may also retain dependencies outside the current permitted scope, direct access to SmartKit-private resources, or instructions coupled to particular callers. Those outputs need assessment against the current dependency contract; compatible content can remain unchanged.

During full setup, use [Generated Authoring](../generated-authoring.md), its qualified SmartKit provider and target-owner inputs, and [Artifact Relationships](../../../write-rules-and-skills/references/artifact-relationships.md) to assess existing blueprint-authored project Skills and their consequential direct and transitive relationships:

- Classify dependencies, opening responsibility boundaries and nonoperative mentions under the current policy. Resolve cycles by correcting responsibility allocation before writing, and establish the generation order with dependencies before their consumers. Apply that order even when older versions of later Skills already exist.
- Bring dependencies within the permitted bundled and project-provided ordinary Skill scope, and replace access to SmartKit-private resources with supported Skill entries or public interfaces. Preserve required behavior and effect boundaries; an unsupported capability or a necessary change to independently owned content requires resolution with its owner rather than silently dropping the behavior.
- Move caller-specific assumptions into caller-supplied inputs. Make required guidance reachable before the decisions that need it, and reconcile availability and failure paths with the current policy. Preserve project-specific behavior, valid additions and unrelated artifacts outside this policy's scope.

Reconcile affected project-owned consumers and references within the accepted authoring scope, preserving independently owned content under setup's ownership rules. Apply earlier selected migrations in the same full setup; this entry replaces none of them.

Completion requires a coherent, acyclic dependency plan, project Skills and their consumers aligned with the supported dependency and resource interfaces, and the writer's required checks and acceptance. Let successful full `finish`, including configuration convergence, CodeGraph readiness and session cleanup, record `setupVersion`; an independent Skill edit does not complete this migration.
