# Worktree preparation Skill and configuration backup contracts

**Release: 1.2.24.** Existing projects may still provide `worktree-environment-setup`, while `create-worktree` now discovers `prepare-worktree-environment`. Repository-mode projects may also retain versioned backup manifests or synchronization receipts that the current reader rejects.

Before starting the frozen session, inspect repository-mode state under [Project Configuration Maintenance](../../../maintain-project-config/references/maintenance.md). A source `manifest.json` containing `version`, or a target `.agents/project-config-sync.json` containing `version`, is unsupported. Earlier entries using a separate source `config.json` and `.agents/project-config-state.json` have no automatic recovery route either. Preserve source files, target contents, binding and synchronization state; report the exact incompatible paths and leave dependent setup pending. Ask the project owner to decide the replacement source, retained content and backup scope under a separately authorized recovery plan. Routine setup must not convert those records or bypass validation. Resume only after supported source and local synchronization state have been established through the maintenance contract.

Run full setup once with this release or later, applying earlier selected migrations in the same session. Migrate the existing project's `.agents/skills/worktree-environment-setup/` directory to `.agents/skills/prepare-worktree-environment/`, carrying its Skill entry, scripts, references, metadata and assets. Set `name: prepare-worktree-environment` and update discovery metadata, project-owned invocations, links and script-path references to the new identity while preserving unrelated metadata and project-specific preparation behavior. Reconcile the migrated Skill with the current blueprint; create it at the new path when no former Skill exists. For generated content, hand off the new output paths and let setup retire only old outputs recorded in `.agents/smartkit.lock.json`. Include necessary moves and deletions of unrecorded project-owned content in the accepted authoring scope, preserving its content; missing authority or destination conflicts leave migration incomplete.

Completion requires the new project Skill to be discoverable, preservation of the project's preparation behavior, no active old-name Skill entry or invocation references, retirement of recorded old outputs, and configuration convergence with verified CodeGraph readiness. Let successful full `finish`, including session cleanup, record `setupVersion`; copied or manually edited markers do not establish completion.
