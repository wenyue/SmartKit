# Consolidate project rules without losing project policy

**Release: 1.2.30.** The default blueprint set now produces `.agents/rules/constraints.md`, `.agents/skills/prepare-worktree-environment/` and `.agents/skills/change-set-verification/`. The separate Tools, Contracts and Structure Rule blueprints are retired. Their project-specific obligations must survive consolidation; the two execution Skills retain their responsibilities and supported project additions.

During full setup, use [Generated Authoring](../generated-authoring.md) and the [Constraints blueprint](../../../../setup-assets/blueprints/rules/constraints.md):

- Identify the old Rule outputs from the `blueprint-project-tools`, `blueprint-project-contracts` and `blueprint-project-structure` records in `.agents/smartkit.lock.json`. Read every recorded output at its actual path, including historical numbered names, alongside existing project policy and the current evidence. A missing output needs a supported disposition, such as an evidenced intentional removal; unresolved lost meaning prevents retirement.
- Record the old outputs, their evidence and the disposition of their obligations in the common plan. Supply the complete old content to each affected writer as migration evidence alongside its normal blueprint inputs; the current blueprint request alone does not include removed blueprints. Carry valid project-specific constraints, exceptions and required loading triggers into the new Rule or an existing reachable owner. Remove repeated shared guidance and leave execution procedures with their owning Skills. Preserve the conditions under which policy applies; a shorter file is not evidence that those obligations survived.
- Preserve independently owned Rules, specialized `rule-*` Skills, scripts, supporting files and ADRs. A filename resembling a retired output grants no removal authority. If `.agents/rules/constraints.md` already exists, reconcile its ownership and complete content through the existing collision and authoring routes before replacement. Required changes outside the frozen generation requests need their owner's accepted correction before registration.
- Reconcile affected links and loading routes against the final set. For this migration's final mapped-link check, add each recorded old output not retained in that set as an absent `--context-path` beneath `GENERATED`, unless the path is already in the union of frozen Candidate paths. This prevents links from passing by resolving a file still present in the live target but due for removal; it grants no writer permission to change that file. Let full setup retire only its recorded outputs and update generated indexes and adapters. Keep the old files available through authoring and validation; do not delete them manually to make the new catalog appear converged.

Retain the project's maintenance mode, source binding and startup preference. In repository mode, use the selected configuration source and business-project evidence through the existing maintenance and setup routes. Consolidation introduces no separate synchronization mechanism.

OpenWiki can supply optional navigation and explanations, verified against the owning sources. Wiki generation is a separate task; this migration neither requires a Wiki nor moves operative policy or accepted decisions into generated Wiki prose.

Apply earlier selected migrations in the same full setup, preserving their still-applicable requirements at the current owners. Historical references to the three retired Rules do not require recreating those files. On repeated setup, retain the complete current content when its meaning and evidence remain sound.

Completion requires the new Rule and both execution Skills to satisfy their writer acceptance, every retired-output disposition and affected reference to be resolved, and independent project content to remain preserved. Successful full `finish`, including configuration convergence, CodeGraph readiness and session cleanup, records `setupVersion`; authoring or Rule-index synchronization alone does not complete this migration.
