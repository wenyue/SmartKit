# Preparation triggers and fixed Skill metadata

**Release: 1.2.25.** Existing generated preparation and verification Skills and the Tools Rule may request preparation solely because work is in a linked worktree or cached preparation evidence is invalid. The two Skills may also lack or differ from the descriptions, interface fields and icons now fixed by their blueprints.

During full setup, reconcile existing content through [Generated Authoring](../generated-authoring.md), using the complete [preparation](../../../../setup-assets/blueprints/skills/prepare-worktree-environment/SKILL.md) and [verification](../../../../setup-assets/blueprints/skills/change-set-verification/SKILL.md) blueprint directories and the [Tools blueprint](../../../../setup-assets/blueprints/rules/tools.md):

- Align `.agents/skills/prepare-worktree-environment/`, `.agents/skills/change-set-verification/` and `.agents/rules/tools.md` around three preparation triggers: first use of a newly created linked worktree, evidence of a missing or stale environment prerequisite for the current task, or an explicit user preparation request. Ordinary implementation and checks use the existing environment when prerequisites are satisfied. A linked-worktree location or invalid cached record alone is insufficient; cache validity governs evidence reuse within an otherwise warranted invocation.
- For both Skills, supply each blueprint's `fixed-content.json` and source files to the public writer. Copy its `description` unchanged, adopt the six declared `interface` fields in `agents/openai.yaml`, and copy the declared icon bytes to `assets/icon.svg`. Preserve independent metadata, project-specific behavior and valid additions; keep applicable project details in the body or supporting resources. Include the interface file, icon and retained support in each complete writer handoff.

Apply the current blueprints' target-Skill acceptance through the writer, including their requirements for changed preparation scripts and reuse of still-applicable evidence. Updating metadata does not itself trigger environment preparation or authorize its effects. The same blueprints and writer remain independently usable outside Setup.

Completion requires agreement across the three artifacts, passing fixed-content checks for both Skills and their required acceptance. Let successful full `finish`, including configuration convergence, CodeGraph readiness and session cleanup, record `setupVersion`; an independent authoring result does not complete the project migration.
