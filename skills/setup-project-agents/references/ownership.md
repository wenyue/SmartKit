# Ownership

Read this before full setup, backup restoration or either local synchronization operation. The catalog and project schema define supported inputs; recorded ownership determines which existing surfaces setup rendering can replace or retire. Preserve independently owned content even when it occupies a nearby path. Restoration follows the maintenance owner's accepted backup scope instead of rendering ownership.

## Establish project inputs

The shipped catalog enables Codex, Cursor, Copilot and Qoder. It installs declared shared Rules and Skills, Codex Plugin Agent defaults and every catalog-declared project blueprint. Optional project configuration adds external Skills, project Agents, MCP servers and supported project-level host settings.

When `.agents/config.json` exists or accepted intent needs non-default inputs, reconcile or create that project-owned file before `start` using the loaded plugin's schema: `<skill-root>/../../setup-assets/catalog/project-config.schema.json`. Absence means shipped defaults; a missing `maintenance` choice remains readable and is resolved during explicit full setup. The same schema governs local synchronization and defines external Skill sources, project Agent mappings, MCP declarations and supported host settings. Settings currently address structured fields in `.codex/config.toml` and `.cursor/cli.json`; their renderer preserves undeclared fields.

The target's `maintenance` declaration selects Project shared (`local`), This machine only (`local-only`), or Separate configuration repository (`repository`). Both local modes keep existing project canonical inputs. Repository mode selects one personal private GitHub repository, branch and entry for its declared complete-file backup. Read [Project Configuration Maintenance](../../maintain-project-config/references/maintenance.md) before binding or working with a repository source. That reference owns backup scope, legacy entry behavior, restoration, local synchronization and publication, including their state and Git exclusion contracts; setup consumes its supported commands and engine without invoking the user-only Skill. Use the business project's evidence while editing a repository source, then apply it through the supported route.

Full-file restoration and setup rendering are separate operations. The backup may preserve complete native configuration, selected generated files and `AGENTS.md`, including its generated section, under the maintenance reference's scope rules. Restoration does not use lock ownership to filter those files or regenerate their content. The target-local synchronization receipt remains outside the backup. A restored `.agents/config.json` may contain binding and `setupVersion`; copied records establish neither successful setup nor runtime readiness for this checkout.

The user explicitly selects initialization/upgrade or restoration through Setup. Restoration uses only the shared maintenance contract and the restored configuration's local prerequisite checks; it does not enter the full-session, migration or authoring lifecycle. Session hooks perform no missing-configuration discovery or restoration inquiry. Repository startup synchronization requires an existing valid binding and explicit local opt-in; absent preference means off, while ordinary upgrades preserve a recorded preference.

`setupVersion` is the last successful full setup's SmartKit release, not the currently installed plugin version or a record of this user's runtime state. The public workflow writes this one field only after CodeGraph readiness, configuration convergence and private-session cleanup. Preparation, failure and local synchronization leave the prior value intact. Preserve the other project configuration values; never advance the field by hand to silence a hook. Session hooks use the project setup record to require a fresh local CodeGraph check, rather than treating this durable version as proof that a runtime is still ready.

For full setup, `start` validates input against its selected canonical or installed-fallback source before freezing the request. If that source rejects input prepared under the loaded schema, follow [Preflight](session-protocol.md#preflight): correct the reported cause within accepted authority and start a fresh invocation. The returned source and request stay immutable.

Project Rule and Skill contents under `.agents/rules/` and `.agents/skills/`, including generated sources and their supporting files, belong to the project. In either local mode they can be edited there between sessions; in repository mode edit the declared source copies and apply them back. Setup discovers and preserves additional project-owned Rules and Skills. Project Agent sources follow the same selected authoring location. A target edit does not update its backup automatically; adopt an accepted edit before a later restoration overwrites local differences within the declared scope. Codex Plugin Agent defaults are fallbacks, not project Agent declarations. Native Cursor, Copilot and Qoder Plugin Agents, and native plugin Rules, Skills and MCP, remain outside setup rendering even when selected for full-file backup.

Project custom Agents discovered in native host directories must be reconciled during full setup, including undeclared ones. The `native_source` harness branch preserves a complete native document under `.agents/agents/` and copies it verbatim to its adapter; that source alone owns its prompt and settings. It is exclusive with structured settings for that harness. A shared prompt `source` is required only for harnesses using the structured branch. Existing recorded plugin defaults retain their owner. The adoption helper's guarded import preserves independent canonical content and existing adapter digest protection; it does not authorize rewriting an ownership record. In repository mode, it saves accepted source and configuration changes to the entry before its guarded target transaction under the maintenance reference's backup contract, retaining source evidence when target recovery is needed.

## Preserve the policy's loading meaning

Every direct `.agents/rules/*.md` file is an unconditional required Rule. Numeric filename prefixes carry no category or precedence. The owned `AGENTS.md` section lists all discovered paths in one required list.

Conditional policy belongs in a native `.agents/skills/rule-<domain>/SKILL.md`. Its frontmatter name matches its folder, and its nonempty model-facing description supports discovery. Ordinary project Skills keep their existing discovery behavior. Harness-native plugin Rules retain their own loading policy.

Full setup and both local operations refuse explicit legacy conditional Rule declarations, including old conditional index rows. Before retrying, separately authorize the source migration to rule-led Skills and the update or removal of legacy `AGENTS.md` declarations. Setup does not silently change when policy loads. Fenced examples are not operative index rows.

## Distinguish reauthoring from recorded retirement

For each generated Rule or Skill, `.agents/smartkit.lock.json` records its blueprint fingerprint and exact output paths, including supporting files. It stores no persistent digests of their contents. Every full session requests the complete current blueprint set; use existing content and current project evidence to preserve qualified intent during assessment and any necessary revision. An unchanged complete handoff preserves exact bytes.

Blueprint removal retires its recorded outputs. A renamed catalog target retires old recorded paths and generates the current destination. A supporting output omitted from a new complete handoff is retired; unrecorded supporting files remain project-owned. Exact records bound retirement, so nearby or apparently obsolete files do not acquire removal authority by association.

The maintenance-owned project synchronization preserves generated sources and blueprint records. Full setup separately records project Agent adapters and MCP fields from shared/default ownership. Broad local sync needs that established record; an older or absent record requires full setup first. It retires only recorded project mappings on declaration deletion or rename, keeping shared/default/external assets and provenance intact. Changed external Skill declarations require full setup; a local synchronization refusal reports that prerequisite without invoking it.

Setup rendering and deliberate local synchronization retain digest protection for managed rendered, shared and external assets. Within a frozen session, setup-relevant target drift is governed by the [Full Session Protocol](session-protocol.md).

## Preserve unowned bytes and structured fields

During setup rendering and deliberate local synchronization, setup owns only files and structured fields recorded in `.agents/smartkit.lock.json`, plus one `## Project rules` section in `AGENTS.md`. A backup selection grants no additional rendering ownership. Full setup renders that section through the next level-one or level-two heading, or file end, and appends it when absent. Fenced headings do not define section boundaries. Duplicate Project rules sections, ownership conflicts or digest conflicts stop setup before replacement.

Preserve every byte outside the owned section and every undeclared file, field, directory and secret value. MCP environment fields name environment variables; URL, command, argument and override literals remain project input. An arbitrary string is not evidence of a secret. When qualified repository evidence identifies a real sensitive literal, stop before rendering and ask its project owner to replace it with supported indirection.

MCP readiness declarations are project configuration to preserve and validate. Their runtime owner executes checks. Full setup additionally prepares and verifies CodeGraph through the public `setup-codegraph` command and rechecks readiness at finish, as specified in [Full Session Protocol](session-protocol.md). That scoped preparation may install the CodeGraph package and create or update the target's local index and runtime state; preserve existing data and unrelated configuration. SmartKit's plugin MCP registry and adapters retain ownership of CodeGraph's MCP declaration. Use this preparation route instead of CodeGraph's broad host installer, which can rewrite independently owned host configuration.

Other MCP dependencies and runtime checks remain with their owners. Local synchronization performs no dependency installation or runtime preparation, and its `clean` result establishes configuration convergence only. CodeGraph databases, process state and logs are local runtime evidence, not transferable proof of readiness or project setup-version content.
