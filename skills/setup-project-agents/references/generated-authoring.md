# Generated Authoring

Use this for every full setup, before registration. Every current catalog blueprint receives a complete assessment, including artifacts whose fingerprints and outputs are unchanged. Setup owns coherence across the resulting project set; individual writer results cannot establish it.

## Plan coverage and loading

Load every requested immutable Setup Authoring Blueprint from the frozen `source_root`. Use its refresh preference and writing focus to assess complete existing content against qualified project evidence. Preserve valid intent, obligations, conditions, exceptions and additions; substantive changes need a blueprint requirement, project fact or demonstrated defect.

Plan across frozen requests, retained project Rules, relevant Skills, applicable SmartKit global Rules and discoverable rule-led Skills. For each artifact, establish purpose, neighboring boundaries, evidence and how readers reach its responsibilities:

- **Coverage:** preserve every required obligation, with its conditions and exceptions, under an artifact or established external owner reachable before the decision.
- **Responsibility:** keep operative meaning with its canonical owner. Generated and retained artifacts must agree; a blueprint requirement cannot be reassigned or omitted to simplify the set.
- **Overlap:** distinguish context useful to different decisions from duplicate definitions or incompatible directions. Resolve ownership while retaining necessary meaning.
- **Loading:** establish supported routes for unconditional Rules and conditional rule-led Skills. Check combined loading; current conversation visibility does not establish future availability.
- **Order:** identify cross-references among generated artifacts and place each referenced artifact before its referrers. For a reference cycle, defer one back-reference: accept one artifact without it, accept the other after its dependency is available, then add the deferred reference through the correction route after both are accepted.

Record the resolved allocation, generation order, refresh directions, qualified evidence and owner-dependency state in a common plan. Evidence beyond the setup fingerprint needs its source and limits. Leave each writer room to organize its Candidate within the plan and blueprint. A discovery affecting neighboring responsibilities returns to Setup; it does not widen that writer's scope.

## Prepare evidence and invoke the pinned writer

Run `workflow.py writer-inputs` as shown in the Skill entry. Read its `--help` for inputs, bundle fields, path resolution and mechanical checks. Use only a successful result.

The bundle preserves complete existing artifact bytes, including project-owned support, as evidence. Those copies neither authorize edits nor require every file to become generated output; the blueprint, ownership and writer's frozen Candidate scope determine that choice. Preparation performs no writing assessment and cannot qualify the common plan's evidence.

Invoke the public writer at `source_root/skills/write-rules-and-skills/SKILL.md` and its required same-source references, including `writing-for-agents`. Use the business-project context, the immutable blueprint as accepted task/spec input, and `GENERATED` as the request root. Repository maintenance does not replace business-project evidence with the configuration repository's own layout or conventions. Resolve complete existing content from the selected authoring source and compare its applied target evidence before freezing; preserve any unadopted target changes. Supply the common plan, complete current content, qualified ownership/loading evidence and dependency state. Ambient or target-checkout writers cannot replace this pinned route.

For each handoff, supply `GENERATED` as `<candidate-root>`, the immutable request's actual business-project target as `<target-root>`, and the exact frozen Candidate-relative path list, including deleted or absent endpoints. Supply every already accepted sibling Candidate's exact frozen paths, including deleted or absent endpoints, through the writer check's `--context-path` option. Read that check entry's `--help` for the option contract. Keep the Candidate's final target-relative layout and delegate validation in the final destination namespace to the pinned writer's supported mapped-check interface. This mapping supplies read context for validation, not permission to mutate the target.

Each request receives exactly one Candidate under the public writer's own scope, validation, review and result protocol. Run jobs in the common plan's generation order so every referrer's checks receive its already accepted generated dependencies as context. Consume only an individual `COMPLETE` whose exact Candidate paths lie beneath `GENERATED` and satisfy that blueprint, retaining required evidence in its handoff. Blueprint readiness terminology is not a substitute.

An unchanged artifact needs the same assessment and `COMPLETE`; the writer may return a verified exact copy with all supporting files that remain part of it. Matching bytes avoid target rewrites. Ownership governs retirement: omitting a recorded supporting output is not reuse.

## Reconcile before registration

Compare all generated outputs together with retained Rules and relevant Skill/global policy against the common plan. Look for lost obligations, stale evidence, conflicting owners, duplication and broken loading routes. Resolve the combined result before registering anything.

As the final reconciliation gate before registration, run the pinned writer's check entry once over every surviving generated Markdown file. Supply `GENERATED`, the business target and the union of every request's exact frozen Candidate paths, including deleted endpoints, so mapped links are checked against the complete proposed final set. A Candidate-caused failure returns to every affected writer through a fresh invocation and requires a fresh `COMPLETE`; do not repair the Candidate in place. Repeat reconciliation and this whole-set gate after corrections until it passes.

If reconciliation changes the plan, prepare a fresh input bundle and provide relevant current handoffs to the affected writers. Every correction goes through a distinct public-writer invocation with a newly frozen single-Candidate scope; obtain a fresh `COMPLETE` for every changed Candidate, including affected earlier outputs. Leave accepted Candidates unchanged behind their handoffs. Repeat until every request and current handoff agrees with the reconciled plan.

Resolve a planned reference cycle through that same correction route: after both artifacts are accepted, invoke a fresh writer for the artifact whose back-reference was deferred, supply the other artifact as accepted context, and require a fresh `COMPLETE`.

In repository mode, accepted writer outputs remain staged under `GENERATED` through review and registration. Writers author only canonical project sources within their frozen scope, leaving direct target writes, rendered adapters, delivered assets and the generated `Project rules` section to their existing owners. Finish saves accepted sources before the ordinary target apply; it also persists selected configuration results under [Project Configuration Maintenance](../../maintain-project-config/references/maintenance.md). Full-file backup selection does not enlarge writer scope or rendering ownership. This persistence belongs to setup's accepted application, not a writer's downstream permission.

Register each final request once using its ID and every output from its handoff; `register --help` supplies path syntax. Registration checks mechanical outputs and records them; it does not certify semantic coherence. Once all requests are registered, proceed to `finish`.

## Handle corrections and unavailable inputs

Plan-input errors can be corrected before registration while frozen evidence remains intact. A registration-input error may be corrected and retried only while that request is still unregistered and its claim was released. Inspect any reported claim/bundle cleanup residue before another operation. Bundles remain private session inputs until terminal cleanup.

A semantic correction discovered after registration begins requires cancellation and restart; neither modifying registered outputs nor replacing a registration is a correction route. Source or target drift follows the same frozen-session rule.

If the pinned source lacks `writer-inputs`, preserve its diagnostic, cancel and select an updated source through a fresh setup invocation. Do not mutate the frozen source or substitute an ambient implementation.

A writer `NEEDS_INPUT` or `BLOCKED`, missing required authority/dependency/access/role, or a necessary correction outside the frozen generation requests stops generation. Preserve the precise dependency and evidence, then cancel under [Stop and Recover](session-protocol.md#stop-and-recover); register no partial work. Use the public writer's owner-dependency/user-assistance route to obtain separately authorized canonical corrections, then restart from accepted inputs. Neither the pinned source nor installation caches are correction targets.

Authoring grants no downstream effect authority. Establish that separately under the session protocol, including cancellation when an authorized effect changes frozen target evidence.
