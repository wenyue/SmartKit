# Cross-Project Portability

For a cross-project Candidate, establish the shared owner, applicability, public discovery, owned
resources, hard dependencies, and supported representative contexts. Freeze the smallest portfolio
covering every evidenced seam that can materially change applicability, dependency availability,
permission, execution, or exit. Names and layout alone do not distinguish contexts.

Portable meaning may come only from accepted decisions, specifications, governing contracts,
observable shared implementation, and representative evidence whose authority is independently
established. Source-project policy, local names, incidental layout, context documents, and
source-only success contribute no portable meaning.

Declare every required Rule, Skill, tool, schema, environment capability, and host behavior with
its shared or target-owned route. Condition platform mechanics at the true boundary. Missing facts,
dependency routes, or portable authority leave alignment incomplete.

Extend Spec Fidelity and Semantic Integrity with shared ownership, applicability, dependency
closure, and source-context exclusion. Extend Critical Behavioral Integrity with representative
paths and exits. Route contexts to Acceptance when static and Machine evidence cannot establish
runtime feasibility confidently. Portability passes only with complete closure, both extended
Correctness verdicts, and every required representative Acceptance case.
