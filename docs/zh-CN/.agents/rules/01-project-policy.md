# 项目政策

**强度：** Mandatory  
**适用范围：**SmartKit 仓库的源文件修改、交付、Setup 所有权、契约退役、验证，以及 Rule/Skill 翻译。
这些约束管理仓库操作，不决定所编写的可移植制品的含义。

## 交付权威

每项生成、交付或安装的内容都有唯一的权威输入。更改这些目标时，必须修改该输入，并使用所属的生成器或同步器。
只能通过已声明的所有者和路径交付和公开这些内容；公开清单只能暴露已声明为公开的内容。
目标端的状态不得成为插件的权威来源。仅编写源文件，既不要求也不授权下游生成、交付或安装。

对 Setup 的修改必须保留
[Setup Project Agents](../../skills/setup-project-agents/SKILL.md#inputs-and-ownership)
定义的所有权和冲突处理边界。

退役当前契约时，必须同时移除其实现、文档、测试和处理逻辑。
仅当已接受的当前契约有要求时，才保留或添加兼容性支持。

## 验证

针对实际修改及受影响的集成，必须以不自动修复的模式通过所属方要求的检查，才能报告完成或成功。
审查所有生成的差异，并运行 `git diff <comparison-point> --check`。

## 翻译

更改项目自有的英文 Rule 或 Skill 后，必须使用 `smartkit:translate-agent-artifacts` 同步其简体中文文档镜像。
