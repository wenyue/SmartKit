# 项目结构

强度：`Advisory`

适用范围：基于证据的仓库变更放置排序和架构接缝判断。

`Project Contracts` 决定放置是否有效。在有效放置中，能够让一项决策贯穿其实现和观察测试的最窄既有
责任方具有最高优先级。这些建议不授予所有权、安装、交付、暴露或依赖权限。

## 证据权重

- 直接调用和导入、注册表或 schema 关系、生成器流程、运行时入口点和行为测试的权重高于目录名称、
  共置、命名和插件打包。
- 一个使用方和一个行为测试接缝倾向于本地放置。同一稳定决策存在多个独立使用方，或本地重复代码了解
  另一责任方的内部细节，说明应使用现有共享接缝。
- 只有当前已有证据支持共享决策时，新的通用接缝才有更高优先级。如果外观相似的智能体宿主或目标分支在选择
  谓词或行为上不同，则倾向于继续分离。

## 仓库接缝

- 当 Rule 注册表的解析或验证由 Hook 交付和 Cursor 适配器生成共享时，`runtime/rules/contract.py`
  的优先级高于任一使用方：`runtime/rules/dispatch.py` 和
  `scripts/sync_cursor_rule_adapters.py` 都导入它。事件选择和上下文交付倾向于 `dispatch.py`；
  Cursor frontmatter 投影倾向于同步器。
- 如果直接证据表明目标或智能体宿主谓词会选择规范意图的一种投影，那么当把决策移到上游会丢失选择行为所需的
  上下文时，应倾向于将该分支放在同步器或渲染器中。每个智能体宿主的智能体和 MCP 语法及字段投影就是当前
  示例。跨目标意图的变更应返回适用的契约责任方；相似的本地分支和生成的适配器是表示层证据，而不是共享
  上游政策接缝。
- 在项目 Setup 中，目录和项目配置的形状或选择行为倾向于 `agents_setup/catalog.py`，并由
  `setup-assets/catalog/project-config.schema.json` 佐证。目标状态投影倾向于
  `agents_setup/renderer.py`；当前状态与期望状态的比较倾向于 `agents_setup/planner.py`；文件系统
  提交和回滚行为倾向于 `agents_setup/transaction.py`。只有在行为负责协调这些阶段，而不是完全属于
  其中一个阶段时，`setup_project_agents.py` 入口点才具有更高优先级。
- 在推荐工具运行时中，实时检测和就绪性评估倾向于 `check_recommended_tools.py`，而执行和验证已批准
  的维护操作倾向于 `maintain_recommended_tools.py`。Hook 事件路由或命令表示变更倾向于其清单，
  因为清单命令会直接进入这些运行时路径。
- 行为覆盖倾向于直接导入或执行变更接缝的现有测试模块。只有当行为必须跨越注册表到生成器、入口点到
  运行时或渲染到事务的路径才能观察时，更广泛的契约测试才具有更高优先级。

命令执行、同步过程、编写工作流和机器验证要求仍由其活动责任方负责。如果仓库证据无法区分两个有效放置，
本 Rule 不作建议。
