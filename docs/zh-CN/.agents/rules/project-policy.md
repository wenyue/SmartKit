# 项目政策

## 将权威保留在规范输入处

每项生成、交付或安装的内容都有唯一的规范输入。插件的权威来源必须始终是该输入，不能是目标端状态。

更改这些内容时，必须通过其规范输入及所属的生成器或同步器进行。只能通过已声明的所有者和路径交付、公开内容。公开清单只能暴露已声明为公开的内容。

仅编写源文件，既不要求也不授权下游生成、交付或安装。

对 Setup 的修改必须保留 [Setup Project Agents](../../skills/setup-project-agents/SKILL.md) 定义的所有权和冲突处理边界。

## 完整退役契约

退役当前契约时，必须一并移除其实现、文档、测试和处理逻辑。仅当已接受的当前契约有要求时，才保留或添加兼容性支持。

## 根据读者需要维护文档

### Skill 引用

项目 Rule 通过 `SKILL.md` 入口引用 Skill，不链接其内部章节。由各 Skill 自己负责引导读者阅读其支持资料。

### 根目录 README

将 `README.md` 和 `README.zh-CN.md` 保持为内容一致、简洁且面向人类用户的插件说明。提供简短介绍和可直接执行的安装说明，包括必要的前置条件和启用步骤。

将 Skill 一览按使用方式分成三类：

1. 必须明确调用：需要用户明确指定调用的 Skill。
2. 用户可主动调用的任务 Skill：用户为具体任务选用的 Skill，Agent 也可以在适用时自动调用。
3. 一般由 Agent 自动调用：Agent 通常为支持用户工作而自行选用的 Skill。

这些分类描述通常的使用方式；实际调用限制仍以 Skill 元数据为准。

为前两类中来源为 SmartKit 的每个 Skill 设置独立章节，并按其条目在一览中的出现顺序排列。简要说明使用时机和调用方式；例子有助于理解用法时，加入一个简短例子。第三类 Skill 只保留在一览中，不设置独立章节。

内部工作原理、架构、Rule 的分发、发现和优先级、实现细节，以及面向维护者或配置的参考资料，均放在这些 README 之外。

### Rule 和 Skill 镜像

更改本仓库维护的第一方英文 Rule 或 Skill 后，无论它是公开工件还是项目本地工件，都必须使用 `smartkit:translate-agent-artifacts` 同步其简体中文文档镜像。

## 报告完成前进行验证

针对实际修改及受影响的集成，以不自动修复的模式运行所属方要求的检查。这些检查必须全部通过，才能报告完成或成功。审查所有生成的差异，并运行 `git diff <comparison-point> --check`。
