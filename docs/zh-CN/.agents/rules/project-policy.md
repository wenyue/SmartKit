# 项目策略

让权限归于规范输入，通过声明的所有者交付，并验证任务实际改变的表面。

## 修改拥有该内容的源

每个生成、交付或安装的表面都有唯一的规范输入。通过该输入及其所属生成器或同步器维护它；目标状态不能成为插件的规范权威。

仅通过声明的所有者和路径交付、暴露表面。公开清单只暴露声明为公开的表面。编写源文件本身既不要求，也不授权后续生成、交付或安装。

修改 setup 时，必须保留 [Setup Project Agents](../../skills/setup-project-agents/SKILL.md) 定义的所有权和冲突边界。

淘汰当前契约时，一并移除其实现、文档、测试和处理逻辑。仅在已接受的当前契约要求时保留或添加兼容行为。

## 通过受支持的插件路径复用资源

SmartKit Skills 可以共享自身目录之外的文档、脚本和资产，前提是这些资源已声明并打包在受支持的插件分发中。应从实际加载的 Skill 或插件安装位置解析资源，不依赖目标工作目录或编写机器。

保留每个资源的规范所有者及适用的加载和失败要求。在消费 Skill 中，或在受支持环境保证会加载的核心 Rule 中，说明何时及如何加载、使用它。一旦中央 Rule 已加载，消费者可以依赖其路径，无需重复指导或指针。受支持命令的接口和帮助也可以提供用法说明。

将任务特定的输入、输出、权限和生命周期契约留给消费 Skill。如果所需资源不可用，报告缺失的前提，并将依赖它的工作保留为未完成状态。

这种受支持路径意味着 Skill 不必能被独立复制。它允许使用已声明的插件共享资源，不允许借此访问其他 Skill 的私有资源或任意项目、外部文件。它不授予打包、发布或安装权限。

## 为文档的读者编写内容

### 通过 Skill 入口引导 Rule 读者

项目 Rules 通过 Skill 的 `SKILL.md` 引用它，不链接内部章节。Skill 负责通向其支持资料的阅读路径。

### 保持根 README 简洁且可操作

让 `README.md` 和 `README.zh-CN.md` 保持一致，作为面向人类的插件文档：简要介绍，加上可操作的安装说明，包括必要前提和激活步骤。

按以下日常用法分组组织 Skill 概览；实际调用限制仍以元数据为准：

1. 仅显式调用：要求用户主动调用的 Skills。
2. 用户可主动调用的任务：用户可为某个任务选择，Agent 也可在适用时自动选择的 Skills。
3. 一般由 Agent 自动调用：通常由 Agent 选择，用来支持用户工作的 Skills。

为前两组中的每个 SmartKit Skill 单独设节，并遵循概览顺序。说明何时及如何调用，有帮助时给出简短示例。第三组只保留在概览中，不单独设节。

内部工作方式、架构、Rule 交付、发现与优先级、实现细节，以及维护者或配置参考资料，都放在这些 README 之外。

### 同步第一方镜像

修改本仓库维护的第一方英文 Rule 或 Skill 后，无论它是公开还是项目本地内容，都使用 `smartkit:translate-agent-artifacts` 同步简体中文文档镜像。

## 验证实际改动

针对改变的表面和受影响集成，运行所有者要求的非修复模式检查。审查生成差异，并运行 `git diff <comparison-point> --check`。必要检查通过后，才能报告完成或成功。
