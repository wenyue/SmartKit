# 编写决策

## 蓝图输入保留含义，不接管编写工作流

蓝图为未来 Author 提供语义要求、有用的项目证据和已接受的固定来源。将这些输入与编写角色及结果分开，既保留公共 writer 的权威，也让同一份蓝图能够独立使用或经 Setup 使用。顺序影响行为时，未来目标的流程仍应写入蓝图；这些流程不是调度编写任务的指令。

蓝图的 `description` 直接提供目标 Skill 的描述。另设编写触发条件会给蓝图虚构一个发现角色，并迫使实际目标值使用第二个字段。

选定的元数据字符串与完整图标文件具有不同的保留边界。字段约束可以稳定发现信息，而不替换独立的项目元数据；将来源打包，使每个调用方都能取得该契约。若由 Setup 专门填充或修复，就会使独立编写不完整，并产生相互竞争的所有者。

## 区别刷新事实与持久意图

工具映射可能变错，而项目已接受流程仍然合理。统一的重写或保留规则，要么保留过时事实，要么抹掉有效决定。明确按内容选择刷新偏好，能同时保护准确性与项目所有权。

## 交接不完整仍可能允许发现

未来 Author 负责在获准访问内发现并确认可恢复的项目证据。把每项未提供事实都视为停止理由，会将有用调查变成反复询问用户；完成发现后仍无依据的重要事实，才是真正的停止条件。
