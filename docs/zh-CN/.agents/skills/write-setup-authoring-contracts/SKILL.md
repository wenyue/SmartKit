# 编写 Setup Authoring Contract

## 前沿 Agent 原则

这是一个由判断主导、面向有能力的当代前沿 Agent 的 Skill。应陈述语义权威、证据、不变量，
以及那些一旦省略就可能改变正确性、安全性、所有权、权限、外部影响、可执行性、退出或交接的边界，
而把常规发现、推理、工具选择和起草方法留给 Agent 自行决定。

首次需要构建或修订契约时，读取并应用已安装的 `writing-for-agents` Skill，以处理信息层级、
上下文指针、完成边界、就近放置和删减。

当已接受的项目意图要求在 `setup-assets/blueprints/**` 下建立契约时，当前 Agent 负责编写或修订
最小而完整的一组仅作判断的 Setup Authoring Contract。这些契约是本 Skill 唯一拥有的成果。

## 权威与所有权

从给定任务、Candidate 和证据开始。只有适用指令或具体角色需要时，才在当前确切授权范围内发现
额外材料；不要主动加载无关内容。契约含义应来自已接受的用户决定，以及当前具权威性的 Issue、
Spec、ADR、管辖契约、目标所有者证据和可观察的目标实现证据。应按语义所有者和来源评定每项资料。
现有契约是完整性和回归证据，而不是设计权威；非规范性上下文、仓库可见性、发现结果、工具可用性和
目录元数据均不授予任何含义或权限。

Setup Authoring Contract 拥有未来 Author 针对一个 Rule 或 Skill 目标必须采用的含义和证据。
`setup-project-agents` 拥有下游生成和 setup 执行。本 Skill 不拥有也不产出未来目标、共享 SmartKit
工件、setup 搜索或编排、翻译、安装、发布、commit 或 push。

只能写入 `setup-assets/blueprints/**` 下确切的预期契约路径。仅当创建、删除或移动某一契约这一
确切操作获得单独授权时，才可执行该操作；否则应在操作前停止。保留所有无关路径和由其他所有者拥有的
表面。

## 确立契约集合

确定最小完整契约集合中的确切路径。对于每个契约，依据已接受的证据确立一个 Setup Contract Frame：

- 未来目标的目标、执行者、触发条件、确切路径、Rule 或 Skill 语义类型和所有者；
- setup 必须向未来 Author 提供的相关目标仓库证据及其来源；
- 每项会改变行为的义务，并将其分类为保留、变更、新增、废止或非目标；
- 未来 Author 的确切 Candidate 和写入路径，独立的创建、删除和移动权限，其他权限、允许的外部影响，
  以及所需验证；
- 每种受支持的结果及其可观察判别条件；以及
- 每项实质性的缺失权威、无依据事实或歧义；这些情况必须导致停止，而不是虚构目标事实、所有者、
  政策、权限或操作。

当必要事实无法在获准访问范围内发现时，使用 `CONTEXT_REQUIRED`；当缺少必要访问权限时，使用
`ACCESS_REQUIRED`。这两者都是例外回退。应返回确切缺失的事实或访问权限、获准发现仍无法取得它的
原因、能够解决问题的所有者或条件，以及获准重试的条件。只有在缺失的上下文或访问权限已经解决，
并且重试权限已经确立后，才能在一次新运行中继续。对于已接受权限之外的实质性选择，使用
`HUMAN_DECISION_REQUIRED`，并说明决策所有者、当前可选项、证据和后果。只有当每项义务都有一个
已接受的值或明确的停止条件，且每项未来操作都符合其授权时，才能开始编写。

## 编写契约

将每个 Setup Contract Frame 表述为仅作判断的契约：规定所需含义、证据、决定、结果和停止条件，
但不规定 setup 如何搜索、安排工作顺序、选择工具、重试、写入或实现生成。对于过程主导型目标，
契约应要求未来目标表达受支持的过程，而不是复述 setup 的实现。

将每个触发条件、结果、判别条件和退出就近放置。让每项有效承诺与其语义所有者保持在一起。当每条
指令都会改变一种受支持的生成或停止结果，并且所有这类结果都无须虚构项目事实即可得出时，完整集合
才是最小的。

## 验证与交接

运行现有、适用且由所有者支持的确定性非修复检查；若不存在，则记录 `NOT_REQUIRED`。在获准的契约
路径内，建立静态证据，证明完整集合：

- 始终仅作判断，且处于蓝图所有权范围内；
- 覆盖每项会改变行为的义务和未来 Author 的权限；
- 使每种受支持的输入都恰好得到一种可观察的生成或停止结果；以及
- 无须任何无依据的项目事实即可得出该结果。

未解决的检查失败、所有权冲突或实质性歧义都是停止条件，而不是已完成的契约。只有当检查通过或记为
`NOT_REQUIRED`，并且静态证据成立时，工作才算完成。

返回确切的契约路径和所有者、受支持的结果、检查及其结果、保留的约束，以及不确定或未经测试的表面。
只把这些契约作为已就绪输入交接给 `setup-project-agents`；不要调用它，也不要执行任何下游影响。
