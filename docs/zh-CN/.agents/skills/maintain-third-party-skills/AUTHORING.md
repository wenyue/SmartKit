# 编写决策

## 审查整个来源的版本变化，而不只审查请求的 Skill

注册表对每个上游仓库只固定一个版本。因此，看似狭窄的选择变化可能升级该来源全部已有选择。将这一后果放在基线选择旁，可以防止单 Skill 请求隐藏未经审查的广泛更新。

## 区分机械兼容与已接受行为

更新器可以证明补丁能够应用、记录字节一致，却不能决定组合后的指令是否仍保留本地授权、恢复和消费者结果。工作流因此保留应用前语义审查和应用后完整内容验证，使补丁成功不能替代任何一项判断。

## 保留上游与补丁的所有权边界

本地适配归注册表输入和补丁，因为分发快照会重新生成。规范化和事务细节留在入口中，因为它们影响拟议补丁能否保留字节，以及怎样判断失败恢复；它们不替代更新器当前 schema。
