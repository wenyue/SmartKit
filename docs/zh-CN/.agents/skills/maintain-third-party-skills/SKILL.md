# 维护第三方 Skills

评估上游 Skills 会引导消费者做什么，确定必要本地适配，再生成并验证仓库快照。在选择改变前，保留已接受的本地行为。主动调查重要风险并推荐有依据的方向：补丁顺利应用只证明机械兼容，不证明接入合理。

本项目本地 Skill 同时支持评估和实现。评估授权调查与提案；添加或升级请求也授权已接受范围内、就绪的实现。两者都不自动授权发布或安装到用户环境。

## 确定来源和受影响范围

阅读 [Skill 注册表](../../../../../skills/registry.json) 的外部来源声明、可用 [锁定记录](../../../../../vendor/external-skills.lock.json) 和列出的补丁。选择工作区和比较点前，检查 Git 状态、已安装目标及受管理输出中的已有工作。

| 起点 | 所需基线 |
| --- | --- |
| 从新来源首次接入 | 不要求已有安装基线。确定来源身份、已审查目标提交、选定 Skills 及完整行为、许可、依赖和本地集成。 |
| 从已有来源新增 Skill | 对新增选择按首次接入审查。为已有选择保留记录的基线，并将任何版本变化作为它们的升级评估。 |
| 升级已安装 Skill | 使用锁中解析的提交作为已安装上游基线，与目标及当前本地适配比较。配置的标签或分支不代表那些字节。 |

真正的新来源或新增选择没有锁记录是正常的。已有安装内容若缺失或无法验证来源，替换前需要调查；将其称为新接入会绕过保护和基线审查。

注册表和补丁是规范输入。[更新器](../../../../../scripts/update_external_skills.py) 派生分发的 Skill 树、许可和锁记录；通过这些输入表达适配。

确定请求的来源、选择、版本和结果。通过当前上游发布及仓库内容验证目标，区分已发布版本与未发布分支工作，并记录解析后的提交。如果目标未定，推荐受支持发布或版本，说明稳定性与所需未发布工作的重大取舍。缺失或无法验证目标证据时，阻止接入，但可继续独立调查。

注册表版本和更新器的 `--source` 作用于整个上游仓库。交代版本变化影响的每个选定 Skill。新增 Skill 使用同一版本；若需要更新版本，评估所有已有选择，并在实现前解决不可避免的范围扩展。

## 找出可能改变接入决定的因素

首次接入时，阅读目标版本中完整的选定 Skills 及所属资源。追踪必需参考资料、脚本、资产和其他 Skill 依赖。区分目标所需能力与可选分支，并确定消费者如何带着前提进入各受支持分支。摘要或近期 changelog 不能证明完整引入行为。

升级时，阅读发布说明，比较所有选定 Skills 及所属资源的旧上游树和目标树。弄清每份本地补丁为何存在，以及目标是否提供等价结果。聚焦行为变化及依赖，同时保留差异外的必要保证。

两种情况都要沿受影响指令追踪本地 Rules、Skills、调用者和工具。上游内部歧义或冲突实质妨碍本地接入时才处理；无关上游功能不因存在就需要工作。

### 比较后果，而不只比较文字

对每个新选定或实质变化的 Skill，检查以下问题：

| 关注点 | 重要证据 |
| --- | --- |
| 行为与组合 | 触发、义务、停止、委派和副作用，结合适用 Rules、原生发现元数据和真实依赖阅读。 |
| 本地适配 | 接入所需最小本地差异；升级时包括每份补丁的目的及目标中的对应机制。区分上下文修补、等价上游行为和意图变化。 |
| 选择与重叠 | 能力补充、重复还是替代本地能力；新增、重命名、移动、移除和新要求对调用者、注册表、公开暴露及维护的影响。 |
| 依赖与迁移 | 约定、模板、链接、脚本、命令、工具和 Harness 能力。选定树之外的依赖需要受支持交付或访问路径；即使补丁干净应用，格式改名仍可能破坏消费者。 |
| 来源与影响 | 来源身份、许可和署名、可执行或网络行为，以及新增访问、凭据、服务、持续成本或信任要求。 |

只有适用条款在同一决定下无法同时满足时，才认定冲突。引用精确位置、条件、触发案例和后果；提出修复前先应用优先级。不同阶段的要求可以共存。Rules 和原生发现已提供路径时，没有显式 Skill 名称不证明能力缺失。区分静态解释与观察到的调用行为，披露重要不确定性。

按消费者所需结果及必要授权、验证和恢复保证判断替代方案。步骤不同本身不足以保留两个 Skills。解释覆盖、剩余缺口，以及它们是否值得小幅集成、独立能力或推迟接入。计入旧协议维护成本，不照搬目的已消失的步骤。

### 将每项适配放在所属位置

比较修改调用者或 Rule 与添加供应方补丁。合理上游设计可能只需要本地集成；只有已接受差异必须留在外部 Skill 时，才需要补丁。仅上下文修补属于现有授权。只有其已接受结果由别处提供，或移除获授权，才能淘汰补丁；让更新器通过，不足以合理化丢失该结果。

淘汰或替代时，追踪剩余引用、公开暴露、术语、协议、文档和检查。区分必要清理和可选简化。旧依赖造成周边复杂度时，推荐有界后续工作；重大扩展仍由用户选择。

每个选择和补丁都有交代、受影响消费者及依赖具有受支持路径或明确缺口、重大风险和选择已解释时，评估就绪。调查证据留在对话；注册表、锁和补丁仍是持久来源记录。

## 推荐并确定重要选择

先给出最符合目标的范围及理由。说明来源和选择，或从基线到目标的变化、收益、重大风险、消费者、补丁处置、迁移工作，以及拟议验证和恢复。优先表达可能改变选择的因素。

未解决的重要选择需要可行替代方案、取舍、建议、证据和关键假设。会推翻建议的证据若可获取，就先获取；否则指出缺口及下一步有用调查或精确用户输入。先完成可做分析，不泛泛要求用户指路。

改变已接受范围或行为前，先询问并等待，例如公开接入或淘汰、名称或激活方式、服务或权限要求，或更广的消费者迁移。复用已有决定和授权；保留已接受结果的常规修复不需要新审批。仅评估时以具体提案结束；获授权接入或升级在范围、行为、前提和检查明确后继续。

## 通过更新器实施

通过 Git 证据或隔离保留原始输入和记录输出。更新前协调受管理输出漂移：保护它、确定所有权和意图、在所属补丁中表达已接受变化，最后才恢复对应记录输出。也要检查新目标；已有目录是待协调的证据，不是覆盖许可。所有权或保护方案不清时，暂停受影响更新并请求指示。

新来源在注册表声明身份、已审查版本、许可和选择。已有来源只改变已接受的版本、选择或路径。精确字段、命名约束、受支持来源和许可形式，取自当前注册表与更新器验证。确认名称和目标可与第一方及其他外部 Skills 共存。

针对解析后的目标创建有序补丁，保留已接受差异外的上游措辞，以及全部许可和版权声明。必要的本地调用元数据和打包资产也放进补丁。获授权的公开暴露、README 覆盖和消费者变化，由仓库所有者处理，与其他外部 Skills 保持一致。淘汰契约包括受影响调用者、文档和检查。

从仓库根目录运行：

```bash
python scripts/update_external_skills.py --update --source <owner/repository>
```

使用注册表中的真实来源 ID，包括新来源；需要时查阅 `--help`。指定来源更新通过其他已配置来源的锁记录保留它们；缺少记录是前提缺口，不是扩大范围的许可。省略 `--source` 会更新全部已配置来源，只有该范围符合意图时才使用。被移除的来源 ID 不能再选中，所以移除整个来源需要规划完整更新。从保留来源移除某项选择，会删除其受管理目标。

### 遵循更新器的表示和事务机制

更新器在应用补丁前，将暂存 UTF-8 资源中不含 NUL 字节的 CRLF 规范为 LF，并在哈希前规范补丁输出。按该表示编写补丁。二进制资源和上游检出保持不变；其他空白，包括 Markdown 硬换行，仍被保留。文本许可也使用 LF。仓库 Git 属性对 Skill 树和许可禁用换行转换，使记录字节不受主机设置影响，即使不透明资源带有文本后缀也是如此。

更新器先暂存并验证补丁，再一起安装 Skills、许可和锁。补丁冲突保留已安装输出不变；此前输入修改仍需审查。重试前调查失败。事务或回滚错误需要检查实际文件和保留的 Git 证据，不能假定已恢复。

## 验证应用结果

阅读完整新增或修改 Skills 及必需资源，追踪受影响调用路径。一起核对预期补丁行为、发现、文档约定和依赖。新增或修改可执行行为时，运行相关受支持检查；文字一致不证明运行时行为，所以应报告精确验证缺口。

运行不改变状态的检查：

```bash
python scripts/update_external_skills.py --check --source <owner/repository>
```

更新和检查都会解析上游来源，可能需要网络；`--check` 不是离线锁检查。将结果锁定提交与已审查目标比较。目标移动或出现新差异时重新评估。补丁规模提示维护负担，不证明正确。

从当前所有者和 [CI](../../../../../.github/workflows/test.yml) 获取并运行适用的清单、Rule 交付、翻译和仓库检查。项目策略要求时同步镜像。对照已接受范围检查每个改变或删除路径、生成输出、许可和锁条目，包括选定来源外的意外变化。运行 `git diff <comparison-point> --check`，也覆盖新增未跟踪文件。

完成要求：已审查选择和版本安装于仓库快照、已接受行为及消费者一致、必要检查通过、已有工作保留。报告来源和版本变化、接入或淘汰条目、重要补丁和迁移决定、证据及剩余限制。后续发布和安装各自保留授权要求。
