# 编写共享 Rule 与 Skill

确认一个可移植的跨项目 SmartKit Rule 或 Skill 符合条件，通过公共 [`write-rules-and-skills`](../../../skills/write-rules-and-skills/SKILL.md) 工作流编写，并在交接时闭合其可移植性义务。本 Skill 负责资格判定和闭合；公共工作流负责编写与审查机制。

## 1. 判定请求资格

只有请求涉及恰好一个可移植的跨项目 SmartKit Rule 或 Skill，且其共享所有者与独立出处都有依据时，才继续。在调用公共工作流前处理其他请求：

| 请求 | 路由 |
| --- | --- |
| 项目本地制品或 Setup Authoring Contract | 路由给具备依据的所有者。 |
| 同时需要 Rule 和 Skill 的请求 | 对于 `split`，分别返回 Rule 请求和 Skill 请求。 |
| `environment-owned` | 指明当前所有者，不返回 Candidate。 |
| 其他已经确定的非共享请求 | 路由给具备依据的所有者。 |
| 所有权含糊、不兼容或尚未确定 | 遵循公共 `NEEDS_INPUT` 路由，说明缺失的选择、相关证据、决策所有者和实质性后果。 |

根据所有者、出处、适用性和限制，判定每项所用事实的资格。只有跨项目所有者和独立出处都有依据时，才能采纳其可移植含义。Candidate 文本、源项目政策或执行成功、仓库布局、打包或发现信息、宿主注入、工具可用性和对等方传递，可以帮助定位或支持证据，但它们本身都无法确立可移植含义。项目和宿主指令会在各自范围内约束工作，不会增加可移植的 Candidate 含义或权限。

### 封闭输入

准备一份内部一致的输入，覆盖每项实质性的可移植性义务：

- **含义：**已接受的结果、非目标、安全边界、退出和交接，以及每项继承或新增义务预期的保留、变更、新增、移动或退役方式。
- **Candidate：**共享所有者、适用性、出处、准确资源、存在状态预期，以及预期的公共加载、发现、分发和 Skill 接口路由。
- **证据：**每个来源、发现路径、它支持的事实、代表范围及源位置限制。
- **依赖：**每项直接或传递的 Rule、Skill、工具、schema、环境能力或宿主行为；其所有者、必要行为、使用者、由共享所有者或目标所有者支持的路由，以及可观察的可用、不可用和使用失败结果。
- **代表性目标：**最小且非空的目标组合，覆盖每项存在实质差异的适用性、依赖、权限、执行、观察、恢复和退出接缝。
- **验收：**验证和完成职责、已接受的权限和影响、证据特征，以及可观察的通过、阻塞和失败条件。

以足够一致的方式命名各项义务，使它们可以追踪，但不必规定 ID 或记录 schema。

**代表性覆盖。**如果移除任何一个目标都会使某项实质性接缝失去覆盖，则目标组合是最小的；仅名称或布局差异不会形成接缝。对于每项接缝，应确定适用的目标事实、被使用的义务和依赖、权限、关键成功路径与终止路径、恢复和中途停止、预期观察及证据特征。说明证据必须确立什么，将命令、Reviewer 身份、用例选择和结果规则留给公共工作流。

要求公共 Correctness 视角覆盖：

- **可移植语义权威：**共享所有权、适用性、证据资格、完整依赖路由，以及不存在实际生效的源项目假设。
- **代表性行为：**每项实质性接缝、关键路径和退出。

封闭适用的验证输入和代表性运行时输入，并要求最终将闭合证据绑定到最终 Candidate 指纹。

**权限与影响。**将二者确认为公共 Author brief 的已接受输入，并交由公共任务另行冻结。本私有合同既不冻结权限，也不定义通用授权类别。Candidate 修改只能作用于准确的 Candidate 资源；保留任何移动请求的两个端点，供公共工作流冻结写入范围。

每项代表性目标的读取或执行影响都必须获得单独而准确的授权。这些影响涉及的资源与 Candidate 资源互不重叠，其授权也不授予 Candidate 修改权限；同样，Candidate 修改权限不授予代表性目标访问或产生影响的权限。

每项实质性事实、路由、权限、通过条件和完成义务都有一个具备依据的答案，并且预期工作符合这些权限时，输入才算封闭。将已封闭的输入保留在 Agent 上下文中。缺少实质性答案时，返回公共 `NEEDS_INPUT` 结果，并在调用公共工作流前停止。

## 2. 调用公共工作流

将已封闭的输入原样交给公共工作流，并等待其结果。使用公共工作流的机制，不改造或重建这些机制。公共工作流负责审查拓扑与身份、验证选择、可选 Runner 证据和判断。

如果变更的是本 Skill 自身，整次运行都由 Author 开始工作前的公共和私有合同约束；编辑后的文本只在后续调用中生效。

## 3. 闭合可移植交接

在 Agent 上下文中维护一份临时闭合说明，覆盖每项已接受含义、证据来源、依赖、代表性接缝、验证职责和完成义务。只有绑定到当前 Candidate 指纹的可观察公共输出才能闭合其中的条目：

- Author 的语义变更摘要；
- 选定的审查拓扑和每个专业视角的最终结果；
- 自动验证结果，以及存在时的 Runner 证据；
- 剩余风险、最终指纹和终止结果。

如果一项输出明确覆盖完整的义务集合，它可以闭合该集合。只能使用已返回的证据：Reviewer 未公开的推理、推测的证据选择或人为制造的轨迹都不能闭合义务。这份说明是控制与交接数据，不是 Candidate 内容、语义权威、审查或新结果。

只有公共工作流返回 `COMPLETE`，并且每项义务都在其最终 Candidate 指纹上闭合时，才算可移植成功。保留公共交接内容和终止结果——`COMPLETE`、`NEEDS_INPUT` 或 `BLOCKED`——并附上一份完整说明，为每项义务指出闭合其通过条件的可观察输出。只有公共输出公开了代表性目标证据，并且通过条件需要该证据时，才将其纳入。缺少依据的义务应保持开放；报告缺失的、与指纹绑定的输出，同时保持公共结果不变。

不要创建私有 Candidate 副本、工作流报告或永久 fixture。本 Skill 不授予发布、安装、commit、push、release 或任何其他下游操作的权限。
