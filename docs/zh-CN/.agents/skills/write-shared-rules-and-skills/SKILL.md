# 编写共享 Rules 和 Skills

确认一个产物具备在受支持项目间使用的依据，将写作和审查委托给 [Write Rules and Skills](../../../skills/write-rules-and-skills/SKILL.md)，再验证返回证据是否闭合其可移植性义务。

核心判断是：哪些含义属于共享产物，哪些事实属于目标项目。公开工作流负责写作和审查机制。

## 1. 确定什么可以跨项目复用

仅针对一个可跨项目使用的 SmartKit Rule 或 Skill 继续，且其共享所有者和独立来源均有依据。在将本地指导视为共享策略或方法前，确定谁拥有其含义，以及它声称支持哪些环境。

调用公开流程前，先处理其他请求：

| 请求 | 路径 |
| --- | --- |
| 项目本地产物、Setup Authoring Blueprint，或其他已明确的非共享请求 | 使用其受支持所有者。 |
| 同时需要 Rule 和 Skill | 为 `split` 返回独立的 Rule 与 Skill 请求。 |
| `environment-owned` | 指出当前所有者，不返回 Candidate。 |
| 所有权模糊、不兼容或未解决 | 返回公开的 `NEEDS_INPUT`，说明缺失选择、证据、决策所有者和重要后果。 |

对每项依赖事实确定所有者、来源、适用性和限制。只有跨项目所有者及独立来源支持时，才将其纳入可移植含义。Candidate 已有文字是待核实的主张，不是自身权威的证明。

例如，“运行每个项目要求的检查”可以作为共享要求；某源项目成功执行 `npm test`，只支持该目标的命令，不支持所有项目都用此命令。将已接受要求保持为可移植内容，将命令留给证据确立它的目标。

对源项目策略、布局、打包与发现、宿主注入、可用工具及其他 Agent 报告，同样作此区分。它们可以定位或支持证据，却不能独立确立可移植含义。项目和宿主指令在自身范围内约束当前工作，既不增加可移植含义，也不增加 Candidate 权限。

## 2. 完备公开写作输入

向公开工作流提供一份一致输入，包含编写和评估此产物所需知识。义务命名应一致到足以贯穿审查和交接追踪，但不强制 ID 或记录 schema。

### 确定含义、依据和依赖

明确已接受结果、非目标、安全边界、退出和交接。交代每项继承及新增义务应保留、改变、增加、移动还是淘汰。向 Author 提供这些目标含义，而不是旧文档提纲。

确认支撑契约：

| 关注点 | 公开输入必须确立的内容 |
| --- | --- |
| Candidate 与路径 | 共享所有者、适用性、来源、精确资源及存在预期，以及计划的公开加载、发现、分发和 Skill 接口路径。 |
| 证据 | 每个来源和发现路径、支持事实、代表范围，以及源项目特有限制。 |
| 依赖 | 每项直接和传递依赖的 Rule、Skill、工具、schema、环境能力和宿主行为：其所有者、必要行为、消费者、受支持的共享或目标所有路径，以及可观察的可用、不可用和使用失败结果。 |
| 验收 | 验证和完成义务、已接受权限及影响、所需证据，以及可观察的通过、受阻和失败条件。 |

将依赖追踪到消费者。在编写机器上存在，既不证明目标可用，也不说明消费者如何到达它。交接依赖这些内容的工作前，解决重要路径及失败行为。

### 覆盖会改变行为的差异

选择最小非空代表目标组合，覆盖每种实质不同的适用性、依赖、权限、执行、观察、恢复和退出分界。分界是会改变产物能否运行或如何运行的差异；项目名称或布局不同本身不构成分界。

两个使用相同受支持检查接口的项目，可能只覆盖同一案例。如果产物覆盖必要能力不可用的情况，该边界就需要证据证明 Agent 能识别它并执行规定退出；另一个成功项目不能覆盖它。若移除某目标后仍覆盖全部重要分界，就应移除该冗余目标。

对每个分界，确定相关目标事实、消费的义务和依赖、权限、关键成功及终止路径、恢复和中途停止、预期观察及证据特征。要求公开 Correctness 同时评估可移植语义权威和代表行为：

- **可移植语义权威：** 共享所有权、适用性、合格证据、完整依赖路径，以及不存在只在源项目成立的执行假设。
- **代表行为：** 每个重要分界、关键路径和退出。

明确证据必须证明什么，同时将命令、Reviewer 身份、案例及验证选择、可选 Runner 使用和判断留给公开工作流。代表目标承诺覆盖，不自动要求执行。必要时完备适用验证和代表运行时输入；要求闭合证据标明最终 Candidate 指纹。

### 区分目标访问与 Candidate 写入

为公开 Author 简报和独立冻结提供已接受权限及影响。Candidate 写入只涵盖精确资源；要求移动时，包含两端路径。本 Skill 确认输入，公开工作流负责冻结权限。

对每个代表目标读取或执行影响，单独、精确授权。让这些影响与 Candidate 资源分离：目标权限和 Candidate 权限互不授予对方。通过公开工作流解决运行边界，不自行创造私有授权分类或执行协议。

### 输入完备后才交接

当每个重要事实、路径、权限、通过条件和完成义务都有唯一受支持答案，且预期工作符合权限时，输入就绪。将其保留在 Agent 上下文。重要答案仍未解决时，在调用前返回公开 `NEEDS_INPUT` 并指出缺口。

原样传递完备输入，并等待公开工作流结果。使用其写作、审查拓扑和身份、验证、可选 Runner 证据及判断机制，不改造或重建这些机制。

重写本 Skill 时，Author 开始前完整的公开和私有契约约束整轮工作。修改后的指令仅在后续调用生效。

## 3. 用返回证据闭合可移植性

将公开结果与每项已接受含义、证据来源、依赖、代表分界、验证职责和完成义务比较。将闭合记录暂存在 Agent 上下文。

只有绑定当前 Candidate 指纹的可观察公开输出，才能闭合义务：

- Author 的语义修改摘要；
- 选定审查拓扑和每个专业视角的最终结果；
- 自动检查及任何 Runner 证据；
- 剩余风险、最终指纹和终态结果。

一个输出明确覆盖一整组义务时，可以闭合该组。隐藏的 Reviewer 推理、推测的证据选择和制造的轨迹都不能填补缺口。记录描述控制和交接事实，不是 Candidate 内容、语义权威、额外审查或新公开结果。

**可移植成功要求公开 `COMPLETE`，并在该最终指纹上闭合每项义务。** 缺少可移植性证据的公开 `COMPLETE` 仍是公开结果，但不证明可移植成功。保留未闭合义务，并指出缺少哪些与指纹绑定的输出。

保留公开交接及其 `COMPLETE`、`NEEDS_INPUT` 或 `BLOCKED` 结果。附上完整说明，逐项列出义务及闭合其通过条件的可观察输出，或剩余缺口。只有公开输出呈现了代表目标证据、且通过条件需要它时，才将该证据纳入。

保持该记录临时：不创建私有 Candidate 副本、工作流报告或永久测试夹具。本 Skill 不授予发布、安装、提交、推送、发版或其他后续影响权限。
