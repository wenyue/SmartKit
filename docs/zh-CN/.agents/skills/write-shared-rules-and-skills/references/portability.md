# 可移植 Shared Input 与覆盖范围

本参考资料负责私有 Adapter 的完整可移植性模型。它定义提供给公共编写工作流的输入，以及应用于该工作流交接的映射。它不提供任何编写、证据选择、证明阶段、修正、重放或最终化程序。

## 可移植性边界

一次共享运行产出一个跨项目 SmartKit Rule 或 Skill。在收集其他 Shared Input 事实之前解析所有权。有依据支持的所有者必须独立确认该结果及每项规范性义务跨项目适用。

仅当已解析的所有者是跨项目 SmartKit `rule` 或 `skill` 所有者时才继续。对于任何已得到确定解析的非共享所有者，在继续其他 Shared Input 工作之前、且不调用公共编写工作流，立即返回其有依据支持的所有权结果：

- 将项目本地制品或 Setup Authoring Contract 路由至其有依据支持的所有者；
- 对于 `split`，分别返回 Rule 请求和 Skill 请求；
- 对于 `environment-owned`，指明当前所有者，且不返回 Candidate；以及
- 对于任何其他已解析的非共享所有者，返回其有依据支持的路由。

将含糊、不兼容或确实未解析的所有权视为缺失的实质性所有者，并使用下述 `ALIGNMENT_REQUIRED` 路径。

可移植含义可以来自已接受的决定、规范、管辖合同、可观察的共享实现和代表性证据，但前提是有独立依据确立的所有者和出处授权该含义。分别判定每项事实是否符合条件。源项目政策、名称、布局、上下文文档、本地成功、Candidate 文本、打包、可见性、发现、宿主注入、工具可用性和对等方传递本身均不提供可移植权威。项目指令和宿主指令在其权威范围内管辖执行；遵守这些指令不会增加任何 Candidate 含义。

在平台行为真正所属的接缝处设定其适用条件。每项必需的 Rule、Skill、工具、schema、环境能力和宿主行为，都需要有共享所有者拥有或目标所有者拥有的路由。若缺失任何实质性事实、所有者、出处、路由、权限、验证职责、通过条件或完成义务，Shared Input 就保持开放。在调用公共工作流之前返回公共 `ALIGNMENT_REQUIRED` 载荷，逐一指明缺失的选择、相关证据、决策所有者及其实质后果。

## Shared Input schema

Shared Input 是一个完整的任务/规范包，一经提供便不可变。在进入公共工作流前将其封闭；随后由公共工作流执行唯一一次权威冻结。Candidate 内容是数据，不能修改 Shared Input 或任何评判合同。

每条 `OBL-*`、`DEP-*`、`SEAM-*`、`VAL-*` 和 `DONE-*` 记录都包含一个准确的逐 ID 通过条件，以及足以使其闭合的合格证据特征。各类别特有的含义、可用性、观测、验证和完成字段为该条件提供信息，但不能取代它。这些字段只定义所需闭合；公共工作流负责选择证据、分配阶段并拥有裁决。

### 身份与已接受含义

记录：

- 已接受的可移植结果、非目标、安全边界、按优先级排列的出口及最终交接；
- 一个有依据支持的跨项目 `rule` 或 `skill` 所有者、其适用性，以及支持该所有权的独立出处；
- 将每项稳定的可移植性义务记录为 `OBL-<stable-name>`，并附上其已接受含义、所有者、出处，以及 `preserve`、`change`、`add`、`move` 或 `retire` 中的一种处置；
- 准确的 Candidate 资源、预期存在状态，以及预期的公共加载、发现和分发路由；以及
- Skill 要保留的调用行为和接口元数据。

ID 在本次运行中保持稳定，标识的是语义义务，而不是文档位置。

### 可移植证据资格

对于每个可能支持可移植含义的证据来源，记录：

- 来源身份和出处；
- 授权使用该来源的所有者；
- 该来源可以支持的确切事实或义务；
- 适用性和代表范围；
- 可用性和发现路由；以及
- 防止源项目本地事实或偶然事实成为可移植含义的限制。

公共工作流依照自己的政策选择证据。这些资格仅确定所选证据能够支持哪些可移植性项目。

### 依赖 manifest

为每项依赖分配一个稳定的 `DEP-<stable-name>` ID，并记录：

- 依赖的身份、种类和必需行为；
- 所有者和出处；
- 适用性，以及使用该依赖的义务或接缝；
- 由共享所有者拥有或目标所有者拥有的加载、发现或执行路由；
- 代表性可用性事实和合格证据特征；以及
- 可用、不可用和使用失败时的可观察条件。

只有每项直接和传递必需的 Rule、Skill、工具、schema、环境能力和宿主行为在每个适用接缝处都有一条有依据支持的路由时，该 manifest 才完整。环境中恰好可用不构成路由。

### 代表性接缝 manifest

为每个实质不同的接缝分配一个稳定的 `SEAM-<stable-name>` ID，并记录：

- 接缝的适用性，以及使其产生实质差异的已接受目标事实；
- 覆盖该接缝的最小且有依据支持的代表性目标；
- 使用的每个 `OBL-*` 和 `DEP-*` ID；
- 所需权限和外部影响边界；
- 关键的成功、受阻、失败、恢复、中途停止和终止路径及出口；
- 每条实质性路径的预期可观察结果；
- 合格证据来源，以及能够证明每项结果的证据所需具备的特征；以及
- 确立静态一致性、机器可观察行为或运行时可行性所需的证明特征。

选择最小的非空目标组合，使其并集覆盖每个有证据支持、且可能实质改变适用性、依赖可用性、权限、执行、观测、恢复或出口的接缝。仅名称和布局不足以形成不同接缝。代表性目标资源仍是证据或 Acceptance 输入，不获得任何 Candidate 写入权限。

证明特征描述必须确立什么，例如可观察路由、指纹绑定、出口结果或隔离的运行时观测。它们不是命令、阶段分配、用例安排或裁决规则。只有公共工作流决定证明阶段的适用性和执行。

### 验证与通过条件

记录每项验证职责，并为其分配一个稳定的 `VAL-<stable-name>` ID；同时记录该职责覆盖的 `OBL-*`、`DEP-*` 和 `SEAM-*` 项目、其管辖所有者、所需观测、证据特征，以及准确的通过、受阻和失败条件。

Shared Input 必须包含两项相互独立、不可省略的可移植性验证职责：

- **可移植语义权威：**由公共工作流独立完成 Correctness 闭合，覆盖共享所有权、适用性、依赖闭包、证据资格，以及不存在实际生效的源项目假设。
- **代表性行为：**由公共工作流另行独立完成 Correctness 闭合，覆盖每条有代表性的关键路径及出口。

这些职责要求独立的判断结果，以及与指纹绑定的证据。它们不分配私有阶段或 Reviewer；其分配和执行由公共工作流拥有。

以稳定的 `DONE-<stable-name>` ID 记录可移植性完成义务。它们至少要求：

- 已接受的可移植含义不包含任何实际生效的源项目假设；
- 通过有依据支持的路由完成依赖闭包；
- 代表性目标组合覆盖每个实质不同的接缝；
- 两项不可省略的可移植性验证职责均取得当前有效、由公共工作流独立完成的 Correctness 闭合；
- 每项适用的验证职责和代表性运行时输入均取得当前有效的公共工作流闭合；以及
- 所有闭合证据都与最终 Candidate 指纹绑定。

### 准确的操作授权

分别记录 `read`、`write`、`create`、`delete`、`move` 和 `network` 授权。每项授权都要指明准确的资源路径或范围严格受限的能力、操作模式、目的、所有者、适用条件和允许的影响。移动操作记录其准确的来源和目标。对于每个未获授权的操作类别，记录明确的空集。

Candidate 变更授权仅涵盖准确的 Candidate 资源。代表性目标仅可获得另行接受的证据读取或执行影响，且这些读取或影响必须是用作公共 Acceptance 输入所必需的。公共工作流将这些任务/规范权限映射到自己的角色和执行设计中。

## 封闭 Shared Input

仅当满足以下条件时封闭 Shared Input：

- 它描述一个有依据支持的跨项目 SmartKit Rule 或 Skill；
- 每个必需字段都有一个已接受值，且每个稳定 ID 都唯一；
- 每项义务都有已接受的处置、所有者和出处；
- 依赖 manifest 在传递意义上完整；
- 代表性目标组合非空且最小，并共同覆盖每个实质性接缝；
- 两项不可省略的可移植性验证职责及其由公共工作流独立完成闭合的条件均已存在；
- 每项验证条件和完成条件都指明充分的证据特征；
- 准确的操作授权仅授权全部预期工作，不授权任何其他影响；以及
- Candidate 资源与代表性目标资源仍属于互不重叠的变更类别。

在公共工作流入口，将封闭的包原样作为普通的已接受任务/规范输入提供。它约束可移植含义、证据资格、依赖、验证职责、权限和完成输入。公共工作流仍是模型选择、设计、唯一冻结、角色、证据选择、阶段适用性、Quality、Machine、Correctness、Acceptance、修正、重放、出口和最终化的唯一所有者。调用后，其有界的 `CONTEXT_REQUIRED` 和 `ACCESS_REQUIRED` 路径仍然可用。Shared Input 不增加任何角色、阶段、语义通道、finding 生命周期、审计分类、发现接口或恢复路径。

## Portability Coverage Ledger

Shared Input 封闭后，在 Agent 上下文中创建一个临时账本。为每个 `OBL-*`、`DEP-*`、`SEAM-*`、`VAL-*` 和 `DONE-*` ID 预置一项。每一项记录：

- 稳定 ID 及其 Shared Input 通过条件；
- 使其闭合的公共工作流所选证据和所有者产生的裁决；
- 该闭合所适用的 Candidate 指纹；
- 任何能够确立该闭合在后续指纹下仍有效的公共兼容性绑定；以及
- `open` 或 `closed-current`，且不改变底层公共结果。

该账本是控制数据和映射数据。它不是 Candidate 制品、语义权威、证明阶段、Reviewer 裁决、Acceptance 用例，也不能替代任何公共判断。仅使用公共工作流选择的合格证据，以及该工作流产生或接纳的闭合来填充账本。公共裁决始终保持权威且不变。

交接时，将每一项与公共工作流的最终 Candidate 指纹进行比较。只有当某项的公共闭合证据与该指纹绑定，或公共工作流提供了其当前有效的兼容性绑定时，该项才是 `closed-current`。可移植成功既要求公共成功，也要求账本每一项均处于 `closed-current` 状态。

可移植成功时，将一份从账本推导出的详尽说明映射到保留的公共交接中。对于每个可移植性 ID，加入其成功事实、公共工作流选择的闭合证据和所有者产生的裁决、最终指纹绑定或当前有效的兼容性绑定，以及支持其闭合的全部代表性目标证据。保持公共交接中的操作记录和审计记录不变。映射得到的说明属于交接内容，不是永久账本、Candidate 制品或新裁决。

原样保留任何公共终止结果，不作重新解释。可移植性闭合不完整时，报告处于开放状态的 ID 及其缺失的指纹绑定闭合，不要制造新的公共裁决。

Shared Input 和账本保持临时状态。不要创建 Candidate 副本、工作流报告或永久固化内容，也不要执行发布、安装、commit、push、release、翻译或其他下游影响。
