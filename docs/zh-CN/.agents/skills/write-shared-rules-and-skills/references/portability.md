# 可移植性

本参考文件定义公共编写工作流前后使用的可移植性判断。

## 原则

- **共享权威。**只有具备依据的跨项目所有者和独立出处能够确立某项事实时，才能将它视为可移植含义。
- **证据资格。**根据每项所用事实的所有者、出处、适用性和限制作出判断，而不是根据它出现在哪里或有多么常见。
- **完整覆盖。**调用公共工作流前，应使每项实质性的可移植性义务都可以检查；交接时，应使每项义务都能追溯到可观察证据。
- **权限分离。**将 Candidate 修改与代表性目标的读取和执行分开；任何一方的权限都不能授予另一方。
- **可观察闭合。**只用绑定到最终 Candidate 指纹的公共输出闭合义务，不得依赖对 Reviewer 推理过程的猜测。

## 判定所有权和证据资格

一次共享运行只能产出一个可移植的跨项目 SmartKit Rule 或 Skill。只有其共享所有者和出处都有依据时才继续。否则，应在调用公共工作流前停止：

- 将项目本地制品和 Setup Authoring Contract 路由给具备依据的所有者；
- 对于 `split`，分别返回 Rule 请求和 Skill 请求；
- 对于 `environment-owned`，指明当前所有者，并且不返回 Candidate；以及
- 将其他已经确定的非共享请求路由给具备依据的所有者。

所有权含糊、不兼容或尚未确定时，遵循公共 `NEEDS_INPUT` 路由，并说明缺失的选择、相关证据、决策所有者和实质性后果。

可见不等于具有权威。Candidate 文本、源项目政策或执行成功、仓库布局、打包或发现信息、宿主注入、工具可用性和对等方传递，可以帮助定位或支持证据，但它们本身无法确立可移植含义。项目和宿主指令会在各自范围内约束工作，但不会增加可移植的 Candidate 含义或新的权限。

## 封闭可移植性输入

准备一份内部一致的输入，覆盖每项实质性的可移植性义务：

- **含义：**已接受的结果、非目标、安全边界、退出和交接，以及每项继承或新增义务预期的保留、变更、新增、移动或退役方式。
- **Candidate：**共享所有者、适用性、出处、准确资源、存在状态预期，以及预期的公共加载、发现、分发和 Skill 接口路由。
- **证据和依赖：**每个证据来源、发现路径，以及它在代表范围和源位置限制内可以支持的事实；还包括每项直接或传递的 Rule、Skill、工具、schema、环境能力或宿主行为依赖，以及它的所有者、必要行为、使用者、由共享所有者或目标所有者支持的路由，和可观察的可用、不可用及使用失败结果。
- **代表性目标：**最小且非空的目标组合，其并集覆盖每项存在实质差异的适用性、依赖、权限、执行、观察、恢复和退出接缝。
- **验收：**验证和完成职责、已接受的权限和影响、证据特征，以及可观察的通过、阻塞和失败条件。

以足够一致的方式命名各项义务，使它们可以追踪，但不必规定 ID 或记录 schema。将权限和影响确认为公共 Author brief 的已接受输入，并交由公共任务另行冻结。本私有合同不执行冻结，也不定义通用授权类别。Candidate 修改只能作用于准确的 Candidate 资源。每项代表性目标的读取或执行影响都需要单独而准确的授权，不能授予 Candidate 修改权限，并且涉及的资源与 Candidate 资源互不重叠。保留任何 Candidate 移动请求的两个端点，供公共工作流冻结写入范围。

如果移除任何一个目标都会使某项实质性接缝失去覆盖，则代表性目标组合是最小的；仅名称或布局差异不会形成接缝。对于每项接缝，应确定适用的目标事实、被使用的义务和依赖、权限、关键成功路径与终止路径、恢复和中途停止、预期观察及证据特征。说明证据必须确立什么，而不是规定命令、Reviewer 身份、用例清单或结果规则。

输入必须要求公共 Correctness 视角覆盖两个方面：可移植语义权威——共享所有权、适用性、证据资格、完整依赖路由，并且不存在实际生效的源项目假设；以及所有关键路径和退出中的代表性行为。公共工作流仍然负责选择审查拓扑和身份、验证、可选 Runner 证据和判断。输入还必须要求覆盖每项实质性接缝，封闭适用的验证输入和代表性运行时输入，并最终将闭合证据绑定到最终 Candidate 指纹。

只有每项实质性事实、路由、权限、通过条件和完成义务都有一个具备依据的答案，并且预期工作符合这些权限时，输入才算封闭。缺少实质性答案时，返回公共 `NEEDS_INPUT` 结果。

## 在交接时闭合可移植性

为每项已接受含义、证据来源、依赖、代表性接缝、验证职责和完成义务维护一份临时闭合说明。只有绑定到当前 Candidate 指纹的可观察公共输出才能闭合其中的条目：Author 的语义变更摘要、选定的审查拓扑、每个专业视角的最终结果、自动验证结果、存在时的 Runner 证据、剩余风险、最终指纹和终止结果。如果一项输出明确覆盖完整的义务集合，它可以闭合该集合。

这份说明是控制与交接数据，不是 Candidate 内容、语义权威、审查或新结果。不得推断 Reviewer 未公开的推理或证据选择，也不得制造公共工作流未返回的轨迹。

只有公共工作流返回 `COMPLETE`，并且每项义务都在其最终 Candidate 指纹上闭合时，才算可移植成功。保留公共交接，并附上一份完整说明，为每项义务指出闭合其通过条件的可观察输出。只有公共输出公开了代表性目标证据，并且通过条件需要该证据时，才将其纳入。任何缺少依据的义务都应保持开放；报告缺失的、与指纹绑定的输出，同时保持公共结果不变。

将已封闭的输入和闭合说明保留在 Agent 上下文中。不要创建私有 Candidate 副本、工作流报告或永久 fixture。本 Skill 不授予发布、安装、commit、push、release 或任何其他下游操作的权限。
