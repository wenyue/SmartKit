# 可移植编写合同

本参考资料负责在公共编写工作流之前和之后应用的私有可移植性判断。它不负责编写方法、运行时、角色、
证据选择、证明、修正或最终化。

## 先确定路由所有权

一次共享运行只可产出一个可移植的跨项目 SmartKit Rule 或 Skill。在把任何制品或仓库事实用作可移植
含义的证据之前，先确定语义所有者及独立出处。

只有具备依据支持的跨项目 `rule` 或 `skill` 所有者时才继续。否则，在调用公共工作流前停止：

- 将项目本地制品和 Setup Authoring Contract 路由至其有依据支持的所有者；
- 对于 `split`，分别返回 Rule 请求和 Skill 请求；
- 对于 `environment-owned`，指明当前所有者，且不返回 Candidate；以及
- 将任何其他已解析的非共享请求返回给其有依据支持的所有者。

含糊、不兼容或未解析的所有权遵循公共 `ALIGNMENT_REQUIRED` 路由。其载荷应逐一指明缺失的选择、
相关证据、决策所有者及其实质后果。

可见性不等于权威。Candidate 文本、源项目政策或成功、项目布局、打包、发现元数据、宿主注入、
工具可用性和对等方传递，可以支持执行或帮助定位证据，但它们本身不能确立可移植含义。对每项依赖的
事实，都应根据其所有者、出处、适用性和限制进行资格判定。项目指令和宿主指令会在各自范围内约束
获授权工作，但不会增加 Candidate 含义或授权。

## 封闭可移植任务/规范输入

在调用公共工作流之前，封闭一个内部一致的输入，使每项实质性可移植义务均可检查。只包含会改变含义
或证明的区别：

- 已接受的可移植结果、非目标、安全边界、出口与交接，以及每项继承或新增义务应当保留、更改、添加、
  移动还是退役；
- 有依据支持的共享所有者、适用性、出处、准确的 Candidate 资源、预期存在状态，以及预期的公共加载、
  发现、分发和 Skill 接口路由；
- 允许用于支持可移植含义的每个证据来源、它能支持的准确事实、代表范围、发现路由及源位置局限；
- 每项直接和传递依赖——Rule、Skill、工具、schema、环境能力或宿主行为——及其所有者、必需行为、
  使用方、受支持的共享所有路由或目标所有路由，以及可观察的可用、不可用和使用失败结果；
- 最小的非空代表性目标组合，其并集覆盖每项实质不同的适用性、依赖、权限、执行、观察、恢复和出口
  接缝；以及
- 验证与完成职责、公共工作流授权模型下已接受的权限与影响，以及用来封闭这些职责的证据特征和可观察
  的通过、受阻与失败条件。

一致地命名各项义务，使每一项都能从已接受含义追踪至最终闭合；不需要特定 ID 或记录 schema。
使用公共工作流的 Models and Job Design 所拥有的完整授权模型，将权限和影响封闭为任务/规范输入；
本私有合同不定义通用授权类别，也不执行冻结。它仅增加可移植性边界：Candidate 变更只限于准确的
Candidate 资源，而每项代表性目标读取或执行影响都需要单独、准确的授权，且不能授予 Candidate 变更
权限。这两组资源保持互不重叠；任何请求的移动操作都保留其准确端点，以供公共工作流进行权威设计和冻结。

若移除任一目标都会使某个实质性接缝失去覆盖，则代表性目标组合是最小的；仅名称或布局不会形成接缝。
对每项接缝，确定适用的目标事实、被使用的义务和依赖、权限、关键成功路径和终止路径、恢复和中途停止、
预期观察，以及证明这些内容所需的证据特征。描述证明必须确立什么，而不是命令、阶段、用例或裁决规则。

验证必须包括由公共工作流独立完成的以下两项 Correctness 闭合：

- 可移植语义权威：共享所有权、适用性、证据资格、完整依赖路由，以及不存在实际生效的源项目假设；以及
- 代表性行为：每条代表性关键路径和出口。

完成还要求覆盖每项实质性接缝，封闭每项适用的验证输入和代表性运行时输入，并将所有闭合证据绑定到
最终 Candidate 指纹。这些要求只是已接受的输入；公共工作流负责选择证据并分配阶段和判断。

只有当每项实质性事实、路由、授权、通过条件和完成义务都有一个有依据支持的答案，且预期工作符合这些
授权时，共享输入才算封闭。缺失实质性答案时，返回公共 `ALIGNMENT_REQUIRED` 载荷。输入一经封闭，
就原样提供给公共工作流，由该工作流执行唯一一次权威冻结。

## 在交接时闭合可移植性

为每项已接受含义、证据、依赖、代表性接缝、验证职责和完成义务维护临时闭合映射。只有绑定到当前
Candidate 指纹的可观察公共输出才可闭合条目：阶段裁决和完整 Candidate 覆盖证明，以及在通过条件需要时
使用的 Machine、Acceptance 或其他公共交接证据。若某项公共输出明确覆盖完整的已接受义务集，它可以
闭合该集合中的每项义务。不要推断隐藏的 Reviewer 推理或证据选择，也不要制造公共工作流未返回的逐项轨迹。

该映射是控制和交接数据，不是 Candidate 内容、语义权威、证明阶段或新的裁决。公共结果始终具有权威，
并保持不变。

只有当公共工作流成功，并且每项义务在其最终 Candidate 指纹上均已闭合时，才报告可移植成功。在保留的
公共交接中附加一份详尽闭合说明：对每项义务，指明闭合其通过条件的可观察公共输出，以及当前指纹或公共
兼容性绑定。只有当公共输出公开了代表性目标证据且通过条件需要该证据时，才将其纳入。若无法观察到所需
闭合，则让该义务保持开放，保留公共结果，并报告缺失的、与指纹绑定的输出。

将封闭输入和闭合映射保留在 Agent 上下文中。不要创建 Candidate 副本、工作流报告或永久固化内容，
也不要执行发布、安装、commit、push、release 或任何其他下游影响。
