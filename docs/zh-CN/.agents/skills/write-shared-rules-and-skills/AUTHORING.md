# 编写决策

## 确认可移植性，不复制公开 writer

共享封装负责跨项目语义确认和闭合，公开工作流负责 Candidate 权限、写作、拓扑、验证和判断。第二套私有审查协议会制造冲突的完成标准，以及公开结果未呈现的证据。

## 将 SmartKit 政策留给负责确认它的所有者

在本 Skill 中以可直接查阅的 reference 保留 SmartKit 的确切依赖范围和 Blueprint Target 可见性。公共 writer 接收经过确认的政策输入，因此为其他提供方使用它时，不会加载 SmartKit 维护工作流，也无需访问未随包提供的仓库本地文件。通用关系语义保持公开，可供独立编写和 Setup 驱动的项目编写复用；蓝图只承载其目标特有的义务。

## 按重要差异选择代表目标

更多项目名称不一定意味着更多覆盖。目标组合按会改变行为的分界组织，包括能力不可用和中途停止，避免多个相似环境的成功掩盖遗漏的失败或权限边界。

## 将闭合绑定到同一版本的可观察输出

不能仅凭公开 COMPLETE 标签或推测 Reviewer 的隐藏工作来推断可移植性。与指纹绑定的可观察输出，使封装结论可供检验，同时保留公开裁决，避免第二套永久 Candidate 或报告。
