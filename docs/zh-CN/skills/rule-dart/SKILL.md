# Dart 语言契约

在决定如何使用 Dart 语言和库时，遵循以下约定。

## 选择错误的表达方式

通过抛出异常报告操作失败时，使用具体的 `Exception`。优先采用语义符合契约的现有异常类型。调用方需要稳定的分类，或需要现有类型未提供的字段时，定义有明确类型的异常。编程契约或不变量遭到违反时，使用 `Error`。

## 按类型匹配失败

优先使用具体的 `on` 子句，并将捕获范围限定在调用方能处理其失败的操作。用类型或已记录契约的字段进行程序化分类，异常消息留作诊断。`on Exception` 会广泛捕获其子类型，`on Object` 和未指定类型的 `catch` 还会捕获 `Error` 和其他任意抛出的对象。

在操作失败的恢复过程中，让编程缺陷继续传播。如果处理外部输入的 API 根据文档或核实结果会用具体的 `Error` 表示无效输入，只在该调用周围处理它，明确保留失败结果，并使状态保持有效。

## 保留错误及其堆栈

在捕获子句内使用 `rethrow` 传播原始错误及其堆栈。要在该捕获子句之外转发捕获的错误，通过第二个捕获参数取得 `StackTrace`，并在所支持的 SDK 提供 `Error.throwWithStackTrace` 时，将原始对象和堆栈传给它。转换失败时，按需将原始对象作为独立的原因证据保留。带着捕获的堆栈抛出替代异常会保留原始抛出位置的堆栈，原始对象则保有失败的类型和数据。

## 有意识地安排行为与数据形状

属于某个所有者的局部行为默认使用实例成员。顶层函数仅用于框架入口、文件级声明、共享算法或没有明确所有者的逻辑。仅在命名类型不能增加清晰度时，用记录表示小型局部元组返回值。

## 让文件系统操作确定自身结果

在可使用 `dart:io` 的环境中，通常直接执行所需的读取、写入、创建或删除。让操作将自身失败交给既定的恢复或报告所有者；后续操作无需复现先前瞬时查询的错误。

只有预先查询具有具体收益时，才直接或通过包装执行查询。解释 `existsSync`、`typeSync` 等查询时，应遵守它们的能力边界：

| 结果 | 含义与允许的用途 |
| --- | --- |
| 否定结果，如 `false` 或 `notFound` | 可能表示不存在、查询失败或类型不匹配。只有不存在与查询失败对当前调用者等价，且任何可能的类型不匹配都可接受时，才能跳过操作或采用默认值。 |
| 肯定结果 | 仅描述查询时的观察结果。状态可能改变，因此它既不保证权限，也不保证后续成功。 |

从实际操作的语义中获得初始化和覆盖保证。检查不存在无法提供这些保证，而默认写入可能截断已有数据。
