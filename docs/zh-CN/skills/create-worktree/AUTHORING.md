# 编写决策

## 保留继承状态，不转移所有权

将默认携带、暂存与未暂存的忠实保留，以及源保持不变的保证放在一起。方便的干净检出可能遗漏用户期望继续的工作，而携带检出又可能诱使调用方把继承修改当成自己的内容提交。因此就绪验证传递结果，但不扩大提交范围。

## 区分工作区就绪与项目健康

工作流验证身份、已有工作保护、必要的 Agent 配置和环境准备；项目基线、构建及测试检查由实现工作流负责。将项目健康并入工作区就绪，会重复检查，也会模糊未就绪结果究竟来自工作区准备，还是正在修改的代码。

## 在发现项目 Skill 前确立 Agent 配置

仅本机和仓库模式下，被忽略的配置都可能缺失，包括环境准备 Skill 本身。发现 Skill 前，先从完成初始化的源检出提供配置，无论源检出最初从哪里取得配置。这样，worktree 准备就独立于配置仓库恢复。

优先使用符号链接，使配置编辑共享同一来源，即使编辑器通过原子替换写入文件也如此。副本保留来源映射，以支持等价修改和安全清理；这不建立后台同步服务。文件可用仍需与宿主激活区分。
