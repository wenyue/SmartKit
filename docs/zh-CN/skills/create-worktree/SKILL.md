# 创建工作树

为一个已获授权的隔离关联 Git 工作树返回一份以证据为依据、状态为 `ready` 或 `non-ready` 的交接。选择调用方已确定的创建或复用模式，保全规范检出目录和所有无关状态，建立目标，只运行已获授权且由目标方所有的准备工作，并报告终止边界。

调用方或所属工作流负责确定实施范围、不可变基准、特定于模式的目标身份、生命周期责任方和变更授权。控制器负责验证并执行该请求，并对就绪判定负责。以下责任方必须彼此区分：

- `scope_owner`：负责已接受的实施范围；
- `creation_owner`：获授权调用创建操作，并负责首次尝试恢复的问责执行者；
- `integration_owner`：负责后续集成；以及
- `cleanup_owner`：负责后续清理。

观察或记录责任方不会授予任何变更权限。本技能不负责实施、提交、已完成改动的验证、集成、跟踪、清理、发布或任何其他下游影响。

## 确定请求和保全边界

选择目标前，必须取得所属工作流对以下事项给出的权威信息：

- 已接受的范围和 `scope_owner`；
- 确切的规范基准检出目录、具名基准分支，以及 `immutable_base` 提交 OID 和树；
- 创建或复用选择及作出该选择的责任方；
- 不可变的预定工作树分支；
- 对于创建模式，由小写字母和连字符组成的 slug；
- 对于复用模式，确切的选定工作树，以及下文**复用身份**使用的每一项由调用方冻结的值；
- `creation_owner`、`integration_owner` 和 `cleanup_owner`；以及
- 对每一种可能变更的确切授权。

证明规范检出目录已附着到具名基准分支，并位于 `immutable_base`。解析并冻结 `canonical_root`，将其记为该检出目录的词法根和有效物理根；同时将 `git_common_root` 冻结为解析后的 Git 公共目录。选择目标后，将 `selected_root` 冻结为互不混淆的词法路径字段和有效物理目的地字段。对于尚不存在的创建目标，根据解析后的最近既有祖先推算有效目的地，并在创建后重新证明。当前分支顶端、约定或发现的工作树绝不能替代请求值。只有调用方委托推导时，控制器才可以根据经过验证的仓库约定推导一次创建分支，并在没有此约定时回退为 `worktree/<slug>`；必须在选择目标前将其冻结。

整个运行过程中使用以下具名谓词：

- **创建身份：**`selected_root`、登记、预定和观察到的具名分支/引用关系、`HEAD` 与当前提交树都与请求完全匹配；引用和 `HEAD` 均解析到 `immutable_base`，而且当前提交树等于其提交树。
- **复用身份：**`selected_root`、登记、预定和观察到的具名分支/引用关系、`HEAD` 与当前提交树都与调用方冻结的 `expected_current_head` 和 `expected_current_tree` 完全匹配；完整本地状态符合逐项所有权和允许范围；已经证明 `creation_owner` 生命周期证据，以及所需的 `immutable_base` 沿袭关系或范围。
- **保全盘点：**目标或部分产物及其词法/有效目的地；规范检出目录的分支、`HEAD`、提交树、索引、已暂存、未暂存、未跟踪、已忽略、文件类型、模式和符号链接状态；完整的已登记工作树集合与本地分支集合；`git_common_root` 下的持久引用、配置、钩子和工作树管理状态；每个已声明的影响目标，以及可观察到的实际文件系统、外部或持久影响；并且将每项差异映射到一个责任方和一项确切授权。
- **就绪快照：**终止时特定于模式的身份凭证，加上目标的完整本地状态；二者均绑定到终止保全盘点及其观察边界。

在任何变更前捕获初始保全盘点。对于复用模式，在运行任何目标方自有命令前证明其身份并为该身份创建快照。每项预存偏差都必须只有一个责任方且属于已接受的范围；存在歧义即为 `non-ready`。后续盘点只能接纳另行授权且已经识别的影响：确切的创建资源、已获授权的防护修复，以及已声明的设置或基线影响。证据用于记录权限，而不会创设权限。

**完成条件：**每个固定值和责任方都已经证明，每种可能的变更都有确切授权，而且初始盘点能够区分允许的影响与用户状态或无关状态。

## 选择并建立恰好一个目标

### 复用

只能复用所属工作流为此范围选定的确切当前关联工作树。证明其身份；不得替换、接管、重置、清理或修复其他工作树。

如果 `selected_root` 位于 `canonical_root` 内部，冻结发生重叠的确切子树及其事前状态，使后续比较能够区分目标方影响与规范检出目录周边状态。否则要明确证明这是外部复用。

通过适用的防护关卡后，重新证明复用身份和保全盘点。复用模式不允许新增登记或分支。对于内部复用，还要重新证明冻结的重叠区域和规范根防护；对于外部复用，则要重新证明没有重叠且防护不适用。任何不一致、意外差异或观察不完整都属于 `non-ready`。

**复用建立条件：**身份、保全盘点和适用防护均通过。否则以 `non-ready` 终结。已经建立的复用目标直接进入目标准备。

### 创建

将 slug 映射到 `<canonical_root>/.worktrees/<slug>`，并将该词法路径冻结为 `selected_root.lexical`。解析其最近的既有祖先，并证明 `selected_root.effective` 保持在有效的 `canonical_root` 内，不会经由存在歧义的遍历、符号链接、联接点或重解析点逃逸。要求文件系统和已登记工作树中均不存在该路径；证明冻结的预定分支语法有效，并且不在本地分支和已登记工作树中。使用时发现宿主当前的物理路径与文件系统/重解析行为；无法取得、存在歧义或解析失败时，必须在变更前判定为 `non-ready`。

创建前，必须取得一项确切授权，其中指明词法路径和有效路径、分支创建、工作树登记，以及 `git_common_root` 下相应的管理性变更；该授权必须绑定到指定的 `creation_owner`。

### 本地防护

对于创建模式，以及位于该目录下的复用模式，要求 `canonical_root` 中存在有效的、相对于仓库的 `.worktrees/` 忽略规则。使用 `git -C <canonical_root> check-ignore -v <selected-root-relative-path>` 验证选定路径。全局排除规则或 Git info 排除规则并不充分。只能修复 `<canonical_root>/.gitignore`，而且必须另有项目自有权限，允许实施能够保留现有本地状态、可与其区分的最小改动。外部复用应记录防护不适用，也不会因此获得任何修复权限。

### 创建尝试

创建操作以观察关卡为前提，而不是串行化的。不得使用任何可移植或全局锁、租约、原子防护或其他协调依赖。宿主原生能力或 Git 后备方式 `creation_mechanism` 必须拒绝创建时出现的路径、分支和登记冲突。竞态可能导致一次失败的尝试，也可能导致表面成功但后续盘点结果为 `non-ready` 的创建；出现相关漂移时，绝不能产生 `ready` 结果。

使用时发现原生能力和 Git 后备方式，并记录不可用或失败的路径。每次尝试都在原生能力可用时使用原生能力，否则使用 Git 后备方式。调用前一刻，重新观察并通过固定请求和责任方、不可变基准、规范检出目录保全、目的地包含关系和路径不存在、分支有效且不存在、登记不存在、确切授权、`creation_owner` 权限、冻结机制可用性及防护证明。发生漂移或证据不完整时，在调用前停止。后备方式使用：

```text
git -C <canonical_root> worktree add -b <requested-branch> <selected_root.lexical> <immutable_base_oid>
```

指定的 `creation_owner` 对每次调用负责，并且不得超出其确切授权；机制不是责任方。一次调用就是一次尝试。每次尝试后都要立即捕获完整保全盘点并观察创建身份的每个字段，即使尝试失败或中断也不例外。在要求创建身份完整之前，先根据下文的狭窄恢复关卡对未成功调用进行分类；只有状态未变或确切的、完全由该次尝试所有的部分影响这两种情况，才不因创建身份失败而直接终结。任何相关漂移；创建时发生的路径、分支或登记冲突；意外或超出范围的影响；证据不完整；或不属于上述例外的任何身份或不变量失败，都会终止创建和整个交接，并使其成为 `non-ready`。即使该条件随后消失，这些情况也一律不得重试或在之后判定就绪。

只有在上述终止条件均未发生时，第一次未成功的调用才可能符合重试条件。其盘点必须证明：创建方彻底失败后状态未发生变化，或者仅有完全由该次尝试所有且不含用户工作的确切部分影响。只有另有绑定到 `creation_owner` 的确切清理授权时，才能移除这种部分影响。重新观察清理结果或已经证明的产物不存在状态，重复每个创建关卡，并且最多重试一次。否则保留产物并停止。第二次失败留下的所有产物均须保留。任何存在歧义、归用户所有、无法解释或未得到完整观察的影响都要保留，并终止创建。

对于表面成功的尝试，重新证明创建身份和保全盘点。创建模式只允许出现其确切的已授权差异。

**创建建立条件：**创建身份、即时盘点、尝试后保全盘点，以及每项创建或防护影响均通过。否则以 `non-ready` 终结。

## 在已声明的影响范围内准备目标

由目标方所有的 `worktree-environment-setup` 和仓库声明的基线都是依赖项；它们各自的声明负责命令与含义，而调用方或所属工作流负责为其影响提供权限。

执行任一依赖项前，检查其当前声明，并冻结其命令和影响范围，包括每个文件系统目标、持久 Git 公共状态变更，以及外部或持久影响。冻结其调用绑定：要么工作目录恰好是 `selected_root.effective`，要么显式仓库目标参数解析到该处。每次调用前一刻验证该绑定。绑定无法取得、存在歧义或不匹配，包括绑定到 `canonical_root` 或另一个根时，必须在执行前判定为 `non-ready`。证明依赖项不会产生变更，或者要求对每个已声明类别和确切目标给予明确权限。将授权方和允许新增的本地状态绑定到这一选定工作树。影响范围缺失、存在歧义、没有责任方或未经授权时，必须在执行前判定为 `non-ready`。使用时重新读取由环境所有的声明；不得将其缓存在此处。

设置存在时先运行设置。若已证明设置不存在，则与就绪状态兼容。设置失败、停止、中断、结果意外或未就绪时，必须在基线前结束准备流程。

只有设置就绪或不存在后，才运行已声明的基线。记录其确切命令和结果。通过与就绪状态兼容。只有用户明确接受观察到的确切失败时，失败才与就绪状态兼容；已经证明的缺失需要用户或所属工作流明确接受。接受行为不授予变更权限。不得臆造基线，也不得以已完成改动的验证代替基线。

设置或基线的每种处置结果出现后——包括成功、失败、中断，或者确定不存在、无法取得、缺失、移动或不可读——都要捕获保全盘点，并将该盘点与该依赖项紧邻在前的特定于模式的身份、保全盘点及其冻结的影响范围进行比较。保留部分证据。任何无法取得、未经授权、无法解释、超出范围或观察不完整的状态均属于 `non-ready`。

**完成条件：**设置和基线都有确切的终止处置结果，而且盘点证明每项已声明或实际影响都得到完整观察、符合影响范围、具备责任方且已获授权。

## 终结并交接

每次退出前捕获保全盘点；观察不完整时要如实报告，不得推断。在创建模式下，只允许经过验证的选定子树和确切的已授权资源差异。对于内部复用，保持冻结的重叠子树边界不变。使用保全盘点，将其内容及差异与冻结的事前状态、所有权、确切授权和明确影响范围进行比较；只接纳相符的影响，并保全该边界以外的所有内容。外部复用没有重叠例外。提前退出仍须完成每项可观察的比较。

只有以下各项均已证明时，才返回 `ready`：

- 固定请求和生命周期责任方完全匹配；
- 每个初始、尝试前即时、尝试后、准备和终止保全盘点均通过；没有发生会导致终结的竞态；任何首次尝试恢复均已通过其狭窄关卡并得到重新观察；
- 适用的忽略防护通过，或者已证明它不适用于外部复用；
- 特定于模式的身份在所有准备工作后通过，已授权的准备状态只位于保全范围和影响范围内；
- 设置不存在或返回就绪；
- 基线通过，或者其确切失败或缺失已经得到所需的明确接受；以及
- 每项最终偏差都位于已接受范围和已授权的允许状态范围内。

所有其他退出都是 `non-ready`。除唯一获授权的首次尝试恢复外，保留工作树和残余状态。

返回一份紧凑的机械式交接，其中包含：

- 状态和确切原因；已接受的范围和 `scope_owner`；
- 模式、三个根、`immutable_base` 和完整的就绪快照；
- 初始和最终保全盘点及每项边界比较；对于每次创建尝试，还包括其即时关卡、责任方、机制、结果、盘点、已授权差异、清理证据和重试处置；
- 所有生命周期责任方；模式的选择责任方；分支推导的来源和委托责任方（若有）；以及创建影响和防护修复的来源与授权方；
- 防护的适用性、证明、修复和实际影响；
- 设置和基线声明、命令、绑定、影响范围、权限、结果、接受情况、实际影响和影响比较结论；
- 每项终止盘点、其完整性、保留的证据、所有权映射和影响范围比较；以及
- 对于 `non-ready`，确切的失败边界和观察结果、保留状态或残余状态、下一责任方和一项确切的后续操作。

使用确切的观察结果。只能在到达相应边界前使用 `not-selected`、`not-created` 或 `not-run`；只有值确实无法观察时才使用 `unavailable`；只有已尝试的关卡仍不完整时才使用 `unverified`。对于已确定不适用或不存在的步骤，应记录其确切原因和影响。`ready` 交接的必填字段中不能出现任何标记。

使用方只有在首次消费或变更目标前一刻重新检查特定于模式的确切就绪快照，才能接纳该目标；任何不一致或 `non-ready` 都会阻止消费。后续已获授权的目标提交或本地改动会使该快照失效，但不会追溯改变本次运行的结果。继续或恢复需要针对调用方冻结的当前快照取得一份全新的复用交接。任何下游收尾方都要把其自身负责的契约独立应用于目标届时的当前身份、所需审查和验证，以及不可变基准沿袭关系。任何交接内容都不会授予新权限。
