# 创建工作树

选择或创建一个 Git 链接工作树，准备环境，并返回 `ready` 或 `non-ready`。默认携带源工作区的当前工作，同时保持源不变。继承的修改仍是受保护的工作，不会自动归入调用者的任务。

## 1. 选择工作区和起始状态

采用已接受的任务范围以及已有的源、目标、基线和效果权限选择。根据仓库拓扑确定源检出、项目主检出和物理 Git 公共目录；发起调用的链接检出不一定是主检出。

继续使用已选工作树时，对照任务上下文检查物理路径、Git 注册、分支、`HEAD`、基线关系及本地修改。一致时复用，保留已有的继承修改和任务修改。不要将新的源修改覆盖到其中。身份或归属不清时返回 `non-ready`；否则跳过创建，直接准备环境。

新建工作树时，将基线解析为不可变提交，并选择起始状态：

- **Carry** 为默认模式：源 `HEAD` 加上已暂存、未暂存和未被忽略的未跟踪修改，保留各层之间的区别。
- **Clean** 需要明确选择：仅使用选定基线，不携带源修改。

使用不同基线时，需要明确选择 clean，或就兼容的 carry 语义达成一致。继续前先确定携带的修改如何应用到该基线；仅选择基线不授权从另一基线复制修改。要求工作区仅含任务所属状态的调用者可以拒绝继承工作，但这不授权丢弃它或改变默认 carry 行为。

## 2. 确定位置与 carry 决策

### 位置

遵守明确给出的目标路径。否则优先使用 `<primary-project-root>/.worktrees/<task>`，并复用有效的现有 `.worktrees` 容器。无效条目、不安全的物理别名或受跟踪内容冲突需要先解决，不能因此自动改用其他位置。

容器不存在且位置尚未确定时，展示两个具体目标路径，让用户在以下两处中选择：

1. `<primary-project-root>/.worktrees/<task>`，并添加本地 Git 排除。
2. 插件的持久 `data/worktrees/<project-id>/<task>` 位置。

从权威宿主或配置输入确定插件数据根目录。在 Codex 中，SmartKit 约定使用 `<resolved-codex-configuration-root>/plugins/data/smartkit/worktrees/<project-id>/<task>`。项目 ID 使用 `<project-name>-<short-hash-of-canonical-git-common-dir>`，使链接工作树共享位置，同时区分同名克隆。这是 SmartKit 的约定，不是官方宿主能力。其他宿主没有已知持久根目录时，先取得该位置，再提供第二个路径。工作树应位于带版本的插件缓存和 Skill 安装目录之外。

选择唯一任务路径和命名分支。确认路径、分支和工作树注册均不存在；解析物理路径，避免别名和在调用工作树下递归嵌套。保留已有分支，不要改作他用。

放在项目内时，验证 Git 排除实际生效。必要时通过 Git 定位本地 `info/exclude`，仅添加 `/.worktrees/`，保留其余字节和共享 `.gitignore`。位置选择在调用者的效果约束内授权这项本地排除。位置与 carry 决策都明确后，才能修改容器或排除文件。

### 源保护与 carry

两种模式都要捕获源的 `HEAD`、分支、索引、工作文件内容和未被忽略的未跟踪状态，足以验证创建后源保持不变。未解决的索引冲突、进行中的操作或不受支持的文件/索引语义会停止创建，除非所选机制能忠实保留该状态。

**Clean** 跳过传输捕获、计数和 carry 审批。**Carry** 分别捕获已暂存和未暂存修改，包括同一路径同时存在两层修改的情况，以及未跟踪输入。保留内容、新增、删除、重命名、二进制文件、可执行模式和符号链接。排除被忽略文件、依赖缓存和嵌套工作树；必需但被省略的输入交由环境准备处理。复制前确定预期目标状态，包括任何已同意的跨基线变换。

累计已暂存、未暂存差异及新增未跟踪文本的增加和删除行数。跨所有层按不同修改路径计数，每个路径只计一次。二进制修改计入路径，不虚构行数。创建或复制前，如果 **lines >= 300 OR paths >= 10**，展示源、目标、计数和携带状态，并取得明确 carry 决策，除非该快照与目标已有此决策。披露无法计量的项目并取得涵盖它们的决定，不能将其视为零。低于两个阈值时，按默认 carry 继续并报告计数。

已审阅快照或目标发生实质变化时，需要重新说明并取得决定。用户拒绝 carry 后，取得明确的 clean `HEAD`/基线选择，或取消；沉默不代表同意。

## 3. 创建并验证

创建前立即复核源快照、选定基线和模式、已有决策，以及目标路径、分支和注册确实不存在。使用适用的宿主创建接口，或采用遇到冲突即拒绝的 Git 操作。执行前，将重要的 hooks、filters 和子进程效果纳入获准操作的考量。

从选定提交创建工作树。Clean 模式不复制源修改；carry 模式重现捕获的索引和工作状态，包括未跟踪输入。保持源字节、索引、`HEAD` 和分支不变：stash、commit、reset 及移动源文件都不是传输方法。

验证注册的目标路径、命名分支及位于所选基线的 `HEAD`。将索引和工作状态与预期结果比较，包括内容、类型、模式，以及已暂存和未暂存修改的区别。比较索引语义，不要求索引扩展元数据的二进制一致。确认源未变，且容器、排除和创建效果符合选定计划。漂移或比较不完整时返回 `non-ready`。

中断或失败后，重试前先检查实际存在的状态。保留部分路径、分支、注册和已复制工作，并留下足以安全继续的上下文；不要重复复制而覆盖后续修改。仅当部分产物完全属于本次尝试、不含其他工作且删除已获授权时，才删除它们。恢复前复核适用选择。

## 4. 准备环境并报告就绪状态

发现所选目标的项目 `worktree-environment-setup` Skill。存在时，在已接受的配置权限内针对该目标调用，并将继承修改标为受保护。消费其 `environment-ready` 或 `environment-non-ready` 结果；复用该目标仍有效的结果，不重复配置检查。存在但不可用、失败、中断或结果不明确时，返回 `non-ready`。不存在时报告 `not-provided` 并跳过；已知必需输入或准备缺失时仍不能就绪。

配置后复核目标身份和预期状态，计入其已授权修改。仅当创建或复用已验证、已有工作已保护、必需配置成功，且没有未解决选择、未授权效果或必需前提缺失时，返回 `ready`。否则返回 `non-ready`，保留工作区和部分状态，供安全继续。

向调用者提供状态、目标路径、分支、不可变基线与当前 `HEAD`、创建还是复用、携带/继承状态摘要和 carry 决策，以及环境状态。`non-ready` 还需给出阻碍、保留的部分状态和具体下一步。必要时保留支持性观察；交接无需完整证据清单。

就绪状态涵盖工作区及其准备，不代表项目健康。此 Skill 不运行项目基线、构建或测试检查。这些检查和提交决定由实现流程负责；携带继承工作不授权提交它。使用返回的工作区前，复核其当前身份和状态，调查意外漂移。
