# 创建工作树

选择、建立并准备恰好一个安全的关联 Git 工作树，然后返回一份以证据为依据、状态为
`ready` 或 `non-ready` 的机械式交接。本技能负责工作树的选择、创建、验证、就绪判定和
交接。调用方负责已接受的实施范围以及要求进行隔离的授权；调用方无需选择创建还是复用、路径或分支。

明确记录 `scope_owner`、负责任何创建及尝试恢复的执行者（`creation_owner`），以及后续的
`integration_owner` 和 `cleanup_owner`。这些身份不会授予影响权限。本技能不负责实施、
提交、已完成改动的验证、集成、跟踪、清理、发布或远程操作。

## 确立边界

根据所属工作流和仓库当前的权威证据解析：

- 已接受的范围、`scope_owner`、隔离要求、确切的不可变基准提交和树，以及任何必要的基准沿袭关系；
- 仓库身份、源检出目录、解析后的 Git 公共目录、所有已登记工作树，以及当前的路径和分支约定；
- 生命周期责任归属，以及调用方对所选路径或分支施加的任何约束；以及
- 可用于创建、目标准备、基线验证、恢复以及每项外部或持久影响的权限。

当前分支顶端、可见约定、既有工作树或责任方身份都只是证据，不是权限。范围、基准、责任归属或
权限存在实质性歧义时，在执行受影响的操作前返回 `non-ready`。

变更前捕获足够的当前状态，以便归因每一项可能的影响：操作能够触及的每个检出目录的身份和本地
状态；受影响的引用和 Git 公共管理状态；拟定目标；以及每个已声明的文件系统、子进程、外部或
持久影响目标。保全所有预先存在的已暂存、未暂存、未跟踪及无关状态。源检出目录的分支、`HEAD`、
树、索引和本地内容必须保持完全不变；在已授权的目标或影响范围之外，每个观察到的项目都必须
保持完全不变。只要某项操作会覆盖、藏匿、重置、清理或丢弃既有状态，就应采用非破坏性的替代方案。

**完成条件：**范围和基准均已明确，潜在影响边界可观察，而且每项可能的变更都有适用的责任方和授权。

## 选择一个目标

检查当前登记、分支、路径、交接和范围责任归属；如果某个既有关联工作树对已接受范围而言是唯一
安全的选择，则选择复用。证明其物理路径和 Git 公共目录、登记、具名分支/引用、`HEAD`、树、
索引、完整本地状态、基准沿袭关系和生命周期处置。由已接受的不可变基准和必要沿袭关系定义的
目标专属比较范围内，每个提交都必须能归因于此范围；复用会使用的每项本地状态也必须如此归因。
不可变基准之前、可从基准到达的历史不在此归因检查范围内。当前的身份和责任归属已经足够；不要求
提供历史创建者身份。绝不能接纳、修复、重置、清理或改作他用任何有歧义或无关的状态。

否则选择创建。适用时遵循目标或宿主当前自有的路径和分支约定。如果没有适用约定且授权允许选择，
则根据范围派生有效且唯一的路径和具名分支。使用当前文件系统和 Git 接口验证两者，包括物理路径
别名、符号链接、联接点或重解析点、登记和引用冲突。嵌套于另一检出目录之下的目标，只有在它已被
排除在该检出目录的已跟踪与未跟踪表面之外，且创建不会改变周边状态时才符合条件；不得通过编辑忽略
规则使其符合条件。只要仓库身份和权限均已证明，外部目标或同级目标也有效。

冻结选定模式、词法和物理路径、分支/引用、基准以及预期本地状态。复用不允许创建登记或分支。
创建要求路径、分支和登记均不存在，并采用不会覆盖现有内容的机制；强制、重置、替换或复用分支
不属于本契约。如果仍有多个实质不同的选择，且证据无法安全地选出一个，则返回 `non-ready`，
并说明决策责任方和可选项。

**完成条件：**已冻结恰好一个不存在冲突的目标身份，而且将被保留或使用的每个既有项目均已证明
其范围和生命周期责任归属。

## 建立新的工作树

对于创建模式，使用时解析实际的工作树创建机制。调用该机制前，闭合其完整影响范围，包括目标检出
目录的填充、分支/引用和 Git 公共管理状态、已配置的钩子、过滤器与子进程，以及它们可能引发的任何
凭据、网络、服务或其他外部或持久影响。要求对确切路径、引用和每项适用影响具有权限。影响边界无法
取得或尚未解析时返回 `non-ready`；一般性的工作树创建请求不会默许无关影响。

尝试前一刻，重新检查不可变基准、源目录保全边界、目标路径和分支不存在、登记集合、机制与授权。
只能使用适用的宿主原生接口或 Git 工作树接口，并采用会拒绝冲突的语义。每次成功、失败或中断之后，
都要先检查尝试的完整影响范围和 Git 状态，再判断发生了什么。一次成功的尝试必须证明：选定物理路径
上恰好有一项登记；它使用选定的具名分支和引用；其 `HEAD` 和树与不可变基准完全一致；且只有已获
授权的创建影响。

尝试失败或结果不确定时，保留所有产物；只有当前证据证明某项产物完全由该次尝试创建、不含用户或
无关工作，而且确切的恢复授权允许移除它，才可将其移除。只有机制所有者支持根据观察到的状态再次
尝试、恢复操作已还原完整的尝试前边界，而且所有创建关卡都再次通过时，才可重试。不要重复一次没有任何
变化的失败。意外、超出影响范围、存在歧义或无法观察的影响均以 `non-ready` 结束，并保留产物和恢复证据。

对于复用模式，不执行任何建立变更。准备前一刻重新检查其冻结身份和本地状态；发生漂移或责任归属
存在歧义时返回 `non-ready`。

## 准备并证明就绪

如果当前目标的证据表明 `worktree-environment-setup` 适用，则调用这个由目标方所有的依赖项。提供选定的确切根目录
以及已接受的设置影响权限；该依赖项负责自己的命令选择、影响核算、恢复和 Git 保全证明。不要复现
它的内部流程。只接受它返回的确切 `environment-ready` 或 `environment-non-ready` 结果。
有充分证据证明其不存在时记为 `not-required`；任何其他无法取得、有歧义、失败、中断或非就绪结果都要
在运行基线前停止。

然后在选定的物理根目录中解析并运行仓库当前自有的基线。执行前冻结其调用、目标绑定、成功条件和
完整影响范围；要求每项变更或外部影响都有确切权限。不得臆造基线，也不得以已完成改动的验证替代
基线。通过与就绪状态兼容。观察到的确切失败只有在用户明确接受后才与就绪状态兼容；已经证明的
基线不存在，需要用户或所属工作流明确接受。

每次准备操作或基线尝试后，重新检查其影响范围、所有可能受影响的既有状态以及目标身份。选定的分支或
引用、`HEAD`、树和索引必须保持完全不变；本地新增项必须归属于此范围、符合预期且已经获授权。
当影响、结果或保全证明未经授权、无法解释、超出范围或不完整时，保留部分状态或不确定状态并返回
`non-ready`。

只有在以下条件全部满足时才返回 `ready`：选择或创建身份仍然有效；所有无关状态均已保全；每项
实际影响均有责任方且已经获授权；设置结果为 `environment-ready` 或 `not-required`；基线已经
通过或已取得对其确切结果所需的接受；生命周期责任方均已知；且最终就绪快照完整。所有其他退出均为
`non-ready`。除上文明示的尝试恢复外，保留选定的工作树和残余状态，交由其责任方处理。

## 交接

返回一份紧凑的机械式交接，其中包含：

- 状态、确切的终止原因、已接受的范围、`scope_owner`、模式和选择理由；
- 仓库和 Git 公共目录身份；不可变基准和沿袭关系；选定的词法与物理根目录、登记、具名分支/引用、
  `HEAD`、树、索引以及归属于范围的本地状态；
- 尝试创建时的 `creation_owner`、`integration_owner` 和 `cleanup_owner`；
- 最终保全判定、已授权和实际影响，以及保留状态或残余状态；
- 确切的环境结果及其证据，以及基线调用、结果、影响和任何已经接受的失败结果或不存在情况；以及
- 就绪快照的观察边界；对于 `non-ready`，还包括失败边界、未解析或部分完成的影响、下一责任方和
  一项确切的后续操作。

使用确切的观察结果，而不是推断值。使用方只有在首次变更前一刻重新检查目标的物理身份、登记、
分支/引用、`HEAD`、树、索引和本地状态快照后，才能使用处于 `ready` 状态的目标。发生漂移就会
使此次使用失效，并要求重新进行复用评估；后续已获授权的工作不会追溯改变本次运行的结果。交接只
记录已经提供的权限，不授予任何权限。
