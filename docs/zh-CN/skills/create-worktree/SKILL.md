# 创建工作树

选择、建立并准备恰好一个 Git 链接工作树，然后返回其当前的 `ready` 或 `non-ready` 结果。调用方负责实现范围和要求隔离的权限；本 Skill 负责目标选择、创建、验证和就绪判断。

明确记录已接受范围及其 `scope_owner`。对于创建尝试，还要将对该尝试和获准恢复负责的参与者记为 `creation_owner`。这些角色用于记录责任；每项效果仍须获得其所有者的明确授权。实现、提交、已完成变更验证、集成、跟踪、生命周期清理、发布和远程操作仍由其既定所有者负责。

## 原则

- **一个确切目标。**一个结果只涵盖一个链接工作树，其仓库身份、物理位置、注册、分支或引用、基点和所属本地状态均须得到证明。
- **默认保留。**保护所有既有、无关和用户所有的状态。若某项操作会覆盖、暂存、重置、清理或丢弃这些状态，应优先选择非破坏性目标。
- **效果需要权限。**在文件系统、Git 公共目录、子进程、凭据、网络、服务和其他持久效果发生前，界定范围并获得授权。
- **不确定性保持可见。**保留部分或模糊状态，直到当前证据和确切恢复授权使清理变得安全。
- **就绪状态具有时效性。** `ready` 描述记录下来的观察边界，而不是永久有效的声明。

## 1. 建立安全边界

解析已接受范围、`scope_owner`、隔离要求、不可变基点提交和树，以及任何必要的基点谱系。确定仓库身份、源检出、Git 公共目录的物理位置、已注册工作树、当前路径和分支约定、调用方约束、既有目标状态的所有权，以及创建、准备、基线检查、恢复和每项外部或持久效果的权限。分支尖端、约定、既有工作树或所有者身份只是证据，不是权限。实质性歧义会在受影响操作前产生 `non-ready`。

变更前，冻结某项操作可能写入、覆盖或删除，或者恢复必须还原的确切路径、引用、注册和 Git 管理状态。对于该写入与恢复集合中的已提交和已暂存内容，记录提交对象 ID 和受影响的索引条目。对于每个非索引项——包括受跟踪但未暂存、未跟踪和忽略的内容——记录文件类型、模式、符号链接目标、大小和内容哈希。只有在既有路径处于风险中且获准恢复可能需要还原它时，才保留原始字节。

对于所有其他检出状态，根据操作语义、已解析的物理边界，以及有界的仓库身份和状态证据，证明操作无法触达。只有当具体别名、配置、钩子、过滤器或子进程形成触达该状态的合理路径时，才扩大观察范围，并记录每个适用的子进程、外部或持久目标。只有当范围和基点精确、完整的潜在效果边界可观察，并且每项可能的变更都有所有者和授权时，才能继续。

## 2. 选择复用或创建

只有一个既有链接工作树对该范围具有唯一安全性时，才选择**复用**。证明其词法和物理路径、Git 公共目录、注册、命名分支或引用、`HEAD`、树、索引身份、基点谱系和当前所有权。由不可变基点和必要谱系界定的目标专属比较范围内，每个提交以及复用会使用的每项本地状态都必须可归因于本范围。不可变基点之前且可由基点到达的历史不在此测试内。通过安全边界保护复用所使用、写入和恢复路径之外的状态。绝不采用、修复、重置、清理或改作他用任何模糊或无关状态。

否则选择**创建**。遵循适用的目标或主机所有路径及分支约定；若没有适用约定且选择已获授权，则从范围派生有效且唯一的路径和命名分支。通过当前文件系统和 Git 接口验证两者，包括物理别名、符号链接、接合点或重解析点、注册和引用冲突。嵌套在另一检出下的路径，只有在它已被排除于该检出的受跟踪和未跟踪表面之外，并且创建不会改变周边状态时才可使用；忽略规则保持不变。外部或同级路径需要已证明的仓库身份和权限。

冻结模式、词法与物理路径、分支或引用、基点，以及预计会使用或影响的本地状态。复用不允许创建注册或分支。创建要求路径、分支和注册均不存在，并采用拒绝冲突的机制；强制、重置、替换和分支复用不在本契约内。若仍有实质不同的选择且证据无法选定一个，则返回 `non-ready`，并给出决策所有者和各项选择。只有一个无冲突目标，并且其会使用或影响的既有状态已证明属于本范围时，才能继续。

## 3. 建立所选工作树

对于**复用**，不执行建立变更。准备前立即重新检查其冻结身份，以及它会使用或可能影响的每项本地状态。发生漂移或所有权模糊时返回 `non-ready`。

对于**创建**：

1. 从当前语义和配置解析实际创建机制及其效果。包括检出内容填充、分支或引用及 Git 公共管理状态，以及适用的钩子、过滤器或子进程；沿这些集成继续追踪，直到识别重要的文件系统、凭据、网络、服务和持久效果。要求路径、引用和每项效果均获授权。无法解析或观察的重要边界产生 `non-ready`。
2. 尝试前立即重新检查不可变基点、源状态保留边界、路径和分支不存在、注册、机制及授权。只以拒绝冲突的语义调用适用的主机原生接口或 Git 工作树接口。
3. 无论成功、失败或中断，都要重新观察冻结效果边界，再判断实际发生了什么。成功要求所选物理路径恰好有一项注册，其命名分支及引用、`HEAD` 和树位于不可变基点，并且只发生了获准效果。
4. 尝试未成功或结果不确定后，保留每项产物，除非当前证据证明它完全由本次尝试产生、不含用户或无关工作，并且确切恢复授权允许删除。只有当机制所有者支持从观察到的状态重复执行、恢复能还原完整尝试前边界，并且每项创建门槛再次通过时，才可重试。同一失败不重复重试。意外、未授权、模糊或无法观察的效果会以 `non-ready` 结束，同时保留产物和恢复证据。

## 4. 准备环境并检查基线

当前目标证据声明 `worktree-environment-setup` 适用时，以所选确切根目录和已接受的设置效果权限调用该目标所有的 Skill。命令选择、效果核对、恢复和 Git 状态保留由它负责；这里只使用 `environment-ready` 或 `environment-non-ready` 结果，不复制其流程。只有当前目标证据证明无需准备时，才记录 `not-required`。适用能力缺失或不可用，或者结果模糊、失败、中断或为 `environment-non-ready`，都会在基线检查前以 `non-ready` 结束。

得到受支持的 `not-required` 或 `environment-ready` 后，选择负担最小且能覆盖每项已接受的重要工作树和环境风险的仓库所有基线检查或检查集合。仓库证据要求强制规范基线时使用它；否则选择最窄的受支持覆盖，只报告非关键缺口。冻结每次调用、目标绑定、成功条件和效果集合；每项变更或外部效果都需要确切权限。不得发明基线，也不得用它替代已完成变更验证。

检查通过与就绪兼容。确切观察到的失败需要用户明确接受。已证明不存在检查，或存在未覆盖的重要就绪风险时，需要用户或所属工作流明确接受。每次准备或基线尝试后，重新观察其效果集合，调查意外变更，并重新检查目标身份。分支或引用、`HEAD`、树和索引必须保持精确；本地新增项必须符合预期、已获授权且属于本范围。未授权、无法解释、越界或观察不完整的效果或结果都会产生 `non-ready`，并保留部分和不确定状态。

## 5. 返回最新就绪结果

只有在目标身份为当前状态、无关状态得到保留、每项效果都有所有者且已获授权并被完整观察、环境设置为 `environment-ready` 或受支持的 `not-required`、基线通过或取得确切的必要接受，并且最终就绪快照完整时，才返回 `ready`。其他所有结果都是 `non-ready`。除上述获准的尝试恢复外，为当前所有者保留所选工作树和残留状态。

返回一份紧凑交接，其中包含状态和终止原因；已接受范围、`scope_owner`、模式及理由；仓库和 Git 公共目录身份；不可变基点和谱系；词法与物理根目录、注册、命名分支或引用、`HEAD`、树、索引和本范围所有的本地状态；适用时的 `creation_owner` 和恢复处置；保留判定；获准和实际效果；保留状态；确切环境与基线证据，包括任何已接受的失败或缺失；以及观察边界。对于 `non-ready`，还要指出失败边界、部分效果、下一位所有者和确切下一步操作。

使用观察值，不使用推断值。首次变更前，调用方重新检查物理身份、注册、分支或引用、`HEAD`、树、索引和范围内本地状态快照。任何漂移都需要基于当前证据重新执行 `create-worktree` 评估，并再次选择复用或创建。后续工作流和最终化流程会建立各自的当前契约；所有效果仍受其原始授权约束。
