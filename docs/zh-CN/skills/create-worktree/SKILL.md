# 创建 Worktree

选择或创建一个关联 Git worktree，并在不干扰已有工作的前提下确立其 Agent 配置和环境就绪状态。返回 `ready` 或 `non-ready`。默认携带源的当前工作；继承修改按原所有权受到保护，不自动成为调用方的任务内容。

## 1. 选择工作区和起始状态

从已经确立的隔离需要和已接受任务范围出发。沿用已有的源、目标、基线和允许影响选择。复用已涵盖本次操作的决定；尚有必要选择或权限未明确时再询问。通过仓库拓扑解析源检出、主项目检出和实际 Git 公共目录；发起调用的关联检出不一定是主检出。

创建 worktree 前，检查已有任务 worktree 能否承载已接受的工作。将候选项的实际路径、Git 登记、分支、`HEAD`、基线关系和本地修改与任务上下文核对。一致时复用，并保留继承及任务修改。不将其他任务的 worktree 改作他用，也不将源的新修改覆盖到继续使用的 worktree。已选 worktree 的身份或所有权不清时，返回 `non-ready`；否则跳过创建，评估配置和环境就绪状态。

新建 worktree 时，将基线解析为不可变提交，并选择起始状态：

| 模式 | 起始状态和决定 |
| --- | --- |
| **携带** | 默认：源 `HEAD` 加上暂存、未暂存和未跟踪且未被忽略的修改，保留各层区别。 |
| **干净** | 必须明确选择：选定基线，不携带源修改。 |

使用不同基线时，需要明确选择干净模式，或约定兼容的携带语义。继续前确定携带修改如何应用到该基线；选择基线本身不授权复制来自另一基线的修改。要求仅有任务自有状态的调用方可以拒绝继承工作，但这不授权丢弃它，也不授权改变默认携带模式。

## 2. 确定位置与携带决定

### 位置

遵循明确指定的目标路径。否则优先选择 `<primary-project-root>/.worktrees/<task>`，并使用已有有效的 `.worktrees` 容器。无效条目、不安全的实际路径别名或受跟踪内容冲突，都需要解决，不能退回另一位置。

容器不存在且位置未决定时，给出以下恰好两个选项的具体目标路径，让用户选择：

1. `<primary-project-root>/.worktrees/<task>`，配合本地 Git 排除。
2. 插件持久的 `data/worktrees/<project-id>/<task>` 位置。

从权威宿主或配置输入解析插件数据根目录。在 Codex 上，SmartKit 约定为 `<resolved-codex-configuration-root>/plugins/data/smartkit/worktrees/<project-id>/<task>`。项目 ID 使用 `<project-name>-<short-hash-of-canonical-git-common-dir>`，让关联 worktree 共享位置，同时区分同名克隆。这是 SmartKit 约定，不是宿主官方能力。其他宿主没有已知持久根目录时，先取得该位置，再提供第二条路径。worktree 应放在版本化插件缓存和 Skill 安装目录之外。

选择唯一任务路径和命名分支。验证路径、分支及 worktree 登记均不存在；解析实际路径，避免别名或递归嵌套到发起调用的 worktree 下。保留已有分支，不将其改作他用。

放在项目内时，验证 Git 排除实际生效。必要时通过 Git 解析本地 `info/exclude`，仅添加 `/.worktrees/`，保留其他字节和共享 `.gitignore`。位置选择在调用方影响约束内授权这项本地排除。位置与携带决定均明确后，才能修改容器或排除配置。

### 源保护与携带

两种模式都要充分记录源的 `HEAD`、分支、索引、工作内容及未跟踪且未被忽略的状态，以验证创建后它们不变。索引冲突未解决、操作进行中，或文件、索引语义不受支持时，停止创建，除非选定机制能忠实保留该状态。

**干净** 模式跳过传递捕获、计数和携带审批。 **携带** 模式分别捕获暂存和未暂存修改，包括两者影响同一路径的情况，并捕获未跟踪输入。保留内容、新增、删除、重命名、二进制文件、执行模式和符号链接。排除忽略文件、依赖缓存和嵌套 worktree；必要的 Agent 配置通过下文配置准备提供，其他必要但省略的输入交给环境准备。复制前确定预期目标状态，包括约定的跨基线转换。

### 携带计数与审批

统计暂存和未暂存差异及新增未跟踪文本的增加行数加删除行数。跨所有层对每个不同修改路径只计一次；二进制变化只计路径，不虚构行数。

创建或复制前，如果 **行数 >= 300 或路径数 >= 10** ，展示源、目标、计数和携带状态，然后取得明确携带决定，除非该快照和目标已有相应决定。披露无法衡量的项目，并取得涵盖它们的决定；不能按零处理。两项均低于阈值时，按默认携带继续并报告计数。

已审阅快照或目标发生实质变化时，需要新的摘要和决定。用户拒绝携带时，取得明确的干净 `HEAD`/基线选择，或取消；沉默不是批准。

## 3. 创建并验证

创建前立即重新检查源快照、选定基线和模式、决定，以及目标路径、分支和登记不存在。使用宿主适用的创建接口，或采用遇冲突拒绝执行的 Git 方式。运行前，在允许操作范围内交代重要 Hook、过滤器和子进程影响。

在选定提交创建。干净模式在这次传递中不复制源修改；后续配置和环境准备各自遵循已接受的范围。携带模式重现捕获的索引和工作状态，包括未跟踪输入。保持源字节、索引、`HEAD` 和分支不变：stash、commit、reset 和移动源文件都不是传递方法。

验证登记的目标路径、命名分支，以及 `HEAD` 位于选定基线。将其索引和工作状态与预期结果比较，包括文件内容、类型、模式，以及暂存和未暂存区别。比较索引语义，不比较二进制索引扩展元数据。确认源未改变，容器、排除和创建影响符合选择计划。漂移或比较不完整时，返回 `non-ready`。

### 中断后安全继续

中断或失败后，重试前检查实际存在的状态。保留部分路径、分支、登记和复制工作，以及足够安全继续的上下文；不将复制操作重放覆盖到后续修改。只有部分产物完全属于本次尝试、不含其他工作且删除获授权时，才能移除。恢复前重新检查适用选择。

## 4. 确立 Agent 配置就绪状态

发现目标项目 Skills 前，确定已接受任务需要哪些项目指令、Rules、Skills、自定义 Agents、MCP 声明和宿主设置。先检查选定 worktree，复用时保留其中可用的配置。不需要项目配置时，将配置状态报告为 `not-needed` 并继续。

由 Git 共享的配置（`local`）随检出或携带提供，无需额外传递。对于 `local-only` 和 `repository`，使用已接受且完成初始化的源检出，并遵循 [Worktree 配置](references/configuration.md) 准备缺少的配置，以及处理链接配置或配置副本的后续编辑与清理。通过 Git 拓扑解析对应项目目录；源不必是物理父目录。代码和项目操作仍以选定 worktree 为根。

在调用方已接受的权限内，将配置准备与干净或携带传递分别处理。保留目标中可用的配置。缺少必要的源内容、范围或冲突未解决，或准备未完成时，返回 `non-ready`；保留 worktree 并报告需要解决的事项。

通过当前宿主支持的加载路径提供选定配置。环境准备前，验证必要指令和 Skills 能针对目标解析，且准备所需的设置和能力可用。复用仍然适用的证据。复制的文件、setup 标记或同步回执本身不能证明已激活；需要重新加载宿主、作出信任决定，或准备能力不可用时，返回 `non-ready` 并说明下一步。某项任务必需能力依赖项目环境准备时，在准备完成后、返回 `ready` 前验证它。

## 5. 评估环境就绪状态

在新建 worktree 首次使用、有证据表明当前任务所需环境前提缺失或过时，或用户明确请求准备时，需要环境准备。否则报告 `not-needed` 并使用现有环境。仅位于 linked worktree 中或缓存准备记录失效，并不能确立准备需要。

需要准备时，发现选定目标的项目 `prepare-worktree-environment` Skill。若存在，在已接受的准备权限内调用，并将继承修改标为受保护；也可复用对该目标仍有效的结果。使用其 `environment-ready` 或 `environment-non-ready` 结果。必要 Skill 不可用，或准备失败、中断、结果仍有歧义时，返回 `non-ready`。

Skill 不存在时，报告 `not-provided` 并跳过；已知不可缺少的输入或准备缺失，仍会阻止就绪。如果缺失的 Skill 不可替代，返回 `non-ready`，并说明应通过项目 setup 提供它。

对于已经使用 CodeGraph 的项目，如果选定工作树将用于持续实现和反复查询代码关系，为它准备本地索引。在首次使用或当前证据表明索引缺失、过时时进行准备，并复用最新的本地索引。短期审阅或一次性验证，不会仅因使用 worktree 就需要准备索引。

在已接受的本地准备权限内使用已安装的 CodeGraph CLI，并检查其版本和帮助以确认支持的接口。将 `<target-root>` 绑定到选定工作树的物理根目录。数据库保留在 `<target-root>/.codegraph/codegraph.db`，而非复制或链接另一棵树的索引。仅在该本地数据库缺失时初始化。对于现有数据库，先检查状态；只有状态表明它是当前这棵树的可用索引时，才同步待处理变更。索引身份不匹配或需要修复、重建时，保留并报告：

```text
codegraph init "<target-root>"
codegraph status "<target-root>" --json
codegraph sync "<target-root>"
```

这些操作按条件选择，不是每次进入都依次执行。Status 和 sync 可能解析到父树索引，因此 sync 前必须确认本地数据库存在，且状态中的 `projectPath` 匹配。交互选择限定为本地索引和手动同步；拒绝安装 hook 或扩大扫描范围。核算工具自有的 `.codegraph` 元数据更新，包括状态检查期间的更新。索引操作后重新检查状态，确认报告的项目和工作树身份与目标匹配，且索引已完整建立。后续 CodeGraph 查询必须通过 `projectPath` 明确指定这棵树。此分支既不安装 CodeGraph，也不配置或管理其服务。

除非已接受任务要求 CodeGraph，否则将此分支视为辅助能力。工具不可用或准备失败时，保留现有及部分索引状态，报告缺口，并在足以完成工作时继续直接检查源码；仅此问题不会改变项目环境结果，也不会使工作区变为 `non-ready`。真正属于任务必需能力的 CodeGraph，遵循下文的必要能力检查。在交接中说明它是已准备、已复用、已跳过还是不可用。

准备完成后，验证其余任务必需的宿主设置和 MCP 能力，包括它们的项目操作是否指向此 worktree。只有必要配置可用时，才将配置状态报告为 `ready`；激活尚未完成或必要能力不可用时，返回 `non-ready` 并说明下一步。

各项评估及任何准备完成后，重新检查目标身份和预期状态，并核算获授权修改。只有创建或复用已验证、已有工作保留、配置状态为 `ready` 或 `not-needed`、环境状态为 `environment-ready`、`not-needed` 或 `not-provided`，且不再有未解决选择、未授权影响或不可缺少前提时，才返回 `ready`。否则返回 `non-ready`，并保留工作区与部分状态，以便安全继续。

向调用方提供简洁的就绪交接：

- 状态、目标路径、分支、不可变基线和当前 `HEAD`。
- worktree 是新建还是复用，携带或继承状态摘要及携带决定，配置来源和范围、链接或副本的来源记录及就绪状态，以及环境状态。
- 对于 `non-ready`，说明阻塞点、保留的部分状态和具体下一步。

保留支撑观察；交接不必复述完整证据清单。

就绪涵盖工作区及其准备，不代表项目健康。本 Skill 不运行项目基线、构建或测试检查。这些检查和提交决定由实现工作流负责；携带继承工作不授权提交它。使用返回工作区前，重新检查当前身份和状态，并调查意外漂移。
