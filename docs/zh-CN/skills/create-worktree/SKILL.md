# 创建 Worktree

此流程主导型技能创建或复用一个具名关联的 Git 工作树，并在保留基点分支、索引和
既有本地状态的同时，为所属实施范围做好准备。它负责工作树的选择、创建、验证、
就绪和机械性所有权交接。它不把范围分类为 task、工单或批次。业务实施、已完成改动的
集成、跟踪器状态和清理仍由各自归属负责。

## 建立准备契约

1. 记录已接受的实施范围、调用方提供的 `scope_owner`、预期路径或小写连字符 slug、
   具名分支、准确基点提交、后续的 `integration_owner` 和 `cleanup_owner`、智能体宿主是否已经
   创建预期工作树；如果已经创建，还要记录调用方提供的 `creation_owner`。
2. 根据调用方提供的准确基点提交，解析一个基点检出目录和具名基点分支。检查当前分支
   和 `HEAD`、Git common directory 以及 `git worktree list --porcelain`；预期基点处于 detached
   状态或存在歧义，或者解析结果与所提供提交不同时停止。不得用当前分支 tip 替代它。
3. 修改前，快照基点检出目录的分支、`HEAD`、提交树、索引树、已暂存、
   未暂存和未跟踪状态，以及所有已注册工作树和本地分支。此快照是保留边界
   和已接受的就绪基点。

## 选择并验证 Worktree

1. 只有所属工作流为准确的实施范围选择了当前关联的工作树时，才复用它。
   要求其具名分支、`HEAD`、提交树和本地状态归属与准备契约匹配；否则停止且不提供
   就绪结果。
2. 对新工作树，选择 `<base-root>/.worktrees/<slug>`，并遵循已验证的仓库分支约定；没有约定时
   回退为 `worktree/<slug>`。验证分支名，并要求该路径和分支在文件系统、已注册工作树
   和本地分支中都不存在。
3. 对 `<base-root>/.worktrees/` 下每个选定路径，无论复用还是新建，都要求根 `.gitignore` 包含有效的
   仓库相对 `.worktrees/` 条目。条目缺失或无效时，只有 `.gitignore` 归项目所有，并且该编辑能够
   保留、区分全部既有内容和本地状态，才追加 `.worktrees/` 作为最小有效修复；把它记录为有意的
   项目自有改动。文件为生成的、只读、归属不明确，或编辑会与无法区分的本地
   工作重叠时停止。
4. 使用 `git check-ignore -v` 证明每个选定的仓库相对 `.worktrees/` 路径都被根 `.gitignore` 忽略；
   global exclude 或 `.git/info/exclude` 不充分。对新工作树，取得准确选定目录和工作树所需的
   权限。该权限不授权任何无关 Git 或文件系统改动。

## 创建并验证

1. 创建前立即根据已记录契约复核基点分支、`HEAD`、提交树、路径和分支。任何值已移动或
   出现时，在创建前停止，并报告记录值、当前值和保留的快照。
2. 智能体宿主的原生工作树创建能力可用时，使用它并把其具体 lifecycle 归属记录为
   `creation_owner`。只有该能力不可用时，才使用 Git 后备方案，并把执行
   `git -C <base-root> worktree add -b <branch> <worktree-path> <base-commit>` 的具体智能体记录为
   `creation_owner`。
3. 使用 `git worktree list --porcelain` 验证路径、分支和 `HEAD` 等于选定值。复核基点检出目录
   的 `HEAD`、提交树、索引树和既有本地状态与快照匹配；只允许已记录的
   `.worktrees/` `.gitignore` 添加。
4. 创建失败时，检查 Git 工作树 metadata 和选定路径。只移除已证明由本次尝试创建且不含用户工作
   的不完整 artifact。无法证明时，保留证据，并以准确恢复归属和操作停止。安全
   移除后，重复创建前检查并重试一次。第二次失败时保留全部剩余证据并停止。

## 准备并建立就绪状态

1. 在选定工作树中继续。目标仓库提供 `worktree-environment-setup` 时，在基线验证前应用。
2. environment 准备后，运行仓库声明的基线验证。失败的基线是既有证据：除非用户
   明确接受它用于此工作树，否则在实施前停止。未声明基线时，除非所属工作流或用户明确
   接受基线不可用，否则停止且不提供就绪。不得用已完成改动的验证代替，也不得臆造命令。
3. 只有工作树有一个具名分支、其 `HEAD` 和提交树等于已接受基点、基线通过或已
   明确接受，并且每个本地路径都只属于已接受实施范围时，才报告工作树就绪。
4. 保留每个失败工作树供诊断，不自动丢弃证据。

## 结果

返回一份准备工作交接，其中包含 `status`；已接受实施范围；选定 `worktree`、
`branch`、准确 `head` 和准确 `tree`；基点检出目录、分支、准确提交和树以及保留的本地状态；
`scope_owner`、`creation_owner`、`integration_owner` 和 `cleanup_owner`；预期路径或 slug、
`.gitignore` 结果和允许的本地状态范围；environment setup 和基线命令、结果及已接受失败；
就绪结果和原因；不就绪时还包含保留的状态、失败 phase 和下一个归属。调用方在实施或
收尾前复核交接。交接不授予其记录值以外的任何权限。
