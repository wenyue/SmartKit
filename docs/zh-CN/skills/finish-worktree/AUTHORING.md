# 编写决策

## 保留独立的结果路线

发布、fast-forward 合入、工作文件转移、保留和丢弃具有不同的接受条件与损失边界。入口负责选择路线并共享中断及清理策略；每份引用文档负责特定效果的流程。路线失败不能默默变成另一种去向。

## 按原始基线转移修改

转回供审阅需要区分 B、S 和 W，并保留目标的完整索引。用目标当前 HEAD 替换 B，或复制整个源目录，都会导致丢失目标演进或转移无关工作。这一路线必须在不提交、不合入的前提下组合工作，因此明确的三方模型值得保留这些细节。

## 改变历史之前先保留恢复手段

历史整合在 detached HEAD 上构建候选，使用正常 hooks，验证后才以预期旧 OID 更新分支。这些步骤保护原分支免受 hook 失败或并发移动的影响。交付、清理和恢复保持各自可观测，避免部分失败导致重复合入。
