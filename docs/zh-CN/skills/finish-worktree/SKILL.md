# 工作树收尾

为一棵隔离工作树完成选定结果，并可靠地说明剩余事项。实施工作流负责修改已接受的结果、验证和正式审查；
本 Skill 负责选定的交接或交付、可选的历史准备，以及相应的恢复和清理。工作项关闭仍由既有负责人处理。

## 原则

- **结果优先。**只要求选定操作所需的证据与权限。保留未完成工作和转移改动，本身就是有用的结果。
- **保护归属。**区分任务改动与用户状态。跨边界传递的只能是已接受的任务改动；归属不明的内容予以保留。
- **复用有效证据。**将证据绑定到它所证明的状态与影响。依赖发生变化时才更新证据，不重复无关证明。
- **保留已证实结果。**后续失败不能抹去已经证实的历史结果、发布、交接或交付。根据观察恢复原来未完成的操作。

## 确定任务

识别来源的物理路径、关联工作树注册信息、共同仓库、分支及当前 `HEAD`；继续前先解决身份被替换或不明确的问题。
确定已接受的范围、本地状态归属、选定结果，以及此前尝试中尚未解决的影响。此前的 `create-worktree` 结果可以帮助
定位任务，当前 Git 证据才负责证明其状态。

从已接受的请求与适用项目规则中确定权限。创建 PR 的请求授权必要的发布；转移改动的请求授权有界的转移及其保护性
准备。复用已经授予的权限。只有缺少实质性选择或影响授权时才询问，例如目标尚未确定，或实际损失超出明确丢弃请求。
归属不明的状态应安全保留。独立适用的项目规则或调用方规则，可以要求比这里的路径更严格的验证或审查。

选定一个结果，并完整阅读其引用契约。结果不明确时，应在修改状态前解决；不得暗中用转移代替整合，也不得用丢弃
代替清理。

| 结果 | 契约 |
| --- | --- |
| `keep-for-later` | [按现状保留工作](references/keep-for-later.md)，包括未完成工作和脏状态。 |
| `create-pull-request` | [发布准确的已审查提交并建立 PR](references/create-pull-request.md)。 |
| `merge-locally` | [快进已授权的本地目标](references/merge-local.md)。 |
| `return-for-review` | [将任务改动转回检出目录](references/return-for-review.md)，保留其 HEAD 和完整暂存区。 |
| 明确丢弃 | [仅移除已授权且已观察到的损失](references/discard.md)。 |

默认保留提交。发布、整合，或用户明确要求、项目规则要求整理提交时，阅读[历史准备](references/history.md)。
保留和转移通常返回 `history_result: inapplicable`；它们不需要重写历史，也不统一要求正式审查。即使与保留或转移
配合执行，明确选定的整理操作仍使用历史契约。

## 执行与收尾

选定路径负责定义自身的就绪条件和成功证明。原生 Git 与仓库的宿主接口负责确定性取证和有界操作；智能体负责判断
意图、归属、语义兼容性和权限。首次产生影响前，只阅读[操作记录](references/recovery.md#operation-receipt)和
[继续未完成的操作](references/recovery.md#resume-the-incomplete-effect)，再创建小型外部操作记录。该引用中的机制
章节，仅在选定路径需要时加载。只读保留结果使用返回记录即可。在同一状态上开始另一项操作之前，先通过该引用处理
尚未解决的原始尝试。

一次性采集选定写入集及其依赖。在批次边界使用共用证明，在有界批次内部使用相关路径保护。每项操作前立即更新它依赖的可变事实：身份、相关引用、暂存区、受影响文件、宿主状态，
以及对新发现损失的权限。操作后观察它可能改变的内容。不可变提交、树和审查证据在依赖仍匹配时继续有效；内容改变后，
将验证与审查交回实施负责人。观察到漂移时，停止依赖该状态的操作，并保留已完成阶段。

清理遵循已经证实的结果专属处置。保留脏来源；最终清理不能授权丢失其中的内容。只有满足选定路径的保留条件、
生命周期和保留负责人均已解除保留要求、且移除已获授权的准确归属项，才可以删除。删除可能触及忽略内容时，先清点
这些内容。宿主创建的工作树由宿主移除。分支不再被任何工作树使用时才可删除；删除自有分支或恢复引用应使用预期旧 OID 更新。每项移除均视为独立、
可恢复的操作。带有负责人和解除保留条件的保留或委派，属于清理完成，不是错误。

按保持兼容的[公共结果契约](references/results.md)，返回选定路径、简明证据、保留位置和下一步操作。返回前阅读该引用，
包括停止或失败的情况。报告没有通过的必需检查，不得声称相应结果已经证实。
