# 完成工作树

根据当前证据结束一个隔离工作树作业。实施工作流负责范围、验证和正式审查；本技能负责历史定型、选定结果、恢复及已授权的清理。它不负责跟踪器状态转换，也不调整已接受的结果。

明确要求丢弃准确本地状态时，进入 [`references/discard.md`](references/discard.md) 中单独的破坏性路径，并在该路径结束。否则，遵循本契约。

一个**逻辑效果尝试**是最小的已授权修改单元，其子操作共享一次重试或恢复决定。为该父尝试赋予一个身份和修改前状态。命令或逐路径写入继承父尝试身份，不具有独立的重试身份，并且只以已完成、已跳过、进行中、有歧义或有残留的子效果出现在父尝试账本中。仅当选定分支契约明确赋予某个子操作单独的重试或恢复决定时，该子操作才成为另一个逻辑尝试。切勿把辅助程序拆成逐命令尝试，也不要把受防护的批次拆成逐文件尝试。

只选择一个结果，并立即完整读取其参考文件：

| 结果 | 选定契约 | 分类 |
| --- | --- | --- |
| `merge-locally` | [`references/merge-local.md`](references/merge-local.md) | 整合性 |
| `create-pull-request` | [`references/create-pull-request.md`](references/create-pull-request.md) | 在权威目标包含结果之前为非整合性 |
| `keep-for-later` | [`references/keep-for-later.md`](references/keep-for-later.md) | 非整合性 |
| `return-for-review` | [`references/return-for-review.md`](references/return-for-review.md) | 非整合性 |

只为预检加载选定契约，并为本次运行冻结该契约；未选定的参考文件保持未加载。选定契约的完整输入、授权、成功证明、恢复、保留和效果边界必须在 Ready 之前纳入通用契约。此时不要执行任何分支步骤；后续执行使用同一个已冻结的分支契约。

每个出口都返回 `history_result`、`outcome_result` 和 `cleanup_result`。每个阶段结果使用最小适用状态：

- `not-started`：未进入该阶段；指出导致这一结果的较早因果边界；
- `inapplicable`：固定契约证明该阶段不适用；
- `stopped`：某项前置条件或防护拒绝预期效果，且完整的事后普查证明该逻辑尝试没有产生效果；记录原因、账本、残留证据和下一责任方；或者
- `failed`：效果已经发生或仍有歧义，或所需的效果后证明失败；记录因果尝试身份、账本、残留状态和恢复责任方。此状态不包括已证明无效果的前置条件或防护拒绝。

只有历史和结果阶段可增加 `proven`；只有清理阶段可增加 `complete`。各自的正向载荷仍由证明该载荷的阶段定义。**`preflight`**是因果边界，而不是第四个阶段。在 Ready 之前停止时，三个阶段均返回 `not-started`，并返回 `causal_boundary: preflight`，同时记录被拒绝的前置条件或防护、没有发生任何阶段效果的证明，以及准确的下一责任方与操作；该边界直接推导出总体 `stopped`。历史尝试失败时，返回失败的 `history_result`，后续阶段返回 `not-started`。明确丢弃时，历史阶段返回 `inapplicable`。在存在已证明的历史或结果事实之前，分类为 `no positive result`。

## 固定收尾契约

要求一个准确的源工作树、目标和已授权结果。绑定：

- 源路径和分支；其 `create-worktree` ready 交接、创建与清理责任方、不可变基点、预期 `HEAD` 和树，以及完整的范围自有提交区间；
- 目标检出目录和分支、预期 `HEAD`、边界关系、目标移动时允许的响应，以及每个须保留的已暂存、未暂存、未跟踪、文件类型、模式和符号链接项；
- 验收来源和固定点；所需验证和正式 `code-review` 结果；二者准确的已审查 `HEAD` 和树；以及没有阻塞问题；
- `preserve-commits` 或 `consolidate-checkpoints`；且恰好选择一个结果——`merge-locally`、`create-pull-request`、`keep-for-later` 或 `return-for-review`——并纳入其选定契约中的每个值、授权、前置条件、可观察成功、恢复和保留要求；
- 发布证据、恢复引用的归属与保留、生命周期及效果授权、每个逻辑效果尝试的一个身份、清理权限、下一责任方，以及每个结果特有的值；以及
- 权威实施工作流，以及各依赖项可观察的不可用、已停止、已失败或有歧义结果。

调用方的断言是需要证明的输入。重新观察 Git、仓库和明确授权的宿主证据。解析两个物理路径、共同仓库、工作树注册信息、分支、提交、树、引用、发布和生命周期责任方。根据该状态复核 `create-worktree` 交接；源不可用、非 ready、过期、被替换、处于分离状态或存在多个身份时，停止收尾。

为每个受影响的检出目录创建快照，并说明区间内的每个提交和路径。将每个本地状态项分类为范围自有、无关或有歧义。在选定历史策略要求的地方，证明基点和目标边界为祖先。把验证和正式审查绑定到同一个验收固定点、已审查提交头和已审查树。缺少证据、存在阻塞问题、重叠不安全、某项操作所需的发布信息不完整，或归属有歧义时，在修改前停止，并返回准确的依赖责任方或决定责任方。

源必须干净。只有选定结果能够逐字节、逐索引地保留每个无关项时，脏目标才符合条件。记录足以供独立复核的命令、输出和对象 ID。

**Ready 条件：**完整的通用契约和选定结果契约、当前身份、已接受区间、审查绑定、保留边界、权限和结果输入准确且相互一致。在通过此门槛之前，不得修改历史或结果。

## 完成已审查历史的定型

紧接每个逻辑效果尝试之前，复核其完整子效果包络所需的每个身份、提交头、树、区间、本地状态、发布、权限和恢复谓词。一次性绑定父阶段、尝试身份、修改前状态和预期包络。尝试返回或中断后，对整个包络做一次普查，并写入父尝试账本。出现漂移即停止。中断或有歧义的尝试保持进行中：保留其状态并交给效果责任方，而不是改换目标或重试。

如果目标已移动，只有当契约允许重新绑定、新目标仍是已审查提交头的祖先，且重新计算的区间完全属于本范围时，才继续。只有结果唯一确定且已获授权时，才能运行仓库自有的同步流程。先建立恢复。任何同步或其他内容变化都会使验证和审查失效：把新的提交头和树交回实施工作流；在开始新的收尾尝试前，该工作流必须重新验证并正式审查。

改写历史前，测试权威结果目标是否已包含每项已接受效果。当当前祖先关系能够证明准确区间时，该证据已充分。否则，要求每项效果都有无歧义的等效变更证据，并在该目标状态上重新运行所需验证。空差异、相似消息、已移动的跟踪器状态或部分补丁均不充分。把成功证明记录为**已交付**，且不执行空的历史或交付修改。

应用固定历史策略：

- **保留提交：**重新枚举 `target..reviewed-head`；证明整个区间属于本范围，且源仍位于已审查提交头和树。该提交头就是交付提交头。只有已观察到的发布状态与选定结果兼容时，已发布提交才符合条件。
- **整合检查点：**要求整个区间未发布且无人依赖，并以准确目标为祖先。创建一个已授权的唯一恢复引用名称，以及一个符合仓库规范的消息文件；该文件中的交付提交消息必须由已接受的实施范围推导。然后运行一次本包脚本：

  ```text
  python <skill-root>/scripts/consolidate_worktree_history.py \
    --repository <source-worktree> \
    --target <exact-target-oid> \
    --message-file <message-file> \
    --recovery-ref <new-recovery-ref>
  ```

  该辅助程序调用是一个父逻辑尝试；其内部 Git 操作是子效果。将其汇总 JSON 视为尝试证据，而不是效果账本或证明。每次返回或中断后，独立普查检出目录、分支、提交、树和引用，以生成父尝试效果账本。成功后，证明只产生了一个新提交：其唯一父提交是准确目标，其树与已审查树逐字节相同，其分支是源分支，且检出目录干净；保留指向已审查检查点提交头的恢复引用。出错时，保留所有状态，包括报告的任何 `-candidate` 引用，并确定准确的当前检出目录和分支。只有当前置条件、防护或预期不存在检查被该普查证明没有产生效果时，才冻结已停止的 `history_result`；效果已经发生或仍有歧义，或所需的效果后证明失败时，冻结失败的 `history_result`。让后续阶段结果保持 `not-started`，保留账本及准确的恢复责任方与操作，且绝不重试。

把已完成阶段冻结为不可变的**`history_result: proven`**，并绑定历史策略、目标边界、已审查提交头和树、所得源提交头和树、交付提交头或**已交付**证明、恢复引用及效果账本。这会结束该次尝试的历史定型。后续任何结果都不得重新进入或重复历史策略。尤其是，在已证明 `history_result` 后发生目标漂移时，应在另一次修改前停止当前尝试，除非当前证据证明**已交付**。保留 `history_result`，并把它交给目标移动责任方。任何选定的同步都会形成新的实施状态，必须重新验证并正式审查；它不能恢复本次尝试，也不能复用本次证明。

任何历史策略都不允许拉取、贮藏、硬重置、清理、强制推送、变基、合并提交、隐式远程操作或替换无关状态。`history_result` 要么是一个已证明的交付提交头和树，要么是**已交付**证据；否则不得开始任何结果流程。

## 执行一个结果

针对不可变的 `history_result` 执行 Ready 之前冻结的选定契约；不得在历史定型后重新读取、替换或发现新的前置条件。冻结其终态**`outcome_result`**，包括结果、已证明或已保留的分类、当前终止步骤、尝试账本、发布、恢复和残留状态。已停止或失败的结果保留 `history_result`，而不是将其替换。

只有独立证明已整合到权威目标的结果（包括**已交付**）才是交付。推送、拉取请求、保留分支或工作树转移都是非整合性交接，不得报告为交付。

## 根据证明结束

结果完成后，重新观察其准确效果、两个检出目录、引用、发布及无关状态。仅当结果特有的证明已经成立，并且准确工作树、分支和恢复项已证明归本生命周期所有、不包含用户或无关工作、且受准确的清理授权覆盖时，才具备清理条件。由宿主移除宿主创建的工作树。只有其保留责任方解除保留后，才可以通过预期旧 OID 比较交换删除任何自有引用，包括分支或恢复引用；不匹配时保留该引用。删除分支前，还要证明它未被任何工作树使用。每次工作树移除和每次引用删除都是一个逻辑清理尝试。不由本技能负责移除时，保留或交接给宿主就是清理处置。

冻结**`cleanup_result`**，其中包括清理资格、每个已移除、已保留或已委派的项目、其尝试账本、残留状态和责任方。它绝不改写 `history_result` 或 `outcome_result`。

只返回一个 `status` 和一个 `classification`：

- `complete` 表示 `outcome_result` 已获证明，且 `cleanup_result` 为每个项目给出了已授权处置。
- 某阶段开始前，`causal_boundary: preflight` 直接产生上文定义的 `stopped`。
- 某阶段开始后，总体状态复制权威阶段结果词汇中其因果终态的 `stopped` 或 `failed`；不得自行重新分类命令结果。后续恢复尝试记录自身结果，但不替换该因果状态。

在历史或结果得到证明前，分类为 `no positive result`。之后，它保留独立证明的最强事实：`history finalized`、`authoritative delivery` 或 `non-integrating handoff`。后续停止或失败会增加其部分效果或未证明效果，但不会抹去或升级较早的结果。只有独立证明的本地整合或**已交付**才属于 `authoritative delivery`。

每次返回状态时，都要返回 `causal_boundary`、`history_result`、`outcome_result` 和 `cleanup_result`；固定契约和历史策略；源、目标、已审查、交付及最终提交头和树；验证和审查证据；发布；已保留的无关状态；准确的残留状态；以及 `next_owner` 和一个准确的后续操作。对于 `stopped` 或 `failed`，还要指出因果终止边界或阶段及尝试、观察到的不匹配或错误，以及恢复路径。出现部分、失败或有歧义的效果后，保留恢复能力。绝不把未获证明的交付、清理、发布、拉取请求或非整合性交接称为完成。
