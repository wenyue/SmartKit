# 收尾工作树

完成一个已选择的结果，并为每个剩余项目明确责任方。本 Skill 按需准备历史、实施交接或交付、恢复自身效果并安排清理。实施流程负责已接受的内容、验证和正式审查。追踪器关闭仍属于原有所有者。

## 确定任务并选择结果

通过物理路径、关联工作树注册、公共仓库、分支和当前 HEAD 确定源身份。`create-worktree` 交接有助于定位它；当前 Git 证据必须证明它仍是预期工作树。在产生效果前解决替换或身份歧义。确定已接受的范围、本地状态所有权及任何未解决的早先尝试。

选择预期结果，并在继续前完整读取对应路线：

| 所选路线 | 需要证明的结果 |
| --- | --- |
| `keep-for-later` | [工作可继续使用，并有继续处理的责任方](references/keep-for-later.md)，包括脏状态或未完成工作。 |
| `create-pull-request` | [确切的已接受提交已发布，并已建立其 PR](references/create-pull-request.md)。 |
| `merge-locally` | [已接受结果位于授权的本地目标](references/merge-local.md)，通过快进或 Already Delivered 证明成立。 |
| `return-for-review` | [任务修改与检出的工作文件合并](references/return-for-review.md)，保留其 HEAD 和完整索引。 |
| 明确丢弃 | [仅删除已授权的已观察损失](references/discard.md)，并保留不受影响的目标。 |

结果不明确时，需要在修改状态前作出决定。集成、传输和丢弃的后果不同；不要为了绕过受阻路线而相互替换。

使用请求和适用策略已经提供的权限。PR 请求包含必要的发布；传输请求包含其有界传输和保护性准备。只询问缺少的重要选择或效果，例如目标位置，或明确丢弃授权之外的损失。保留所有权不确定的状态。项目或调用者独立规定的检查和审查要求仍然适用。

## 只准备该结果需要的阶段

默认保留提交。发布、集成或明确选择压缩历史时，读取[历史准备](references/history.md)。压缩需要用户明确请求或项目要求；仅选择收尾路线并不授权压缩。普通保留和传输的历史阶段不适用，也没有一律先正式审查的前置条件。

路线提供就绪条件和正面证明。原生 Git 和仓库宿主接口提供确定性事实及有界操作；Agent 判断范围、所有权、语义兼容性和权限。必需能力或来源不可用时，停止依赖它的工作并报告缺失依赖，不要声称已获得该路线的证明。

首次改变状态前，读取[效果恢复](references/recovery.md)，并持久保存其外部回执。如果早先尝试尚未解决，在对同一状态产生其他效果前先恢复原尝试。只读保留交接只需其返回记录。

一次捕获写入集合和依赖。在批次边界复用共享证据，在有界批次内使用相关路径保护。紧接效果发生之前，刷新它所依赖的可变事实：身份、相关引用、索引、受影响文件、宿主状态，以及对新观察到损失的权限。之后观察该效果可能改变的内容。不可变提交/树和审查证据在其依赖仍匹配时可以复用。

漂移会停止依赖它的效果，已经完成的阶段保持有效。内容变化时，按实施所有者的契约把验证和验收交回该所有者；收尾不得默默接受不同结果。

## 安排剩余事项

遵循已证明路线的保留条件。保留脏源：普通收尾清理不授权丢失其内容。删除需要确切的自有项目、生命周期和保留所有者的释放，以及既有删除权限。在任何可能触及被忽略内容的删除前清点这些内容。由宿主创建的工作树交给宿主删除。

删除分支前，证明所有工作树都不再使用它。通过预期旧 OID 更新删除自有分支和恢复引用。为每次删除分别记录回执和恢复决定。已授权的保留或移交，只要明确责任方和释放条件，也可以完成清理，无须删除。

每次返回前，包括停止和失败时，读取[公共结果](references/results.md)。报告实际效果、简洁证据、保留位置和下一责任方/行动。完成要求同时有路线的正面证明，以及每个生命周期项目的处置。必需检查未通过时，其结果尚未得到证明。后续失败不能抹去已独立证明的历史、发布、交接或交付。
