# 工作树收尾

验证选定的目的地或保留状态，并使剩余工作易于继续，以此完成收尾。实现流程负责内容、检查和 review；任务跟踪器的所有者决定何时关闭记录。PR 或转移属于交接，不证明结果已合入。

## 选择结果

对照预期任务确认源的物理路径、Git 工作树注册、仓库、分支和 HEAD。确定范围、本地修改及未完成的先前操作。复用已有选择和授权；目的地或重要选择缺失时才询问。改变状态前读取所选路线：

| 结果 | 使用时机 |
| --- | --- |
| 保留待续 | 保持工作可供继续，包括脏状态或未完成工作。遵循下文说明。 |
| [创建拉取请求](references/create-pull-request.md) | 发布已接受的提交，交给后续审查。 |
| [本地合并](references/merge-local.md) | 通过 fast-forward 交付到已授权的本地分支。 |
| [转回供审阅](references/return-for-review.md) | 将任务修改合入检出目录的工作文件，保留其 HEAD 和完整索引。 |
| [明确丢弃](references/discard.md) | 删除实际损失已获用户授权的工作。 |

路线受阻不授权改用另一种结果。除非用户明确要求或项目策略要求整合历史，否则保留提交。

发布、本地合入和请求的历史整合需要读取[历史准备](references/history.md)。保留、转移和丢弃本身不要求正式 review；独立的项目和调用者要求仍适用。

**保留待续** 时，保持文件、索引和引用不变。报告工作树、分支、HEAD、未完成工作、待运行检查或操作，以及由谁继续、下一步是什么。并发工作改变状态时更新说明。仅为保留工作，无需先清理或 review。保留先前失败操作的残留不代表该操作成功。

## 处理变化和中断操作

每次写入前，刷新其依赖的身份、引用、文件或宿主状态。协调写入者；这些事实变化时，停止受影响操作。复用不可变证据和仍有效的检查；已接受内容发生变化时，交回实现流程执行适用的检查和 review。如果必需能力不可用，保留工作并说明继续所需条件。

失败或响应缺失后，重试前先检查原操作实际做了什么。只继续前提和授权仍成立的未完成工作。例如，push 成功而 PR 创建失败时，只需恢复 PR 创建；交付成功而清理失败时，只需继续清理。无法确定效果时，明确保留不确定性及解决它所需的状态。文件转移中断时，保留源和外部备份，按该路线检查部分完成的结果。

## 清理并报告

只删除已识别、属于任务、不再需要且删除已获授权的项目。保留脏工作树、归属不确定的状态，以及 review、继续或恢复所需内容。删除可能触及被忽略内容前先清点；普通清理不授权丢失它们。宿主创建的工作树使用该宿主的删除接口。

删除分支前，确认没有工作树正在使用它。删除所属分支和恢复引用时，校验预期旧 OID。观察每次删除结果后再继续；部分清理失败不会撤销已验证的交接或交付。保留项目也是有效收尾，只要位置、下一位责任方和后续删除条件明确。转移备份和源还受其路线中更严格的接受条件约束。

报告选定结果及其已验证证据：相关路径、分支/提交或 PR URL、检查、保留工作和下一步。区分已完成动作、失败和不确定性。例如，“已交付到 main；源清理失败”意味着需要清理，而不是再次合入。

所选结果已验证，剩余项目已安全删除，或已主动保留且有足够继续信息时，收尾完成。
