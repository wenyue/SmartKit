# 完成工作树

依据当前证据闭合一项隔离工作树任务。实现工作流负责范围、验证和正式审查。本 Skill 负责历史最终化、一个选定结果、其恢复和获准清理。跟踪器转换和已接受结果的变更仍由其既定所有者负责。

## 原则

- **一项任务，一条路径。**通过一个冻结结果契约，最终化或明确丢弃一个确切的隔离工作树。
- **先证明，后产生效果。**每项变更前，重新确定当前身份、所有权、权限、恢复和完整效果边界。
- **每次尝试只有一个重试决策。**将子操作归入同一次逻辑效果尝试，由该尝试的所有者决定重试或恢复。
- **最强事实优先。**后续失败会保留每项独立证明的历史、交付或交接事实，但不会提升其等级。
- **恢复遵循因果。**保留模糊或部分状态，并将其交回产生该状态的效果所有者。

## 公共状态模型

一次**逻辑效果尝试**是最小的获准变更单元，其子操作共享一个重试或恢复决策。为尝试赋予一个身份和前置状态。将其命令或逐路径写入记录为已完成、已跳过、运行中、有歧义或残留子效果。只有当选定路径给予某个子操作独立的重试或恢复决策时，它才是独立尝试；辅助程序或受保护的批处理仍是一次尝试。

每次退出都返回 `history_result`、`outcome_result` 和 `cleanup_result`，并使用适用的最窄状态：

| 状态 | 含义 |
| --- | --- |
| `not-started` | 从未进入该阶段；指出作为原因的更早边界。 |
| `inapplicable` | 冻结契约证明该阶段不适用。 |
| `stopped` | 某项前置条件或门槛拒绝了预期效果，并且完整重新观察证明该尝试没有产生效果。记录原因、ledger、残留证据和下一位所有者。 |
| `failed` | 已经产生效果或效果仍有歧义，或者必要的效果后证明失败。记录作为原因的尝试、ledger、残留状态和恢复所有者。无效果的门槛拒绝不属于失败。 |

历史和结果还可以使用 `proven`；只有清理还可以使用 `complete`。证明正向状态的阶段拥有其 payload。

`preflight` 是三个阶段之前的因果边界。就绪前的最终化停止会将三者都返回为 `not-started`，同时给出 `causal_boundary: preflight`、被拒绝的前置条件或门槛、没有阶段效果发生的证明，以及确切的下一位所有者或操作。明确丢弃则使历史变为 `inapplicable`；在首次效果前，结果和清理为 `not-started`。任一预检边界都会使总体状态为 `stopped`。失败的历史尝试会让结果和清理保持 `not-started`。

只有当结果已得到证明，而且清理为每个生命周期项给出获准处置时，总体 `status` 才是 `complete`。预检拒绝为 `stopped`；阶段开始后，总体状态就是该阶段作为原因的 `stopped` 或 `failed`。后续恢复记录自己的结果，不替换原始原因。

分类从 `no positive result` 开始。已证明的丢弃会变为 `explicit discard`。最终化保留独立证明的最强分类：`history finalized`、`authoritative delivery` 或 `non-integrating handoff`。只有已证明的本地集成或**已交付**属于权威交付。后续停止或失败会增加其部分或未证明效果，但不会抹去或提升该事实。

每次返回都要标明冻结路径、`status`、`classification`、`causal_boundary`、全部三个阶段结果，以及证明每项声明和残留效果所需的充分证据。包括来源、目标、已审查、交付和最终 head 或 tree；验证和审查绑定；发布；保留证据；并且只在重要时包括 `next_owner`。使用有界身份和状态证据摘要无影响状态，证明它处于效果边界外。最终化还要返回其固定契约和历史策略。停止或失败结果会指出作为原因的阶段和尝试、不匹配或错误、恢复路径，以及每项保留的部分、失败或模糊效果。

## 选择一条路径

明确要求丢弃确切本地状态时，采用 [`references/discard.md`](references/discard.md) 中单独的破坏性契约，并在那里结束。否则，恰好选择一个最终化结果，并且只完整读取它的 reference：

| 结果 | 选定契约 | 分类 |
| --- | --- | --- |
| `merge-locally` | [`references/merge-local.md`](references/merge-local.md) | 集成 |
| `create-pull-request` | [`references/create-pull-request.md`](references/create-pull-request.md) | 在权威目标包含已接受结果前均为非集成 |
| `keep-for-later` | [`references/keep-for-later.md`](references/keep-for-later.md) | 非集成 |
| `return-for-review` | [`references/return-for-review.md`](references/return-for-review.md) | 非集成 |

在预检期间加载选定 reference，并为本次运行冻结它；其他 reference 均不加载。在就绪前，将其完整输入、授权、可能效果、成功证明、恢复和保留要求纳入公共契约。只有就绪后才执行同一个冻结契约。

## 1. 证明最终化契约

要求一个确切的源工作树、目标和获准结果。绑定：

- 源路径和分支；其当前预期 `HEAD`、树、不可变基点、完整范围所有提交区间，以及选定效果所需的本地、Git 管理和生命周期状态；
- 目标检出和分支、预期 `HEAD`、边界关系、对移动的允许响应、选定操作可触达的确切路径、引用和 Git 管理状态，以及针对无关本地状态的有界 Git 身份和状态证据；
- 验收来源和固定点；必要验证和正式 `code-review` 结果；其确切已审查 `HEAD` 和树；以及不存在阻塞发现；
- `preserve-commits` 或 `consolidate-checkpoints`；恰好一个结果——`merge-locally`、`create-pull-request`、`keep-for-later` 或 `return-for-review`——以及选定契约中的每个值、授权、前置条件、可观察成功、恢复和保留要求；
- 发布证据、恢复引用所有权和保留、生命周期与效果授权、每次逻辑效果尝试的一个身份、清理权限（包括任何工作流所有辅助文件）、下一位所有者，以及每个结果特定值；
- 权威实现工作流，以及每项依赖的可观察不可用、停止、失败或模糊结果。

将调用方断言视为需要证明的声明。重新观察 Git、仓库和明确获准的主机证据：两个物理路径、它们的公共仓库、工作树注册、分支、提交、树、引用、发布和生命周期所有者。使用当前任务上下文、Git 状态与差异、仓库证据、验证和正式审查证据，以及明确授权。先前的 `create-worktree` 结果可以定位来源，或解释其基点和生命周期，但此处使用的每项断言都由当前证据控制。来源处于 detached、被替换、不可用或具有多个身份时，停止最终化。

只推断当前证据唯一证明的技术事实。变更前，将每项未解决选择或授权交给其所有者：确切目标；混合工作中的已接受范围；已审查 head 和 tree 及无阻塞审查；某项操作要求的发布知识；历史策略；结果或远程操作权限；清理所有权和授权。

定义选定效果可能更改的确切路径、引用和 Git 管理状态。只快照该写入集合和恢复所需状态：受影响提交、树和引用的对象 ID；受影响暂存路径的完整索引条目和 blob OID；以及受影响非索引内容的状态、文件类型、模式、适用符号链接目标和内容哈希清单。只有覆盖、删除或获准恢复可能需要原始字节时才保留它们。证明其他所有已暂存、未暂存、未跟踪和忽略状态都位于选定目标与写入集合之外，然后保留足以发现意外效果的有界 Git 身份和状态证据。

核对已接受区间内的每个提交和路径，将每个相关本地状态项分类为范围所有、无关或有歧义，并证明必要祖先关系。将验证和正式审查绑定到同一个验收固定点、已审查 head 和已审查 tree。只有当写入集合排除无关状态，而且有界前后证据能够发现意外效果时，脏目标才仍然合格。

### 源就绪条件

只有选定历史操作会读取、替换源索引或工作树状态，或从中派生结果时，才要求 `git status --porcelain=v1 -z` 为空；合并检查点需要此干净谓词。否则，只有有界证据证明每个源本地状态项与已接受结果和当前实现任务无关、位于选定操作的写入和效果集合之外，并且能通过前后比较发现，同时已提交交付 tree 仍恰好是已审查 tree 时，该状态才合格。与已接受结果或当前任务实质相关，或关系有歧义的状态，会在就绪前停止并返回实现所有者。只有独立的已接受权限将该确切状态分类为本结果之外需要保留的后继范围时，它才合格。对于选定写入、恢复或生命周期清理操作可能触达的每个忽略项，记录详细证据，并保留其他所有忽略项。脏源状态会使工作树不具备最终化清理资格；保留或交接它。只有单独的明确丢弃路径可以授权丢失它。记录足以供独立复查的命令、输出和对象 ID。

### 就绪门槛

就绪要求完整的公共和选定结果契约、当前身份、已接受区间、审查绑定、保留边界、权限和结果输入均精确且彼此一致。只有通过此门槛后，历史和结果变更才会开始。

## 2. 最终化已审查历史

每次逻辑效果尝试前，立即重新检查其子项可能影响的所有状态对应的每项身份、head、tree、区间、本地状态、发布、权限和恢复谓词。一次性绑定父阶段、尝试身份、前置状态和预期受影响状态。返回或中断后，重新观察全部状态一次，并在父 ledger 中记录每个子项。发生漂移时停止。中断或有歧义的尝试保持运行中；为效果所有者保留其状态，由它决定下一步。

若目标移动，只有当契约允许重新绑定、新目标仍是已审查 head 的祖先，并且重新计算的区间完全归范围所有时，才能继续。否则，将观察到的目标和已审查状态返回实现工作流或其他冻结的目标移动所有者。该所有者执行同步或其他内容变更，然后在新的最终化尝试前完成验证和正式审查。

改写历史前，测试权威结果目标是否已包含每项已接受效果。若当前祖先关系证明确切区间，它便足够。否则，需要每项效果都有明确的等价变更证据，并且有证据证明确切目标 `HEAD` 和 tree 已通过必要验证及无阻塞正式审查。使用实现所有者提供的绑定证据，或将目标状态返回该所有者；本 Skill 不执行审查。空差异、相似消息、移动的跟踪器状态、部分 patch，或绑定到不同目标身份的证明都不充分。将成功证明记录为**已交付**，并携带该证明直接继续。

应用下方冻结历史策略。

### 保留提交

重新枚举 `target..reviewed-head`；证明整个区间归范围所有，而且源仍位于已审查 head 和 tree。该 head 是交付 head。只有观察到的发布状态与选定结果兼容时，已发布提交才合格。

### 合并检查点

要求整个区间尚未发布且未被依赖，确切目标是其祖先。在任何准备效果前，为主机选择本 Skill 的 POSIX 或 PowerShell 启动器，并证明它可以运行。每个启动器只先检查 `python3`，再检查 `python`，验证每个命令是否为 Python 3.10 或更高版本，并用第一个兼容命令运行辅助程序。若两者都不合格，它会输出 `ERROR: Python 3.10 or newer is required; checked python3, then python.` 并以 `2` 退出；将其视为无效果的前置条件拒绝。就绪前，只使用 `--help` 调用选定启动器，并要求退出 `0`。

冻结 `refs/smartkit/recovery/` 下一个预期不存在的唯一恢复引用，以及由其派生的 `<recovery-ref>-candidate` 引用，包括确切创建、保留和基于预期旧值的删除授权。使用 `refs/smartkit/recovery/<job>/<attempt>` 这样的有效唯一名称。还要冻结位于每个受影响工作树之外、预期不存在的消息文件路径，其从已接受范围派生并符合仓库约定的字节和模式，以及确切创建、读取、保留、删除和清理所有权。将文件创建一次，作为独立逻辑历史尝试，并在为历史尝试调用启动器一次前证明其确切内容。

在 POSIX 主机上：

```sh
sh "<skill-root>/scripts/consolidate_worktree_history.sh" \
  --repository <source-worktree> \
  --target <exact-target-oid> \
  --message-file <message-file> \
  --recovery-ref <new-recovery-ref>
```

在 PowerShell 主机上：

```powershell
& "<skill-root>/scripts/consolidate_worktree_history.ps1" `
  --repository <source-worktree> `
  --target <exact-target-oid> `
  --message-file <message-file> `
  --recovery-ref <new-recovery-ref>
```

辅助程序调用是一次父逻辑尝试；其内部 Git 操作是子效果。将其汇总 JSON 视为尝试证据，绝不视为效果 ledger 或证明。每次返回或中断后，独立重新观察检出、分支、提交、树和引用，并将它们记录到父 ledger 中。

成功时，证明恰好有一个新提交，其唯一父提交是目标，tree 与已审查 tree 逐字节相同，分支是源分支，并且检出干净。将恢复引用保留在已审查的检查点 head 上。发生错误时，保留所有状态，包括消息文件和任何已报告的 `-candidate` 引用，并确定当前确切检出和分支。

只有重新观察证明某项前置条件、门槛或预期不存在拒绝没有产生效果时，才将 `history_result` 冻结为 `stopped`。当效果已经发生或仍有歧义，或者必要的效果后证明失败时，将其冻结为 `failed`。让后续阶段保持 `not-started`；保留 ledger 和确切恢复所有者或操作。绝不自动重试——由所有者决定任何另行授权的后续尝试。

将完成阶段冻结为不可变的**`history_result: proven`**，并绑定到历史策略、目标边界、已审查 head 和 tree、产生的源 head 和 tree、交付 head 或**已交付**证明、恢复引用、消息文件处置和效果 ledger。所有结果工作都使用该不可变结果。此后目标漂移会在另一项变更前停止尝试，除非当前证据证明**已交付**。为目标移动所有者保留 `history_result`。任何后续同步都会形成新的实现状态，必须重新通过验证和正式审查。

保持历史最终化在本地以确定性方式完成：使用不可变对象 ID，保留无关状态，通过辅助程序合并提交，并且只通过指定的受保护更新移动引用。任何历史策略都不允许 pull、stash、hard reset、clean、force push、rebase、merge commit、隐式远程操作或替换无关状态。结果执行从一个已证明的交付 head 和 tree，或**已交付**证据开始。

## 3. 执行选定结果

针对不可变 `history_result` 执行就绪前冻结的契约。将其终止**`outcome_result`**与结果、已证明或保留的分类、当前终止步骤、尝试 ledger、发布、恢复和残留状态一起冻结。停止或失败的结果仍保持 `history_result` 不变。

权威交付需要独立证明已经集成进权威目标，包括**已交付**。将 push、pull request、保留分支或工作树传递分类为非集成交接。

## 4. 根据证明闭合

应用就绪前冻结的范围内证明。详细重新观察选定写入、恢复或生命周期清理集合中的每个检出路径、引用、发布事实和 Git 管理项。对于其他所有状态，重新证明不可达，并比较有界 Git 身份和状态证据，查找意外效果。

只有结果特定证明确定为清理选定的每个确切工作树、分支、恢复项、忽略项或工作流所有辅助文件都属于本生命周期、不含用户或无关工作，并且具有确切清理授权后，才具备清理资格。主机会移除由主机创建的工作树。只有保留所有者释放所属分支或恢复引用后，才能通过基于预期旧 OID 的 compare-and-swap 删除它；不匹配时保留引用。删除分支前，还要证明它不存在于每个工作树中。

每次工作树移除、辅助文件移除和引用删除都是一次逻辑清理尝试。若此处不拥有移除操作，清理处置就是保留或交给主机。

将**`cleanup_result`**与资格、每项移除、保留或委托项、其尝试 ledger、残留状态和所有者一起冻结。它绝不改写 `history_result` 或 `outcome_result`。
