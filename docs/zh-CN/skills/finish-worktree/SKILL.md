# 工作树收尾

为一个隔离工作树完成选定结果，并说明剩余事项。本 Skill 负责历史准备、所选交接或交付、相应操作效果的恢复、清理与报告。实施工作流负责修改已接受结果、验证和正式审查；工单闭合仍由原负责人处理。

## 选择结果

确定已接受范围、本地状态归属、所选结果，以及此前尚未解决的操作效果。识别来源的物理路径、关联工作树注册、共同仓库、分支和当前 HEAD。先前的 `create-worktree` 结果可以帮助定位任务；当前 Git 证据必须确认其身份，包括解决身份替换或含糊情况。

完整阅读所选路径的契约。结果含糊时，在修改状态前解决；不得暗中以转移代替整合，或以丢弃代替清理。

| 结果 | 契约与完成条件 |
| --- | --- |
| `keep-for-later` | [保留可继续使用的工作](references/keep-for-later.md)并明确接续负责人，包括未完成和脏工作。 |
| `create-pull-request` | [发布已接受提交并建立 PR](references/create-pull-request.md)。 |
| `merge-locally` | 通过快进或 Already Delivered 证据，[证明已接受结果位于获授权的本地目标](references/merge-local.md)。 |
| `return-for-review` | [将任务改动转入检出目录](references/return-for-review.md)，保留其 HEAD 和完整索引。 |
| 明确丢弃 | [仅移除已授权且已观察到的损失](references/discard.md)，并证明未受影响的目标得到保护。 |

根据已接受请求和适用策略确定操作权限，复用已授予的权限。PR 请求授权必要的发布；转移请求授权有界转移和保护性准备。只在缺少实质选择或操作权限时询问，例如目标尚未确定，或损失超出明确丢弃权限。保留归属不明的状态。独立适用的项目或调用方策略可能要求更严格的验证或审查。

默认保留提交。发布、整合和明确选择的提交整理需要[历史准备](references/history.md)。整理提交需要用户明确请求或项目要求；仅选择结果不构成授权。普通保留和转移既不需要重写历史，也不统一要求正式审查；其历史阶段不适用。

## 执行有界操作

所选路径定义就绪条件和成功证明。使用原生 Git 与仓库宿主接口获取确定性事实并执行有界操作；自行判断范围、归属、语义兼容性和权限。首次改变状态前，读取[操作效果恢复](references/recovery.md)并持久化其外部操作记录。同一状态上产生其他效果前，先在该流程中恢复尚未解决的原始尝试。只读保留只需返回记录。

一次性采集写入集及依赖。在批次边界使用共用证明，在有界批次内部使用相关路径保护。紧接操作前，刷新其可变依赖：身份、相关引用、索引、受影响文件、宿主状态，以及对新发现损失的权限。操作后观察它可能改变的内容。不可变提交、树和审查证据在依赖匹配时继续复用。内容变更后，将验证和验收交回实施负责人，按其契约处理；漂移使依赖该状态的操作停止，同时保留已完成阶段。

## 完成生命周期处置并报告

遵循已证明结果的保留条件。保留脏来源：收尾清理不授予丢失其内容的权限。只有生命周期和保留负责人已解除保留要求、且移除已获授权的确切自有项，才可删除。删除可能触及忽略内容时，先清点。宿主创建的工作树由宿主移除。删除分支要求它不被任何工作树使用；删除自有分支或恢复引用使用预期旧 OID 更新。每项移除分别记录和恢复。明确负责人和解除保留条件的保留或委派，可以在不删除的情况下完成清理。

每次返回前读取[公共结果](references/results.md)，包括停止和失败的情况。报告所选路径、实际效果与简明证据、保留位置，以及下一位负责人和操作。完成要求所选路径的结果已证明，且每个生命周期项都有处置。报告未通过的必需检查，不得声称其结果已证明。后续失败不能抹去独立已证明的历史、发布、交接或交付。
