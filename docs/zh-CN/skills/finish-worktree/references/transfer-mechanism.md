# 转移机制

任何路径选择只读取证工具时，读取**只读取证**。使用[转回检出目录](return-for-review.md)的工具时，还需读取**批量转移机制**；恢复中断或部分转移前，读取**部分文件转移**。所选路径负责 B/S/W 判断、验收和验证；工具负责确定性观察、能力检查和受保护写入。

## 只读取证 <a id="read-only-evidence"></a>

使用前运行 `python "<skill-root>/scripts/worktree_evidence.py" --help` 探测。Snapshot 将 JSON 写到 stdout；compare 读取外部快照。两个命令都不写入 Git 状态或工作文件状态。重定向 stdout 时，要保留快照的 UTF-8 JSON 编码。

```text
python "<skill-root>/scripts/worktree_evidence.py" snapshot --repository "<physical-checkout>" --path "<relative-file>" > "<external-snapshot.json>"
python "<skill-root>/scripts/worktree_evidence.py" compare --snapshot "<external-snapshot.json>"
```

重复 `--path` 可指定依赖集合。不指定路径时，snapshot 只采集仓库、HEAD 和暂存区的边界证据。`--inventory` 会明确
加入所有工作文件、忽略内容和全局 Git 状态；只有保留、删除或其他操作确实需要这份清单时才使用它。目录路径会在该
范围内递归。这里使用 v2 快照；旧 v1 证据应重新采集，不能暗中改变其比较范围。

每份快照都包含物理工作树和 Git 身份、注册信息、HEAD/引用，以及完整原始暂存区和分离暂存区依赖的哈希。有界快照
省略全局状态，不读取无关工作文件内容。指定范围内的路径包含缺失状态、类型、模式、内容哈希、符号链接目标和祖先
路径身份。安全属性、所有者和相关属性可能受到影响时，必需的状态保护证据也应覆盖它们；仅有字节和模式相同还不够。
工具的能力检查必须在依赖操作产生影响前建立这些证据。嵌套仓库，包括跨越其祖先路径的情况，以及子模块、符号链接
祖先路径和物理文件别名，需要由各自负责人另行取证。

Snapshot 观察两次，拒绝检测到的不稳定状态。Compare 按记录的范围重新观察：退出码 0 表示相同，1 表示漂移，2 表示
输入无效或观察失败。证据不是锁、原始内容备份、归属判断或语义证明。它不能保证全局原子快照，不能发现两次观察之间
被撤回的编辑，也不能证明远端状态。

## 批量转移机制

使用前运行 `python "<skill-root>/scripts/worktree_transfer.py" --help` 探测。在来源、目标及其 Git 目录之外，使用一个新的物理操作目录，且与目标父目录位于同一文件系统。该目录与来源一起保留，直到转移的用户验收条件满足。

工具处理通过准入检查的普通文件新增、修改和删除操作，目标须位于现有真实目录中。其实现负责宿主特定的能力和
元数据检查。只有这些检查能够证明目标路径、操作存储及每份生成或使用的材料满足所需的内容、安全属性、所有者、
属性和身份保护要求时，才可使用。能力检查拒绝时，停止依赖操作；不能据此绕过保护条件。将不受支持的情况交回所属
工作流，或使用能够建立相同状态保护契约的既有已授权机制。

目录创建、重命名解析、所有者或安全属性迁移，以及语义合并，仍不属于这一任务文件操作机制。经过路径别名和间接
路径时，仍须保留预期的观察与写入边界；不能仅因字节可读，就将不支持的类型、元数据或访问条件当作普通文件处理。

准备一份使用 `smartkit.worktree-transfer/v1` schema 的 JSON 计划：

| 字段 | 接受的输入 |
| --- | --- |
| `repository` | 目标检出根目录的绝对物理路径。 |
| `source` | 覆盖每条已改变 S 路径的有界 v2 证据快照，来自同一公共仓库中的另一个检出目录。 |
| `baseline` | 不可变共同基线 B 的准确提交 OID，须为双方已观察 HEAD 的祖先。 |
| `authority`, `owner` | 已接受请求的引用和后续处理负责人。它们记录智能体已确立的权限；工具不能授予权限。 |
| `changes` | 非空列表，按唯一、规范化的相对 `path` 排序。每项包含 `before`、`after` 和 `output`。 |

`before` 是有界证据中该路径的准确 W 文件状态对象。`after` 是准确的已接受输出文件状态对象：普通文件包含 `type`、
以 JSON 整数表示的 `mode`、`size`、`sha256`，以及观察到的 `uid`/`gid`；缺失状态为 `{"type":"absent"}`。
对于文件，`output` 是受影响工作树之外准备内容的绝对物理路径，也可以是对应的已接受来源文件本身。直接引用的来源
输出必须匹配 S。删除操作的 `output` 为 null。除非已接受改动有意改变权限细节，否则保留目标权限细节。智能体负责
确立每项都属于 B → S，且组合输出保留了 W 中兼容的改动；这份清单不能绕过语义判断。

```text
python "<skill-root>/scripts/worktree_transfer.py" prepare --plan "<external-plan.json>" --operation "<new-operation-directory>"
python "<skill-root>/scripts/worktree_transfer.py" apply --operation "<operation-directory>"
python "<skill-root>/scripts/worktree_transfer.py" inspect --operation "<operation-directory>"
```

`prepare` 冻结所有已接受输出、待写入副本和可读备份，并写入 `receipt.json`，记录操作前状态、权限、负责人和保留
条件。目标漂移、已接受输入改变或不支持的边界都会阻止应用。`apply` 只接受这次已准备的尝试，在开始时一次性核对
材料和共用依赖，在批次内使用路径、祖先路径和输出保护，并在结束时证明完整 HEAD、暂存区和输出受到保护。它不会
暂存、提交、删除备份或运行项目验证。前后状态相同的条目无需写入工作文件。整个仓库的观察次数与文件数无关；有界
文件操作量随受影响路径增长。

操作记录在写入前记下执行中的子操作，在写入后记录其归属明确的结果。失败或中断的操作可能留下部分内容、新建路径
或保留的原对象；应保留这一实际状态及其因果记录。整个批次不具备原子性。协作式操作锁阻止两个工具实例同时应用
同一次尝试，但不会排除任意外部写入者。机制必须保留足够的持久证据，以观察和恢复其影响，但不承诺普遍的断电持久性。
`inspect` 只读，报告边界保护情况、各路径属于 before/after/both/other 中哪种状态、操作记录阶段，以及任何执行中的
子操作或锁。成功响应丢失时，需要先进行这项观察，不能再次 apply。工具阶段描述机械执行进度，不代表 Skill 的公共
分类或行为验证结果。

对于部分完成的尝试，先确立原进程已停止，再调用：

```text
python "<skill-root>/scripts/worktree_transfer.py" recover --operation "<operation-directory>" --quiescent
```

`--quiescent` 记录调用方已经确立的进程事实；它允许替换残留的操作锁，绝不能仅凭经过的时间推断。恢复保留原始错误，
只还原记录中仍匹配本次尝试的写入，并在漂移或执行中工作含义不明时停止。已完整应用的候选结果保持可审阅状态，后续
验证失败时亦然。未解决的操作记录、部分准备结果或不安全的还原，都应按照转移的验收条件，为指定负责人保留备份、
保留的原对象和其他材料。每个成功命令退出码
为 0；拒绝或错误退出码为 2，并附操作位置。将结果转换为公共阶段契约前，重新观察操作记录和文件，区分未产生影响的
拒绝与部分失败。

## 部分文件转移 <a id="partial-file-transfer"></a>

按照[转移的用户验收要求](return-for-review.md#apply-with-preservation-evidence)，保留来源快照、可读外部备份及任何
保留的原对象。部分应用后，考虑恢复前先观察准确的已写入集合和当前状态。只恢复能够归属于本次尝试、且当前状态仍
匹配记录输出的写入，包括内容、类型、模式、缺失状态，以及状态保护所依赖的身份或元数据。检查受影响祖先路径，
并在依赖写入前，将每份使用的备份或保留原对象与其冻结的操作前状态核对。恢复不得覆盖已改变的内容、安全属性、
所有者或其他相关元数据，也不得将这些变化带回目标。状态不匹配或写入不明确时，为负责人保留部分目标和恢复材料。
有界恢复是在已接受转移的恢复权限下执行的另一项记录操作；更广泛的变更需要各自权限。

如果整个转移已应用而后续验证失败，保留可审阅的组合状态和失败证据。恢复不能用于抹去失败结果。任何恢复都不得移动
目标 HEAD、改变目标暂存区或重置无关状态。
