# 传输机制

路线负责 B/S/W 判断、验收和行为验证。这些 helper 提供观察、能力检查及受保护的机械操作。在任何路线选择证据 helper 时，都要读取**只读证据**。使用[传回检出](return-for-review.md)路线的传输 helper 时，还要读取**批次传输机制**。恢复中断或部分应用的传输前，读取**部分文件传输**。

## 只读证据 <a id="read-only-evidence"></a>

使用前探测 CLI：

```text
python "<skill-root>/scripts/worktree_evidence.py" --help
python "<skill-root>/scripts/worktree_evidence.py" snapshot --repository "<physical-checkout>" --path "<relative-file>" > "<external-snapshot.json>"
python "<skill-root>/scripts/worktree_evidence.py" compare --snapshot "<external-snapshot.json>"
```

`snapshot` 向 stdout 输出 JSON；外部保存时保留 UTF-8 JSON。`compare` 读取该快照。两者都不写入 Git 或工作文件状态。对实际依赖集合重复 `--path`；目录会在该范围内递归。没有路径时，快照仅覆盖仓库/HEAD/索引边界。删除等效果需要全部工作文件、被忽略内容和全局 Git 状态时，使用 `--inventory`。将旧 v1 证据重新捕获为 v2，不要默默改变比较范围。

每个快照包含物理工作树/Git 身份、注册、HEAD/引用，以及完整原始索引和 split-index 依赖的哈希。有界快照避免全局状态和无关工作内容。范围内观察覆盖不存在状态、类型、模式、内容哈希、符号链接目标和祖先身份。保护也可能依赖安全性、所有权和相关属性：单靠字节和模式无法证明它们未变。在依赖效果前通过能力检查建立必需证据。嵌套仓库，包括跨越其祖先的路径，以及子模块、符号链接祖先和物理文件别名，需要另有所有者负责的证据。

返回快照前，两次观察用于检测不稳定状态。比较使用已记录范围：退出 0 表示相同，1 表示漂移，2 表示输入无效或观察失败。这些观察不是锁，也不是原始内容备份、所有权决定或语义证明。它们不承诺全局原子快照，不能检测两次观察间修改后又恢复的情况，也不能确定远端状态。

## 批次传输机制

### 准备前确认边界可接纳

```text
python "<skill-root>/scripts/worktree_transfer.py" --help
```

使用一个新的物理操作目录，位于源、目标及其 Git 目录之外，并与目标父目录处于同一文件系统。与源一起保留它，直到满足传输的用户接受条件。

helper 接纳现有真实目录内普通文件的创建/更新/删除。其实现负责目标路径、操作存储及每个产出或消费工件的宿主特定能力和元数据检查。这些检查必须在依赖效果之前，证明所需的内容、安全性、所有权、属性和身份保护。能力拒绝会停止该效果；交回所属流程，或使用另一种已获授权且满足相同保护契约的机制。

目录创建、重命名解析、所有权/安全性迁移和语义合并不属于此机制。跨别名和间接路径时，保持预期观察及写入边界完整。字节可读，不意味着不受支持的类型、元数据或访问方式就能安全地视为普通文件。

### 描述已接受输出

准备 schema 为 `smartkit.worktree-transfer/v1` 的 JSON 计划：

| 字段 | 接受的输入 |
| --- | --- |
| `repository` | 目标检出根目录的绝对物理路径。 |
| `source` | 覆盖每个变化 S 路径的有界 v2 证据，来自同一公共仓库中的另一个检出。 |
| `baseline` | 确切不可变共同 B 提交 OID，必须是两个已观察头提交的祖先。 |
| `authority`, `owner` | 已接受请求的引用和继续处理的责任方，记录 Agent 已经确定的权限。 |
| `changes` | 按唯一规范化相对 `path` 排序的非空列表；每项包含 `before`、`after` 和 `output`。 |

helper 的基线接纳范围比路线对 B 的一般提交/树描述更窄。只有满足该条件时才使用 helper；不要换一个基线来通过检查。计划和 helper 都不授予权限，也不证明 B → S 及兼容 W 修改的语义。

`before` 是有界证据中的确切 W 文件状态对象。`after` 描述已接受输出：普通文件含 `type`、整数 `mode`、`size`、`sha256` 及观察到的 `uid`/`gid`；不存在为 `{"type":"absent"}`。文件的 `output` 是受影响工作树之外已准备内容的绝对物理路径，或对应的已接受源文件本身。直接源输出必须匹配 S。删除使用 null `output`。保留目标权限细节，除非已接受修改有意改变它们。

### 准备、应用并检查一次尝试

```text
python "<skill-root>/scripts/worktree_transfer.py" prepare --plan "<external-plan.json>" --operation "<new-operation-directory>"
python "<skill-root>/scripts/worktree_transfer.py" apply --operation "<operation-directory>"
python "<skill-root>/scripts/worktree_transfer.py" inspect --operation "<operation-directory>"
```

`prepare` 冻结全部已接受输出、待写副本和可读备份。其 `receipt.json` 记录前态、权限、所有者和保留条件。目标或已接受输入发生漂移，或边界不受支持时，阻止应用。即使目标文件未变，准备也可能留下外部工件；准备失败时，保留并说明这些工件。

`apply` 只接受原来的已准备尝试。它在入口验证共享依赖和工件，在批次内使用路径/祖先/输出保护，在退出时证明完整 HEAD/索引及输出保护。它不暂存、提交、删除备份或运行项目验证。前后相同的条目无需写入工作文件。全仓库观察次数与文件数量无关；有界文件工作随受影响路径数量增长。

回执在子操作写入前记录其进行中状态，之后记录可归属结果。中断或失败可能留下部分内容、新创建路径或保留的原始对象。保留该状态及其因果记录。批次不是原子的。协作式操作锁防止多个 helper 调用并发应用同一次尝试，但无法排除任意外部写入者。持久证据支持观察和恢复效果，不承诺普遍适用的断电耐久性。

`inspect` 是只读的。它报告边界保护、每个路径为 before/after/both/other、回执阶段及任何进行中子操作或锁。响应缺失后，先检查，不要再次应用。helper 阶段报告的是机械进展，不是 Skill 的公共分类或行为验证结果。

### 仅恢复可归属的部分写入

恢复前，确定原进程已停止：

```text
python "<skill-root>/scripts/worktree_transfer.py" recover --operation "<operation-directory>" --quiescent
```

`--quiescent` 记录该已确定事实，并允许替换过期操作锁；单靠时间流逝无法确定它。恢复保留原始错误，只还原已记录且仍匹配该尝试的写入。漂移或含糊的进行中工作会停止还原。完整应用的候选保持可审阅，包括验证失败之后。

未解决回执、部分准备或不安全还原，会将备份、保留原件及其他工件按传输接受条件留给指定所有者。成功 CLI 操作退出 0；拒绝或错误退出 2 并给出操作位置。在将结果映射为公共阶段前，重新观察回执和文件：仅目标文件未变，不能证明整个尝试未产生效果。

## 部分文件传输 <a id="partial-file-transfer"></a>

按[传输的用户接受要求](return-for-review.md#apply-with-preservation-evidence)保留源快照、可读外部备份和保留的原始对象。考虑还原前，观察确切写入集合及当前状态。只还原属于本次尝试且当前状态仍匹配已记录输出的写入，包括内容、类型、模式、不存在状态及保护所需的任何身份或元数据。

写入前，检查受影响祖先，并按冻结前态验证每份将消费的备份或保留原件。恢复既不能覆盖已变化的内容、安全性、所有权或其他相关元数据，也不能把这些变化带回目标。不匹配或含糊时，为所有者保留部分目标和恢复工件。有界还原是已接受传输恢复权限内的一项单独记录效果；更广修改需要自己的权限。

整个传输已经应用而后续验证失败时，保留可审阅的组合状态和失败证据。还原不能抹去该失败结果。任何恢复都不得移动目标 HEAD、改变其索引或重置无关状态。
