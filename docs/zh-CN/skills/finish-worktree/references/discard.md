# 显式丢弃

此破坏性路径不属于收尾。只有用户明确授权丢失一个准确隔离工作树及其准确本地状态时，才进入本流程。

1. 解析并展示已注册的工作树路径、分支、基点、`HEAD`、完整唯一提交区间、已暂存/未暂存/未跟踪项清单、发布、恢复引用、创建责任方，以及使用该分支的每个其他工作树。为不受影响的目标检出目录和本地状态创建快照。
2. 让授权与观察到的损失相匹配。它必须明确涵盖将被移除的每个未发布提交、脏项或未跟踪项、工作树、分支及恢复引用。如果请求尚未指明准确目标和损失，则取得确认。之后任何状态变化都会使该授权失效，并以 `stopped` 退出。
3. 宿主创建的工作树由其宿主在一次已报告的逻辑尝试中移除。对于 Git 创建的工作树，在移除该准确路径前立即复核完整清单和归属。干净时使用普通移除；只有已确认的授权覆盖清单中的脏状态时，才使用强制工作树移除。工作树移除是一次逻辑尝试。证明所有工作树均未使用该分支后，才把其准确引用作为单独的逻辑尝试，通过预期旧 OID 比较交换删除。普通丢弃要求整合证明；否则，授权必须明确放弃已证明的未合并提交；两者都不允许无条件删除分支。
4. 只有另行授权时，才把每个工作流自有恢复引用作为独立逻辑尝试，通过预期旧值检查删除。保留不匹配或非自有引用。
5. 证明准确的已授权工作树和分支已不存在，并且目标检出目录、所有无关引用和所有无关本地状态均与快照一致。

重新观察每次尝试。中断或有歧义的效果不得重试；为效果责任方保留观察到的残留状态。工作树移除和引用删除中的命令是子效果，而不是其他尝试。

返回 `history_result: inapplicable`、显式丢弃的 `outcome_result`，以及涵盖分支和恢复引用处置的 `cleanup_result`。将总体 `complete`、`stopped` 或 `failed` 绑定到当前终止尝试，同时保留此前每项已证明的删除。包括准确的已丢弃对象、已保留引用或路径、不可逆性、残留状态，以及下一责任方与操作。切勿把不完整的收尾权限或一般清理请求重新解释为丢弃权限。
