# 明确丢弃

丢弃是一条独立的破坏性路径，不是最终化。只有用户明确授权丢失一个确切隔离工作树及其观察到的本地状态时，才能进入。

1. 解析并展示已注册工作树路径、分支、基点、`HEAD`、完整唯一提交区间、发布、恢复引用、当前生命周期和清理所有者，以及使用该分支的每个其他工作树。记录每个已暂存路径的完整索引条目和 blob OID。另行盘点每个受跟踪但未暂存、未跟踪和忽略项的路径、状态、文件类型、模式、适用的符号链接目标、内容哈希和大小。证明删除无法触达未受影响的目标检出；保留发现其中意外效果所需的对象、索引、引用及有界状态证据。
2. 使权限与观察到的损失相符。它必须明确涵盖移除会丢失的每个未发布提交、已暂存、未暂存、未跟踪或忽略项、工作树、分支和恢复引用。若请求尚未指出这些确切目标和损失，取得确认。之后任何状态变化都会使该权限失效，并以 `stopped` 结束。
3. 删除前立即重新检查完整损失清单、生命周期和清理所有者，以及每项损失的确切权限。发生漂移时在删除前停止。主机创建的工作树必须由其主机在一次报告的逻辑尝试中移除。对于 Git 创建的工作树，干净时使用普通移除；只有确认的权限覆盖普通移除会拒绝或销毁的每个已盘点项时，才使用强制工作树移除。工作树移除是一次逻辑尝试。只有证明分支不存在于任何工作树中后，才能通过基于预期旧 OID 的 compare-and-swap 将其确切引用作为独立逻辑尝试删除。普通丢弃需要集成证明，否则必须有明确放弃已证明未合并提交的权限。两者都不允许无条件删除分支。
4. 只有另行获得权限，并且通过预期旧值检查时，才将每个工作流所有的恢复引用作为独立逻辑尝试删除。保留不匹配或无主引用。
5. 证明确切的获准工作树和分支已经消失，相关目标对象、索引和引用身份保持不变，并且有界目标状态证据没有显示意外效果。

重新观察每次尝试。绝不重试中断或有歧义的效果；为效果所有者保留观察到的残留状态。工作树移除或引用删除内的命令仍是子效果，不是额外尝试。

返回 `history_result: inapplicable`、明确丢弃的 `outcome_result`，以及涵盖分支和恢复引用处置的 `cleanup_result`。应用主 Skill 的阶段状态和分类，同时保留每项更早证明的删除。包含确切的已丢弃对象、保留的引用或路径、不可逆性、残留状态和下一位所有者或操作。不完整的最终化权限或一般清理请求绝不会变成丢弃权限。
