# 明确丢弃

移除一棵准确指定的隔离工作树，并且只承受用户已授权、实际已观察到的损失。一般清理或不完整的最终处理权限，
不足以授权丢失工作。

识别已注册的物理工作树、分支、HEAD、基点与独有提交、发布和恢复引用、生命周期负责人，以及每个使用该分支的
检出目录。清点移除可能丢失的已暂存、未暂存、未跟踪和忽略内容，包括字节或内容身份、文件类型、模式与符号链接目标。
证明移除不会触及不受影响的目标检出目录，并采集其保护证据。

将已接受请求与清单匹配。现有明确权限已经覆盖准确工作树及其全部本地内容时，无需再次请求；应披露观察到的损失。
只有实质损失、分支或引用删除、或负责人超出该权限时才询问。删除前，新增或变化的损失需要重新匹配权限，
不必对未改变的请求自动重新确认。未合并提交需要明确放弃权限或整合证明。

移除前，阅读[恢复](recovery.md)并记录外部操作记录。每项操作紧前重新检查损失清单和目标身份。发生漂移则停止。
宿主创建的工作树由宿主移除。Git 创建的工作树尽可能使用普通移除；只有现有明确损失权限覆盖强制移除将销毁的
全部内容时，才可强制移除。

观察移除结果后，才删除分支。分支必须不再被任何工作树使用，并且只能通过预期旧 OID 更新删除。分支删除及每项
另行授权的自有恢复引用删除，均视为独立操作；不匹配时保留引用。绝不只凭响应中断就重复结果不明确的移除。

证明已授权项已经移除，不受影响目标的 HEAD、暂存区和本地状态均受到保护。返回 `history_result: inapplicable`、
丢弃的 `outcome_result`，以及覆盖分支和恢复项处置的 `cleanup_result`。已证实丢弃为
`classification: explicit discard`；后续工作失败时，保留此前已证实的删除，并报告残余状态及不可逆性。
