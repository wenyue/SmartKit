# 明确丢弃

## 将授权与实际损失匹配

丢弃需要覆盖实际损失的明确授权；一般清理权限不够。确认工作树的物理注册、分支、HEAD、独有提交、发布情况和恢复引用。识别正在使用该分支的其他检出，并将它们排除在删除边界之外。

清点已暂存、未暂存、未跟踪和被忽略内容，包括内容身份、类型、模式和符号链接目标。确认删除无法触及应保持不变的目标，捕获其 HEAD、完整索引和本地状态供比较。将已有授权与这些损失匹配并披露损失；只询问未被涵盖的实质损失。未合入工作需要明确放弃授权，或证明结果已合入。

## 只删除当前授权涵盖的内容

删除前立即刷新身份和损失清单。事实改变时重新匹配授权。宿主创建的工作树使用创建它的宿主处理，其他情况使用普通 Git 删除。强制删除需要覆盖其确切全部损失的权限。

删除任何分支或恢复引用前，验证工作树已删除。每项都遵循入口的清理条件；删除一项不授权删除另一项。结果不明确时，先检查当前状态再重试。

验证工作树已消失，且不受影响目标的 HEAD、完整索引和本地状态得到保留。报告删除和保留项目，包括不可逆损失及清理失败。保留另一个分支或产物，并不使已删除的本地内容变得可恢复。
