# 明确丢弃

仅丢弃明确权限覆盖的确切工作树和已观察损失。一般清理权限并不充分。将目标和其他所有者的状态保持在删除边界之外。

## 将授权与实际损失匹配

确定物理注册、分支、HEAD、基线、独有提交、发布、恢复引用、所有权及使用该分支的每个检出。清点已暂存、未暂存、未跟踪和被忽略内容，包括字节或内容身份、类型、模式和符号链接目标。确定删除无法触及不受影响的目标，并记录之后证明其保留所需的证据。

复用覆盖这些确切完整内容的既有授权，并披露损失。只询问授权之外的重要损失。观察发生变化时，需要重新匹配权限，而不是自动重复已经确定的决定。未合并工作需要明确的放弃权限，或其结果已经集成的证明。

## 在已观察边界内删除

产生效果前持久保存[恢复回执](recovery.md)。紧接删除前刷新身份和损失清单；发生漂移时，停止删除，直到边界得到解决。宿主创建的工作树使用宿主途径，Git 拥有的工作树使用普通 Git 删除。强制删除需要覆盖其确切全部损失的明确权限。

观察工作树已删除后，再考虑删除分支。分支必须不被任何工作树使用，删除必须匹配预期旧 OID。将每个分支或恢复引用删除作为独立效果处理。不匹配时保留引用；结果含糊时先观察再重试。删除一个项目不会默默授予删除另一个项目的权限。

证明工作树已不存在，且不受影响目标的 HEAD、完整索引及本地状态已保留。历史不适用。结果是明确丢弃；清理要安排每个剩余引用和其他生命周期项目。后续工作失败时，在报告中保留已证明的删除及任何不可逆损失，并给出残留位置和所有者。不要仅因为保留了另一个项目，就把已丢失状态描述为可恢复。
