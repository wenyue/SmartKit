# 本地合并

读取[历史准备](history.md)。如果已授权本地目标已经包含完整的已接受结果，验证并报告该交付，不重复写入。否则，其 HEAD 必须是已接受提交的祖先：此路线仅允许 fast-forward。分叉交回实现流程同步并重新验收。

确定目标检出的物理位置、分支及 fast-forward 可能影响的文件。只有本地修改与这些文件互不影响且能验证其保留时，才允许目标处于脏状态。捕获受影响文件、完整索引、相关引用，以及操作可能触及的未跟踪或被忽略状态。协调写入者，并在合入前立即复核目标身份和 HEAD。目标发生移动时重新评估，不基于过期观察合并。

在已授权、唯一且预期不存在的恢复引用下保留旧目标，然后在目标检出中运行：

```text
git merge --ff-only <exact-accepted-oid>
```

失败或响应缺失后也要观察目标。验证分支指向已接受提交、树和受影响文件匹配、必需目标检查通过，且无关索引条目、工作文件、未跟踪及被忽略状态保持不变。超时本身不能成为重复合并的理由。

仅在上述检查完成后报告交付。继续或恢复仍需使用时，保留源和恢复引用；仅在符合入口的清理条件时删除。清理失败时，单独报告已完成交付，使下一步继续清理而不是再次合入。
