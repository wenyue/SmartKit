# 本地合并

通过快进一条已授权的本地目标分支，交付已接受的结果。

确定目标检出目录、分支和预期 HEAD。使用[历史准备](history.md)，建立归属任务、通过必需验证且正式审查没有阻塞
问题的交付提交。目标必须是该提交的祖先。出现分叉时，交回实施工作流同步并重新验证和审查。此路径不执行 rebase、
pull，不创建合并提交，也不用转移代替合并。

确定快进写入集。只有目标本地状态位于该集合之外，且前后证据能够证明其受到保护时，脏目标才可使用；否则保留双方
检出目录并停止。采集受影响文件、完整暂存区证据、引用及相关 Git 状态，包括更新可能触及的忽略内容或未跟踪内容。
与其他写入者协调。

操作紧前再次核对目标身份和 HEAD。若历史已经证实后发生移动，应保留 `history_result`，并停止交由目标移动负责人
处理，除非当前证据证明**Already Delivered**。该情况下，记录权威证明，不进行整合写入。否则，通过预期不存在的
更新，在旧目标 OID 上创建已授权且唯一的恢复引用，记录该引用，并从目标检出目录运行：

```text
git merge --ff-only <exact-delivery-oid>
```

即使 Git 报告失败或调用中断，也要观察实际结果。证明目标分支已指向交付提交、树为已接受的树、目标必需验证通过、
受影响文件符合预期更新，而且无关的暂存区、工作文件、未跟踪及忽略状态均受到保护。只有该证明才能建立
`outcome_result: proven` 和 `classification: authoritative delivery`。结果不明确时进入[恢复](recovery.md)；
不能只因缺少成功响应就再次合并。

继续执行已授权的清理或保留。后续清理失败时，保留已证实的交付及其证据。来源和恢复引用保留到各自生命周期负责人
解除保留要求为止。
