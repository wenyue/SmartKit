# 本地合并

通过一次快进，将准确的已授权本地目标分支整合到交付提交头。

1. 复核目标身份、预期 `HEAD`、完整本地状态快照、`history_result`、交付提交头和树、祖先关系及授权。证明该操作会保留每个无关项。在 History Result 之后发生目标移动时，不得重新进入历史定型：可行时重新证明**已交付**；否则保留该结果并停止，将已停止的 `outcome_result` 交给目标移动责任方。存在不安全重叠时停止，并可把 `return-for-review` 作为新决定指出，但绝不自动替代。
2. 对于**已交付**，不作任何修改，并在当前目标上重新证明已接受结果。否则，通过预期不存在更新，在准确的旧目标提交头处创建一个已授权的唯一恢复引用，将其作为一次逻辑尝试并重新观察。只有证明该尝试成功后，才从目标检出目录运行一次快进逻辑尝试：

   ```text
   git merge --ff-only <exact-delivery-head>
   ```

   使用不可变提交 ID，不要使用分支名。
3. 证明目标分支现在指向交付提交头，其树是已审查的交付树，所需验证在该目标上通过，并且每个无关的索引项、工作树项、未跟踪项和已忽略项均与快照一致。

每次恢复引用或快进尝试返回或中断后，都要普查其完整效果包络。前置条件、防护、预期不存在或预期旧值拒绝经证明无效果时，冻结已停止的 `outcome_result`。效果已经发生或有歧义，或所需的效果后证明失败时，冻结失败的 `outcome_result`。保留已完成的恢复、账本、观察到的目标状态、`history_result`，以及准确的恢复或验证责任方与操作；绝不自动回滚或重试。

已证明的结果会冻结权威交付的 `outcome_result`，并返回**根据证明结束**。
