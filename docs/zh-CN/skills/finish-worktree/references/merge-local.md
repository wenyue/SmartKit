# 本地合并

通过一次快进，将已审查结果集成到一个确切且获准的本地目标分支。

1. 重新检查目标身份、预期 `HEAD`、不可变 `history_result`、交付 head 和 tree、祖先关系、授权、确切快进路径和引用、Git 管理状态，以及它们的范围内快照。使用有界身份和状态证据证明快进无法触达其他状态，并发现意外效果。历史完成后的目标移动绝不会重新进入历史最终化。可行时重新证明**已交付**；否则，为目标移动所有者保留 `history_result`，并以 `outcome_result: stopped` 停止。不安全重叠也会停止。它可以将 `return-for-review` 作为新的所有者决策提出，绝不自动选择。
2. 对于**已交付**，不作变更，并在当前目标上重新证明已接受结果。否则，通过预期不存在更新，在确切的旧目标 head 处创建一个获准且唯一的恢复引用，作为一次逻辑尝试，并重新观察它。只有该尝试得到证明后，才从目标检出运行一次快进逻辑尝试：

   ```text
   git merge --ff-only <exact-delivery-head>
   ```

   使用不可变提交 ID，不使用分支名。
3. 证明目标分支指向交付 head，其 tree 是已审查交付 tree，必要验证在该目标上通过，每个受影响路径都处于预期状态，并且有界索引、工作树、未跟踪和忽略证据没有显示快进写入集合之外的意外效果。

每次恢复引用或快进返回或中断后，重新观察该尝试可能影响的所有状态，并按照顶层阶段状态对其分类。保留已完成恢复、ledger、观察到的目标、`history_result`，以及确切恢复或验证所有者或操作。绝不自动回滚或重试。

已证明的结果会冻结权威交付的 `outcome_result`，并返回主 Skill 的**根据证明闭合**。
