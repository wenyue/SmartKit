# 本地合并

将已接受结果放到一个已授权的本地目标分支上。先消费[历史准备](history.md)。其 **Already Delivered** 证明可以在不写入的情况下确定交付；否则，目标必须是确切已接受交付提交的祖先，使集成只能快进。分叉交给实施所有者同步并重新验收。此路线不替换为 rebase、pull、合并提交或文件传输。

## 确定快进可能影响什么

确定物理目标检出和分支，再推导快进写入集合。脏目标只有在本地状态与写入集合不相交且能证明保护时才适用。否则保留目标，并在产生效果前停止。捕获受影响文件、完整索引、相关引用，以及 Git 操作可能触及的任何被忽略或未跟踪状态。协调该边界内的写入者。

紧接集成前重新检查目标身份和 HEAD。历史已证明后目标移动，不会使该历史结果失效，但会停止结果阶段并交给目标移动所有者，除非当前 **Already Delivered** 证据证明无须写入。

## 集成并证明交付

在[外部回执](recovery.md)中记录效果。为旧目标创建一个已授权、唯一且预期不存在的恢复引用，再从目标检出运行：

```text
git merge --ff-only <exact-delivery-oid>
```

即使命令失败或响应中断，也要观察目标。证明要求：分支位于交付 OID，树为已接受树，必需目标验证及受影响文件符合预期，无关索引、工作区、未跟踪和被忽略状态得到保留。含糊结果进入恢复；单凭超时绝不能重复集成。

此证明确定权威交付。保留源和恢复引用，直到其所有者释放。后续清理失败仍保留已证明的交付分类，使调用者可以根据交付继续，而不再次集成。
