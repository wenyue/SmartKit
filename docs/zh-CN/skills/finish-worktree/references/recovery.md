# 操作效果恢复

首次改变状态或恢复未解决尝试前，读取本引用。任何路径选择只读取证工具时，读取其[取证协议](transfer-mechanism.md#read-only-evidence)。文件转移工具使用和部分恢复还应遵循[转移机制](transfer-mechanism.md)。

## 操作记录 <a id="operation-receipt"></a>

在所有受影响工作树之外持久化一份小型操作记录。复用在这些工作树被移除后仍可保留的工作流记录。记录任务和路径、来源与目标身份、已接受权限、操作前状态、预期效果，以及可追溯因果关系的尝试身份。追加观察和残留状态，注明其接续负责人及保留、解除保留条件。包含区分完成与部分工作所需的确切 OID、路径和宿主身份；哈希不足以恢复内容时，保留可读备份。

按重试和恢复决策划分操作：受保护的文件批次或历史工具各算一次尝试；推送、建立 PR 和后续移除分别算独立尝试。记录区分已完成、不存在、进行中和含糊状态所需的子操作效果。开始下一项依赖操作前更新记录，使响应缺失不会掩盖已完成的推送、合并或删除。

## 继续未完成的操作

任何重试前，先通过权威 Git、文件系统或宿主接口重新观察。将记录与当前事实核对：保留已证实的前缀，尝试前证明某项
影响尚未发生，并仅在权限与前置条件仍有效时继续原来未完成的后缀。无法观察时，不明确结果继续保持未解决状态。
绝不单凭超时或缺少响应重复合并或创建 PR。推送已证实而 PR 失败时，继续建立 PR；交付已证实而清理失败时，继续清理。

使用[公共阶段含义](results.md)，区分未产生效果的拒绝与部分、含糊或未获证明的效果。恢复可以解决不确定性并支持接续；保留原始原因和观察、独立已证明的阶段，以及任何发布事实。
