# 效果恢复

首次改变状态前，或恢复未解决的尝试时，读取本文件。恢复首先要确定原尝试做了什么。当第一次尝试可能已发布、传输或删除状态时，重复请求的命令并不安全。

使用附带 helper 进行有界观察时，读取[只读证据](transfer-mechanism.md#read-only-evidence)。使用文件传输 helper 或恢复部分传输前，完整读取[传输机制](transfer-mechanism.md)中的相关章节。

## 操作回执 <a id="operation-receipt"></a>

将回执持久保存到所有受影响工作树之外，使它在工作树删除后仍然存在。记录任务和路线、确切源/目标身份、权限、前态、预期效果和尝试身份。追加已观察效果、残留位置、恢复责任方和释放条件。使用确切 OID 及物理或宿主路径；仅凭哈希无法支持恢复时，保留可读备份。

按重试所需的决定对效果分组。一个已准备文件批次或历史 helper 可以构成一次尝试。推送、PR 创建和单项删除需要分别记录效果，因为其中一项可以独立于下一项成功。在一次尝试内，区分已知完成、已知未发生、进行中或含糊的子操作。依赖效果继续前，更新回执。

## 解决原尝试

决定是否重试前，观察当前权威状态。保留已证明前缀，只继续权限和前置条件仍成立的原尝试未完成后缀。再次尝试某项效果前，证明它尚未发生。观察不可用时，保留不确定性及其所有者，不要把缺失响应当成未发生。

例如，已证明推送成功而 PR 创建失败，需要恢复 PR，不需要再次推送。已证明交付成功而清理失败，需要恢复清理，不需要再次集成。文件传输恢复在其机制契约中还有更严格的归属和还原保护。

使用[公共结果](results.md)说明原阶段是无效果拒绝、部分产生效果，还是仍然含糊。即使恢复成功或后续工作完成，也保留原始原因、任何已证明发布或其他正面结果，以及恢复观察。
