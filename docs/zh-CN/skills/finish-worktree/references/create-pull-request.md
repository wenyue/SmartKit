# 创建拉取请求

以非强制方式发布已验证的交付提交头，并且最多建立一个准确的拉取请求。在权威目标包含已接受结果之前，这是非整合性交接。

1. 要求显式远程权限。冻结仓库、基点分支及观察到的提交、提交头引用、交付提交、标题、正文、草稿状态、仓库批准的宿主接口和成功证明。已授权的观察还必须确定任何现有远程提交头和拉取请求。
2. 复核源、不可变的 `history_result`、自有区间、交付提交头和树、审查绑定、发布以及远程基点和提交头。基点移动属于历史阶段之后的目标漂移：不要重复历史策略。可行时重新证明**已交付**；否则，保留 `history_result` 并停止，把它交给目标移动责任方，同时记录已停止的 `outcome_result`。提交头不兼容、发布情况不确定、宿主证明不可用或先前尝试有歧义时，在再次产生效果前停止。
3. 如果基点包含每项已接受效果，返回**已交付**，且不推送，也不创建空拉取请求。如果已有一个打开的拉取请求与每个冻结字段和准确交付提交完全匹配，则验证并返回该现有交接，不要重复创建。
4. 否则，以一次逻辑尝试，通过普通非强制推送把准确交付提交推送一次到冻结的提交头引用。证明该结果后，再以第二次逻辑尝试，通过批准的接口创建一次拉取请求。每次尝试前后都重新观察；有歧义的结果保持进行中并予以保留，且不重试。
5. 证明远程提交头，以及拉取请求的仓库、基点、提交头、标题、正文、草稿状态、打开状态和 URL。分支已推送但拉取请求未创建或未验证时，`outcome_result` 为失败；把已证明的推送和分支报告为残留发布状态，并给出继续处理的责任方和准确操作。保留 `history_result`。

保留源分支、工作树和必要的恢复引用，以供审查更新。以后独立证明已整合后，才可以授权清理；仅创建拉取请求不构成清理条件。已验证的拉取请求产生已证明的 `outcome_result`，分类为 `non-integrating handoff`。
