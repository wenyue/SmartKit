# 创建拉取请求

通过仓库的宿主接口发布确切的已接受提交，并建立其 PR。PR 将工作交给后续审查，不代表权威交付。

## 确定已接受提交和 PR 目的地

读取[历史准备](history.md)，然后确定远端仓库、基线分支及 OID、head 引用和已接受提交。远端写入需要用户要求该结果；PR 请求包含必要的发布。根据已接受范围和项目约定确定常规标题、正文和草稿状态。

按仓库、base 和 head 查找现有 PR。复用匹配的开放 PR，核对其实际 head，只做已授权更新。已关闭、已合并、不兼容或不明确的匹配需要决定如何继续。如果目标已经满足历史准备中的完整交付检查，报告该结果，不创建空 PR。

## 分别发布并验证每项独立效果

发布前刷新本地和远端引用。基线移动后，需要重新确认验收仍有效，否则交回实现流程。将确切的已接受 OID 非强制 push 到预期 head 引用，观察远端引用匹配后再创建或更新 PR。已经完成的 push 或创建无需重复。

拒绝、中断或响应缺失后，先检查远端引用和 PR 状态再重试。Push 和 PR 创建可能分别成功。即使 PR 创建失败，报告也要保留发布已成功的事实，并保留源和远端引用供继续。

验证远端和 PR 的 head 都等于已接受 OID，且仓库、base、head 引用、开放状态、元数据和 URL 正确。保留 review 和后续更新所需内容。报告 PR 和剩余工作；工作树清理必须保留继续能力。
