# 创建拉取请求

以非强制方式发布已经验证的交付 head，然后至多建立一个确切拉取请求。在权威目标包含已接受结果前，这仍是非集成交接。

1. 每项远程效果都需要明确权限。冻结仓库、基分支及观察到的提交、head 引用、交付提交、标题、正文、草稿状态、仓库批准的主机接口和成功证明。获准观察还必须确定任何既有远程 head 和拉取请求。
2. 重新检查来源、不可变 `history_result`、所属区间、交付 head 和 tree、审查绑定、发布以及远程基点和 head。基点移动属于历史完成后的目标漂移；绝不重复历史策略。可行时重新证明**已交付**。否则，为目标移动所有者保留 `history_result`，并以 `outcome_result: stopped` 停止。head 不兼容、发布不确定、主机证明不可用或更早尝试有歧义时，也要在另一项效果前停止。
3. 若基点包含每项已接受效果，返回**已交付**，不推送，也不创建空拉取请求。若已有一个打开的拉取请求与每个冻结字段和确切交付提交相符，验证并返回该既有交接，不重复创建。
4. 否则，将确切交付提交以普通非强制推送方式向冻结 head 引用推送一次，作为一次逻辑尝试。只有证明该结果后，才通过批准的接口创建拉取请求一次，作为第二次逻辑尝试。每次尝试前后都重新观察。有歧义的结果保持运行中并得到保留，绝不重试。
5. 证明远程 head 提交，以及拉取请求的仓库、基点、head、标题、正文、草稿状态、打开状态和 URL。分支已经推送但拉取请求没有创建并验证时，属于失败的 `outcome_result`；将已证明的推送和分支报告为残留发布，并给出继续处理的所有者和确切操作。保留 `history_result`。

保留源分支、工作树和必要恢复引用，以供审查更新。仅创建拉取请求绝不授权清理；之后独立证明已经集成时才可能授权。已经验证的拉取请求产生 `outcome_result: proven`，分类为 `non-integrating handoff`。
