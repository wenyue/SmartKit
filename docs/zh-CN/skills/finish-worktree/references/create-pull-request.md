# 创建 PR

发布一个准确的已接受提交，并建立其 PR。已接受的 PR 请求提供发布权限；使用仓库认可的宿主接口，
根据已接受范围和项目约定判断常规标题、正文及草稿状态。

确定远程仓库、目标分支及已观察到的目标提交、预期来源引用，以及当前宿主状态。创建前按仓库、目标和来源查找已有 PR。
匹配且开放的 PR 可以复用；检查其实际来源提交与元数据，仅更新已接受请求范围内的字段。对于已关闭、已合并、不兼容
或身份不明确的 PR，必须作出具体的继续处理决定；不得仅因上次调用缺少响应就创建替代 PR。

使用[历史准备](history.md)，将交付提交与准确树绑定到其已接受状态的证据。该提交结果之外的任务工作，
应交回实施负责人，除非已接受权限已将其确定为另一项需要保留的后续任务。已经证明无关的本地状态可以留在发布影响
范围之外；脏来源应保留。

发布前，重新核对交付绑定及远端目标、来源。目标移动按历史契约中的**保留结果**处理。权威目标已包含已接受结果时，使用其中的**Already Delivered**证明，不创建空 PR。已有准确匹配的 PR 就是成功交接，无需重复推送或创建。

否则，以普通非强制推送将不可变交付 OID 推到确切来源引用。观察到远端引用等于该 OID 后，才创建或更新 PR。在操作记录中，将发布和建立 PR 作为两个独立效果。竞态、拒绝、超时或中断后，必须先通过[操作效果恢复](recovery.md)观察服务器，再继续。

证明远端来源与 PR 来源都等于交付 OID，并核对仓库、目标、来源引用、开放状态、预期元数据和 URL，由此证明 PR 交接。若已证明推送成功，但建立 PR 失败，保留发布事实、来源、分支、操作记录及恢复负责人，按操作效果恢复流程继续处理 PR。

保留来源及所需恢复状态，以便审查期间更新。仅有 PR 既不解除这些内容的保留要求，也不构成权威交付。
