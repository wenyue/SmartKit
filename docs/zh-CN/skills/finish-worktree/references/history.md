# 历史准备

发布、本地合入或请求的历史整合之前，确定已接受范围、不可变基线、完整的任务所属提交范围、源分支及 HEAD/tree，以及预期目的地。必需检查必须通过，且无阻断问题的正式 review 必须覆盖这一确切已接受状态。证据缺失、阻断问题未解决或这些提交之外还有任务修改时，交回实现流程；此 Skill 消费验收结果，不执行 review。操作不会影响无关本地状态且能验证其保留时，这些状态可以存在。

## 保留已接受历史

默认保留提交。当前 HEAD/tree 匹配已接受状态、范围内每个提交均属于任务后，发布或合入该 HEAD。已发布提交与选定结果兼容时也可使用。收尾不授权同步分叉分支或改变已接受内容。

先检查权威目标是否已包含每项已接受效果。祖先关系可证明确切已接受范围的交付；否则，要求整个范围有无歧义的等价修改证据，且检查与验收绑定到确切目标 HEAD/tree，由实现流程提供。空 diff、相似消息、PR 或 tracker 状态本身不够。已证明的交付避免不必要的改写、push 或合入。

目标或源发生移动时，重新评估所选操作所需事实。内容变化或验收失效交回实现流程；保留仍有效的先前结果，不默默接受另一个结果。

## 仅在授权时整合

整合需要明确用户请求或项目要求，以及提交权限。范围必须完全属于任务、未发布且未被依赖；确切目标必须是其祖先，源在 `git status --porcelain=v1 -z` 下必须干净。使用正常仓库提交 hooks。

在源工作树之外记录原始分支、HEAD/tree 和确切目标。用 `git update-ref <backup-ref> <old-oid> ""` 创建唯一且预期不存在的恢复引用，指向原始 HEAD。预期旧值为空表示要求该引用不存在。在恢复不再需要原始历史之前，保留此引用。

在 detached HEAD 上构建候选，使 hook 失败时原分支保持不变。在源工作树中逐条执行以下命令，只有上一条成功后才执行下一条：

```text
git switch --detach <old-oid>
git reset --soft <exact-target-oid>
git commit --file <external-message-file>
```

使用所属消息文件和正常提交 hooks。暂存差异为空时停止，不创建空交付提交。验证候选以目标为唯一父提交、树与已接受树完全相同，且检出状态干净。Hook 改变内容时需要重新检查和验收；保留其修改，不用 reset 抹除。内容相同允许复用内容 review，但应重跑依赖提交身份或 hooks 的检查。

仅在这些检查通过后，使用 `git update-ref <original-branch-ref> <candidate-oid> <old-oid>` 移动原分支，再切回该分支并验证分支、HEAD/tree 和干净状态。分支已变化时，更新会被拒绝，不会替换他人的工作。任何失败或中断后，继续前先检查 HEAD、分支、索引和工作文件；保留候选、备份引用和消息供人工恢复。不要盲目 reset 或重试。仅按入口的清理条件删除恢复项目。
