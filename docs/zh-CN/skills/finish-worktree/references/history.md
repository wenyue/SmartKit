# 历史准备

将发布、整合或明确选择的提交整理绑定到一个已接受范围、不可变基点、来源分支和 HEAD/树、完整任务归属提交范围及目标边界。默认保留提交。整理提交需要用户明确请求或适用项目要求；历史准备不能暗中同步分叉，也不能改变已接受内容。

## 使用已接受状态的证据

必需检查必须通过；通常还要求无阻塞问题的正式审查覆盖确切已接受 HEAD/树。只有实施负责人的契约明确授权、且由其提供证据时，替代路径才有效：带不可变输入的完整原始审查报告、每项发现的处置、获授权的有界修复差异，以及负责人在确切最终 HEAD/树上对该差异和所有阻塞发现已解决的验证。这属于负责人验收，不是新的正式审查结论。保留原始受审状态和报告，不得将它们改称为对修复后状态的审查。

收尾使用这些证据，不进行正式审查。证据缺失或无效、存在未解决阻塞，或已接受提交之外仍有任务工作时，交回实施负责人，按其修复和审查次数限制处理。只有所选操作不会影响无关本地状态且能够证明其得到保护时，才可将其保留。

## 已经交付

重写历史或交付前，检查权威目标是否已包含每项已接受效果。祖先关系能够证明确切已接受范围时，就足够了。否则，需要覆盖每项效果的明确等价改动证据，以及绑定到确切目标 HEAD/树的已接受状态证据。使用实施负责人提供的证明，或将当前目标交回该负责人。空 diff、相似消息、工单状态、部分补丁、PR 或保留分支本身，都不能证明交付。

已证明的**Already Delivered**可以避免重写、推送和整合。在历史和结果记录中保留其权威目标身份及证据。

## 保留提交

相对冻结边界核对已接受范围中的每个提交。证明来源仍处于已接受状态证据所绑定的 HEAD/树：该 HEAD 就是交付提交，无需修改历史即可证明历史准备完成。选定结果与已观察发布情况兼容时，可以使用已发布提交。保留已接受结果和操作边界之外的本地状态。

## 整理检查点提交

要求来源按 `git status --porcelain=v1 -z` 判断为干净，整个范围归属任务、确切目标是其祖先，并有证据证明该范围尚未发布且未被依赖。确定提交权限和仓库正常 hooks。准备前运行 `python "<skill-root>/scripts/consolidate_worktree_history.py" --help` 探测；探测失败时停止，不产生历史效果。

在受影响工作树之外准备自有提交消息文件。在 `refs/smartkit/recovery/` 下预留一个预期不存在的唯一引用，及其派生的 `<recovery-ref>-candidate` 引用。在外部[操作记录](recovery.md#operation-receipt)中记录确切创建、保留、删除权限、预期值、消息字节和生命周期负责人。消息文件只创建一次，并在使用前验证。

```text
python "<skill-root>/scripts/consolidate_worktree_history.py" --repository "<source-worktree>" --target "<exact-target-oid>" --message-file "<external-message-file>" --recovery-ref "<new-recovery-ref>"
```

工具执行带 hooks 的正常提交，将检查点保留在恢复引用下，并检查新提交以目标为唯一父提交、已接受树保持不变。其内部 Git 操作构成一次历史尝试；输出的 JSON 是需要复核的证据。

成功后，独立证明来源 HEAD 和分支、唯一父提交、相同树、干净检出目录及保留的恢复引用。沿用相同树和未变已接受 diff 的验收证据，保留原始输入身份；重新运行依赖提交身份或 hooks 的检查。hook 改变树时，该绑定失效，交回实施负责人，按**使用已接受状态的证据**处理。

失败后，检查检出目录、分支、索引、工作文件和两个恢复引用。保护条件成立时，工具可以恢复其受控检出状态；否则保留部分状态。即使 hook 拒绝提交，创建恢复引用也已产生效果。为负责人保留候选、消息和操作记录，任何接续前先使用[操作效果恢复](recovery.md)。

## 保留结果

记录已证明的历史及其策略、基点和目标边界、已接受状态证据、交付 HEAD/树或 Already Delivered 证明，以及恢复项。后续目标移动或结果操作失败不能替换它。仅在结果操作的依赖仍匹配时继续。否则，将观察状态交回实施或目标移动负责人，按**使用已接受状态的证据**同步并验收。新的已接受状态不会改写已证明的历史记录。
