# 转回供审阅

在 review 前或后，将任务修改与一个检出目录的工作文件组合。确切保留目标 HEAD 和完整索引，包括已有暂存内容。这是等待接受的交接，不是合入。只有独立的项目/调用者策略或明确选定的历史操作要求时，才需要正式 review。

## 准备组合结果

区分三个输入：

| 输入 | 含义 |
| --- | --- |
| **B** | 衡量任务修改所依据的不可变共享基线提交/树。 |
| **S** | 为本次交接选定的任务结果：确切内容、不存在状态、类型和模式。 |
| **W** | 目标的实际工作文件，包括已提交的演进和本地修改。 |

S 可以包含归属明确的暂存、未暂存和未跟踪工作，无需提交或改变源索引。排除无关工作；归属或基线未解决时，保留双方状态并交回实现流程。转移 **B → S**，而不是整个源检出目录。目标 HEAD 和索引都不代表 W，当前目标 HEAD 也不能直接替代 B。

W 等于 B 时使用 S。保留目标独有修改，相同修改只包含一次。文本重叠时，在临时文件上运行 `git merge-file -p`，以 W 为本地版本、B 为祖先、S 为传入版本。即使合并干净，也要检查语义兼容性。写入目标前确定每个输出。冲突未解决或意图不明确时询问；解决期间保留双方状态。删除/修改冲突、复杂重命名和二进制重叠需要明确解决方案。重新生成仍由确定性的生成所有者负责，并需要已接受的授权。

## 保留确切的输入和输出快照

在准备和应用期间协调写入者。在两个工作树及其 Git 目录之外创建外部操作目录。保留可读的 `before/` 和 `after/` 目录树，只包含受影响的相对路径：before 保存 W，after 保存组合结果。缺失文件表示不存在；记录受影响路径列表，以区分删除和遗漏输入。不经过过滤器或换行转换，复制字节和预期模式，并验证副本。不刷新索引，捕获目标分支/HEAD 和完整原始索引，包括任何 split-index 依赖。记录源身份和选定的 S 状态，供最终比较。

使用真实目录中的普通文件。检查重命名两端和受影响的祖先路径；将 Git 管理路径、嵌套仓库、符号链接和文件别名排除在操作之外。保留已有权限。Git 补丁记录可执行模式，不包含所有权限或元数据：使用前，检查原生操作对实际文件和平台的行为。例如，文件替换可能无法保留显式 Windows ACL 或 POSIX 扩展属性。对此类文件，使用已验证能够保留属性的原生方法，否则停止受影响的转移。仅有可读备份不能证明这些属性可以恢复。

## 选择保留字节和权限的转移方法

使用能够保留已确认权限的原生文件操作：创建时检查预期不存在，替换或删除前检查确切前态。工作文件 Git 补丁是普通文件的一种选择。先检查适用的 Git 属性：即使不暂存，过滤器、文本转换、`ident` 和 `working-tree-encoding` 也可能转换字节。存在这些转换或补丁无法表达的权限变化时，改用直接保留字节的文件操作。

选择补丁方式时，在生成和应用补丁时都关闭换行转换，避免外部 `core.autocrlf` 设置将快照字节规范化。在操作目录中执行以下命令，以保留原始字节的方式将标准输出保存为补丁文件，放在两个目录树之外：

```text
git -c core.autocrlf=false diff --no-index --binary --no-renames --no-ext-diff --no-textconv --no-color --src-prefix=a/ --dst-prefix=b/ -- before after
```

退出码 1 表示发现差异；0 表示没有变化。其它失败会停止准备。检查补丁的确切路径集合和输出，包括新增与删除。两个命名的快照目录额外增加了一级路径，因此在物理目标检出目录中执行：

```text
git -c core.autocrlf=false apply -p2 --check --whitespace=nowarn <absolute-patch-file>
git -c core.autocrlf=false apply -p2 --whitespace=nowarn <absolute-patch-file>
```

## 复核准备好的状态，应用并验证

应用前，将每个受影响的目标路径与 before 比较，验证源 S 和已捕获的 HEAD/索引未变，并确认备份和输出仍与准备时一致。仅检查补丁不够：上下文匹配可能容忍后续编辑。只有协调好的写入窗口仍然有效时才应用。仅应用到工作文件；`--index`、`--cached` 和 `--3way` 会改变索引约定，`--reject` 则允许部分应用。空补丁无需写入。

验证组合内容、不存在状态和权限完全符合预期，目标 HEAD/完整索引未变，源以及所选操作可能影响的任何外部状态均被保留。在组合后的目标上运行相关的非修改性检查。修复、格式化或生成需要另行明确授权。完整转移后检查失败，仍应保留可审阅结果和失败证据；不要仅为抹去该结果而还原。

## 处理中断并保留至接受

失败、状态漂移或响应缺失时，停止并确认原进程是否已结束。将实际文件与 before 和 after 比较；保留补丁、备份、源和失败细节。不自动重试或回滚。检查当前内容和权限后，只完成或还原归属明确的修改；存在后续编辑或归属不明的部分写入时，解决后才能再次写入。恢复也必须保留 HEAD/索引及无关工作。

报告源、目标和备份位置、保留与验证结果，以及下一步 review 或接受动作。在用户接受转移前，保留源工作树、分支、已准备的输入和备份。委托接受必须能够追溯到用户授权；仅负责清理不意味着有接受权限。接受后，删除仍须满足入口的清理条件。目标中已存在相同修改，不会将此次交接变成交付。
