# 移回检出目录

公共路径 `return-for-review` 在审查前或后，将已接受任务改动转入一个目标检出目录的工作文件，同时完整保留其 HEAD 和索引。已有暂存内容保持暂存。此路径始终属于非整合性交接。

## 冻结三个输入

确定目标与已接受任务范围。建立**B**，即衡量任务改动的不可变共同基线；**S**，即冻结的已接受任务结果；以及**W**，即准备时目标的实际工作文件。用提交或树 OID 固定 B，用确切字节、缺失状态、类型和模式固定 S。S 可以包含可归属的已暂存、未暂存和未跟踪工作，无需提交或改变源索引。将分层编辑解析为已接受的最终内容，排除无关源工作；归属不明时停止。

只转移**B → S**。W 包含目标已提交的演进和本地改动，不是 HEAD 或索引版本。不得复制整个检出目录，也不得图方便将目标当前 HEAD 当作 B。B 或 S 含糊时，保留双方并将决定交回结果负责人。只有独立适用的项目或调用方策略，或明确选择的历史操作，才要求正式审查。

## 写入前准备完整结果

从 B → S 推导全部受影响路径，包括受支持重命名的两端。在批次边界采集有界路径与祖先证据，以及完整目标 HEAD/索引证据。依赖仍匹配时，复用不可变 B 和已接受 S 的证据。只有具体状态保护风险涉及无关路径时，才检查它们；普通转移无需反复清点全局状态、未跟踪或忽略内容。

准备一个已接受的组合结果。W=B 时直接使用 S。保留目标独有改动，相同编辑只包含一次。普通文本重叠时，用原生三方合并，以 B 为祖先、W 为本地、S 为传入输入，例如对临时文件运行 `git merge-file -p`。即使没有文本冲突，也要检查语义兼容性并验证组合行为。冲突块、删除与修改冲突、复杂重命名、二进制重叠、不受支持的类型或模式、不兼容行为或含糊生成输出，都应在目标写入前停止。重新生成仍由其确定性负责人处理，并需已接受权限。

在已有目录中创建、更新或删除普通文件时，读取[转移机制](transfer-mechanism.md)，准备一个包含预期 W 和已接受输出的工具计划。W=B 时直接使用已接受 S 文件；重叠时提供已准备的组合输出。工具在应用任何变更前，冻结全部输出和可读外部备份。主动准备完整计划，不要通过 Agent 调用逐文件驱动子进程。Agent 负责任务归属、B/S/W 推理、语义和验证；工具负责受保护的机械操作。

将不受支持的转移交回实施负责人。另一种已授权机制必须证明同样的整批准备与状态保护，包括缺失状态、类型、模式、别名和符号链接祖先。工具能力检查拒绝操作，不意味着获准绕过边界。准备失败时，目标工作文件保持不动。

## 在状态保护证据下应用 <a id="apply-with-preservation-evidence"></a>

与其他写入者协调，然后在机制的入口、路径和出口保护及持久化写入记录下，一次性应用已准备批次。复用其来源、目标 HEAD/索引和输出证明，不要为每个子操作重复全仓库检查；出现漂移或依赖变化时重新观察。部分写入、响应缺失和漂移，需要先检查原始操作记录并执行[部分转移恢复](transfer-mechanism.md#partial-file-transfer)，才能继续。该机制处理合作式并发和已检测漂移，不能承诺跨平台的多文件原子写入，也不能防御任意同时写入者。

在组合目标上运行相关非修改式验证，复用有效检查，重新运行输入变化的检查。格式化器、修复器或生成器属于需要明确权限的独立操作。结合工具输出证明和具体外部依赖的有界证据，证明状态保护成立。全部应用后验证失败时，保留可审查的目标、来源、备份及失败事实；不得通过回滚已完成转移来抹去结果。

已证明的转移包含状态保护与必需验证、确切来源、目标和备份位置，以及下一步审查或验收操作。来源工作树、分支、快照、备份和必需恢复项应保留到用户接受转移。委派验收必须可追溯到用户授权；仅负责清理不授予验收权限。验收前，清理处置为保留；验收后，已有清理权限和生命周期条件仍然适用。即使目标已经包含相同改动，也不能将此次交接视为交付。
