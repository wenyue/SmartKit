# 返回审查

在目标工作树中呈现已接受结果，同时保持目标 `HEAD` 和每个索引条目完全不变。这是非集成交接。

1. 重新检查目标身份，并根据已证明目标边界与交付 tree 之间的差异推导确切传递写入集合。若**已交付**使得没有已接受效果需要返回，则重新证明该权威结果并立即结束结果流程：保留目标，不创建备份或清单，不执行传递，也不进入恢复步骤。否则捕获范围内只读预检证据：`HEAD`；写入集合路径的确切索引条目和 blob OID；以及它们的非索引状态、文件类型、模式、适用符号链接目标和内容哈希。使用有界身份和状态证据，将其他每个项目置于写入集合之外，并发现意外效果。
2. 写入前，为传递可能触达的每个路径创建获准的外部备份和清单，作为一次逻辑备份尝试，其中包括不存在状态、文件类型、符号链接目标、模式和字节。证明该尝试完整、可读且位于每个受影响工作树之外。
3. 对每个路径分类。对于没有目标本地变更的范围路径，验证完整的仅工作树 patch。对于重叠文本，在临时文件中根据 merge-base 版本、当前目标工作文件和已接受结果构建三方候选项。若存在删除或修改冲突、复杂重命名、二进制重叠、不兼容的文件类型或模式、互斥行为、有歧义的生成输出，或已接受证据无法确定的任何结果，在不安全写入前停止。只有通过明确获准的确定性所有者流程才能重新生成。
4. 每个路径都无歧义后，将完整的仅工作树传递作为一次受保护批次逻辑尝试应用，不执行暂存。逐路径写入是子效果。路径名相同表示重叠，本身不是冲突证据。
5. 在目标中运行必要的非变更性验证。格式化程序、修复程序、生成器或依赖更新器属于独立变更，需要自己的权限和证明。
6. 证明目标 `HEAD` 和写入集合索引条目均未改变，每个受影响路径都包含已接受变更及每项兼容的本地变更，而且有界 Git 身份和状态证据没有显示写入集合之外的意外效果。返回的变更保持未暂存或未跟踪。
7. 在结果所有者接受工作树交接前，保留源分支和工作树、历史恢复引用和外部备份。将 `outcome_result: proven` 冻结为非集成交接，并返回每个确切位置和下一项审查操作。

批次传递部分完成或失败后，只有本次运行的确切写入集合被完整观察、不覆盖任何中途编辑，并且获得另行授权时，才能通过一次恢复尝试从备份还原。有歧义的写入集合或不安全恢复会保留确切的当前目标和备份。若批次已经完成，但传递后验证或证明失败，则保留该可供审查的目标和备份；不要还原。传递和证明成功时不进入恢复路径。按照顶层阶段状态对结果分类，并记录任何后续还原，但不替换作为原因的状态。绝不重试有歧义的尝试、移动目标 `HEAD`、改变索引或重置无关状态。
