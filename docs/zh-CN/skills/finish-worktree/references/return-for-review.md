# 移回检出目录

面向既有调用方，公共路径仍保留为 `return-for-review`。它执行工作文件转移，在审查前后均可使用：将已接受的任务
改动带入一个目标检出目录，同时准确保留其 HEAD 和完整暂存区。原有已暂存内容仍保持已暂存；转移改动只影响工作文件。
这始终属于非集成交接。

## 冻结三个输入

确定目标检出目录和已接受的任务范围。建立**B**：衡量任务改动的不可变共同基线；**S**：已接受任务结果的冻结快照；
以及**W**：准备时目标的实际工作文件。用提交或树 OID 固定 B，用准确文件字节、缺失状态、类型和模式固定 S。
S 可以包含归属明确的已暂存、未暂存和未跟踪任务工作，无需创建提交或改变来源暂存区。将分层改动归并为已接受的最终
内容；归属不明时停止。S 不得包含来源中的无关工作。

只转移任务差异**B → S**。W 不是目标 HEAD 或暂存区版本：它包含目标上已提交的演进和用户本地改动。绝不复制整个
来源检出目录，也不能仅因方便就把目标当前 HEAD 当作 B。无法明确共同基线或已接受的来源快照时，保留双方状态，
将该决定交回结果负责人。只有项目或调用方政策另行要求，或明确选定的历史操作要求时，才需要正式审查。

## 写入前准备完整结果

从 B → S 推导准确的受影响路径，包括受支持重命名的两端。对这些路径及其祖先路径采集有界证据，在批次边界采集完整
目标 HEAD 和暂存区证据。不可变 B 与已接受 S 的既有证据，在依赖仍匹配时继续有效。只有具体的状态保护风险涉及无关
路径时，才检查这些路径；普通转移无需反复采集全局状态、未跟踪内容或忽略内容清单。

在一个本地批次中准备已接受的组合结果。W 等于 B 时，S 就是结果，三方合并不会提供额外信息。保留目标独有改动，
相同改动只保留一次。普通文本存在重叠时，使用原生三方合并，以 B 为祖先、W 为本地输入、S 为传入输入，例如对临时
文件执行 `git merge-file -p`。即使 Git 未报告文本冲突，也要检查语义兼容性并验证组合行为。冲突块、删除与修改冲突、
复杂重命名、二进制重叠、不支持的类型或模式、互不兼容的行为，以及含义不明的生成结果，都应在目标写入前停止。
重新生成仍由其确定性生成工具负责，并须具备已接受的权限。

在现有目录中新增、修改或删除普通文件时，使用[批量转移工具](recovery.md#batch-transfer-mechanism)。为它提供一份
已接受输出计划，包含预期 W 状态和输出状态。对于简单的 W=B 情况，计划可以直接引用已接受的 S 文件；存在重叠时，
提供准备好的组合输出。工具在应用任何改动之前，将全部输出和可读备份冻结在受影响工作树之外。它负责确定性取证和
有界操作；智能体负责任务归属、B/S/W 推理、语义和必要验证。一次准备完整计划，避免通过智能体工具调用为每个文件
分别驱动子进程。

不受支持的转移继续由所属实施工作流处理。另一种已授权机制必须建立相同的完整准备与状态保护契约，包括缺失状态、
类型、模式、别名和符号链接祖先路径；工具的支持范围限制不构成临时采用不安全写法的许可。准备失败时，目标工作文件
保持不变。

## 在状态保护证据下应用 <a id="apply-with-preservation-evidence"></a>

先与其他写入者协调，再应用准备好的批次一次。工具在开始时检查已接受的 S、目标身份、HEAD 和完整暂存区；批次内只
保护各项相关路径、祖先路径和输出。它持久记录写入，在结束时检查结果路径及 HEAD、暂存区未变的事实。复用这份证明，
避免围绕每个子操作重复检查整个仓库。只有实际漂移或其他操作改变了依赖时，才补充观察。

不存在可移植的多文件文件系统原子性保证。本流程保护的是协作式并发和检测到的漂移，不能对任意同时写入者作出保证。
部分写入、响应丢失和观察到的漂移按[恢复](recovery.md#partial-file-transfer)处理；选择后续动作前先检查原始操作
记录。路径名相同本身不构成冲突，文本合并干净本身也不构成语义证明。

在组合后的目标上运行相关的非修改式验证。复用仍然有效的检查，重新执行输入已改变的检查。格式化工具、自动修复工具
或生成器属于独立操作，除非明确授权，否则不在本次转移范围内。完整暂存区保护使原有已暂存内容继续保持已暂存；
转移本身只改变工作文件。使用工具的输出证明，以及针对具体外部依赖的有界证据，建立状态受到保护的结论。后续验证
失败时，保留可审阅的目标、来源和备份及失败证据，不得回滚已经完整应用的转移。

经证实的转移返回 `outcome_result: proven`、`classification: non-integrating handoff`，以及准确来源、目标和
备份位置与下一步审查或接受动作。来源工作树、分支、快照、备份及必需恢复项应保留到用户接受本次转移为止。
代理验收必须能够追溯到用户授权；生命周期负责人不能仅凭负责清理就代用户验收。验收前，清理处置为保留；验收后，
既有清理权限和生命周期条件仍然适用。任何工作文件转移都不能证明交付，即使目标已经具有相同改动。
