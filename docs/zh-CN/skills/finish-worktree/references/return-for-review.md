# 返回审查

在目标工作树中呈现已接受结果，同时保持目标 `HEAD` 和每个索引条目不变。这是非整合性交接。

1. 复核目标身份，并为其 `HEAD`、完整索引条目、已暂存和未暂存改动、未跟踪路径、文件类型、模式及字节创建快照。根据已证明目标边界与交付树之间的准确差异推导转移内容。如果**已交付**后没有可返回的已接受范围效果，则保持目标不变。此分支立即终止该结果流程：返回权威的**已交付**结果及其证据；不创建备份或清单，不执行转移，也不进入后续任何转移或恢复步骤。
2. 写入前，以一次逻辑备份尝试，为转移可能触及的每个路径创建已授权的外部备份和清单，包括不存在状态、文件类型、符号链接目标、模式及字节。证明该尝试已经完成、内容可读，且位置在每个受影响的工作树之外。
3. 对路径分类。对于没有目标本地改动的范围路径，验证完整的仅工作树补丁。对于重叠文本，在临时文件中根据合并基点版本、当前目标工作文件和已接受结果构造三方候选。每个路径都无歧义后，以一次受防护的批次逻辑尝试应用完整的仅工作树转移且不暂存；其逐路径写入是子效果，而不是独立尝试。路径名相同只是重叠，并非冲突证据。
4. 遇到删除与修改冲突、复杂重命名、二进制重叠、不兼容的文件类型或模式、互斥行为、有歧义的生成输出，或已接受证据无法确定的结果时，在不安全写入前停止。只有通过明确授权的确定性责任方流程才可以重新生成。
5. 在目标中运行所需的非修改性验证。格式化程序、修复程序、生成器或依赖更新器是单独的修改，需要自身的权限和证明。
6. 证明目标 `HEAD` 和每个索引条目均未改变；无关本地状态与快照一致；每个返回的范围路径都包含已接受改动和所有兼容的本地改动。返回的改动保持未暂存或未跟踪状态。
7. 在结果责任方接受工作树交接之前，保留源分支和工作树、历史恢复引用及外部备份。冻结已证明的 `outcome_result`，分类为非整合性交接，并返回它们的准确位置和下一审查操作。

如果转移在完整候选形成前失败，则仅恢复本次运行写入的路径，且必须先证明不会覆盖中途发生的编辑，并把恢复作为一次单独授权的尝试。否则，保留准确的当前目标和备份。在批次转移前停止时，冻结已停止的 `outcome_result`；发生转移修改、证明失败或效果有歧义时，冻结失败的结果。记录任何后续恢复结果，但不替换该因果状态。转移后验证失败时，保留可审查结果和恢复，不要把它分类为已证明的交接。切勿重试有歧义的尝试、移动目标 `HEAD`、更改索引或重置无关状态。
