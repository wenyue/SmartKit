# 保留待续

当预期结果是让工作保持可用以便继续时，使用此路线。脏状态、未完成或未审查的工作都适用；保留不要求先清理干净或取得审查。

确定工作树、分支和 HEAD，再充分描述本地工作、任何发布、未完成检查和恢复状态，使下一责任方能够继续。记录该责任方和下一步行动。归属不确定是保留状态的理由，不意味着必须先解决每个所有权问题，或读取所有被忽略文件才能让工作保持可用。

保留源、目标、索引、引用和文件。这是只读交接。如果并发工作改变了观察到的状态，刷新继续处理记录，不要把旧观察当成冻结快照。早先未解决的破坏性或发布尝试仍需要[原尝试的恢复责任方](recovery.md)；保留其残留不能将它变成成功。

可用工作和可用的继续处理记录证明该结果。列出保留的生命周期项目及其所有者和释放条件，即可完成清理。历史通常不适用；明确的历史要求必须满足[其自身契约](history.md)。此路线证明的是非集成交接，不意味着实施验收、审查或权威交付。
