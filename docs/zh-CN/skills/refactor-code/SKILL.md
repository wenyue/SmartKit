# 重构代码

消除一个具体代码目标中已确认的结构压力。改善知识在代码中的分布和实现的组织关系，同时保持受支持的调用者可见行为、不变量和外部契约不变。结构压力决定修改的目的，受支持的契约界定修改的边界。

## 写入前确定路径

先通过已获授权的仓库读取和非修改性证据，判断请求是否属于边界明确的重构。相邻 Skill 继续负责各自的工作，并通过其现有公共 Skill 接口到达它们。

| 请求的结果 | 路由 |
| --- | --- |
| 纯符号或受跟踪路径改名，包括公共名称或外部可观察路径 | 向模型可调用的 `rename-code` 返回 **已转交** 。它负责兼容性决策。传递已确认的目标、保留边界、相关证据和所需结果。 |
| 开放式架构机会探索 | 向用户调用的 `improve-codebase-architecture` 返回 **已转交** 。仅确认探索范围，并交付该范围和结果，供用户调用；不要在此启动探索。 |
| 调用者可见行为或外部契约的非改名变更 | 返回 **超出范围** ，说明目标、可观察行为或契约发生变化的证据，以及所需结果。这包括公共接口、持久化、协议、集成和用户可见行为的变化。 |

具体重构中仍可能存在真正的设计问题。只有在既有仓库证据和普通的范围内判断无法解决实质性的接口、衔接点、适配器或测试界面选择时，才使用模型可调用的
`codebase-design`。继续前，将其结果与仓库证据核对一致。如果结果要求调用者可见行为或外部契约发生非改名变更，则属于 **超出范围** 。

**已转交** 、 **超出范围** 以及写入前的 **受阻** 结果均不执行写入。如果分类或返回的设计依赖不可用的材料，返回 **受阻** 并说明确切缺失的证据。

## 确定边界

写入前，确定目标、结构压力、预期内部结果和已接受的范围。追踪受影响的实现和调用者路径，直到足以区分哪些结构可以改变，哪些受支持的行为、不变量和外部契约必须保留。在有助于确定这些事实时，使用目标的测试、配置、历史和本地模式。

针对这次重构可能引入的回归，在每个受支持的衔接点选择保留证据。假设记录解析器的调用者依赖输入顺序得到保留，并依赖格式错误的记录产生特定错误。检查解析是否返回非空列表，不能证明任何一项保证。通过受支持的接口观察承诺的结果。有用的检查应能区分保留与回归，而不只是运行代码。

收集能在每个受支持的衔接点作出上述区分的最少证据，同时完成所有者要求的每项受影响内容检查。确定适用的项目规则、每项手写或生成内容的所有者、必需检查的路径，以及每项必需读取、命令和写入的权限。对于生成内容，在任何写入前，确定通过其所有者执行的已授权操作；直接编辑不能替代这条路径。

将发现和证明工作限制在这些义务，以及解释它们所需的集成上下文内。只有证据暴露了其他实质受影响路径或未解决风险时，才扩大范围。非关键证据不可用时，缩小结论范围，并在交付中说明。如果缺失的事实、访问条件、权限、重要证据或检查路径使安全修改或保留结论缺乏支持，在写入前返回 **受阻** ，说明确切缺口。

## 重组目标

选择能消除已接受的压力、集中相关知识的最小连贯内部结构。让压力的来源指导结构选择：重复的知识可能应放在一起；把一个概念分散开来的间接层可能值得移除。只有真实的衔接点足以证明价值时，才引入抽象。臆测性的框架、扩展点、兼容层以及仅供测试的 API 不属于结果范围。

例如，假设每次修正同一条转义规则时，几个解析分支都必须一起修改。用一个内部实现承载这条规则，可以消除重复知识，同时保留解析行为。可配置的解析框架则需要额外的真实变化才能证明其必要性。目标是集中现有职责，而不是为未来的一系列解析器做准备。

只修改必要且经所有者授权的实现内容和内部调用者，让范围始终围绕这个目标和压力。对一个内部元素的权限不会延伸到另一个。生成内容只能通过既定所有者和已授权操作修改。在整个工作期间保留无关状态和用户拥有的状态。

退役内部元素前，确认每个实质可达引用的去向。将保留断言放在受支持的衔接点；只有保留行为断言时，才能调整与结构耦合的测试。测试依赖已退役的辅助函数，意味着应改变它到达被测行为的方式，而不是丢弃它保护的行为。

## 证明结果

形成一个连贯的内部结果后：

1. 对照已确定的边界检查最终差异及必要的集成上下文。确认每项编辑都属于已授权结果、受影响调用者已迁移，且已退役内部元素没有实质可达引用。
2. 运行有区分力的保留证据，以及所有者要求的每项受影响内容检查。对等价结论复用有效证据。只有尚未覆盖的实质风险或独立要求的检查，才需要补充证明；重复证明同一属性不能关闭另一个缺口。
3. 当证据支持一项已获授权、范围内且能保留既定行为、不变量和契约的修改时，修正发现的问题。运用常规工程判断在可靠的方法之间选择，优先考虑局部性和简单性，然后重跑受影响检查。

假设一次重构将记录分组后按组顺序返回，而调用者要求保留输入顺序。保留输入位置或改变遍历方式，都可能恢复该行为。如果两者都符合既定契约和授权范围，就选择更适合当前实现、也更清晰的做法。如果所需行为或权限尚未确定，或者修改的一项实质影响仍不清楚，就停止依赖这些信息的修正：选择方法不能解决这些缺口。

## 结果与交付

只有结构压力已消除、受支持的调用者可见行为和外部契约得到保留、不变量成立、被替换的内部元素已退役、最终范围符合所有权和权限，且每项必需检查均通过时，才返回 **完成** 。

写入后，若必需检查无法通过或运行、保留证据失去区分力、现有证据不支持任何已获授权的范围内修正，或同一发现原样再次出现，返回 **失败** 。失败优先于同时存在的受阻、已转交或超出范围事实：交付必须说明已经改变的状态。保留有用状态和证据，不自行假定拥有回滚权限。

交付结构压力和结果；保留的行为、不变量与契约；改变的内部元素与调用者；已退役代码；确切检查及退出结果；修正；以及未解决或未经测试的内容。非完成结果还要指出停止事实和保留的状态。

本 Skill 不授予发布、安装、提交、推送、工作树、翻译、网络访问或远端效果的权限。目标项目治理仍然支配读取、写入、命令和生成内容的所有者。
