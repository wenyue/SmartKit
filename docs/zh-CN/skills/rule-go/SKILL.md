# Go 包契约

有意识地设计包的公共行为：API、错误身份、初始化和共享状态都应有明确的所有者。

## 为生产用途设计 API 和初始化

让产品需求塑造公共 API。仅凭测试或推测中的复用，不足以引入导出名称、接口或新的接缝。

通过构造函数、`main` 或包所属的设置函数显式初始化，而不是添加 `init()` 函数。包级全局变量应经过有意识的选择、保持稳定，并在一处初始化。

## 通过所属契约处理每个错误

将每个返回错误绑定到具名值，检查它，并通过所属契约处理或传播。通过空白标识符丢弃错误，就失去了这次决策。

包的公共错误契约决定哪些错误跨越边界。为这些错误提供有用的上下文，用 `%w` 包装，并用 `errors.Is` 或 `errors.As` 检查。

有意识地选择调用方可以检查什么。包装会暴露底层身份或类型，因此应保留已承诺的检查行为，同时避免无意中将实现细节加入公共 API。在拥有该契约的边界转换仅属于实现的错误，并保留最终处理所需的原因和诊断证据。在创建动态错误前，优先使用能够表达契约结果的现有哨兵错误。

### 有意识地选择运行时检查和终止

类型断言可能失败时，使用 `value, ok := x.(T)` 并检查 `ok`。只有可见的不变量保证类型正确时，才使用 `x.(T)`。

将 `panic`、`logger.Fatal` 和 `os.Exit` 限于无法继续执行的顶层启动路径。

## 响应取消并同步共享状态

适用标准 Go 模式时，将 `context.Context` 放在首位。让循环和长时间运行的工作响应取消。

用所属包的同步原语保护共享可变状态。

## 通过所属包提供诊断

运行时输出遵循所属包的日志约定，不要引入 `fmt.Print*` 或标准 `log` 包。说明操作，并包含诊断失败所需的值。

## 让仓库工具管理机械规范

由仓库的格式化器和 lint 工具管理布局、命名、限制、导入、注释及抑制语法。在所属配置中修改已配置的阈值，不要在这里复制。
