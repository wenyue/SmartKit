# Python 契约与运行时行为

用类型解释受支持的运行时契约。注解应阐明程序已有的含义，验证和资源处理则让这些含义在运行时成立。

## 先确定行为，再细化类型

仅修改注解时，应保留行为。如果类型化暴露出含义不明确的运行时分支，应从代码、测试或项目政策中确定其含义，而不是为了满足检查器而选择新行为。在对该分支进行受支持的行为变更前，先添加并运行一个确定当前行为的针对性测试。

使用仓库声明的 Python 版本范围支持的注解和泛型语法，仅在需要时导入类型辅助工具。

## 明确接口与状态

为公共或可复用边界的参数和返回值添加注解。根据函数的实际契约选择返回注解：

| 函数 | 返回注解 |
| --- | --- |
| 仅产生副作用的函数 | `-> None` |
| 协程函数 | 等待后产生的值 |
| 异步生成器函数 | 异步迭代器或生成器类型 |

为参数命名；只有契约确实开放或需要转发参数时，才使用 `*args` 或 `**kwargs`。签名有多个可独立选用的可选值时，将这些参数设为仅限关键字传递。

用 `Protocol` 表达结构化 API，用数据类或带类型的领域类型表达数据形状。用 `Literal`、枚举或命名类型表达有限状态，而不是用布尔标志或隐含的 `None` 哨兵表达具有业务含义的状态组合。例如，缓存若要区分“尚未加载”和“已加载但不存在”，就需要明确状态，不能让两者共用一个 `None` 值。

每个函数返回一种稳定的形状。结果具有不同含义时，使用命名结果、枚举或异常表达。

## 验证动态输入并明确状态修改权限

将 `Any` 限制在真正动态或无类型的边界，在值进入有类型的领域逻辑前进行验证或收窄。构造有类型的领域值前，验证外部映射、序列化数据和无类型提供者的值：注解本身不会执行这些验证。

只有运行时边界本质上是动态的，才使用反射、猴子补丁和元编程，并将这些机制隔离在该边界。

契约不包含修改操作时，接受 `Mapping`、`Sequence` 和 `Iterable` 等只读集合抽象。需要调用者允许修改时，要求可变类型。这些接口描述可用操作；只读接口不会使底层对象不可变。

## 让局部流程容易理解

在首次使用附近声明变量，为含义不明或空的初始值添加注解，并将可空值限制在实际可行的最小路径中。每个变量名只承担一种角色和一种类型，不要复用于不同的值。

让函数职责集中，主路径保持较浅的嵌套。对无效、缺失或无需操作的输入，尽早按契约返回结果或抛出异常；提前退出必须保留这些结果之间的区别。

## 保留失败含义与运行时约束

对于预期失败，抛出精确的领域或集成异常。跨边界转换错误时，保留有用的原因上下文。

只在拥有失败处理政策的边界捕获宽泛异常。对于无法安全容纳的失败，重新抛出或转换。

断言用于内部不变量，不用于用户输入或可恢复的运行时失败。断言可能被禁用，因此生产环境必需的验证、控制流、副作用和不变量约束必须在没有断言时仍然有效。

## 让所有权贯穿延迟执行的工作

在异步或回调边界前捕获稳定依赖；在需要状态当前值时再读取会变化的状态。

为每个获取的资源指定一个清理所有者，并明确所有权转移。在每条仍保有所有权的路径上，通过上下文管理器、`try/finally` 或所有者的生命周期方法保证清理。

## 让仓库工具管理机械规范

由仓库的格式化器、lint 工具和类型检查器配置管理各自的机械规范。
