# Python 指南

## 添加类型时保持行为

仅修改注解时，保持行为不变。当类型工作暴露出含义不明确的运行时情形时，从代码、测试或项目策略中确定其含义，不要为了满足类型检查器而选择新行为。在对此类分支作出受支持的行为变更前，添加并运行一个聚焦的测试，明确其当前行为。

使用仓库声明的 Python 版本范围支持的注解和泛型语法。仅在需要时导入类型辅助工具。

## 用签名和状态表达契约

在公开或可复用边界处为参数和返回值添加注解，包括为只产生副作用的函数标注 `-> None`。协程函数的注解应描述等待后产生的值；异步生成器函数应标注异步迭代器或生成器类型。

为参数命名，除非契约确实开放或需要转发参数，因此需要 `*args` 或 `**kwargs`。当签名中有多个可独立选择的可选值时，将这些参数设为仅限关键字传入。

用 `Protocol` 表达结构化 API，用 dataclass 或带类型的领域类型表达数据形状。用 `Literal`、枚举或具名类型表示有限状态。不要用布尔标记或隐含的 `None` 哨兵值编码有实际含义的状态组合。例如，如果缓存区分“尚未加载”和“已加载但不存在”，就明确表示这两个状态，不要让它们共用同一个 `None` 值。

让每个函数返回一种稳定的形状。当不同结果有不同含义时，使用具名结果、枚举或异常。

## 明确动态数据和修改边界

将 `Any` 限制在真正动态或无类型的边界处，然后在把值传入带类型的领域逻辑前验证或收窄类型。在构造带类型的领域值前，验证外部映射、序列化数据和无类型提供方的值：单靠注解不会执行这种验证。

只有运行时边界本质上是动态的，才使用反射、猴子补丁和元编程，并将它们隔离在该边界内。

当修改不属于契约时，接受 `Mapping`、`Sequence` 和 `Iterable` 等只读集合抽象。当调用者必须允许修改时，要求可变类型。这些接口描述可用的操作；只读接口不会让底层对象变成不可变对象。

## 保持局部值和控制流清晰

在首次使用附近声明变量，为含义不明确或空的初始值添加注解，并将可空值限制在实际可行的最窄路径内。让每个值名称只承担一种角色和一种类型，不要复用于不同的值。

保持函数职责集中，让主路径保持浅层。按照契约规定的返回或异常结果，提前处理无效、缺失和无操作输入；提前退出必须保留这种区别。

## 保留失败含义和生产检查

对预期失败抛出精确的领域或集成异常。跨边界转换错误时，保留有用的原因上下文。

只在拥有失败策略的边界处捕获宽泛异常。对于无法安全容纳的失败，重新抛出或转换。

用断言检查内部不变量，而不是处理用户输入或可恢复的运行时失败。断言可以被禁用，因此生产所需的验证、控制流、副作用和不变量约束必须在没有断言时仍然有效。

## 跨延迟执行保持生命周期

在异步或回调边界之前捕获稳定依赖；需要变化状态的当前值时，再读取该状态。

为每个已获取的资源指定唯一的清理责任方，并明确所有权转移。在每条仍保留所有权的路径上，通过上下文管理器、`try/finally` 或责任方的生命周期方法保证清理。

## 将机械性策略留给仓库工具

让仓库的格式化器、lint 工具和类型检查器配置拥有各自的机械性策略。
