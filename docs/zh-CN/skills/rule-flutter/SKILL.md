# Dart 与 Flutter 所有权

将行为、失败决策和生命周期留在拥有它们的组件中。文件操作、组件资源、导航和生成代码都遵循这一原则。

## 有意识地安排行为与数据形状

属于某个所有者的局部行为默认使用实例成员。顶层函数仅用于框架入口、文件级声明、共享算法或没有明确所有者的逻辑。仅在命名类型不能增加清晰度时，用记录表示小型局部元组返回值。

## 让文件系统操作确定自身结果

在可使用 `dart:io` 的环境中，通常直接执行所需的读取、写入、创建或删除。让操作将自身失败交给既定的恢复或报告所有者；后续操作无需复现先前瞬时查询的错误。

只有预先查询具有具体收益时，才直接或通过包装执行查询。解释 `existsSync`、`typeSync` 等查询时，应遵守它们的能力边界：

| 结果 | 含义与允许的用途 |
| --- | --- |
| 否定结果，如 `false` 或 `notFound` | 可能表示不存在、查询失败或类型不匹配。只有不存在与查询失败对当前调用者等价，且任何可能的类型不匹配都可接受时，才能跳过操作或采用默认值。 |
| 肯定结果 | 仅描述查询时的观察结果。状态可能改变，因此它既不保证权限，也不保证后续成功。 |

从实际操作的语义中获得初始化和覆盖保证。检查不存在无法提供这些保证，而默认写入可能截断已有数据。

## 保留组件与资源的生命周期

在 `dispose()` 中释放 `State` 对象的控制器、订阅和监听器。由项目生命周期机制管理的资源继续归该机制负责。

在异步间隙前解析稳定的组件依赖。间隙之后，先确认捕获的 `BuildContext` 仍处于 mounted 状态，再使用它；也只有通过该检查后，才读取会变化的状态。

## 通过所有者关闭路由和重新生成输出

通过拥有路由的 Navigator 关闭由 Navigator 管理的对话框、底部面板和覆盖层，并传递返回结果。选择所有者时，应考虑嵌套 Navigator。

将生成文件视为输出：修改其源声明，并运行项目现有的所属生成器。如果生成受阻，报告缺少的前提条件，而不是手动编辑输出。
