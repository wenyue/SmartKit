# Dart 与 Flutter 指引

## 按归属组织行为与数据形态

所有者内部行为默认使用实例成员。顶层函数用于框架入口、文件级声明、共享算法，或没有明确所有者的逻辑。

record 只用于小型、局部的元组返回，且命名类型不会让含义更清楚。

## 依据文件系统操作的契约

在支持 `dart:io` 的环境中，通常直接执行所需的文件系统操作，包括读取、写入、创建和删除。让操作将自身的失败交给既有的恢复或错误报告责任方。后续操作不必重现先前短暂的路径查询错误。

只有预先查询文件系统能带来具体收益时，才直接或通过包装方法进行查询。对于 `existsSync` 或 `typeSync` 等查询，应将 `false` 或 `notFound` 等否定结果视为无法区分对象不存在与路径查询失败；它也可能表示类型不符。只有当查询失败与对象不存在对调用方等价，且任何可能的类型不符都可接受时，才能据此跳过操作或采用默认值。

肯定结果只是检查当时的观察。它既不能保证权限，也不能保证后续操作成功；状态可能变化。

初始化和覆盖写入所需的保证，应由实际操作的语义保障。检查对象是否不存在，不能提供这种保证；默认写入可能截断已有数据。

## 保持资源与上下文的有效生命周期

由 `State` 负责的控制器、订阅和监听器，应在其 `dispose()` 方法中释放。由项目生命周期机制管理的资源仍由该机制负责。

经过异步间隔后，使用捕获的 `BuildContext` 前，应确认它仍处于 mounted 状态。稳定的组件依赖应在间隔前解析，会变化的状态只在 mounted 检查之后读取。

## 通过所属 Navigator 关闭路由

由 Navigator 管理的对话框、底部面板和浮层，应通过其路由所属的 Navigator 关闭，并传递返回结果。选择该 Navigator 时，应考虑 Navigator 的嵌套关系。

## 通过所属机制维护生成源文件

将生成的文件视为输出。修改其源声明，然后运行项目既有的所属生成器。如果代码生成受阻，应报告缺失的前提条件，不要手工修改输出。
