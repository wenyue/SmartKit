# 选择配置仓库

用户选了独立仓库维护或恢复，且仍需确定来源时，进入这一步。沿用用户的明确答复和适用的已接受字段。用户要求改变某项却未给出新值时，即使已经记录旧值，该项也仍待确定。恢复时，直接沿用绑定须有匹配的本地成功同步记录，或用户已明确选定该来源。只有用户还未确认复制来的绑定时，才将它作为来源建议出示。

缺地址时先问 Git 地址。询问仍缺的分支和项目条目。项目条目是 `projects/` 下的目录名。用户知道这些信息时，可以一次提供。建议使用已核实的默认分支或项目条目时，给出具体值，请用户确认。只用用户接受的值建立绑定。业务远端、其他仓库或不同 checkout 均不能作为来源授权。

使用不含凭据的 GitHub 或 GitHub Enterprise HTTPS 仓库地址。简写 `owner/repository` 指 github.com。私有仓库必须属于当前已认证的个人账号。凭据保留在现有的凭据存储中。恢复需要现有的私有仓库和备份条目。初始化时，如需创建指定的私有仓库，即使用户已经提供所有者和名称，也要取得明确的创建授权。新项目条目还需要已接受的备份范围。

## 缺少地址时的问法

> 你的私有配置仓库的 Git 地址是什么？可以直接粘贴地址，例如 `https://github.com/your-name/project-config.git`。
>
> 如果也知道分支和项目条目，可以一起发给我，例如 `your-name/project-config, main, my-project`。

## 确认复制来的绑定时的问法

> 当前 checkout 保存的来源是 `<repository>`，分支是 `<branch>`，项目条目是 `<entry>`。要沿用这个来源吗？可以回复 **沿用** ，或告诉我需要改哪些值。

## 补齐剩余信息时的问法

> 仓库地址已收到。要使用哪个分支和项目条目？可以一起回复，例如 `main, my-project`。

只缺一项时，只问那一项。已核实远端默认分支时，在问题里写出其名称，例如“这个仓库的默认分支是 `main`。要用这个分支吗？”

## 申请创建私有仓库时的问法

> 要创建私有配置仓库 `<owner>/<repository>`，还是用已有仓库？可以回复 **创建** ，或发已有仓库的 Git 地址。
