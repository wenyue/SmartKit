# 所有权

完整设置、备份恢复或任一本地同步操作之前阅读本文。目录和项目 schema 定义受支持输入；已记录所有权决定 Setup 渲染可以替换或退役哪些现有表面。即使独立所有者的内容位于邻近路径，也要保护它。恢复遵循维护所有者已接受的备份范围，而不是渲染所有权。

## 确定项目输入

随附目录启用 Codex、Cursor、Copilot 和 Qoder。它安装声明的共享 Rule 和 Skill、Codex Plugin Agent 默认项，以及每个目录声明的项目蓝图。可选项目配置添加外部 Skill、项目 Agent、MCP 服务器和受支持的项目级宿主设置。

当 `.agents/config.json` 存在，或已接受意图需要非默认输入时，在 `start` 前使用已加载插件的 schema 协调或创建该项目自有文件：`<skill-root>/../../setup-assets/catalog/project-config.schema.json`。缺失意味着使用随附默认值；缺少 `maintenance` 选择时仍可读取，并在明确调用的完整 setup 中解决。同一 schema 约束本地同步，并定义外部 Skill 来源、项目 Agent 映射、MCP 声明和受支持的宿主设置。设置目前针对 `.codex/config.toml` 和 `.cursor/cli.json` 中的结构化字段；其渲染器保留未声明字段。

schema 的可选字段 `ruleEntry` 选择包含生成 `Project rules` 章节的文件。省略时仍使用 `AGENTS.md`；项目策略要求本地入口时，选择 `AGENTS.local.md`。在 `start` 前，与其他权威输入一起确定此选择。

### 配置来源与恢复

目标的 `maintenance` 声明选择项目共享（`local`）、仅本机（`local-only`）或独立配置仓库（`repository`）。两种本地模式都保留现有项目权威输入。仓库模式为其声明的整文件备份选择一个个人私有 GitHub 仓库、分支和条目。绑定或使用仓库来源前，阅读 [项目配置维护](../../maintain-project-config/references/maintenance.md)。该参考负责备份范围、恢复、本地同步和发布，包括其中的状态与 Git 排除约定；setup 使用其受支持命令和引擎，不调用仅限用户调用的 Skill。编辑仓库来源时以业务项目证据为依据，再通过受支持路径应用。

整文件恢复与 setup 渲染是独立操作。按照维护参考的范围规则，备份可以保留完整原生配置、选中的生成文件，以及包含生成章节的所选 Rule 入口。恢复不使用 lock 所有权筛选这些文件，也不重新生成其内容。目标本地同步记录仍不纳入备份。恢复的 `.agents/config.json` 可以包含绑定和 `setupVersion`；复制来的记录既不能证明当前 checkout 已成功完成 setup，也不能证明运行时就绪。

用户通过 Setup 明确选择初始化／升级或恢复。恢复仅使用共享维护约定及恢复配置的本地前置条件检查，不进入完整会话、迁移或编写流程。会话 hook 不发现缺失配置，也不询问恢复。仓库启动同步要求已有有效绑定并在本地明确开启；没有偏好时默认为关闭，常规升级保留已记录偏好。

### Setup 完成与来源验证

`setupVersion` 是上次成功完整 setup 使用的 SmartKit 发布版本，不是当前已安装插件的版本，也不记录该用户的运行时状态。公开工作流只有在 CodeGraph 就绪、配置收敛和私有会话清理完成后，才写入这一个字段。准备、失败和本地同步均保留原值。保留其他项目配置值；绝不能手动推进该字段来消除 hook 提示。会话 hook 根据项目 setup 记录要求重新检查本地 CodeGraph，不会把这个持久版本当作运行时仍然就绪的证明。

完整设置中，`start` 在冻结请求前，根据选定规范来源或已安装回退来源验证输入。如果该来源拒绝按已加载 schema 准备的输入，遵循[预检](session-protocol.md#preflight)：在已接受权限内修正报告的原因，并启动新调用。返回来源和请求保持不可变。

### 项目工件与原生 Agent 纳管

`.agents/rules/` 和 `.agents/skills/` 下的项目 Rule、Skill 内容，包括生成源及其支持文件，属于项目。两种本地模式下都可在会话之间直接编辑；仓库模式下应编辑声明的源副本，再应用回来。Setup 发现并保护额外项目自有 Rule 和 Skill。项目 Agent 源也遵循相同的已选编写位置。

目标编辑不自动更新备份。恢复前，对每一项来源与目标之间的差异遵循维护参考中的用户选择路径；保留本地会跳过同步，将已接受的目标编辑采纳到备份仍是单独的操作。

Codex Plugin Agent 默认项是回退项，不是项目 Agent 声明。即使被选中进行整文件备份，原生 Cursor、Copilot 和 Qoder Plugin Agent，以及原生插件 Rule、Skill 和 MCP，仍不属于 setup 渲染范围。

完整 setup 必须协调原生宿主目录中发现的项目自定义 Agents，包括尚未声明的 Agents。`native_source` 宿主分支在 `.agents/agents/` 下保留完整原生文档，并逐字节复制到适配文件；只有该源拥有提示词和设置。同一宿主不能同时使用这个分支和结构化设置。仅使用结构化分支的宿主需要共享提示词 `source`。已经记录的插件默认项保留其所有者。纳管工具的受保护导入保留独立权威内容和现有适配文件摘要保护；它不授权改写所有权记录。在仓库模式下，该工具按照维护参考的备份约定，先将已接受的来源和配置变更保存到条目，再执行受保护的目标事务，需要恢复目标时保留源证据。

## 保留策略的加载含义

每个直接 `.agents/rules/*.md` 文件都是无条件必需 Rule。数字文件名前缀不代表类别或优先级。所选 Rule 入口的自有章节把所有发现路径放在一个必需列表中。

条件策略属于原生 `.agents/skills/rule-<domain>/SKILL.md`。其 frontmatter 名称与文件夹一致，非空模型侧 description 支持发现。普通项目 Skill 保持既有发现行为。Harness 原生插件 Rule 保留自己的加载策略。

完整设置和两种本地操作都会拒绝显式旧式条件 Rule 声明，包括旧条件索引行。重试之前，单独授权向 rule-led Skill 的源迁移，以及所选 Rule 入口中旧声明的更新或删除。Setup 不暗中改变策略何时加载。围栏示例不属于操作性索引行。

## 区分重新编写与按记录退役

对于每个生成 Rule 或 Skill，`.agents/smartkit.lock.json` 记录其蓝图指纹和确切输出路径，包括支持文件，不持久存储内容摘要。每个完整会话请求当前完整蓝图集；在评估及必要修订时，使用既有内容和当前项目证据保留合格意图。未变化的完整交接保留精确字节。

Skill 蓝图的指纹覆盖完整源目录；Rule 蓝图的指纹覆盖入口文件。私有会话登记另外封存输出字节，直到 finish。临时封存在应用过程中保护已接受交接，不妨碍项目在会话之间编辑自有内容。

移除蓝图会退役其已记录输出。目录目标改名会退役旧记录路径，并生成当前目的地。新完整交接省略的支持输出会退役；未记录支持文件仍属于项目。确切记录限定退役范围，因此邻近或看似过时文件不会因关联而获得删除授权。

维护拥有的项目同步保留生成源和蓝图记录。完整设置将项目 Agent 适配器、MCP 字段与共享/默认所有权分别记录。较广本地同步需要这一已建立记录；记录过旧或缺失时必须先完整设置。声明删除或改名时，它只退役已记录项目映射，保护共享/默认/外部资产及出处。外部 Skill 声明变化需要完整设置；本地同步拒绝时报告这个前置条件，不调用完整设置。

Setup 渲染和有意执行的本地同步保留托管渲染、共享及外部资产的摘要保护。冻结会话中，与设置相关的目标漂移由[完整会话协议](session-protocol.md)约束。

## 保留非自有字节和结构化字段

在 setup 渲染和有意执行的本地同步期间，Setup 只拥有 `.agents/smartkit.lock.json` 中记录的文件和结构化字段，以及 `ruleEntry` 选中文件中的一个 `## Project rules` 章节。完整设置、宽本地同步和仅 Rule 索引同步使用同一选择；完整设置将该选择和所选入口冻结为会话证据。备份选择不授予额外的渲染所有权。渲染替换该章节到下一个一级或二级标题之前，或文件末尾；缺失时追加。围栏内标题不定义章节边界。所选入口中的重复 Project rules 章节、所有权冲突或摘要冲突会在替换前停止设置。

保留未选择的入口、所选自有章节之外的每个字节，以及每个未声明文件、字段、目录和秘密值。修改 `ruleEntry` 会选择新的目的地，不会移动或删除现有章节，也不会删除原入口。MCP 环境字段命名环境变量；URL、命令、参数和覆盖字面量仍是项目输入。任意字符串不是秘密的证据。合格仓库证据识别出真实敏感字面量时，在渲染前停止，请其项目所有者替换为受支持的间接引用。

MCP 就绪声明是需要保护和验证的项目配置。其运行时所有者执行检查。完整 setup 还通过公开的 `setup-codegraph` 命令准备并验证 CodeGraph，并按 [完整会话协议](session-protocol.md) 在 finish 时再次检查就绪状态。这项限定准备可以安装 CodeGraph 软件包，并创建或更新目标的本地索引和运行时状态；保留现有数据和无关配置。SmartKit 插件 MCP 注册表和适配文件仍拥有 CodeGraph 的 MCP 声明。使用这条准备路径，不要使用可能重写独立所有者宿主配置的 CodeGraph 通用宿主安装器。

其他 MCP 依赖和运行时检查仍由各自所有者负责。本地同步不安装依赖，也不准备运行时，其 `clean` 结果仅证明配置收敛。CodeGraph 数据库、进程状态和日志是本地运行时证据，不能转交为就绪证明，也不属于项目 setup 版本内容。
