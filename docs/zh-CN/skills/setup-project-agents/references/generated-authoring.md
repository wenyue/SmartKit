# 生成编写

每次完整 setup 都在登记前使用本文。每份当前目录蓝图都要获得完整评估，包括指纹和输出未变化的工件。Setup 负责最终项目集合的一致性；单项 writer 结果不能证明这一点。

## 规划覆盖和加载

从冻结的 `source_root` 加载每份请求的不可变 Setup Authoring Blueprint。遵循其更新偏好和编写重点，对照合格项目证据评估完整既有内容。保留有效意图、义务、条件、例外和补充；实质变更需要蓝图要求、项目事实或已证明的缺陷作为依据。

规划应涵盖冻结请求、保留的项目 Rules、相关 Skills、适用的 SmartKit 全局 Rules 及可发现的 rule-led Skills。对每个工件，明确用途、相邻职责边界、证据及读者如何到达其职责说明：

- **覆盖：** 保留每项必需义务及其条件和例外，交由某个工件或已确立的外部所有者负责，并确保决策前能到达该说明。
- **职责：** 将操作性含义保留在其权威所有者处。生成与保留的工件必须一致；不能为了简化集合而转移或省略蓝图要求。
- **重叠：** 区分服务于不同决策的有用背景，与重复定义或不兼容指引。解决所有权，同时保留必要含义。
- **加载：** 为无条件 Rules 和有条件 rule-led Skills 建立受支持的路径。检查组合加载；当前对话中可见不能证明未来可用。

在共同计划中记录已确定的职责分配、更新方向、合格证据和所有者依赖状态。超出 setup 指纹范围的证据需要说明来源和局限。在计划与蓝图范围内，给每个 writer 留出组织 Candidate 的空间。影响相邻职责的发现交回 Setup 处理，不扩大该 writer 的范围。

## 准备证据并调用固定来源的 writer

按 Skill 入口中的示例运行 `workflow.py writer-inputs`。阅读其 `--help`，了解输入、输入包字段、路径解析和机械检查。只使用成功结果。

输入包将完整既有工件字节，包括项目自有的支持内容，保留为证据。这些副本既不授权编辑，也不要求每个文件都成为生成输出；由蓝图、所有权和 writer 冻结的 Candidate 范围决定这一点。准备操作不进行编写评估，也不能判定共同计划中的证据是否合格。

调用 `source_root/skills/write-rules-and-skills/SKILL.md` 处的公共 writer 及其所需同源引用，包括 `writing-for-agents`。使用目标仓库上下文，将不可变蓝图作为已接受的任务/规格输入，并将 `GENERATED` 作为请求根目录。提供共同计划、完整当前内容、合格的所有权/加载证据和依赖状态。环境中或目标检出中的 writer 不能替代这一固定来源路径。

每个请求恰好对应一个 Candidate，遵循公共 writer 自己的范围、验证、审查和结果协议。各任务可以顺序执行。只接受独立的 `COMPLETE`，其确切 Candidate 路径须位于 `GENERATED` 下并满足对应蓝图，同时在交接中保留所需证据。蓝图中的就绪术语不能替代该结果。

未变化工件也需要相同的评估和 `COMPLETE`；writer 可以返回经验证的精确副本，以及仍属于该工件的全部支持文件。字节相同可避免重写目标。“所有权”负责退役规则：省略已记录的支持输出不等于复用。

## 登记前协调整体结果

将全部生成输出与保留的 Rules 及相关 Skill/全局策略一起对照共同计划。检查丢失的义务、过时证据、所有者冲突、重复和失效加载路径。任何登记之前，先协调好组合结果。

如果协调改变了计划，准备新的输入包，并向受影响 writer 提供相关当前交接结果。每项修正都通过单独的公共 writer 调用完成，重新冻结单 Candidate 范围；每个改动的 Candidate，包括受影响的较早输出，都须取得新的 `COMPLETE`。已接受的 Candidate 必须保持与交接时一致。重复此过程，直到每个请求和当前交接结果都符合协调后的计划。

使用 ID 和交接中的每个输出，将每个最终请求登记一次；`register --help` 提供路径语法。登记检查并记录机械输出，不证明语义一致性。所有请求登记完毕后，继续执行 `finish`。

## 处理修正和不可用输入

登记前，只要冻结证据保持完整，就可以修正计划输入错误。登记输入错误只有在该请求尚未登记且其占用已释放时，才可修正并重试。再次操作前，检查报告中的任何占用或输入包清理残留。输入包始终是私有会话输入，直到终止清理。

登记开始后发现语义修正需求，必须取消并重启；修改已登记输出或替换登记记录都不是修正路径。来源或目标漂移遵循同一冻结会话规则。

如果固定来源不支持 `writer-inputs`，保留诊断、取消会话，并通过新的 setup 调用选择已更新来源。不能修改冻结来源或换用环境中的实现。

writer 返回 `NEEDS_INPUT` 或 `BLOCKED`，缺少必需权限、依赖、访问或角色，或必要修正超出冻结生成请求范围时，停止生成。保留确切依赖和证据，再按照 [停止与恢复](session-protocol.md#stop-and-recover) 取消；不登记部分工作。通过公共 writer 的所有者依赖/用户协助路径，取得另行授权的权威修正，再从已接受输入重启。固定来源和安装缓存都不能作为修正目标。

编写不授予下游效果权限。按会话协议单独确定该权限，包括在获准效果改变冻结目标证据时取消会话。
