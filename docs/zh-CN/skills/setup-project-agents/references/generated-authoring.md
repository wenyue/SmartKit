# 生成编写

每次完整设置都使用本文，在任何请求注册之前完成。即使上游指纹和已记录输出未变，也请求当前每个目录蓝图。Setup 必须确定结果项目集合能够协同工作；单项编写结果不能证明这一点。

## 确定固定输入和职责

从会话的 `source_root` 解析每个请求对应的不可变 Setup Authoring Blueprint。加载 `source_root/skills/write-rules-and-skills/SKILL.md` 的公共 writer，将全部必需同源引用及其 `writing-for-agents` 依赖固定在该来源。环境中或目标检出中的 writer 不是本会话的权威。

Setup 拥有整套职责和加载计划。公共 writer 拥有单个 Candidate 的编写、范围内设计、验证、审查和结果。蓝图提供必需目标含义；目录、schema 和脚本拥有其事实边界和机制。规划不能添加生成请求、覆盖蓝图或授权其他所有者的改动。

读取完整当前项目输入和现有生成内容作为证据。应用不可变蓝图时保留合格项目意图。依据冻结请求、目录和蓝图确定结果成员，包括请求之外保留的项目 Rule。相关 Skill 的职责影响集合时，将它们纳入；不要假设固定工件数量。

## 规划整套覆盖和加载

任何 Rule 编写之前，确定每项必需职责由谁拥有，以及读者如何到达其内容。对每个 Rule，确定目的、主要内容、邻接边界和必要引用。将相关 Skill 纳入同一计划，避免 Rule 重新定义其他地方拥有的流程或事实。

考虑适用的常驻项目 Rule 和 SmartKit 全局 Rule，以及受支持使用中可以加载的 rule-led Skill。通过受支持的发现和加载证据确定这些路线。仅在当前对话中可见的指令，不能证明未来读者会收到它们。

用以下区别确定分配：

- **覆盖：** 每项必需义务都需要负责工件，或一个需要时可达的已确定外部所有者。保留其条件和例外；加载过晚的引用不能覆盖该决定。
- **职责：** 策略、任务流程和项目事实保留在其规范所有者处。生成与保留工件必须对一项职责在哪里结束、另一项从哪里开始达成一致。不能仅为简化集合而重新分配或省略蓝图要求。
- **重叠：** 区分有用上下文和重复的操作性定义。两个工件可以针对不同读者决定讨论同一主题；独立规定同一含义或给出不兼容方向时才出现问题。确定所有者及受支持引用，同时保留每位读者所需含义。
- **加载：** 无条件基线策略属于受支持的直接 Rule 路线；条件策略需要可发现的 rule-led Skill，具备充分入口信息和及时指针。检查实际组合加载情况，而不只孤立检查每个文件。

在共同计划中记录已解决职责、所有权/加载证据和未解决所有者依赖。这是 Setup 对整套结果的资格确认，不是文档模板。让每个 writer 在该计划和蓝图内，自行组织和表达其 Candidate。改变邻接职责的发现交回 Setup 协调，不扩大 writer 的冻结范围。

## 取得完整的单 Candidate 交接

对每个请求，在目标仓库上下文调用固定来源的公共 writer。将其 Setup Authoring Blueprint 作为已接受任务/规格输入，将 `GENERATED` 作为请求根。每项工作，包括 Skill 工作，都接收共同计划、所有权及加载证据、所有者依赖状态和完整当前项目内容。每次调用只拥有一个 Candidate，带有自己的冻结范围、证据、验证、审查和结果。工作可以顺序执行。

只消费公共 writer 的 `COMPLETE`，且其确切 Candidate 路径已经位于 `GENERATED` 下并满足对应请求蓝图。在交接中保留蓝图要求的证据。蓝图的就绪术语不能替代公共 writer 的结果。

编写不提供下游效果权限。此类效果发生前取得单独授权；若它改变与设置相关的目标状态，则应用冻结目标漂移规则。writer 返回 `NEEDS_INPUT` 或 `BLOCKED`，或必需权限、依赖、访问或角色缺失时，停止生成。保留确切阻碍和证据，按[停止与恢复](session-protocol.md#stop-and-recover)取消，并仅在解决后启动新会话。不要注册部分工作。

## 注册前协调整体结果

使用编写发现更新共同计划。对照计划和已接受蓝图，将全部生成输出与保留 Rule、相关 Skill/全局 Rule 上下文一起审查。把上述 Setup 的覆盖、职责、重叠和加载判断应用到实际组合结果。单项 `COMPLETE` 证明其 Candidate，不证明整套一致性。

每项必要生成修正都通过独立有效的公共 writer 调用处理，提供更新计划和新冻结的单 Candidate 范围。既修正受影响的先前输出，也修正后续输出，为每个改变的 Candidate 取得新 `COMPLETE`。重复整套检查，直到全部请求输出及当前交接与已解决计划一致。不要绕过交接编辑已接受 Candidate，也不要用注册替换它。

任何冻结生成请求之外的必需修正，包括保留项目 Rule 或 SmartKit 全局 Rule，都会停止本会话。取消会话，保留所有者依赖，通过公共 writer 的所有者依赖/用户协助路线，取得单独获授权的规范修正。然后从所得已接受状态重启。固定来源和安装缓存都不是替代修正目标；发现问题不能扩大本会话或 writer 工作。

## 只注册最终交接

整套协调及全部修正完成后，每个请求注册一次，使用其 ID 和当前 `COMPLETE` 交接中的确切路径：

```text
python "<skill-root>/scripts/workflow.py" register --session "<SESSION>" --request-id "<ID>" --output "<PATH>"
```

对交接中的支持文件重复使用 `--output`。路径可以是 `GENERATED` 下的绝对路径，或 `.agents/` 下相对于目标的路径。注册验证并记录单个请求的输出，不认证 writer 的语义交接。重复注册会被拒绝，不替换先前记录。

只有该请求仍未注册且其占用已释放时，注册输入错误才能修正并在同一会话重试。占用清理失败后，在任何重试前检查所报告会话。目标漂移要求取消和重启。注册开始后若发现语义修正需要，取消并重启，不修改已注册输出。全部请求注册后，继续 `finish`。
