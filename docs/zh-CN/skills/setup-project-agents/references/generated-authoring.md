# 生成内容编写

每次全量设置都会请求 catalog 中的全部当前契约，即使上游指纹和记录的输出均未变化。注册任何请求前，完成此工作流。将当前项目证据和生成内容作为编写输入，在应用不可变上游契约的同时，在最终集合中保留有合格证据支持的项目意图。

## 规划最终集合

从 `source_root` 解析每个请求对应的不可变 Setup Authoring Contract。加载 `source_root/skills/write-rules-and-skills/SKILL.md` 中的公共 writer，包括同一来源的引用文件和 `writing-for-agents` 依赖。环境中已有的 writer 或目标工作区中的 writer，都不是本次会话的权威。在开始编写任何 Rule 前，运用该 writer 的**职责分配**标准，建立一份共同规划。

规划最终的整组项目 Rules，包括生成请求之外保留的 Rules。根据冻结的请求、catalog、契约和完整的当前项目输入确定成员，不预设固定数量。为每条 Rule 明确职责、主要内容、与相邻所有者的边界，以及必要引用。Skills 的职责会影响分配时，也将其纳入。提供适用的始终加载的项目 Rules 和 SmartKit 全局 Rules，以及受支持使用方式下可能共同加载的条件 Rules 的证据。通过受支持的发现和加载路径建立上下文，不能只依赖当前会话中可见的指令。

规划记录所有权与加载证据，以及尚未解决的所有者依赖。设置流程负责这份批量规划和会话协调；公共 writer 负责每条 Rule 或 Skill 的职责分配及单一定义判断。catalog、schema、契约和脚本仍保有各自的事实与边界。规划不能增加生成请求、覆盖契约或授权其他所有者。

## 注册前编写并协调

针对每个请求，在目标仓库上下文中调用固定来源的公共 writer，将其 Setup Authoring Contract 作为已接受的任务或规格输入，并将 `GENERATED` 作为请求根目录。向每个任务提供共同规划、所有权与加载证据、所有者依赖状态和完整的当前项目内容，Skill 任务也不例外。每次调用只负责一个 Candidate，以及自己的冻结范围、证据、验证、审查和结果。任务可以顺序执行。

只接受公共 writer 返回的 `COMPLETE` 交接；其中准确的 Candidate 路径必须已经位于 `GENERATED` 下，并满足请求的契约。保留交接中契约要求的全部证据；契约中的就绪状态术语不能替代公共 writer 的结果。设置流程不提供下游操作权限：开始任何此类操作前，都应取得单独授权；如果操作改变了设置相关的目标状态，还应应用冻结目标的漂移规则。

用编写期间的新发现更新共同规划。注册前，将全部生成输出、保留的 Rules、相关 Skill 和全局 Rule 上下文放在一起，对照规划与已接受的契约审查。使用固定来源 writer 的职责分配标准，解决覆盖缺失、职责重叠和语义重复。各个任务的 `COMPLETE` 交接不能证明整组内容一致。

对于每项必要的生成内容修正，应以更新后的规划和重新冻结的单 Candidate 范围，发起一次独立、有效的公共 writer 调用。此前受影响的输出和之后的输出都要重新编写，每个发生变化的 Candidate 都应取得新的 `COMPLETE` 交接。重复整组检查，直到所有请求的输出及其当前交接均与已解决问题的规划一致。协调必须在注册前完成；不能绕过交接修改已接受的 Candidate，也不能借注册替换它。

若必要修正属于冻结生成请求之外的内容，包括保留的项目 Rule 或 SmartKit 全局 Rule，应停止并取消会话。沿公共 writer 的所有者依赖和用户协助路径，取得单独授权的规范所有者修正，然后从已接受的状态重新开始。保留固定来源和安装缓存；两者都不能充当替代修正目标。发现新的所有权关系，不会扩大本次会话或 writer 任务的冻结范围。

writer 返回 `NEEDS_INPUT` 或 `BLOCKED`，或者所需权限、依赖、访问条件或角色不可用时，停止生成。保留并报告准确的阻塞原因及证据，通过[会话协议](session-protocol.md#stop-and-recover)取消会话，仅在问题解决后启动新会话。不要注册部分工作。

## 注册完整交接

整组审查和全部修正完成后，使用各请求的 ID 以及其当前 `COMPLETE` 交接中的准确路径，为每个请求注册一次：

```text
python "<skill-root>/scripts/workflow.py" register --session "<SESSION>" --request-id "<ID>" --output "<PATH>"
```

交接包含配套文件时，重复使用 `--output`。路径可以是 `GENERATED` 下的绝对路径，也可以是 `.agents/` 下相对目标仓库的路径。该命令验证并记录一个请求的输出，不认证 writer 的语义交接。重复注册请求会被拒绝，且不会替换先前的注册。只有请求仍未注册且占用标记已经释放时，才可修正注册输入错误，并在同一会话重试。占用标记清理失败时，重试前应检查所报告的会话；目标发生漂移时，必须取消并重启。如果开始注册后才发现需要语义修正，应取消并重启，不能修改已注册输出。全部请求注册完成后，继续执行 `finish`。
