# 准备触发条件与固定 Skill 元数据

**发布版本：1.2.25。** 现有生成的环境准备 Skill、验证 Skill 和 Tools Rule 可能仅因任务位于 linked worktree，或缓存的准备证据失效，就要求执行准备。两个 Skill 也可能缺少蓝图现已固定的描述、界面字段和图标，或与这些内容不一致。

在完整 setup 期间，通过[生成内容编写](../generated-authoring.md)协调现有内容，使用完整的[环境准备](../../../../setup-assets/blueprints/skills/prepare-worktree-environment/SKILL.md)和[验证](../../../../setup-assets/blueprints/skills/change-set-verification/SKILL.md)蓝图目录，以及 [Tools 蓝图](../../../../setup-assets/blueprints/rules/tools.md)：

- 围绕三种准备触发条件，统一 `.agents/skills/prepare-worktree-environment/`、`.agents/skills/change-set-verification/` 和 `.agents/rules/tools.md`：新建 linked worktree 后首次使用、有证据表明当前任务所需的环境前提缺失或过时，或用户明确请求准备。前提已满足时，普通实现和检查使用现有环境。仅位于 linked worktree 或缓存记录失效，不足以触发准备；缓存是否有效，只决定在已有正当触发条件的调用中能否复用证据。
- 对两个 Skill，分别向公共 writer 提供对应蓝图的 `fixed-content.json` 和源文件。原样复制其 `description`，在 `agents/openai.yaml` 中采用声明的六个 `interface` 字段，并将声明的图标字节复制到 `assets/icon.svg`。保留独立元数据、项目专用行为和有效补充，将适用的项目细节留在正文或支持资源中。每份完整 writer 交接都应包含界面文件、图标和保留的支持文件。

通过 writer 执行当前蓝图对目标 Skill 的验收要求，包括准备脚本发生变化时的要求，以及仍然适用的证据复用要求。更新元数据本身不触发环境准备，也不授权其影响。同一组蓝图与 writer 仍可在 Setup 之外独立使用。

完成迁移要求三个工件相互一致、两个 Skill 的固定内容检查通过，并满足各自必需的验收要求。由成功的完整 `finish` 在配置收敛、CodeGraph 就绪且会话清理完成后记录 `setupVersion`；独立编写的结果不代表项目迁移完成。
