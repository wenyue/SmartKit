# 项目 Skill 依赖契约

**发布版本：1.2.29。** 早期 Setup 允许通过后续修正补全循环引用。从 SmartKit 蓝图编写的现有 Skill 也可能保留超出当前允许范围的依赖、对 SmartKit 私有资源的直接访问，或与特定调用方耦合的指令。需要按当前依赖契约评估这些产物；仍兼容的内容可以保持不变。

在完整 setup 期间，使用[生成内容编写](../generated-authoring.md)、其中经过确认的 SmartKit 提供方与目标所有者输入，以及[工件关系](../../../write-rules-and-skills/references/artifact-relationships.md)，评估现有蓝图生成的项目 Skill，以及会影响其行为的直接和间接关系：

- 按当前策略区分依赖、开头的职责边界和非操作性提及。在编写前调整职责分配以消除循环，并确定依赖先于使用方的生成顺序。即使已有排序靠后 Skill 的旧版本，也要遵循这一顺序。
- 将依赖限定在允许的内置普通 Skill 和项目提供的普通 Skill 范围内，通过受支持的 Skill 入口或公共接口取代对 SmartKit 私有资源的访问。保留必要行为和影响边界；对于不受支持的能力，或必须修改独立所有者内容的情况，应与其所有者解决，不能悄悄舍弃相应行为。
- 将特定调用方的假设改为由调用方通过输入提供。确保读者在需要作出决策前能获得必要指导，并按当前策略协调可用性和失败路径。保留项目特有行为、有效补充，以及不在此策略范围内的无关产物。

在已接受的编写范围内协调受影响的项目自有使用方和引用，按 setup 的所有权规则保留独立所有者的内容。在同一次完整 setup 中应用先前选中的迁移；本条目不替代其中任何一项。

完成条件包括一致且无环的依赖计划、项目 Skill 及其使用方符合受支持的依赖和资源接口，以及通过编写流程要求的检查与验收。由成功的完整 `finish` 在配置收敛、CodeGraph 就绪和会话清理完成后记录 `setupVersion`；单独修改 Skill 不代表完成此迁移。
