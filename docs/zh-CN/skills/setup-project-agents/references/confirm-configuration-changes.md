# 确认配置改动

维护契约要求用户决定采用来源还是目标内容、确认备份范围或接受保存计划时，按当前检查结果或计划提问。列出操作方向、将新增、替换或删除的路径和内容。涉及二进制文件时，也说明差异。用仓库、分支和项目条目标明选中的备份。提供简洁摘要，以及供审阅的实际改动。被检查的内容发生变化时，重新展示差异，并针对新版本取得选择。

## 选择同步方向

根据观察到的状态和操作选择问法。每个选项都适用于已审阅的整个范围。选择保留本地会跳过同步，保留当时的目标内容和仍存在的同步记录，依赖两侧一致的工作继续待处理。已单独接受的绑定或 Git 排除变更继续有效。保留选定的方向和准确的检查指纹，用于受保护的应用或采纳。

每次询问是否保存时，说明这次操作的实际影响。结果需要发布时，说明审阅过的改动会在验证后提交并推送。只保留本地结果时，说明改动会保存在本机的配置仓库 checkout 中，发布暂缓。

### 应用备份或保留本地

有差异的仅恢复操作，或完整 Setup 在收到 `source-updated` 后需要应用有差异的配置时，使用这个问法。启动同步对仅仓库更新的例外不适用于这些操作。

> 将 `<repository>`（分支 `<branch>`、条目 `<entry>`）的备份应用到 `<project>`，会有这些改动。
>
> <已审阅的逐路径改动>
>
> - **A. 保留本地文件。** 跳过备份应用。
> - **B. 应用备份。** 执行上面列出的改动。
>
> 回复 **A** 或 **B** 就可以。

### 保存本地改动或保留本地

完整 Setup 的项目协调操作返回 `needs-choice`，且已核实只有本地有改动时，使用这个问法。说明保存会影响哪些完整的来源文件。

> 自上次同步以来，只有本地配置发生了变化。
>
> <已审阅的逐路径改动>
>
> - **A. 保存本地改动。** <本次操作的保存结果>
> - **B. 暂时保留在这里。** 同步留待处理。
>
> 回复 **A** 或 **B** 就可以。

### 无法自动协调改动时选择同步方向

完整 Setup 的项目协调操作返回 `needs-choice`，且双方都有改动或方向未明时，使用这个问法。说明各方向的具体影响，包括来源或目标中的覆盖和移除。

> <发生了哪些改动，或为什么方向未明>
>
> <已审阅的各方向改动>
>
> - **A. 将本地配置保存到备份。** <本次操作的保存结果>
> - **B. 将备份应用到这个项目。** 在本地应用已审阅的改动。
> - **C. 暂时保留本地文件。** 跳过本次同步。
>
> 回复 **A** 、 **B** 或 **C** 就可以。

### 准备 OpenWiki 备份

`wiki prepare` 在备份有差异时返回 `needs-choice`。项目本身就是 Git 根目录时，对这份共用快照运行普通项目 `reconcile`，并使用上面对应的问法。用户选择保存，且双方都有改动或方向未明时，用已经审阅的文件和检查指纹执行受保护的 `adopt --accept-existing`。按计划保存时，使用已接受计划的指纹。保存后，记录源与目标一致，再重新执行 `wiki prepare`。

对于嵌套项目的 Wiki，用 `wiki prepare` 返回的确切 Git 根目录路径和 `source_updates_only` 证据，按应用或保留的问法处理。只有自上次同步以来来源未变，且针对嵌套范围的 `wiki save` 计划通过维护契约的检查时，才提供保存选项。无论哪种情形，用户接受应用备份后，都用准确的已审阅检查指纹执行 `wiki prepare --accept-existing`。用户选择保留本地时，将准备工作留待处理，并保留恢复证据。

## 备份范围

初次导入或扩大范围时，列出确切的文件和目录根，并按维护契约审查其中的完整内容。已有确认覆盖相同范围和内容时，直接沿用。

> 可以把这些路径纳入 `<project>` 的备份。文件会整份保存，列出的目录也会保存其中的全部内容。
>
> <建议纳入的路径和影响>
>
> 可以回复 **纳入这些路径** ，或告诉我需要调整哪些路径。

> 保存本地配置会使 `<repository>`（分支 `<branch>`、条目 `<entry>`）中的备份发生这些变化。
>
> <已审阅的逐路径来源改动>
>
> <本次操作的保存结果>
>
> 回复 **保存这些改动** 即可接受此计划，或回复 **保留本地** 暂缓保存。
