# 完整会话协议

完整设置前阅读本文。公开工作流从来源选择、注册直至一次终止性 `finish` 或 `cancel`，始终拥有同一个不可变私有会话。明确要求的本地同步使用独立命令，不进入此协议。

## 预检 <a id="preflight"></a>

解决影响随附默认值、项目自有输入或效果的重要选择。使用合格仓库证据，只询问真正未解决的选择。

`start` 检查项目自有 Matt 上下文。报告设置不完整时，结束本次调用，请用户在目标中调用 `setup-matt-pocock-skills`。该工作流完成后启动新的设置调用。Setup 既不创建也不拥有 Matt 上下文。

每种效果发生前，确定其权限：私有系统临时存储、一次对规范 SmartKit `master` 的只读获取、已配置外部 Skill 获取、生成编写和目标修改，是不同授权。已接受设置意图可能已经涵盖它们，不重复已解决的确认。生成编写的下游效果仍需自己的权限。在任何未授权效果之前停止。

获取仅联系已声明仓库，可以创建和移除私有临时检出。它们以非交互方式运行，不使用环境中的 Git 配置、凭证助手、代理、SSH 或 askpass 状态。这些授权不包含依赖安装、发布、Git 历史变更或无关目标写入。规范获取不可用时，`start` 可以使用已验证的已安装插件根，并报告 `source_commit: null`。已配置外部来源仍需其自身网络权限。

目标修改前，脚本验证外部来源声明、许可证、Skill 树、名称、目的地冲突和已记录标签稳定性。如果 `start` 拒绝输入或来源，在已接受权限内修正报告原因，并启动新调用。

## 启动一个冻结会话

使用公开入口：

```text
python "<skill-root>/scripts/workflow.py" start --target "<target-root>"
```

会话命令为 `start`、`register`、`finish` 和 `cancel`；通过每个命令的 `--help` 查看参数。`sync-project` 和 `sync-project-rules` 是独立本地操作。

非零结果时停止。将返回的 `session` 保留为 `SESSION`、`generated` 保留为 `GENERATED`，并保留 `request`、`source_root`、`source_commit` 和 `source_fingerprint`。请求冻结设置输入、外部快照、生成请求、来源证据及与设置相关的目标指纹。公开启动器拒绝没有请求当前全部目录蓝图的固定来源。编写前对照已接受意图确认完整请求。

规范来源由提交和指纹固定。已安装回退来源由根、为 null 的提交值和指纹标识。整个会话中保持该来源和请求不可变。

### 区分冻结设置证据和无关工作

目标指纹覆盖 Setup 消费的证据：项目设置配置、所有权及托管资产、生成目的地、项目 Rule 和 rule-led Skill 元数据、项目 Agent 源，以及触及的原生主机配置。Git 历史/index 状态、缓存、日志和其他项目自有工作在该边界外。

`start` 之后冻结的设置相关表面内发生任何变化，都会结束会话，即使另有编写授权允许该变化。取消并从已接受的结果目标重启。表面之外的变化不重启生成；将其作为无关状态保护。这使单独获授权效果不会被暗中吸收进旧设置请求。

仅保持返回的这个私有会话，直到其终止操作。若另一操作持有会话占用，保留会话并停止，不争用同一尝试。

## 结束一次

每个请求都有最终已注册输出后，调用：

```text
python "<skill-root>/scripts/workflow.py" finish --session "<SESSION>"
```

Finish 验证完整输出、冻结证据、所有权和计划，再在一个回滚边界内应用计划及干净后置条件。直至完成或失败处理结束，保持对每个计划目标路径的独占访问。文件系统检查无法防止不合作写入者在检查与修改之间的写入被覆盖。

成功需要退出 0，且 JSON 包含 `phase: finish` 和 `check: clean`，私有会话已随事务完成而移除。使用完整结果；仅目标收敛不能证明会话清理成功。

## 停止与恢复 <a id="stop-and-recover"></a>

`start` 后但尚未尝试任何 `finish` 时，若工作停止，执行取消：

```text
python "<skill-root>/scripts/workflow.py" cancel --session "<SESSION>"
```

Finish 前的未解决声明、所有权/摘要冲突或设置相关目标漂移，都要求取消，并在修正后启动新会话。取消失败是终止结果，原样报告。

固定来源的 finish 或事务失败后，保留原始错误。事务尝试恢复 finish 前的设置状态。保护条件检测到并发第三方改动时拒绝回滚修改；报告的回滚失败标明需人工检查的目标残留状态。恢复期间仍需独占访问，因为第三方写入者仍可能在回滚检查与修改之间介入。

随后 Finish 尝试清理私有会话。清理失败时，必须报告确切残留会话路径。这可能发生在目标收敛之后，也可能发生在失败事务之后；不能凭目标外观推断操作成功或回滚成功。

绝不复用、结束或取消这样的残留会话。将剩余占用或部分内容保留为失败证据，报告目标及确切会话路径。新会话之前，在适当恢复权限下解决原原因和任何已验证归工作流所有的残留。清理只限这些已验证残留。
