# 完整会话协议

完整 setup 从来源选择到登记拥有一个不可变的私有会话，并以一次终止操作 `finish` 或 `cancel` 结束。明确的本地同步不进入此协议。

## 预检 <a id="preflight"></a>

在依赖相关选择和权限的工作之前，解决重大项目输入选择和效果权限。已接受的 setup 意图可能已经授权这些效果；不重复确认已确定的权限。

私有系统临时存储、一次只读的权威 SmartKit `master` 获取、已配置外部 Skill 获取、CodeGraph 安装和目标本地运行时准备、生成内容编写以及目标变更，是各自独立的授权。单独执行 Setup 不授权提交、推送、发布、无关依赖安装或生成内容编写的下游效果。完整 setup 必须由用户明确调用；维护报告前置条件不等于调用它。开始这次单独调用的 setup 时，保留先前已接受的配置源改动及其证据。

`start` 要求项目自有的 Matt 上下文。若不完整，结束本次调用，要求用户在目标中调用 `setup-matt-pocock-skills`；完成后重新调用 setup。Setup 不创建也不拥有该上下文。

在 `start` 前，为已接受的目标和当前宿主运行 setup 拥有的 `setup-codegraph` 命令，准备 CodeGraph。其 `--approved` 标志记录既有的安装、索引和启动权限，不创造权限，也不要求再次同意。就绪要求已安装、有可用的目标索引且运行时实际响应。Hook 就绪检查只观察该状态；setup 负责安装、索引和服务启动。保留既有数据和独立所有者的宿主配置；过时或不完整的索引需要单独修复。使用此限定路径，不使用覆盖整个宿主的安装程序。准备失败时，完整 setup 仍未完成，即使留下了本地进展。

### 来源选择

区分下文选定的 SmartKit 实现来源和项目配置的编写来源。仓库模式下的配置遵循维护拥有的 [项目配置维护](../../maintain-project-config/references/maintenance.md) 契约，使用经过认证的 GitHub/Git 访问和持久工作副本。冻结前解决并应用已接受的输入改动。该工作副本可能保存唯一的未发布工作，绝不属于私有会话清理范围。

SmartKit 和外部 Skill 快照获取只联系已声明仓库，可以创建和移除私有临时检出。它们以非交互方式运行，不使用环境中的 Git 配置、凭据助手、代理、SSH 或 askpass 状态。权威来源获取不可用时，`start` 可以使用经过验证的已安装插件根目录，并报告空的 `source_commit`；外部来源仍有各自的网络前置条件。

选定来源要求公共启动器在准备或变更之前支持实时 CodeGraph 验证、私有会话清理和最终 `setupVersion` 提交。获取更新来源不会升级启动器。如果兼容性被拒绝，结束调用、更新已安装插件并重新开始。其他来源、schema 或外部输入拒绝也需要在已接受权限内修正，再重新调用。

## 启动一个冻结会话

```text
python "<skill-root>/scripts/workflow.py" start --target "<target-root>"
```

非零状态时停止。将 `session` 保留为 `SESSION`，将 `generated` 保留为 `GENERATED`，并保留返回的请求、`source_root`、`source_commit`、`source_fingerprint`、setup 版本和选定迁移。对照已接受意图确认完整蓝图请求；编写前从该来源读取选定指南。

权威来源由提交和指纹固定；已安装回退来源由根目录、空提交和指纹固定。保持来源和请求不可变。会话命令为 `writer-inputs`、`register`、`finish` 和 `cancel`；[生成编写](generated-authoring.md) 负责 writer 和登记顺序。按需查看各命令的 `--help`。`inspect`、`setup-codegraph` 和本地同步是独立操作。

### 区分冻结设置证据和无关工作

请求冻结 setup 输入、外部快照、生成请求和来源证据。在仓库模式下，冻结目标时一并保留选定配置源的身份和证据；来源发生并发变更时，必须取消并重新评估。其目标指纹覆盖实际使用的项目配置、所有权/受管工件、当前及已记录的生成 Skill 目录和目标位置、项目 Rule 和 rule-led Skill 元数据、项目 Agent 源、原生 Agent 成员及内容、项目 Codex 声明和目标内引用，以及涉及的原生配置。

Git 历史和暂存区状态、CodeGraph 索引和运行时状态、缓存、日志及未使用的项目工作仍在此边界之外。保留无关改动。`start` 后，冻结范围内的任何变化都会终止会话，即使另有授权：取消后从已接受输入重启。因此，运行时准备中涉及 setup 的变更必须先于 `start`。

保留返回的私有会话，直到执行终止操作。如果另一操作占用该会话，保留现场并停止，不争用同一次尝试。

## 结束一次

每个请求都有最终已登记输出后，确认 CodeGraph 就绪。若守护进程因空闲退出，在首次尝试 finish 前，为同一目标和宿主重新运行已授权的 `setup-codegraph`。仅运行时变化不使冻结失效；涉及 setup 的变化会使其失效。

```text
python "<skill-root>/scripts/workflow.py" finish --session "<SESSION>"
```

Finish 重新检查 CodeGraph，但不准备它，然后验证完整输出、冻结证据和所有权。在仓库模式下，先将已接受的生成项目源保存到选定条目，再进行常规目标应用。它在既有目标回滚边界内应用目标计划并检查收敛。来源持久化、目标应用和远端发布是独立结果；目标回滚不意味着已保存的源工作被丢弃。就绪检查失败会阻止应用和版本推进，同时仍按常规清理会话。

启动器移除私有会话后，以原子方式将来源发布版本记录为 `setupVersion`，保留其他配置值，并拒绝并发配置漂移。成功要求退出码 0、`phase: finish`、`check: clean`、`codegraph.ready: true`、报告的成功 setup 版本及已完成清理。仅配置收敛不足以证明成功。CodeGraph 准备发生在此事务之外，不会因后续 setup 失败而回滚。即使后续获准的来源推送失败，最终 `setupVersion` 仍记录本地完整 setup 成功。

应用和恢复期间，保持对计划目标路径的独占访问。保护检查无法阻止不配合的写入者在检查与变更之间修改路径。

## 停止与恢复 <a id="stop-and-recover"></a>

任何 finish 尝试之前，未解决声明、所有权/摘要冲突、漂移或生成受阻都要求取消：

```text
python "<skill-root>/scripts/workflow.py" cancel --session "<SESSION>"
```

启动新会话前，由对应所有者修正原因。取消失败即为终止性失败，原样报告。

固定来源的 finish 或事务失败后，保留主要错误和任何已保存的配置源改动。分别报告来源持久化与目标恢复。

目标应用失败时，保留主要错误。回滚尝试恢复到 finish 前的 setup 状态；检测到第三方变更时，保护措施拒绝覆盖它们进行回滚。报告回滚失败和残余目标状态，以便检查。

Finish 在失败后仍尝试清理会话。清理失败会报告确切残余会话；绝不能复用、finish 或 cancel 该会话。保留其占用和内容作为证据，在恢复权限内解决原因及任何经验证的工作流自有残留，再重新开始。清理仅限经验证的残留；目标看起来正常不能证明成功或回滚。

配置收敛后的清理失败会保留此前的 `setupVersion`。最终版本提交失败可能留下已更新配置和已移除会话，同时受保护事务保留或恢复之前的基线。报告失败及任何回滚失败，保留冲突的第三方变更，并使用新的完整会话。不能声称之前的配置事务已经回滚。
