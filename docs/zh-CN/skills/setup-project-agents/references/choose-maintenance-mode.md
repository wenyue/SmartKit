# 选择配置维护方式

检查报告 `selection_required` 且用户还没选定模式，或用户要求切换但未指定新模式时，才发出询问。一次给出三种方式。A 对应 `local`，B 对应 `local-only`，C 对应 `repository`。已有项目也可能缺少维护信息。用户要求切换时，说明切换对当前来源和目标的具体影响。若计划范围包含已跟踪路径，列出这些路径，并说明选择 B 或 C 后这些文件仍会被跟踪。

用户选 C 后，按 [选择配置仓库](choose-configuration-repository.md) 询问 Git 地址。仓库模式在本地成功后按确定范围提交并正常推送，用户要求只保留本地结果时除外。实际的发布与已跟踪文件按维护契约处理。

## 问法

> `<project>` 的配置想放在哪里？
>
> - **A. 随项目共享。** 配置留在当前项目，可以随业务仓库管理版本。
> - **B. 仅本机使用。** 配置留在当前项目，在本机将配置路径排除在业务 Git 之外。
> - **C. 独立的私有 GitHub 仓库。** 在该仓库维护备份，并在本机将配置路径排除在业务 Git 之外。初始化成功后，我会提交并推送约定范围内的备份，除非你要求只保留本地结果。
>
> 回复 **A** 、 **B** 或 **C** 就可以。
