# 补齐项目上下文

Setup 已确定维护来源并报告项目上下文缺失时，阅读此参考。从业务目标核实项目决策，在权威编写位置检查已有内容。两种本地模式都在项目内编写。仓库模式在选定的来源条目中编写，并通过维护流程应用已接受的改动。备份范围需要扩展时，按 [确认配置改动](confirm-configuration-changes.md) 处理。完整 Setup 要求插件随附 `triage` Skill。缺失时，报告插件分发不完整，依赖它的 Setup 工作继续待处理。

## 链接到现有项目文档

`docs/agents/issue-tracker.md`、`docs/agents/triage-labels.md` 和 `docs/agents/domain.md` 均已存在，且为常规文件、并非符号链接，内容也有效且一致时，使用这条路径。沿用项目根目录下已确定的 `CLAUDE.md` 或 `AGENTS.md` 入口。仅根据已有文件判断时，优先使用已有的 `CLAUDE.md`，其次是 `AGENTS.md`。两份都缺失时，使用用户或项目约定已为此用途确定的文件名。Rule 索引的目标配置无法决定这个文件名。如果入口尚未确定，或与所选维护模式冲突，在写入前询问这个决定。

入口和写入权限确定后，在该常规入口文件的第一个有效 `## Agent skills` 区块补齐链接，使它包含上述三个确切路径。入口文件须为常规文件，且不能是符号链接。保留现有的有效文本和其他区块。验证链接能解析到对应文档。在交接时报告实际入口及新增链接。仅在工作只涉及添加链接，且能保留自定义文本和项目约定时，使用这条路径。

> 找到了已有项目文档。要把它们的链接加到哪个入口文件？
>
> - **A. `AGENTS.md`。** <在当前项目中的影响>
> - **B. `CLAUDE.md`。** <在当前项目中的影响>
>
> 回复你想用的文件名就可以。

只有两个选项都可用，而且入口确实未确定时，才使用这个问法。遇到具体冲突时，说明实际路径、冲突情况和适用的处理办法。
