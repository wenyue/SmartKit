# 设置项目 Agent

根据可信 SmartKit 快照和仓库自己的 Agent 输入，协调一个仓库。

## 原则

- **一个仓库，一项事务。**探索完整的设置相关状态，将其冻结在一个私有会话中，然后完成该会话一次或取消它。
- **明确所有权。** SmartKit 拥有目录、渲染目标、主机适配器、所有权记录、验证和事务。仓库保留其本地 Rules、Skills、Agent 来源、配置、无关内容和秘密。
- **项目意图仍是权威。**只有获得已接受权限时，才更改项目所有的输入。渲染文件是这些输入的结果，绝不是新的事实来源。
- **效果各需授权。**网络访问、临时存储、生成内容编写和目标变更是不同效果。允许一种效果并不代表允许另一种。
- **证据会被冻结。**会话会绑定源、外部快照、生成请求，以及设置实际使用的目标状态。该表面发生漂移时必须新建会话。
- **完成必须收敛或恢复。**在一个回滚边界内应用完整计划，保留无关状态，并且只有后置条件干净时才宣告完成。

## 输入与所有权

随附目录始终启用 Codex、Cursor、Copilot 和 Qoder。它会安装声明的共享 Rules 和 Skills、Codex Plugin Agent 默认值，以及目录声明的所有项目蓝图。可选项目配置可以添加外部 Skills、项目 Agents 和 MCP 服务器。

若 `.agents/config.json` 存在，或已接受意图要求非默认输入，则使用[随附 schema](../../setup-assets/catalog/project-config.schema.json)，在 `start` 前协调或创建这个归项目所有的文件。没有此文件表示使用随附默认值。通过该 schema 确定外部 Skill 来源、项目 Agent 映射和 MCP 声明。

`.agents/rules/` 和 `.agents/skills/` 下的项目本地 Rules 与 Skills，包括蓝图生成的源文件及其支持文件，其内容归项目所有，可在会话之间编辑。设置会发现并保留额外的项目所有 Rules 与 Skills。项目 Agent 来源也仍归项目所有。目录声明的 Codex Plugin Agent 默认值只是回退项，不是项目 Agent 声明。原生 Cursor、Copilot 和 Qoder Plugin Agents，以及原生插件 Rules、Skills 和 MCP，均不属于本工作流。

对于每个生成的项目 Rule 或 Skill，SmartKit 会在 `.agents/smartkit.lock.json` 中记录合约指纹和包括支持文件在内的确切输出路径；它不持久化存储这些文件的内容摘要。合约未变且所有已记录输出都存在时，保留项目编辑，不重新生成。新增或变更合约，或任何已记录输出缺失时，都会选入生成请求。移除合约会删除其已记录输出；重命名目录中的合约目标会移除旧的已记录路径，并在当前目标位置生成。选入重新生成时，当前项目内容仍作为输入。

托管的渲染资产、共享资产和外部资产仍受摘要保护。冻结会话的目标漂移检查仍适用于下文所述的设置相关表面。

SmartKit 拥有 `.agents/smartkit.lock.json` 中记录的托管文件和结构化字段，以及经过认证、由标记包围且包含 `## Project rules` 的 `AGENTS.md` 单元。脚本在替换前强制执行接管、标记、所有权和摘要检查，并保留该单元之外的内容以及每个未声明文件、字段、目录和秘密值。

MCP 环境字段命名环境变量；URL、命令、参数和覆盖字面量仍属于项目输入。不要推断任意字符串是敏感信息。若合格的仓库证据识别出真实的敏感字面量，在渲染前停止，并要求项目所有者将其替换为受支持的间接引用。

MCP 就绪状态属于另一个每日自动项目检查。设置会验证、冻结并保留就绪声明，但不执行它们。该检查选择当前 Harness 和操作系统，在 `checks` 不存在时推断检查，遵守显式检查和 `checks: []`，并负责自己的发现。它不会安装任何内容，也不会启动服务器、联系端点或进行身份验证。因此，设置成功和 `check: clean` 证明的是配置收敛，而不是 MCP 已就绪。

## 预检

只解析会影响随附默认值、项目所有输入或获准效果的重要选择。优先使用合格的仓库证据，只询问真正尚未解决的选择。

`start` 会检查归项目所有的 Matt 上下文。若它报告设置不完整，结束本次调用并要求用户在目标中调用 `setup-matt-pocock-skills`；该工作流完成后再开始新的调用。设置既不创建也不拥有这些上下文。

在 `start` 前，取得已接受的项目意图，并分别取得以下权限：私有系统临时会话、对规范 SmartKit `master` 的一次只读 Git 获取，以及配置的外部 Skills 声明的每次获取。下游生成内容编写效果和 `finish` 应用的确切目标变更仍是独立授权；各自在操作开始前取得。

这些获取只能联系其声明的仓库，并可创建后再删除私有临时检出。它们以非交互方式运行，不使用环境中的 Git 配置、凭据辅助程序、代理、SSH 或 askpass 状态。它们均不授权依赖安装、发布、Git 历史变更或任何其他目标写入。遇到未授权效果时，在其发生前停止。若规范获取不可用，`start` 可以使用经过验证的已安装插件根目录，并报告 `source_commit: null`；配置的外部来源仍需各自的网络权限。

脚本会在目标变更前验证配置的外部来源、许可证、Skill 目录树、名称、目标冲突和已记录标签的稳定性。若 `start` 拒绝声明或来源，修正报告的原因后开始新的调用。

## 启动冻结会话

将当前已加载 Skill 的目录标识为 `<skill-root>`，目标仓库根目录标识为 `<target-root>`。通过公共入口 `scripts/workflow.py` 启动一个私有会话：

```text
python "<skill-root>/scripts/workflow.py" start --target "<target-root>"
```

`workflow.py` 是 `start`、`register`、`finish` 和 `cancel` 的公共入口。

遇到非零结果时停止。将 `session` 记录为 `SESSION`，将 `generated` 记录为 `GENERATED`，并记录返回的 `request`、`source_root`、`source_commit` 和 `source_fingerprint`。请求会冻结设置输入、外部快照、生成请求，以及源和设置相关目标指纹。目标指纹只覆盖设置使用的证据：项目设置配置、所有权与托管资产、生成目标、项目 Rule 元数据、项目 Agent 来源，以及涉及的原生主机配置。Git 历史和索引状态、缓存、日志及其他项目所有工作均不在其中。
编写前确认它符合已接受意图。规范运行固定到其提交和指纹；已安装回退由其根目录、空提交和指纹标识。

在一次 `finish` 或 `cancel` 前，只保留这一个私有会话。将请求和来源视为不可变。若另一项操作持有会话声明，保留会话并停止。`start` 后，冻结的设置相关表面发生任何目标变更——包括经过独立授权、在该表面产生的编写效果——都会终止此会话：取消它，并从变更后的已接受目标状态重新开始。该表面之外的变更不会重启生成；将其作为无关状态保留。这样，编写效果仍受自己的授权约束，而不会被悄然纳入设置。

## 完成生成请求

没有生成请求时，直接执行 `finish`。否则，应先完成以下工作流，再登记任何请求。

### 规划最终集合

从 `source_root` 解析每个请求对应的不可变 Setup Authoring Contract。加载 `source_root/skills/write-rules-and-skills/SKILL.md` 中的公共编写器，包括其同源 references 和 `writing-for-agents` 依赖。环境中或目标检出内的编写器不是本会话的权威。在开始编写任何 Rule 前，应用该编写器的**分配职责**标准，形成一份共同规划。

规划最终形成的整个项目 Rule 集合，包括生成请求之外需要保留的 Rule。根据冻结的请求、目录、合约和完整的当前项目输入确定集合成员，不预设固定数量。为每个 Rule 明确职责、主要内容、与相邻所有者的边界，以及必要的引用。如果 Skill 的职责会影响这项分配，也将其纳入考虑。提供适用且无条件加载的项目 Rule 和 SmartKit 全局 Rule，以及在受支持使用场景中可能共同加载的条件 Rule 的证据。通过受支持的发现与加载途径建立这些上下文，不能仅依据当前会话中可见的指令。

规划记录归属和加载证据，以及尚未解决的所有者依赖。Setup 负责这份批次规划和会话协调；公共编写器负责每个 Rule 或 Skill 的职责分配与单一定义判断。目录、schema、合约和脚本继续各自负责其事实与边界。规划不能新增生成请求、覆盖合约或授予修改另一个所有者的权限。

### 登记前完成编写与协调

在目标仓库上下文中，为每个请求调用固定来源的公共编写器，将对应的 Setup Authoring Contract 作为已接受任务或规格输入，并将 `GENERATED` 作为请求根目录。向每项任务提供共同规划、归属和加载证据、所有者依赖状态，以及完整的当前项目内容，Skill 任务也不例外。每次调用只负责一个 Candidate，并拥有自身的冻结范围、证据、验证、审查和结果。任务可以依次执行。

只接纳公共编写器返回的 `COMPLETE` 交接，且交接中的确切 Candidate 路径必须已位于 `GENERATED` 下并满足请求合约。保留交接中合约要求的所有证据；合约使用的就绪术语不能替代公共编写器的结果。Setup 不提供下游效果的授权：每项此类效果发生前都必须取得独立授权；如果它改变设置相关目标状态，则应用冻结目标的漂移规则。

根据编写中的新发现更新共同规划。登记前，将全部生成输出与保留的 Rule、相关 Skill 和全局 Rule 上下文一起，对照规划及已接受合约进行审查。使用固定来源编写器的职责分配标准，解决覆盖遗漏、职责重叠和语义重复。单个 `COMPLETE` 交接不能证明整组内容连贯。

每项必要的生成内容修正，都应通过一次独立、有效的公共编写器调用完成，并传入更新后的规划及重新冻结的单个 Candidate 范围。受影响的早期输出和后续输出都要重新编写，每个变更后的 Candidate 都应取得新的 `COMPLETE` 交接。重复整组检查，直到所有请求输出及其当前交接都与已解决依赖的规划一致。这项协调必须在登记前完成；不得绕过交接编辑已接纳的 Candidate，也不得通过登记来替换它。

如果所需修正归属冻结生成请求之外的所有者，包括保留的项目 Rule 或 SmartKit 全局 Rule，则停止并取消会话。按照公共编写器的所有者依赖和用户协助路径，在独立授权下完成规范所有者的修正，再从已接受的状态重新开始。保留固定来源和安装缓存；二者都不能充当替代修正目标。发现新的归属不会扩大本会话或编写任务的冻结范围。

编写器返回 `NEEDS_INPUT` 或 `BLOCKED`，或者必需的权威、依赖、访问条件或角色不可用时，都应停止生成。保留并报告确切阻塞项及其证据，通过**停止与恢复**流程取消会话，问题解决后才能启动新会话。不得登记局部完成的工作。

### 登记完整交接

整组审查和所有修正完成后，使用每个请求的 ID 及其当前 `COMPLETE` 交接中的确切路径，将每个请求登记一次：

```text
python "<skill-root>/scripts/workflow.py" register --session "<SESSION>" --request-id "<ID>" --output "<PATH>"
```

对交接中的支持文件重复使用 `--output`。路径可以是 `GENERATED` 下的绝对路径，也可以是 `.agents/` 下的目标相对路径。该命令验证并记录一个请求的输出，不认证编写器交接的语义。重复登记请求会被拒绝，先前的登记不会被替换。修正登记输入错误后，只有该请求仍未登记且其声明已释放时，才可在同一会话中重试。若声明清理失败，重试前必须检查报告的会话；目标漂移则要求取消并重新开始。如果登记开始后才发现需要语义修正，应取消并重新开始，不得修改已登记的输出。所有请求登记完成后，继续执行 `finish`。

## 完成一次

恰好运行一次 `finish`：

```text
python "<skill-root>/scripts/workflow.py" finish --session "<SESSION>"
```

Finish 会验证完整输出、冻结证据、所有权和计划，然后在一个回滚边界内应用计划及其干净后置条件。从开始到完成或失败处理结束，给予它对每个计划目标路径的独占访问：文件系统检查无法防止不协作的写入者在检查与变更之间的写入被覆盖。成功要求零退出，并返回包含 `phase: finish` 和 `check: clean` 的 JSON；只有此时，会话才会作为已完成事务被移除。

## 停止与恢复

若工作必须在 `start` 后、任何 `finish` 尝试前停止，取消该会话：

```text
python "<skill-root>/scripts/workflow.py" cancel --session "<SESSION>"
```

完成前，未解决的声明、所有权或摘要冲突，或设置相关目标漂移，都要求取消会话，并在修正后新建会话。取消失败是终止结果，应原样报告。

固定来源的 finish 或事务失败后，保留其确切错误。事务会尝试还原完成前的设置状态；若检查发现并发第三方变更，则拒绝执行回滚变更。报告的回滚失败会指出残留目标状态，供人工检查。同一文件系统限制也适用于回滚检查与其变更之间，因此在失败处理期间保持独占访问。随后，Finish 会尝试删除私有会话；若清理失败，必须报告确切会话路径。

清理失败可能发生在目标已达到干净预期状态之后，也可能发生在事务失败后，因此不能推断零退出成功或已经回滚。绝不复用、完成或取消该残留会话。将任何剩余声明或部分会话内容视为失败证据。检查报告的目标和会话，只移除经过验证的工作流所有残留；存在原始原因时先解决它；若仍需设置，再启动新会话。

## 交接

报告来源模式、来源根目录、来源指纹，以及存在时的提交；启用的主机；变更路径；所有权结果中的外部 Skill 来源和提交；保留的项目所有路径；适用时的回滚或残留状态证据；以及干净检查状态。要求维护者审查并提交项目快照。本 Skill 不授予提交、推送、发布、依赖安装、目标外安装或发行权限。
