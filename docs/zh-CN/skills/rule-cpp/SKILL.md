# C++ 指南

## 明确接口与所有权

限制公共接口的范围，并保留既有的 ABI、FFI 和平台边界。行为应留在所属位置；只有相关输入形成稳定概念时，才引入选项类型。

优先使用 RAII 和值语义。当指针拥有其资源时，优先使用智能指针，而不是拥有资源的裸指针。

## 通过边界契约表达失败

将预期失败纳入返回契约。仅对所在边界视为异常的失败使用异常机制。

## 明确共享状态与原生回调的责任

通过一个明确的所有者，使用足以满足需要的最小同步原语协调共享可变状态。跨越原生回调时，仍须满足清理、取消和线程亲和性要求。

## 遵循项目工具并验证边界

由仓库的格式化器、编译器和静态分析配置负责机械风格与命名。

对原生所有权、失败处理或 ABI 行为可能退化的行为边界进行测试。
