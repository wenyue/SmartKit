# 编写决策

本记录保留后来的编写者可能撤销、且撤销会带来实际代价的有意取舍。它不属于正常执行流程，也不是隐藏的要求来源。指导、元数据、可执行接口及其他现行行为，仍由各自的现行所有者负责。

## 保持以角色为中心的架构

保留 Controller、一位常驻 Author、一份公共 Reviewer 契约及相互独立的 Quality、Change 和 Correctness 视角，以及由 Correctness 委派的 Runner。角色参考文件保持分开，因为每个身份需要不同的问题、证据和权限；合并它们会重新造成 [ADR 0012](../../../../docs/adr/0012-organize-authoring-around-roles.md) 所取代的那种上下文与职责相互纠缠的局面。相似的主题可以从不同的专业视角出现，但重复同一条现行规则并非有意为之。

## 让重新设计成为显式判断

要求 Quality 每轮都用反问检验设计，并说明是否需要重新设计。评估表明，隐含的“可以重新考虑设计”很容易被忽略；而强制对话或删减配额会增加负担，却不能改善判断。这些问题用来集中注意力，不授予更大的编辑权限。[ADR 0021](../../../../docs/adr/0021-make-skill-redesign-an-explicit-review-decision.md) 记录了更完整的决定。

## 分层 Skill 依赖，但保留边界重定向

让 Skill 依赖单向流动，从需要另一个 Skill 的一方指向它所需的 Skill，且不形成环；向其他任何 Skill（包括依赖引用方的 Skill）路由工作，只能通过非执行性的边界重定向。严格禁止平级引用会去掉这类重定向，而正是它们让被误选的 Skill 能指明正确的负责方，而不是毫无指引地停下或越界做该负责方的工作。反过来，不受限制的平级调用会让 Skill 耦合到彼此的内容并形成环。方向取决于每处引用实际做什么，因此审查者可以直接从产物判断，无需分层登记表。不建立关系的提及，例如许可证署名、自包含教学示例或正在编写的 Skill，不在这项政策范围内；禁止一切提及会去掉必需的署名，也无法指名正在处理的 Skill。

## 将已提供的 Skill 依赖视为可用

对工具、服务、凭据和其他环境能力，要求说明不可用或失败时的结果；但对 Rule 或 Skill 依赖其受支持环境已配置为提供的 Skill，则不作此要求。在 SmartKit 中，SmartKit Skill 随每个 SmartKit Rule 和 Skill 一起交付；项目的 Rule 和 Skill 可以依赖 SmartKit Skill，因为项目以 SmartKit 为前提；项目自身的 Skill 随其自身的 Rule 和 Skill 一起交付；缺少某个 Skill（包括其他插件的 Skill）属于环境配置问题。针对这些 Skill 的不存在分支在受支持环境中永远不会执行，而单独的失败要求与 Correctness 仍会走查的常规结果处理重复。把豁免限定在已提供的 Skill：受支持目标可能提供也可能不提供的 Skill，例如目标项目为某个 SmartKit Skill 编写以供使用的 Skill，需要存在和不存在两种情况的结果。针对这类 Skill 的具体 SmartKit 规则属于本仓库的项目本地 `write-shared-rules-and-skills` Skill，而不属于这个公开 Skill，因为公开 Skill 不得依赖项目 Skill。

## 保持编写记录精简

只有当某个有意的取舍很可能被后来的编写者撤销、且误撤代价高昂时，才在 `AUTHORING.md` 中为它建立条目。条目只写决定及其理由；只有值得记住时才保留备选方案或后果。这样既能避免记录沦为例行历史或第二份契约，又能保留必要背景，防止代价高昂的错误“修正”。

## 区分精确协议与设计判断

范围、版本身份、审查放行和运行时清理需要精确边界，因为其他角色依赖这些结果。写作决定则需要优先事项、证据和重要例外。在入口和角色指导中明确保留这一区别：把设计建议变成强制模板或数值限制，会缩窄可接受方案；把协议边界当作风格建议，则会破坏协同审查。同样因为这一差异，文档检查器与语义 Reviewer 保持互补。

## 将固定内容视为输入约束

精确字符串字段和精确文件都是由 Controller 接受的可选通用约束。蓝图和 setup 是调用方，而非特殊编写模式，因此同一来源可以独立使用，无关元数据仍可编辑。复用证据快照保存已接受来源和声明：若与实时来源或 Author 重新抄写的预期值比较，漂移就可能重新定义成功。字段读取器遇到超出支持范围的语法时报告结果不完整，而不近似解释 YAML 值；语义验收仍由 Reviewer 负责。
