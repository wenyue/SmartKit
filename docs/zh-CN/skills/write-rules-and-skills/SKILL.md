# 编写 Rule 和 Skill

根据已经确认的意图和验证过的证据，编写最小而完整的 Rule 或 Skill。使用 `writing-for-agents`
处理信息层级、Markdown 结构和 Skill 机制。这个混合型技能负责普通候选项的编写及通用资格门控；
更具体的调用方可以补充范围证明，但不能降低这些门控的要求。

当前智能体是控制器，不充当语义作者或审查者。它可以查找已授权的项目事实、选择证据、启动新的
智能体、原样应用返回内容并运行确定性检查。承担语义工作的角色只能接收明确提供的上下文包。

## 建立义务和归属

编写前，先明确：

- 请求结果、保留语义、已接受变更、非目标和安全边界；
- 工件当前及请求的归属、允许写入的位置，以及受影响的加载、资源、发现、生成和分发表面；
- 适用的 Rule、当前行为、验证接缝，以及可能改变政策、作业、操作、目标或退出方式的环境事实。

每项可以独立变化的义务都要在上下文中的语义台账里占一行，记录其证据、请求或当前归属，以及
`preserve`、`change`、`add`、`move` 或 `retire` 处置。不要把台账、编写模型、来源和审查
证据写入运行时工件。

完整阅读并应用 [`references/owner-gate.md`](references/owner-gate.md)。如果用户明确要求只读的
归属审查，返回判定后停止。其它情况只有在每个候选项都有证据支持的 Rule 或 Skill 归属时才能继续。

## 路由并达到就绪

每个候选项都是直接使用的直接使用型工件。完整阅读
[`references/ordinary-artifact.md`](references/ordinary-artifact.md)，然后只读取一份语义引用：

| 候选项 | 语义引用 |
| --- | --- |
| Rule | [`references/rule-semantics.md`](references/rule-semantics.md) |
| Skill | [`references/skill-semantics.md`](references/skill-semantics.md) |

当归属判定关口返回 `split` 时，创建用户所选、分别归属的 Rule 和 Skill 候选项。只有在现有
证据仍允许实质不同的行为、归属、写入、权限、副作用或退出时才提问；否则记录唯一受支持的事实并继续。

完整阅读 [`references/soft-isolation.md`](references/soft-isolation.md)。顶层控制器必须先取得一次
软隔离探针 `PASS`，才能启动行为对照、作者、精简者、审查者或验收执行者。更具体的调用方
只能复用同一次顶层运行、通过同一种新智能体启动机制得到的 `PASS`。探针失败后必须停止。

执行直接使用型工件引用所要求的行为对照。只有所有选定引用都能在没有实质未知项的情况下应用，才算
准备就绪。

## 编写一个候选修订版

为 Rule 建立临时规则框架，或为 Skill 建立已经选定且有证据支持的技能设计形态。把每项义务投影到
最窄且可靠的运行时归属和加载层级。让环境归属的事实可发现，只在触发条件出现时披露条件材料，并且仅对
重复、脆弱的确定性机制使用脚本。现有工件是遗漏证据，不是新大纲。

启动一个无工具的软隔离智能体作为作者，并向它提供一个上下文包，其中包含已经确认的结果、语义
台账、选定框架、已有的完整当前候选项及其资源、允许使用的证据、适用的编写指导和完整的规范目标
映射。编写项目相关内容时，要明确附上所有必需的项目事实或 Rule 正文。作者返回
`CONTEXT_REQUIRED`，或者返回每个变更目标的完整替换内容；它不编辑文件。

收到 `CONTEXT_REQUIRED` 时，可以停止，也可以重新构建完整的上下文包并启动新的作者。否则，
把返回内容原样写入已授权的规范路径，并在继续前验证结果。控制器不能在写入时自行修改语义。

候选修订版是完成写入并验证后的完整当前内容。阅读时不依赖上一版本或 diff。只有另一个智能体无需
自行补造条件、事实、操作、归属或退出方式就能使用它，流程才能继续。

分别判断每个阻塞问题：

- `uniquely-forced`：当前证据确定唯一的范围内修正，无需新政策、权限、行为、范围或副作用；
- `decision-required`：证据仍允许实质不同的受支持结果，或者修正需要新意图、证据、权限、范围或
  外部操作。指出确切的未决选择、其决策归属，以及每种结果的证据。

## 精简、验证、审查和验收

1. 完整阅读 [`references/pruning-agent.md`](references/pruning-agent.md)。把候选项交给一个未参与
   编写、无工具的软隔离智能体负责精简。修正精简问题时始终使用同一个智能体；之后不能再由它负责
   审查或验收。
2. 对每个变更归属和受影响表面运行调用方环境要求的机器检查。机器检查证明结构和执行，而不是自然语言
   含义。如果必需检查以非零退出，停止并报告确切命令、最终退出、相关输出、未运行门控和未验证表面。
3. 冻结所有写入。完整阅读 [`references/semantic-review.md`](references/semantic-review.md) 和
   [`references/acceptance-runner.md`](references/acceptance-runner.md)。把完整且范围明确的证据交给
   一位新的、无工具的独立审查者。它必须先返回语义审查 `PASS` 或 `FAIL`，之后才能开始验收。
4. 每个选定案例都使用新的验收执行者。由审查者判断其可观察结果，并另行返回验收 `PASS` 或
   `FAIL`。

无法启动所需的新智能体时停止。启用工具的验收案例属于例外，运行前必须满足验收执行者引用中的
对应探针和上下文包规则。

## 修正直到稳定

遇到有效的 `decision-required` 问题时停止。当所有问题都是 `uniquely-forced` 时，把它们一次性交给
作者。作者返回完整修订内容，控制器原样应用并验证。这次写入会产生新的候选修订版，此前依赖旧内容
的机器检查、审查和验收结果全部失效。按原顺序重新执行门控：精简仍使用同一智能体，审查使用新的
审查者，每个受影响案例使用新的执行者。

同一问题在修正后原样出现，或修正不会改变候选项时，因无进展而停止。只有同一个候选修订版同时
通过精简、机器验证、语义审查和验收，流程才算成功。

报告工件类型、归属、保留及确认的改动、受影响表面、与基线的大小比较、实际命令和退出状态、探针与
各门控的判定、修正情况，以及仍未解决或未测试的表面。上下文包、台账、探针结果和审查证据只保留
在智能体上下文中，不创建工作流报告或临时编写目录。共享可移植性声明、项目设置编写契约的编写、
发布、安装、提交、推送和其它外部操作都交给各自的归属方。
