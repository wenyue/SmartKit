# 验收执行者

此引用规定直接使用型工件验收时通用的隔离和执行协议。父 Skill 负责何时开始验收，以及谁可以担任
验收执行者；所选生命周期和语义类型引用负责代表性案例和特定范围的通过条件。

## 提供一个上下文包

向执行者提供运行时实际可见的冻结候选项、一个触发任务或政策应用、一个选定案例的输入，以及完整的
必要上下文。上下文包中不能包含预期结果、语义台账、diff、作者推理、问题、审查者指令或先前案例
的输出。

每个案例都使用新的软隔离智能体作为执行者，并从声明的冻结输入开始。一个案例的结果不能成为另一
个案例的输入。如果准备阶段要求行为对照，必须等对照和匹配的候选项运行都结束后再比较原始结果；
任何一方都不能看到另一方的结果。

## 应用工件

默认使用无工具执行者。如果 Rule 或写作/判断类 Skill 的可观察结果就是返回的响应，那么在响应中实际
应用它已经构成真实验收；再把同样内容写进文件不会增加证据。

只有候选项的可观察契约必须产生真实效果时，才提供工具。先通过 `soft-isolation.md` 中对应的工具政策
探针，再在上下文包中列出允许使用的每个工具、输入、路径和效果。一次性文件系统状态由候选项自有
的测试或 fixture 提供；编写工作流不创建通用验收工作区。

如果存在真实的公共作业入口或政策应用接缝，就使用它。确定性资源通过其公共入口运行。环境无法执行
但有依据支持的部分应报告为“未测试”；受控演练可以解释该表面，但不能代替必要的真实效果，也不能
证明机器检查通过。

每个案例只运行一次。不确定或不稳定的案例最多再由新的软隔离智能体重复一次；两次结果不一致就
判定失败。把可观察结果及已测试/未测试表面返回给审查者，但不能对照未披露的预期结果自行下结论。
不要持久化执行者输出或案例报告。
