# 普通工件

Ordinary Artifact 是直接作为政策或触发作业使用的 Rule 或 Skill。此引用负责其生命周期分类、运行时
边界和代表性应用。

## 遵守所提供的归属边界

| 调用方范围 | 契约 |
| --- | --- |
| Project-local | 根据显式提供的仓库事实编写项目行为，并将其放在最窄的项目归属中。 |
| Shared | 只保留显式提供的共享依赖和可移植性证据所支持的行为。 |

只有项目私有共享工作流可以声明 Shared。删除项目细节或单独调用公共工作流，不能提供源上下文或
可移植性证明。

## 证明行为塑造需求

当提议指令只用于改变 Agent 默认行为，且没有已观察失败证明该需求时，在编写前运行一次 Soft-isolated
Behavior Control。重写时使用先前接受的工件，新建时不提供候选项，并给 fresh Agent 与候选项
Acceptance 计划相同的任务。把其原始返回结果保留在控制器上下文中供审查。

不要为政策权限、项目事实、引用材料或已经观察到的失败运行 control。如果 control 已经产生所需行为，
则省略无操作指令，除非独立的已接受证据要求显式政策。

## 编写运行时工件

- 陈述最终政策或作业，而不是编写历史、语义台账、审查过程或资格证据。
- 把项目事实保留在 Project-local 工件中。在 Shared 工件中，只命名稳定协议，并告诉 Agent 如何发现
  本地事实，或者在发现无法解决时停止。
- 每项要求只保留在一个归属中。遵循更具体的 Rule 和受支持的本地覆盖，不要将其复制到更宽泛的正文。
- 只包含 schema 要求或能改变行为且不能从可靠加载归属推导出的指令。

## 验收代表性使用

选择的 `rule-semantics.md` 或 `skill-semantics.md` 提供类型特定 case。应用父 Skill 选择的通用
Acceptance Runner 协议。

- 对于 Project-local 工件，显式提供仓库声明、归属边界、真实入口或执行点和相关本地 case。
- 对于 Shared 工件，使用其归属工作流提供的 case、依赖和可移植性证据。

只有当工件在其声明范围中保持一个含义、为每个选定 case 产生一个受支持结果，且不需要发明项目事实、
操作或退出时，Acceptance 才通过。
