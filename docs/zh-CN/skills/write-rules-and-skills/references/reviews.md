# Quality 与 Correctness Review

在 Design 期间加载两份合同。冻结每个完整全新 cohort、职责分配和分批调度，之后才可启动角色
或改变 Candidate。阶段入口在`P`内激活已冻结身份；它不增加调度事实。

每个 Reviewer 在其单元的修正循环中保持身份，并接收同一份完整 Candidate Version 与已授权
证据。任何 Reviewer 都不会收到 Author 推理、预期修复、diff 或其他 Reviewer 的工作。
Reviewer 先私下判断，随后仅通过通用直接修正生命周期，与常驻 Author 讨论自己负责的 finding。
Author 与 Reviewer 独立评估主张和理由，直到形成双边不动点。服从、投票、Controller 解释或
其他 Reviewer 都不能决定结果。

## Quality

Quality 是第一个证明阶段。冻结一个四人 cohort。向每个成员提供完整 Candidate 资源树、加载
与分发路径、已接受要求、保留义务、所选模型和写作指引。

为下列每项职责绑定一个 Reviewer 作为主要 Owner。每项职责至少绑定一个次要 Reviewer，其余
成员作为支持者。每个 Reviewer 仍覆盖全部四项职责：

- **主要：**使用多个高风险反例主动证伪所分配职责。
- **次要：**检查所有相关出现位置，并在存在时给出反例或实质更好的方案。
- **支持：**扫描完整表面，并在证据需要时深入检查。

### 制品架构与信息流

主要：掩盖关系、拆散一个关注点、耦合无关关注点、迫使来回查找、膨胀上下文或使变更脆弱的
边界与顺序。

次要：入口充分性、在触发条件旁披露、路由发现、单一来源归属，以及加载或分发路径。支持：
掩盖阶段、分支或同级关系的 Markdown。

### 语言、组合与清晰度

主要：句子与段落构造，以及依赖暗示、Author 上下文或环境词汇表才能成立的含义。

次要：术语、触发条件、前置条件、例外、限定词，以及要求、权限、禁止和建议的力度。支持：
可避免的间接表达或纠结文字。

### Agent 理解与可用性

主要：全新、有能力的 Agent 必须自行猜测的目标、Owner、边界、顺序和结果关系；缺失判别信息；
以及需要无依据推断的路由。

次要：不清晰的输入、权威、工具、可观察动作或证据，导致完成、恢复、受阻、失败与停止混淆。
支持：远离其所管辖行为的高风险约束。

### 经济性与可维护性

主要：消耗大量注意力却不改变行为、证据、权威、边界或出口的文本；可避免的语义开销；以及
脆弱的同步编辑。

次要：重复含义、不受支持的约束，以及陈旧缓存事实或依赖。支持：具有具体收益的更小合并。

Quality 只产生`critical`或`material`finding。每个 finding 都要证明当前存在且有支持的成本，
并说明改进机制、有界方向、受影响 scope 和保留约束。偏好、对称性、命名品味、文件长度、
修复规模和数字缩减都不能证明存在缺陷。

只有当前 Candidate Version 上不再有 critical 或 material 主张，且路由给该 Reviewer 的每条
note 均已解决，Quality Reviewer 才通过。后续阶段的 note 不阻塞 Quality。只有四名成员对同一
版本分别独立通过，Quality 才通过。后续变更使已关闭阶段失效时，应绑定全新的完整四人 cohort。

## Correctness

Correctness 仅在 Machine `PASS`或有效`NOT_REQUIRED`后开始。冻结一个两人 cohort，并为每个
Reviewer 绑定一个 scope。向两者提供已接受的人类决策上下文、保留义务、管辖证据、所选模型和
当前阶段证据。每个 Reviewer 独立检查所有相关表面，执行受支持场景，并尝试证伪 Candidate。

### Spec Fidelity and Semantic Integrity

寻找一个不可容忍且有支持的用例，其中 Candidate：

- 遗漏、替换、弱化或违反已接受的要求、义务、变更、非目标、含义、保护、行为或结果；
- 增加不受支持的行为、义务、依赖、权限或解释；
- 把含义、责任、权限或能力移出已有证据支持的 Owner、适用性、依赖闭包或代表性上下文；或
- 让相同条件要求实质不兼容的行为。

### Critical Behavioral Integrity

寻找一个不可容忍且有支持的用例，其中：

- 必需关键路径上的触发条件、依赖、权限、动作、验证、恢复或停止失效；
- Agent 可以擅自取得权威、绕过决策 Owner、超过已接受影响或违反安全；
- 成功、受阻、失败、恢复或终止状态缺少关键出口或证据；或
- 同时出现的条件发生冲突、逃避优先级，或允许工作未完成时宣告完成。

Correctness 只产生`critical`finding。每个 finding 都应提供一个不可容忍场景、已接受证据、
具体反例、实质影响、修复机制与有界方向、受影响 scope 和保留约束。修复规模不决定影响，
所有替换文本均由 Author 负责。

非阻塞改进可以成为不含语义的 Scope Transfer Note，并路由到 Quality，而不改变原阶段裁决。
只有当前 Candidate Version 上不再有阻塞主张，各 Correctness Reviewer 才通过。只有两者对同一
版本分别独立通过，Correctness 才通过。后续变更使已关闭阶段失效时，应绑定全新的完整两人
cohort。
