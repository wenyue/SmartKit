# 共同判断依据

制品指一个 Rule 或 Skill；Candidate 指当前正在编写和审查的制品及其范围内的配套资源。Controller、Author 和 Quality 在各自职责内，将这些判断应用于两种制品类型，分别用于对齐与分配、编写和质量审查。行动和结论的权限仍由各自的角色合同规定。

## 实际生效的含义

具有权威性的已接受要求确立制品的预期含义；现有 Candidate 文本是回归证据。制品的治理指令表达最终要求，并保留其含义、范围、条件、例外和非目标。只有中间推理或未选的编写方案对读者理解或执行已接受的要求有实质帮助时，才将其提炼为有用的理由、边界或例外予以保留。对话历史仍是编写和审查的证据；出现在证据中，本身并不构成将其纳入制品的理由。这一要求适用于制品自身的指令，也包括要求产出方案比较内容的指令。

应用 `writing-for-agents` 的正向目标指导：默认正向说明目标。只有正向措辞无法可靠避免实质性混淆、错误适用或安全风险时，才将负向边界保留为必要的硬性护栏，并同时说明所需的正向行为。正向表述足以传达预期范围和行为时，用这种方式保留已接受的约束和非目标。

## 职责与加载 <a id="responsibility-and-loading"></a>

Rule 负责在触发的工作中持续生效、且边界清晰的政策领域；Skill 负责有明确结果和边界的触发式任务，以及该任务所需的约束。根据含义和范围，将共享的持续性政策分配给最合适的现有 Rule，必要时完善该 Rule。无条件加载可以作为可用性的证据，但不能成为将项目或 Skill 专属义务提升为全局政策的理由。如果某项事实已由代码、配置、schema 或其他现有所有者负责，则相应变更归该所有者负责。

每条政策在相关 Rule 和 Skill 中只保留一个完整定义。Rule 可以引用其他 Rule 和 Skill；Skill 可以引用其他 Skill，但不得直接引用 Rule。在这些引用边界内，使用指向所有者的简短引用，以及作出任务决策所需的本地背景，将政策定义保留在其所有者处。

评估合适的现有所有者时，检查相关 Rule 和 Skill、适用且无条件加载的项目 Rule 和 SmartKit 全局 Rule，以及在受支持的使用场景中可能共同加载的条件 Rule。通过环境支持的发现与加载途径，确认它们的含义、范围、触发条件和规范源。仅凭当前编写会话，无法确认未来使用者能否获得它们。

比较含义，包括条件、例外和配置，而不是匹配措辞。Skill 不能使 Rule 变得适用，也不能激活它。只有在 Skill 支持该行为的所有场景中都具备受支持的加载保证时，Skill 才能依赖独立适用的 Rule 中的具体约束。这些约束由 Rule 的独立加载提供；Skill 只保留作出自身任务决策所需的本地背景。这种依赖应保留 Rule 的范围、条件和例外。移除 Skill 中的义务，须先解决职责分配和加载问题；仅有引用并不能证明适用性或可用性。

先选择最合适的所有者，再检查能否修改它。将规范源的访问条件、写入授权与可读性分别确认，以实际可用的访问为证据，不要仅凭位置推断需要提权。可编辑的安装缓存或 Skill 中的重复政策都不能替代规范所有者。缺少源文件、访问条件或权限时，仍存在需要由负责角色解决的所有者依赖。
