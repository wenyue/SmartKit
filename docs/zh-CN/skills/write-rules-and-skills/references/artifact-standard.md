# 共同判断依据

一个**artifact**是一份 Rule 或 Skill；其**Candidate**包含范围内的配套资源。Controller、Author 和 Quality 使用本依据分配职责、编写和判断质量。实际行动和结论由各角色契约决定。

## 含义与理解

已接受的权威要求决定预期含义；现有 Candidate 文本提供回归证据。保留有实质后果的义务、条件、例外、非目标，以及帮助读者行动的理由。被放弃的选项和编写讨论留在证据记录中；即使工件本身要求使用者比较方案，也同样适用。

正确性、Agent 可理解性和 Agent 可执行性同等重要。明确有实质后果的决定，将普通方法和无关紧要的细节留给有能力的 Agent。结果依赖顺序时固定顺序。以读者能否理解并完成预期工作来判断完整阅读路径，不为标题或长度设配额。

## 归属与加载

已安装的 SmartKit 核心治理负责适用性、强度、优先级和组合；引用该所有者。明确采用的任务替代方案或项目委托会影响受支持的决策时，说明其条件、预期偏离或委托结果，以及剩余约束。

### 选择所有者

| 所有者 | 职责 |
| --- | --- |
| Rule | 相关工作中的有界、持续性政策。 |
| 任务 Skill | 触发后有明确结果的工作。 |
| 规则导向 Skill | 通过原生 Skill 发现应用于现有工作的政策。 |
| 代码、配置、模式或其他活动所有者 | 各自管辖的事实。 |

根据含义，将每项政策的完整定义放在最合适的现有所有者处。始终加载只能证明可用，不能证明归属。一个公开 Skill 可以保留条件性资源，无需抹平其加载边界。

### 确立路径

检查相关 Rule 和 Skill、适用且始终加载的项目与全局 Rule，以及可能同时加载的条件性 Rule。比较条件、例外和配置，确立规范源、含义、触发条件及受支持的路径。仅凭本次会话中的上下文无法证明未来可用性。

- **从 Rule 出发：**可以引用 Rule 或 Skill。Skill 只有在提供某行为的所有场合都存在受支持的独立加载保证时，才能依赖独立加载的 Rule。
- **从 Skill 出发：**调用或引用 Skill，包括规则导向 Skill。使用简短的所有者指针和本地判断背景，不直接引用独立加载的 Rule 文件。

保留所有者的条件和例外。移除义务前，先解决归属和加载：只有指针不足以证明适用或可用。使用规范源；可编辑的缓存和副本不能确立权威。缺少源、访问或权限仍是所有者依赖。

## 让形态适合工作

**Rule**从政策入手。读者应能重建其所有者、Strength、可观察的条件与结果、例外和优先级。

**Skill**的打包和调用遵循 `SKILL-MECHANICS.md`。其描述必须支持 Agent 根据加载前可见的名称、任务和上下文选中它。精简发现时的上下文，同时通过静态追踪覆盖预期用途、相近但不匹配的用途，以及容易遗漏的必要用途。

围绕工作中的决策选择形态：

| 形态 | 组织思路 |
| --- | --- |
| 原则导向 | 结果、治理原则、关键约束和完成条件；方法保持开放。 |
| 流程导向 | 当顺序或协议影响正确性、安全、归属、协调、恢复或外部效果时，使用有序步骤。 |
| 规则导向 | 治理相关工作的要求和例外。 |
| 混合型 | 将不同形态连贯整合，各关键部分分别满足其加载和执行标准。 |

原则导向和流程导向的任务 Skill 服务于具体工作。将普遍需要的方法集中在易取得的位置；仅为缩短入口而拆分会增加跳转。

### 规则导向 Skill

为这种形态使用 `rule-<domain>` 名称，不论 Strength 如何。面向模型的描述应在领域相关、治理决策发生前触发，并使明确调用和专门评估可被发现。在入口声明默认 Strength，将会改变行为的条件放在要求旁边。

普通激活约束当前工作。按要求进行的评估按照同一政策和请求权限，覆盖现有工作并报告规定结果。两种路径都在现有权限内执行。

广泛触发使首次激活成本成为验收的一部分。区分以下成本：

| 成本 | 读者加载的内容 |
| --- | --- |
| 发现 | 始终可见的描述和指针。 |
| 首次激活 | 入口及所有无条件读取，包括传递依赖和已写在入口中的分支。 |
| 后续分支 | 在依赖它的决策或行动前读取的条件性内容。 |

入口应让普通实质性修改和常规审查走到行动与完成。将基本政策、Strength，以及足以决策的证据、条件和例外放在入口。所有或几乎所有工作都需要的背景保留在正文中；当可识别的事实触发所属资源时，再披露额外知识或约束。在依赖该资源的行动或审查判断前加载它。

通过实际文件和传递读取追踪普通修改、常规审查及深入路径。按所需知识判断分支，而非按任务标签。每次读取都应及时提供必要背景；名义上有条件、实际上普通工作几乎必经的路径，会背离降低首次激活成本的目标。修订时以既有加载边界作为回归证据。静态追踪已经足够，无需任务频率断言、额外报告或运行实验；不设配额或强制拆分，综合判断完整性和成本。

核心治理的继承规则适用于所属的规范性资源。说明性材料和独立所有者的政策保留各自契约。原生发现与公开暴露由不同所有者负责；编写入口不会自动注册它，也不会迁移其他政策。
