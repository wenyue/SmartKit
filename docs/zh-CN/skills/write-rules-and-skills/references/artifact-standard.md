# 共同判断依据

制品指一个 Rule 或 Skill；Candidate 指当前正在编写和审查的制品及其范围内的配套资源。Controller、Author 和 Quality 在各自职责内，将这些判断应用于两种制品类型，分别用于对齐、分配及 Author brief；编写；质量审查。行动和结论的权限仍由各自的角色合同规定。

## 实际生效的含义

具有权威性的已接受要求确立制品的预期含义；现有 Candidate 文本是回归证据。制品的治理指令表达最终要求，并保留其含义、范围、条件、例外和非目标。只有中间推理或未选的编写方案对读者理解或执行已接受的要求有实质帮助时，才将其提炼为有用的理由、边界或例外予以保留。对话历史仍是编写和审查的证据；出现在证据中，本身并不构成将其纳入制品的理由。这一要求适用于制品自身的指令，也包括要求产出方案比较内容的指令。

围绕有意义的决策组织内容，将每项要求与应用它所需的证据、行动和验证放在一起。结果依赖顺序时，明确规定顺序；否则将方法留给 Agent 判断。通过准确的引用条件按需展开真实分支，而不是依照任意长度阈值拆分。判断连贯性和完整性时，不强制规定标题、清单、字数预算，也不另加一套重复政策的工作流。

应用 `writing-for-agents` 的正向目标指导：默认正向说明目标。只有正向措辞无法可靠避免实质性混淆、错误适用或安全风险时，才将负向边界保留为必要的硬性护栏，并同时说明所需的正向行为。正向表述足以传达预期范围和行为时，用这种方式保留已接受的约束和非目标。

## 职责与加载

Rule 负责在相关工作中持续生效、且边界清晰的政策领域。任务型 Skill 负责有明确结果和边界的触发式任务，以及该任务所需的约束；规则导向 Skill 则负责应用于现有工作的政策。规则导向 Skill 是通过原生 Skill 发现机制提供的 Rule，不是争取独立交付物的任务工作流。根据含义和范围，将共享的持续性政策分配给最合适的现有政策所有者，无论它是 Rule 文件还是规则导向 Skill，必要时完善该所有者。无条件加载可以作为可用性的证据，但不能成为将项目或 Skill 专属义务提升为全局政策的理由。如果某项事实已由代码、配置、schema 或其他现有所有者负责，则相应变更归该所有者负责。

每条政策在相关 Rule 和 Skill 中只保留一个完整定义。引用应符合受支持的途径：Rule 文件可以引用 Rule 和 Skill；Skill 可以调用或引用其他 Skill，包括规则导向 Skill，但不得直接引用独立加载的 Rule 文件。在这些边界内，使用指向所有者的简短引用，以及作出决策所需的本地背景，将政策定义保留在其所有者处。Skill 的加载途径可以加载规则导向政策，但不能扩大该政策声明的范围。

评估合适的现有所有者时，检查相关 Rule 和 Skill、适用且无条件加载的项目 Rule 和 SmartKit 全局 Rule，以及在受支持的使用场景中可能共同加载的条件 Rule。通过环境支持的发现与加载途径，确认它们的含义、范围、触发条件和规范源。仅凭当前编写会话，无法确认未来使用者能否获得它们。

比较含义，包括条件、例外和配置，而不是匹配措辞。对于独立加载的 Rule 文件，Skill 不能使其适用或激活它。只有在 Skill 支持相应行为的所有场景中都有受支持的独立加载保证时，才可依赖其中的具体约束，并仅保留作出自身决策所需的本地背景。无论采用哪种加载途径，都要保留政策的范围、条件和例外。移除 Skill 中的义务，须先解决职责分配和加载问题；仅有引用并不能证明适用性或可用性。

先选择最合适的所有者，再检查能否修改它。将规范源的访问条件、写入授权与可读性分别确认，以实际可用的访问为证据，不要仅凭位置推断需要提权。可编辑的安装缓存或 Skill 中的重复政策都不能替代规范所有者。缺少源文件、访问条件或权限时，仍存在需要由负责角色解决的所有者依赖。

## 制品形态

选择适合所分配工作的形态。对每种形态都应用上文的共同判断；选择、编写或评估其形态时，应用下文相应的标准。

### Rule

编写 Rule 时，以治理政策开篇，并确保其所有者、强度、范围、可观察条件与结果、例外、优先级和边界都可以还原。

### Skill

编写 Skill 时，将 `SKILL-MECHANICS.md` 应用于调用和包装，从三种并列写法中选择适合工作的形态：

- **原则导向的 Skill**说明结果、治理原则、会产生实质后果的约束和完成条件，同时将具体方法留给 Agent 判断。
- **流程导向的 Skill**在顺序或协议会影响结果、正确性、安全、所有权、协作、恢复或外部影响时，明确规定步骤及顺序。
- **规则导向的 Skill**通过有明确适用范围的要求和例外约束相关工作。

**混合型 Skill**在这些写法能发挥实质作用的地方加以组合。围绕决策整合其含义，而不是拼接一段规则说明和一套工作流。

### 规则导向 Skill

将 `rule-<domain>` 名称保留给这种写法，命名不随强度变化。结合 Rule 写法与 Skill 机制：在入口中明确声明适用范围和默认强度，并通过面向模型的描述，让政策在相关决策前得到加载。涵盖支持的日常工作条件和专项评估条件；保留显式调用方式，但不因此扩大适用范围。

正常激活时，约束当前工作，而不是另外启动审计或报告。用户要求的评估有自身明确的覆盖范围和结果，仍须处于政策范围和请求授权内。两种途径都不授予额外权限。要求可以包含必要流程，以及相关决策所需的证据和验证，同时让已有明确做法的日常情形保持轻量。

适用性、强度、优先级以及与任务型 Skill 的冲突，均依赖已安装的 SmartKit 核心治理，不重复或重新定义这些契约。对自身负责的规范性资源采用核心治理的继承规则，并将其与示例材料和独立所有者的政策区分开；独立政策保留自身契约。为每项必要资源给出具体的加载条件，使其在依赖它的决策前得到加载。原生 Skill 发现和公开暴露仍由既有所有者负责；写出规则导向入口并不等于注册它，也不等于将其他政策迁入其中。
