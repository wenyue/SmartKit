# Rule

Rule 负责一项持续生效的政策。本引用直接适用于候选工件。

## 建立规则框架

根据已经确认的意图、当前 Rule schema 和治理证据，确定 Rule 的类别、归属与强度、范围与适用条件、
可观察的“条件到结果”映射、例外、优先级和归属边界。这些内容共同构成规则框架。每个适用字段都
必须有证据支持的值；只有证据能证明某字段不会影响政策时，才能省略。

## 编写一项政策

- 开头先写真正生效的政策。每个条件都要和对应的结果、例外放在一起。
- 每项要求保留在拥有它的最窄 Rule 中；不要复制或悄然覆盖更具体的 Rule。
- 使用可以观察的条件和结果。每个阈值、重叠范围、区间、例外和排除项，都要能处理最接近边界的误判
  与漏判，不能依赖没有定义的标签。
- 把有序执行流程放在 Skill 中。
- 可以从环境发现的事实留在实际负责它的地方。理由和决策历史放在对应文档中，除非它们会影响政策
  如何适用。
- 标题用于稳定的政策区域或真实存在的适用分支；列表用于并列要求；表格只用于精确映射或重复字段
  的比较。

## 审查和验收 Rule 语义

语义审查根据候选工件和证据重建每个适用字段，以及每一条“条件到结果”映射。以下情况必须判定失败：
字段没有明确写出、无依据地声称不适用、虚构条件、归属重复、覆盖关系未声明，或同一组事实会产生
多个结果或没有结果。

只选择风险最高的相关案例：

- 一个适用案例，以及与它最接近的不适用案例；
- 一个受影响的阈值、区间、重叠范围、例外或归属边界；
- 如果另一个 Rule 能改变结果，再选择一种优先级或冲突组合。

在政策真正生效的接缝应用通用验收执行者协议，并要求得到可以观察的决定或动作；只解释 Rule 写了
什么，不算实际应用。
