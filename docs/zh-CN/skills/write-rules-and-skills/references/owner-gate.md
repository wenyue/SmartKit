# 归属判定关口

归属判定关口判断已经确认的义务应归属于 Rule、Skill、二者，还是都不属于。它在写入候选修订版
前运行，也为父 Skill 提供只读的归属审查出口。

## 对义务分类

根据已经确认的请求、语义台账、现有工件（如有）、更宽和更窄的归属，以及可以从环境发现的事实，
逐项独立分类：

- `rule`——跨触发式工作持续约束决策的政策；
- `skill`——由触发条件启动并产生一个有界结果的工作；
- `environment-owned`——可以从代码、配置、schema、工具输出或其它现有归属中可靠获得，因此无需
  缓存在工件中的事实；或
- `ambiguous`——当前证据仍然支持多种实质不同的归属。

返回一个完整结论：`rule`、`skill`、`split`、`environment-owned` 或 `ambiguous`。
`split` 要求至少有一项由 Rule 独立拥有的义务和一项由 Skill 独立拥有的义务。

## 比较所有权

将证据支持的结论与请求的归属比较；如果工件已经存在，还要与当前归属比较。

- 二者一致时，不询问所有权问题并继续。不能仅因为创建或编辑的是 Rule 就要求另行批准。
- 二者冲突时，说明证据、每种有依据的放置方式会怎样影响行为和加载，以及建议保留、移动还是拆分。
  返回 `decision-required`，并在用户选择归属前停止写入候选项。
- 结论为 `ambiguous` 时返回 `decision-required`。不要用请求的包装方式来决定语义所有权。

完整结论为 `environment-owned` 时，指出实际归属和可发现的证据，返回“无候选项”结果并停止，不写入
Rule 或 Skill。

所选归属仍必须满足对应的 Rule 或 Skill 语义以及完整的验收标准。用户的选择只解决归属意图；
不会把持续生效的政策变成触发式工作，也不会免除语义门控。

## 返回归属审查

对于明确要求的只读审查，检查所选工件，以及发现重复或放错位置所需的相关归属。每个工件都要返回：

- 当前归属和证据支持的归属；
- 每项义务的分类和完整结论；
- 证据、影响、建议和任何确切缺失的决定；以及
- 所有权一致时返回 `PASS`，否则返回 `decision-required`。

声明没有修改任何文件，然后停止；不创建候选修订版，也不启动精简、机器验证、语义审查或验收。
