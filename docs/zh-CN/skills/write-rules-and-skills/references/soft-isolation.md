# 软隔离

此引用负责软隔离探针的资格认定和上下文包边界。软隔离是一种经过验证的行为边界，不是文件系统、
进程或用于抵御攻击的安全沙箱。

## 验证新智能体的启动方式

每次顶层编写工作流在启动第一个软隔离智能体前，都要运行一个一次性、无工具的探针。不得跨父级
运行或跨新智能体启动机制复用结果。

启动前，在父级可见的对话中放入一个随机的历史控制值，但不要把它写进探针提示。然后设计准确的问题，
答案分别只存在于每份可用的源项目 Rule 正文、SmartKit 全局 Rule 正文、智能体宿主 Rule 正文和完整
Skill 正文中；这些答案同样不能出现在提示里。探针提示中还要加入另一个不同的随机控制值。

启动一个不继承此前轮次的新智能体。要求它只使用初始上下文，不调用工具、不读取文件、不委派、不做
推断，并返回：

- 提示控制值；
- 父会话历史控制值或 `UNKNOWN`；
- 每个 Rule 和 Skill 正文问题的答案或 `UNKNOWN`；
- 入口文件内容、Rule 指针或 Skill 目录元数据是否可见；
- 它是否使用了工具、文件读取、推断或委派。

`PASS` 要求提示控制值完全一致，历史控制值和所有正文问题都返回 `UNKNOWN`，并且没有使用工具、读取
文件、推断或委派。入口文件及其中的 Rule/Skill 指针，以及 Skill 目录中的名称、说明和位置可以可见；
探针不得沿这些指针继续读取，也不能把它们当成上下文包输入。如果能看到被引用的 Rule 正文或完整
Skill 正文，无法用规定方式启动新智能体，返回格式错误，或有其它任何不匹配，就判为 `FAIL`。遇到
`FAIL` 后停止并警告，不能降级为普通智能体，也不能改在同一对话里重新提示。

## 构建上下文包

一个上下文包包含某个角色所需的全部语义输入：

- 该角色唯一的职责、请求结果和输出 schema；
- 与该角色有关的、已经确认的意图和候选项内容；
- 选择的证据，以及每份必需 Rule、Skill 或引用的完整正文；
- 角色负责写作时所需的完整文件内容和规范目标标识；
- 仅在角色的可观察任务需要时提供的允许工具和路径；以及
- 适用的完成、停止和失败结果。

不能用工作区路径代替实际内容。上下文包不完整时，无工具智能体返回 `CONTEXT_REQUIRED`，说明缺少
什么事实以及用途。控制器可以停止，也可以用一份完整的新上下文包启动另一个新智能体；不能继续向
原角色的对话补充材料。

上下文包和角色结果只保留在当前智能体上下文中。不要把包清单、提示、证明、台账或判定报告写入文件。

## 认定例外工具访问

只有候选项的可观察契约确实无法在无工具条件下测试时，验收执行者才能使用工具。运行该案例前，
以相同的工具权限再次执行探针，任务只能依赖明确提供的目标。这个工具政策探针只能针对该目标使用已
声明的工具；只有它未读取或使用任何未声明上下文时才算 `PASS`。探针失败或结果无法验证时，停止工作流。
