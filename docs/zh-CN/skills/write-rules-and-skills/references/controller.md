# Controller

将请求转化为一份忠实、有界的 Author brief，并管理工作流直至收尾。Author 负责编写 Candidate，Reviewer 负责结论，Correctness 在冻结权限内负责运行时验证。

对齐前阅读[共同判断依据](artifact-standard.md)和具有权威性的 `writing-for-agents` Skill，用于分配职责和准备 brief。

## 确立意图与所有者

保留完整的**用户意图记录**，与自己的解释及 Author brief 区分。保留原始请求、后续关于含义、范围和非目标的修正与决策，以及这些回应所针对的提案、问题或选项。

选择 Candidate 前，检查合适的现有所有者。确定整体结果所需的变更和依赖。分别确立规范源访问和写入授权：可实际访问是证据；仅凭位置不能确立权限。

| 所有者状态 | 路由 |
| --- | --- |
| 可编辑且已授权 | 将变更交给该所有者。 |
| 缺少源、访问或权限 | 返回 `NEEDS_INPUT`：说明所有者、职责、所需变更、实际限制，以及可解决问题的源、授权或所有者行动。 |
| 多个所有者需要变更 | 按依赖顺序拆成任务，每个任务恰好包含一个工件。调用方可以提供分配计划。 |
| 必要的所有者变更与用户文件限制冲突 | 写入前返回 `NEEDS_INPUT`。 |

只有所有者依赖闭合后，依赖它的任务才能返回 `COMPLETE`。从权威来源研究可查明的事实，解决关于结果、现有行为、非目标、保留要求、兼容性、依赖、权限、验证、安全、分发和交接的实质性选择。

## 准备 Author brief

给 Author 一份自包含的 brief，包含：

- 目标和请求的变更；
- 准确的 Candidate 路径，以及获准的新增、编辑、移动和删除操作；
- 已接受的约束和权威证据路径；
- 职责分配、所有者及受支持加载的证据、调用方计划（如有）和依赖状态；
- 已冻结的不自动修复验证，以及可观察的完成条件。

### 限定运行时权限

冻结有限的场景数、尝试次数和资源总量上限，包括任务内委派。区分宿主能力与实际授权。给 Correctness 生命周期控制，以记录并安全结束 Runner 和子活动，同时保留对全局收尾的监督。Correctness 在这些边界内直接作出普通运行时决定。

## 选择与调整审查拓扑 <a id="choose-and-adjust-review-topology"></a>

两种拓扑都完整应用三个视角：

| 拓扑 | 适用情形 |
| --- | --- |
| **Integrated Review：**一个身份应用 Quality、Change 和 Correctness | 义务、路径和集成背景已闭合，没有实质性不确定性，且风险有界。 |
| **Independent Review：**每个视角由独立身份负责 | 任务涉及自举、广泛影响、高风险，或在归属、安全、权限、外部效果、恢复、验证、关键路径上存在不确定性。 |

收到 `INDEPENDENT_REVIEW_REQUIRED` 时，安全结束 Integrated 尝试和活动中的运行时工作。在当前指纹上启动三位全新的 Independent Reviewer，在同一轮内替代 Integrated 尝试。确保此前尝试不会替代或影响独立判断。如果切换或其原因需要更广范围、访问或权限，返回 `NEEDS_INPUT`。

## 维护对齐与处理阻断 <a id="maintain-alignment-and-handle-blockers"></a>

随证据到来，保持请求、分配、依赖和 brief 一致。新发现所有者时，在越过冻结范围前返回 `NEEDS_INPUT`。

如果 Correctness 根据用户意图证明 brief 存在遗漏或曲解，仅修正有证据支持的部分。所有 Reviewer 返回后，将其交给同一位 Author 做一次连贯修复。应用正常的返回门槛、指纹捕获、验证和下一轮审查，仍受原定三轮上限约束。Controller 修正 brief；语义结论仍由 Correctness 负责。

| 阻断因素 | 结果 |
| --- | --- |
| 权威上下文无法消除实质性的意图歧义 | 将 Reviewer 的原问题呈现给用户，不添加解释，并返回 `NEEDS_INPUT`。 |
| 缺少用户控制的运行时输入或权限，或请求超出冻结任务 | 返回 `NEEDS_INPUT`。 |
| 因边界耗尽或不支持安全执行，必要证据仍不可用 | 返回 `BLOCKED`；保留冻结的运行时权限。 |

每条退出路径都按主工作流完成角色和残留状态的收尾。
