# 精简智能体

本引用规定精简智能体所用的上下文包、任务、判定和复查方式。父 Skill 负责何时运行该门控、如何
隔离角色、处理问题分类、执行修正以及进入后续出口。

## 提供上下文包

向智能体提供：

- 已接受结果和语义账本；
- 归属判定关口的结论，以及选定的规则框架或技能设计形态；
- 完整候选工件、自有资源以及加载或分发表面；
- 治理证据和适用引用；
- 存在前一版本时的基线行数、词数和字节数。

不能提供前一版本、diff、作者推理、疑似缺陷、预期修改或预期判定，也不能提供工具或工作区路径。
缺少判断所需的语义输入时返回 `CONTEXT_REQUIRED`，不得自行查找上下文。

## 检验保持语义的缩减

查找陈旧或重复的含义、不必要缓存的环境事实、放错位置的分支专属内容，以及可以删除或压缩的措辞
或结构。重点质疑只是在重述有证据支持的智能体或智能体宿主默认行为、重复可靠加载的上层归属，或者能由
触发条件、输入、步骤或相邻上下文唯一推导出来的明确指令。

还要质疑：

- 与归属判定关口结论冲突，却被放进 Rule、Skill 或运行时资源的义务；
- 没有证据表明流程会影响正确性、安全性、外部协议合规性、协调、恢复或已接受结果，却规定的
  Skill 动作或顺序；
- 让一个固定流程片段把无关判断也变成固定工作流的混合型技能；
- 过早加载条件性细节，或无法通过明确指针到达完整选定框架或路径的主文件。

只有删除一项指令后，所有代表性动作、选择、权限、安全边界以及完成、停止和失败出口都不变，才能
认为它可以删除。声称某项行为属于默认行为时，必须有智能体宿主治理证据或适用的行为对照支持。

## 返回并复查

返回 `PASS` 或 `FAIL`。`PASS` 表示已经没有证据支持的无损精简机会，并不要求工件一定变小。每个
`FAIL` 问题都要写明证据、候选位置、建议如何精简、不变的行为、保留的义务，以及对应的问题分类。

每次完成已授权的修正后，使用修订后的候选工件和以前的问题重新检查。返回 `FAIL` 时，要列出所有
剩余的精简机会，并说明已处理的问题是否原样再次出现。不要创建持久的精简报告。
