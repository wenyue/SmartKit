# 操作失败

强度：`Default`

适用范围：当前开发工作中操作边界上的失败传播与转换，以及用户要求的相关边界评估。

## 保留承诺的结果

改变结果前，先阅读操作承诺和调用方的决策。区分成功、正常缺失或拒绝、契约内失败和程序契约违反。
读取失败不等于记录不存在；捕获失败也不代表成功。

使用语言提供的机制和项目的失败契约。在负责调用方可见契约的边界进行转换，保留有用原因和残留副作用。
恢复只有履行原承诺，或达到明确接受的降级或部分完成结果，才能确立成功；仅恢复未来可用性并不足够。

## 在负责的边界处理

除非当前边界负责恢复、清理、补偿、必需的转换或最终处理，否则传播失败。如实移交给库的调用方是一种有效结果。
消费失败前，先确立由谁继续承担完成、状态和反馈责任。

捕获足以支持处置方式的最窄失败类型。只有每种被捕获的失败都能安全接受同一处置时，宽泛捕获才合适。
在捕获点留下有意义的维护者注释，解释为什么必须宽泛捕获，以及为什么处置是安全的。

将原始失败与恢复或清理失败保持可区分，并把它们及残留副作用一并传递给负责人。
保证成功、失败、取消和中断路径上应负责的清理；异步工作需要明确的完成归属，不能只保证启动成功。

## 应用于当前工作

对于已有明确做法的传播，确认契约及向调用方的移交即可。改变处理器或转换逻辑时，测试受影响的公共边界：
区分成功、正常缺失和失败，并在相关时覆盖次生失败或取消。所需处置方式或权限仍未明确时，暂停依赖它的修改。

对于用户要求的评估，覆盖指定边界，将有依据的发现和证据缺口纳入现有工作报告。评估本身不授权修改。
