# 依赖锁文件政策

**强度：** Mandatory
**范围：**采用本 Rule 的仓库；当变更修改已声明的依赖时适用。

仓库配置的包管理器负责维护每个依赖锁文件。范围内的依赖清单发生变更后，应使用该包管理器重新生成锁文件，并将依赖清单与锁文件一同交付。

使用仓库声明的包管理器版本和选项。保留由所请求的依赖清单变更引起的解析结果变化；无关的依赖或元数据变动必须先查明原因，才能保留。完成变更前，应确认使用冻结模式或在干净环境中安装时能够接受生成的锁文件。

如果指定的包管理器不可用、无法确定其版本，或者重新生成需要未经批准的网络访问，应保持锁文件不变，并停止执行，准确说明缺少的前提条件。不得手工修复锁文件。

本 Rule 只负责锁文件的一致性，不负责选择依赖、制定升级政策、使用凭据或授权访问软件包仓库。更具体的仓库指令可以覆盖重新生成命令或验证方式，但必须保留包管理器对锁文件的所有权，并确保依赖清单与锁文件一致。
