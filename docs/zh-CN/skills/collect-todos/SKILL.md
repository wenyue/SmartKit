# 收集待办

仅当用户明确请求调用 `collect-todos` 时使用此 Skill。

保存暂缓工作，并留下足够的上下文，让后续会话能够接续。保持轻量收集：使用对话和相关项目来源中已有的证据，然后返回主任务。收集用户选定的任务，或已有收集指令涵盖的任务；仅仅发现无关的改进机会，并不授权写入任务跟踪器。

## 找到项目的任务跟踪器

阅读目标项目的入口指令，例如 `AGENTS.md`，并沿其指针读取任务跟踪器及相关接收或分流约定。在写入前，明确保存位置、受支持的操作途径，以及创建或补充任务的要求。项目拥有其跟踪器、记录格式、标签和工作流；使用项目声明的远端或本地跟踪器，不预设某个服务或文档目录。

如果声明缺失、冲突、不可读，或操作途径不可用，指出缺失的前提并暂停保存。只询问继续所需的决定或访问权限。在报告中保留未保存的任务；聊天中的草稿不等于已保存的待办。更改保存位置需要用户决定，不能静默改用其他存储。

## 收集足够的信息，便于以后接续

将可独立执行的目标分开，同时将同一项工作的各个部分保留在一起。为每个任务提供具体标题，并保留有用的上下文：

- 预期结果、发现背景，以及暂缓的原因。
- 已知事实，以及相关文件、工件或已有任务的指针。
- 已确认的范围、约束，以及已知的验收条件。
- 有用的下一步，以及仍需调查或决定的问题。

区分观察结果、建议和未知信息。链接已有规格，避免复制其内容。缺失的细节可以记为待解决问题；只调查识别任务、确定保存位置或判断可能重复项所需的信息。收集不要求完整的实施计划，也不授权执行暂缓的工作。

如果这项工作是主任务的必要前提，说明该依赖并保留其阻碍意义。将其记录为以后处理，并不会让主任务变为已就绪或已完成；只继续可以独立推进的主任务工作。

## 保存时避免重复任务

在配置的跟踪器中搜索可能匹配的记录，并在选择保存位置前阅读其范围和状态。根据目标和上下文判断是否匹配，而不是只看标题：

- 如果没有已有记录涵盖暂缓的目标，创建任务。
- 通过项目支持的更新或评论途径，向匹配的任务补充有用的新证据，并保留已有内容和决定。
- 如果已有记录已经涵盖该任务，引用该记录，避免重复写入。

新记录遵循项目的接收约定。保留已有优先级、指派和工作流状态，除非收集请求或项目约定要求变更。不完整的收集记录不能证明任务已就绪、可以实施。

逐项保存并验证任务，让部分失败有明确的结果。读回新建或已补充的记录，确认预期内容存在于其权威链接或配置的本地路径。也要验证被引用的记录。发出了命令或收到未经确认的响应，都不能证明保存成功。

如果写入失败或结果不确定，在重复操作前核实跟踪器状态。只有证据表明先前操作已经结束、重复执行安全，而且有依据支持针对失败的修正时，才重试。如果验证或恢复无法确定结果，停止受影响的写入，并将该任务报告为未保存或结果不确定，说明原因及下一步需要什么。保留其他任务已验证的结果。

## 报告收集的待办，并返回主任务

交代每个选定收集的任务。对每项任务，报告人类可读的工作摘要、处理结果，以及已验证记录的权威链接或本地路径。区分新保存、已补充、已有记录、未保存和结果不确定；对未成功的项目，指出仍缺少的证据或决定。只报告数量或一组链接是不够的。

当前有主任务时，将此报告作为进度更新，然后继续其已获授权的工作，同时遵守必要前提造成的阻碍。对于独立的收集请求，以该报告结束。
