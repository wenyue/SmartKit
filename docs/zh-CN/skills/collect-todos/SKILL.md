# 收集待办

仅在用户明确请求 `collect-todos` 时使用本 Skill。

保存延期工作，并提供足够上下文，便于未来会话接手。保持收集过程轻量：使用对话和相关项目来源中已有的证据，然后回到主任务。收集用户选定或既定收集指令涵盖的任务；仅发现一个无关改进，并不授权写入跟踪器。

## 1. 确定目标位置和收集范围

阅读目标项目的入口指令，例如 `AGENTS.md`，并沿指针查阅任务跟踪器以及相关接收、分流约定。在写入前确定目标位置、受支持的操作路径，以及创建或补充任务的要求。跟踪器、记录格式、标签和工作流归项目所有；使用项目声明的远程或本地跟踪器，不假定特定服务或文档目录。

如果声明缺失、冲突、无法读取，或操作路径不可用，指出缺失的前提并暂停持久化。只询问继续所需的决定或访问权限。在报告中保留未保存任务；聊天中的草稿不算已保存待办。改变目标位置需要用户决定，不得悄然使用另一处存储。

## 2. 保留足够的接手上下文

为每个任务提供具体标题。拆分可独立行动的结果，将同一工作的组成部分放在一起，并保留未来会话需要的上下文：

- 期望结果、发现背景和延期原因。
- 已知事实，以及相关文件、产物或已有任务的指针。
- 已确认的范围、约束和验收条件（如已知）。
- 有用的下一步，以及仍需调查或决定的问题。

区分观察、建议和未知事项。链接已有规格，不重复复制。缺失细节可记录为开放问题；只调查识别任务、目标位置或可能重复项所需的内容。收集不要求完整实现计划，也不授权执行被延期的工作。

如果该工作是主任务的必要前提，解释依赖并保留其阻塞意义。记录为待办，不会使主任务就绪或完成；只继续可独立推进的主任务工作。

## 3. 写入前按结果匹配

在配置的跟踪器中搜索可能匹配的记录，阅读其范围和状态后，再决定保存位置。匹配结果和上下文，不只比较标题：

| 跟踪器中的已有状态 | 操作 |
| --- | --- |
| 没有记录覆盖延期结果 | 创建任务。 |
| 匹配任务需要有用的新证据 | 通过受支持的更新或评论路径补充，保留已有内容和决定。 |
| 已有记录完整涵盖该任务 | 引用它，不重复写入。 |

新记录遵循项目的接收约定。保留已有优先级、分配和工作流状态，除非收集请求或项目约定要求改变。收集不完整不能证明任务已准备好实现。

## 4. 验证每条保存或引用的记录

逐项持久化并验证任务，使部分失败也有明确结果。回读每条新建或补充的记录，在其权威 URL 或配置的本地路径确认目标内容。引用的记录也要验证。发出命令或收到未经确认的响应，不能证明已持久化。

写入失败或结果不确定时，先核对跟踪器状态，再考虑重试。只有证据证明之前的操作已结束、重复安全，并且对失败有有依据的修正时，才能重试。如果验证或恢复仍无法确定结果，停止受影响的写入，将该任务报告为未保存或不确定，并说明原因和下一步所需条件。保留其他任务已经验证的结果。

## 5. 报告每项结果并恢复主任务

逐项交代所有选定收集的任务。每项都提供人类可读的工作概要、结果，以及已验证记录的权威链接或本地路径。区分新保存、已补充、已有记录、未保存和不确定；对于未成功的项目，指出仍缺少什么证据或决定。仅给数量或链接列表不够。

有主任务进行中时，将该报告作为进度更新，然后在前提阻塞允许的范围内继续已授权工作。独立的收集请求则以该报告结束。
