# 错误处理

选择最简单、同时履行操作承诺、遵守已接受损失和权限、并留下有效状态的处理方式。恢复未来可用性，本身不代表失败的操作已经完成。

## 按受影响的决策加载指导

实质性工作和评估适用下述通用原则。在选择、修改或审查表中的决策前，阅读所有匹配的参考文件。取消远程写入可能需要多份。必要指导不可用时，报告缺口，暂停依赖它的决策。

| 受影响的决策 | 必读资源 |
| --- | --- |
| 存储或序列化数据：解释、恢复、丢弃、迁移或持久化保证。 | [持久化](references/persistence.md) |
| 文件系统、网络、子进程或其他外部操作：发出请求、结果不明、重放、核对或补偿。 | [外部操作](references/external-operations.md) |
| 并发或延后执行的工作：完成、取消、超时、过期结果、流或生命周期清理。 | [异步工作与流](references/async-and-streaming.md) |
| 身份认证、权限校验、完整性检查、安全回退，或包含凭据或私密载荷的诊断。 | [身份与安全](references/identity-and-security.md) |
| 面向用户的恢复：保留输入、补救行动、人工修复，或移交给其他执行者。 | [用户恢复](references/user-recovery.md) |

## 从承诺的结果出发

依据操作承诺区分成功、正常拒绝或缺失、契约内失败和程序契约违反，不以它们的表示形式、发生频率或可重试性为依据。

只有操作履行了承诺，或达到已接受的降级或部分结果时，才能报告成功。捕获错误或提供默认值并不足够；保留调用方需要关注的失败和残留副作用。

保持不会失败的操作直接明了。使用语言原生机制和既有项目契约；在契约所属边界转换失败。

穷尽处理封闭的业务结果集合。开放协议需要保留明确的未知失败路径和有用原因；偶发失败不得变成正常拒绝。

可选检查被禁用时，所需验证、控制流、副作用和不变量仍须在生产中生效。

在理解数据语法和含义的边界验证数据，区分内容无效与 I/O 失败。代码、类型和引用契约未清楚表达重要调用方义务时，补充说明。

## 审慎设计公开失败契约

优先采用语义准确的既有失败契约。只有具体的处理或诊断收益足以抵偿调用方知识和兼容成本时，才新增公开区分；可选细节也适用。

新增可供外部使用的失败区分前，须取得用户对该新增项的明确同意，除非它符合下述忠实细化条件。异常类型、错误标识或错误码、结果分支，以及新开放检查能力的底层失败，都可能增加此类契约。已有明确同意仍然有效；一般性的功能实现授权并不足够。

### 何时细化无需额外同意

忠实细化保留语言或标准库中语义准确的具体失败类别，以及该类别承诺的识别方式、信息和处理行为。调用方无需适配，已有的类别层面处理就必须有效；调用方可以按需使用具体细节。

通过原生匹配或分类机制确认这一点；不要求继承，仅共用通用异常基类或错误接口也不满足条件。此豁免只免除额外取得同意的要求；收益仍须抵偿成本，并保留受支持契约。

## 明确责任直到操作完成

仅为当前边界负责的恢复、清理、补偿、必要契约转换或最终处理而拦截失败；否则如实传播。库可以通过已接受的调用方契约返回失败结果来履行责任。

为每个独立发起的操作明确完成、失败、残留状态和最终反馈的负责人。在成功、失败、取消和中断路径上完成应负责的清理。

停止传播失败或委托报告，不会消除对残留状态和恢复的责任。将未解决结果、重要副作用和所需证据移交给明确的负责人；仅委托工作不代表操作完成。

## 选择最简可接受的恢复方式

复用能够保留所需状态和工作的最简单既定恢复方式。受影响的人有实际可行的后续行动时，短暂等待或安全地手动重试就可能足够。只有为保障所需结果或显著减轻失败影响时，才增加包装、回退状态或自动修复。

恢复须可行、有明确限度，并在负责人权限内。明确已接受的损失、残留副作用，以及恢复失败时的结果。告知已接受的部分完成留下的重要副作用。

重试需要有依据表明失败原因可以克服，并有明确的停止条件。

## 只处理已有既定处置的失败

有依据认为正常条件通常成立时，优先直接执行并在局部处理。无法确认条件有效时，优先采用可靠、低成本的显式检查。

遵守语言的安全前提；捕获失败不能使不安全的执行变得安全。可变状态的预检查只能确认检查当时的条件，因此检查通过后，仍须处理或传播实际操作失败。

使用原生匹配或分类机制，只处理当前边界已有既定处置的失败。保持处理局部化，保留程序缺陷和无关失败所需的传播或报告。遵守语言和库对返回错误、异常和类似 panic 中断的约束；`Error` 这样的名称或能够拦截它，本身不能证明处理安全。

同一种恢复、回退或转换，必须对其覆盖的每种失败都安全。

在编写的代码中，每个宽泛拦截点附近都要留下维护者注释，说明为何必须宽泛拦截，以及为何处置对每种被拦截失败都安全；宽泛异常捕获和类似 panic 的拦截均适用。常规检查返回错误并如实传播，不要求此类注释。

## 保留证据而不扩大公开契约

在转换和最终处理过程中，保留原始错误、原因链、可用堆栈，以及适合向相应受众提供的有用上下文。区分原始失败与恢复、清理或补偿失败。如果次生失败决定调用方的处置，保留原始失败作为补充证据；否则保留原始结果，由次生失败的负责人处理它。面向人的解释用于补充这些证据。

分别决定诊断保留与公开错误识别能力：原生匹配或解包可能使底层错误成为调用方依赖。保留已承诺的识别能力，新增前应用公开契约政策。有用证据本身，既不足以证明新增公开包装或检查契约合理，也不要求每种原生错误表示都携带堆栈。

## 让最终反馈对受众有用

每个需要报告的事件都应有一个最终报告负责人。补充诊断与面向受众的反馈可以并存；传播不得重复报告同一事件。

依据影响、运行预期和所需响应，采用项目定义的严重级别和告警规则。报告通道或恢复成功本身，都不能决定严重级别。

最终反馈必须传达有用的上下文、影响、结果状态及任何受支持的下一步行动，包括重要损失或功能不可用，即使受众无法修复。

## 在任务内明确并验证

判断修正前，沿实现、调用方、转换和最终归属追踪受影响结果。在当前任务权限内修改所属边界，保留无关结果和受支持契约。仅评估的工作保持只读；本政策不增加远程或破坏性操作权限。

在询问处置、损失、归属或受众负担决定前，先调查能够查明的事实。既定的安全处置无需等待根因。缺少重要证据、契约或决定、必要资源或能力、或权限时，报告缺口，暂停依赖它的工作；独立且获准的工作可以继续。

通过负责的公共操作或边界及其所属检查，验证变更后的结果、最终反馈和残留状态。覆盖有实质差异的成功、缺失或拒绝及失败路径，包括恢复或停止条件，以及可能改变承诺的次生失败、取消或中断。必要验证失败或不可用，工作就仍未完成。

使用当前任务的验证和交接，不另起常规审计。为每条已识别的路径给出处置或证据缺口，报告范围、有依据的发现或修正、实际检查、未解决决定及未验证部分。缺口既不是已验证路径，也不是已完成修正。
