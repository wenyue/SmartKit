# 错误处理

先看调用者需要这次操作完成什么。操作失败时，合适的处置仍可以满足调用者的需要。例如保存失败后仍能保留编辑内容，用户释放空间后可以再试。额外保护应带来足以抵偿实现与维护成本的收益。保持状态有效，遵守权限和可接受损失的范围，让本身不会失败的操作保持直接。

## 确认操作结果及归属

根据操作的承诺区分成功、正常缺失或拒绝、契约内的失败，以及编程错误。失败的频率、表示形式或可重试性都不能决定它属于哪类。只有兑现承诺时才报告成功，包括契约允许的降级或部分结果。捕获异常或提供默认值，本身不足以说明操作兑现了承诺。保留调用者关心的失败及其残留影响，并告知部分完成带来的重要影响。

每项独立发起的操作，都应有人负责完成、失败、剩余状态和最终反馈。库可以按已约定的调用契约返回失败，履行自身责任。成功、失败、取消和中断时都要完成自己负责的清理。工作转交给其他责任方时，一并交接未确定的结果、重要影响以及后续处理需要的证据。消化错误或委派报告之后，仍要处理剩余状态和恢复安排。

选择、修改或审查受影响操作的处理方式前，阅读每份涉及当前决定的参考。一次取消的远端写入可能涉及多份参考。必读参考不可用时，报告缺口并暂停依赖该参考的决定。

## 选择失败的处置方式

让失败到达能够处理它的边界。只有为了本边界负责的恢复、清理、补偿、必要的契约转换或最终处理，才拦截失败。其余情况沿用语言原生机制和项目现有契约，如实传播失败。已有安全、明确的处置方式时，可以在根因尚未查明前执行。

确实需要恢复时，优先选择满足调用者需要的最简单既有做法。恢复应可行，并处于责任方的权限和可接受损失范围内。为恢复设定边界，确认会留下什么影响，包括恢复自身失败时的后果。只有有理由相信后续尝试能成功，并且有明确停止条件时，才重试。

有证据表明正常条件通常成立时，优先直接执行，在本地处理相关失败。有效性不确定时，优先采用可靠、低成本的显式检查。执行前满足语言的安全前提。对可变状态的检查只能证明检查当时的情况，仍要处理或传播实际操作中的失败。

在能理解数据语法和含义的位置进行验证，区分内容无效与 I/O 失败。禁用可选检查后，必要验证、控制流、副作用和不变量仍须在生产环境有效。穷尽封闭业务取值中的每一种情况。为开放协议提供显式的未知失败路径并保留有用原因，避免偶发故障被归入正常拒绝。说明代码、类型和所引用契约未写清楚的重要调用义务。

依据原生分类匹配失败，只处理在当前边界已有明确处置方式的失败。就地处理，让无关失败和编程缺陷继续传播或到达其报告责任方。遵守语言和库对返回错误、异常和类似 panic 的中断规定。能拦截某个失败，或它的名字叫 `Error`，都不足以说明可以安全恢复。

共用的恢复、回退或转换必须对覆盖的每种失败都安全。在编写的代码中，每处宽泛拦截，包括宽泛捕获异常和拦截类似 panic 的中断，都要在附近留下注释，说明为什么需要覆盖这么广、为何同一处置对所有被拦截的失败都安全。检查返回错误后按原意传播，照常直接写即可。

## 保留证据并决定调用者可以识别什么

转换和最终处理时，带上原始错误、原因链、可用的堆栈和对受众安全且有用的上下文。把恢复、清理或补偿失败与初始失败区分开。如果次生失败决定了调用者收到的结果、剩余状态或应采取的行动，保留原始失败作为补充证据。其余情况保留原来的操作结果，在次生失败所属的边界处理它。面向人的解释补充底层证据。堆栈可用时予以保留，原生错误表示沿用自身机制。

单独决定调用者可以依赖什么。原生匹配或解包可能把底层失败暴露为公开契约的一部分。保住已承诺的识别能力，在拥有该契约的边界做转换，优先使用语义准确的现有契约。仅有诊断价值不足以引入公开包装或可检查的契约。

只有具体的处理或诊断收益足以抵偿调用者需要了解的额外信息和兼容成本时，才增加可供外部使用的失败区分，即使细节可由调用者选择使用也是如此。新的异常类型、错误标识或错误码、结果分支以及新增可检查的底层原因均属此类。除非属于忠实细化，否则新增区分需要用户明确同意。之前的明确同意仍然有效。通用的功能实现授权不包含这类契约变化。

忠实细化保留一个语义准确、具体的语言或标准库错误类别，保住已承诺的识别能力、信息和处理方式。通过原生匹配或分类确认已有类别级调用者无需适配即可继续工作。更具体的信息由调用者选择使用。继承是可选的，仅共享通用异常基类或错误接口不足以证明兼容。此例外只免除另行同意的要求，新增区分仍须有足够收益并保留受支持的契约。

## 交付结果并验证

每个需要报告的事件由一方负责最终报告。按需提供相互补充的诊断信息和受众反馈，避免错误传播时重复报告同一事件。按影响、运行预期和需要采取的行动决定项目的严重度和告警。报告渠道或恢复成功本身不足以决定严重度。向受众说明发生了什么、有什么影响、留下什么状态，以及有哪些受支持的后续动作。即使受众无法修复，重要的损失或不可用也需要说明。

判断应如何修正前，沿实现、调用者、契约转换和最终责任方追踪受影响的结果。在当前任务的权限内修改负责该行为的边界，保留无关结果和受支持的契约。评估保持只读。远程操作和破坏性操作仍按原有授权处理。

在询问谁应负责、能接受多少损失或受众负担、应如何处置失败前，先查明可推导的事实。缺少重要证据、契约或决定、必要资源或能力，或者权限时，指出缺口并暂停依赖它的工作。继续独立且已获授权的工作。

通过负责的公开操作或边界及其检查，验证变更后的结果、最终反馈和剩余状态。覆盖有实质差异的成功、缺失或拒绝以及失败路径。恢复和停止边界、次生失败、取消或中断可能影响操作承诺时，也应覆盖。必需检查失败或不可用，工作仍未完成。

沿用当前任务的验证和交接。说明每条已识别路径已有的处置或证据缺口。报告范围、得到支持的发现或修正、实际检查、未决事项和未经测试的部分。有证据支持时，才能确认路径已验证或修正已完成。
