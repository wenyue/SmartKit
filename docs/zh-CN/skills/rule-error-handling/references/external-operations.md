# 外部操作

## 重放前明确结果

选择恢复方式前，识别已知和不确定的副作用，包括在途工作、持有资源和可见状态。明确清理、补偿或中断后留下什么，以及由谁负责。原生清理语义可能掩盖原始失败或保留资源时，检查其行为。

| 证据 | 对处理方式的影响 |
| --- | --- |
| 请求未发出。 | 此次尝试未产生远程副作用；本地准备可能需要清理。 |
| 权威响应拒绝了请求。 | 遵循拒绝契约，包括其中允许的副作用；区分无关基础设施失败。 |
| 请求已受理或副作用已确认。 | 确定承诺是否完成，还是仍需确认或后续步骤。 |
| 响应丢失、超时，或完成情况不明。 | 保留不确定性；缺少响应不能证明变更失败。 |

有受支持的状态查询或操作标识时，通过它核对不确定结果；否则，在不安全的重放前移交未决结果。优先仅重试未完成步骤。需要时使用既有幂等或去重保证；新的尝试标识可能使其失效。

可选文件访问中，只有调用方接受原生查询可能发生的查找失败或类型不匹配时，才能跳过或采用默认值。让必需访问暴露实际操作的失败。存在性检查既不能保证独占创建，也不能保证原子替换；应使用具有所需保证的操作。

## 确保完整重放路径安全

检查完整重放路径，包括恢复状态和补偿，是否会产生重复或不可逆的副作用。重试点的参数、当前状态、资源和已完成副作用，必须仍然允许实现承诺结果。明确所需的幂等性或补偿；重放安全依据未在其他地方清楚表达时，在逻辑旁说明。

远程创建成功而必需刷新失败时，完整重试可能重复创建。契约支持时，仅重试刷新、补偿创建，或报告部分结果；否则，传播失败和残留远程状态。创建失败必须跳过刷新，仅刷新恢复不得再次创建。

补偿有自己的完成和失败结果；尝试补偿不能证明已经回滚。在上述示例中，补偿失败必须同时保留刷新失败和残留远程对象。创建后或补偿期间停止可能改变结果时，应验证对应情况。
