# 外部操作

文件系统、网络、子进程或其他外部副作用决定恢复、重放或完成方式时，使用本参考。依据操作实际做了什么，以及契约确认了什么来处理。

## 重放前明确结果

沿失败步骤和恢复过程追踪重要写入、远程变更、持有资源、通知和可见状态。包括在途工作和结果不明的副作用。明确清理、补偿、取消或中断后留下什么，以及由谁负责。次生失败可能替换原始错误或掩盖保留资源时，检查原生失败机制。

| 证据 | 对处理方式的影响 |
| --- | --- |
| 请求未发出。 | 此次尝试未产生远程副作用；本地准备仍可能需要清理。 |
| 权威响应拒绝了请求。 | 遵循拒绝契约，包括其中允许的副作用；单独保留无关基础设施失败。 |
| 请求已受理或副作用已确认。 | 明确承诺的操作是否完成，还是仍需确认、后续步骤或核对。 |
| 响应丢失、超时或其他原因导致完成情况不明。 | 保留不确定性。有受支持的状态查询或标识时，通过它核对；否则，在不安全的重放前，将未决结果移交给负责人。 |

请求发出后超时或连接中断，不能证明变更失败。状态查询或仅重试未完成步骤能确立承诺结果时，优先采用。需要时使用既有幂等或去重契约；新的尝试标识可能使该保护失效。

普通可选文件访问中，只有调用方接受原生查询可能发生的查找失败或类型不匹配时，才能选择跳过或默认分支。必需访问以及调用方必须观察的失败，应交给实际操作暴露。预先检查存在性既不能保证独占创建，也不能保证原子替换；应使用能提供所需保证的协议。

## 确保完整重放路径安全

检查完整重放路径，包括恢复状态和补偿，是否会产生重复或不可逆的副作用。复用检查点需要有证据表明，参数、当前状态、资源和已完成副作用仍允许实现承诺结果。明确整条路径所需的幂等性或补偿。代码、类型和引用契约未清楚表达重试安全依据时，在重放逻辑旁说明。

假设操作承诺远程创建后执行必需的本地刷新。创建成功而刷新失败时，远程状态已经改变，因此完整重试需要防止重复创建。依据已接受的契约，负责人可以仅重试刷新、补偿创建，或报告已接受的部分结果。若这些方式都不受支持，就向负责人传播失败及残留远程状态。

补偿有自己的完成和失败结果；尝试补偿不代表已经回滚。如实传播并说明已知残留副作用，或安全地手动重试，已能满足契约时，避免另建补偿系统。

## 验证会重复什么、留下什么

通过公共操作或负责边界，检查它承诺重复、保留或补偿的副作用。停止条件、补偿失败和中断可能改变结果时，应覆盖这些情况。

在创建示例中，创建失败后不得继续刷新。仅刷新恢复不得再次创建。补偿失败时，必须同时保留刷新失败和残留远程对象。路径支持时，测试创建后或补偿期间停止的情况。
