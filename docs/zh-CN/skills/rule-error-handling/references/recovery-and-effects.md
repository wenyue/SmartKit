# 重试与副作用

当重试、补偿或其他恢复依赖于哪些副作用可能已发生、可能重复或会在中断后留下时，阅读本参考文件。

## 查明哪些副作用已经发生

沿失败步骤和后续恢复追踪有实质影响的写入、远端变更、占用的资源、通知和可见状态。纳入仍在执行的工作以及结果未知的副作用。明确清理、补偿、取消或中断后还留下什么，以及由谁负责。次生失败可能覆盖原始错误或掩盖仍被占用的资源时，检查原生失败机制的行为。

## 确保整个重放路径安全

检查完整的重放路径，包括恢复和补偿，确定哪些副作用可能重复或无法撤销。

要复用检查点，须有证据表明参数、当前状态、资源和已发生的副作用仍允许实现承诺的结果。建立完整重放路径所需的幂等保证或补偿措施。如果代码、类型和引用的契约未说明为什么可以安全重试，在重放逻辑旁补充说明。

假设一项操作承诺先在远端创建对象，再完成必需的本地刷新。创建成功而刷新失败时，远端状态已改变，整项重试需要防止重复创建。根据已接受的契约，负责人可以采用以下方式之一。

- 只重试刷新。
- 补偿创建操作。
- 报告契约允许的部分完成结果。

若契约不支持这些方式，将失败及残留的远端状态传递给负责人。

## 验证哪些副作用会重复、哪些会保留

通过公共操作或负责边界，验证其承诺会重复、保留或补偿的副作用。如果达到停止条件、补偿失败或中断会改变该结果，验证相应路径。

在创建示例中，创建失败后不能继续刷新。仅重试刷新不能再次创建对象。补偿失败时必须保留刷新失败和仍存在的远端对象的信息。如果路径支持在创建后或补偿过程中停止，验证对应的停止路径。
