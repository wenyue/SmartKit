# 恢复与副作用

当选择、修改或审查恢复、重试、补偿或已接受的部分完成策略，且其安全性取决于副作用、重放或结果状态时，使用本资源。

## 明确失败后的残留状态

将承诺结果与操作实际达到的状态进行比较。追踪持久写入、远程修改、持有资源、已发出事件和可见状态等重要副作用，从起点经过处理责任移交直到最终负责人。包括必需的异步完成、取消、中断及次生失败。明确每个负责人会获知哪些结果和残留状态；报告失败本身并没有解决其副作用。

恢复必须通过可行、有界且对其效果具有权限的行动，建立有效状态。明确可接受损失、相关权限、恢复失败时的结果，以及该策略是在完成当前操作，还是仅恢复未来可用性。将拟议处置与操作承诺及调用方所需决策进行比较。已接受的部分完成或降级结果必须披露残留副作用；否则，为负责人保留失败结果及状态。当代码、类型和引用契约未清楚表达恢复理由时，补充说明，尤其是损失权限与重试安全性。

## 保证整个路径上的重放安全

重试需要有理由相信失败原因可以被克服，并有停止边界。检查完整重放路径，包括恢复与补偿，识别重复或不可逆副作用。可复用的检查点需要证据证明参数、当前状态、资源和已经完成的效果，仍允许达到承诺结果。明确所需幂等性或补偿，不能因为捕获了失败就认为再次尝试安全。

例如，远程创建成功后，必需的本地刷新失败，此时远程状态已经变化。完整重试需要防止重复创建。根据已接受的契约，负责人可以只重试刷新、补偿创建，或报告已接受的部分结果。若都不受支持，在明确处置方式期间继续传播失败及残留远程状态。这是说明副作用的模式，不是规定策略。

将清理和补偿结果与原始失败保持可区分。当次生失败可能替换最初错误或掩盖仍持有的资源时，检查原生机制。为最终负责人保留有用的原始证据、次生原因和残留状态。沿相同的归属和状态转换追踪恢复期间的取消与中断；中途停止必须留下有明确归属的结果，不能假定已经回滚。

## 验证所选处置

通过公共操作或负责边界检查策略。覆盖实际存在且有意义的成功、初始失败、部分副作用、不受支持的恢复、恢复成功与失败、停止边界，以及取消或中断路径。确认承诺结果和残留状态，包括哪些效果被重复、保留或补偿。

在创建示例中，创建失败后不能继续刷新；仅刷新恢复不能再次创建。补偿失败必须同时保留刷新失败及残留远程对象。如果路径支持取消或中断，测试创建后或补偿期间的停止。依据实际副作用与契约选择检查，不要把示例扩展成对无关失败情况的要求。
