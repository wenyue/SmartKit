# 异步工作与流

并发或延后执行的工作、取消、超时、迟到结果或流输出影响操作承诺时，使用本参考。

## 将必需工作纳入完成链

返回、等待或以其他方式观察操作完成所必需的工作。观察每个已启动的同级任务，包括其他任务失败后才发生的失败。前置工作失败时停止依赖工作；完成条件依赖已接纳工作和必要清理时，先等待它们结束，再宣告完成。

脱离当前操作的工作需要独立的完成、失败、恢复和生命周期负责人。仅标记脱离或安装回调，不能确立这些责任。工作有意超出发起者生命周期时，为负责人提供完成所需的状态和诊断上下文，使它不依赖已销毁的调用方。

## 区分停止观察与停止副作用

明确取消、超时、关闭和销毁实际停止了什么。取消订阅或等待超时，可能仍留下在途工作。必要时停止接纳新工作，请求受支持的取消，并按契约等待已接纳工作结束或移交它们。通过仍然存在的负责人，使残留副作用和清理失败保持可见。

使用既有生命周期或操作标识，在已被替代工作的迟到结果发布到当前状态前将其拒绝。跨越异步间隔后，当前边界负责的可变条件若可能使行动失效，就重新检查。令牌检查不能撤销已经发出的写入；重置和替换必须通过排序、等待在途工作结束或其他既定协议处置这些写入。只有可实际发生的冲突影响已接受结果时，才增加协调。

## 区分部分输出与完成

流可能先交付有用输出，再失败。明确契约是将该输出保留为已接受的部分结果、展示为未完成草稿，还是丢弃它。保留终止失败或取消，以及重要副作用；收到一个条目、空结果或传输关闭，本身都不能证明已达到承诺的完整结果。

为流的终止错误和取消完成安排观察者。暂停或取消时，保留必要背压和有明确上限的在途工作。在成功、失败、取消和中断路径上完成必要资源清理；前面的清理失败时，仍尝试其余安全清理。应用入口的原始与次生失败政策，避免清理失败无声地替换原始事件。

同级任务失败、取消或超时、迟到结果、部分输出和清理失败会改变完成承诺时，在受影响的完成边界验证它们。立即重置可见状态，以及成功请求取消，与持久化重置或所有工作均已结束，是不同的观察结果。
