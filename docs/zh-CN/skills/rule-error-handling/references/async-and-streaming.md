# 异步工作与流

## 将必需工作纳入完成链

返回、等待或以其他方式观察必需工作，包括其他同级任务失败后才发生的每个已启动任务的失败。前置工作失败时停止依赖工作；完成条件依赖已接纳工作和必要清理时，先等待它们结束，再宣告完成。

脱离当前操作的工作需要完成、失败、恢复和生命周期负责人，并有足够的状态和诊断上下文，使其能在发起者销毁后完成。仅标记脱离或安装回调，不能确立这些责任。

## 区分停止观察与停止副作用

明确取消、超时、关闭和销毁实际停止了什么：取消订阅或等待超时，可能仍留下在途工作。必要时停止接纳新工作，请求受支持的取消，并按契约等待已接纳工作结束，或将其移交给会保持可用的负责人。

使用既有生命周期或操作标识拒绝过期状态发布；可变前提发生变化可能使行动失效时，在异步间隔后重新检查。令牌检查不能撤销已发出的写入。重置或替换时，通过排序、等待在途工作结束或既定机制处置它们；只有可实际发生的冲突影响已接受结果时，才增加协调。

## 区分部分输出与完成

流可能先交付有用输出，再失败。按其契约保留已接受的部分输出、展示未完成草稿，或丢弃输出。保留终止失败或取消及重要副作用；条目、空结果或传输关闭，本身都不能证明已达到承诺的完成状态。

观察流的终止错误和取消完成。暂停或取消时，保留必要背压和有明确上限的在途工作；前面的清理失败时，仍尝试其余安全清理。按入口的证据政策保留原始和次生失败。
