# 持久化

普通 I/O 失败传播不需要重建政策；修改或丢弃数据则需要。

## 明确允许恢复或丢失什么

依据数据用途和所属契约，明确必须保留什么、允许丢失什么，以及有效的结果状态。数据损坏或路径可写，都不构成删除授权。

| 数据角色 | 选择恢复方式前需要明确 |
| --- | --- |
| 派生数据或缓存 | 重建来源，以及暂时或长期缺失是否为有效状态。 |
| 访问凭据或本地状态 | 由谁或什么机制重建，以及此前哪些能力不可用。 |
| 可采用默认值的状态 | 有效默认值，以及被替换的选择或进度所造成的损失是否已获接受。 |
| 重要、用户编写、导入或仅有一份的数据 | 权威替代来源或针对具体损失的授权，以及有效结果。损失权限或结果有效性尚未明确时，保留原始字节。 |

在这些边界内，优先重置、丢弃或重建最小无效单元；保留其他有效记录。只有数据契约需要时，才增加抢救、隔离或兼容处理。

重建假设和损失权限未在其他地方清楚表达时，在恢复逻辑旁说明。

## 区分访问、解释和修复

区分读取、验证、迁移和修复失败。访问失败或迁移未完成，不足以认定当前格式内容无效，也不得据此触发损坏数据删除。

使用受支持的历史格式和必要迁移解释旧数据。迁移元数据控制这种解释：修复无效标记前，确定先前版本和必要转换。仅将旧记录标记为当前版本，可能无声地改变其含义。

只读库可以在明确的降级结果契约下跳过无效记录。为调用方保留跳过记录造成的影响和诊断，并在存储字节不变的情况下，验证已承诺的重复读取行为。只有承诺要求持久化修复，且当前边界可以修改存储时，才需要落盘修复。

需要持久化修复时，验证存储修改和下一次读取；可用默认值本身无法证明其中任何一项。修复失败时，将内容无效的原因、修复失败，以及受影响的数据或位置交给最终负责人。

## 保留实际写入承诺

等待存储契约要求的写入、刷盘或提交确认。内存更新不能证明已经持久化；等待后端调用完成，也只能确立其文档承诺的保证。

将调用方串行化，不会让多次写入成为原子操作。替换会话元数据成功而清空历史失败时，保留重置失败结果和已知残留状态。使用已接受的修复或部分完成契约。失败或中断的写入序列可能改变保留数据含义时，验证后续读取。
