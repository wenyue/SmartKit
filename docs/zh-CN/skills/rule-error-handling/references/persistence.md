# 持久化

存储或序列化数据涉及恢复和失败决策时，使用本参考。普通 I/O 失败传播不需要重建政策；修改或丢弃数据则需要。

## 明确允许恢复或丢失什么

确定负责人、数据用途、可接受的损失，以及已接受结果要求的有效状态。明确恢复是否必须改变后续读取，以及当前边界是否有权修改存储。路径、格式或损坏事实本身，不构成丢失数据的授权。

| 数据角色 | 选择恢复方式前需要明确 |
| --- | --- |
| 派生数据或缓存 | 重建来源，以及重建期间或获准丢弃后，缺失是否为有效状态。 |
| 访问凭据或本地状态 | 由哪个执行者或服务重建，以及此前哪些能力不可用。 |
| 可采用默认值的状态 | 有效默认值，以及被替换的选择或进度所造成的损失是否已获接受。 |
| 重要、用户编写、导入或仅有一份的数据 | 权威替代来源或针对具体损失的授权，以及有效的结果状态。损失权限或结果有效性尚未明确时，保留原始字节。 |
| 模式或迁移元数据 | 它如何控制保留记录的解释，以及必要转换的选择。 |

权限和结果有效性已明确时，优先直接重置、丢弃或重建最小无效单元。保留其他有效记录。只有数据契约需要时，才增加抢救、隔离或兼容处理。将重要损失、归属或所需状态的未决事项交给其负责人，并保留未经授权丢失的字节。

代码、类型和引用契约未清楚表达重建假设或损失权限时，在恢复逻辑旁说明。

## 区分访问、解释和修复

定位失败阶段：读取字节、验证语法或含义、应用必要迁移，还是执行修复。语法有效本身不代表含义有效。访问失败或迁移未完成，不足以认定当前格式内容已损坏，也不得据此触发损坏数据删除。

将迁移元数据视为数据解释契约的一部分。用当前版本替换无效标记，可能把旧记录错误地标记为已迁移。确定先前版本并应用必要转换，让保留记录维持原有含义。依据受支持的历史格式和迁移契约，区分旧版有效数据与当前无效数据。

只读库可以通过跳过无效记录并返回明确的降级结果履行契约。为调用方保留跳过记录造成的影响及有用诊断，并验证存储字节不变时重复读取仍符合承诺。只有已接受的承诺要求修改持久化状态，且当前边界有必要权限时，恢复才必须落盘。

契约要求持久化修复时，验证修改以及下一次读取。得到可用默认值本身不代表修复完成。例如，数据契约允许通过重新登录重建时，删除已确认无效的登录数据可能恢复为有效的未登录状态。如果承诺后续读取干净有效，就检查删除和下一次读取。修复失败时，将内容无效的原因、修复失败，以及受影响的数据或位置交给最终负责人。

## 保留实际写入承诺

报告承诺的完成结果前，等待存储所属契约要求的写入、刷盘或提交确认。内存更新不能证明已经持久化；等待后端调用完成，也只能确立该后端文档承诺的保证。

将调用方串行化，不会让多次写入成为原子操作。轮换会话元数据成功而清空历史失败时，部分重置副作用会保留。保留已知存储状态和重置失败结果，使用已接受的修复或部分完成契约，而非声称已经回滚。检查下一次读取，以及可能改变保留数据含义的中断或失败写入序列。
