# 身份与安全

身份认证、权限校验、完整性检查、安全回退，以及包含凭据或私密载荷的诊断适用本参考。

## 恢复时保持安全边界

区分身份认证缺失或过期、权限被拒绝、身份或完整性证据无效，以及检查执行失败。刷新过期凭据可以是受支持的恢复方式，但不会授予执行被禁止操作的权限。权限检查失败或不可用，不得变成继续执行的许可。

在既定身份和范围内，使用已接受的登录、续期或重新授权路径。尝试须有明确限度；续期只能恢复未来访问时，保留本次操作的失败结果。重放原请求还须满足外部操作的重放条件；新会话不能证明先前请求没有产生副作用。

延后执行的授权工作结束后，主体、会话、资源和授权发生变化可能使操作授权失效时，验证它们仍与本次操作相符。使用负责方既有的同步或绑定机制。拒绝过期结果，不将其应用到替换后的身份。操作失败时，不得通过跳过完整性验证或扩大授权来回退。

清除无效凭据或会话元数据，也是一项持久化决策：明确损失权限、重建方式，以及此前不可用的能力。如实返回失败并提供受支持的登录行动已能满足契约时，避免丢失无关数据或强制更换身份。

## 保留有用证据，同时保护私密数据

从日志、公开错误、遥测和用户反馈中过滤凭据、令牌、密钥和不必要的隐私信息。错误对象、原因链、请求 URL、解码器消息和捕获的载荷本身都可能包含秘密；仅过滤新增上下文字段并不足够。

无法披露原始载荷时，保留有用的结构事实、适合受众的操作标识、失败类别和可用堆栈。更完整的证据只能通过既定且获授权的诊断渠道，并按其保留契约保存。公开反馈所需细节可以少于私密诊断；两者都不应为了说明拒绝而暴露其他主体的数据。

拒绝、检查不可用、异步间隔后身份过期、续期失败和诊断脱敏影响变更边界时，应验证对应路径。恢复成功须保持与正常成功相同的安全条件。
