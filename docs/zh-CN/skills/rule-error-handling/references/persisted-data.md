# 持久化数据

选择、修改或审查持久化或序列化数据的修复、重建、丢弃或降级使用方式，需要明确权限、损失、后续读取或数据解释时，先使用本资源。仅传播普通 I/O 失败，不需要作出数据恢复决定。

## 明确哪些数据可以恢复或丢失

确定负责人、数据用途、可接受损失，以及已接受结果所要求的有效状态。明确恢复是否必须改变后续读取，以及当前边界能否修改存储。路径、格式或发现数据损坏，都不构成丢失数据的授权。

根据数据作用调查重要问题：

| 数据作用 | 选择恢复方式前需要确定的事项 |
| --- | --- |
| 派生或缓存数据 | 重建来源，以及重建期间或获准丢弃后，缺失是否为有效状态。 |
| 访问状态或本地状态 | 负责重建的角色或服务，以及重建前不可用的能力。 |
| 可使用默认值的状态 | 有效的默认值，以及对被替代选择或进度的损失已获接受。 |
| 重要、用户编写、导入或唯一副本的数据 | 权威替代来源或针对具体损失的权限，以及有效的结果状态。损失权限或结果有效性仍未明确时，保留原始字节。 |
| 模式或迁移元数据 | 它如何控制保留记录的解释和必需转换的选择。 |

契约可以支持降级、重建、修复或获准丢弃。当其他状态能够履行已接受契约时，无需精确重建。在开展依赖性变更前，将未解决的重要损失、归属或状态决定交给其负责人。

当代码、类型和引用契约未清楚表达重建假设或损失权限时，在恢复代码附近解释理由。

## 区分可读结果与持久化修复

定位失败阶段：读取字节、验证语法或含义，或执行修复。语法有效，并不能证明含义有效。处理过程中仍须区分访问失败与内容无效。

只读库可以通过跳过无效记录并返回明确的降级结果来履行契约。为调用方保留被跳过记录的影响和有用诊断，并在存储字节不变的情况下验证重复读取符合承诺。只有已接受承诺要求持久化变更，且边界具有必要权限时，恢复才需要改变持久状态。

对于可写状态，验证具体修复，不把默认值当作成功证据。假设解析器已确认保存的登录状态无效，契约允许通过重新登录重建，且应用有权删除字节。此时，丢弃该状态可以是有依据的修复。如果修复承诺后续读取不再遇到损坏，就验证删除和下一次读取。

在这个示例中，需要身份验证的原操作仍应报告身份验证不可用；恢复有效的已登出状态，并未完成该操作。

## 在整个修复过程中保留证据与数据解释

修复失败时，将无效内容的原因、修复失败、受影响状态和可采取行动的路径传递给最终负责人。只读存储可能阻止本已获准的丢弃；返回默认值不能证明修复已建立预期状态。

任何重试都需要可能改变的条件、安全的重复效果和停止边界。唯一副本数据的损失未获授权时，在负责人明确处置方式期间保留数据和失败结果。

将迁移元数据视为数据解释契约的一部分。把无效标记替换为当前版本，可能错误地将旧记录标记为已迁移。明确旧版本如何推导、遗漏转换如何执行，并验证恢复保留了原记录的含义。

验证负责的公共操作所产生的状态及重复读取行为。实际存在相关路径时，包括修复失败、异步完成、部分写入后的中断及其他恢复效果。当实际策略还需要恢复或补救约束时，应用入口中的对应分支；仅涉及持久化数据，不构成无条件的资源加载链。
