# 持久化数据

在选择、修改或审查持久化或序列化数据的修复、重建、丢弃或降级使用方式前，如果需要确定权限、可接受的损失、后续读取或数据解释，阅读本参考文件。单纯传播 I/O 失败无需作出数据恢复决策。

## 确定可以恢复或丢弃哪些数据

确定数据的负责人、用途、可接受的损失，以及已接受的结果所需的有效状态。明确恢复是否必须改变后续读取的结果，以及当前边界是否有权修改存储。路径、格式或确认数据损坏都不能单独证明有权丢弃数据。

根据数据的用途确定需要查明什么。

| 数据用途 | 选择恢复方式前须确定 |
| --- | --- |
| 派生数据或缓存 | 重建所用的数据来源，以及重建期间或获准丢弃后能否接受数据缺失。 |
| 访问状态或本地状态 | 由谁或哪个服务重建，以及在此之前哪些功能不可用。 |
| 允许恢复默认值的状态 | 有效的默认值，以及丢失原有选择或进度是否可接受。 |
| 重要数据、用户创建或导入的数据、唯一副本 | 权威替代数据或允许承担特定损失的权限，以及有效的结果状态。在损失权限或结果有效性尚未明确时，保留原始字节。 |
| 模式或迁移元数据 | 它如何决定保留记录的含义，以及哪些迁移必须执行。 |

把尚未解决的重大损失、归属或必要状态的决定交给相应负责人。保留未经授权丢弃的原始字节。

代码、类型和引用的契约若未说明重建所依赖的条件或数据丢失的权限，在恢复逻辑旁补充说明。

## 区分可读结果与持久化修复

确定失败发生在哪个阶段，包括读取字节、验证语法或含义、执行修复。语法有效仍需验证含义。处理时须区分访问失败和内容无效。

只读库可以按契约跳过无效记录，并明确返回降级结果。向调用方保留被跳过记录造成的影响和有用诊断，并验证原始字节保持不变时，重复读取仍符合承诺。只有契约要求修改持久化数据且当前边界拥有相应权限时，才需要写入修复。

契约要求持久化修复时，验证存储变更和下一次读取。可用的默认值不足以证明修复成功。例如，数据契约允许通过重新登录重建数据时，可以删除已确认无效的登录数据，使系统回到有效的未登录状态。如果承诺后续读取不再遇到无效数据，验证删除和下一次读取。

## 保留现有记录的含义

将迁移元数据视为数据解释契约的一部分。把无效的版本标记直接替换为当前版本，可能使旧记录被错误地视为已迁移。确定原版本并执行所需迁移，保留现有记录的含义。

修复失败时，将内容无效的原因、修复失败及受影响的数据或位置交给最终负责人。
