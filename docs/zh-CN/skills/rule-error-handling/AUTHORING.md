# 编写决策

## 将证据保留与公开识别分开

将诊断证据与调用方可检查的失败标识作为两个独立决定。解包可能暴露实现依赖，而为诊断保留原因并不一定使其成为公共 API。因此，忠实细化豁免要求保留具体原生类别的处理行为，不能把共用异常基类视为兼容性的证明。

## 在宽泛拦截的位置解释理由

维护者注释要求应针对采用统一处置的宽泛拦截。若读者无法看出该处置为何对覆盖的每种失败都安全，宽泛捕获就可能无声地吞掉无关缺陷。常规返回错误传播被明确排除，因为在那里套用同一要求会产生重复注释，却不存在同样的风险。

## 为每项恢复策略保留唯一归属

通用的结果、传播、诊断、权限、责任和恢复标准留在入口。通过五份按决策划分的参考展开策略，场景交叉时读取多份。领域政策可以保留自己的状态不变量和完成契约；在那里重复恢复方法会造成相互竞争的归属。

## 在已接受的结果范围内简化

当两种方式都能满足已接受的结果时，优先直接处理并采用既定的有限恢复，而不增加保护机制。删除无效存储数据以具有损失权限和有效结果状态为前提：某个项目的迁移和重建保证，不能为其他项目确立这种权限。丢失这一区分，会把有用的简化变成未经授权的数据损失。
