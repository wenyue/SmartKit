# 维护项目配置

根据业务项目的证据维护 Agent 配置。先在实际业务项目中编写和验证，再在仓库模式下将明确选定且已验证的文件完整备份到配置仓库。显式恢复方向相反，不编写或发布配置。

将本目录解析为 `<skill-root>`、所在插件解析为 `<plugin-root>`、业务项目解析为 `<target-root>`。使用 `<skill-root>/scripts/maintain.py` 作为 `<maintain>` 前，阅读[项目配置维护](references/maintenance.md)。该共享参考负责绑定、备份范围、恢复、本地同步和发布恢复。显式的 setup 恢复和已启用的启动同步使用该参考和受支持命令，不调用这个仅限用户调用的 Skill。从已加载的插件解析资源，不依赖目标工作目录。

## 1. 明确预期结果和来源

```text
python "<maintain>" inspect --target "<target-root>"
```

检查为只读操作。确认维护模式、选定条目、备份范围、目标差异和未完成工作。仅要求检查时，到报告这些结果及不可用证据为止；这不授权更新、恢复、编辑或发布。

| 情形 | 写入前需要明确的事项 |
| --- | --- |
| 未绑定项目 | 一起提供项目共享、仅本机和独立配置仓库三种模式；绑定前取得用户的模式选择。 |
| 显式恢复 | 遵循参考中的来源选择路径：复用具有匹配本地成功恢复记录的有效绑定，或询问仓库、分支和条目。仅有复制的绑定不能确定本 checkout 的来源。 |
| 同一 checkout 的后续维护 | 复用其有效绑定；不从业务远端或其他 checkout 推断仓库身份。 |
| 在已有配置上初始化 | 分析实际内容和差异，提出具体方案，并取得用户的替换决定。 |

## 2. 区分编写与恢复

保留业务项目和配置 checkout 中已暂存、未暂存、未跟踪和未发布的工作。显式恢复按[恢复流程](references/maintenance.md#restore-explicitly-or-synchronize-at-startup)先更新来源，不使用过时快照，然后验证 Git 处理方式和本地前置条件，报告未满足的要求。恢复到此结束，不生成配置、不执行完整 setup，也不发布。在恢复过程中决定将本地内容保存到备份，是另一项操作，须明确授权。

## 3. 在实际业务项目中编写并验证

编辑业务项目中实际维护的文件，不编辑备份条目的 `files/` 来起草改动。根据业务项目的证据决定配置内容和适用检查；备份布局不是项目架构的证据。编写或修订 Rule 或 Skill 时，以本地项目文件作为 Candidate，使用[编写 Rule 和 Skill](../write-rules-and-skills/SKILL.md)。

只要已知的本地范围已获授权，且工作不依赖上游决定，即使配置仓库无法访问或同步冲突尚未解决，也可在本地编写并验证。保留现有本地工作，不擅自推断备份范围，也不推翻已有的用户决定；依赖上游的步骤留待处理。两种本地模式均无需访问配置仓库。

如果需要本地生成，按[本地生成流程](references/maintenance.md#render-local-configuration-only-when-required)确认命令可以运行。先完成能独立运行的检查；必要的生成或检查受阻时，保留本地结果并报告缺少的验证，不导出。通过适用检查验证本地结果，包括实际发生的生成变更和 Git 处理方式；报告业务 Git 已跟踪的配置路径。两种本地模式到此结束，不调用 `apply`，也不发布到配置仓库。维护不等同于完整 setup；未满足的 setup 或迁移要求由用户显式调用所属 Skill 处理。

## 4. 备份明确选定且已验证的内容

仓库模式下，按共享参考中的[本地优先编写流程](references/maintenance.md#back-up-verified-local-authoring)导出本次操作的确切范围。审查所选文件的完整内容，避免把凭据、无关配置或本地同步记录纳入备份。保留采纳结果 JSON，供按精确范围发布使用。

确认整个备份范围一致，再记录一致状态。不要用恢复来消除剩余差异；如果存在上游漂移或无关本地改动，保留它们并报告阻碍。后续步骤失败时，分别报告已完成的本地改动和已保存的备份工作，不声称跨仓库回滚。

## 5. 发布经过验证的来源范围

已授权的仓库写入按[精确范围发布](references/maintenance.md#publish-an-exact-verified-scope)执行，用户要求仅保留本地结果时除外。保留的 JSON 涵盖完整已接受范围时，通过 `--plan` 传入。范围来自直接编辑或多个操作时，按参考对各路径分别使用 `--path`。保留无关的暂存项和工作区改动。失败时遵循参考中的提交 hook 处理和保留提交恢复流程。

完成要求来源已验证、目标一致、适用检查通过，且发布结果明确：已验证远端发布、用户显式要求本地结果，或本次操作无需发布。本地模式不需要配置仓库发布。

报告模式和来源、接受和保留的路径、验证与恢复、任何有意执行的生成、Git 排除和已跟踪配置，以及适用时的精确提交和已验证远端结果。未完成时，分别说明已保存来源、保留提交、已应用目标、未满足前提和剩余远端同步。
