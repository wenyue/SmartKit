# 编写决策

## 所有维护操作使用同一入口

日常维护、Setup、已启用的启动同步和 OpenWiki 共用同一个 Skill 入口，维护约定的修改因此能覆盖每个调用方。入口只执行所请求的操作。调用方负责自身的工作流程和操作权限，包括完整 Setup 先改配置仓库的顺序。将共用命令和相应决策放在这里，可以让各条路径遵循同一维护流程。

## 保留快照，不据此声称初始化成功

整文件备份有意直接复制原生配置和选定的初始化标记，不重新生成或转换字段。复制的标记或成功恢复，不能证明当前 checkout 执行过初始化或具备本地前提。区分恢复、有意执行的生成和完整初始化，才能使恢复既不改写已接受的字节，也不绕过必要初始化。

## 根据同步记录判断哪一侧发生变化

维护流程在来源指纹之外，还记录成功同步的范围，以便配置仓库更新后，将完整本地内容与基线比较。旧记录仍可读取，但不能证明仅配置仓库发生变化。双方都变时始终需要用户选择，从而避免单独分析包含关系或合并。把这项判断和受保护的写入放在一起，Setup 和启动同步就能使用同一份证据。已接受的范围和权限由调用方负责。来源与目标一致后更新同步记录。
