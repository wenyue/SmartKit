# 诊断 Agent 会话

针对一个确切的客户端/会话组合，使用足以回答问题的最少证据进行诊断。自有封装程序收集有边界的观测，Agent 将这些观测与任务联系起来，判断它们支持什么结论。高用量、长时间等待或采集失败本身都不能证明会话行为异常。

报告只包含元数据和派生观测。绝不复述提示词、回复、会话正文、工具输入、工具输出或凭证。这一边界同样适用于失败说明和成功取得的证据。

## 确定目标和有用的范围

一起确定客户端和会话。支持的客户端为 `codex`、`cursor` 和 `copilot`，其中 `copilot` 指 GitHub Copilot CLI。会话 ID 只能包含字母、数字、点、下划线、冒号和连字符。仅当两个显式参数都未提供时，`CODEX_THREAD_ID` 才可提供当前 Codex 身份。显式组合不完整或无效时，不能回退到这一环境身份；绝不选择最新日志或替换为方便取得的会话。

根据诊断问题选择 `turn`、`session` 或 `both`。问题跨越当前轮次与会话，或比较两者能解决重要的因果不确定性时，使用 `both`。请求没有提供缩小范围的依据时，使用 `both`。在已采集范围内，只分析对问题重要的能力，包括区分重要替代原因所需的能力。观测揭示新的重要不确定性时再扩展分析，而不是仅仅因为还有其他指标可用。

`turn` 指所选 Codex 会话不可变快照中最后记录的轮次：从最后一个用户消息边界直到最后一个事件。诊断当前进行中的会话时，它是记录下来的本次调用轮次；对于已结束会话，它是最后记录的轮次。接口不支持选择更早的历史轮次。

| 客户端 | 支持的采集 |
| --- | --- |
| Codex | `turn`、`session` 或 `both`，提供本地日志中的轮次与行为证据，并按请求提供 Tokscale 整个会话的证据。 |
| Cursor 或 GitHub Copilot CLI | Tokscale 整个会话的证据。`turn` 请求在采集前停止；`both` 采集会话证据并将轮次标为不支持。此封装程序没有集成这两种客户端的行为证据。 |

身份缺失、不完整或不受支持，会话 ID 无效，或请求其他历史轮次时，在采集前停止。说明确切前提，不改变请求的身份，也不把整个会话的证据当作轮次证据。

## 确定本次采集的权限

Codex 适配读取确切的本地会话日志。私有内容仅保留在本次尝试内，不进入报告。整个会话的用量、模型活动和估算费用来自已安装的 Tokscale 提供程序，其采集具有不同的效果边界。

每次请求会话证据的尝试之前，确认该安装有权：

- 扫描所选客户端在请求日期窗口内的记录；无法确定可靠边界时，扫描其可用本地历史，以选出确切会话并读取既有 Tokscale 身份状态。
- 访问已安装构建使用的价格或提供程序端点。
- 仅读写该构建在当前主机上解析出的 Tokscale 自有配置和缓存目录。

上一次诊断的授权不是持续授权。封装程序不执行登录、同步、凭证变更、安装、遥测配置或修复。缺少认证或先前遥测是独立的前提问题；在受影响的重跑或任何补齐前提的工作之前，取得单独授权。

Cursor 可能依赖既有有效的 Tokscale Cursor 身份，以及先前完成且单独获授权的同步。Copilot CLI 可能依赖活动发生前已配置的 OTEL 文件导出；从未记录的遥测无法重建。这些是可能的来源前提，不能从空结果推断它们就是诊断原因。仅仅缺少匹配行，既不能证明缺少同步，也不能证明缺少 OTEL 历史。

## 采集一次并保留各来源的边界

将已加载 `SKILL.md` 所在目录解析为 `<skill-root>`。可以不采集会话证据而查看 CLI：

```text
python "<skill-root>/scripts/timing.py" diagnose --help
```

生成 32 个新的随机字节，编码为恰好 64 个小写十六进制字符。将此采集 ID 连同选定范围和身份传给自有封装程序一次：

```text
python "<skill-root>/scripts/timing.py" diagnose --scope both --client "<client>" --session-id "<id>" --acquisition-id "<64-lowercase-hex>"
```

若选定范围更窄，将 `both` 替换为该范围。Codex 适配使用这个确切 ID 在工具调用记录中识别当前采集。恰好匹配一次时，只排除该次调用。零次匹配不排除任何内容，并报告未观测到采集调用。多次匹配不排除任何内容，并报告自身调用归因失败且有歧义。历史 ID，以及无关或已完成的诊断调用，仍然是证据。

### Codex 观测

适配先复制确切的本地日志，再记录截止点，此后只读取不可变副本。保留该来源的时间区间和采集状态。对于轮次证据，标明会话及实际轮次起止边界。本地适配提供轮次用量，以及工具、子 Agent 和等待观测。Tokscale 整个会话证据缺失或失败时，封装程序也可以保留有支持依据的 Codex token 总量；这既不补齐缺失的模型或费用证据，也不抹去提供程序失败。

### Tokscale 观测

记录解析出的 Tokscale 可执行文件路径和版本、提供程序起止时间、支持的效果契约，以及已验证的 JSON schema。接受确切组合对应的客户端/会话/模型分组行。只有 Codex 可以使用单一的 `rollout-{session-id}` 别名；精确行与别名行同时出现会造成歧义，归因失败。schema 不兼容属于提供程序失败，不能据此猜测版本。提供程序 stdout 和 stderr 始终不披露。

Codex 与 Tokscale 的采集不构成原子快照。即使封装程序将它们呈现在同一报告中，也要区分其不可变观测、时间区间、效果和失败。来源不可用或失败时，保留有支持依据的部分证据，不尝试其他遥测命令。如果封装程序本身无法运行，报告失败步骤和确切缺失的能力；不要自行构造等效采集路线。

## 判断证据能够回答什么

对每项选定能力，使用恰好一个封装程序状态，并给出针对其来源的原因：

| 状态 | 含义 |
| --- | --- |
| `available` | 指定来源和 schema 提供可用证据。 |
| `unavailable` | 本次尝试没有受支持的来源或兼容证据。 |
| `failed` | 已尝试获授权的采集或验证，但失败了。 |

暴露的能力覆盖会话用量、整个会话的模型活动和费用、当前轮次用量、当前轮次模型活动和费用、工具调用、未完成调用、子 Agent 生命周期、Agent 协调及等待。按诊断问题及其重要因果依赖选择能力。每项选定行为能力都标明 `turn` 或 `session` 身份；在 `both` 范围内，两者都重要时保留独立记录。

此包没有自有的按轮次限定的模型活动或费用提供程序。其中任一能力重要时，说明这一不支持的限制。除非未来已接受的契约提供自有来源及调用路径，否则重跑也无法补齐它。

对每项选定能力，分别保留事实、推断、不确定性以及不可用或失败的覆盖。一个来源失败时，另一个来源或不受影响的能力仍可能提供有用观测。对于非关键缺口，将分析收窄到有支持依据的证据，并说明仍未检验的内容。不要仅为统一报告而扩大采集或宣告所有能力失败。

### 解释行为，不虚构事件

生命周期、协调和等待回答不同问题。Codex `sub_agent_activity` 只确立其文档定义的 `started`、`interacted` 和 `interrupted` 观测。`interacted` 既不证明完成，也不证明等待。协调调用/输出记录可以确立观测到的任务状态；只有 `wait_agent` 调用/输出记录才能确立等待。未知生命周期类型只使该能力失败。工具输出封装可以证明失败，但其私有内容不得进入报告。

未完成调用是在捕获证据中有受支持的开始记录，却没有匹配完成记录的调用。它并不自动意味着卡住。等待、超时、重复调用和未完成调用，都需要任务上下文才能支持原因判断。时长求和可能与实际经过时间重叠，生命周期计数是观测下界，子会话 token 在归因前需要稳定的子会话映射。

将可靠观测与任务和适用并发限制比较。对当前轮次的直接了解可以作为明确标示的推断用于解释。token、调用、费用和时长总量是描述性信息，没有固定的异常阈值。每个金额都标为 `estimated API-equivalent cost`，绝不当作账单。

## 得出一个有边界的结论

在证据支持的最窄范围内，恰好选择一个结论：

| 结论 | 所需依据 |
| --- | --- |
| **观测到异常证据** | 可靠证据确立异常；将判断限制在已证明的范围内。 |
| **未观测到异常** | 对所述结论重要的每项能力都充分可用，且没有异常信号。 |
| **无法确定** | 缺失、失败或冲突的证据使请求的诊断仍存在重要不确定性。 |

整个会话的用量本身不能证明行为健康。缺少行为证据不能支持行为健康的结论。同样，在与任务相关的观测足以支持对会话本身的判断之前，采集超时只是关于采集的证据。

## 交接诊断和必要恢复

返回一份结构化报告，开头说明客户端/会话身份、请求范围和选定范围、实际边界、Harness 适配，以及每个已用来源的时间区间和效果契约。然后给出选定能力及其范围/状态/原因、相关用量与估算 API 等价费用、重要观测和因果推断、不确定性或失败证据，以及恰好一个结论和限制该结论的未检验面。尝试过提供程序，或其身份影响解释或恢复时，包含解析出的可执行文件及版本。

只从封装程序实际尝试过的请求来源，以及观测到的失败或缺失前提，推导可执行的恢复前提。不支持、未请求或非关键能力不产生提供程序恢复行动。例如，观测到的提供程序执行/schema 失败涉及该安装的提供程序；它不证明需要登录、同步或配置遥测。任何获授权重跑都保留确切的客户端/会话组合和来源边界。

每个事实只在有助于读者判断后续行动的位置说明一次，不要把它重复列为问题、限制和恢复步骤。封装程序执行前停止或封装程序失败时，仍在证据允许的范围内使用这一结构，标明缺失前提和失败步骤。

当身份和范围明确、每项选定能力有一个状态、可靠部分证据得到保留、来源边界各自独立、不含私有内容，且结论遵守覆盖条件而不暗示已检查未检验行为时，诊断才算完成。
