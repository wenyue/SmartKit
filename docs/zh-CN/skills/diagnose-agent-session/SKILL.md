# 诊断 Agent 会话

在 `turn`、`session` 或 `both` 范围内诊断一个已识别的 Agent 会话。所属包装器收集有界事实；Agent 将事实与任务关联并得出结论。

## 原则

- **先确认身份，再收集证据。**只分析一个确切的客户端与会话组合。绝不根据时间新近程度推断目标，也不替换为更方便的会话。
- **最小充分范围与分析。**只获取所需范围。基于这些证据，仅解释和报告重要能力；只有当观察结果暴露出另一个重要备选原因时，才扩大分析。
- **明确来源边界。**分别保留每个来源的时间区间、效果、覆盖范围和失败状态。Codex 与 Tokscale 的两次获取不构成原子快照。
- **先观察，后推断。**保留部分证据，并区分观察事实、依赖任务的解释、不确定性，以及不可用或失败的覆盖。
- **从设计上保护隐私。**只报告元数据和派生观察结果，绝不报告提示、响应、对话内容、工具输入、工具输出或凭据。

## 1. 固定身份与范围

解析一个客户端与会话组合。受支持的客户端标识符为 `codex`、`cursor` 和 `copilot`；`copilot` 指 GitHub Copilot CLI。会话 ID 只能包含字母、数字、点、下划线、冒号和连字符。只有两个显式参数都不存在时，`CODEX_THREAD_ID` 才提供当前 Codex 身份；绝不选择最新日志，也不以其他方式根据时间新近程度推断身份。

`turn` 指不可变 Codex 快照中最后记录的一轮，从最新用户消息边界到最后一项事件。对于进行中的会话，它是调用本 Skill 的当前轮；对于已完成会话，它是会话最后记录的一轮。此接口不能选择其他历史轮次。

选择足以满足请求的最小范围。只有当诊断同时涉及当前轮和整个会话，或对比两者能解决重要的因果不确定性时，才使用 `both`。如果请求没有提供选择更窄范围的依据，使用 `both`。

Codex 支持 `turn`、`session` 和 `both`。Cursor 和 GitHub Copilot CLI 仅支持整个会话的 Tokscale 证据。若 Cursor 或 Copilot 请求 `turn`，在获取前停止。对于 `both`，获取请求的会话证据，并将轮次证据标记为不受支持；绝不把会话证据呈现为轮次证据。

若客户端与会话组合缺失或不完整、客户端或 ID 不受支持、请求了其他历史轮次，或平台没有受支持启动器，也要在获取前停止。报告确切前置条件，不改变身份或范围。

## 2. 授权数据来源

Codex profile 会读取确切的本地会话日志。它只为本次尝试保留内容，不报告私密内容。

整个会话的用量和模型证据来自已安装的 Tokscale 提供方。每次尝试请求 `session` 证据前，确认该安装已获授权执行以下操作：

- 扫描请求日期窗口内所选客户端的记录——若不存在可靠边界，则扫描其可用本地历史——以选择确切会话并读取既有 Tokscale 身份状态；
- 访问该已安装版本使用的定价或提供方端点；
- 只读取或写入该版本在当前主机上解析出的 Tokscale 自有配置和缓存目录。

包装器不执行登录、同步、凭据变更、安装、遥测配置或补救。若缺少身份验证或既有遥测，报告前置条件，并在任何受影响的重跑前另行取得授权。以前的诊断授权不是持续权限。

## 3. 获取不可变证据

将包含已安装 `SKILL.md` 的目录解析为 `skill_root`。生成 32 个新的随机字节，并编码为恰好 64 个小写十六进制字符。将该获取 ID 只传给所属包装器一次。Codex profile 仅在工具调用记录中匹配这个确切 ID：恰好一次匹配时，只排除该次调用。零次匹配时不排除任何调用，并报告未观察到当前获取调用。多次匹配时不排除任何调用，并报告自身调用归因失败且存在歧义。历史 ID 以及无关或已完成的诊断调用仍属于证据。

在 Linux 上使用 `sh`：

```sh
skill_root='<absolute directory containing the installed SKILL.md>'
sh "$skill_root/scripts/task-metrics.sh" diagnose --scope both --client <client> --session-id <id> --acquisition-id <64-lowercase-hex>
```

在 Windows 上使用 PowerShell：

```powershell
$skillRoot = '<absolute directory containing the installed SKILL.md>'
$wrapper = Join-Path $skillRoot 'scripts\task-metrics.ps1'
powershell -ExecutionPolicy Bypass -File $wrapper diagnose --scope both --client <client> --session-id <id> --acquisition-id <64-lowercase-hex>
```

将 `both` 替换为选定的更窄范围。启动器只先检查 `python3`，再检查 `python`，并使用第一个报告 Python 3.10 或更高版本的可执行文件。若两者均不合格，保留指出 Python 3.10+ 和检查顺序的启动器错误。当某个表面不可用或失败时，保留其部分证据，不尝试其他遥测命令。

### Codex 来源

profile 在记录该来源的截止点前复制确切本地日志，随后只读取不可变副本。对于 `turn`，报告会标明选定会话及其轮次起止边界。Codex 还提供工具、子 Agent 和等待证据。

### Tokscale 来源

提供方给出整个会话的用量和模型活动。记录解析出的 Tokscale 可执行文件路径和版本、提供方起止时间、受支持效果契约，以及经过验证的 JSON schema。接受确切客户端与会话组合的按客户端、会话和模型分组记录。只有 Codex 还能使用单个 `rollout-{session-id}` 别名；确切记录与别名记录同时存在时具有歧义并判为失败。不兼容的 schema 属于提供方失败，不是猜测版本的理由。提供方的 stdout 和 stderr 不予披露。两个来源的时间区间彼此独立，不构成原子快照。

Cursor 可能需要既有且有效的 Tokscale Cursor 身份，以及此前已经完成并另行授权的同步。GitHub Copilot CLI 可能要求在活动发生前配置 OTEL 文件导出；缺失的历史遥测无法重建。此包装器没有 Cursor 和 Copilot 的行为集成。

## 4. 先解释覆盖范围，再解释数值

选择诊断所需的每项重要能力，包括区分重要备选原因所需的任何辅助能力。只有当观察结果暴露出新的重要不确定性时，才扩大选择。为每项选定能力赋予恰好一种包装器状态：

- `available`：指定来源和 schema 包含可用证据；
- `unavailable`：本次尝试不存在受支持来源或兼容证据；
- `failed`：已尝试获准的获取或验证，但失败。

包装器暴露会话用量、整个会话的模型活动、当前轮用量、当前轮模型活动和成本、工具调用、未完成调用、子 Agent 生命周期、Agent 协作和等待。选择与请求相关的表面及其重要因果依赖，而不是仅因表面存在就全部选择。为每项选定的行为能力标明其 `turn` 或 `session` 身份；在 `both` 范围下，如果两者都重要，应保留独立记录。

将生命周期、协作和等待分开。Codex `sub_agent_activity` 记录只能证明其记载的 `started`、`interacted` 和 `interrupted` 观察结果。`interacted` 既不证明完成，也不证明等待。协作调用可以证明观察到的任务状态，但只有 `wait_agent` 调用和输出记录才能证明等待。未知的生命周期类型只会使该表面失败。工具输出封装可以证明工具失败，但其中内容不得进入报告。

本包没有所属的轮次范围模型活动或成本提供方。若选择其中任一能力，将其报告为不受支持的限制；除非未来已接受契约提供所属来源和调用路径，否则不要自行发明重跑前置条件。

在每个选定表面上，始终明显区分事实、推断、不确定性、不可用证据和获取失败。未完成调用是受支持的开始事件在捕获证据中没有对应的完成事件。等待、超时、重复和未完成调用必须结合任务上下文，才能支持因果判断。持续时间可能与经过时间重叠，生命周期计数是观察下限，子会话 token 需要稳定的子项映射。若缺少非关键证据，将分析缩小到受支持表面，并指出尚未测试的内容；不要扩大获取，也不要将缺口变成全局失败。

将每个金额都表述为 `estimated API-equivalent cost`，绝不表述为账单。

## 5. 得出一个结论

将可靠观察结果与请求任务及适用并发限制进行对比。对当前轮的直接了解只能作为明确标注的推断来辅助解释。token、调用、成本和时长只是描述性数据；它们都没有固定的异常阈值。

在证据支持的最窄范围内，选择恰好一个结论：

- **观察到异常证据**：存在可靠异常证据，结论限定在其范围内。
- **未观察到异常**：只有当所述结论所需的每项重要能力均足够可用，且不存在异常信号时才能得出。
- **无法确定**：缺失、失败或冲突的证据使请求诊断仍存在重要不确定性。

仅有会话用量覆盖不能证明行为健康。缺少行为证据时，不能得出健康结论。

## 6. 交接诊断结果

返回一份结构化报告。开头列出会话身份、请求和选定范围、范围边界、harness profile，以及每个已使用来源的时间区间和效果契约。随后只包含诊断所需内容：

- 每项选定能力的范围、状态和原因；
- 相关用量和预估 API 等价成本；
- 重要观察结果、问题、缺失或失败的证据、不确定性和因果推断；
- 恰好一个结论，以及限制该结论的未测试表面；
- 可操作的恢复前置条件。

尝试过 Tokscale 提供方，或者其身份会影响解释或恢复时，包含解析出的 Tokscale 可执行文件和版本。恢复只能从包装器已经尝试的请求来源中推导。不受支持、未请求或非关键的表面不会产生提供方恢复操作。每项事实只陈述一次，不要将它重复写成问题、限制和恢复步骤。

对于包装器运行前停止或包装器失败，在证据允许的范围内保留此结构，并指出缺失的前置条件和失败步骤。只有在身份和范围明确、每项选定能力都有一种状态、可靠部分证据得到保留、来源边界保持独立、没有复现私密内容，并且结论遵守覆盖规则且不暗示覆盖未测试表面时，诊断才算完成。
