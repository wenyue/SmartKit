# 诊断智能体会话

诊断一个身份明确的智能体会话，范围可以是 `turn`、`session` 或 `both`。自带的包装器负责采集事实；智能体负责提供任务上下文并得出结论。

## 固定身份和范围

解析出唯一的一组客户端与会话。受支持的客户端标识符为 `codex`、`cursor` 和 `copilot`，其中 `copilot` 指 GitHub Copilot CLI。会话 ID 只能包含字母、数字、句点、下划线、冒号和连字符。只有当两个显式参数都未提供时，`CODEX_THREAD_ID` 才能提供当前 Codex 身份。绝不能根据时间新近程度推断身份，也绝不能选择最新日志。

`turn` 指不可变 Codex 快照中最后一个已记录轮次：从最后一个用户消息边界开始，到快照的最后一个事件为止。对于仍在进行的会话，它就是调用本 Skill 的轮次；对于已结束的会话，它是该会话最后一个已记录轮次。此接口不能选择其他历史轮次。如果用户要求其他历史轮次，应在采集前停止。

除非用户明确要求 `turn` 或 `session`，否则使用 `both`。如果这组客户端与会话不完整或缺失、客户端或 ID 不受支持，或者当前平台没有受支持的启动器，应在采集前停止。报告确切的前提条件，不得改用其他会话或范围。

Codex 支持全部三种范围。Cursor 和 GitHub Copilot CLI 只支持整个会话的 Tokscale 证据：如果只请求 `turn`，应在采集前停止。对于 `both`，采集请求的整个会话证据，并将轮次范围报告为不受支持；不得把会话证据说成轮次证据。

## 授权证据来源

Codex profile 会读取精确匹配的本地会话日志。它只在本次尝试期间持有内容，并且不会报告任何 prompt、response、转录内容、工具输入、工具输出或凭据内容。

整个会话的用量和模型证据来自已安装的 Tokscale provider。每次尝试请求 `session` 证据前，都要确认已授权 Tokscale 执行以下操作：

- 扫描所选客户端在请求日期窗口内的会话记录——如果不存在可靠边界，则扫描其可用的本地历史——以选出精确会话，并读取现有的 Tokscale 身份状态；
- 访问该已安装版本使用的定价或 provider endpoints；以及
- 只读写该版本在当前主机上解析出的 Tokscale 自有配置与缓存目录。

包装器不会执行登录、同步、凭据变更、安装、遥测配置或补救命令。如果缺少必需的身份验证或先前遥测，应报告该前提条件。再次运行受影响的步骤前须另行获得授权；不得把先前的诊断授权当作持续有效的授权。

## 采集请求的证据

将包含当前已安装 `SKILL.md` 的目录解析为 `skill_root`。选择 32 个新的随机字节，并将其编码为恰好 64 个小写十六进制字符，作为本次尝试的 acquisition ID；然后只执行一次自带包装器。Codex profile 只检查与该 ID 精确匹配的工具调用记录。恰好有一条匹配时，只排除该调用。没有匹配时，不排除任何内容，并报告未观察到当前采集调用。出现多条匹配时，不排除任何内容，并报告自身调用归属失败且存在歧义。历史 acquisition ID，以及无关或已完成的诊断调用，仍然属于证据。

使用 `sh` 的 Linux：

```sh
skill_root='<absolute directory containing the installed SKILL.md>'
sh "$skill_root/scripts/task-metrics.sh" diagnose --scope both --client <client> --session-id <id> --acquisition-id <64-lowercase-hex>
```

使用 PowerShell 的 Windows：

```powershell
$skillRoot = '<absolute directory containing the installed SKILL.md>'
$wrapper = Join-Path $skillRoot 'scripts\task-metrics.ps1'
powershell -ExecutionPolicy Bypass -File $wrapper diagnose --scope both --client <client> --session-id <id> --acquisition-id <64-lowercase-hex>
```

只有在明确选择了其他范围时才替换 `both`。启动器会解析 Python 3.10 或更高版本；如果找不到，应保留它们给出的错误。某个表面失败或不可用时，应保留部分证据，而不是尝试其他遥测命令。

Codex profile 会先复制精确匹配的本地日志，再记录该来源的截止时间，并且只评估这份不可变副本。报告会说明所选会话与轮次的起止边界。对于 `session` 证据，包装器还会分别记录解析出的 Tokscale 可执行文件路径与版本、provider 起止时间、受支持的效果契约，以及已验证的 JSON schema。它接受精确匹配该组客户端与会话的、按客户端/会话/模型分组的数据行；只有 Codex 还接受唯一的 `rollout-{session-id}` 别名。Codex 的精确行与别名行同时存在时，属于歧义失败。Schema 不兼容表示 provider 失败，而不是版本推测。Provider 的 stdout 和 stderr 不得披露。两个来源的时间区间相互独立，并不构成原子快照。

Tokscale 提供整个会话的用量和模型活动。Cursor 可能要求已有有效的 Tokscale Cursor 身份，以及此前已经单独授权并完成的同步。GitHub Copilot CLI 可能要求在活动发生前已配置 OTEL 文件导出；缺失的过去遥测无法重建。Codex 本地 profile 还提供当前轮次、工具、子智能体和等待证据。Cursor 与 Copilot 在此包装器中没有对应的行为集成。

## 先解读覆盖情况，再解读数值

保留包装器为每项请求能力报告的状态：

- `available`：指定来源与 schema 包含可用证据；
- `unavailable`：本次尝试没有受支持的来源或兼容证据；
- `failed`：已经尝试授权的采集或验证，但发生失败。

根据所选范围，覆盖会话用量、整个会话的模型活动、当前轮次用量、当前轮次模型活动与成本、工具调用、未完成调用、子智能体生命周期、智能体协作和等待。每项行为能力都要标明其 `turn` 或 `session` 身份；对于 `both`，分别报告两条记录，不得合并它们的状态。最后三项行为表面必须彼此分开。Codex `sub_agent_activity` 记录只能证明其文档定义的 `started`、`interacted` 和 `interrupted` 观察。`interacted` 事件既不能证明完成，也不能证明等待。协作调用可以证明观察到的任务状态；只有 `wait_agent` 调用及其输出记录才能证明等待。未知的生命周期类型只会使生命周期表面失败。工具输出 envelope 可以证明工具失败，但其内容绝不能出现在报告中。

本包没有自有的、限定到轮次的模型活动或成本 provider。应将这两项当前轮次能力报告为不受支持的局限。除非未来接受的契约增加了具体的自有来源和调用路径，否则不得给出重新运行的前提条件。

明确区分观察、推断、不确定性、不可用证据和采集失败。未完成调用是指在已捕获证据中，某个受支持的开始事件缺少匹配的完成事件。等待、超时、重复与未完成调用都需要任务上下文，才能支持原因判断。时长可能与经过时间重叠，生命周期计数是观察到的下界；只有存在稳定的子会话映射时，才能归属子会话 Token。

所有货币数值都必须称为 `estimated API-equivalent cost`，绝不能说成账单。不得持久化或复述 prompt、response、转录内容、工具输入、工具输出或凭据。

## 根据覆盖情况得出结论

将可靠观察与请求的任务及适用的并发限制进行比较。对当前轮次的直接了解只能用于解释证据，并且必须明确标记为推断。Token、调用、成本和时长仅用于描述，没有固定的异常阈值。

必须且只能选择一种结论：

- 有可靠的异常证据时，选择**Abnormal evidence observed（已观察到异常证据）**，并将结论限定在该证据能够证明的范围内。
- 只有当请求涉及的每项相关能力都充分可用，并且没有异常信号时，才选择**No abnormality observed（未观察到异常）**。
- 其他情况均选择**Inconclusive（无法确定）**。

仅有会话用量覆盖不能证明行为健康；缺少行为证据也不能支持健康结论。

## 交接

按以下顺序返回一份报告：身份和请求范围；所选范围的边界；harness profile，以及每个来源的观察区间、解析出的 provider 可执行文件与版本和效果契约；能力覆盖情况及证据或原因；请求范围内的用量和估算 API 等价成本；轮次、模型、工具、未完成调用、生命周期、协作和等待观察；已观察到的问题；不可用证据；采集失败；不确定性；因果解释；恰好一个结论；局限；恢复前提，以及每项前提是否需要另行授权后重新运行，或是否无法恢复过去证据。恢复措施只能从包装器实际尝试过的请求来源推导；不受支持或未请求的范围不能产生 provider 恢复操作。Provider 事实只陈述一次；不得把同一项能力原因重复复制到问题、局限和恢复章节。

如果在运行包装器前停止或包装器失败，应在证据允许的范围内保留上述结构，并指出缺失的前提和失败步骤。只有当身份和范围均已明确、请求的每项能力都有一个状态、可靠的部分证据均已保留、各来源边界保持区分、没有复述转录内容，并且结论符合覆盖规则时，诊断才算完成。
