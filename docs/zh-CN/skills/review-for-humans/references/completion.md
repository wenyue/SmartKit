# 完成操作

准备或提供完成效果、执行或恢复未完成效果前阅读。技能入口负责普通沟通、分组选择及修复复审；这里负责具体提交、发布、Viewed 准备及其对应的同意或恢复决定。

## 区分三个范围

| 范围 | 覆盖 |
| --- | --- |
| 审查与进度 | 已展示并评估的所选符合条件差异。 |
| 提交与发布 | 经检查及纳入同意后的全部分支待提交状态和全部待发布祖先链。 |
| Viewed | 特定已验证版本的整文件 PR 差异：当前已展示组及明确纳入的先前组；最终通过覆盖全部已展示审查组。 |

提交或推送不是审查。本地或分支完成不产生 PR 或推送权限。PR 发布要求已验证 PR 和对所说明差异的授权，不包含批准或合并。

PR 没有尚未发布的审查工作或未完成的已选提交发布操作时，可以不提交推送而记录 Viewed。只读确认无关本地差异，包括子模块检出差异，不影响固定差异、依赖和整文件覆盖。保留它们，其存在本身不要求发布或纳入同意。审查修复或优化必须先到达已验证 PR 版本，再记录 Viewed。

## 准备完整操作

提交或推送前确定准确仓库、工作树和分支，清点已暂存、未暂存、未跟踪内容；涉及发布时，还清点每个待发布提交。保留分支顶端、原始暂存区、工作树及适用未跟踪恢复证据。提交包括整个分支待提交状态：测试、生成及支持文件、仅已暂存和未展示或被排除文件。明确解决敏感、忽略或临时文件的纳入限制，不悄悄缩小提交。内容冲突阻止完成。

部分暂存时，确定一致的最终工作树内容，说明取代的暂存内容，并保留原始暂存区。根据对话操作和基准确定来源，包括混合来源改动块。说明其他或未知来源的路径、提交、行为及实质效果，并取得明确纳入确认。已有同意适用于相同内容效果，分组认可不涵盖未披露额外内容。没有同意时保留内容及整分支范围，不自动缩小提交、挑选提交、改写历史或发布。

本次对话产生的额外内容需要清点检查，但不需要额外来源同意。检查完整拟提交发布范围，评估已展示审查的有效性，完成受影响部分的专门复审，包括每个选定 O 修复。纳入同意不替代检查或审查。

PR 操作前验证所属及源仓库、源分支远端、查看者、base/head，以及可用写入和回读接口。将发布的完整待发布祖先链与差异同 Viewed 分开说明。除下述已记录的 amend 路线外，使用普通推送；完成不授权变基或排除提交。

将每条选定 Viewed 路径的完整拟发布 PR 差异与已展示评估比较。专门回复中复审每个未覆盖改动块并给出两个判断，即使是已同意的独立额外内容。保留编号、分组和进度，O 复审不产生主资格。缺少覆盖、证据或范围时，路径不标记，完成保持待处理，不能靠丢弃选定路径结束。早先改动块未变、检查通过和纳入同意都不能补足覆盖。

请求决定前完成可推导的只读准备。说明实际剩余写入、完整提交发布内容、Viewed 集合、纳入问题、检查限制及可复用的已验证效果。额外分支检查只有影响审查时才阻止继续。不需要空提交或无必要推送。

## 说明实际选择

提供普通通过选项前，将确切剩余效果交给入口的分组菜单：提交哪些分支内容，是否推送及推送到哪里，哪些文件标为已查看，以及之后展示下一组还是结束。已完成效果省略，不把必要写入藏在“通过”二字里。

额外内容同意尚未决定且其他前提均就绪时，使用 A **继续** （推荐），末组改为 **结束** ：不提交、发布或记录，直接推进结束；B **通过** ：明确确认指定额外内容，并执行完整已披露完成操作；仅有可选建议时增加 C **优化** 。先说明额外路径提交和具体影响。拒绝纳入后不悄悄重复询问，保留内容及整分支范围，审查有效时允许继续，仅通过新的明确请求调整完成目标。

缺少用户事实时直接问。可执行检查，以及范围内的专门审查，直接完成，不再加一轮选择。固定改动已可用且在授权审查范围内时，整文件覆盖缺口不是权限问题。

## 执行并验证

使用受支持 PR 操作前阅读[完成助手](completion-helper.md)及其帮助。助手负责机械性的冻结、执行、恢复和日志，Agent 负责审查、成功检查、来源同意、覆盖及授权。支持的准备可保留私有证据或 Git 对象，同时保持真实暂存区、分支和文件不变。助手不可用不免除任何前提。

本地分支完成或助手不支持的情况，使用以下手动流程。它也规定助手结果必须满足的要求，不是助手之后还需重复执行的另一套实现。

1. 重新验证证据、顶端、暂存区、工作树和受影响依赖；涉及发布时，还验证相关 PR base/head 和待发布祖先链。变化需要清点、检查、受影响复审，以及对变化效果重新确认额外内容。预期新 head 需要版本和内容验证，不重复已覆盖审查；文本相同不自动证明效果相同。
2. 需要提交时，暂存全部已披露最终内容并核验预期文件树。记录证明 HEAD 是本次审查修复或优化提交，且当前分支与任何推送目标都不是 `master` 或 `main` 时，使用 `git commit --amend`；否则新建提交。运行正常钩子，验证提交、父提交、完整文件树、暂存区和剩余工作树。钩子改动需要检查复审，超出同意的效果需要更新同意。不留下无法解释的残余。本地或分支完成此时可推进或结束；步骤 3–4 仅适用于 PR 完成。
3. PR 发布已获授权且需要时，钩子之后重新验证待发布祖先链。替换已发布审查提交时，对已验证源引用使用 `--force-with-lease=<ref>:<verified-old-remote-SHA>`；否则普通推送。变化或拒绝时停止。回读 base/head 和完整已发布差异，确认预期提交、检查过的内容及有效评估。
4. 记录 PR Viewed 时，在实际 PR 版本验证查看者、两个提交 ID 和选定集合的整文件覆盖。仅标记符合条件且仍待记录的路径。回读所有选定路径，包括复用标记，以及 base/head。全部路径必须为 `VIEWED`，记录期间 base/head 不变。
5. 全部选定效果和回读成功后，确认结果并从保存位置推进或结束。最终完成覆盖全部已展示组，包括此前未记录而直接推进的组。

## 恢复选定操作，不重启对话

写入、接口或验证失败时，保留已确认、失败和未知效果：提交、推送状态、部分暂存、剩余文件及 Viewed 路径。不推进，不自动回滚，也不替换为继续或结束。

保留清单、来源决定、固定证据、发布与 Viewed 集合、查看者版本、分组状态、恢复状态和下一位置。中断或丢失响应后，先检查实际本地远端状态再重试。复用已验证效果，就绪后恢复缺失步骤。新事实可能要求检查复审或变化效果的同意，不要求重做成功写入，也不允许静默缩小范围。

全部必要回读必须成功。未变的已授权效果就绪后，无需再询问通过，直接恢复缺失步骤。访问或回读因外部原因不可用、用户没有可执行补救时，报告已完成、未知和待处理效果，保留操作。不提供等待或补足选择，不承诺监控，也不开始轮询。稍后在支持的机会检查实际状态，仅按原授权恢复缺失效果。

缺少用户事实时直接问。已验证的变化效果需要新同意时，说明调整范围，提供 A **停止** （推荐）：报告残余效果并停止；B **通过** ：明确批准调整效果并恢复同一操作。新的审查发现使用入口的必要问题选择，同时保留待完成操作；继续或结束不能绕过它。不从旧选择推断额外内容、检查、覆盖或权限。

明确停止时，将残余工作报告为未完成。保留进度，不重新筛选以移除已展示文件。
