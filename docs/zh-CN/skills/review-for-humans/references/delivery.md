# 交付

准备或提供交付、执行或恢复其效果前阅读。本指南负责完整交付范围、审查覆盖、就绪条件、写入、回读和实际恢复。技能入口负责动作选择、待完成的用户意图和推进；将交付事实返回该循环。

## 定义选定工作区的交付

交付完成选定且已披露审查工作区中全部待处理改动的适用效果，不论由谁或在哪次对话中产生。“当前工作区”指该确切路径，不是 Agent 进程碰巧所在的工作目录。

| 审查上下文 | 按顺序适用的效果 |
| --- | --- |
| PR | 提交工作区全部待处理改动，向已验证 PR 源发布完整待推送范围，再将本次对话已审查且符合条件的所有文件记录为 Viewed，并验证结果。 |
| 本地或分支 | 提交工作区全部待处理改动。只有用户选择了已披露的发布目标和效果时才推送；没有 PR 就不记录 Viewed。不隐式创建 PR。 |

复用已完成且仍有效的效果。干净工作区无需空提交；源引用已是最新时无需重复推送。只有不再需要提交或发布效果时，才能仅记录 Viewed；不能借此把无关的工作区待处理改动排除在选定交付之外。快照审查必须先选择可交付工作区，才能承诺本地或发布效果。

选择交付覆盖全部已披露工作区和待发布范围，包括其他对话产生的改动。来源不同需要清点和适用审查，不需要单独询问是否纳入。明确的用户排除项或冲突的保留要求，必须在交付前解决；不悄悄缩小提交。交付不授予无关历史变更、PR 审批或合并权限。

## 区分范围和审查覆盖

| 范围 | 所需覆盖 |
| --- | --- |
| 主审查及进度 | 为普通文件分组选定的固定比较及筛选。 |
| 提交和发布 | 清点和必要检查覆盖每项实际提交差异及待推送提交，包括测试、文档、生成或支持文件、仅已暂存改动、未被忽略的未跟踪文件，以及主比较之外的工作。语义审查覆盖其中全部非测试改动。 |
| Viewed | 本次对话已审查其完整预期 PR 差异的每个当前 PR 文件，包括此前未记录就推进的分组及补审内容。 |

任何交付写入前，确定本次对话已审查完整拟议提交和发布范围内的每项非测试改动。普通主审查及交付补审均排除测试文件，沿用相同的仓库或主审查分类。生产文件不会仅因被测试使用就变成测试文件。测试仍属于完整提交或发布清单及必要检查。先前的修复或优化可能已经覆盖；作者身份、测试通过、文件名出现在报告中、其他对话的审查，都不能证明覆盖完整。只有确切内容、依赖和效果仍有效时才复用判断。amend 后的提交也需要覆盖其保留的非测试内容。已有未发布提交属于发布覆盖范围；目标处已有的未变内容，不因它是祖先就算再次新发布。

对每项未覆盖的非测试改动，应用入口的完整检查标准，包括必要的文件及关联上下文。报告补审前，阅读[报告格式](report-format.md)，并使用其固定呈现方式。提供固定前后证据和链接，与未见的主审查分组分开。受影响条目复用现有编号，新补审修改项分配连续的新 M 编号，并明确区别于主进度。精简或省略说明绝不证明未审查改动已经覆盖。其他被排除的非测试文件仍接受这项审查，测试文件不接受。补审覆盖不改变主文件总数，不推进保存的位置，也不通过刷新 Viewed 筛选移除未见文件。

补审是必要准备。写入前，将新发现和证据缺口返回入口，由其待完成请求规则决定后续选择与恢复。明确保留的判断继续记录。

测试通过或测试文件被提交，不会让这些未审查文件获得 Viewed 资格。已审查修复片段不等于完整 PR 文件覆盖。根据完整逐文件 PR 差异及本次对话判断建立 Viewed 集合。拟记录文件有未覆盖部分时补审；其他只审查部分内容的文件不标记，并说明区别。预期集合固定后，缺失检查或回读失败意味着交付未完成；绝不为宣称完成而删去选定路径。O 类观察本身不提供整文件覆盖，但其修复文件在完整补审后可以符合条件。

## 准备确切效果

确定仓库、选定工作区、分支、预期最终内容，发布时还要确定全部待推送祖先链。清点已暂存、未暂存、未跟踪、冲突及子模块状态。保留原始暂存区、顶端提交、工作树及适用的未跟踪恢复证据。部分暂存时，确定连贯的最终工作树内容，并披露将替换哪个暂存版本。按各自约束处理被忽略、敏感、临时或独立归属内容，不自动添加，也不静默排除。冲突阻止交付。

对完整预期提交或发布运行必要检查，并建立上述审查覆盖。报告就绪前，完成可推导的只读准备和可用补审。未知清单、接口或覆盖，不等于不可用的证据。区分仅影响交付的限制和使审查失效的限制；后续选择由入口负责。

PR 效果需要验证所属及源仓库、源分支和远端、认证查看者、base/head，以及可用写入和回读接口。本地或分支发布需要确定选定目标及完整待推送范围；不虚构上游，也不从提交请求推断推送权限。披露实际剩余写入、完整内容及待推送提交、Viewed 集合、检查和限制，让入口描述具体动作。适用时说明 amend 和精确租约发布，不把这些效果藏在动作名后面。

让发布覆盖和 Viewed 覆盖可以分别检查。主报告的指定文件及 Viewed 筛选不缩小交付审查。全工作区范围更大，也不授权记录只审查了部分内容的 PR 文件。

## 执行已检查计划

从实际加载的 Skill 解析 `<skill-root>`，不依赖目标工作目录。选择助手前，阅读其支持能力和接口：

```text
python "<skill-root>/scripts/complete_review.py" --help
```

助手冻结并执行支持的 PR 效果；Agent 提供语义覆盖、成功检查、范围和授权。其帮助负责请求字段、命令、证据及状态存储、输出和重试机制。助手准备可保留私有证据及 Git 对象，同时保持真实暂存区、分支和文件不变。实际计划超出能力时，使用下方手动顺序；绝不为了适配工具而改变或省略必要效果。助手不可用不免除任何前提。

本地或分支交付，以及助手不支持的情况，使用以下手动顺序。它也规定助手执行必须达到的结果，不是在助手之后再运行的第二套实现。

1. 重新验证预期内容、顶端提交、暂存区和工作树、受影响依赖，以及相关目标或 PR 版本和待推送祖先链。内容变化后，先重新清点、审查受影响部分并检查，再复用授权。目标、方法或明确范围限制发生变化时，与用户解决；仅来源不同不需要再次决定是否纳入。预期的新 head 需要内容和版本验证，不重复仍有效的未变审查。
2. 需要时暂存全部已披露最终内容，验证预期暂存区文件树。记录证明 HEAD 是本次审查的修复或优化提交，且当前分支和任何推送目标都不是 `master` 或 `main` 时，使用 `git commit --amend`；否则创建新提交。运行正常钩子，再验证提交、父提交、完整文件树、暂存区和剩余工作树。钩子变化需要检查和受影响审查，不留下未解释残余。
3. 需要执行选定发布时，在钩子后重新验证待推送祖先链。替换已发布审查提交时，对已验证源引用使用 `--force-with-lease=<ref>:<verified-old-remote-SHA>`；否则正常推送。漂移或拒绝时停止。回读目标及完整已发布差异；PR 还要回读 base/head。确认预期提交、已检查内容及有效判断。不包含自动 rebase、排除提交、发布标签或发布子模块。
4. PR 记录前，在实际发布版本上验证查看者、两个提交 ID 及整文件覆盖。标记准备好的 Viewed 集合中每个仍待记录的符合条件路径。回读所有选定路径，包括复用标记，并回读 base/head。所有路径都必须为 `VIEWED`，且整个记录期间 base/head 不变。
5. 所有适用效果和回读成功后，报告已验证交付及实际产生的工作区和远端状态。将结果返回入口；执行本身不推进审查。

## 核对未完成效果

保留选定工作区、清单、固定证据及判断、已接受取舍、发布和 Viewed 集合、查看者和版本，以及已完成、失败或未知步骤。中断或响应不确定时，重试前检查实际本地及远端结果。复用已确认效果，只执行缺失步骤，不自动回滚。入口另行保留用户待完成请求及审查位置。

内容、依赖、目标或效果发生变化时，先回到对应清点、覆盖和检查，再继续执行。向入口报告由此产生的发现或权限变化。等待用户决定时，保留成功效果和恢复证据。

每项必要回读都必须成功。接口不可用或结果不确定时，报告已确认、未知及待完成效果，交付仍未完成。在之后有依据的机会中，检查实际状态并按未变授权恢复。明确停止时，保留恢复证据，并将残余效果报告为未完成。
