# 交付

完成通过[Skill 入口](../SKILL.md)选定的实际效果。Agent 确立覆盖范围和权限；交付辅助程序负责清点、冻结、执行并验证受支持的 PR 效果。将发现和实际结果返回入口，由入口负责决定和推进。

## 确定效果集合

选定工作区指已披露的确切审查路径。交付覆盖其中所有待完成改动和完整待发布范围，包括本次对话之外的工作。

| 审查上下文 | 按顺序执行的适用效果 |
| --- | --- |
| PR | 提交工作区待完成改动，将完整待发布范围发布到已验证的 PR 源，并将本次对话已审查的每个合格文件标记为 Viewed，完成回读。 |
| 本地或分支 | 提交工作区待完成改动。只有用户选定了目标及发布效果时才发布；不隐含创建 PR 或记录 Viewed。 |

复用已完成且仍有效的效果。工作区干净时无需空提交；源引用已是当前版本时无需重复推送。只有无需提交或发布时才适用仅记录 Viewed 的交付。快照审查需要先选定可交付工作区，才能承诺本地或发布效果。

需要提交时，若已有动作记录证明 HEAD 是本次审查的修复或优化提交，且当前分支和推送目标分支都不是 `master` 或 `main`，则修订该提交；否则新建提交。

交付前解决明确排除项和保全冲突。仅凭来源不需要额外询问是否纳入，审查筛选也不缩小提交范围。权限不包含无关历史变更、PR 审批或合并。

清单包括暂存、未暂存、未被忽略的未跟踪、冲突及子模块状态、预期最终内容和待发布提交关系。部分暂存文件需要确定连贯的最终工作树内容，并披露它替代哪个暂存版本。被忽略、敏感、临时或有独立归属的内容按其适用限制处理。冲突阻止交付。辅助程序支持的路径使用其清单；只有手动交付才直接收集这些证据。

## 将方案与已有覆盖对应

提交和发布要求检查覆盖每个提交差异及待发布提交，并由本次对话完成其中每项非测试改动的语义审查。这包括支持、生成、仅已暂存、未跟踪及修订提交中的内容，以及已有未发布提交。内容已经位于目标时，不会仅因它是祖先内容就算作新发布。测试沿用入口的仓库分类：仍属于清单和检查范围，供测试使用的生产代码仍是生产代码。

已有评估和检查结果仍覆盖精确预期内容、相关依赖和输入以及效果时，复用这些记录。提交或预期内的 PR head 变化本身不使证据失效。只通过项目的验证负责人和入口的补审流程补齐缺失或过期的覆盖。补审流程负责报告格式、条目标识、发现和待解决的用户决定；主审查进度及保存的序列保持不变。

Viewed 单独从本次对话已审查的完整逐文件 PR 差异推导，包括此前尚未记录的分组。修复片段或检查成功不能证明整文件覆盖。准备记录的文件需补审未覆盖部分；其他部分审查文件保持未标记并披露原因。因此，一项修复可以就绪并发布，而该文件原有的 PR 改动仍留在保存的审查序列中。未审查测试仍不合格。

披露具体的剩余写入、完整提交内容、待发布提交、预期 Viewed 集合，以及检查或限制，适用时包括修订提交和精确租约发布。已有披露仍准确时直接复用。选定通过已授权其披露的效果；新发现或效果变化返回入口处理，同时保留待完成的选择。交付写入前解决覆盖缺口和应由用户决定的问题。预期 Viewed 集合一经固定，就不能为掩盖检查或回读失败而缩小。

## 通过辅助程序完成受支持的 PR 交付

从已加载的 Skill 解析 `<skill-root>`，并阅读其支持的接口：

```text
python "<skill-root>/scripts/complete_review.py" --help
```

CLI 帮助负责能力、请求字段、命令、私有状态、传输要求及重试。提供选定工作区、已确立的 PR 和源身份及查看者、预期效果，以及已有审查、验证和授权记录。哈希绑定记录，但不能证明语义覆盖或权限。

1. **准备。** 调用 `prepare` 获取完整当前清单和冻结方案。将方案与上述覆盖及权限对应，使用保留的完整清单，而非仅凭简要计数。执行前解决未覆盖或已变化的范围；只有确定后的方案或其证据变化时才准备替代方案。
2. **执行。** 使用 `run` 执行已覆盖且已授权的方案。辅助程序重新验证当前状态，运行正常 hooks，验证提交和待发布范围，按条件发布到精确源，并回读 PR 版本及每个选定的 Viewed 路径。使用这些结果作为其机械操作职责的证据。
3. **完成。** 成功的 `complete` 结果加上已确立的覆盖和权限，即表示交付完成。将所得工作区、提交、发布和 Viewed 状态报告给入口，恢复选定的审查动作。只有结果未完成、不确定，或有证据表明之后又发生变化时，才需要进一步检查。

辅助程序的私有状态就是交付恢复记录。将其保存在工作树外、由任务管理的私有临时存储中，并引用已有审查和验证证据。任务负责保留及清理：交付或恢复尚未完成时，以及必要结果和证据尚未交接前，均须保留。直接使用已有记录；交付不要求再做一次归档、复制日志集合或重写证据摘要。另行请求的保留或导出沿用其自身范围和生命周期。

## 对不受支持的方案使用手动执行

本地或分支交付，以及辅助程序无法表达的效果，使用此路径。保留完整选定效果；工具限制不缩小这些效果。必要接口不可用时，依赖该接口的交付仍未完成。

1. **准备并重新验证。** 收集上述清单，在任务私有存储中保留原始暂存区、顶端、工作树及适用的未跟踪内容恢复证据。确定目标和待发布范围；PR 效果还需验证所属及源仓库、源分支和远端、已认证查看者、base/head，以及可用的写入和回读接口。写入前，将内容、依赖、范围和权限与有效覆盖对应。
2. **需要时提交。** 暂存完整已披露最终内容，验证预期暂存区树。按选定的新建或修订模式执行提交并运行正常 hooks，再验证提交、父提交、完整树、暂存区和剩余工作树。Hook 改动需要受影响的检查和审查；解释所有残留状态。
3. **已选且需要时发布。** Hooks 结束后重新验证待发布提交关系。替换已发布审查提交时，对已验证源引用使用 `--force-with-lease=<ref>:<verified-old-remote-SHA>`；否则正常推送。漂移或拒绝时停止。回读目标及完整已发布差异，适用时同时回读 PR base/head，以确立预期提交、已检查内容和有效评估。不包含自动 rebase、排除提交、发布 tag 或子模块。
4. **记录 PR Viewed。** 在实际已发布版本上验证查看者、两个提交 ID 和整文件覆盖。标记每个尚未记录的选定路径，再回读每个选定路径（包括复用标记）及 base/head。所有路径都必须是 `VIEWED`，记录期间 base/head 保持不变。
5. **完成。** 每个适用效果和回读都成功后，将所得工作区及远端状态报告给入口。手动恢复记录沿用辅助程序交付的私有存储生命周期。

## 恢复未完成的交付

保留选定工作区及效果、覆盖记录和已接受取舍、查看者和版本，以及已确认、失败或未知结果。按辅助程序文档中的恢复路径复用同一状态；手动交付则检查实际本地和远端结果，只完成缺失工作。切换传输方式或重试前，先核实不确定的发布结果。只有效果和明确的方法限制仍成立时，切换传输方式才属于现有权限。

内容、依赖、目标或效果变化时，继续前解决相应清单、覆盖和权限。将新发现和决定返回入口，同时保留已确认效果。不可用、未知和待完成结果均报告为未完成；明确停止时保留恢复证据并报告残余效果。恢复不包含自动回滚。
