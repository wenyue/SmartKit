# 交付

准备并验证通过[Skill 入口](../SKILL.md)选定的实际效果。本指南负责完整交付清单、语义覆盖、检查、写入、回读和恢复证据。即使清单、补审或检查尚未完成，选定通过也会启动这些准备工作。将就绪状态、发现和实际效果返回入口，由入口负责菜单、待完成意图和推进。

## 确定完整效果集合

“选定工作区”指已披露的确切审查路径，不是 Agent 进程恰好所在的目录。交付覆盖其中所有待完成改动，不论作者或所属对话。

| 审查上下文 | 按顺序执行的适用效果 |
| --- | --- |
| PR | 提交工作区待完成改动，将完整待发布范围发布到已验证的 PR 源，并将本次对话已审查的每个合格文件标记 Viewed，完成回读。 |
| 本地或分支 | 提交工作区待完成改动。只有用户选定了目标及推送效果时才推送；不隐含创建 PR 或 Viewed 记录。 |

复用已完成且仍有效的效果：工作区干净时不做空提交，源引用已是当前版本时不重复推送。只有无需提交或发布时才适用仅记录 Viewed 的交付，不能用它将工作区待完成改动排除在选定交付之外。快照审查需要先选定可交付工作区，才能承诺本地或发布效果。

选择覆盖完整已披露工作区和待发布范围，包括本次对话之外的工作。仅凭来源不需要额外询问是否纳入。交付前解决明确排除项和保全冲突，不擅自缩小提交。权限不包含无关历史变更、PR 审批或合并。

清点暂存、未暂存、未被忽略的未跟踪、冲突及子模块状态；确定仓库、分支、预期最终内容和完整待发布提交关系。保留原始暂存区、顶端、工作树及适用的未跟踪内容恢复证据。部分暂存文件需要确定连贯的最终工作树内容，并披露它替代哪个暂存版本。被忽略、敏感、临时或有独立归属的内容按其适用限制处理。冲突阻止交付。

## 确定这些效果的覆盖范围

三种范围回答不同问题：

| 范围 | 覆盖 |
| --- | --- |
| 主报告与进度 | 入口的固定比较、筛选和已展示文件分组。 |
| 提交与发布 | 清单和必要检查覆盖每个提交差异及待发布提交，包括测试、文档、生成或支持文件、仅已暂存及未跟踪改动，以及主比较之外的工作。本次对话的语义审查覆盖该集合中的每项非测试改动。 |
| Viewed | 本次对话已审查的当前 PR 文件的完整预期差异，包括此前未记录就推进的分组及补审。 |

提交或发布覆盖中，只有精确内容、依赖和效果仍有效时才能复用评估。作者身份、测试通过、文件名出现在报告中，以及其他对话的审查，都不能证明覆盖。修订提交包含它保留的非测试内容；发布包含已有未发布提交。内容已经位于目标时，不会仅因它是祖先内容就算作新发布。

测试沿用主审查中的仓库分类，也不进入补充语义审查。供测试使用的生产代码仍是生产代码。所有测试仍进入清单和必要检查。

对未覆盖的非测试内容，按入口的完整检查标准评估改动及必要文件、调用方上下文。按规定固定格式展示补审，提供前后证据和链接，与尚未展示的主分组分开。受影响项复用编号，新补充修改项分配连续 M 编号。与主进度区分：补充覆盖不改变主总数和保存位置，也不通过刷新 Viewed 筛选移除尚未展示文件。选定 O 工作按入口要求保留独立身份。

任何交付写入前，返回新增可处理发现、值得考虑的可选改进及证据缺口。入口的补审表处理新条目，同时保留待完成交付请求。没有未解决条目时，完成剩余前提并执行已选交付，不为未变化的效果再次询问授权。简洁呈现或省略解释不能补足缺失评估；明确保留的判断仍需记录。

### 从整文件 PR 审查推导 Viewed

分别判断提交或发布的就绪状态与 Viewed 资格。按本次对话对完整逐文件 PR 差异的评估构造记录集合。修复片段、O 观察、检查通过、文件名出现在报告中或纳入提交都不足以证明资格。准备记录的文件需补审未覆盖部分；其他部分审查文件保持未标记并披露原因。未审查测试仍不合格。

例如，某次修复触及主审查保存位置之后的文件；该文件原有的 PR 改动已经位于发布目标。完整提交与待发布范围满足上述审查、检查及其他交付前提后，即使这些原有 PR 改动仍未审查，也可以按选定交付提交和发布该修复。保持该文件未标记，并留在保存的主审查序列中。若补审还覆盖了该文件的完整当前 PR 差异，它可以获得 Viewed 资格，但保存的主审查清单和位置仍保持不变。

预期集合固定后，检查缺失或回读失败都使交付未完成，不能为了完成而删除选定路径。报告原筛选不缩小合格记录或交付覆盖范围，更大的交付范围也不证明部分审查文件可以标记。

## 使就绪状态具体可核对

对完整预期提交和发布范围运行必要检查，完成可做的补审。报告就绪前完成可推导的只读准备；清单、接口或覆盖未知不能证明交付不可用。指出已验证限制是仅影响交付还是使审查失效，再将该区别返回入口。

PR 效果需要验证所属及源仓库、源分支和远端、已认证查看者、base/head，以及可用的写入和回读接口。本地或分支发布需要确定选定目标和精确待发布范围；提交请求不提供上游或推送权限。

披露剩余写入、完整内容、待发布提交、Viewed 集合及检查和限制。适用时包括 amend 和精确租约发布。发布覆盖与 Viewed 覆盖应能分别检查。选定通过已授权其披露的效果范围；只有效果变化或未解决的用户决定超出现有权限时才询问。

## 选择执行路径

从实际加载的 Skill 解析 `<skill-root>`，不依赖目标工作目录，并阅读辅助程序支持的接口：

```text
python "<skill-root>/scripts/complete_review.py" --help
```

凡方案在辅助程序支持的能力范围内，都使用辅助程序。它冻结并执行 PR 效果；Agent 提供语义覆盖、成功检查、已披露范围和权限，哈希和方案不能证明这些前提。CLI 帮助负责请求字段、命令、私有证据和状态、输出及重试。准备可以保留私有证据和 Git 对象，同时保持真实暂存区、分支和文件不变。辅助程序失败时，应通过该接口诊断和恢复，不能另用 Git 或原始 API 写入序列代替。

下方顺序规定所有交付的结果契约，同时作为本地或分支交付及已证实不受支持方案的手动路径。选择该路径前，根据受支持接口和实际效果确定能力缺口。工具缺失或受支持操作执行失败，都使依赖效果仍未完成，均不授权绕过校验。常见的能力缺口应通过辅助程序所属的维护任务补齐。不能为适配工具省略或改变选定效果，也不重复它已完成的写入。

1. **重新验证。** 检查预期内容、顶端、暂存区、工作树、受影响依赖、目标或 PR 版本，以及待发布提交关系。内容变化后，需要刷新清单、受影响审查及检查，才能复用权限。目标、方法或明确范围限制变化时与用户解决。预期内新 head 需要验证内容和版本，不重复仍有效且未变的评估。
2. **需要时提交。** 暂存完整已披露最终内容，验证预期暂存区树。遵守明确的新建提交请求。否则，已有动作记录证明 HEAD 是本次审查的修复或优化提交，且当前分支和任何推送目标都不是 `master` 或 `main` 时，使用 `git commit --amend`；其他情况新建提交。运行正常 hooks，再验证提交、适用的原有或新增父提交、完整树、暂存区和剩余工作树。Hook 改动需要检查和受影响审查，解释所有残留状态。
3. **已选且需要时发布。** Hooks 结束后重新验证待发布提交关系。替换已发布审查提交时，对已验证源引用使用 `--force-with-lease=<ref>:<verified-old-remote-SHA>`；否则正常推送。漂移或拒绝时停止。回读目标及完整已发布差异，适用时同时回读 PR base/head；确认预期提交、已检查内容和有效评估。不包含自动 rebase、排除提交、发布 tag 或子模块。
4. **记录 PR Viewed。** 在实际已发布版本上验证查看者、两个提交 ID 和整文件覆盖。标记准备好的合格路径中所有尚未记录项，再回读每个选定路径（包括复用标记）及 base/head。所有路径都必须是 `VIEWED`，记录期间 base/head 保持不变。
5. **返回已验证效果。** 只有每个适用效果和回读都成功，交付才成立。将最终工作区及远端状态报告给入口。

## 重试前核实不确定结果

保留清单、固定证据和评估、已接受取舍、选定工作区、发布及 Viewed 集合、查看者和版本，以及已完成、失败或未知步骤。中断或响应不确定后，检查实际本地和远端结果，复用已确认效果，只做缺失工作。不自动回滚。

内容、依赖、目标或效果变化时，继续前完成相应清单、覆盖和检查。将产生的发现或权限变化返回入口，同时保留成功效果及恢复证据。

接口不可用或结果不确定时，交付仍未完成。报告已确认、未知和待完成效果；之后在受支持机会检查实际状态，在未变权限内恢复。明确停止时保留恢复证据并报告残余效果。
