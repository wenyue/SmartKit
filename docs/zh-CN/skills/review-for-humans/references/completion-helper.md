# 完成助手

在 Skill 的准备流程已建立就绪、可审阅的完成操作后，使用此助手。它支持在选定本地分支中完成已核验的 github.com PR：仅记录 Viewed，或新建提交并正常推送后记录 Viewed。它可以复用已经提交的待推送内容。修订提交、强制或带租约的发布、镜像推送 remote、分离工作区、未解决的 Git 操作、特殊索引标记，以及已变更的子模块或目录条目，使用 Skill 现有的手动流程。

## 判断和权限仍由 Agent 负责

助手检查冻结的身份、内容、提交历史和读回结果。执行前，Agent 必须确认整个提交或发布所需的检查通过，解决问题和复审，核验每个选定 Viewed 路径的整文件覆盖，披露所有待提交路径和待推送提交，并取得所选操作的授权。按 Skill 的要求处理混合来源和部分暂存内容。`plan_id` 标识已准备的操作；将它传给命令不会授予权限。

将这些决策的证据保存在工作区外的稳定、可读文件中。助手会计算其字节摘要，并在内容变化或文件消失时停止。这些引用绑定证据，不能代替评估其含义或重跑已失效的检查。对于仅记录 Viewed 的完成操作，应确认保留的本地差异不会使固定审查或其依赖失效。

## 准备冻结的计划

前提为 Python 3.8+、Git、已认证的 GitHub CLI（`gh`）、对 PR 和来源分支的访问权限，以及现有的已准备工作区。当前 GitHub 查看者必须与审查时的查看者一致。助手通过 `gh api` 访问 github.com；认证、工具、权限、来源对象或读回结果不可用时，完成操作仍未完成。它不会安装工具、获取远端对象、同步或选择其他工作区。

将 `<skill-root>` 解析为实际加载的此 Skill 目录，不依赖目标工作目录。首先阅读命令接口：

```text
python "<skill-root>/scripts/complete_review.py" --help
```

编写 JSON 请求，使用完整提交 ID 和选定本地分支的准确名称。`pull_request` 指定 PR 所属仓库；助手从 GitHub 获取来源仓库和引用，包括 fork。`viewed_paths` 包含完整的选定且符合资格的集合；结束审查时，还应包括此前已展示的分组。`evidence` 指定支持就绪状态、整文件覆盖、已披露范围和授权的稳定文件。

```json
{
  "repository": "/absolute/selected-worktree",
  "branch": "review-branch",
  "pull_request": "owner/repository",
  "number": 123,
  "base": "1111111111111111111111111111111111111111",
  "head": "2222222222222222222222222222222222222222",
  "viewer": "reviewer-login",
  "viewed_paths": ["src/feature.py"],
  "mode": "commit-push",
  "remote": "origin",
  "message": "Fix reviewed behavior",
  "requires_amend": false,
  "evidence": ["/absolute/private/review-and-checks.json"]
}
```

不需要发布时，将 `mode` 设为 `viewed-only`，并省略 `remote` 和 `message`。该模式要求本地 HEAD 位于固定的 PR head，并保留已冻结的索引和工作区差异。当已记录的审查操作要求修订提交时，设置 `requires_amend`；准备操作会拒绝该请求，让现有的修订提交和带租约发布流程继续负责。该值为 false 或省略时，必须符合实际记录的操作。

按所属制品的生命周期，在工作区外选择一个新的私有状态目录。该目录在完成前保存唯一的恢复证据，必须保持可用；应保持私有且不发布。助手会以仅 POSIX 所有者可访问的权限创建目录；在 Windows 上，应将其保存在当前账户的私有目录下，并使用适当的继承访问控制。

```text
python "<skill-root>/scripts/complete_review.py" prepare --input "/private/request.json" --state "/private/completion-state"
```

准备操作保存 `plan.json`、原始索引字节、已跟踪文件的二进制差异、已变更工作文件的字节或符号链接目标、预期的完整目录树、待推送提交历史和差异、完整分页的 GitHub 文件信息，以及证据摘要。准备发布时，它使用隔离索引暂存，运行 Git 原生 clean filter，并可能添加 Git 对象；它保留真实索引、分支、HEAD 和工作文件内容，然后核验这些状态未变。披露范围时检查已保存的清单和日志；stdout 中的简短计数不能代替该披露。

将计划中的准确路径、完整待推送提交列表和差异、最终内容、PR 来源、查看者和版本，以及选定 Viewed 集合，与已准备的操作核对。只为这些相同的效果取得或复用授权。准备操作本身不能建立审查质量、来源纳入同意、依赖有效性或授权。

## 执行并恢复所选操作

操作获授权后，原样传入返回的 `plan_id`：

```text
python "<skill-root>/scripts/complete_review.py" run --state "/private/completion-state" --confirm "<plan_id>"
```

命令锁定此操作，重新核验已准备的状态，在需要时暂存完整且已披露的最终内容，并运行正常的提交 hook。它核验预期目录树和父提交、待推送提交历史和已核验推送目标上的来源引用，仅在需要时执行范围明确的正常推送，且不自动发布标签或子模块，并读回来源引用、PR 版本以及已发布的提交和目录树。随后，它只将选定且尚未 Viewed 的路径标记为 Viewed，并读回每个选定路径及保持不变的 PR 版本。已有提交、已发布 head 和 Viewed 结果在复用前均会核验。不会创建空提交。

Stdout 是一条简短的 JSON 摘要，包含状态、版本与计数、计划及进度的位置，以及完整日志目录。每条 Git/gh 命令的 stdout、stderr、参数、进程身份、退出状态和耗时均保存在私有日志中；摘要不会隐藏失败。助手保留部分效果，不回滚，也不推进审查进度。退出码 `0` 表示所需读回已完成；`1` 表示未完成；`2` 是 CLI 用法错误；`130` 是中断。报告完成前，应检查结果并说明残留效果。

中断或响应丢失后，使用相同状态和计划 ID 重跑同一条 `run` 命令。它会先检查实际本地和远端状态：预期提交需要已检查的目录树和父提交，推送需要来源引用和 PR 读回，Viewed 需要当前逐路径状态。它只恢复缺失的操作，包括部分 Viewed 记录之后的剩余操作。其原生锁在进程退出时释放；子进程启动后发生任何失败时，它会等所属 Git/gh 子进程停止后再释放锁。

内容、分支、证据、查看者、来源、base/head 或发布范围变化时，包括检测到由 hook 引起的变化，依赖操作停止。保留操作及其证据，刷新受影响的清单、检查、复审以及必要的同意；只有变更效果明确后，才使用新准备的计划。已经创建私有状态的准备操作失败后，会保留该诊断目录；选择新状态目录前先检查它。缺失读回或仍不确定的活动子进程状态均表示未完成；不要删除锁、重置工作区、推测性重复写入，或用普通继续替代。
