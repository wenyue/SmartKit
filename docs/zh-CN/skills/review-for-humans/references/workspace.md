# 工作区

为 PR 或需对齐远端的分支准备工作区或生成链接前阅读。先确定选择对齐路线所需的事实，再询问效果选择。普通事实补问遵循技能入口；这里负责工作区选择。

## 确定仓库、分支和版本

使用当前权威 PR 元数据确定所属仓库、源仓库或 fork、源分支和目标提交。选定历史版本时保留该目标，本地跟踪不能证明当前 PR head。

即使检出看似匹配也要检查。从已加载的 SmartKit 资源解析 `local_web`：

```text
python "<local_web>" --help
python "<local_web>" diff --inspect --input "<context.json>"
```

提供已验证 PR 上下文。读取 `current` 与 `worktrees`，没有备选不说明当前仓库身份。分别解释 `repository_status`、`branch_status` 和版本 `status`。提交相同不证明分支身份，仓库相关不证明源分支身份。检查不 fetch、不检出，也不同步。

保留路径、仓库关系、分支、提交及全部已暂存、未暂存、未跟踪和冲突 `changes`，包括部分暂存与重命名来源。提出使用已有工作区前先检查该工作区。清单不是恢复快照，也不能证明安全；未知不等于干净或最新。向用户说明相关路径和工作保留效果，不照念状态字段名。

1. 确定检出属于 PR 所属仓库还是已验证源仓库。保留无关工作区。
2. 验证源仓库和分支。已验证跟踪别名可以符合要求，但需说明。不同分支或 detached HEAD 即使位于目标提交也要选择。找到匹配工作树不等于选定它，不强制重复检出已被占用的分支。
3. 比较选定对应分支工作区的 HEAD 与目标。匹配时无需同步问题，但说明实时内容中的未提交改动。领先或分叉方案应指出本地及目标独有提交，保留工作与历史。

区分比较证据和本地证据。即使本地身份、版本或安全对齐方案不可用，仍可审查已独立验证的固定 PR 比较。它要求已验证范围、PR 身份目标和前后内容，不改变本地工作。选定后跳过无关本地对齐，只解决必要筛选和证据。版本不同的实时链接需要固定证据并明确说明，不改变已评估提交或 Viewed 资格。

## 询问具体对齐方案，不展示内部状态

先确定会实质影响选择的事实。对当前工作区的对齐方案，说明工作区、目标分支提交、方法、受影响提交，以及如何保留暂存区、工作树、未跟踪内容和本地提交。完整安全方案已验证时，一个选择可以明确包含检出及同步到确切目标。后续步骤仍依赖未知事实时，只提供已验证的前一步，再检查并解决依赖后提出其余步骤。单独检出不授权未说明的同步。

检查后使用以下第一个适用情况。按所列顺序展示全部适用选择，连续编号，第一个选项为 A 并标推荐。每项使用短动作词，后面写清确切效果。创建选项提出在已验证目标上建立干净的隔离工作区；除非有已知阻碍，否则应包含此项。

| 情况 | 有序真实选择 |
| --- | --- |
| 仓库相关、分支错误、当前安全对齐方案已验证，且源分支未被其他工作树占用 | **切换** 到源分支，只有完整已验证方案中明确包含同步时才同步；可用时 **快照** ；可用时 **使用** 另一已验证工作区；**创建** 隔离工作区；**停止** 。 |
| 对应分支工作区落后目标，安全的确切目标同步已验证 | **同步** 到确切目标；可用时 **快照** ；可用时 **使用** 另一已验证工作区；**创建** 隔离工作区；**停止** 。 |
| 对应分支工作区领先或分叉，且有固定审查证据 | 可用时 **快照** ；可用时 **保留** 已验证的不同版本实时工作区并说明差异；仅按已验证保留方案 **同步** ；可用时 **使用** 另一已验证工作区；**创建** 隔离工作区；**停止** 。 |
| 当前路线未知、无关、不可用、被其他工作树占用，或检出同步已知不安全或不可用 | **使用** 已验证备选工作区；可用时 **快照** ；**创建** ；**停止** 。 |
| 仓库、分支、版本匹配，或已选固定比较 | 直接继续，不再询问对齐。 |

菜单需要至少一条可行的非停止路线。没有时，直接问能建立路线的具体用户事实，或报告具体限制；不虚构“获取证据”或仅含停止的菜单。多个已有工作区符合要求时，在使用选项下列出具体路径，同时保留快照、创建等其他可行路线。只有用户选择使用且路径仍不明确时，才直接问哪个路径；不能用路径问题替用户选定这条路线。本地事实未知不使独立已验证备选失效。仅分支审查没有 PR 快照兜底。

用户选择创建后，使用 [create-worktree](../../create-worktree/SKILL.md) 完成创建检查、执行已授权创建和环境评估，遵守用户的干净模式选择和已验证不可变基准。复用已有选择，只解决剩余决定。任何对齐选择都不授权未说明的历史变更或发布。

## 审查前验证

对齐后在确切路径重新检查，验证分支映射、目标提交和工作保留。审查或链接前刷新 PR base/head 与 Viewed 证据并重评变化目标。中断后先检查实际结果再重试。验证、明确选择固定比较或停止前，依赖审查保持待处理。

保留工作区、源分支映射、目标和快照或实时模式。历史固定 PR 审查或源身份不可用时使用快照，实时 PR 链接绑定已验证的确切路径，不交给自动发现。

仅分支审查时，通过只读 Git 检查检出及工作树，使用明确或可靠确定的权威远端，不臆造上游。PR 检查要求 PR 上下文。无展示工作区时，解决已验证工作区、创建或其他范围。有意选择本地分支或未暂存审查时无需远端同步。
