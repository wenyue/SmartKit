# 准备

用于 PR 或需对齐远端的分支审查，在选择工作区或准备对应链接前阅读。本指南负责源与版本证据、PR Viewed 筛选、工作区路线和已验证展示上下文。技能入口负责普通审查和用户决定；通用本地比较与链接生成不需要本指南。

## 确定仓库、分支和版本

使用当前权威 PR 元数据确定所属仓库、源仓库或 fork、源分支和目标提交。选定历史版本时保留该目标，本地跟踪不能证明当前 PR head。

使用 Viewed 筛选时，获取已认证查看者的完整文件状态，并确认所有分页的 base/head 一致。对于 `github.com` 上的当前 PR，运行已加载技能中的 `snapshot`，并在工作树外指定一个新的私有证据目录。

```text
python "<skill-root>/scripts/complete_review.py" snapshot --pull-request owner/repo --number 123 --state "/private/viewed-snapshot"
```

从所选版本的证据中选取状态为 `UNVIEWED` 和 `DISMISSED` 的路径，历史比较同样适用。使用 `snapshot.json` 时，先核对其中的查看者及 base/head 是否与本次审查目标一致，再使用 `candidate_paths`。审批、评论和先前在聊天中展示过的内容都无法证明文件状态。

用户要求包含已查看文件时，选取已验证比较中的全部路径。若当前的 `snapshot.json` 与比较匹配，完整的 `files` 映射包含这些路径。无论是否启用 Viewed 筛选，都应用项目的测试文件排除规则。

已授权获取后，完整 Viewed 筛选仍不可用时，先直接询问真正必要的用户事实。否则，固定比较证据就绪时，直接询问用户是否愿意不按 Viewed 筛选，审查所有其他符合条件文件。只有明确选择后才采用这个更大范围；不虚构历史或当前 Viewed 状态。

即使检出看似匹配也要检查。从已加载的 SmartKit 资源解析 `local_web`：

```text
python "<local_web>" --help
python "<local_web>" diff --inspect --input "<context.json>"
```

提供已验证 PR 上下文。读取 `current` 与 `worktrees`，没有备选不说明当前仓库身份。分别解释 `repository_status`、`branch_status` 和版本 `status`。提交相同不证明分支身份，仓库相关不证明源分支身份。检查不 fetch、不检出，也不同步。

保留路径、仓库关系、分支、提交及全部已暂存、未暂存、未跟踪和冲突 `changes`，包括部分暂存与重命名来源。提出使用已有工作区前先检查该工作区。清单不是恢复快照，也不能证明安全；未知不等于干净或最新。向用户说明相关路径和工作保留效果，不照念状态字段名。

1. 确定检出属于 PR 所属仓库还是已验证源仓库。保留无关工作区。
2. 验证源仓库和分支。已验证跟踪别名可以符合要求，但需说明。不同分支或 detached HEAD 即使位于目标提交也要选择。找到匹配工作树不等于选定它，不强制重复检出已被占用的分支。
3. 比较选定对应分支工作区的 HEAD 与目标。匹配时无需同步问题，但说明实时内容中的未提交改动。领先或分叉方案应指出本地及目标独有提交，保留工作与历史。

区分比较证据和本地证据。即使本地身份、版本或安全对齐方案不可用，仍可审查已独立验证的固定 PR 比较。它要求已验证范围、PR 身份目标和前后内容，不改变本地工作。选定后跳过无关本地对齐，只解决必要筛选和证据。版本不同的实时链接需要固定证据并明确说明，不改变已评估提交或 Viewed 资格。

## 按实际任务选择工作区路线

仓库、分支和版本已经匹配时，直接继续，不增加对齐选择。明确选定固定比较时，也无需本地对齐。保留先前的工作区及视图选择；只有事实变化或新增任务要求，才重新处理受影响部分。

否则，提供路线前先检查可用性。这些动作准备工作区或比较，不交付改动，也不推进审查分组。

| 动作 | 适用路线及必须披露的内容 |
| --- | --- |
| **切换** | 通过已确定的保留计划，将当前相关 checkout 切换到已验证源分支。说明受影响状态和提交。只有确切同步方法及安全性都已验证并披露时，才包含组合同步。 |
| **同步** | 通过已验证保留计划，将选定的对应分支或工作区对齐到确切目标。披露受影响的本地和目标提交，以及要保留的暂存区、工作树、未跟踪内容和历史。 |
| **使用** | 选择已验证的现有工作区。给出路径、仓库与源分支映射、提交和保留的改动。实时工作区版本不同时，必须有独立固定比较证据，并明确说明差异。 |
| **创建** | 在已验证不可变目标上创建干净的隔离工作区。说明路径、分支或别名、目标及环境评估，并保留当前工作区。除非已知阻塞使其不可行，否则包含该路线。 |
| **快照** | PR 已有独立验证的前后证据时，不改变本地工作而审查固定比较。它不提供用于编辑或本地执行的匹配 checkout。仅分支审查没有 PR 快照兜底。 |

首先遵守已经明确选择且可行的路线。否则，使用入口的决策原则及下方常见 PR 情况。当前工作区路线指安全且能满足任务的切换或同步，在菜单里使用该具体动作名。路线只有能建立任务所需工作区或证据时才有用。快照不能替代必要的本地编辑或执行。判断可行性时，保留源分支占用约束和已有工作。

| 当前情况 | 推荐动作 | 选项顺序 |
| --- | --- | --- |
| 当前工作区已匹配，或已经选定可行路线 | 开始审查 | 无需新选择；完成选定路线的验证 |
| 当前工作区有安全路线，也有已验证的现有工作区 | **切换** 或 **同步** 当前工作区 | **切换** 或 **同步** ； **使用** ； **创建** ； **快照** |
| 当前工作区有安全路线；没有符合条件的现有工作区 | **切换** 或 **同步** 当前工作区 | **切换** 或 **同步** ； **创建** ； **快照** |
| 当前工作区不适合；有已验证的现有工作区 | **使用** 现有工作区 | **使用** ； **创建** ； **快照** |
| 当前工作区和现有工作区都不符合条件 | **创建** 工作区 | **创建** ； **快照** |

这些选项行假定创建和固定 PR 快照都可行；其他情况对已确定的路线应用相同优先顺序。每条可行路线按顺序只展示一次，连续标注字母，第一项为推荐。如果切换包含已完整验证的同步，只描述一次组合。已验证的现有工作区需要对齐时，可提供使用及其具体同步计划。未知事实需要调查，不证明选项不可用；排除潜在有用路线前先查明。已知前提缺失导致某个相关选择不可用时，应说明原因。

有多个工作区符合使用条件时，列出具体路径，同时保留其他路线。只有用户选择使用且路径仍有歧义时才询问路径；这个问题不能代替用户选择使用。不提供停止或取消选项，也不因为路线被推荐或是唯一可用路线就自动选择。没有已验证的有用路线时，询问能建立路线的具体用户事实，或直接报告实际限制，不虚构菜单。本地身份或对齐未确定时，独立验证的 PR 证据仍可能支持快照。

选择创建后，使用 [create-worktree](../../create-worktree/SKILL.md)，按用户的干净工作区选择及不可变基准执行创建检查、已授权创建和环境评估。复用既有选择，只解决未定事项。任何路线都不授权未声明的同步、历史改写或发布。

## 审查前验证

对齐后在确切路径重新检查，验证分支映射、目标提交和工作保留。审查或链接前刷新 PR base/head 与 Viewed 证据并重评变化目标。中断后先检查实际结果再重试。验证、明确选择固定比较或停止前，依赖审查保持待处理。

保留工作区、源分支映射、目标和快照或实时模式。历史 PR、选定的固定比较或源身份不可用时，使用 `view="snapshot"` 并提供已验证的固定证据。PR 实时链接使用 `view="worktree"`，将 `repo` 绑定到本指南已验证的确切路径，包括已验证的本地别名。

仅分支审查时，通过只读 Git 检查检出及工作树，使用明确或可靠确定的权威远端，不臆造上游。PR 检查要求 PR 上下文。无展示工作区时，解决已验证工作区、创建或其他范围。有意选择本地分支或未暂存审查时无需远端同步。
