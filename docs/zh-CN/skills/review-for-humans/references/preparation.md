# 准备

审查 PR、需对齐远端的分支，或需要选择展示工作区的本地分支时，阅读本指南。它负责源和版本证据、PR 的 Viewed 筛选、工作区路线及已核实的展示上下文。技能入口负责普通审查和用户决定。

## 确定比较范围

### 无 PR 的分支

使用只读 Git 确定仓库身份、分支、分支顶端、比较基准和检出或工作树的状态。需要对齐远端时，根据明确选择或可靠的仓库证据核实权威远端及引用。必要的远端、引用或基准仍有歧义时，只向用户询问需要由其确定的具体信息。需要对齐或选择展示工作区时，按下文检查和选择工作区。除非用户明确选了其他比较，否则沿用分支范围。

### 拉取请求

从权威 PR 证据核实托管站点、所属仓库及编号、源仓库或 fork 及源分支，以及 base/head。保留选定的历史版本。本地跟踪配置用于确定工作区与源的关系。当前 PR 版本由 PR 元数据确定。

使用 Viewed 筛选时，获取已认证查看者的完整文件状态，并确认各页的 base/head 不变。对于 `github.com` 上的当前 PR，运行已加载技能中的 `snapshot`，在工作树外指定新的私有证据目录。内置路线使用已认证的 GitHub 访问。其他已获授权的接口只有在能为所选站点及版本提供必要的 PR 和文件状态证据时才可使用。

```text
python "<skill-root>/scripts/complete_review.py" snapshot --pull-request owner/repo --number 123 --state "/private/viewed-snapshot"
```

从所选版本的证据中选取状态为 `UNVIEWED` 和 `DISMISSED` 的路径，历史比较同样适用。使用 `snapshot.json` 时，先核对其中的查看者及 base/head 是否与本次审查目标一致，再使用 `candidate_paths`。审批、评论和先前在聊天中展示过的内容都无法证明文件状态。

用户要求包含已查看文件时，选取已验证比较中的全部路径。若当前的 `snapshot.json` 与比较匹配，完整的 `files` 映射包含这些路径。无论是否启用 Viewed 筛选，都应用项目的测试文件排除规则。

已授权获取后，完整 Viewed 筛选仍不可用时，先直接询问真正必要的用户事实。否则，固定比较证据就绪时，直接询问用户是否愿意不按 Viewed 筛选，审查所有其他符合条件文件。只有明确选择后才采用这个更大范围；不虚构历史或当前 Viewed 状态。

独立核实固定 PR 比较需要 PR 身份、选定的 base/head 和范围，以及完整的前后内容。用户选定该比较后，补齐仍需的筛选和内容证据，跳过无关的工作区对齐。本地展示有独立的前提。用 `local_web` 展示快照时，核实确切的 Git 工作树根目录和还原比较两侧所需的固定对象，包括重命名路径和确实不存在的一侧。使用 `view="snapshot"`，确认它实际展示了固定差异。即使命令成功，也可能返回诊断页面的 URL。本地无法展示时，保留固定证据，按入口的展示流程处理。

## 为选定任务检查工作区

工作依赖检出时，即使看似匹配也要检查。纯分支使用上面的 Git 路线。受支持的 `github.com` PR 可从已加载的 SmartKit 资源中定位 `local_web`。

```text
python "<local_web>" --help
python "<local_web>" diff --inspect --input "<context.json>"
```

向 `local_web` 提供已核实的 PR 上下文。读取 `current` 和 `worktrees`，分别解释 `repository_status`、`branch_status` 和版本 `status`。即使没有列出备选工作树，也要核实当前仓库身份。提交相同不足以确认分支身份，仓库有关联也不足以确认源分支身份。检查不执行抓取、检出或同步。内置检查不可用时，在提供依赖它的路线前，从 Git 和已核实的 PR 源获取只读证据，确认同样的事实。

保留路径、仓库关系、分支、提交及全部已暂存、未暂存、未跟踪和冲突 `changes`，包括部分暂存与重命名来源。提出使用已有工作区前先检查该工作区。清单不是恢复快照，也不能证明安全；未知不等于干净或最新。向用户说明相关路径和工作保留效果，不照念状态字段名。

1. 确定检出是否属于选定的仓库。涉及 PR 时，核实它与 PR 所属仓库及已核实的源仓库的关系。保留无关工作区。
2. 核实选定的分支和它的来源。PR 使用跟踪别名时，确认实际配置的远端指向源仓库、合并引用指向源分支，并披露已核实的别名。不同分支或分离的 HEAD 即使位于目标提交也需要选择。找到匹配工作树后仍要按已选路线使用，禁止强制重复检出已在别处使用的分支。
3. 比较选定对应分支工作区的 HEAD 与目标。匹配时无需同步问题，但说明实时内容中的未提交改动。领先或分叉方案应指出本地及目标独有提交，保留工作与历史。

实时链接指向不同版本时，须有已核实的固定比较证据并明确披露差异。评估和 Viewed 资格仍以固定比较为准。

## 按实际任务选择工作区路线

仓库、分支和版本已经匹配时，直接继续，不增加对齐选择。明确选定固定比较时，也无需本地对齐。保留先前的工作区及视图选择；只有事实变化或新增任务要求，才重新处理受影响部分。

否则，提供路线前先检查可用性。这些动作准备工作区或比较，不交付改动，也不推进审查分组。

| 动作 | 适用路线及必须披露的内容 |
| --- | --- |
| **切换** | 通过已确定的保留计划，将当前相关 checkout 切换到已验证源分支。说明受影响状态和提交。只有确切同步方法及安全性都已验证并披露时，才包含组合同步。 |
| **同步** | 通过已验证保留计划，将选定的对应分支或工作区对齐到确切目标。披露受影响的本地和目标提交，以及要保留的暂存区、工作树、未跟踪内容和历史。 |
| **使用** | 选择已验证的现有工作区。给出路径、仓库与源分支映射、提交和保留的改动。实时工作区版本不同时，必须有独立固定比较证据，并明确说明差异。 |
| **创建** | 在已核实的不可变目标上创建干净的隔离工作区。说明路径、分支、目标和就绪检查，保留现有工作区。任务需要实时 PR 源映射时，先确认有可行方案，再提供创建选项。能够通过同名分支确认来源时可用同名分支，否则说明将别名映射到已核实来源所需的跟踪配置。 |
| **快照** | PR 有独立核实的前后证据时，在保留本地工作的情况下审查固定比较。编辑和本地执行需要各自可用的工作区。 |

首先遵守已经明确选择且可行的路线。否则，使用入口的决策原则及下方常见 PR 情况。当前工作区路线指安全且能满足任务的切换或同步，在菜单里使用该具体动作名。路线只有能建立任务所需工作区或证据时才有用。快照不能替代必要的本地编辑或执行。判断可行性时，保留源分支占用约束和已有工作。

| 当前情况 | 推荐动作 | 选项顺序 |
| --- | --- | --- |
| 当前工作区已匹配，或已经选定可行路线 | 开始审查 | 无需新选择；完成选定路线的验证 |
| 当前工作区有安全路线，也有已验证的现有工作区 | **切换** 或 **同步** 当前工作区 | **切换** 或 **同步** ； **使用** ； **创建** ； **快照** |
| 当前工作区有安全路线；没有符合条件的现有工作区 | **创建** 工作区 | **创建** ； **切换** 或 **同步** ； **快照** |
| 当前工作区不适合；有已验证的现有工作区 | **使用** 现有工作区 | **使用** ； **创建** ； **快照** |
| 当前工作区和现有工作区都不符合条件 | **创建** 工作区 | **创建** ； **快照** |

这些 PR 示例假定创建和固定 PR 快照都可行。纯分支审查或其他场景下，对已确认可行的路线应用同样的优先顺序。每条可行路线按顺序展示一次，连续标注字母，第一项为推荐。如果切换包含已完整核实的同步，只说明一次组合方案。已核实的现有工作区需要对齐时，可以提供使用选项并说明具体同步方案。排除可能有用的路线前，先查清未知事实。因缺少已知的必要前提而无法提供某条路线时，说明原因。

有多个工作区符合使用条件时，列出具体路径，同时保留其他路线。只有用户选择使用且路径仍有歧义时才询问路径；这个问题不能代替用户选择使用。不提供停止或取消选项，也不因为路线被推荐或是唯一可用路线就自动选择。没有已验证的有用路线时，询问能建立路线的具体用户事实，或直接报告实际限制，不虚构菜单。本地身份或对齐未确定时，独立验证的 PR 证据仍可能支持快照。

选择创建后，使用 [create-worktree](../../create-worktree/SKILL.md)，沿用用户选择的干净工作区和不可变基准。根据它返回的 `ready` 或 `non-ready` 判断创建和环境是否就绪。返回 `ready` 时，执行已选方案授权的跟踪配置变更，并按下文核实实际映射和其他要求。沿用已有选择，只解决尚未决定的事项。同步、改写历史和发布仍须有明确授权。

## 审查前验证

对齐后在确切路径重新检查，核实分支映射、目标提交和工作保留情况。审查 PR 或生成其链接前，刷新 base/head 和适用的 Viewed 证据，并重新评估发生变化的目标。中断后先检查实际结果，再重试。工作区未就绪或映射未确定时，报告阻塞，保留已选路线和部分状态。暂停依赖就绪状态或映射的操作，包括受影响的编辑和本地执行。当选定范围与独立核实的证据支持时，继续只读评估。

按需保留选定工作区、已核实的映射、目标和选定的展示模式。历史 PR 和选定的固定比较用固定展示。PR 实时链接使用 `view="worktree"`，将 `repo` 绑定到此处已核实的确切工作区，包括已核实的本地别名。无法核实源身份时，从用户已有选择或明确选择中确定可行路线。
