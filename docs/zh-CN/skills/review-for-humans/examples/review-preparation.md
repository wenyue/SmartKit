# 工作区或比较基准未定时的审查准备

在这个虚构 PR 审查中，相关检出位于 `main` 且没有本地改动。已验证的 PR 源分支为 `feature/export`；当前检出可以安全切换过去并快进到固定的 head，不会丢失工作。没有符合条件的既有任务工作树，但新建工作树和固定快照审查都可行。

## 选择展示工作区

**Agent：** 当前检出在 main，PR 使用 feature/export。以下路径都能保留当前干净状态：

- A． **切换当前工作区** （推荐）：将 /work/app 切换到 feature/export，快进到已验证目标，并验证原有状态得到保留。
- B． **创建工作区** ：在固定目标上使用 review/export 创建 /work/app/.worktrees/export-review，评估其环境，并保留当前检出。
- C． **快照审查** ：审查固定 PR 内容，不改变当前工作区。

**用户：** 创建。

**Agent：** 已验证所选工作树、分支映射、目标和环境。审查将使用 /work/app/.worktrees/export-review。

用户的选择确定了具体工作区和分支操作。随后 Agent 验证创建结果，而不是把拟定路径当作工作区已经就绪的证据。

## 无法建立 Viewed 筛选

另一个 PR 审查已取得固定源码版本，但经过已授权的获取操作，仍拿不到已认证查看者的完整文件状态。这里没有任何待用户补充的事实能解决获取失败。

**Agent：** 我已取得固定 PR 内容，但无法确定你已标记为 Viewed 的文件。是否跳过该筛选，审查其他条件均符合的全部非测试文件？

**用户：** 不，保留 Viewed 筛选。

扩大后的范围仍未被选择。Agent 保留固定比较，并说明在完整 Viewed 证据可用前，无法继续这个带筛选的审查。它既不悄悄纳入所有文件，也不把未见内容描述为没有问题。

## 分支比较没有已确认的基准

用户要求审查 `feature/export`，却未指定基准，仓库现有证据也无法确定基准。

**Agent：** feature/export 应与哪个分支比较？

**用户：** release。

验证后发现，与 `release` 的 merge-base 就是被审查分支的顶端。Agent 报告该比较没有改动，不给出进度分数或动作菜单。用户的回答确定了比较方式，并没有凭空产生待审查文件。
