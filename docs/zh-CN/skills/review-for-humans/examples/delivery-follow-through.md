# 在新发现和部分完成效果中持续完成选定交付

这个虚构 PR 审查的进度为 4 / 9 个文件。已展示分组没有未解决发现，但选定工作区中还有未审查的已暂存删除。用户尚未选择交付。

## 提供会由通过启动的工作

- A． **通过** （推荐）：清点并审查剩余交付范围，完成检查，提交并发布完整待发布改动，记录合格 Viewed 文件，然后从保存的下一组位置继续。
- B． **继续** ：不交付，审查下一组，保持已暂存删除不变。

**用户：** 通过。

清单现在包含已暂存删除、一个未发布提交，以及来自另一段对话的测试。即使主审查筛选没有展示这些内容，它们仍进入交付覆盖。如果补充审查和检查没有发现新的可操作项，Agent 就完成已选交付，不再询问一次通过。

## 补充审查发现缺陷和可选简化

在这个分支中，删除仍在使用的导出破坏了既有调用者（M11），而另一个已改文件重复实现了可以安全复用的格式化器（M12）。补充报告解释这两项之后，提供：

- A． **修复** （推荐）：恢复 M11 受支持的导出，检查修复并复审受影响调用者；M12 仍待决定。
- B． **优化** ：实施 M12 的格式化器简化，检查并复审；M11 仍未解决。
- C． **忽略** ：保留 M11 已破坏的调用者和 M12 重复的格式化器，接受已说明的后果。

**用户：** 修复 M11。

修复检查和专门复审通过后，M12 仍待选择。Agent 提供优化 M12，或忽略其重复格式化器的选择；它不再次询问通过。

**用户：** 暂时保留重复。

M12 的负担继续记录为已接受。两项决定都已解决，且必要覆盖与检查全部完成后，Agent 恢复原有提交、发布及 Viewed 工作，然后从保存的位置推进。

## 原请求是只交付

如果用户在第一次选择时说的是“交付你说明的完整范围，但不要开始下一组审查”，仍需完成相同的清单、补充发现处理、检查和修复。完成后，Agent 会停留在 4 / 9，而不是开始下一组。保留的请求决定最终位置；解决 M11 和 M12 并不另行构成继续指令。

## 未选择交付时的部分处理请求

在另一个分组中，M2 可能遗漏承诺的 flush，而 M7 有证据支持的清理简化。用户说：“先只优化 M7。”Agent 修改并复审 M7，报告已消除的负担和检查结果，同时保持 M2 的 flush 缺陷可见。用户没有选择交付或推进，因此该优化结束于更新后的决定。

## 范围冲突或发布失败中断交付

在已暂存删除清单的另一个分支中，用户此前明确要求保留一个导出的测试夹具，但暂存改动删除了它。Agent 无法推导出同时满足两者的完整最终版本。它指出该夹具，并询问应交付哪种预期内容；用户负责的选择尚未解决时，通过继续待完成。

如果范围已经确定，但发布不可用且没有受支持的恢复路径，Agent 就报告这一外部阻碍及已确认的本地状态。选定的通过仍待完成；将它换成继续，会在未经选择的情况下改变用户请求的效果。如果尚未选择交付，同样的发布限制仍可能允许提供只读的继续选项。

## 记录范围大于最近展示的一组

稍后的 PR 审查中，九个主文件和一个补充生产文件都已获得完整、当前的 PR 差异覆盖。其中四个主文件此前通过继续推进。此时只剩记录操作。合格 Viewed 集合包含全部十个文件，而主进度保持 9 / 9；未审查测试和仅覆盖修复片段的文件仍不标记。

在一个部分成功的分支中，提交和推送已确认，十个 Viewed 更新中有六个成功。Agent 报告其余四个待完成，核对它们在 GitHub 上的实际状态，然后恢复记录。它不重复已确认的提交或推送。运行中断后，保留的版本、查看者、路径集合和已确认结果确定了剩余工作。

## 本地交付选择的效果更少

另一位用户请求准备本地提交。一个标签改动就是完整交付清单，其检查与审查均已就绪，也未请求远端发布。在范围结束处，通过会提交、验证并结束；结束则让改动保持未提交。本地选择不会从上述 PR 情景继承 PR 发布或 Viewed 效果。
