# 对话示例

这些合成案例说明判断和转换，不是执行记录，也不能证明模型普遍可靠。[Skill 入口](../SKILL.md)负责决定，[报告格式](../references/report-format.md)负责呈现，准备和交付指南负责各自条件分支。

## 一份完整文件报告

前提：固定 PR 比较中只剩一个生产文件。检查在作者总结遗漏的清理编辑中发现取消回归。下方链接和源码用于示意。

**助手：** 最后一组包含剩余的非测试文件。

---

📄 **[src/editor/save_controller.dart](http://127.0.0.1:47821/diff?example=complete-report)**

这个控制器保存草稿并报告进度。本次改动标明已保存草稿，并移动等待状态的清理。

⚖️ **不合理** — M1 标明已保存草稿。M2 是 P2：取消操作现在跳过等待状态重置，使下次保存一直不可用。应恢复这个退出路径的清理。

🎨 **需要改进** — M2 将同一清理职责分散到成功和失败分支，并遗漏取消路径。统一收尾块可以覆盖每种退出，减少重复维护。M1 没有引入新边界。

**M1 — 标明已保存草稿**

> ⏪ 状态只说明动作：`status = 'Saved';`。
>
> ⏩ 状态包含已有草稿名称：`status = 'Saved ${draft.name}';`。

**M2 — 将清理移入结果分支（P2）**

> ⏪ 每次保存尝试结束后，统一收尾块清除等待状态。
>
> ```dart
> pending = true;
> try {
>   if (cancelled) return;
>   await persistDraft(draft);
> } finally {
>   pending = false;
> }
> ```
>
> ⏩ 取消检查后，成功和失败分别清理状态。
>
> ```dart
> pending = true;
> if (cancelled) return;
> try {
>   await persistDraft(draft);
>   pending = false;
> } catch (_) {
>   pending = false;
>   rethrow;
> }
> ```

---

**已展示 1/1 个主文件。** 源码与控制流检查确认 M2 的取消缺陷和清理负担。尚未运行修复检查；统一清理归属可以同时解决两项发现。

- A. **修复并优化** （推荐）：恢复 M2 的统一清理，运行必要检查，单独展示其复审。
- B. **忽略** ：不修改 M2，接受下次保存不可用的风险及重复清理负担。

## 判断是否需要这项能力

| 已确定证据 | 判断的决定因素 |
| --- | --- |
| 写入需要原子可见性，现有库事务已经保证。新增快照层重复了该保证，增加第二个状态归属，且故障注入测试通过。 | 删除快照层才是相关的更小方案。重复归属构成 **需要改进** 的依据；测试不能证明存在额外需求。 |
| 解析器现在拒绝更多值，但任务和调用方证据没有确定更强策略是否需要。 | **证据不足** 指出缺失的契约或使用依据。整洁适配器及其拒绝测试都不能确定是否应增加严格行为。 |
| 不可信输入可以请求无界内存分配；服务必须保持可用，而库没有提供边界。 | 可信触发条件及影响足以证明限制有必要，无需以前发生过事故。比较足够的实施机制；保留默认行为会遗漏需求。 |

## 区分准备与不可用

前提：PR 文件进度为 4/9，没有待处理发现，也没有选定交付。工作区还包含暂存删除。

| 调查后的证据 | 响应 |
| --- | --- |
| 删除在已披露工作区内，没有排除项或保全冲突。 | 完成其非测试补审和全范围检查。提供 A **通过** ，说明准备好的提交、发布、Viewed 效果及下一组；再提供 B **继续** ，进入该下一组但不交付。中文 B 项以 **继续** 开头，后写效果。 |
| 用户明确要求将删除保留在交付之外，且无法推导预期解决方式。 | 准备具体交付选择前，直接询问如何解决保全冲突。未回答的决定不是已验证的交付限制。 |
| 完整准备确认必要发布接口不可用，审查本身仍有效。 | 解释限制，提供 **继续** 。如果通过原本已待完成，则保留它并报告阻塞，不替换为推进。 |

## 遵循选定意图

以下是简略决策说明。实际补审和修复报告仍使用完整固定文件布局。

| 情况 | 决定与结果 |
| --- | --- |
| 文件进度为 4/9，只剩 M8 可选重命名，用来显式标明毫秒。检查和覆盖就绪，只剩 Viewed 记录。 | 提供 **优化** ，再提供 **通过** 并明确保留 M8 的单位查阅成本、记录合格文件，然后提供 **继续** 并保持建议待处理。优化后检查并独立报告，进度仍为 4/9；随后通过包含任何新提交或推送。 |
| 本地标签编辑是完整交付清单；检查和覆盖就绪，未选发布。 | **通过** 执行提交、验证并结束； **结束** 保留未提交编辑。 |
| 进度 4/9 时只交付待完成。清单发现未发布提交、暂存生产工作和另一对话的测试。补审发现 M11。 | 清点并检查全部内容，对未覆盖非测试内容做语义审查，展示 M11 的补救或明确 **忽略** 。解决、检查并独立复审后，恢复交付并停在 4/9。 |
| M2 可能遗漏承诺的 flush，M7 重复清理。没有待完成交付，用户说“先只优化 M7”。 | 修复并复审 M7；下一决定仍针对 M2。子集请求不提供交付或推进权限。 |
| 九个主文件及一个补充生产文件都已覆盖完整当前 PR 差异，四个主文件此前通过继续推进。只剩记录。 | Viewed 覆盖全部十个合格路径，进度仍为 9/9。未审查测试和仅修复片段保持未标记。选定通过后，回读十个路径及未变 PR 版本，再结束。 |
| 通过已提交并推送，但四个 Viewed 路径只有两个结果已确认。 | 报告已确认、未知和待完成效果。受支持恢复时，检查实际标记、补足缺失效果，回读完整集合和版本后再推进。重复提交或推送不能修复不确定结果。 |
| 没有待处理 M 问题；O1 有依据充分的标准化简化方案。交付已准备但未选定。 | 提供 **优化 O1** ，再提供 **通过** 且不改 O1，然后提供 **继续** 。选择含义唯一的优化后，单独报告 O1，不增加 M 编号或进度，其改动进入交付覆盖。 |
| 必要主发现与 O1 有依据的优化并存。 | 推荐主补救，提供明确 **忽略** ，再提供 **优化 O1** 并说明主问题仍在。O 建议不能替代必要补救。 |

## 保持工作区替代项可见

前提：相关 checkout 在 main 且干净，可以安全切换到 PR 源并快进到固定目标。没有合格现有工作树，但新建和固定快照审查可用。

**助手：** 当前 checkout 在 main，PR 使用 feature/export。

- A. **切换当前工作区** （推荐）：将 /work/app 切换到 feature/export，快进到已验证目标，验证保全状态。
- B. **新建工作区** ：在 /work/app/.worktrees/export-review 创建工作树，目标为固定版本，分支为 review/export；评估环境并保留当前 checkout。
- C. **快照审查** ：审查固定 PR 内容，不改变当前工作区。

**用户：** 新建。

**助手：** 已验证选定工作树、分支映射、目标和环境。将从该路径审查。

## 询问缺失决定

经授权获取后仍无法取得完整 Viewed 状态，也没有缺失用户事实能解决限制。固定比较证据就绪时，询问是否愿意不使用该筛选，审查所有其他合格非测试文件。拒绝意味着未选择扩大范围。

分支审查没有已确定比较基准时，询问要与哪个分支比较。已验证 merge-base 若等于被审查顶端，报告没有改动，不显示进度比例或虚构菜单。
