# 对话示例

这些合成案例说明判断和转换，不是执行记录，也不能证明模型普遍可靠。[Skill 入口](../SKILL.md)负责决定，[报告格式](../references/report-format.md)负责呈现，准备和交付指南负责各自条件分支。

## 一份完整文件报告

前提：固定 PR 比较中只剩一个生产文件。检查在作者总结遗漏的清理编辑中发现取消回归。下方链接和源码用于示意。

**助手：** 最后一组包含剩余的非测试文件。

---

📄 **[src/editor/save_controller.dart](http://127.0.0.1:47821/diff?example=complete-report)**

这个控制器保存草稿并报告进度。本次改动标明已保存草稿，并移动等待状态的清理。

⚖️ **不合理** — M1 标明已保存草稿。M2 是 P2：取消操作现在跳过等待状态重置，使下次保存一直不可用。应恢复这个退出路径的清理。

🎨 **需要改进** — M2 将清理分散处理，导致取消路径缺少负责重置等待状态的清理逻辑。恢复统一收尾块可覆盖每个出口并消除重复维护，这是 M2 必要修复的一部分。M1 没有引入新边界。

**M1 — 标明已保存草稿**

> ⏪ 状态只说明动作：`status = 'Saved';`。
>
> ⏩ 状态包含已有草稿名称：`status = 'Saved ${draft.name}';`。

**M2 — 将清理移入结果分支（P2）**

> ⏪ 每次保存尝试结束后，统一收尾块清除等待状态。
>
> ```dart
> pending = true;
> try {
>   if (cancelled) return;
>   await persistDraft(draft);
> } finally {
>   pending = false;
> }
> ```
>
> ⏩ 取消检查后，成功和失败分别清理状态。
>
> ```dart
> pending = true;
> if (cancelled) return;
> try {
>   await persistDraft(draft);
>   pending = false;
> } catch (_) {
>   pending = false;
>   rethrow;
> }
> ```

---

**已展示 1/1 个主文件。** 源码和控制流检查确认 M2 的取消缺陷与清理负担。尚未运行修复检查；统一清理归属可同时处理同一缺陷的行为和结构部分。

- A. **修复** （推荐）：恢复 M2 的统一清理，运行必要检查，并展示独立复审。
- B. **忽略** ：不修改 M2，接受下次保存不可用的风险及重复清理负担。

## 判断是否需要这项能力

| 已确定证据 | 判断的决定因素 |
| --- | --- |
| 写入需要原子可见性，现有库事务已保证。新增快照层重复该保证，增加第二个状态归属，并通过故障注入测试。 | 删除快照层是相关的更小方案。如果没有已确立的要求必须将其删除，重复归属支持 **可选改进** ；测试不能建立额外需求。 |
| 解析器现在拒绝更多值，但任务和调用方证据没有确定更强策略是否需要。 | **证据不足** 指出缺失的契约或使用依据。整洁适配器及其拒绝测试都不能确定是否应增加严格行为。 |
| 不可信输入可以请求无界内存分配；服务必须保持可用，而库没有提供边界。 | 可信触发条件及影响足以证明限制有必要，无需以前发生过事故。比较足够的实施机制；保留默认行为会遗漏需求。 |

## 交付准备前提供通过

前提：PR 文件进度为 4/9，没有待处理发现。选定工作区还有尚未审查的暂存删除。

| 交付意图及证据 | 响应 |
| --- | --- |
| 用户只请求审查；交付准备尚未开始。 | 提供 A **通过** ，准备并交付选定工作区全部未交付改动、发布完整待发布范围、记录合格 Viewed 路径并推进；B **继续** ，不交付而审查下一组。暂存删除不会隐藏通过。 |
| 用户选择通过。暂存删除的补审没有发现可处理缺陷或可选改进。 | 完成全范围检查和剩余准备，披露具体方案，按适用情况提交、推送和记录，验证效果后推进。不再次询问通过。 |
| 用户选择通过。补审发现 M11 的契约缺陷及 M12 的可选简化。 | 暂停写入，提供 A **修复** 、B **优化** 、C **忽略** ，列明各自范围。一次选择只处理所选条目；两项决定及必要检查都完成后，恢复原交付。 |
| 已选交付，但明确请求将这些删除排除，且无法推导应如何处理。 | 直接询问如何解决保全冲突。属于用户决定的范围事项未解决期间，保留待完成的通过。 |
| 已验证的发布限制阻止交付，但审查本身仍有效。 | 尚未选择交付时，解释限制并提供 **继续** 。通过已经待完成时，保留它并报告阻塞，不替换为推进。 |

## 每类动作保留一个选项

前提：M21 有可选简化。O1 和 O2 是无关且有依据的优化建议，没有待处理主缺陷。

- A. **优化** （推荐）：实施 M21 的简化，再检查并复审。也可以明确按编号选择 O1 和 O2；它们不在该选项默认的 M21 范围内。
- B. **通过** ：保留 M21 已评估的取舍，准备并完成适用交付，再推进。O1 和 O2 保持未选定。
- C. **继续** ：不交付而审查下一组，M21 保持待处理。

**用户：** 优化 O1 和 O2。

**助手：** 选定的 O 修复使用 O 编号，单独检查并复审。主进度不变；产生的改动进入后续交付覆盖。

## 完成一次局部修复

前提：用户选择修复上文的 M2，没有请求交付。没有实质设计选择、契约变化或风险需要展开完整报告。链接与结果均为示意。

**助手：** **M2 已解决** — [src/editor/save_controller.dart](http://127.0.0.1:47821/diff?example=repair-report)。恢复 `finally` 块，统一在成功、失败和取消时清除等待状态。

⚖️ **合理** — 取消操作不再阻止下一次保存。既有的完成和失败行为得到保留。

🎨 **优雅** — 共享清理逻辑消除了重复的结果分支，并覆盖所有退出路径。

项目必要检查已在修复后的内容上通过，覆盖保存成功、失败、取消及改动完整性。独立复审覆盖修复及受影响的已审查保存调用方。[验证证据](http://127.0.0.1:47821/evidence?example=repair-checks)记录所用验证方式、结果和可用日志。

修复已完成，没有新发现。这是最后一个主文件；交付仍待选择。

- A. **通过** （推荐）：准备并交付工作区全部未交付改动，将完整待发布范围发布到 PR 源，记录合格 Viewed 路径，回读验证后结束。
- B. **结束** ：结束本次审查，不交付。

## 保持工作区替代项可见

前提：相关 checkout 在 main 且干净，可以安全切换到 PR 源并快进到固定目标。没有合格现有工作树，但新建和固定快照审查可用。

**助手：** 当前 checkout 在 main，PR 使用 feature/export。

- A. **切换当前工作区** （推荐）：将 /work/app 切换到 feature/export，快进到已验证目标，验证保全状态。
- B. **新建工作区** ：在 /work/app/.worktrees/export-review 创建工作树，目标为固定版本，分支为 review/export；评估环境并保留当前 checkout。
- C. **快照审查** ：审查固定 PR 内容，不改变当前工作区。

**用户：** 新建。

**助手：** 已验证选定工作树、分支映射、目标和环境。将从该路径审查。

## 询问缺失决定

经授权获取后仍无法取得完整 Viewed 状态，也没有缺失用户事实能解决限制。固定比较证据就绪时，询问是否愿意不使用该筛选，审查所有其他合格非测试文件。拒绝意味着未选择扩大范围。

分支审查没有已确定比较基准时，询问要与哪个分支比较。已验证 merge-base 若等于被审查顶端，报告没有改动，不显示进度比例或虚构菜单。
