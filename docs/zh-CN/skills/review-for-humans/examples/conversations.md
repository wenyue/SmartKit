# 对话示例

Skill 入口负责普通审查循环，[报告格式](../references/report-format.md)负责固定呈现，准备与交付指南负责各自条件分支。这些合成场景代替检查证据。完整报告使用占位的返回链接和示意源码，不是执行记录，也不是模型普遍可靠的证据。

## 一份完整报告

场景：PR 最后一组只有一个符合条件的生产文件。检查覆盖其完整 diff 及必要上下文，包括作者总结遗漏的清理编辑。下方源码是合成的固定比较。

**Agent：** 固定 PR 比较已就绪。本组包含剩余的非测试文件，测试不进入报告。

---

📄 **[src/editor/save_controller.dart](http://127.0.0.1:47821/diff?example=complete-report)**

这个控制器负责保存草稿并显示进度。本次改动标明了已保存草稿的名称，并移动了等待状态的清理代码。

⚖️ **不合理** — M1 让用户知道保存的是哪份草稿。M2 是 P2：取消操作现在跳过等待状态重置，导致下一次保存仍不可用。应恢复这个退出路径的清理。作者总结虽然漏掉了这处编辑，缺陷仍须由明确条目覆盖。

🎨 **需要改进** — M2 需要优化：成功和失败分支重复承担同一清理职责，还漏掉了取消路径。统一收尾可以覆盖每种退出，并减少重复维护。M1 无需新增边界。

**M1 — 标明保存的草稿**

> ⏪ 状态文字只说明动作：`status = 'Saved';`。
>
> ⏩ 状态文字带上已有草稿名称：`status = 'Saved ${draft.name}';`。

**M2 — 将清理移入结果分支（P2）**

> ⏪ 统一收尾块在保存尝试结束后清除等待状态。
>
> ```dart
> pending = true;
> try {
>   if (cancelled) return;
>   await persistDraft(draft);
> } finally {
>   pending = false;
> }
> ```
>
> ⏩ 成功和失败分支分别清理状态，取消判断位于它们之前。
>
> ```dart
> pending = true;
> if (cancelled) return;
> try {
>   await persistDraft(draft);
>   pending = false;
> } catch (_) {
>   pending = false;
>   rethrow;
> }
> ```

**已展示 1/1 个主审查文件** 。源码与控制流检查支持 M2 的 P2 取消缺陷和重复清理负担；尚未运行修复后的检查。统一清理归属可以同时处理两者。

- A. **修复并优化** （推荐）：恢复 M2 的统一清理，运行必要检查，再单独展示这个文件的复审。
- B. **忽略** ：不修改 M2，明确接受下次保存不可用的风险和重复清理的负担。

## 用简短场景说明选择与转换

以下独立场景是简要说明，不是完整审查回复。它们省略重复文件块，聚焦决策；实际补审、主项修复及选定 O 项复审，仍须完整展示固定布局，才能继续依赖它的动作。

## 工作区替代方案保持可见

场景：当前相关 checkout 干净且在 main，可以安全切换到 PR 源分支并快进到固定目标。没有其他符合条件的现有工作区，创建和固定快照审查都可用。

**Agent：** 当前 checkout 在 main，PR 使用 feature/export。

- A. **切换当前工作区** （推荐）：将 /work/app 切换到 feature/export，快进到已验证目标，验证原状态保全。不推送。
- B. **新建工作区** ：在 /work/app/.worktrees/export-review 创建工作树，分支为 review/export，目标为固定版本；评估环境并保留当前 checkout。
- C. **快照审查** ：审查固定 PR 内容，不改变当前工作区。

**用户：** 创建。

**Agent：** 已验证选定工作树、分支映射、目标及环境。接下来从该路径审查。

## 筛选缺失需要同意，不自动扩大范围

场景：固定 PR 证据已就绪，但已授权获取仍无法取得完整 Viewed 状态，也没有用户提供的事实能解决此限制。

**Agent：** 完整 Viewed 筛选暂不可用。是否愿意不应用这个筛选，审查固定版本中所有其他符合条件的非测试文件？

**用户：** 不了，先停在这里。

**Agent：** 已停止，比较证据已保留；尚未审查任何文件，也未选择扩大范围。

## 直接询问缺失事实

分支审查没有已确定比较基准时，直接问“应该与哪个分支比较？”用户选择 release 后，求出已验证的 merge-base。如果它等于被审查顶端，报告没有改动，不显示进度比例或虚构动作菜单。
