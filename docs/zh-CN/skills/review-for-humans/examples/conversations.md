## 判断是否需要这项能力

| 已确定证据 | 判断的决定因素 |
| --- | --- |
| 写入需要原子可见性，现有库事务已保证。新增快照层重复该保证，增加第二个状态归属，并通过故障注入测试。 | 删除快照层是相关的更小方案。如果没有已确立的要求必须将其删除，重复归属支持 **可选改进** ；测试不能建立额外需求。 |
| 解析器现在拒绝更多值，但任务和调用方证据没有确定更强策略是否需要。 | **证据不足** 指出缺失的契约或使用依据。整洁适配器及其拒绝测试都不能确定是否应增加严格行为。 |
| 不可信输入可以请求无界内存分配；服务必须保持可用，而库没有提供边界。 | 可信触发条件及影响足以证明限制有必要，无需以前发生过事故。比较足够的实施机制；保留默认行为会遗漏需求。 |
