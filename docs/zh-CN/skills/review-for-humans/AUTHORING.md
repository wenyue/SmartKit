# 编写决策

## 将普通审查决策保留在一起

入口沿着用户的工作展开：确定上下文，检查并判断，解释完整文件分组，再处理选择和恢复。标准、必须披露的信息、M/O 身份、分组、进度、动作含义、优先级和待完成意图保留在一起。通用链接生成仍在入口；PR 专属身份和展示上下文则归准备指南。

## 为报告呈现确定唯一归属

[报告格式](references/report-format.md)负责完整模板、呈现规则、说明深度和发送前格式检查。将这些细节保留在一起，让入口的审查决策更易理解，也避免将呈现规则混入准备或交付。每类报告前都必须阅读这份参考文档，普通审查也不例外；这增加了必读步骤，而不是减少普通审查所需的总材料。格式不可用时，暂停依赖它的报告。检查和完整发现披露仍在入口，精简呈现不能降低审查强度。

## 在条件分支入口加载对应知识

准备指南负责 PR 或远端证据、Viewed 筛选和工作区选择。交付指南负责完整提交或发布覆盖、就绪条件、写入、回读，以及核对实际效果。入口决定用户请求了什么、是否推进；交付指南报告哪些已就绪或实际发生了什么。这个边界防止推送中断或补审发现抹去待完成的通过请求，同时不重复定义对话规则。

助手的 CLI 帮助在可执行接口旁承接机械能力、请求字段、状态、输出和重试说明，不再用助手参考文档重复接口。交付指南仍决定语义覆盖和已授权效果，包括助手无法表达完整计划、需要手动路径的情况。接口说明迁入帮助不改变执行逻辑，也不让助手承担语义审查。

## 区分检查覆盖与报告粒度

实际非测试改动及必要上下文决定审查覆盖。两个前置判断让用户先看到评估，再看实现对比；其中保留关联条目编号的完整发现。报告格式负责固定骨架、完整路径标题段落和每个文件边界，引用块中的对比则按理解难度呈现实现。精简报告和分组不能隐藏或平均掉局部问题。示例说明这个契约，不另建一套。

## 根据事实与保留意图推导选择

稳定动作含义和简短有序决策表让推荐可预测，无需穷举每种对话。准备指南的工作区优先级服务于另一类决定，不等同于审查补救优先级。事实和外部阻塞不是菜单。不提供常规停止选项让选择聚焦工作，同时保留明确用户控制和安全停止；推荐从不等于授权。

全工作区交付与主阅读顺序的范围不同。测试文件仍进入提交和检查，但不进行语义审查；未审查测试不会因检查通过获得 Viewed 资格。通过组合交付与推进，只交付具有相同效果但停留原处。补审发现暂停该意图，直到问题解决或被明确保留；既不取消意图，也不自动接受问题。

## 让示例说明不同转换

一份紧凑的完整报告展示报告格式。独立对话示例再用短场景和明确节选，展示有意义的选择、效果和下一位置，不重复整份报告。场景前提保留动作可用条件。示例不削弱完整补审或修复报告要求，不拥有规则，也不证明模型普遍可靠。
