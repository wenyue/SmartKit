# 编写决策

## 区分审查、发布和 Viewed 范围

展示的审查会排除部分分支内容；发布可在必要检查与同意后纳入这些内容；Viewed 则证明特定 PR 版本上的整个文件已获审查覆盖。合并这些范围，要么会掩盖待发布内容，要么会把未展示的改动块标成已审查。提交后仍保留固定证据，使工作树变干净后，尚未展示的分组依然可以审查。

## 保持合理性与优雅性独立

合理性判断受支持的行为、契约、范围和实际后果。主审查 Agent 通过相关上下文阅读和设计比较，在优雅性上投入更多精力，因为结构债务的纠正成本很高；这不要求委派，也不要求报告更长。必须处理的优雅性问题需要优化或明确接受保留后才能推进，值得实施的有限调整仍为可选项，个人偏好和低收益润色则会被过滤。保持两个判断独立，使有证据支持的结构负担得到实质重视，同时避免把缺少额外防御或个人偏好当成正确性缺陷。

## 将完成操作设计为可恢复的过程

提交、推送和 Viewed 记录可以分别成功。中断后，已选完成操作仍保留其范围和剩余步骤；普通继续不能替代未完成的完成操作。明确的回读和精确的预期远端身份，有助于防止重复写入或无依据地声称已经审查。

## 保留展示不同状态的菜单示例

示例覆盖了就绪程度和授权实质不同的状态，包括部分暂存、额外待推送提交、同一文件中尚未覆盖的改动块，以及部分完成的 Viewed 记录。这些差异决定了可用操作。状态图标和可复用的收尾版式是便于比较重复分组的建议，必要的审查内容与操作契约另行保留。灵活调整表达，可以避免机械重复，同时保留这些有用的默认做法。单一的通用收尾还会掩盖范围和恢复条件的区别。
