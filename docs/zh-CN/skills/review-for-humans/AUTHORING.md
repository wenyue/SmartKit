# 编写决策

## 将决策循环放在一处

入口负责评估、发现、用户意图及推进。准备指南处理有条件的 PR 和工作区分支，交付指南负责清单、实际效果及恢复。交付返回就绪状态和已观察结果，不判断用户请求。这种分工避免写入中断或补充发现悄然替换待完成的通过。

原则处理不常见情况，四张常见情况表在实际决策点稳定推荐动作和顺序。每类动作占一个选项，编号界定其范围。将每条发现都列成选项，会重新产生多个优化选项，模糊用户要做的决定。

通过同时选择交付准备和适用效果。如果要求准备完成后才提供通过，就会在普通审查和修复后隐藏该选择。补审的新发现让写入暂停并等待决定，而原选择继续待完成，解决发现后无需第二次通过。

必要性与实现属于同一评估路径。拆成独立清单，会让经充分测试的机制在其能力用途尚无依据时就得到优雅性结论。

## 为呈现指定唯一归属

报告格式为普通审查、补审、修复和选定 O 项报告统一负责按文件展示的布局、条目详略、收尾顺序及菜单呈现。入口保留评估、身份、动作语义和选项顺序。独立的修复摘要格式曾导致呈现不一致，也容易隐藏配套改动；逐项选择详略，让简洁报告仍保持相同的可见覆盖范围。

一份完整普通报告和一份完整多文件修复报告展示统一布局，包括省去重复标题的简洁项。简略转换说明其他决定，无需逐一复制完整报告。示例和这些记录解释设计；操作要求仍归入口和报告格式所有。

## 区分进度、覆盖与效果

主进度遵循固定比较。交付可能需要更多非测试审查，但不改变该顺序；测试属于清单和检查，而非语义覆盖。Viewed 依赖完整 PR 文件评估，不取决于展示进度或检查成功。区分这些范围，避免全工作区交付标记部分审查文件或丢失尚未展示证据。

修复过程中，既有发现编号保持稳定，其他需要单独解释的 M 改动使用下一个尚未分配的编号。两者的关系在修复引言中说明，不重复条目标签，也不另设编号体系。因此，最大的 M 编号不等于主进度计数。选定 O 项的配套文件使用文件说明，不新增 M 编号或虚构顺带观察，从而保留用户选定的独立范围。

入口保留待完成的通过还是只交付，交付指南保留实际已完成及不确定效果。两类记录各司其职，使恢复不重复发布，也不意外推进。

## 将机械接口留在实现旁

辅助程序的 CLI 帮助负责能力、请求结构、状态、输出和重试。交付指南保留语义覆盖与授权效果要求，为不受支持方案提供手动路径。在另一份参考文档复制 CLI 细节，只会增加第二份接口规范，不能使辅助程序成为语义审查者。

效果模式冻结用户选定的历史变更。传输方式留作运行时选择，使 Git 端点受阻后可以在恢复时绕过它，无需另建发布方案。两条路径绑定同一组对象和预期旧引用。API 对象重建会验证精确 SHA，并在改变引用前拒绝无法复现的元数据，从而保留恢复与审查证据要求的身份。
