# 面向人类的审查

帮助用户理解所选改动，判断其合理性与优雅性。先建立固定证据，检查关联实现，按完整文件分组解释，再执行选定操作。审查授权采集证据和准备链接，不授权修改被审查文件、真实暂存区、分支、发布状态或 Viewed 状态。

普通审查与沟通留在这里。为 PR 或需对齐远端的分支准备工作区或生成链接前，阅读[工作区](references/workspace.md)。准备或提供完成效果、执行或恢复未完成操作前，阅读[完成操作](references/completion.md)。这些指南负责对应分支的选择与验证。必要指导不可用时，依赖工作不能视为完成。

## 选择有用的回应

提问前先做已授权且可推导的工作：查可访问的事实、准备链接、运行检查、复审受影响内容。范围清楚时，简短说明后直接开始，不让用户选择是否获取你自己能查到的证据。

只有用户知道必要事实时，直接问具体内容：“这次要和哪个分支比较？”选择缺编号时，问“M2、M5，还是全部？”，不套用提供信息、取消、停止三选菜单。先应用已规定的默认范围；编号可以补足已明确的待处理动作，但本身不选择动作。只澄清未解决部分，保留分组、此前授权和未完成的完成操作。撤回这个请求不取消更早已选的工作。

只有涉及效果或取舍的真实选择才用菜单。按规定顺序展示全部适用选择，不能因为推荐某项就省略其他项。核实会实质影响选择的事实，并说明已知限制。尚未检查或仍未知不等于不可用。先说明具体情况，推荐项放在 A；每项以加粗的短动作词开头，再写这一次的实际效果。

- A. **通过** （推荐）：将这四个文件标为已查看，核验它们和 PR 版本，再展示下一组。

提交、推送和 Viewed 效果写在说明中，不藏在单独的“通过”二字后，也不把整个操作句放进粗体。

字母不区分大小写，按最新适用菜单解释。接受对已披露效果的明确自然语言和复合请求。M/O 编号选择条目，不选择动作。提问或异议不授予写入权限。已选动作就绪后直接执行，不例行重新确认。用户始终可明确停止或暂停，并如实报告残余工作。

没有可执行选择时，报告结果或具体阻塞。说明什么已成功、什么失败或尚不确定，以及还剩什么。不虚构等待或授权菜单，也不暗示持续监控。完成操作未结束时，进一步行动前遵循完成操作指南。

## 固定比较与证据

| 请求 | 比较 |
| --- | --- |
| PR | 验证所属仓库、源仓库和源分支，准备工作区，固定 base/head，再应用已认证查看者的文件级 Viewed 筛选。 |
| 分支 | 固定分支顶端及其与可靠比较基准的 merge-base。补足未知基准，不假定为 `main`。 |
| 本地改动或未明确指定范围 | 比较暂存区与工作树，仅审查未暂存改动。 |
| 指定文件 | 将适用比较筛选到这些路径。 |

明确指定 PR 或分支比较时，除非另有要求，否则排除本地未提交改动。遵守选定的历史版本；其他审查指导默认范围不同时，保留此范围。

本地审查跳过仅已暂存改动，只评估部分暂存文件中的未暂存部分。在工作树中撤销暂存内容，仍属于未暂存改动。只有明确要求时才将未跟踪文件作为新增文件纳入。明确选择其他比较方式时覆盖这些默认值。

对 PR，获取当前已认证查看者完整的文件状态，完成所有分页，并核验 base/head 保持不变。排除 `VIEWED`，纳入 `UNVIEWED` 和 `DISMISSED`。审批、评论、先前聊天展示，以及历史快照对应的当前状态，都不能建立所需筛选。要求包含已查看文件时覆盖该筛选。

已授权获取后，完整 Viewed 筛选仍不可用时，先直接询问真正必要的用户事实。否则，固定比较证据就绪时，真实选择是 A **全量** （推荐）：不筛选并审查所有其他符合条件文件；B **停止** 。不虚构历史或当前 Viewed 状态。

测试不进入文件报告、修改项计数或进度，但相关测试可作为证据。先应用指定文件、Viewed 和本地范围筛选，再计数。这些筛选不缩小后续整分支提交或检查的范围。按 GitHub 目录树排列：递归列出子目录中的改动文件，再列出直接文件；沿用可观察的同级顺序，否则分别按名称排序同级目录和直接文件。因此 `src/z/api.dart` 排在 `src/a.dart` 前。

保留固定提交、固定的修改前后内容、有序文件清单，以及 PR 查看者和筛选证据。本地审查还要保留原始暂存区基准，即使选择了其他修改前版本。第一组前说明范围与排除项。比较为空时直接结束，不显示进度比例或虚构文件。

已知文件即使证据不全也保留在总数中。为受影响判断指出缺失证据；暂停依赖它的审查，不把未知内容当成干净状态。评估所选改动引入、触发或加剧的缺陷，包括位于未改动代码中的证据。无关既有问题单独作为 O 类观察。

### 将文件名链接绑定到证据

从已加载的 SmartKit 资源中解析 `local_web`，遵循其支持的接口：

```text
python "<local_web>" --help
python "<local_web>" diff --input "<batch.json>"
```

每个被审查文件的文件名链接使用返回的 Markdown，并通过返回 ID 关联。采集快照时一并保留基于暂存区的本地链接；PR 或分支链接按要求提供固定的修改前提交、已有 blob 或真实不存在状态，以及重命名路径和固定 PR 上下文。

历史 PR、选定的固定比较或源身份不可用时，使用 `view="snapshot"` 并提供已验证的固定证据。PR 实时链接使用 `view="worktree"`，将 `repo` 绑定到工作区指导已验证的确切路径，包括已验证的本地别名。仅审查分支时使用已验证的展示工作区，不提供 PR 上下文。说明实时内容中的版本差异或未提交改动；它们不改变被审查版本或 Viewed 资格。

链接失败时暂停依赖它的报告。解决时保留比较和选定模式。生成链接不能证明编辑器已展示内容。

## 检查结果及其实现结构

在优雅性上投入比合理性更多的审查精力。检查相关周边实现、受影响调用方，以及附近或同类模式，不只查看 diff。利用单元及集成测试证据聚焦行为检查，同时仍评估任务结果、已接受范围、契约及运行成本与风险。区分实际检查与作者报告的结果，保留任务或规范方面的实质发现。

对有实质意义的设计选择，先根据任务、契约、实际用法和生命周期确定用户或调用方需要的结果，再选择结构。实现中已有的能力不自动等于需要。比较满足需求的更小设计：删除不必要能力或层次、直接调用或复用已有归属，而不只是重新组织相同功能。追踪每层独有职责。简化后仍须有人承接必要反馈、日志、恢复和生命周期保护；改变受支持的行为或契约属于范围决策，不是保持行为不变的优化。

检查所选范围内的每个新增文件和新声明，包括旧文件中新增的函数、类型、成员和状态。很小的文件和简单转发也增加边界，不能适用直接明了编辑的豁免。新文件需要特别充分的独立职责或边界依据，并说明为何不能放在已有准确归属或局部位置。随实际可达范围和生命周期提高审视要求：公开类型、函数、成员和顶层状态需要充分的调用方或契约依据；私有辅助函数和成员适度检查；普通局部变量无需额外必要性说明。仅凭可见性关键字不能确定暴露范围。

调用方数量、代码简短、统一展示、预期复用或测试便利，本身不足以证明边界有必要。真实职责可以证明只有一个调用方的边界也有必要。源码、任务或契约可能已清楚表明理由；不要求理由注释，也不要求为每个新增项生成报告条目。

### 作出两个独立判断

每个修改项都要有两个明确结论及各自理由，文字和翻译也适用。

| 判断 | 证据及后果 |
| --- | --- |
| ⚖️ **合理** | 实现任务所需结果，符合已接受范围、受支持行为与契约，运行成本和风险有合理依据。 |
| ⚖️ **不合理** (P0–P3) | 存在实质任务、行为或契约缺陷、不必要范围，或不合理运行成本与风险。解释影响及具体修正。 |
| 🎨 **优雅** | 职责、边界与对外接口值得承担其理解和维护成本；表达易读；抽象、状态、分支、重复和防御具有具体收益。接口与已观察的同类模式一致，偏离时有依据。 |
| 🎨 **需要改进** | 存在实质且可避免的理解或维护负担，并有值得承担改动成本的更简单或更一致方案。说明负担、补救和收益；必须优化并复审，或明确接受保留。 |
| 🎨 **可选改进** | 结构已达要求，但有依据的调整能带来值得其有限成本的具体收益。保持可选。 |
| 任一维度的 **证据不足** | 说明缺失的关键证据及补足方式。另一个判断仍可有充分依据。 |

结构负担本身属于优雅性问题，不是合理性缺陷。错误行为也可以有清晰、简练的结构；仅有行为缺陷不能证明结构不好。两个维度分别有证据时可同时不通过。缺少需求或归属证据既不能证明优雅，也不能证明结构缺陷。省略个人偏好与低收益润色，合并同一根本负担的补救措施。

按结构收益评估额外防御检查与兜底。优先依赖既定不变量和边界保证，避免重复校验或推测性恢复。缺少额外保护，只有在存在可信触发条件及可能严重后果时才构成不合理；正常受支持行为和承诺的失败处理仍是正确性义务。

只为不合理发现分配严重级别：P0 关键且需立即处理，P1 严重且需尽快修正，P2 普通优先级，P3 影响较低但值得修正。依据后果和受影响条件判断。必须处理的优雅性问题是实质门槛，不是可选的风格润色。

## 解释完整文件分组

每个文件给出带链接的文件名，简述职责与改动。按解决的问题合并实现步骤；无法用同一简单说明解释的独立改动才拆开。本地化文件算一个修改项。附带小改动可留在概述中或省略。

M 编号跨文件和分组连续，在发现、选择及复审中保留。可使用 `🔧 **M1** - **<title>**`。保留路径和代码自身标点。分别给出理由，通常用 ⚖️ 和 🎨 两段区分判断。

行为直接、范围清楚且没有实质取舍时，通常只需一个简短前后说明和两个判断。机制、契约、发现或证据缺口适合展开，并使用最小而有用的真实前后代码。保留错误、状态和生命周期条件，标明示意性简化并保持行为。一行 diff 也可能需要深入检查，深入检查不意味着报告更长。

在完整展示某文件后，若本组修改项达到至少 10 项，则结束分组；不要拆分文件。范围末尾展示不足一组的内容。进度表示累计已展示文件数占符合条件文件数，不暗示完成操作或 Viewed。主审查文件只计一次。

跨回复保留分组成员、下一位置和 M 编号、证据、判断、发现与决定、已接受取舍、建议和已验证效果。整分支提交使工作树变干净后，仍按保留证据展示未见文件。只有范围实际变化时才调整总数。

### 单独处理顺带观察

只有必要阅读证明既有问题确实存在，且本次改动没有引入、触发或加剧它时，才报告该问题。这不构成扩大审计范围。

使用连续 O 编号。最初放在分组收尾中单独的范围外部分，包含标题、源码位置或链接、证据与影响、独立关系及建议收益。O 项不增加主文件、修改项、进度或 Viewed 资格。建议本身不阻止推进。批量修复、优化、忽略或接受保留不含 O 项；除非用户明确扩大主范围，O 修复需要单独选择、检查和复审。

每组收尾给出结论与进度、实际检查及限制、待处理不合理项的编号严重级别与影响、必须处理的优雅性负担补救及收益、已接受取舍与可选建议，以及单独的 O 类建议。用具体前后因果及用户或调用方后果解释：哪一步被跳过，哪些状态重复，哪个边界没有职责。“符合契约”或“结构清晰”本身不是理由。罕见机制留在内部分析，除非它改变用户的选择。[报告示例](references/report-examples.md)提供完整对话，不定义规则。

## 提供下一个真实选择

先完成可推导准备，区分什么阻止审查，什么只影响拟议写入。正确性或版本证据缺失或过时、必要检查失败或未完成、受影响部分的复审未完成，都阻止推进。仅缺优雅性证据不阻止推进。待处理不合理问题需要修复或明确忽略；必须处理的优雅性问题需要优化复审或明确接受保留，包括之前分组的条目。O 类建议本身不阻止推进。

缺少用户事实时直接问。外部条件没有可执行补救时报告阻塞，不提供无法执行的动作。仍可选择独立且有依据的修复，但说明修复后什么仍会受阻。

使用以下固定分组选择，代入具体编号和效果：

| 情况 | 有序选择 |
| --- | --- |
| 只有待处理不合理问题 | A **修复** （推荐）：修复所列问题、检查并复审；B **保留** ：明确忽略这些问题，保留严重级别与影响；C **停止** ：留下未解决问题并停止。 |
| 只有必须处理的优雅性问题 | A **优化** （推荐）：实施所列补救、检查并复审；B **保留** ：明确接受已披露负担；C **停止** 。 |
| 两类必要问题并存 | A **处理** （推荐）：明确提出修复所列不合理问题 **并** 优化所列必须处理的优雅性问题，再检查复审；B **保留** ：明确提出忽略所列发现 **并** 接受所列结构负担；C **停止** 。 |
| 审查及完成操作均就绪，有已披露效果待执行且无单独纳入决定 | A **通过** （推荐）：执行实际已准备的提交、推送、Viewed 效果，再推进或结束；B **继续** ：不执行这些写入而推进，末组改为 **结束** ；仅在有可选建议时增加 C **优化** 。 |
| 准备后审查可以推进，但无需完成效果，或已验证的仅影响完成操作的限制阻止这些效果 | A **继续** （推荐），末组改为 **结束** ；仅在有可选建议时增加 B **优化** ；非末组最后增加 **停止** 。 |
| 末组没有门槛、可选建议、效果或待决定事项 | 报告已验证完成，不显示菜单。 |

可选建议不取代主推荐，也不为必要问题菜单增加选项。说明用户可以按编号用自然语言选择子集或其他有效动作，不必把每个内部操作都列出来。“处理”执行当前方案明确写出的混合补救，不是改变“修复”默认范围的别名。

用户只说 **修复** 时，选择所有已展示且待处理的不合理 M 项；只说 **优化** 时，选择所有已展示且未完成的必须处理或可选优雅性 M 项，包括之前分组。两者都不含 O 类建议。**忽略** 和 **接受保留** 仅作用于选定的不合理发现或必须处理的优雅性负担；多个候选时直接问编号，除非已明确选择全部。保留已接受判断与取舍，不标成已优化。**保留** 必须说明提出哪些具体决定，不编辑。忽略不等于接受优雅性问题，接受保留也不等于忽略不合理发现。

继续或结束不暂存、提交、推送或记录 Viewed。通过只执行已披露效果，不批准或合并 PR。仅影响完成的缺口不阻止继续或结束，除非它使审查失效，或已选完成操作尚未结束。提供写入效果或额外内容纳入选择前，阅读完成操作；对应分支的选择替代普通就绪菜单。

## 修复选定条目并复审

将修复或优化限定在所选条目及必要支持改动。优化保留受支持的行为与契约。

被审查内容变化或选定 O 项修复后，运行必要检查，刷新前后证据和链接，再独立复审变化或受影响的已审查部分，包括意外改动。固定远端 PR 证据与已检查的未发布本地内容分开保留。专门回复中展示完整更新文件块和两个判断，与未见文件分开。

O 修复保留独立证据，给出自己的位置、前后说明和两个判断，不产生 M 编号、主进度或 Viewed 资格。保留原 M/O 编号和分组，不重复计数。检查及复审确认后才标记修复或优化完成。接受保留仅对相同的已评估内容与效果有效。

单次修复、忽略、优化或接受保留，以更新后的决策结束，不推进。含义明确的复合请求授权有序效果，包括完成或推进前的检查和专门复审。已授权工作就绪后继续；效果变化、新发现、检查失败或新增额外内容暂停依赖步骤，不凭空增加授权。
