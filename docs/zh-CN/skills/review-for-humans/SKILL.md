# 面向人类的审查

让用户充分理解固定改动，以便判断并选择下一步。评价实现方式前，先确定为什么需要该行为。审查授权采集证据和准备链接。执行选定的审查补救、交付或推进前，先解释完整文件分组。

本入口负责审查范围、评估、发现、进度及用户决定。PR 或需对齐远端的分支证据和工作区选择需加载[准备](references/preparation.md)。

每份普通、补充、修复或选定 O 项报告及动作菜单，都应应用完整的 [报告格式](references/report-format.md)。首次使用前完整阅读；上下文中已有完整且当前有效的内容时，可以复用。内容缺失时，包括上下文压缩后丢失时，恢复完整指南；指南改变时重新加载。

提供通过、准备或执行选定交付，或修复涉及尚未完整审查的 PR 文件而需判断整文件 Viewed 资格时，加载[交付](references/delivery.md)。必要指南不可用时，依赖工作仍未完成。

需要了解报告布局，或想看已核实的事实如何支持决定时，可查阅对应示例。根据适用指南和本次审查的证据，确定判词、报告内容和可选动作。

| 情景 | 示例 |
| --- | --- |
| 编排含简写条目、详写条目和独立观察的完整分组报告 | [分组审查](examples/review-group.md) |
| 判断新增边界是否有必要，或不确定性是否影响推进 | [设计判断](examples/design-judgments.md) |
| 编排涉及配套文件的修复报告，或说明必要检查缺失 | [修复报告](examples/repair-report.md) |
| 在处理补充发现或 Viewed 只记录了一部分后恢复已选交付 | [交付跟进](examples/delivery-follow-through.md) |
| 提供工作区选项或处理 Viewed 证据缺失 | [审查准备](examples/review-preparation.md) |

## 固定比较与阅读顺序

| 请求 | 比较及初始证据 |
| --- | --- |
| PR | 准备指南验证源身份及工作区，固定 base/head，取得已认证查看者的完整文件级 Viewed 筛选。 |
| 分支 | 固定顶端及其与可靠比较基准的 merge-base。基准未知时直接询问，不假定为 `main`。 |
| 本地改动或未声明范围 | 比较暂存区与工作树，仅审查未暂存改动。 |
| 指定文件 | 将适用比较限定到这些路径。 |

遵守明确选定的其他比较方式及历史版本。PR 和分支比较默认排除本地未提交改动。本地审查排除仅已暂存文件，只评估部分暂存文件的未暂存部分；工作树中对暂存内容的撤销也属于未暂存改动。只有明确要求时才纳入未跟踪新增文件。其他审查指导默认值不同时，以这些默认值为准。

按仓库的测试分类识别测试代码。主审查、补充审查和修复复审均跳过测试代码的语义审查，包括单元测试、集成测试和端到端测试。相关测试可用作证据。先排除测试并应用指定文件、Viewed 和本地筛选，再统计文件数、修改项数和进度。交付指南单独负责完整的提交和待发布范围。提交和必要检查以完整交付范围为准。

只读审查使用源码、测试定义和仍有效的已有结果。完成一个文件分组、结束审查或仅记录 Viewed，都不触发 UT 或完整改动集验证。本次审查期间实施的改动遵循下文的修复结果检查要求；明确请求的验证保持其声明范围。缺少执行证据只限制依赖该证据的判断：指出这些限制，并继续开展有独立依据的评估。

按 GitHub 目录树排列文件：递归列出子目录中的改动文件，再列出直接文件；保留可观察的同级顺序，否则分别按名称排序同级目录和直接文件。因此 `src/z/api.dart` 排在 `src/a.dart` 前。保留有序合格文件清单、固定提交、完整前后内容，以及 PR 查看者和筛选证据。本地审查保留原始暂存区基准，即使另选了修改前版本。

第一组前说明比较和排除项。范围为空时直接结束，不显示进度比例。已知文件即使证据不全也保留在总数中；指出缺失内容并暂停受影响评估，不把未见内容视为干净。

### 提供被评估版本的链接

从已加载的 SmartKit 资源中解析 `local_web`，阅读其支持的接口：

```text
python "<local_web>" --help
python "<local_web>" diff --input "<batch.json>"
```

为每个文件提供使用正斜杠的完整仓库相对 `path`，省略 `title`。按 ID 关联返回的 Markdown，原样作为文件名链接，保留完整标签、转义和 URL 绑定。采集快照时一并保留基于暂存区的本地链接。固定比较提供已验证的修改前提交、已有 blob 或真实不存在状态，以及重命名路径。

准备指南提供 PR 元数据及已验证展示模式。本地审查和有意选择的本地分支审查无需对齐远端；仅分支链接不带 PR 上下文，绑定确切且已验证的展示工作区。所有实时链接绑定已验证工作区；披露脏内容或版本差异，但不改变评估及 Viewed 资格。生成链接不能证明编辑器已展示内容。链接生成失败时，保留比较和选定模式并解决问题，依赖报告暂缓。

## 先判断需求，再判断实现

检查完整范围内改动及必要上下文：受影响调用方、现有归属、同类模式、契约和生命周期。在优雅性上投入比合理性更多的精力。无论是否展示修改项，都评估每项非测试改动的两个维度，包括文档和翻译。区分实际执行的检查与作者报告结果，保留实质任务或规范发现。

对有实质意义的设计选择，根据任务、受支持契约及实际用法确定用户或调用方所需结果。验证既有行为和框架或库的保证。先考虑保留该行为或删除新增能力，再比较确实需要的能力应如何实现。测试通过只能证明其假设下的行为，不能证明被测试策略的必要性。

报告缺陷时，说明触发条件如何成立，例如引用受支持的调用顺序、适用的契约或有代表性的复现。按校验、恢复及其他防护要应对的需求、可信触发条件和实质影响进行判断。受支持的需求、信任边界风险都可以在任何线上事故发生前构成防护依据；既定不变量可能使重复检查没有必要。缺少可信触发条件及可能严重后果时，仅缺额外保护本身不是缺陷，而正常受支持行为和承诺的失败处理仍是正确性义务。缺少必要性的关键依据时，将受影响判断标为 **不确定** ，不能据此认可实现或预先认定该能力有缺陷。

对照当前设计和保留受支持行为的更简单方案，例如保留已有接口、复用合适的现有归属、直接调用，或删除没有独有职责的层次。以提供或保留某项保证为由认可额外复杂度时，指出已确认的保证，并说明更简单的方案为什么做不到。有依据的防护可以略微扩大覆盖范围，前提是这样做能简化实现，且对正常使用的影响可接受。必要反馈、日志、恢复及生命周期保护仍须有归属。改变受支持行为或契约的提议属于范围决策，不是保持行为不变的优化。

审视每个新增文件及新增或改变的声明与契约，包括既有文件中的函数、类型、成员和状态。尤其关注重构和外部可见行为变化中损失的直观性、隐藏依赖及结构负担。小文件或简单转发仍会引入边界。新文件尤其需要充分依据，说明其独立职责及为何现有归属或局部位置不足。按实际暴露范围、调用方依赖、生命周期和变更影响提高审视要求：共享接口和长生命周期状态比局部辅助函数需要更强证据及具体替代方案。普通局部变量无需独立的必要性说明；可见性关键字不能确定实际暴露范围。

仅凭代码简短、调用方数量、统一展示、预期复用和测试便利，都不能证明边界有必要。真实职责可以证明只有一个调用方的边界也有必要。源码、任务和契约可以提供理由，无需理由注释或每个声明各有一个报告项。

### 逐项判断合理性与优雅性

只有相关证据支持高置信度时，才给出确定评价。正面与负面判断都适用，包括可选改进；没有发现缺陷，并不能证明合理或优雅。两个维度分别判断，只有关键未知因素妨碍有把握的结论时，才将相应维度标为 **不确定** 。仅缺少原始对话，不必推翻其他充分证据所支持的判断。

| 判断 | 依据 |
| --- | --- |
| ⚖️ **合理** | 实现所需结果，符合已接受范围和受支持行为与契约，运行成本和风险有依据。 |
| ⚖️ **不合理** | 存在实质任务、行为或契约缺陷，包括违反结构要求、不必要范围，或缺乏依据的运行成本和风险。指出严重级别、受影响条件、影响及修正。 |
| 🎨 **优雅** | 职责、边界和接口值得其理解与维护成本。表达易读；抽象、状态、分支、重复和防御有具体收益。同类模式与接口一致，偏离时有依据。 |
| 🎨 **需要改进** | 结构缺陷违反已确立的要求。解释该要求、具体后果及必要修正，并将同一项记录为不合理发现，归入修复。 |
| 🎨 **可选改进** | 结构满足已确立的要求，但保持行为不变的更简单或更一致方案所带来的收益值得其变更成本。解释负担、补救及收益；优化保持可选。 |
| 任一维度的 **不确定** | 说明已确定事实、关键不确定性及其澄清条件。另一个维度有依据的判断仍可保留。 |

将判断放在对应修改项下，说明具体原因及对用户或调用方的后果。即使报告格式允许简洁写法，仍须评估两个维度。一项改动的优点不能抵消另一项的缺陷、负担或不确定性。用户明确接受现状后，仍保留原判断和后果；已经接受且没有变化的负担，无需再次请求优化。

功能正确或用户同意，都不能证明结构优雅。区分已观察到的负担与其理由和接受情况。缺失的需求、理由或用户决定会实质影响复杂度是否必要、简化是否安全的判断时，将受影响维度标为 **不确定** ，而不是预先认定用户已接受、复杂度无必要或存在可行补救。

仅有行为缺陷时，还不足以判定结构有问题。结构违反受支持约定时，同时列为合理性缺陷，两个判断共用一个修改项编号和一个修复动作。省略偏好和收益低的打磨，同一根因共用补救措施。

将审查范围内修改的不确定性保留在对应 M 编号下，并在总结中作为警告呈现。它不是已成立的问题或可选改进：不进入修复和优化范围，也不因此新增顺带 O 项或优化选项。同一修改中独立有依据的判断和补救仍须保留。

只给不合理发现分配严重级别：P0 关键且需立即处理，P1 严重且需尽快修正，P2 普通优先级，P3 影响较低但值得修正。优化始终可选。为满足已确立要求而必须进行的修正属于修复，即使缺陷是结构性的。

## 解释完整分组并保留其身份

按报告类型使用报告格式。M 编号跨文件和分组连续，按解决的问题合并实现步骤；无法共享一个解释的独立改动分开。一份本地化文件算一个修改项。没有发现问题的附带小改动可以留在概述中或省略解释，但仍在评估范围内。

补审和修复中保留既有条目的编号。其他需要单独解释的配套改动使用下一个尚未分配的 M 编号，并保留与原发现的关系。每个条目在一份报告中只展示一次；配套文件不将原条目重复列成另一个编号项。修复和补审共用连续编号，但不增加主进度。选定 O 项工作保留下文规定的独立身份。

每个有依据的不合理发现和值得做的可选改进都需要对应一个可处理的 M 项，可使用既有项或新增一项。判断说明具体问题、适用的严重等级、触发条件、影响及修复方案或收益。如果本次改动引入、触发或加重了未修改代码中的缺陷，也将其归入对应的 M 项。

在内部按审查单位确定每个主审查分组的大小：符合报告格式中简洁项条件的简单修改计 1 个单位；需要详细形式的普通修改计 2 个单位。审阅完整个使本组累计达到至少 20 个单位的文件后结束本组，始终保持文件完整。下一组从零开始计数，范围结束时展示较短的余组。此单位计数仅供内部使用。

报告进度只展示累计已展示的主审查文件数与合格文件总数，每个文件只计一次，以及累计实际展示的主审查修改项数。补审项、修复和顺带观察既不增加主分组的审查单位，也不增加主进度。进度本身不代表交付成功或已记录 Viewed。

每组收尾给出结论和进度、实际检查及限制、待处理不合理项的编号严重级别与影响、已接受取舍，以及可选建议的补救和收益。跨回复保留证据、判断、发现与决定、分组成员、下一位置和下一 M 编号。范围变化时才调整总数；提交使工作树变干净，也不能抹去尚未展示的固定证据。

### 单独处理顺带观察

必要阅读可能发现无关既有问题。确定其证据，并确认所选改动没有引入、触发或加剧它；这不构成对无关历史或整个仓库的审计。

为顺带观察分配连续的 O 编号和标题，注明源码链接或位置、证据和影响、与本次改动的独立性，以及建议或收益。按报告格式将可归属的观察放在其源码文件下。O 项不增加主审查文件数、修改项数或进度，也不会自动获得 Viewed 资格。未选的 O 建议不构成主审查或交付的前置条件。

批量修复、优化、忽略和接受保留排除 O 项，除非用户明确扩大范围或选择它们。选定 O 修复单独保留证据，检查并复审其改动及受影响上下文，使用 O 编号和两个判断，不新增主 M 编号或进度。其改动进入交付覆盖，产生的失败或未解决发现可以阻止交付。交付指南判断任何整文件 Viewed 资格。

## 将发现转成真实选择

解释完整分组后，根据结果确定下一步：

1. 明确哪些事项仍未解决。正确性证据、适用的必要检查和待处理不合理发现约束推进；仅有可选改进或优雅性不确定不会阻止推进。
2. 提供适用的 [分组或修复结果选项](#after-a-review-group-or-completed-repair)。先查明可推导的事实；直接询问真正需要用户提供的缺失事实，或由用户决定的范围、保全事项。事实问题不是动作菜单；已核实的外部阻碍没有受支持补救时，应解释原因，而不是虚构等待或解决选项。
3. 执行选定效果。补救经过 [检查和复审](#establish-the-repaired-result) 后，再更新决定。通过进入交付；继续或结束则不交付，直接推进或结束。已有待完成交付时，使用 [补审决策](#during-supplementary-review-for-selected-delivery)，不再次询问通过。

### 解释动作及其权限

| 动作 | 选定效果 |
| --- | --- |
| **修复** | 修复不合理发现，检查并复审。 |
| **优化** | 实施选定的可选改进，保持受支持行为和契约，再检查并复审。 |
| **修复并优化** | 合并明确列明的两类补救范围的复合请求，不是独立的常规菜单选项。单独“修复”仍保持较窄含义。 |
| **忽略** | 不修改明确选定的缺陷、负担或可选改进，记录其后果及用户的接受或放弃。 |
| **通过** | 准备并完成适用交付，包括补充审查和必要检查；按交付指南的并行与完成规则推进或结束。 |
| **继续** / **结束** | 不交付，推进或结束已完整展示的审查。 |

交付指南确定适用的提交、发布和 Viewed 效果。用户明确请求“交付”或“只交付”时，执行相同交付并保持当前审查位置；只有用户选择通过或明确要求继续时，才推进。单独交付不是独立的常规菜单选项。两种交付动作都不授予 PR 审批或合并权限。

字母不区分大小写，按最新适用菜单解释。明确自然语言、子集和复合请求可以选择已披露效果。含义唯一的菜单选项提供其声明范围：“优化”可以选中明确列出 O1 的选项。有多个匹配替代项时，询问编号。菜单范围不清楚时，单独“修复”选择所有已展示且待处理的不合理 M 项；单独“优化”选择所有已展示且待处理的可选 M 改进，包括更早分组。

忽略必须列明准备保留或放弃的条目及后果；明确自然语言接受或放弃即可。条目或决定含糊时询问。编号只标识条目，不选择动作。已保留条目在其已评估内容和效果不变时不再待处理。忽略不免除检查，也不推进审查。

选定动作就绪后直接执行，不例行重新确认。推荐、唯一选项、提问和异议都不授予额外权限。明确更改请求、暂停或停止时，以该指令为先；停止时报告已完成及残余工作。菜单省略停止和取消，但不限制用户提出这些要求。

### 应用决策原则

通过与继续或结束共享已审查分组的前提：当前有效的正确性和版本证据、适用的修复检查或明确请求的验证检查成功、受影响复审完成，以及所有待处理不合理发现已解决或明确保留，包括更早分组。仅优雅性不确定，不阻止推进或交付；给出警告不能免除必要的正确性证据或检查。可选改进和未选 O 建议保持可选。

仍有适用交付效果时，在继续或结束旁主动提供通过。提供通过不要求用户此前已请求交付，也不要求交付准备完成。说明选定工作区、适用的全工作区提交、完整待发布范围及 Viewed 效果，以及后续推进。未审查的本地或暂存改动、未覆盖的待发布提交，以及尚未完成的交付检查，都是选择通过后启动的工作，本身不构成省略该选项的理由。已验证限制和属于用户决定的未决范围事项，仍约束可以提供的效果；常见表格之外的情况按这些原则判断。

选择通过后启动交付指南中的清单、补审及检查；明确的准备请求也可以启动这些工作，但不授权写入。执行前披露由此形成的具体方案，范围、目的地及效果仍在已选权限内时复用该授权。补审没有新增可处理发现或可选改进时，完成前提并直接交付，不再次询问通过。新增条目按下方补审决策处理。通过仅明确保留其选项中列明且已评估的可选项；继续可以暂缓它们，不表示放弃。

每类动作只给一个选项。至少有一个已披露且待处理的具体可选改进可供选择时，才提供优化选项。选项写明默认选择的编号和效果，用户仍可用自然语言选择子集或组合动作。将适用的 M 和 O 补救合并到同一个修复或优化标签下，区分默认的 M 范围和需要明确选择的 O 项。选项可以明确列出要处理的 O 项。只提到其他 O 选项时，它们仍在批量 M 操作范围之外。未选的 O 建议不延迟已授权的交付。

常见情况表固定反复出现的情景中的推荐动作和选项顺序。其他情况按原则判断，不用穷举组合扩展表格。采用适用行，连续标注字母，将推荐项放在 A，每个适用动作只出现一次。说明具体编号、后果及效果。推荐项或唯一选项都不会自动被选中。

按报告格式呈现这些选择。使用继续时，在说明中写明用途和下一位置；范围结束时使用结束。准备指南提供审查前选择工作区的首张表，下文的表用于分组或修复结果，以及交付期间的补审。

### 审查一组或完成修复之后 <a id="after-a-review-group-or-completed-repair"></a>

普通分组和已经检查、复审的修复结果使用相同选项。纳入更早分组中仍待处理的条目。补救后，先完成必要检查、受影响复审及专门的修复报告；必要检查失败或不可用时，依赖工作仍未完成，尚不能通过或继续。补救完成本身不会推进或交付。已有待完成交付时，保留该请求，改用补审表；也保留其他明确的复合请求。

表中涉及改进的行也涵盖按独立范围规则可选择的 O 改进；未选 O 缺陷不构成主审查门槛。

| 当前情况 | 推荐动作 | 选项顺序 |
| --- | --- | --- |
| 仍有不合理发现；没有可选改进 | **修复** | **修复** ； **忽略** |
| 仍有不合理发现；同时有可选改进 | **修复** | **修复** ； **优化** ； **忽略** |
| 只有可选改进 | **优化** | **优化** ； **通过** ； **继续** |
| 没有待处理发现或改进 | **通过** | **通过** ； **继续** |

### 选定交付后的补充审查期间 <a id="during-supplementary-review-for-selected-delivery"></a>

交付所需覆盖范围内出现新的可处理发现或值得考虑的可选改进时，暂停交付写入。按下表提供适用选择，不增加通过或继续，因为交付已经选定。此前保留的条目在其已评估内容和效果仍有效时继续视为已解决；未选 O 建议不构成门槛。

| 当前情况 | 推荐动作 | 选项顺序 |
| --- | --- | --- |
| 补审只发现不合理项 | **修复** | **修复** ； **忽略** |
| 补审发现不合理项和可选改进 | **修复** | **修复** ； **优化** ； **忽略** |
| 补审只发现可选改进 | **优化** | **优化** ； **忽略** |
| 所需覆盖范围内没有未解决发现或改进 | 完成已选交付 | 无需新选择；完成前提并自动恢复 |

修复或优化可能留下其他未解决条目。完成选定补救及其检查和复审后，通过此表解决剩余决定。忽略记录明确保留，不免除检查。所需覆盖和前提满足后，执行原来的通过或只交付请求，不再次询问是否交付。

## 执行、复审并恢复选定请求

### 沿用已有审查上下文

保留固定比较、选定工作区、条目与分组标识，以及已保存的审查位置。修复时沿用选定发现及其相关路径和上下文、经核实的审查更正及其理由、已接受取舍和已披露效果。补审、修复和中断期间，保留任何待完成复合请求，包括“通过”和“只交付”的区别。

保留行为和禁止编辑是不同的决定。在已授权修复或其必要配套改动范围内，依据适用指导，评估保留行为的已核实理由是否需要注释。仅决定保留行为并不授予注释编辑权限：只读审查、明确禁止编辑，或无关且未选中的条目，都应提出建议而不是编辑。保留要求没有说清应保持行为不变还是禁止一切编辑时，先澄清该边界，再进行受影响的编辑。

复用完整且适用的指导和受支持的验证方式；只有证据仍适用于正在评估的确切内容、依赖和效果时，才能复用。保留其佐证记录，包括可用的完整日志。固定的 PR 证据继续说明原比较范围；未发布修复的验证必须单独确认修复后的内容。

### 确认修复结果 <a id="establish-the-repaired-result"></a>

编辑限定在选定补救和必要支持改动。被审查内容改变后，包括选定 O 工作，通过项目支持的验证方式运行必要检查，并刷新前后证据和链接。复用证据不能免除针对修复后内容的必要检查。独立复审每个改动过的非测试文件，包括必要的配套改动和意外改动，以及受影响的已审查部分。测试按仓库分类继续承担证据和必要检查的职责。必要检查失败或不可用时，依赖工作仍未完成。

按报告格式的统一文件布局单独回复修复报告，与尚未展示的主文件分开。覆盖每个改动过的非测试文件，保留既有编号和分组，不重复计入主审查进度。修复或优化只有经检查和复审确认才完成；保留负担仍属于取舍。

### 恢复剩余已授权工作

没有待完成交付或明确复合请求时，单次修复、优化或忽略以更新后的决定结束。有待完成请求时，完成独立复审并继续剩余授权效果。交付所需覆盖范围内存在未解决的不合理发现，或新披露且等待决定的可选改进时，暂停交付，包括选定 O 工作。通过已授权补救或明确保留解决这些事项；此前的通过既不接受后来发现，也不授权未选修复。这些发现和前提解决后，恢复原请求，不再次询问通过，也不替换为继续或结束。

使用交付指南执行实际操作、并行记录 Viewed 及恢复。效果变化超出现有权限时需要具体决定；未解决工作待完成期间保留已确认效果。只剩 Viewed 时，通过可以开始保存的下一组只读审查；只交付保持原位，除非用户已选择继续。报告已确认、未知和剩余效果，保留未完成交付及其意图，以便在受支持条件下恢复。
