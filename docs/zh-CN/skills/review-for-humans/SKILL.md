# 面向人类的审查

让用户充分理解固定改动，以便判断并选择下一步。评价实现方式前，先确定为什么需要该行为。审查授权采集证据和准备链接。执行选定的审查补救、交付或推进前，先解释完整文件分组。

本入口负责审查范围、评估、发现、进度及用户决定。PR 或需对齐远端的分支证据及工作区选择，加载[准备](references/preparation.md)。每次普通、补审、修复或选定 O 项报告前，完整阅读[报告格式](references/report-format.md)。有明确交付请求或待完成交付，或修复触及尚未完整审查的 PR 文件而需要判断整文件 Viewed 资格时，加载[交付](references/delivery.md)。必要指南不可用时，依赖工作仍未完成。[对话示例](examples/conversations.md)说明困难选择，不增加规则。

## 固定比较与阅读顺序

| 请求 | 比较及初始证据 |
| --- | --- |
| PR | 准备指南验证源身份及工作区，固定 base/head，取得已认证查看者的完整文件级 Viewed 筛选。 |
| 分支 | 固定顶端及其与可靠比较基准的 merge-base。基准未知时直接询问，不假定为 `main`。 |
| 本地改动或未声明范围 | 比较暂存区与工作树，仅审查未暂存改动。 |
| 指定文件 | 将适用比较限定到这些路径。 |

遵守明确选定的其他比较方式及历史版本。PR 和分支比较默认排除本地未提交改动。本地审查排除仅已暂存文件，只评估部分暂存文件的未暂存部分；工作树中对暂存内容的撤销也属于未暂存改动。只有明确要求时才纳入未跟踪新增文件。其他审查指导默认值不同时，以这些默认值为准。

计数前应用指定文件、Viewed 和本地筛选。测试不进入普通报告、修改项计数和进度；相关测试可作为证据。交付指南单独负责完整提交及待发布范围。报告筛选不缩小提交或必要检查范围。

按 GitHub 目录树排列文件：递归列出子目录中的改动文件，再列出直接文件；保留可观察的同级顺序，否则分别按名称排序同级目录和直接文件。因此 `src/z/api.dart` 排在 `src/a.dart` 前。保留有序合格文件清单、固定提交、完整前后内容，以及 PR 查看者和筛选证据。本地审查保留原始暂存区基准，即使另选了修改前版本。

第一组前说明比较和排除项。范围为空时直接结束，不显示进度比例。已知文件即使证据不全也保留在总数中；指出缺失内容并暂停受影响评估，不把未见内容视为干净。

### 提供被评估版本的链接

从已加载的 SmartKit 资源中解析 `local_web`，阅读其支持的接口：

```text
python "<local_web>" --help
python "<local_web>" diff --input "<batch.json>"
```

为每个文件提供使用正斜杠的完整仓库相对 `path`，省略 `title`。按 ID 关联返回的 Markdown，原样作为文件名链接，保留完整标签、转义和 URL 绑定。采集快照时一并保留基于暂存区的本地链接。固定比较提供已验证的修改前提交、已有 blob 或真实不存在状态，以及重命名路径。

准备指南提供 PR 元数据及已验证展示模式。本地审查和有意选择的本地分支审查无需对齐远端；仅分支链接不带 PR 上下文，绑定确切且已验证的展示工作区。所有实时链接绑定已验证工作区；披露脏内容或版本差异，但不改变评估及 Viewed 资格。生成链接不能证明编辑器已展示内容。链接生成失败时，保留比较和选定模式并解决问题，依赖报告暂缓。

## 先判断需求，再判断实现

检查完整范围内改动及必要上下文：受影响调用方、现有归属、同类模式、契约和生命周期。在优雅性上投入比合理性更多的精力。无论是否展示修改项，都评估每项非测试改动的两个维度，包括文档和翻译。区分实际执行的检查与作者报告结果，保留实质任务或规范发现。

对有实质意义的设计选择，根据任务、受支持契约及实际用法确定用户或调用方所需结果。验证既有行为和框架或库的保证。先考虑保留该行为或删除新增能力，再比较确实需要的能力应如何实现。测试通过只能证明其假设下的行为，不能证明被测试策略的必要性。

按校验、恢复及其他防护要应对的需求、可信触发条件和实质影响进行判断。受支持的需求、信任边界风险都可以在任何线上事故发生前构成防护依据；既定不变量可能使重复检查没有必要。缺少可信触发条件及可能严重后果时，仅缺额外保护本身不是缺陷，而正常受支持行为和承诺的失败处理仍是正确性义务。缺少必要性的关键依据时，将受影响判断标为 **证据不足** ，不能据此认可实现或预先认定该能力有缺陷。

对受支持行为，将所选设计与满足需求的更小方案比较：保留已有接口、复用准确的现有归属、直接调用，或删除没有独有职责的层次。必要反馈、日志、恢复及生命周期保护仍须有归属。改变受支持行为或契约的提议属于范围决策，不是保持行为不变的优化。

审视每个新增文件及新增或改变的声明与契约，包括既有文件中的函数、类型、成员和状态。小文件或简单转发仍会引入边界。新文件尤其需要充分依据，说明其独立职责及为何现有归属或局部位置不足。按实际暴露范围、调用方依赖、生命周期和变更影响提高审视要求：共享接口和长生命周期状态比局部辅助函数需要更强证据及具体替代方案。普通局部变量无需独立的必要性说明；可见性关键字不能确定实际暴露范围。

仅凭代码简短、调用方数量、统一展示、预期复用和测试便利，都不能证明边界有必要。真实职责可以证明只有一个调用方的边界也有必要。源码、任务和契约可以提供理由，无需理由注释或每个声明各有一个报告项。

### 每个文件给出两个独立判断

| 判断 | 依据 |
| --- | --- |
| ⚖️ **合理** | 实现所需结果，符合已接受范围和受支持行为与契约，运行成本和风险有依据。 |
| ⚖️ **不合理** | 存在实质任务、行为或契约缺陷、不必要范围，或缺乏依据的运行成本和风险。指出严重级别、受影响条件、影响及修正。 |
| 🎨 **优雅** | 职责、边界和接口值得其理解与维护成本。表达易读；抽象、状态、分支、重复和防御有具体收益。同类模式与接口一致，偏离时有依据。 |
| 🎨 **需要改进** | 存在实质且可避免的负担，并有值得承担变更成本的更简单或更一致方案。解释负担、补救与收益；需要优化或明确保留。 |
| 🎨 **可选改进** | 结构已达要求，但有依据的调整带来的收益值得其有限成本。保持可选。 |
| 任一维度的 **证据不足** | 指出缺失的关键证据及获取方式。另一个维度有依据的判断仍可保留。 |

解释具体原因及用户或调用方后果，不以“符合契约”“结构清晰”等标签代替理由。发现关联修改项编号。一项好改动不能抵消另一项的缺陷、负担或证据缺口；明确保留仍须保留原判断和后果。

两个维度保持独立。仅有结构负担属于优雅性问题；仅有行为缺陷不能证明结构不佳。需求或归属证据缺失既不能证明优雅，也不能证明结构缺陷。省略个人偏好及低收益润色，合并同一根本负担的补救。

只给不合理发现分配严重级别：P0 关键且需立即处理，P1 严重且需尽快修正，P2 普通优先级，P3 影响较低但值得修正。必须处理的优雅性问题是实质门槛，不是可选风格润色。

## 解释完整分组并保留其身份

按报告类型使用报告格式。M 编号跨文件和分组连续，按解决的问题合并实现步骤；无法共享一个解释的独立改动分开。一份本地化文件算一个修改项。没有发现问题的附带小改动可以留在概述中或省略解释，但仍在评估范围内。

每项有依据的不合理发现，以及值得处理的必要或可选改进，都需要可执行的 M 项，可以复用已有项或新增。前置判断说明问题、不合理严重级别或优雅性状态、触发条件、影响、修正或收益。笼统结论不能替代发现。本次改动引入、触发或加剧的未改动代码缺陷也属于主发现，应关联相应 M 项。

完整展示某文件后，若本组修改项达到至少 10 项，则结束分组，不在文件中途截断。范围末尾展示不足一组的剩余内容。进度表示累计已展示主文件数占合格文件数，每个文件只计一次；不暗示交付成功或 Viewed 已记录。

每组收尾给出结论和进度、实际检查及限制、待处理不合理项的编号严重级别与影响、必要优雅性负担及补救收益、已接受取舍和可选建议。跨回复保留证据、判断、发现与决定、分组成员、下一位置和下一 M 编号。范围变化时才调整总数；提交使工作树变干净，也不能抹去尚未展示的固定证据。

### 单独处理顺带观察

必要阅读可能发现无关既有问题。确定其证据，并确认所选改动没有引入、触发或加剧它；这不构成对无关历史或整个仓库的审计。

使用连续 O 编号单独报告，包含标题、源码链接或位置、证据和影响、独立关系、建议或收益。不增加主文件、修改项、进度，也不自动获得 Viewed 资格。未选 O 建议不增加主审查或交付门槛。

批量修复、优化、忽略和接受保留排除 O 项，除非用户明确扩大范围或选择它们。选定 O 修复单独保留证据，检查并复审其改动及受影响上下文，使用 O 编号和两个判断，不新增主 M 编号或进度。其改动进入交付覆盖，产生的失败或未解决发现可以阻止交付。交付指南判断任何整文件 Viewed 资格。

## 将发现转成真实选择

### 解释动作及其权限

| 动作 | 选定效果 |
| --- | --- |
| **修复** | 修复不合理发现，检查并复审。 |
| **优化** | 实施必要或可选优雅性改进，保持受支持行为和契约，再检查并复审。 |
| **修复并优化** | 合并明确列明的两类补救范围。单独“修复”仍保持较窄含义。 |
| **忽略** | 不修改明确选定的缺陷、负担或可选改进，记录其后果及用户的接受或放弃。 |
| **通过** | 完成适用交付效果，再推进，或在范围末尾结束。 |
| **继续** / **结束** | 不交付，推进或结束已完整展示的审查。 |

交付指南确定适用的提交、发布和 Viewed 效果。接受“只交付”，即相同交付但不推进；它不是独立的常规菜单选项。两种交付动作都不授予 PR 审批或合并权限。

字母不区分大小写，按最新适用菜单解释。明确自然语言、子集和复合请求可以选择已披露效果。含义唯一的菜单选项提供其声明范围：“优化”可以选中明确列出 O1 的选项。有多个匹配选项时，询问编号。菜单范围不清楚时，单独“修复”选择所有已展示且待处理的不合理 M 项；单独“优化”选择所有已展示且待处理的必要和可选优雅性 M 项，包括更早分组。

忽略必须列明准备保留或放弃的条目及后果；明确自然语言接受或放弃即可。条目或决定含糊时询问。编号只标识条目，不选择动作。已保留条目在其已评估内容和效果不变时不再待处理。忽略不免除检查，也不推进审查。

选定动作就绪后直接执行，不例行重新确认。推荐、唯一选项、提问和异议都不授予额外权限。明确更改请求、暂停或停止时，以该指令为先；停止时报告已完成及残余工作。菜单省略停止和取消，但不限制用户提出这些要求。

### 提供效果前确定就绪状态

询问前完成已授权且可推导的工作：查事实、准备链接、运行可用的必要检查、完成受影响复审。直接询问真正属于用户决定的缺失事实或范围、保全事项。事实问题不使用动作菜单。已验证外部阻塞且没有可选受支持补救时，直接报告，不虚构等待或解决选项，不承诺监控。

推进需要当前有效的正确性和版本证据、必要审查检查成功、受影响复审完成，以及所有待处理不合理发现和必要优雅性负担已解决或明确保留，包括更早分组。仅缺优雅性证据不阻止推进。可选改进和未选 O 建议保持可选。

用户明确请求交付或交付准备，或已有待完成交付时，启动交付准备。仅审查、补救或推进不触发这项工作。为所请求的交付提供通过前，完成交付指南中可推导的清单、补审和检查，包括已有暂存工作。遵守明确排除项和保全要求，解决方式属于用户决定时直接询问。准备未完成、决定未解决，都不是已验证的不可用。已验证且仅影响交付的限制，在审查仍有效且没有待完成交付时，仍允许普通继续或结束。没有交付效果待执行时，直接提供推进，不提供空交付。

### 提供每个适用替代项

使用第一个匹配行，按其顺序纳入每个可用选择，连续标注字母，将推荐项放在 A。说明实际编号、后果及效果。发送前检查被省略的适用选择，并解释使其不可用的已验证原因。

| 当前情况 | 有序选择 |
| --- | --- |
| 待完成交付仍有未解决发现 | 两类问题并存时提供 **修复并优化** ，否则为 **修复** 或 **优化** ； **忽略** 所列发现或负担。 |
| 没有待完成交付；不合理发现与任何优雅性改进仍在 | **修复并优化** ； **忽略** 所列缺陷和改进。 |
| 没有待完成交付；只有不合理发现 | **修复** ； **忽略** 所列缺陷。 |
| 没有待完成交付；必要优雅性问题仍在 | **优化** ，包括待处理可选改进； **忽略** 所列负担和改进。 |
| 只剩可选改进 | **优化** ；交付已请求且准备就绪时提供 **通过** ，明确保留所列条目； **继续** 或 **结束** 。 |
| 没有待处理发现或改进；所请求交付准备就绪且仍有效果 | 可用时提供 **通过** ； **继续** 或 **结束** 。 |
| 最后一组，没有发现、有依据的 M/O 改进、所请求交付效果或待决定事项 | 报告已验证完成，不提供菜单。 |
| 未请求交付而审查可推进，或交付没有效果或不可用 | **继续** ，范围末尾则为 **结束** 。 |

待处理 O 观察有依据充分的优化方案时，每次构造真实菜单都提供明确的 **优化 O…** 。没有必要主问题或待完成交付优先时，在通过或继续之前推荐该优化。只有明确列出编号和效果时，才组合 M 与 O 补救。否则保留必要主补救为推荐项，将 O 优化放在主补救和忽略之后，说明仍未解决什么。已有授权且就绪的交付只需披露 O 建议，不制造新菜单或延迟执行。

表格行不会使不可用动作变得可执行。推荐补救需要用户事实时直接询问；独立且有依据的补救仍可选择，同时说明阻塞。自然语言子集无需穷举组合菜单。通过中的明确保留仅覆盖所列已评估可选项。继续可以暂缓它们，不表示放弃。

每个选项以加粗短动作名开头，再写具体效果。Continue 的中文名称固定为 **继续** ；目的和下一位置放在后面。通过说明实际提交、推送、Viewed 效果和后续推进。准备指南负责独立的工作区选择优先级。

## 执行、复审并恢复选定请求

保留选定条目、工作区、已披露效果、已接受取舍及任何待完成复合请求。尤其要在补审、修复和写入中断期间保留“通过”还是“只交付”，以及已保存的下一位置。

编辑限定在选定补救和必要支持改动。被审查内容改变后，包括选定 O 工作，运行必要检查并刷新前后证据和链接。独立复审改动及受影响的已审查部分，包括意外改动。固定远端 PR 证据与已检查的未发布内容分开保留。按报告格式单独回复修复报告，与尚未展示主文件分开；保留编号和分组，不重复计数。修复或优化只有经检查和复审确认才完成；保留负担仍属于取舍。

没有待完成交付或明确复合请求时，单次修复、优化或忽略以更新后的决定结束。有待完成请求时，完成独立复审并继续剩余授权效果。必要交付覆盖内，任何未解决的不合理发现或待处理的必要、可选改进，包括选定 O 工作，都会暂停交付，等待补救或明确保留。此前的通过不接受后来发现，也不授权未选修复。这些发现和前提解决后，恢复原请求，不再次询问通过或替换为继续、结束。
