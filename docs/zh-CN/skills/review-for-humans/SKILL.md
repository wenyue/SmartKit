# 面向人类的审查

帮助用户理解固定改动，判断其合理性与优雅性，并选择下一步。先解释完整文件分组，再执行用户选择。审查授权采集证据和准备链接；编辑、工作区变化、交付和推进取决于选定动作。

本入口负责完整审查循环：确定上下文，检查并判断，解释完整分组，再按用户选择执行和恢复。PR 或需对齐远端的分支证据及工作区选择，阅读[准备](references/preparation.md)；普通本地审查使用下方比较和链接规则。准备或提供交付、执行或恢复其效果前，阅读[交付](references/delivery.md)。这两份指南负责条件分支；必要指导不可用时，依赖工作仍未完成。

## 确定审查上下文

| 请求 | 比较 |
| --- | --- |
| PR | 验证所属仓库、源仓库和源分支，准备工作区，固定 base/head，再应用已认证查看者的文件级 Viewed 筛选。 |
| 分支 | 固定分支顶端及其与可靠比较基准的 merge-base。补足未知基准，不假定为 `main`。 |
| 本地改动或未明确指定范围 | 比较暂存区与工作树，仅审查未暂存改动。 |
| 指定文件 | 将适用比较筛选到这些路径。 |

明确指定 PR 或分支比较时，除非另有要求，否则排除本地未提交改动。遵守选定的历史版本；其他审查指导默认范围不同时，保留此范围。

本地审查跳过仅已暂存改动，只评估部分暂存文件中的未暂存部分。在工作树中撤销暂存内容，仍属于未暂存改动。只有明确要求时才将未跟踪文件作为新增文件纳入。明确选择其他比较方式时覆盖这些默认值。

测试不进入普通主审查报告、修改项计数或进度，但相关测试可作为证据。先应用指定文件、Viewed 和本地范围筛选，再计数。交付清点并检查完整内容；补审沿用相同分类排除测试文件，按交付指南覆盖其他被排除的非测试改动。审查筛选绝不缩小提交或检查的范围。按 GitHub 目录树排列：递归列出子目录中的改动文件，再列出直接文件；沿用可观察的同级顺序，否则分别按名称排序同级目录和直接文件。因此 `src/z/api.dart` 排在 `src/a.dart` 前。

保留固定提交、固定的修改前后内容、有序文件清单，以及 PR 查看者和筛选证据。本地审查还要保留原始暂存区基准，即使选择了其他修改前版本。第一组前说明范围与排除项。比较为空时直接结束，不显示进度比例或虚构文件。

已知文件即使证据不全也保留在总数中。为受影响判断指出缺失证据；暂停依赖它的审查，不把未知内容当成干净状态。评估所选改动引入、触发或加剧的缺陷，包括位于未改动代码中的证据。无关既有问题单独作为 O 类观察。

### 将文件名链接绑定到证据

从已加载的 SmartKit 资源中解析 `local_web`，遵循其支持的接口：

```text
python "<local_web>" --help
python "<local_web>" diff --input "<batch.json>"
```

为每个被审查文件提供使用正斜杠的完整仓库相对 `path`，省略 `title`，让它默认使用该路径。文件名链接原样使用返回的 Markdown，通过返回 ID 关联；保留其转义和 URL 绑定，不缩短显示名称。采集快照时一并保留基于暂存区的本地链接。固定比较提供已验证的修改前提交、已有 blob 或真实不存在状态，以及重命名路径。适用时，由准备指南提供 PR 上下文和已验证展示模式；普通本地审查不需要 PR 元数据或远端对齐。

将实时链接绑定到已验证的确切展示工作区。仅分支审查使用该工作区，不提供 PR 上下文，有意选择本地分支审查时也如此；验证这个绑定不需要远端对齐。说明实时内容中的版本差异或未提交改动；它们不改变被审查版本或 Viewed 资格。

链接失败时暂停依赖它的报告。解决时保留比较和选定模式。生成链接不能证明编辑器已展示内容。

## 检查结果及其实现结构

在优雅性上投入比合理性更多的审查精力。检查相关周边实现、受影响调用方，以及附近或同类模式，不只查看 diff。利用单元及集成测试证据聚焦行为检查，同时仍评估任务结果、已接受范围、契约及运行成本与风险。区分实际检查与作者报告的结果，保留任务或规范方面的实质发现。

对有实质意义的设计选择，先根据任务、契约、实际用法和生命周期确定用户或调用方需要的结果，再选择结构。实现中已有的能力不自动等于需要。比较满足需求的更小设计：保留既有接口或职责边界、删除不必要能力或层次、直接调用或复用已有归属，而不只是重新组织相同功能。追踪每层独有职责。将所选结构的收益与它实现的行为或通过的测试分开判断。简化后仍须有人承接必要反馈、日志、恢复和生命周期保护；改变受支持的行为或契约属于范围决策，不是保持行为不变的优化。

检查所选范围内的每个新增文件，以及新增或修改的声明与契约，包括旧文件中的函数、类型、成员和状态。很小的文件和简单转发也增加边界，不能适用直接明了编辑的豁免。新文件需要特别充分的独立职责或边界依据，并说明为何不能放在已有准确归属或局部位置。按实际暴露范围、调用方依赖、生命周期和变更影响提高审视要求：向局部归属之外暴露的接口、被广泛依赖的声明，以及共享或长生命周期状态，需要充分的调用方或契约证据和具体的设计比较；局部辅助函数和成员也按这些因素适度审查；普通局部变量无需额外必要性说明。仅凭可见性关键字不能确定暴露范围。

调用方数量、代码简短、统一展示、预期复用或测试便利，本身不足以证明边界有必要。真实职责可以证明只有一个调用方的边界也有必要。源码、任务或契约可能已清楚表明理由；不要求理由注释，也不要求为每个新增项生成报告条目。

### 检查每项改动，按文件报告两个判断

审查强度取决于范围内的实际非测试改动，不取决于展示的 M 清单。严格评估每项此类改动的两个维度，包括文字和翻译，并检查文件整体及必要关联实现，确定其影响。合并或省略说明条目，绝不将其改动排除在审查之外。

每个文件使用下列结论给出两个独立且说明理由的判断。理由和发现关联到相关 M 编号：某项好改动不能抵消另一项的缺陷或结构负担。保留明确接受的发现和关键证据缺口，不把它们变成无问题结论。

用具体前后因果及用户或调用方后果解释：哪一步被跳过，哪些状态重复，哪个边界没有职责。“符合契约”或“结构清晰”本身不是理由。

| 判断 | 证据及后果 |
| --- | --- |
| ⚖️ **合理** | 实现任务所需结果，符合已接受范围、受支持行为与契约，运行成本和风险有合理依据。 |
| ⚖️ **不合理** | 存在实质任务、行为或契约缺陷、不必要范围，或不合理运行成本与风险。指出发现及其严重级别、影响和具体修正。 |
| 🎨 **优雅** | 职责、边界与对外接口值得承担其理解和维护成本；表达易读；抽象、状态、分支、重复和防御具有具体收益。接口与已观察的同类模式一致，偏离时有依据。 |
| 🎨 **需要改进** | 存在实质且可避免的理解或维护负担，并有值得承担改动成本的更简单或更一致方案。说明负担、补救和收益；必须优化并复审，或明确接受保留。 |
| 🎨 **可选改进** | 结构已达要求，但有依据的调整能带来值得其有限成本的具体收益。保持可选。 |
| 任一维度的 **证据不足** | 说明缺失的关键证据及补足方式。另一个判断仍可有充分依据。 |

结构负担本身属于优雅性问题，不是合理性缺陷。错误行为也可以有清晰、简练的结构；仅有行为缺陷不能证明结构不好。两个维度分别有证据时可同时不通过。缺少需求或归属证据既不能证明优雅，也不能证明结构缺陷。省略个人偏好与低收益润色，合并同一根本负担的补救措施。

按结构收益评估额外防御检查与兜底。优先依赖既定不变量和边界保证，避免重复校验或推测性恢复。缺少额外保护，只有在存在可信触发条件及可能严重后果时才构成不合理；正常受支持行为和承诺的失败处理仍是正确性义务。

只为不合理发现分配严重级别：P0 关键且需立即处理，P1 严重且需尽快修正，P2 普通优先级，P3 影响较低但值得修正。依据后果和受影响条件判断。必须处理的优雅性问题是实质门槛，不是可选的风格润色。

## 解释完整文件分组

准备普通审查、补审、独立修复复审或选定 O 项报告前，完整阅读[报告格式](references/report-format.md)，并使用其固定结构。无法取得完整必要格式规范时，暂停依赖它的报告。无论呈现详略如何，下方审查和披露义务都不变。

M 编号跨文件和分组连续，在发现、选择及复审中保留。按解决的问题合并实现步骤；无法用同一简单说明解释的独立改动才拆开。本地化文件算一个修改项。没有发现问题的附带小改动可留在概述中或省略说明，但仍要审查。

披露每个有依据的不合理发现，以及值得处理的必要或可选改进，即使其实际改动最初被合并或省略。通过已有 M 项明确覆盖，或补充 M 项。指出问题、不合理严重级别或必要/可选优雅性状态、相关触发条件、影响，以及修正或收益。笼统的文件结论不能替代可执行的发现。未改动代码中的缺陷若由所选改动引入、触发或加剧，应作为主发现关联到相应 M 项；必要阅读发现的无关既有问题遵循下方 O 规则。这不是对无关文件历史或整个仓库的审计。

在完整展示某文件后，若本组修改项达到至少 10 项，则结束分组；不要拆分文件。范围末尾展示不足一组的内容。进度表示累计已展示文件数占符合条件文件数，不暗示完成操作或 Viewed。主审查文件只计一次。

跨回复保留分组成员、下一位置和 M 编号、证据、判断、发现与决定、已接受取舍、建议和已验证效果。整分支提交使工作树变干净后，仍按保留证据展示未见文件。只有范围实际变化时才调整总数。

每组收尾给出结论与进度、实际检查及限制、待处理不合理项的编号严重级别与影响、必须处理的优雅性负担补救及收益、已接受取舍与可选建议，以及下方规定的单独 O 类建议。[对话示例](examples/conversations.md)简要说明决策和转换，不定义格式或规则。

### 单独处理顺带观察

只有必要阅读证明既有问题确实存在，且本次改动没有引入、触发或加剧它时，才报告该问题。这不构成扩大审计范围。

使用连续 O 编号。最初与主发现分开报告，包含标题、源码位置或链接、证据与影响、独立关系及建议收益。O 项不增加主文件、修改项、进度，也不自动获得 Viewed 资格。未选建议本身不阻止推进或交付。O 补救一旦选定，其改动就进入交付覆盖和检查；这些工作中的失败或新未解决发现可以阻止交付。批量修复、优化、忽略或接受保留不含 O 项；除非用户明确扩大主范围，O 修复需要单独选择、检查和复审。

O 修复保留独立证据，针对选定 O 改动及受影响上下文报告两个判断，关联其 O 编号。其发现和结论与主文件审查分开，不产生主 M 编号或进度。任何 Viewed 资格仍须满足交付要求的整文件覆盖。

## 处理选择、执行与恢复

这些动作适用于 PR、分支和本地审查。能否执行取决于证据和选定工作区；审查快照本身不提供可编辑或可交付的 checkout。

| 动作 | 含义及完成条件 |
| --- | --- |
| **修复** | 修复选定的不合理问题，运行必要检查，复审受影响内容。 |
| **优化** | 实施选定的必要或可选优雅性改进，运行必要检查，复审受影响内容。 |
| **修复并优化** | 明确组合两类补救，分别列出问题范围；不改变单独“修复”的含义。 |
| **忽略** | 不编辑，记录明确选定的忽略缺陷、接受结构负担或放弃可选改进。保留原判断及已披露后果。 |
| **通过** | 完成交付，然后推进到下一组，或在范围末尾结束。 |
| **继续** / **结束** | 不交付，推进到下一组，或结束已经完整展示的审查。 |

交付指交付指南中的适用提交、发布和 Viewed 效果，不作为常规菜单中的独立选项。接受“只交付”：完成相同效果并停留在当前组。通过包含推进；交付成功后不再次询问。两者都不授予 PR 审批或合并权限。

当前菜单选项含义唯一时，自然语言动作回复也采用它已披露的范围：“优化”可以选择明确列出 O1 的选项。有多个优化选项时，询问编号。没有清楚菜单范围时，单独“修复”选择所有已展示且待处理的不合理 M 项，单独“优化”选择所有已展示且未完成的必要和可选优雅性 M 项，包括更早分组；这些默认范围排除无关 O 类观察。“忽略”必须列明准备不作修改的缺陷、负担或可选改进及其后果。也接受明确的自然语言接受或放弃；目标条目或决定类型仍含糊时，询问具体编号和决定。忽略不会免除必要检查、抹去判断，也不单独授权推进。编号本身选择条目，不选择动作。已保留条目在其已评估内容与效果不变期间，不再属于待处理项。

字母不区分大小写，按最新适用菜单解释。接受对已披露效果的明确自然语言、子集和复合请求。已选动作就绪后直接执行，不例行重新确认。被推荐或成为唯一可用选项，都不代表动作已被选择或权限扩大。菜单不提供停止或取消选项。提问或异议不授予写入权限；明确改变、暂停或停止请求时，以新指令为准。用户暂停或停止时，报告已完成及残余工作；未解决工作仍未完成。

### 新选择前先解决当前请求

首先履行已有请求。在交付效果证据之外，保留“通过”还是“只交付”、任何明确复合请求、选定工作区和已披露效果、已接受取舍、分组进度及下一位置。待完成请求在补审、选定修复和写入中断期间继续保留。必要交付覆盖中（包括已选 O 工作）新发现的不合理问题、必要或可选改进会暂停交付；报告它们，并使用下方补救或忽略选择。先前的通过既不接受后来发现，也不授权修复。不替换成继续或结束，也不再次要求通过。发现全部解决或明确保留且所有前提满足后，恢复原交付及原有推进选择。

否则，提问前完成已授权且可推导的工作：查事实、准备链接、运行检查、复审受影响内容。直接询问真正只有用户才能决定的缺失事实，例如比较分支或含糊的条目选择。事实问题不使用动作菜单。没有可选的受支持补救时，报告已验证的外部阻塞；不虚构等待或解决选项，不承诺监控。

### 确定哪些选择可用

正确性或版本证据缺失或过时、必要审查检查失败或未完成、受影响部分的复审未完成，都阻止推进。仅缺优雅性证据不阻止推进。待处理不合理问题需要修复或明确忽略；必要优雅性问题需要优化或明确保留，包括更早分组。可选改进保持可选，无关 O 类建议从不阻止主审查。

审查仍有效且没有待完成交付时，仅影响交付的限制不阻止普通的继续或结束。提供通过前，完成交付指南要求的可推导准备，并披露实际剩余效果。未知或尚未检查不等于不可用。没有交付效果待执行时，直接提供推进，不提供空的通过。

### 优先推荐改进，再考虑交付

使用第一个适用行。代入编号、后果和具体效果；按所列顺序纳入每个可用选择，再连续标注字母，将推荐项放在 A。

| 当前决策 | 有序选择 |
| --- | --- |
| 待完成交付中存在未解决发现 | 两类问题都在时选择 **修复并优化** ，否则为 **修复** 或 **优化** ； **忽略** 所列发现或负担。全部发现解决或明确保留后恢复交付。 |
| 没有待完成交付；不合理问题与任何待处理优雅性改进并存 | **修复并优化** ； **忽略** 所列缺陷及改进。 |
| 没有待完成交付；只有不合理问题 | **修复** ； **忽略** 所列缺陷。 |
| 没有待完成交付；仍有必要优雅性问题 | **优化** ，包括待处理的可选改进； **忽略** 所列负担或改进。 |
| 只剩可选改进 | **优化** ；可用时提供 **通过** ，明确保留所列可选项； **继续** 或 **结束** 。 |
| 没有待处理发现或改进；交付仍有效果 | 可用时提供 **通过** ； **继续** 或 **结束** 。 |
| 最后一组，没有发现、有依据的 M/O 改进、效果或待决定事项 | 报告已验证完成，不提供菜单。 |
| 审查可推进，但不需要交付效果或交付不可用 | **继续** ，范围末尾则为 **结束** 。 |

待处理 O 类观察有依据充分的优化方案时，每次构造真实菜单都要提供明确的 **优化 O…** 选项。没有必要主问题或待完成交付优先时，在通过或继续之前推荐该优化；只有明确列出编号和效果时，才组合 M 与 O 补救。有必要主问题或使交付暂停的发现时，仍推荐它们的补救，在主补救及忽略之后额外展示 O 优化，并说明它留下哪些未解决义务。O 建议本身不增加推进或交付门槛。已有授权且就绪的交付，说明 O 机会即可，不制造新菜单或延迟请求。

表格不会让不可用动作变得可执行。推荐的补救需要未解决的用户事实时，直接询问；独立且有依据的补救仍可选择，并说明剩余阻塞。用户可以用自然语言选择子集，无需列出所有组合。通过说明中的明确保留只适用于所列已评估条目，不覆盖后来发现。继续可以暂缓可选建议，不表示用户已放弃它。

每个菜单项先写加粗的短动作名，再写这次的效果。修复与优化说明编号及结果；通过说明实际提交、推送、Viewed 效果及后续推进。推荐某项不构成省略适用替代项的理由。准备指南负责工作区动作及其推荐依据，不替代这里的审查优先级。

### 执行选定动作

将修复和优化限定在选定条目及必要支持改动。优化保留受支持的行为和契约。

被审查内容变化或选定 O 项修复后，运行必要检查，刷新前后证据和链接，再独立复审变化及受影响的已审查部分，包括意外改动。固定远端 PR 证据与已检查的未发布本地内容分开保留。在单独回复中展示完整更新文件块，与未见的主审查文件分开，使用上方检查标准和必需的报告格式；选定 O 项的报告保留独立编号和结论。保留现有编号和分组，不重复计数。检查及复审确认后才标记修复或优化完成；明确保留仍是已记录取舍，不是优化。

没有待完成交付或明确复合请求时，单次修复、优化或忽略以更新后的决策结束。有这些请求时，先完成必要的独立复审，再恢复剩余授权效果，不增加一轮许可。“只优化，先不要交付”等明确指令改变该意图。新发现、交付效果变化或检查失败会暂停依赖工作；变化效果超出现有权限时，执行前需要具体决定，同时保留已成功效果。

通过交付指南执行或核对实际效果。只有所有适用效果和必要回读都成功后，通过才恢复保存的下一组或结束；只交付停留在当前组。即使提交使工作树变干净，也保留主进度及尚未展示的固定证据。交付仍未完成时，保留待完成意图，报告已确认、未知和剩余效果。遵循上方事实或阻塞规则，不虚构等待菜单、监控承诺或轮询循环。
