# 跟踪器边界

本 reference 负责批次选择和安全使用配置的跟踪器。权威身份、状态、阻塞项、声明、完成、释放、观察和变更均归跟踪器所有。只使用其当前项目契约记载的操作和含义；不得发明 compare-and-set、操作 cursor、批次专属声明、释放或恢复接口。

## 原则

- **正向资格。**只有肯定的 Agent 可执行资格证据才能让工单入选；负面状态是排除理由，不是另一项资格测试。
- **冻结选择。**依赖顺序、来源、排除项和声明时机构成一个不可变选择结果。当前观察可以验证或使其失效，绝不能悄然更新它。
- **效果可归因。**对一项有文档说明的跟踪器变更只请求一次，并且只有其权威后置状态出现时才接受。失败或有歧义的尝试仍归其原始所有者，在权威交付前一直持有已取得声明。

## 选择批次

解析配置的跟踪器或分诊所有者对 Agent 可执行资格的肯定谓词，然后使用其权威查询或观察路径，对调用方有界范围内的完整候选集合，以及闭合依赖所需的阻塞边进行分类。保留每个选定工单或排除项所需的身份、来源、状态、声明或所有者、排序证据和资格理由。谓词、候选集合边界或重要结果缺失或有歧义时，在选择结果能够建立批次前停止。

只选择具有权威正向资格证明的工单。只有同样具有该证明，才递归包含范围相同的未完成阻塞项。将已完成、已拒绝、归人工所有、因信息阻塞或已被外部声明等权威负面结果记录为排除项及理由，绝不把它们当作另一项资格测试。只有跟踪器证明外部阻塞项已完成时，才将其视为已满足；否则排除其依赖项。拒绝相互冲突的身份、有歧义的边和循环。按依赖关系排列剩余图，只在同等就绪工单间使用稳定公开顺序打破平局。

针对选择中每一种不同声明策略，解析跟踪器所有者的声明要求、会话边界和合法时机；只有当策略或当前状态不同，才应用工单特定证据。产生的声明计划为每个工单提供一条所有者支持路径：在其他批次写入前的初始声明、在更早批次效果后明确兼容的即时声明，或者跟踪器不要求声明时无需声明。普通的逐工单声明语法本身并不授权为尚未就绪的工单执行初始声明。时机缺失或不兼容时，在任何写入前停止。

返回一个冻结选择结果，其中包含工单、完整来源、图、顺序、排除项及理由、外部完成证明和完整声明计划。若没有工单仍然合格，返回 `nothing-to-do` 及这些观察和排除项。这是成功的无效果结果：它不建立批次，也不授权变更。

在工单声明前，以及接受其工单提交前，重新观察该工单和阻塞项。已证明的工单提交会使该选定工单对批次内后续工单变为就绪。任何其他重要状态、所有者、声明、要求或边变更都会停止冻结批次，而不是悄然改变它。唯一预期的声明或所有者差异，是跟踪器所有者已经为该工单配置的声明操作证明的确切后置状态；只豁免可归因于该已使用效果的字段。

**完成条件：**已证明一个无环、闭合的非空选择、其第一边界和完整的所有者支持声明计划，或已将空合格选择证明为 `nothing-to-do`。

## 满足初始声明门槛

携带非空选择结果，在首次批次写入前进入。初始声明前，只有当后续派发失败可能依照跟踪器所有的释放、重新分配或过期语义遗留该声明时，才要求 [`worker-transaction.md`](worker-transaction.md) 的非变更性资格判断。在可观察时效谓词仍成立时，只验证一次共享运行时、权限和环境事实；只添加会改变可行性的工单特定约束。随后，通过下方操作边界，按稳定依赖顺序请求跟踪器授权的初始声明；每次都要重新观察确切后置状态，再进行下一项声明。

遇到首个不可用、失败或运行中的资格判断或声明时停止。保留冻结选择结果和声明计划；已证明的声明前缀及其原始响应和当前跟踪器状态；已经开始时的确切当前失败或运行中声明尝试，包括预期差异、前置状态、原始结果和观察，以及跟踪器所有者或操作；还有未触及的后缀。未解决的当前声明既不属于前缀，也不属于后缀，绝不根据当前状态推断重试。

将这些证据作为就绪前选择交接的声明分区返回，其中包括每项冻结的即时声明或无需声明处置，并让创建状态为 `never-started`，明确指出工作树不存在。之后的公共创建结果只能推进与之独立的创建分区。除非每个选定工单的声明路径仍兼容、每项必要初始声明均得到证明且没有未解决的声明尝试，否则不得调用 `create-worktree` 或执行另一项批次写入。

**完成条件：**每项必要初始声明，以及每项延后或无需声明路径，当前均依照跟踪器所有计划得到证明。

## 恢复就绪前选择

重建 [`stop.md`](stop.md) 定义的声明分区：已证明的初始声明前缀、可选的失败或运行中当前尝试、未触及的后缀，以及每项即时声明或无需声明处置。重新观察每项保留结果，只使用确切且已证明的跟踪器效果。未解决的声明仍在前缀和后缀之外，并继续归原始所有者；此后不能产生创建效果。

将独立创建分区重建为 `never-started`、原始 `non-ready-or-in-flight` 或可归因的 `ready`。当没有未解决声明且每项必要初始声明均得到证明时，`never-started` 可以调用 `create-worktree` 一次。`non-ready-or-in-flight` 结果继续归其依赖所有者及恢复操作。只有记录的快照仍与当前状态一致时，才能使用可归因的 `ready` 结果。

若绑定批次前必须重新确立选择或就绪状态，针对既有候选项和当前证据调用公共 `create-worktree`；它会选择自己的路径。这会重新评估就绪状态，不能成为第二次初始创建。只有新鲜 `ready` 结果标识同一候选项时才使用它；保留每个 `non-ready` 或未解决结果及其所有者。

**完成条件：**声明分区得到证明，并且一个当前 `ready` 结果可以安全使用，或确切的非就绪或未解决依赖结果已得到保留并在不产生另一效果的情况下停止批次。

## 重新验证冻结选择

在验证和审查屏障之后、最终化之前，通过配置的跟踪器重新观察每个选定工单和相关阻塞项。通过权威修订版本、摘要或变更信号重新验证冻结验收来源；只有所有者没有暴露稳定时效证据，或报告发生变化时，才重新读取内容。将产生的重要来源、依赖图、状态、所有者和声明与冻结选择结果比较。只允许下方操作边界中已经为本批次使用且得到权威证明的每项确切声明或所有者差异。

任何其他重要变更都会使验证和审查屏障失效，并在最终化效果前进入 [`stop.md`](stop.md)。当前观察绝不悄然更新冻结批次。

**完成条件：**在紧邻最终化调用前的状态上，整个冻结选择仍为当前状态，仅允许其确切且可归因的声明效果。

## 使用一项有文档说明的跟踪器效果

只有跟踪器契约记载了声明、完成或释放操作，其成功含义可观察，并且调用方提供确切效果权限时，才执行它。请求前立即观察当前状态。若跟踪器已经证明预期状态，只有其含义足以支持本批次时才使用；否则将其视为漂移。

只请求一次操作，保留其原始响应，然后重新观察权威状态。返回成功但未出现有文档说明的后置状态时，不算通过。返回失败仍是失败。若响应缺失，或观察无法区分成功和无效果，则让该确切跟踪器效果以运行中状态保留，并附上其工单、预期差异、前置状态、原始证据、所有者，以及下一项观察或恢复操作。不要根据推断重复执行。

实现前，只有配置的跟踪器提供声明操作时才请求声明。若没有声明操作，只有其自身契约和已接受工作流仍能证明该工单适合此 Worker 时才继续；否则在不受支持能力处停止。在权威交付前一直持有每项已取得声明。只有跟踪器契约将不同的释放操作定义为闭合的一部分时，才要求执行它。

**完成条件：**预期跟踪器状态已得到权威观察，或原始失败或运行中效果连同其所有者和下一步操作得到保留。

## 权威交付后闭合

只有携带未改变的 `finish-worktree` 结果才能进入，并且其自身分类必须是权威交付；同时提供选定顺序和可恢复的工单提交边界。按依赖顺序重新观察每个工单，必要时请求有文档说明的完成操作，并执行任何另行记载为必需的声明释放。在第一个未解决效果前停止；保持剩余后缀不变。交付状态得到保留，绝不回滚。

每个工单均权威完成后，将闭合证明交给 `finish-worktree` 交接中指定的生命周期所有者。保留源历史、声明、引用、工作树和其他恢复状态，直到其所有者证明获准的移除、释放或保留处置。

**完成条件：**每个选定工单均权威完成，每项跟踪器要求的声明处置都得到证明，并且生命周期所有者取得闭合保留状态所需的证明。
