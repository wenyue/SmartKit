# 跟踪器契约

已配置的外部跟踪器及其冻结契约，拥有权威业务状态、阻断项、认领、完成和释放的含义，以及每项变更操作。本参考仅拥有通过该接口进行的`implement-tickets`观察、批次资格与选择、依赖闭包与顺序、请求的增量、证明与恢复游标、漂移和消费。其他参考传入规范工单身份和请求的增量；它们既不重述也不推断跟踪器行为。

冻结已配置的跟踪器所有者与路径、规范身份字段、公开顺序、每项权威业务含义、批次认领表示、变更操作、准确的前后谓词、授权和观察证明。按返回结果原样消费这些含义与操作；本参考不定义或重新解释它们。可见控件并不构成权限。外部契约发生漂移时停止批次。

## 观察并选择

通过冻结路径读取有界范围内的每个候选项和阻断项。记录规范身份、完整契约与验收来源、原始状态、所有者、认领、阻断项、公开顺序，以及外部契约的权威谓词。依据这些谓词，排除被跟踪器判定为已完成、已拒绝、由人工负责、因信息不足而受阻或已被外部认领的工单。对符合条件、处于同一范围内的开放阻断项递归闭合选择。只有跟踪器提供的权威批次前完成证明，才能证明外部阻断项已满足；如果某个依赖项被跟踪器识别出的开放阻断项既未完成，也不符合进入同一批次的条件，则排除该依赖项。

拒绝环、冲突身份和含糊边。生成依赖有效的顺序，仅在多个工单同样就绪时使用公开顺序打破平局。冻结一个**选择结果**，其中包含选定工单及完整来源、图与顺序、排除项与理由、外部完成证明，以及使首个工单就绪的观察。已证明的工单提交会使其选定工单在后续就绪性判断中视为已满足；批次内其他证据都不能达到此效果。后续决策应重新观察受影响的工单和阻断项。契约、所有者、状态、认领或边发生变化即为选择漂移，应停止而不是静默更改结果，但有一个例外：在冻结的跟踪器操作契约授权当前批次的准确认领增量且其权威后状态证明通过后，该增量可以更新当前观察。这个预期增量不会改变已冻结的选择结果、依赖图或顺序。其他任何所有者、状态、认领或边的变化，包括未绑定或未证明的认领增量，仍属于选择漂移。

**完成条件：**一个非空、无环、闭合的选择结果及其下一工单证据具有权威性，并且彼此一致。

## 请求并消费一个跟踪器增量

每次认领、完成和释放请求都有一个可恢复的操作游标：

1. 观察前状态，然后通过持久化契约转换游标，并绑定批次、工单、增量、唯一尝试身份、权限、路径，以及准确的前后谓词。
2. 如果已证明本次尝试的后状态，则直接消费而不请求变更。否则，请外部跟踪器所有者从准确的前状态恰好调用一次其冻结操作。
3. 通过冻结接口重新观察权威后状态，然后通过持久化契约转换原始调用证据、观察与游标，之后才能前进。

请求前的前置条件不可用时为`stopped`。返回的失败应保留为该原始结果。调用结果未知、状态冲突或后状态未证明时为含糊：将操作保留在其游标处的进行中状态，除非后状态或已证明无效果的前状态化解了原始尝试，否则绝不能再次请求。

认领工单时，应在尝试前立即重新观察资格和依赖就绪性。认领会绑定尚待生成的准确批次与工单提交证明。所有批次认领都要保留至交付；交付前的失败均不授权放弃或释放认领。

**完成条件：**请求的增量具有已证明的后状态，或者保留了一个准确、可恢复的游标和原始结果。

## 在权威交付后闭环

只有在持有未改变的`finish-worktree`结果，且其权威分类为`authoritative delivery`时才能进入；其中只有该分类是依赖项自身给出的**Already Delivered**时，才包括这种情况。绑定该原始结果及其阶段交接、选定的依赖顺序、每个工单提交边界、保留的来源历史，以及首个未证明的跟踪器游标。

按依赖顺序为每个工单请求完成，再通过上述游标契约请求释放其批次认领。绝不越过首个未证明的操作。已证明的现有后状态可直接前进而不再发起请求；含糊操作使后缀保持未触及。交付持续有效，绝不回滚。

通过持久化契约转换已完成前缀和下一游标。恢复时，重新证明同一交付结果、来源边界证据、跟踪器契约、已完成前缀，以及当前前后状态；不要重建工作树、派发执行者、重新运行审查，或调用另一次收尾器效果尝试。

越过最终游标后，将完整闭环证明交还给冻结的`finish-worktree`/生命周期清理所有者。保留来源历史及每个恢复项，直到该所有者证明其已获授权的移除、释放或有意保留处置。缺少清理证明不等于批次完成。

**完成条件：**每个选定工单均已完成、每个批次认领均已释放、完整操作顺序已证明，并且生命周期所有者已获得足以关闭保留状态的准确证明。
