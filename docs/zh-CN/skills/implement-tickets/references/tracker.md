# 跟踪器边界

已配置的跟踪器拥有工单身份、状态、阻断项、认领、完成、释放、观察和变更操作的权威定义。只消费其当前项目契约实际说明的含义和能力。本参考负责批次选择及这些操作的安全使用；它不会虚构 compare-and-set、操作游标、批次专属认领、释放操作或恢复接口。

## 选择批次

解析已配置跟踪器/分流所有者对“代理可执行且符合条件”的肯定谓词，然后通过该所有者的路径读取调用者有界范围内的每个工单和阻断项。保留每个工单的规范身份、完整工单/Spec 来源、权威状态、认领或所有者、阻断边、公开顺序和资格结果。谓词或结果缺失或含糊时，必须在选择结果建立批次之前停止。

只选择具有权威肯定资格证明的工单。只有当同一范围内的开放阻断项也具备相同证明时，才递归将其纳入。记录权威否定结果——例如工单已完成、已拒绝、由人工负责、因信息不足而受阻或已被外部认领——作为排除项及理由，绝不能把它们当作另一套资格测试。只有跟踪器证明外部阻断项已完成，才视其已满足；否则排除依赖该阻断项的工单。拒绝冲突身份、含糊边和环。按依赖关系对剩余图排序，只有多个工单同样就绪时，才使用稳定的公开顺序打破平局。

为每个选定工单解析跟踪器所有者规定的认领要求、会话边界、合法时机，以及阻塞中或位于后续前沿的工单能否被初始认领。由此得到的认领计划必须为每个工单提供一种所有者支持的路径：在其他批次写入前初始认领；在较早批次效果后明确兼容的即时认领；或者当跟踪器不要求认领时无需认领。普通的单工单认领语法本身并不授权初始认领一个尚未就绪的工单。时机缺失或不兼容时，必须在任何写入之前停止。

返回一份冻结的选择结果，其中包含工单、完整来源、图、顺序、排除项及理由、外部完成证明和完整认领计划。如果没有工单仍然符合条件，则返回`nothing-to-do`以及这些观察和排除项。这是成功且无效果的结果：它不会建立批次，也不授权任何变更。

在认领前及接受工单提交前，重新观察该工单和其阻断项。已证明的工单提交会使该选定工单满足后续批次内就绪条件。状态、所有者、认领、要求或边发生任何其他实质变化时，应停止冻结批次，不得静默更改它。唯一预期的认领或所有者增量，是该跟踪器所有者已经针对本工单已配置认领操作证明的准确后状态；只豁免可归属于该已消费效果的字段。

**完成条件：**已证明无环、闭合的非空选择、其首个前沿和完整且由所有者支持的认领计划，或者已证明符合条件的选择为空并返回`nothing-to-do`。

## 满足初始认领门

进入时，应持有非空选择结果，且尚未发生首次批次写入。对于分配到本门的每项认领，先取得[`worker-transaction.md`](worker-transaction.md)针对该选定工单的当前非变更资格结果。然后仅通过下方操作边界，按稳定依赖顺序请求跟踪器授权的初始认领。重新观察并消费每项准确后状态后，才能请求下一项认领。

遇到首个不可用、失败或进行中的资格检查或认领时停止。保留冻结的选择结果和认领计划；已经证明的已认领前缀及其原始响应/当前跟踪器状态；确实已开始的当前失败或进行中认领尝试，包括预期增量、前状态、原始结果与观察，以及跟踪器所有者/操作；还有未触及的后缀。未解决的当前认领既不属于前缀，也不属于后缀，绝不能根据当前状态推断而重试。

把这些证据作为就绪前选择交接的认领分区返回，其中包含每项冻结的即时/无需认领处置，而 Create 状态为`never-started`，且明确说明工作树不存在。除非每个选定工单的认领路径仍兼容、所有必需初始认领均已证明且没有未解决的认领尝试，否则之后的公开 Create 结果不得推进该独立 Create 分区，也不得调用`create-worktree`或执行其他批次写入。

**完成条件：**跟踪器所有的计划中，每项必需初始认领及每项延后或无需认领的路径当前均已证明。

## 重新验证冻结选择

完成整个验证/审查屏障后、紧接收尾前，通过已配置跟踪器重新观察每个选定工单及相关阻断项，并通过权威路径重新读取每个冻结验收来源。把这些完整来源、依赖图、状态、所有者和认领与冻结选择结果比较。只允许已根据下方操作边界为本批次消费并得到权威证明的每项准确认领或所有者增量。

其他任何实质变化都会使验证/审查屏障失效，并应在产生收尾器效果前进入[`stop.md`](stop.md)。当前观察绝不能静默更新冻结批次。

**完成条件：**在紧接调用收尾器之前的状态上，整个冻结选择仍为当前状态，唯一例外是其可准确归属的认领效果。

## 使用一项已有文档说明的跟踪器效果

只有跟踪器契约说明了某项认领、完成或释放操作，且其成功含义可观察，并且调用者授权了该准确效果时，才可执行。请求前立即观察当前状态。如果跟踪器已证明预期状态，只有当该状态的含义足以支持本批次时才可直接消费；否则视为漂移。

只请求一次操作，保留其原始响应，然后重新观察权威状态。成功返回但缺少文档规定的后状态，不能算通过。返回的失败仍为失败。响应缺失，或者观察无法区分成功和无效果时，将该准确跟踪器效果保持为进行中，并保留相应工单、预期增量、前状态、原始证据、所有者，以及下一项观察或恢复操作。不得根据推断重复执行。

实施前，只有已配置跟踪器提供认领操作时才请求认领。如果它没有认领操作，则只有在其自身契约和已接受工作流仍能证明该工单适合由本执行者处理时才继续；否则停止在不受支持的能力边界。所有已取得的认领都须保留到权威交付。只有跟踪器契约将独立释放定义为闭环组成部分时，才需要执行释放。

**完成条件：**权威观察已证明预期跟踪器状态，或者原始失败或进行中效果已连同其所有者和下一操作得到保留。

## 权威交付后闭环

只有持有未经更改的`finish-worktree`结果，且它自身将结果分类为权威交付时才能进入；同时应提供选定顺序和可恢复的工单提交边界。按依赖顺序重新观察每个工单，在需要时请求已有文档说明的完成操作，并执行任何另外有文档规定且必需的认领释放操作。在首个未解决效果前停止，剩余后缀不作变更。交付证明须保留，绝不能回滚。

每个工单得到权威完成后，将闭环证明交给`finish-worktree`交接指定的生命周期所有者。保留来源历史、认领、ref、工作树和其他恢复状态，直至其所有者证明已授权的移除、释放或保留处置。

**完成条件：**每个选定工单都已权威完成，每项跟踪器要求的认领处置均已证明，并且生命周期所有者已收到足以关闭保留状态的证明。
