# 停止或交接批次

本 reference 保留一个非完成边界，以及安全恢复所需的证据。

## 原则

- **首个边界优先。**在第一个未证明边界停止，并阻止之后的每个工单和阶段。对受保护效果之前尚未证明的前置条件使用 `stopped`；在尝试效果后，保留所有者返回的 `failed` 结果；当原始尝试可能仍在运行，或其效果无法辨别时使用 `in-flight`。绝不凭直觉将一种状态转换为另一种。
- **可恢复的交接。**保留足够的当前证据，使指定所有者无需重复效果或失去归属便能执行一项确切后续操作。保留声明、源历史、工作树、引用和其他恢复状态，直到其所有者证明获准的处置结果。

## 批次存在前

对于任何批次效果前的边界，返回有界范围、跟踪器路径和观察结果、选择或排除项、确切缺失事实或能力、未发生变更的证明，以及决策或依赖所有者。这样不会建立批次。已经证明的空合格选择则是 tracker.md 的成功 `nothing-to-do` 结果。

对于就绪前选择，返回两个独立分区。**声明分区**包含冻结选择结果和声明计划；零个或多个已证明的初始声明及其原始响应和当前跟踪器证明；可选的当前失败或运行中声明尝试及其预期差异、前置状态、原始结果、观察结果和跟踪器所有者或操作；未触及的初始后缀；以及每项即时声明或无需声明的处置。未解决的声明既不属于前缀，也不属于后缀。

**创建分区**恰好是以下一种：

- `never-started`：工作树不存在，并且证明没有创建尝试；
- `non-ready-or-in-flight`：包含原始依赖所有者或操作，以及每项原始结果、观察结果、效果、产物和残留；
- 可归因的 `ready`：包含完整就绪结果及其记录的快照。

携带两个分区和当前证据，进入 [`tracker.md`](tracker.md) 的**恢复就绪前选择**路径。该路径负责使用声明、唯一可能的初始创建、依赖恢复，以及既有候选项的就绪重新评估。

## 批次绑定后

对于已经建立的批次，返回指定所有者所需的当前证据，使其无需重复效果或失去归属便可恢复；适用时包括：

- 选定工单、依赖顺序、不可变基点和目标；
- 批次工作树身份、分支、`HEAD`、树、完整本地状态、工单提交前缀，以及当前工单或修复范围；
- 跟踪器观察结果、已取得声明、确切请求或运行中操作，以及原始响应；
- Worker 和最终化身份、状态、保留的依赖交接和效果；
- 验证、审查、交付、发布、生命周期和保留的恢复证据；
- 失败或未证明的边界、残留不确定性、下一位所有者，以及一项确切后续操作。

通过重新观察当前跟踪器和 Git 状态、使用保留的可归因交接，并携带保留和当前证据重新进入主 Skill 的**确立路径**来恢复。应用其完整路径谓词，它们会保留就绪、审查和最终化状态门槛，然后遵循选定路径和下一位所有者。

在权威交付前一直持有受支持声明；在交付后的跟踪器和生命周期闭合前一直保留源历史。运行中效果仍归其原始所有者，绝不只因当前状态看似等于预期结果就重复执行。

## 保留边界

每份交接都会保留恢复所需的规范检出、用户和无关状态、工作树、提交、引用和外部效果。强制、变基、重置、清理、回滚、丢弃、放弃声明、未配置的跟踪器变更、隐式远程效果，以及删除保留恢复状态，都需要单独的明确权限及其所属工作流。

**完成条件：**后续工作已被阻止，确切原始边界、保留状态、恢复所有者和下一项有用操作均无歧义。
