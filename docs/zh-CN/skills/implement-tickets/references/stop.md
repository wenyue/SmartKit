# 停止或交接批次

在第一个未证明的边界停止，并阻断之后的每个工单和阶段。保留所有者的原始结果：若受保护效果尚未执行，而前置条件、权限、依赖、决策或观察缺失，则使用`stopped`；效果已经尝试后，保留返回的`failed`结果；原始执行者、跟踪器、工作树或收尾器尝试可能仍在运行，或其效果尚无法辨别时，则使用`in-flight`。不得凭直觉把一种状态改成另一种状态。

对于发生在任何批次效果之前的边界，返回有界范围、跟踪器路径和观察、选择或排除项、准确缺失的事实或能力、没有发生变更的证明，以及决策或依赖项所有者。这不会建立批次。已经证明符合条件的选择为空时，应改为返回 tracker.md 成功的`nothing-to-do`结果。

对于就绪前选择，返回两个彼此独立的分区。认领分区包括冻结的选择结果和认领计划；零个或多个已证明的初始认领，以及相应原始响应和当前跟踪器证明；一个可选的当前失败或进行中认领尝试，以及其预期增量、前状态、原始结果、观察和跟踪器所有者/操作；未触及的初始后缀；以及每项 JIT/无需认领处置。未解决的认领既不属于前缀，也不属于后缀。

Create 分区必须且只能是以下之一：

- `never-started`，此时工作树不存在，并且有证据证明没有 Create 尝试；
- `non-ready-or-in-flight`，此时须包含原依赖项所有者/操作，以及每项原始结果、观察、效果、产物和残留项；或者
- 可归属的`ready`，此时须包含完整的公开交接和当前快照。

恢复时，重新观察两个分区。消费已证明的认领，不得重放。只有全部必需初始认领均已证明且没有未解决认领时，`never-started`才能发起一次初始 Create。`non-ready-or-in-flight`仍完全归其原所有者/操作负责。可归属的`ready`应直接消费而不再次调用，并进入主 Skill 的公共批次绑定和即时就绪复查。已漂移的就绪快照必须由公开`create-worktree`执行 Reuse 评估，且绝不能变为`never-started`。不得虚构`ready`路径、分支、`HEAD`或树。

对于已建立的批次，返回足以让指定所有者安全恢复的当前证据：

- 选定工单、依赖顺序、不可变基准和目标；
- 批次工作树身份、分支、`HEAD`、树、完整本地状态、工单提交前缀，以及当前工单或修复范围；
- 跟踪器观察、已取得的认领、准确的已请求或进行中操作，以及原始响应；
- 执行者和收尾器身份、状态、已保留的依赖交接和效果；
- 验证、审查、交付、发布、生命周期和已保留的恢复证据；以及
- 失败或未证明的边界、残留不确定性、下一所有者，以及一项准确的下一操作。

恢复时，重新观察当前跟踪器和 Git 状态，并消费已保留且可归属的交接。受支持的认领须保留到权威交付，并且来源历史须保留到交付后的跟踪器闭环和生命周期闭环完成。进行中的效果仍归原所有者负责，绝不能仅因当前状态看似符合预期结果就重复执行。

每项交接都要保留恢复所需的规范检出目录、用户和无关状态、工作树、提交、ref 和外部效果。强制操作、rebase、reset、clean、rollback、丢弃状态、放弃认领、未配置的跟踪器变更、隐式远程效果，以及删除已保留的恢复状态，都需要另行取得明确授权，并通过其所属工作流执行。

**完成条件：**后续工作已被阻断，而且准确的原始边界、已保留状态、恢复所有者和下一项有用操作都清晰无歧义。
