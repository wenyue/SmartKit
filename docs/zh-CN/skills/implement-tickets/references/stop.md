# 停止批次

在首个未证明的边界停止，并阻断之后的每个工单或阶段。只选择下方一个终止入口；如果已建立交接的转换本身不可用或尚未解决，则通过**持久化不可用或尚未解决**终止，且不再执行另一次转换。如果在受保护的效果尝试前，前置条件、权限、依赖、决策或要求的观察不可用，则可以使用`stopped`。所有者尝试效果后，应保留该所有者的原始状态和证据；不要凭直觉重新分类。尤其是，丢失或含糊的收尾器响应在`recover-finalizer.md`下保持`in-flight`，绝不能伪造为`stopped`或`failed`结果。

## 批次建立之前

当有界首次使用观察证明本控制器未建立任何不可变批次、批次或执行者交接、认领、持久化转换、调用/效果尝试或受保护效果时，使用这个仅证据入口。可以存在无效果的选择结果或其他有界观察；仅把其身份、来源和内容作为非权威证据包含在内，绝不能作为持久建立状态。

返回有界请求范围；冻结的跟踪器所有者、契约和路径；不可用或含糊的原始观察；任何此类非权威证据；每个不存在的建立与效果字段的证明；残留的外部不确定性；以及一个准确的配置/跟踪器所有者和下一操作。不要发起持久化转换或跟踪器变更。

这次返回不会建立批次，也不授权把它作为一个批次继续。只有在缺失的能力或决策可用后，才能通过冻结所有者与路径启动新的有界观察，然后重建或重新验证选择。绝不能将这份证据或其中的选择结果作为批次状态消费。

## 持久化不可用或尚未解决

当所需持久化尝试因能力、权限或证明路径不可用而无法启动，或者其调用或后状态含糊时，使用这个仅证据入口。不要发起额外的批次、执行者、标记、游标或其他持久化转换。对于尝试前边界，返回计划转换的准确记录、已观察前状态、缺失的能力/权限/证明、受保护效果，以及下一所有者/操作。只有这些要求可用且未变化的前状态得到重新证明后才能继续。

对于已经尝试的转换，保留其准确身份、前状态、未知后状态、调用与原始所有者证据、冻结的恢复所有者、残留项、受保护效果禁令，以及下一协调操作。只有该所有者才能协调同一次尝试并证明其后状态。在此之前，不得发起第二次转换、推断记录状态，也不得执行受保护效果或重试。

## 停止已建立的批次或执行者

通过持久化契约转换一个持久的批次或执行者交接。其中包含准确观察到的状态与效果、不可变批次与阶段、操作和尝试身份、调用或静止状态是否已证明、原始所有者状态/分类、已完成边界、残留状态、缺失的证明或决策，以及一个下一所有者/操作。酌情包含：

- 目标/基准、工作树/分支、认领、选择和依赖顺序；
- 执行者交接、单元基准/范围、工单提交与检查点、本地状态、验证、自审、审查发现和修复范围；
- 收尾器输入和阶段结果、已审查与已交付身份、历史政策、发布、ref、保留证据、跟踪器游标，以及清理/留存状态；并且
- 结果或所有权仍不确定的每项效果。

如果该转换无法开始，或者其调用或后状态含糊，则在该准确边界通过**持久化不可用或尚未解决**终止；不要发起或重复交接转换。

认领应保留至权威交付，之后继续保留，直至证明按依赖顺序完成并释放。保留已审查的来源历史，直到跟踪器和生命周期闭环证明其处置。恢复的所有者从这个准确交接开始；不要重复其原始尝试仍在进行或含糊的 Create、执行者、跟踪器操作、收尾器效果或清理。

本 Skill 不提供强制操作、rebase、rollback、reset、clean、discard、放弃认领、未配置的跟踪器变更、未授权远程效果，或删除已保留恢复状态的权限。此类操作需要单独的明确授权及其所属工作流。

**完成条件：**所有后续工作都已阻断，并且恰好返回一个入口：不虚构批次的有界批次前证据；没有另一次转换的不可用或进行中持久化边界；或者说明每项观察状态和效果的持久已建立交接。每次返回都指定准确的恢复所有者和下一项有用操作。
