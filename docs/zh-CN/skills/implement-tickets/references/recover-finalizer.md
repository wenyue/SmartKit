# 恢复缺失的收尾器响应

本参考负责处理一个缺失、中断或无法归属的`finish-worktree`响应。它不拥有收尾器效果或分类。进入时，应提供原始调用身份（如果宿主公开此信息）、准确的冻结输入、预期前状态、已审查的基准/`HEAD`/树、依赖契约、已保留的交接，以及所有已观察效果。

使用原始宿主/会话以及`finish-worktree`提供的恢复路径，判断同一次调用是否仍在运行，以及它是否生成了可归属的响应。在解析期间，保留其工作树、分支、ref、目标状态、发布证据、恢复对象和无关状态。当前目标内容或跟踪器状态可以帮助观察，但仅凭它们不能确定交付、**Already Delivered**、失败，也不能授予重试权限。

如果原始调用可能仍在运行或其效果仍然含糊，则以`in-flight`状态返回，并包含准确缺失的证据以及下一项由收尾器所有者执行的观察或恢复操作。如果原所有者恢复了具有因果归属的原始响应，则将该完整响应原样传给[`complete-run.md`](complete-run.md)的唯一收尾器结果路径。本参考绝不授权再次调用收尾器，也不虚构恢复或分类接口。

**完成条件：**原所有者提供一个可归属的原始结果，或者保留准确的进行中尝试及其下一所有者/操作，且不通过推断执行第二次效果。
