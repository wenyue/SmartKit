# 恢复丢失的收尾器响应

当响应缺失、中断或无法持久归属于某次尝试时，本参考会将进行中的收尾器尝试路由到其原始效果/恢复所有者。它不拥有收尾器效果、恢复、分类、跟踪器转换或清理。进入时，应持有持久的尝试身份、预期前状态、授权、冻结的`finish-worktree`契约与准确输入、已审查的基准/`HEAD`/树，以及所有保留的观察。原样保留原始逻辑效果尝试及其证据。

## 协调同一次尝试

通过冻结依赖契约允许的路径，在执行任何恢复变更之前，证明原控制器和收尾器已经静止。观察权威目标与分支、来源工作树与分支、相关 ref 与恢复对象、发布/依赖状态、完整效果包、无关状态保留情况，以及任何持久的依赖输出。只有已冻结尝试能证明归属时，才将观察与其建立因果绑定；仅凭当前目标内容绝不能证明交付或**Already Delivered**。

将进行中的准确尝试——身份、前状态、冻结输入与契约、父子效果证据、观察、残留项和不确定性——原样交给该契约指定的原始`finish-worktree`效果/恢复所有者。只有该所有者才能延续或协调其逻辑尝试，并返回权威原始结果。本路径不调用第二个收尾器效果，也不假定存在单独命名的恢复/分类接口。

从该所有者返回可建立因果归属的原始结果后，通过持久化契约转换准确响应和`result-awaiting-consumption`标记，不检查其分类。持久化转换不可用或含糊时，进入[`stop.md`](stop.md)的未解决持久化入口，并继续由其冻结的持久化恢复所有者负责。准确后状态得到证明后，将响应原样移交给[`complete-run.md`](complete-run.md)的已返回响应入口；无论分类是否可用，这都是唯一的公开结果路径。本参考不解释或枚举分类。

如果静止状态、因果所有权、效果协调，或者响应归属或返回仍然含糊，则保持原始尝试进行中，并保留每项已观察效果、准确缺失的证明，以及下一收尾器恢复所有者/操作。不得根据推断将其视为`stopped`或`failed`，也不得重试、执行跟踪器转换、清理、变更工作树或释放。

**完成条件：**原始效果/恢复所有者提供一个可归属的权威原始结果；或者保留准确的进行中交接及该所有者的下一操作，且不执行第二次效果尝试。
