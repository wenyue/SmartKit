# Worker 边界

Controller 负责一张工单或一次批次修复的范围及其验收。宿主运行时负责 Agent 身份、派发、中断、观察和停止活动的证明。确认其当前受支持的接口能够提供这些事实；运行时不可用或含糊时，在派发前停止。

每张新工单使用新的实施 Worker，每次新批次修复也使用新的 Worker。同一未完成候选的普通修复继续由原 Worker 负责。每次派发前，证明确切工作树和工作单元基线、当前 HEAD/tree 与本地状态归属、范围内操作权限，以及此前所有写入者都已停止活动。最多一个 Worker 可以写入。实施暂停期间，独立审查角色可以只读并行运行；它们独立于 Worker，也彼此独立。复用已建立环境，不复用上一张工单的 Worker 范围。

工单或修复流程负责提供 Worker 输入。将写入和正常 hooks 下的候选提交与 amend 限于当前工作单元。Worker 不能 amend 已验收提交、操作跟踪器、完成批次收尾，也不能自行授权完成标记。要求其返回内容标明 Agent 和原始状态、当前候选、最终 HEAD/tree、完整的归属内本地状态、检查及其输入、未解决发现和下一步操作。

保留原始结果。即使当前文件看似完整，失败仍是失败的尝试；应观察操作效果、解决原因，并在验收前取得受支持的继续执行结果或恢复结果。审查前证明写入已暂停，接收结果前证明 Worker 已停止活动。响应缺失或发生中断后，读取[暂停与恢复](resume.md)：经过的时间和看似合理的 Git 内容，都不能证明原 Worker 已停止。

## 必要时在认领前确认可派发

仅当跟踪器的释放、重新分配或过期语义意味着后续派发失败可能使拟议认领无法妥善处置时，使用这个只读门槛。确认运行时可用性、观察与控制路径、范围内权限，以及不存在可能仍在运行的竞争尝试。如果工作树已存在，验证其独占归属；创建前，仍保留派发前必须就绪的要求。共享事实仍有效时予以复用，只补充影响可行性的工单特定约束。

资格检查不派发 Worker、不预留容量，也不创建持久状态。存在尚未解决的实质派发风险时，停止认领，并指出该事实及下一位负责人。
