# Worker 边界

本 reference 负责一次工单或修复 Worker 尝试。

## 原则

- **有界所有权。**单元所有者提供范围、当前状态、权限和成功条件；主机运行时负责 Worker 身份、派发、观察、中断和静止判断。Worker 不取得整个批次或相邻单元的权限。
- **串行归因。**保留原始结果，并让原始尝试持续拥有控制权，直到主机证据证明它已静止，并对每项继承变更完成归因。此后，后继项或重建结果才可继续。

## 必要时验证声明资格

只有当 `tracker.md` 或 `process-one-ticket.md` 判断后续派发失败可能遗留拟议声明时，才以只读方式进入。确定环境所有的运行时和观察路径可以提供一次具有拟议权限的串行尝试。批次工作树已经存在时，还要确定独占控制权，以及任何保留 Worker 已静止；创建前则要确定没有可归因的批次 Worker 尝试仍在运行，并且派发前会检查就绪状态。在可观察时效条件仍成立时跨声明复用共同事实，只评估可能改变此结果的工单特定约束。

此门槛不分配或派发 Worker，不预留容量，不持久化状态，也不改变跟踪器或工作树。事实不可用或有歧义时，在声明前停止。

**完成条件：**无需效果即可解决可能遗留拟议声明的重要派发风险，或由确切未解决风险和所有者阻止该声明。

## 派发或恢复一次尝试

派发前立即确定批次工作树的独占所有权、确切单元基点及当前 `HEAD`、树和本地状态、一个合适的 Worker 身份、范围内写入与提交权限，并且每个更早尝试均已静止。若一个静止且可归因的批次 Worker 的前一个单元已经闭合，并且能无歧义地重新绑定其范围和权限，则复用它；否则使用新身份。能力缺失或 Worker 可能仍在运行时，在另一次派发前停止。

只向所选 Worker 提供该单元、适用项目规则、既有可归因状态、使其变更可以安全交回所需的针对性检查、成功谓词和范围内权限。Worker 可以在单元内创建可恢复提交，并返回其身份、原始状态、提交、最终 `HEAD` 和树、本地状态、检查证据、残留和下一步操作。它不执行跟踪器或最终化效果。整个批次的仓库验证和独立 Standards 与 Spec 审查仍是最终屏障，不由每个 Worker 重复执行。

保留原始返回。即使工作树看似完成，返回的失败也不会变成成功；单元所有者根据两类证据决定下一项安全处置。只有先前 Worker 已证明静止，并且每个观察到的提交和本地状态项都可归因于同一单元时，新的替代项才合格。将恢复的状态提供给新 Worker，而不是盲目重新开始。

**完成条件：**一个有界尝试已经返回并处于静止状态，或确切的不可用或运行中 Worker 边界得到保留。

## 恢复缺失响应

缺失响应既不证明失败，也不证明静止。检查原始主机身份和控制路径。Worker 可能仍在运行时，保留它对工作树的所有权，不允许替代项或重叠写入。

证明静止后，检查该单元的第一父级历史和完整本地状态。可归因的完整结果可以重建，并交给单元所有者独立证明。完全可归因的不完整状态可以在上述派发门槛下交给新的替代项。所有权混杂、静止状态不确定或效果无法解释时，继续由原始 Worker 身份持有运行中状态，以及下一项主机观察或恢复操作。

**完成条件：**原始尝试已静止，且其完整或不完整状态均可完整归因；或其确切运行中所有权和下一步操作得到保留。
