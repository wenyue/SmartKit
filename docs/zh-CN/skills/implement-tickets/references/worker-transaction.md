# 执行者边界

本参考负责一次工单或修复执行者尝试。单元所有者提供范围、当前状态、授权和成功谓词；宿主运行时负责执行者身份、派发、观察、中断和静止。使用实际公开的这些能力，不得要求独立的执行者状态存储或协议。

## 认领前确认资格

以只读方式进入，并提供一个选定工单、其预期单元和批次边界、工作树存在时的当前证据，以及拟授予的写入和提交权限。证明环境所有的执行者运行时及观察路径、一次全新串行尝试的容量、该单元可以获得的准确权限；批次工作树存在时，还须证明控制器拥有互斥控制权，且所有较早执行者均已静止。说明任何可归属的已保留尝试和状态。在创建新批次工作树之前，则应证明不存在批次工作树或可归属的批次执行者尝试、互斥控制路径可用，并且派发前将重新建立准确的就绪状态。

本门不会分配或派发执行者，不会预留容量或持久化状态，也不会变更跟踪器或工作树。任何事实不可用或含糊时，应在认领前停止。

**完成条件：**不会产生效果，并且已经证明当前可知且可能导致拟议认领搁置的每项执行者前置条件。

## 派发或恢复一个尝试

紧接派发前，证明批次工作树由控制器互斥拥有、单元基准准确，并确认当前`HEAD`/树/本地状态、一名可用的全新执行者身份、限定范围的写入和提交权限，以及所有较早尝试均已静止。缺少能力或执行者可能仍在运行时，应在再次派发前停止。

仅向全新执行者提供该单元、适用的项目规则、现有可归属状态、验证、成功谓词和限定范围的权限。执行者可以在单元内创建可恢复提交，验证并自审完整结果，并返回自身身份、原始状态、提交、最终`HEAD`和树、本地状态、验证、自审、残留项以及下一操作。执行者不得产生跟踪器或收尾器效果。

保留原始返回。即使工作树看似完整，返回失败也不能变成成功；单元所有者应根据两类证据决定下一项安全处置。只有在先前执行者已证明静止，并且每个已观察提交和本地状态项都可归属于同一单元时，才可使用全新替代执行者。应把恢复的状态提供给新执行者，不得盲目重新开始。

**完成条件：**一个全新尝试已经返回且执行者处于静止状态，或者准确的不可用或进行中执行者边界得到保留。

## 恢复缺失的响应

响应缺失不能证明失败或静止。检查原始宿主身份和控制路径。执行者可能仍在运行时，应保留其对工作树的所有权，不得使用替代者或执行重叠写入。

证明静止后，检查该单元的第一父历史和完整本地状态。可归属的完整结果可以重建，并交给单元所有者独立证明。可完整归属的不完整状态，可以在上方派发门下交给一个全新替代执行者。所有权混杂、静止状态不确定或效果无法解释时，应保持进行中，并保留原始执行者身份以及下一项宿主观察或恢复操作。

**完成条件：**原始尝试已静止，且其完整或不完整状态可以完全归属；或者其准确的进行中所有权和下一操作得到保留。
