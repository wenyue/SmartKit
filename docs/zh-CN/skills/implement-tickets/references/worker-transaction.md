# 执行者事务

本参考是工单或修复执行者尝试、响应、交接、静止、重建和替代的唯一权威。单元所有者提供其范围和成功谓词，并消费事务结果；它们不定义另一套执行者状态协议。

冻结环境所有的执行者运行时身份、控制器与执行者角色、派发与观察路径、限定范围的写入/提交权限、静止证明、替代权限，以及不可用/使用失败结果。消费持久化契约中现有的执行者交接记录身份、角色、能力、权限和生命周期。一个**执行者交接**会绑定这些事实、单元与基准、唯一的尝试和执行者身份、派发/响应证据、自有提交和本地状态、当前`HEAD`和树、验证/自审证据、原始结果、残留项，以及下一所有者/操作。能力缺失或变化时，在派发前停止。

## 确认单元边界资格

在工单单元所有者请求跟踪器认领前立即以只读方式进入。重新观察并证明已冻结的执行者运行时身份与观察路径、一次全新尝试的容量、限定权限，以及任何必需的静止状态和已保留执行者交接的所有权与状态。只向单元所有者返回准确的通过结果或缺失/不匹配边界。

该门不会分配或派发执行者，不会预留容量、变更工作树，也不执行持久化转换。缺失或不匹配的证明会阻断认领请求。

**完成条件：**在认领请求之前，已证明允许后续一次全新尝试所需的每项事实，且未发生任何状态变化。

## 派发一名全新执行者

只有在不存在先前尝试，或持有已证明静止的不完整尝试时才能进入。重新证明准确单元、当前自有状态、运行时身份、权限、容量和静止状态。通过持久化契约转换执行者交接，绑定唯一尝试、全新执行者身份、完整交接和获授权效果，然后只派发一次。

只向执行者提供其单元、适用的项目规则、恢复的自有状态、验证，以及单元范围的写入/提交权限。执行者应说明其完整范围、执行验证并自审，然后返回单元成功谓词要求的证据。

收到响应后，保留其原始状态和证据，收集当前宿主与工作树观察，然后进入下方**对一次已观察尝试进行分类**。不要把原始失败转换为成功。

**完成条件：**响应和当前证据已准备好交给公共分类器；或者准确、尚未解决的尝试已被保留。

## 恢复缺失的响应

响应缺失不能证明任何事情。冻结所有观察，首先通过已冻结的宿主路径证明原始执行者和派发均已静止。在此之前，保留其所有权；不允许替代或写入工作树。

证明静止后，根据持久的执行者交接、单元基准、工单提交边界、第一父历史和完整本地状态重建本次尝试。对于修复单元，使用相应的审查发现范围和修复范围，而不要虚构工单边界。然后进入返回响应所用的同一分类器；本分支不增加分类规则。

## 对一次已观察尝试进行分类

将下列谓词应用一次，既可用于返回的响应，也可用于根据缺失响应重建的证据：

- **完整：**尝试与执行者身份准确，静止状态已证明，每项观察状态与效果都已完整说明并可归属于该单元，并且完整的冻结成功谓词已证明。返回的原始失败不构成成功证据。
- **不完整：**身份与静止状态准确，每项状态和效果都已完整说明并可归属于该单元，但成功谓词尚未完全满足，或者返回的原始状态为失败。
- **含糊：**身份、静止状态、所有权、范围、本地状态或效果未解决、混杂或冲突。

通过持久化契约转换原始证据和分类。完整结果无需另一名执行者，直接进入单元所有者的独立验证。只有已证明不完整的结果才允许使用全新替代执行者，但必须先重新证明静止，并提供所有恢复状态。含糊结果保留原始进行中所有权和准确的下一观察/证明操作；既不能根据推断将其视为已失败/已停止，也不能授权替代或写入工作树。

**完成条件：**一个有证据支持的分类已持久化，并明确其唯一获准的下一操作。
