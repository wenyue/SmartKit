# 暂停与恢复

可能存在先前尝试、控制中断、证据缺失或出现重要阻碍时，阅读本文。在首个未证明边界暂停整个批次。保留部分文件、自有本地尾部改动、候选、已验收提交、领取权和恢复证据；后续票据保持未动。只在[主工作流](../SKILL.md)下继续原可归属工作。暂停不自动授予 revert、reset、clean、discard、放弃领取或变更队列的权限。

将效果发生前未证明的前提描述为 `stopped`。尝试后保留所有者返回的 `failed` 结果。原尝试可能仍在运行或效果未解决时，使用 `in-flight`。后续恢复中保留所有者更具体的词汇及独立已证明事实。无法确定可以继续时，报告具体阻碍和确切下一所有者/行动。

## 重建原批次及其最远阶段

使用已有 Git 历史、冻结选择/来源修订、跟踪器观测、检查/审查报告、公开所有者交接和可观察运行时状态。不创建批次日志。恢复归属未完成工作所需的事实：

- 范围、排除项、依赖顺序、领取计划和确切工作树/分支绑定。
- 不可变批次/单元基线、已验收前缀、当前候选、HEAD/tree 和完整本地状态归属。
- 检查来源及验收绑定；原审查输入、角色身份和各轴尝试状态；完整报告或恢复位置、发现处置、修复增量及 Controller 验证。
- 原始 Worker、跟踪器、Create 和收尾者结果、观测到的效果/残留、结果消费状态，以及未完成事项的所有者/行动。

领取可能先于工作树；收尾者回执可能在工作树移除后仍存在。如果证据证明没有发生批次效果，保留这一无效果前提结果，不声称批次已经存在。范围、所有权、基线、存活状态或效果含糊时停止修改。

已有或可能存在的收尾尝试优先，直到其所有者交回控制：

| 恢复出的状态 | 从此继续 |
| --- | --- |
| 收尾者响应缺失或收尾者可能仍存活 | 恢复下文的原收尾边界。 |
| 原始收尾结果尚未消费 | 进入[消费结果](../SKILL.md#consume-the-result)一次，包括已证明交付但跟踪器关闭未完成的情况。 |
| 收尾结果已经消费 | 仅恢复其指定的跟踪器、生命周期、分类或其他所有者行动，保留已证明效果，不再收尾或消费。 |
| 工作树尚未就绪 | 分别恢复领取和创建。 |
| 尚未收尾 | 恢复已验收提交前缀、至多一个当前票据或批次修复候选及其完整自有本地尾部改动；重新验证该阶段的跟踪器/来源事实和 Worker 控制。 |

### 重新确定工作区绑定

对于现有工作树，将物理路径、注册、Git common 身份、分支、不可变基线关系、HEAD/tree、index 及 staged/unstaged/untracked 状态与保留阶段比较。说明影响所有权、写入、检查、收尾或清理的忽略状态。给有边界的非关键残留指定所有者。缺少必需身份或工作树时，在其所有者处停止；已证明处于创建前的阶段可以在没有工作树时恢复领取/Create 关卡。

实现控制出现缺口后，请公开 `create-worktree` 在保护保留状态的前提下，重新评估该确切现有工作树。消费同一候选的新 `ready` 证据。复用不授权替代创建。在持续可归属控制下，当前身份/状态检查已经足够，除非重要漂移使就绪失效。未就绪或就绪未解决的情况仍由其所有者负责。

## 分别恢复领取和创建

重建冻结领取计划、带原始响应及当前证明的已证明初始领取前缀、任何失败/进行中领取及其操作前状态和预期增量、未动后缀，以及全部延后领取或无需领取路线。未解决领取既不属于已证明前缀，也不属于未动后缀。使用跟踪器所有者的原操作观察/恢复路线；初始领取未解决时不能继续创建。

对于每个未解决跟踪器效果，保留原尝试、票据、预期增量、操作前状态、原始证据、当前观测和下一所有者/行动。解决该操作期间，已取得领取权和已证明效果继续保留。

单独确定 Create 状态：

- 已证明 `never-started`：证据确定没有尝试且没有工作树。只有该状态在全部必需初始领取之后，才可进入干净创建。
- `non-ready-or-in-flight`：保留原效果及其恢复所有者。部分或中断的创建交回该所有者。
- 可归属的 `ready`：保留其快照，并在消费之前确定当前绑定。

刷新现有候选而不替换它。仅在当前领取和就绪状态可归属时推进。

## 恢复 Worker 独占控制

通过受支持的主机接口观察原 Worker。缺少响应既不证明失败，也不证明静止。它可能写入期间，保持独占所有权：不替换 Worker、不审查可变候选、不重叠实现。证明它停止后，才能恢复它或分配替代者。安全替代者在原单元范围和审查证据下，继承确切候选及自有本地尾部改动。

静止后，将历史及完整本地状态与已验收边界比较。保留已验收前缀。提交或尾注不能证明 Controller 验收；中断前写入的标记，在全部票据条件成立前仍未验收。混合或无法解释的改动，不会仅因所处位置而成为当前票据的一部分。

## 恢复原审查及验收

恢复不可变检查/审查输入及完整原报告。必要时重复缺失检查，并通过主机接口观察原审查角色。已证明从未开始的轴可以在原轮次的未变冻结输入上运行。已完成的轴绝不重复。已尝试后报告缺失，或无法确定是否运行过时，必须恢复或暂停，而不是替换为新正式审查。

审查冻结前，未完成但可归属的实现可以由其 Worker 继续。修复期间，恢复未完成的范围内工作，包括已返回但未验收结果，或按上文证明安全的替代者。使用原报告、处置和候选继续 [Controller 收束](../SKILL.md#close-findings-until-the-controller-can-accept)，直到验收或受阻。

经过标记操作、来源协调和收尾返回的恢复过程中，保留原始失败或中断。恢复既不重置正式轮次，也不使 Worker 返回自动成为已验收。同样的已验收历史和确切状态验收条件仍然适用。

## 恢复收尾边界

向原主机/会话及公开 `finish-worktree` 恢复路线提供已暴露的调用身份、冻结输入和预期操作前状态、已接受基线/HEAD/tree、原始交接及观测到的效果。该所有者确定存活状态并恢复其原效果/结果。与此同时，保留源、目标、发布、引用、回执和恢复对象。目标内容或跟踪器状态本身不能分类交付，也不能授权另一次尝试。

收尾者拥有其外部操作回执；这与保留交接及不另建批次日志兼容。执行或效果含糊期间，保留同一个 `in-flight` 尝试，以及缺失事实和下一所有者观测。将恢复的原始结果原样传给主消费步骤；对于已消费结果，仅恢复指定的未完成行动。绝不为取得回执而重复可能已完成的跟踪器或收尾效果。
