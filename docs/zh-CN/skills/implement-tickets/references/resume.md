# 暂停与恢复

遇到实质阻塞、控制中断、证据缺失、可能的先前尝试或保留交接时，读取本引用。在第一个未获证明的边界暂停整个批次。保留工作树、部分文件、候选、已验收提交、认领和恢复状态；后续工单保持未动。只按[审查与修复](review.md)接续原始可归属的未完成阶段，或使用剩余次数。无法确立验收时，报告确切阻塞及下一位负责人和操作。暂停不自动授予回退、reset、clean、丢弃、放弃认领或改变队列的权限。

前置条件未获证明且尚未产生其效果时，使用 `stopped`；尝试后保留负责人返回的 `failed` 结果；原始尝试可能仍在运行或其效果未解决时，使用 `in-flight`。保留负责人更具体的词汇和最强已证明事实。

## 保留接续所需事实

不建立批次 journal。使用 Git 历史、冻结选择和已接受来源版本、跟踪器观察、检查与审查报告、公共依赖交接，以及可观察的 Agent 状态。保留对归属、安全、验收和操作效果恢复有实质意义的适用事实：

- 范围、排除项、依赖顺序、认领计划，以及确切工作树与分支绑定；
- 不可变批次基线和当前单元基线、HEAD/tree、完整自有本地状态、已验收前缀及当前候选；
- 检查出处、验收绑定，以及 `review.md` 定义的原始审查与修复状态；
- 跟踪器、Worker、Create 和最终收尾的原始结果、操作效果与残留、最终收尾响应是否已被使用，以及下一位负责人和操作。

有证据证明尚未发生任何批次操作效果时，报告这一未产生效果的状态和缺失前置条件，不得声称批次已存在。最终收尾负责人拥有其外部操作记录；这些记录与本交接兼容。

## 恢复最靠后的可归属阶段

选择和认领可能发生在工作树创建前；最终收尾记录可能在工作树移除后仍保留。根据现有证据恢复原始范围和尝试。范围、归属、基线、活动状态或外部效果含糊时，停止修改。最终收尾尝试存在或无法排除时，优先处理它，直到其负责人交回控制：

- 最终收尾响应缺失或原调用可能仍在运行时，使用下方最终收尾恢复边界。
- 存在尚未使用的原始结果时，进入[使用结果](../SKILL.md#consume-the-result)一次，也包括已交付但跟踪器闭合未完成的情况。
- 结果已被使用时，只继续其指定的跟踪器、生命周期、分类或其他负责人操作。保留已证明效果；不再收尾或重复使用结果。
- 就绪前，按下文分别恢复认领和创建。
- 收尾前，恢复已验收提交前缀、最多一个当前工单或修复候选，以及其完整自有本地尾部状态。重新验证跟踪器、来源事实和 Worker 控制后，再返回该票或整批关卡。

存在工作树时，对照该阶段检查物理路径、注册、Git 共同身份、分支、不可变基线关系、HEAD/tree、索引，以及已暂存、未暂存和未跟踪状态。说明影响归属、写入、验证、收尾或清理的忽略状态；有界非关键残留由指定负责人保留。必需工作树的身份或存在情况未获证明时，在其负责人处停止。经证明尚未创建的阶段，可以在没有工作树时恢复认领和 Create 关卡。

实施进度边界发生控制中断后，请公共 `create-worktree` 重新评估这个确切已有工作树，并保护保留状态。只使用针对同一候选的新 `ready` 证据；复用不授权创建替代工作树。控制持续且归属明确时，当前身份和状态检查就足够，除非实质漂移使就绪失效。非就绪或未解决证据仍由其负责人处理。

## 分别恢复认领与创建

恢复冻结认领计划、带原始响应和当前证明的已证明初始认领前缀、可选的失败或进行中认领及其操作前状态和预期差异、未动后缀，以及全部延后认领或无需认领路径。未解决认领既不属于前缀，也不属于后缀。使用跟踪器负责人的原始操作恢复；认领未解决时，不能继续 Create。

独立确定 Create 的状态：有未尝试、无工作树证明的 `never-started`；带原始效果和恢复负责人的 `non-ready-or-in-flight`；或带快照、可归属的 `ready`。只有已证明 `never-started`，且所有必需初始认领已完成，才能开始干净创建。部分或中断创建交回原负责人；刷新已有候选，不暗中替换。只使用当前可归属的认领和就绪结果，保留成功操作的效果。

## 恢复原始角色与验收

通过宿主接口观察原始 Worker。响应缺失既不能证明失败，也不能证明已停止活动。它可能仍在写入时，保留其独占归属：不替换、不审查可变候选、不重叠实施。证明它已停止后，才能恢复它或指定替代者。替代者在原始单元范围内继承确切可归属候选和本地尾部状态；替换绝不增加修复次数。

确认停止活动后，将历史和完整本地状态与已验收边界比较。验收需要 Controller 证据，仅有提交或 trailer 不够。恢复不可变检查与审查输入和报告；按需重跑缺失检查。通过宿主接口恢复原始审查角色。已证明从未开始的维度，可以在原轮次中基于未变冻结输入运行；已完成维度绝不重跑。尝试后报告缺失或尝试状态不明时，必须恢复或暂停，不能进行替代审查。

恰在中断前写入的标记，在所有工单验收条件成立前仍未验收。保留此前已验收边界；不能仅按位置将混杂或无法解释的变更归入当前工单。

审查冻结前，可归属的未完成实施可以由原 Worker 继续。修复期间，只能恢复原来的未完成阶段及其工作，也可以由已按上文证明可安全接替的替代者处理。已返回阶段仍需更正时，保留失败并暂停。恢复出的完整结果，只有具备必需证明才能进入针对性闭合。保留原始失败或中断及恢复情况；标记操作、来源协调和最终收尾返回都沿用相同审查与修复状态。

## 恢复最终收尾边界

向原宿主、会话及公共 `finish-worktree` 恢复路径提供可用的调用身份、冻结输入与预期操作前状态、已接受 base/HEAD/tree、原始交接和已观察效果。该负责人确认活动状态并恢复原始操作效果与结果。其间保留来源、目标、发布、引用、操作记录和恢复对象；目标内容或跟踪器状态本身不能确定交付分类或授予重试权限。

执行或效果仍含糊时，保留同一个 `in-flight` 尝试，以及缺失事实和下一位负责人需做的观察。将恢复出的原始结果原样交给主 Skill 的结果使用步骤。绝不为获得记录而重复可能已完成的跟踪器或最终收尾操作。
