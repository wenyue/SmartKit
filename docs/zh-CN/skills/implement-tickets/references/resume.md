# 暂停与恢复

遇到可能的先前尝试、控制中断、证据缺失或实质阻塞时，读取本分支。在第一个未获证明的边界暂停整个批次。保留部分文件、自有本地尾部状态、候选、已验收提交、认领和恢复证据；后续工单保持未动。只按[主流程](../SKILL.md)继续原始可归属工作。暂停不自动授予回退、reset、clean、丢弃、放弃认领或改变队列的权限。无法证明可以继续时，报告具体阻塞及确切下一位负责人和操作。

前置条件未获证明且尚未产生其效果时，使用 `stopped`；尝试后保留负责人返回的 `failed` 结果；原始尝试可能仍在运行或其效果未解决时，使用 `in-flight`。在后续恢复中一并保留负责人更具体的词汇和最强已证明事实。

## 重建最靠后的阶段

使用 Git 历史、冻结选择和来源版本、跟踪器观察、检查与审查报告、公共负责人交接，以及可观察的运行时状态；不建立批次 journal。恢复范围、排除项、依赖顺序和认领计划；确切工作树与分支绑定、不可变批次与单元基线；已验收前缀、当前候选、HEAD/tree 和完整本地状态归属。保留检查出处和验收绑定、原始审查输入、角色身份及各维度尝试状态、完整报告或恢复位置、处置、修复差异及 Controller 验证。保留 Worker、跟踪器、Create 和最终收尾的原始结果、操作效果与残留、结果使用状态，以及未完成事项的负责人和操作。

认领可能发生在工作树创建前，最终收尾记录可能在工作树移除后仍保留。证明尚无批次操作效果的证据，可以支持因前置条件而停止且未产生效果的结论，但不能据此声称批次已经存在。范围、归属、基线、活动状态或效果含糊时，停止修改。已有或可能存在的最终收尾尝试优先处理，直到其负责人交回控制：

- 响应缺失或最终收尾调用可能仍在运行时，按下方最终收尾边界恢复。
- 将尚未使用的原始结果交给[使用结果](../SKILL.md#consume-the-result)一次，也包括已权威交付但跟踪器闭合未完成的情况。
- 结果已被使用时，只继续其指定的跟踪器、生命周期、分类或其他负责人操作，保留已证明效果，不再收尾或重复使用结果。
- 就绪前，分别恢复认领和创建。收尾前，恢复已验收提交前缀、最多一个当前工单或批次修复候选，以及完整自有本地尾部状态，再为该阶段重新验证跟踪器、来源事实和 Worker 控制。

已有工作树时，对照保留阶段检查物理路径、注册、Git 共同身份、分支、不可变基线关系、HEAD/tree、索引，以及已暂存、未暂存和未跟踪状态。说明影响归属、写入、检查、收尾或清理的忽略状态；将有界非关键残留归属到指定负责人。必需身份或工作树存在情况未获证明时，在该负责人处停止。经证明尚未创建的阶段，可以在没有工作树时恢复其认领和 Create 关卡。

实施控制中断后，请公共 `create-worktree` 重新评估这个确切已有工作树，保护保留状态。使用针对同一候选的新 `ready` 证据；复用不授权创建替代工作树。控制持续且归属明确时，当前身份和状态检查就足够，除非实质漂移使就绪失效。非就绪或未解决的就绪状态仍由其负责人处理。

## 恢复认领与创建

重建冻结认领计划、带原始响应和当前证明的已证明初始认领前缀、任何失败或进行中认领及其操作前状态和预期差异、未动后缀，以及延后或无需认领路径。未解决认领既不属于前缀，也不属于后缀。使用跟踪器负责人的原始操作观察或恢复路径；初始认领未解决时，不能继续创建。对于任何未解决的跟踪器操作效果，保留原始尝试、工单、预期差异、操作前状态、原始证据、当前观察及下一位负责人和操作。保留已取得的认领和已证明效果。

独立确立 Create 的状态：已证明无尝试、无工作树的 `never-started`；带原始效果和恢复负责人的 `non-ready-or-in-flight`；或带快照、可归属的 `ready`。只有已证明从未开始创建，且每项必需初始认领都已完成，才能开始干净创建。部分或中断创建交回原负责人；刷新已有候选，不暗中替换。只有使用当前可归属的认领与就绪结果后，才能推进。

## 恢复 Worker、报告与验收

通过受支持的宿主接口观察原始 Worker。响应缺失既不能证明失败，也不能证明已停止活动。它可能仍在写入时，保留独占归属：不替换 Worker、不审查可变候选、不重叠实施。证明它已停止后，才能恢复它或指定替代者。任何替代者均在原始单元范围和审查证据下，继承确切候选和自有本地尾部状态。

确认停止活动后，将历史和完整本地状态与已验收边界比较。提交或 trailer 本身不能构成 Controller 验收；中断前写入的标记，在每项工单验收条件成立前仍未验收。保留已验收前缀。不能仅按位置将混杂或无法解释的变更归入当前工单。

恢复原始不可变检查与审查输入和报告，按需重跑缺失检查。通过宿主接口观察原始审查角色。已证明从未开始的维度，可以在原轮次中基于未变冻结输入运行。已完成维度绝不重跑。尝试后报告缺失或尝试状态不明时，必须恢复或暂停，不能进行替代正式审查。

审查冻结前，可归属的未完成实施可以由原 Worker 继续。修复期间，恢复范围内的未完成工作，包括已返回但未验收的结果，也可以由已按上文证明可安全接替的替代者处理。使用原始报告、处置和候选，继续 [Controller 问题闭合](../SKILL.md#close-findings-until-the-controller-can-accept)，直到验收通过或受阻。在标记操作、来源协调和最终收尾返回过程中，一并保留原始失败或中断及恢复情况。恢复既不重置正式审查轮次，也不使 Worker 返回自动成为已验收结果。

## 恢复最终收尾边界

向原宿主、会话及公共 `finish-worktree` 恢复路径提供可用的调用身份、冻结输入与预期操作前状态、已接受 base/HEAD/tree、原始交接和已观察效果。最终收尾负责人确认活动状态并恢复原始操作效果与结果。其间保留来源、目标、发布、引用、操作记录和恢复对象；目标内容或跟踪器状态本身不能确定交付分类或授予重试权限。最终收尾的外部操作记录仍由其负责人管理，与此保留交接兼容。

执行或效果含糊时，保留同一个 `in-flight` 尝试，以及缺失事实和下一位负责人需做的观察。将恢复出的原始结果原样交给主流程的结果使用步骤；结果已被使用时，只恢复指定的未完成操作。绝不为获得记录而重复可能已完成的跟踪器或最终收尾操作。
