# 暂停与恢复

遇到实质阻塞、控制中断、证据缺失、可能的先前尝试或保留交接时，读取本引用。遇到第一个未证明边界即暂停整个批次。保留工作树、部分文件、当前候选、已验收工单和修复提交、认领及恢复状态；不处理后续工单。受支持的普通修复在仍有进展时可以继续，否则报告确切阻塞及下一位负责人和操作。

操作前提未获证明且尚未执行操作时，使用 `stopped`；已经尝试操作后，保留负责人返回的 `failed` 结果；原始尝试可能仍在运行或其操作效果未明时，使用 `in-flight`。保留负责人更具体的结果词汇和最强的已证明事实。停止后不得自动执行 revert、reset、clean、discard、放弃认领或改变队列。

## 保留有用的交接

不建立批次 journal。依靠 Git 历史、冻结选择和已接受来源版本、当前跟踪器观察、保留的检查与审查报告、公共依赖交接，以及可观察的活动 Agent 状态恢复。保留区分已完成、待处理和含糊工作所需的身份与因果边界。最终收尾负责人仍负责自身的外部操作回执。

交接应标明范围和排除项；依赖顺序与认领计划；确切工作树、分支、不可变的批次和工单或修复基线、HEAD/tree 及完整的归属内本地状态；已验收提交前缀与当前候选；检查和审查出处及验收绑定；跟踪器、Worker、Create 和最终收尾的原始结果；已观察到的操作效果与残留项；以及唯一确切的下一位负责人和操作。仅纳入适用证据，但必须覆盖所有对归属、安全、验收或操作恢复有实质影响的项目。任何操作都尚未发生时，报告这一证明及缺失前提，不声称批次已存在。

## 确立原始阶段

根据现有保留证据识别原始范围和尝试：选择与认领结果可能早于工作树创建，最终收尾回执则可能在工作树移除后仍然存在。范围、归属、基线、活动状态或外部操作状态含糊时，在下一次变更前停止。选择能够明确归属的最靠后阶段；一旦存在或无法排除最终收尾尝试，就不能恢复更早的实施阶段，除非该负责人的恢复流程将其交回：

- **就绪前：**按下文恢复冻结选择，以及相互独立的认领与 Create 状态。
- **最终收尾前：**恢复已验收提交前缀，以及至多一个当前工单或修复候选和其完整的归属内本地尾部状态。重新验证跟踪器与来源事实，恢复 Worker 控制后，再返回当前工单或整批验收关卡。
- **保留了最终收尾原始结果：**将其交给[使用结果](complete-run.md#consume-the-result)一次，包括已交付但跟踪器闭合尚未完成的情况。
- **最终收尾响应缺失或可能仍在运行：**按下文恢复原始尝试。
- **终止结果已经使用：**只恢复被点名的跟踪器、生命周期、分类或其他依赖负责人操作。保留既有结果，不重复使用该结果，也不再次收尾。

工作树存在时，根据已识别阶段重新核对其物理路径、注册、Git 共同身份、分支、不可变基线关系、HEAD/tree、索引和暂存、未暂存、未跟踪状态。已忽略状态影响归属、待写入操作、验证、最终收尾或清理时，也要核对；有界的非关键残留项连同负责人一起保留。如果该阶段需要既有工作树，却无法证明其身份或存在，则在该边界的负责人处停止。已经证明处于创建前阶段时，恢复认领与 Create 门槛不需要工作树。

实施前沿发生控制间断后，要求公共 `create-worktree` 重新评估这个确切的既有工作树，并保护保留状态。仅对同一候选使用新的 `ready` 结果；这是重新评估就绪，不是再次创建。未就绪或未解决结果仍由其负责人处理。持续保持可归属控制时，当前身份与状态检查即可满足要求，除非漂移使就绪证明失效。

## 分别恢复认领与创建

保留冻结的认领计划、带原始响应和当前证明的已证明初始认领前缀、可选的失败或进行中当前认领及其操作前状态和预期变化、尚未处理的后缀，以及每条延后认领或无需认领路径。尚未解决的当前认领既不属于前缀，也不属于后缀。通过跟踪器负责人恢复其原始操作；存在未解决认领时，Create 不能继续。

单独保留 Create 状态：`never-started`，附带不存在尝试或工作树的证明；`non-ready-or-in-flight`，附带原始操作效果、产物及负责人和操作；或可归属的 `ready`，附带其记录的快照。只有 `never-started` 且所有必需初始认领通过后，才能启动首次 clean 创建。部分完成或中断的 Create 交回其负责人；已有候选需要刷新就绪时复用该候选，不得悄然替换。仅凭当前可归属证明使用认领和就绪结果，不重复成功操作。

## 恢复 Worker 及其候选

响应缺失既不代表失败，也不代表 Worker 已停止活动。通过宿主控制接口观察原 Agent。只要它可能写入，就保留其独占归属，不允许替换、审查可变候选或重叠实施。恢复它或指定替代者前，先证明它已停止。替代者在原工作单元范围内接收确切、可归属的既有候选和本地尾部状态，不得盲目重启工单。

证明停止活动后，将 Git 历史和完整本地状态与已验收边界比较。已验收工单需要 Controller 验收证据，不能只看提交或完成 trailer。不可变的检查与审查报告及其原始输入绑定仍可用时，恢复这些证据；否则针对归属明确的候选补做缺失检查和两个独立判断。恰好在中断前写入的标记，在全部验收条件重新得到证明前仍属于未验收状态。保留已证明的先前边界。混杂或无法解释的变更继续保持阻塞，不能仅凭位置将其归给当前工单。

归属明确的未完成候选交回其 Worker，执行正常修复与验收循环。恢复出的完整结果，只有在全部必需证明成立后才能进入 Controller 验收；保留原始尝试的失败或中断，以及受支持的恢复结果。

## 恢复最终收尾的原始操作

保留已暴露的原始调用身份、冻结输入、预期操作前状态、已接受 base/HEAD/tree、原始交接和已观察到的操作效果。通过原宿主或会话及公共 `finish-worktree` 恢复路径，确认活动状态并恢复可归属结果。期间保留源和目标状态、发布情况、分支与引用、回执和其他恢复对象。当前目标内容或跟踪器状态不能独立给出交付分类，也不能授权重试。

如果调用可能仍在运行，或其操作效果仍然含糊，返回同一个 `in-flight` 尝试，指出缺失事实和负责人的下一项观察或恢复操作。如果负责人恢复了原始响应，将其原样交给 `complete-run.md`。不得仅为取得新回执而重复可能已完成的跟踪器或最终收尾操作。
