# 审查、收尾并闭环批次

必须且只能使用以下一个入口：

- **正常：**每个选定工单都有一个已证明的工单提交；每项适用的认领都被保留；没有遗留任何阻断性的审查状态、发现集或修复单元；批次工作树符合仓库的干净谓词，且没有无主本地尾部；每个忽略项都有说明；不可变目标/基准仍为当前状态；没有未解决的执行者尝试；也不存在收尾器尝试。进入**验证并审查一个不可变状态**。
- **修复恢复：**已保留的阻断发现、已审查状态、`repair_base`、修复自有提交和完整本地状态、适用的认领以及执行者状态，都可归属于同一个修复单元，且不存在收尾器尝试。进入**修复并重放**。
- **已返回收尾器结果：**存在一个完整且可归属的`finish-worktree`原始响应，包括权威交付结果已返回但跟踪器闭环尚未完成的情况。进入**消费收尾器结果**。

这些入口互斥。若存在没有准确工单或修复单元所有者的本地尾部、陈旧的目标/基准，或者未解决的执行者或收尾器，应进入[`stop.md`](stop.md)，不得运行更早阶段。

## 验证并审查一个不可变状态

冻结批次工作树当前的`HEAD`和树，并证明它相对于批次基准的整个批次 diff 非空。空 diff 不能进入当前公开`code-review`契约：保留每个工单提交边界、认领、工作树和恢复事实，然后携带该依赖边界及所有者进入[`stop.md`](stop.md)。不得制造变更，也不得声称已完成审查、收尾或交付。

对于非空 diff，运行仓库要求的完整验证。构造一个临时的原始 Spec 输入，其中包含完整的已接受批次范围、每个选定工单及其验收来源，以及它们引用的每项治理 Spec，同时保留每个组成部分的身份和来源。

从不可变批次基准调用公开`code-review`一次，并提供这份完整输入。要求 Standards 与 Spec 两个维度覆盖同一不可变 diff、基准、`HEAD`和树。Standards 必须覆盖该依赖项负责的仓库标准和异味基线输入；Spec 必须覆盖这份保留来源的原始工单/Spec 输入中的每个组成部分。验证失败、有文档依据的标准违规、Spec 不匹配、缺少维度、所有者定义的覆盖不完整，或无法分类的发现，都会阻断收尾。基线异味只属于建议，除非已接受的项目权威另行规定其具有阻断性。

**完成条件：**完整验证和两个审查维度在同一不可变 diff、基准、`HEAD`和树上通过且没有阻断发现，并且 Standards 与 Spec 分别证明已覆盖上述各自的来源。

## 修复并重放

把全部阻断发现和已审查状态冻结为一个修复单元。读取[`worker-transaction.md`](worker-transaction.md)，派发或恢复一个互斥的修复执行者，其范围仅限这些发现。修复提交不得带有工单 trailer。独立证明其完整范围和本地状态、每项发现均已解决、工单提交边界未变、要求的验证和自审已完成、最终工作树干净，以及目标/基准未变。

未完成的执行者结果或不受支持的修复应进入[`stop.md`](stop.md)。完整修复后，在返回**验证并审查一个不可变状态**并重新运行完整验证和两个审查维度之前，须重新建立每项**正常**入口谓词。修复后不得沿用任何先前证明。

**完成条件：**修复后的状态通过完整的验证/审查屏障。

## 恰好调用收尾器一次

根据当前证明构造公开`finish-worktree`输入：准确的来源工作树和目标；作为生命周期来源的初始`create-worktree`就绪交接；公开契约要求的、控制连续时可归属的实施交接，或出现间断后新取得的 Reuse `ready`交接；不可变基准；已审查的`HEAD`和树；完整的批次自有范围与边界历史；验证报告和两份审查报告；已接受的结果和历史政策；生命周期所有者；保留边界；发布事实；以及准确的效果与清理授权。不得提供跟踪器操作或其他交付判断。

紧接收尾器效果之前，必须依据[`tracker.md`](tracker.md)，针对冻结选择结果和本批次已消费的准确认领效果，对整个选择进行重新验证。漂移会使验证/审查屏障失效，并应在不调用收尾器的情况下进入[`stop.md`](stop.md)。

调用`finish-worktree`一次并保留其原始响应和可观察效果。如果响应缺失、中断或无法归属，应携带原始调用进入[`recover-finalizer.md`](recover-finalizer.md)；不得启动另一个收尾器尝试。

## 消费收尾器结果

完全按照依赖项的返回内容消费`status`、`classification`、各阶段结果、效果、残留项和交接。根据其保留的最强分类选择路径：

- 权威交付分类——只有在`finish-worktree`作出分类时才包括**Already Delivered**——进入[`tracker.md`](tracker.md)的交付后闭环。重新观察任何已被权威完成的跟踪器前缀，只继续未解决的后缀；绝不能重复已证明的跟踪器效果。除该独立证明的分类外，仍须保留任何原始 stopped 或 failed 状态。
- 非整合交接保持原样返回。工单保持开放；受支持的认领、工作树、来源边界历史、发布证据和恢复状态都留给其指定的所有者。
- `history finalized`或`no positive result`应通过`stop.md`返回该准确分类和交接；两者都不授权完成跟踪器工单。
- 不可用或含糊的分类，应通过`stop.md`返回一个已消费但尚未解决的分类交接。它保留完整原始结果、未知分类以及依赖项所有者/操作，不作推断，不重试收尾器，不产生跟踪器效果，也不允许之后再次消费。

原始`stopped`或`failed`状态随适用的分类分支一起保留。它不能把权威交付变成非交付结果，也不能独立授权完成跟踪器工单。

交付后跟踪器闭环完成后，将其证明交给收尾器交接指定的生命周期所有者。该所有者在不重复历史或结果效果的前提下，决定经授权的清理或保留。跟踪器闭环及其生命周期处置都得到证明之前，须保留来源边界历史。

**完成条件：**一次收尾器调用已有可归属结果且其准确路径已被消费，或者其原始进行中所有者及下一操作得到保留。
