# 审查、最终化并闭合批次

本 reference 负责唯一的整个批次屏障、其修复循环、一次最终化调用，以及交付后的跟踪器和生命周期闭合。

## 原则

- **不可变证据。**必要验证和 `code-review` 的两个维度在同一个批次基点、`HEAD`、树和差异上通过。修复会形成新的不可变状态，并重新执行整个屏障。
- **单一活动转换。**至多保留一个当前修复单元，最终化只调用一次。已完成的前置修复仍作为审计历史；推断或缺失的响应不授权重复执行。
- **闭合绑定所有者。**保留 `finish-worktree` 的原始状态和最强分类。只有权威交付才能开始闭合跟踪器；声明和源历史必须保留，直到跟踪器和生命周期所有者证明各自处置结果。

## 选择一个入口

恰好使用一个入口：

- **正常：**每个选定工单都有一个经过证明的工单提交；每项适用声明均得到保留；没有保留当前阻塞屏障结果，也没有当前可派发修复单元；批次工作树按照仓库谓词保持干净，不存在无主本地尾部；已观察到、且对批次所有权、待写入项、恢复、最终化正确性或清理安全具有实质影响的忽略或未跟踪状态均可归因，或作为所属残留保留；其他已观察到的非关键状态在其所有者名下记录为有界残留或未测试表面；不可变目标和基点仍是当前状态；没有未解决的 Worker 尝试；也不存在最终化尝试。不可变的前置修复单元审计历史不违反此入口。进入**验证并审查一个不可变状态**。
- **修复恢复：**当前阻塞屏障结果、失败的不可变屏障状态（无论只有验证还是已经审查）、`repair_base`、修复所有的提交和完整本地状态、适用声明，以及 Worker 状态，都可归因于恰好一个尚未产生已接受完整修复的当前可派发修复单元，并且不存在最终化尝试。进入**修复并重新执行**。
- **修复后状态重放：**当前阻塞屏障结果和当前修复单元仍处于活动状态；修复 Worker 已返回并静止；其完整修复所有范围和本地状态可归因；工单提交边界未改变；安全重放所需的检查通过；工作树干净；目标和基点仍是当前状态；并且不存在最终化尝试。进入**验证并审查一个不可变状态**，但不应用正常入口的“无当前阻塞项”或“无当前修复单元”谓词。
- **返回的最终化结果：**存在一个完整且可归因的原始 `finish-worktree` 响应，包括跟踪器闭合尚未完成的权威交付结果。进入**使用最终化结果**。

这些入口互斥。没有确切工单或修复单元所有者的本地尾部、陈旧的目标或基点，或者未解决的 Worker 或最终化，都会进入 [`stop.md`](stop.md)，而不会运行更早阶段。

## 验证并审查一个不可变状态

冻结当前批次工作树的 `HEAD` 和树，并证明相对批次基点的不可变整个批次差异非空。空差异无法进入当前公共 `code-review` 契约：保留每个工单提交边界、声明、工作树和恢复事实，然后携带该依赖边界和所有者进入 [`stop.md`](stop.md)。不要人为制造变更，也不要宣称审查、最终化或交付。

对于非空差异，运行仓库的必要验证；只有当变更表面或观察到的风险需要时，才选择额外检查。构建一份临时原始规格输入，其中包含已接受的批次范围、每个选定工单中实质相关的验收来源，以及它们引用的治理 Specs，并保留每个组成部分的身份和来源。记录仍未测试的非关键检查或表面，不要在没有风险所有者的情况下扩大通过门槛。

必要验证到达审查阶段后，从不可变批次基点调用公共 `code-review` 一次，并传入这份完整输入。要求 Standards 和 Spec 两个维度覆盖同一个不可变差异、基点、`HEAD` 和树。Standards 覆盖该依赖所有的适用仓库标准和 smell-baseline 输入；Spec 覆盖保留来源的原始工单或规格输入中的每项实质相关义务。**阻塞屏障结果**包括失败的必要验证结果、阻塞性审查发现、维度缺失或不完整，以及无法分类的所有者结果。基线异味属于建议，除非已接受项目权威另行规定其具有阻塞性。

正常入口和修复后状态重放共用一次屏障失败转换。在必要验证和两个审查维度全过程中保留任何当前修复单元。完整屏障通过后，只清除它当前的阻塞和可派发标记，并将它与任何前置单元一起保留为不可变审计历史；通过的正常状态没有需要清除的当前单元。此后结果便可以最终化。

屏障未通过时，保留失败的不可变状态、每项当前阻塞屏障结果、声明、工作树、目标和基点时效性，以及已经存在的完整验证和审查证据。对于修复后状态重放，先将已经完成的当前修复单元及其尝试转为不可变、不可再次派发的前置历史，并保留其状态、提交和本地状态、归属、Worker 静止性和工单提交边界。若支持修正，将失败的不可变状态和所有当前阻塞屏障结果原子冻结为恰好一个初始或后继当前修复单元，且其修复尚未开始或得到接受；后继单元只将完成的前置单元链接为历史。进入**修复恢复**。若不存在受支持的可继续修正，则携带保留证据和下一位所有者或操作进入 [`stop.md`](stop.md)。绝不从失败屏障调用最终化。

**完成条件：**必要验证和两个审查维度在同一不可变差异、基点、`HEAD` 和树上通过，没有阻塞屏障结果；每个维度证明其所属覆盖；任何明确标为非关键的未测试表面都得到披露，且不扩大结果。

## 修复并重新执行

进入时恰好有一个当前修复单元，其中包含阻塞屏障结果和失败的不可变状态；该状态可以只有验证，也可以已经审查。其修复尚未开始或仍不完整；已完成的前置单元只作为不可变历史保留。读取 [`worker-transaction.md`](worker-transaction.md)，并且只为当前单元派发或恢复一个独占修复 Worker。修复提交不含工单 trailer。独立确定完整且可归因的修复所有范围和本地状态、Worker 静止性和状态、未变的工单提交边界、安全重放所需检查、干净的最终工作树，以及未变的目标和基点。除非证据矛盾、实质不完整或陈旧，否则接受可归因的 Worker 证据；阻塞屏障结果是否解决，由重新执行的验证和审查屏障判断。

非完成 Worker 结果或不受支持的修复会进入 [`stop.md`](stop.md)。修复完成后，确立每个**修复后状态重放**谓词，并在保留发现和修复单元的同时进入**验证并审查一个不可变状态**。针对新的不可变状态重新运行必要验证和两个审查维度；只让有效性依赖先前差异的证据失效。

**完成条件：**修复后的状态通过整个验证和审查屏障。

## 调用最终化一次

只有一个可以最终化的不可变状态，其必要验证和两个审查维度均已通过，并且不保留当前阻塞屏障结果或可派发当前修复单元时，才能进入。允许保留不可变的前置修复单元审计历史，且这些单元仍不可派发。

根据当前证明构建公共 `finish-worktree` 输入：完整的已接受批次范围和工单或规格来源；确切源工作树和目标；不可变基点；已审查的 `HEAD` 和树；完整批次所有范围及边界历史；验证和两份审查报告；已接受结果和历史策略；不可变修复单元审计历史；保留边界；当前发布事实；以及确切效果与清理权限。跟踪器操作和替代交付判断仍由其各自所有者负责。

在最终化效果发生前，立即重新观察源工作树的注册、路径、分支、`HEAD`、树、索引和本地状态，以及目标引用。要求源身份匹配已审查状态，然后要求 [`tracker.md`](tracker.md) 对照冻结选择结果和本批次已经使用的确切声明效果，重新验证整个选择。任一检查发生漂移都会使验证和审查屏障失效，并在不调用最终化的情况下进入 [`stop.md`](stop.md)。

调用 `finish-worktree` 一次，并保留其原始响应和可观察效果。若响应缺失、中断或无法归因，携带原始调用进入 [`recover-finalizer.md`](recover-finalizer.md)；不要开始另一次最终化尝试。

## 使用最终化结果

完全按照依赖返回的内容使用 `status`、`classification`、阶段结果、效果、残留和交接。依据其中保留的最强分类选择路径：

- 权威交付分类——仅当由 `finish-worktree` 分类时才包括**已交付**——进入 [`tracker.md`](tracker.md) 的交付后闭合。重新观察任何已权威完成的跟踪器前缀，只继续其未解决后缀；绝不重复已证明的跟踪器效果。与分类独立证明的同时，保留任何原始 stopped 或 failed 状态。
- 非集成交接原样返回。工单保持开启；受支持的声明、工作树、源边界历史、发布证据和恢复状态仍归其指定所有者。
- `history finalized` 或 `no positive result` 通过 `stop.md` 返回该确切分类和交接；两者均不授权完成跟踪器。
- 不可用或有歧义的分类通过 `stop.md` 返回一份已使用但分类未解决的交接。它保留完整原始结果、未知分类以及依赖所有者或操作，不进行推断、最终化重试、跟踪器效果或后续重复使用。

原始 `stopped` 或 `failed` 状态随适用的分类分支一起保留。它不能将权威交付变成非交付结果，也不能独立授权跟踪器完成。

交付后的跟踪器闭合完成后，将其证明交给最终化交接中指定的生命周期所有者。该所有者决定获准清理或保留，不重复历史或结果效果。保留源边界历史，直到跟踪器闭合和生命周期处置均得到证明。

**完成条件：**唯一的最终化调用已经产生可归因结果并使用其确切路径，或原始运行中所有者及下一步操作得到保留。
