# 处理一张工单

以一张冻结且依赖已就绪的工单，以及可归属的批次工作树进入。Worker 产出候选；只有 Controller 能验收并给出 `completed-in-batch`。冻结审查前读取[审查与修复](review.md)，恢复既有阶段时读取[暂停与恢复](resume.md)。

## Worker 协议 <a id="worker-protocol"></a>

本协议适用于每张工单和批次修复。每个新单元使用新的 Worker；同一票的实施和集中修复由该 Worker 负责。宿主运行时必须提供受支持的派发、身份、观察、中断和停止活动确认接口。运行时不可用或含糊时，在派发前停止。

紧接派发前，证明确切工作树和单元基线、当前 HEAD/tree、本地状态归属及范围内权限，并确认此前每个写入者都已停止活动。最多一个 Worker 可以写入。实施暂停时，只读独立审查角色可以并行运行。复用已建立环境，每个 Worker 都限于当前单元。

向 Worker 提供规范工单身份或批次修复范围、完整要求和来源版本、项目规则、依赖结果及相关研究指针。还应包含确切工作树、批次与单元基线、此前已验收提交、必需针对性检查，以及范围受限的写入和正常 hook 提交权限。修复还需接收 `review.md` 中的冻结审查证据、汇总发现和剩余次数。Worker 只能修改所属单元的候选；不能 amend 已验收提交、操作跟踪器、为批次收尾或授权自己的完成标记。

要求返回 Agent 身份和原始状态、候选与最终 HEAD/tree、完整自有本地状态、检查及其输入、阶段已返回还是仍处于中断状态，以及未解决工作和下一步操作。修复还应包含发现处置和确切差异。即使文件看起来已完成，也保留失败尝试的事实；通过 `resume.md` 恢复原始阶段事实。审查前证明写入已暂停，验收前证明已停止活动。仅凭响应缺失或经过的时间，都不能判定失败或停止活动。

## 确立候选

使用[跟踪器边界](tracker.md)，重新验证完整已接受来源、阻塞、状态和认领。使用已证明的初始认领、执行受支持的即时认领，或确立当前无需认领的资格。将 `ticket_base` 及其树冻结在前一个已验收 HEAD；恢复时保留该边界，不选择新基线。

按上文协议派发工单 Worker。要求完整预期工单结果，以及验收和后续安全工作所需检查。明确说明确实不关键、延后到整批关卡的覆盖。普通实施、测试和调试持续到审查冻结为止。

结果非空时，Worker 通过正常 hooks 创建一个候选，其唯一父提交为 `ticket_base`。提交消息使用配置跟踪器可发现的工单引用语法，且不含 `SmartKit-Ticket` trailer。无需变更时，保留基线状态用于基于要求的审查；不得遗漏预期变更来制造空差异。

暂停写入，独立核实完整预期结果、已通过的工单检查、按项目判据判断为干净的索引与工作树，以及重要未跟踪或忽略状态的明确归属。冻结审查前，将遗漏变更或失败检查交回同一 Worker。

## 审查并闭合问题

从确切 `ticket_base` 应用 `review.md` 的单轮契约：diff 非空时使用公共 `code-review`，为空时独立审查既有满足情况。完整报告齐备后，Controller 处置发现，并在该单元剩余次数范围内将集中修复交给同一 Worker。只 amend 当前未发布、未验收候选；修复改变基线状态时，创建该工单的唯一候选。使用正常 hooks。

按 `review.md`，在结果状态上进入 Controller 问题闭合。diff 形态变化沿用原轮次。只有该契约的验收证据成立，才能进入标记步骤；存在未解决发现、覆盖不足或仍需进一步修复时，暂停批次。

## 标记已接受候选

问题闭合后，Controller 授权在这个确切候选上执行一次受限的正常 hook 操作，携带规范工单引用和唯一 trailer：

```text
SmartKit-Ticket: <canonical-id>
```

amend 已有候选的消息。无改动且没有候选的工单，创建一个以 `ticket_base` 为唯一父提交的空提交。修复使已有候选变为空差异时，将同一候选 amend 为空工单提交；绝不追加另一个工单提交。

重新核对结果树、diff 和提交。将仅元数据变化的等价结果明确绑定到原始报告，保留其出处，并重新运行依赖提交身份和 hooks 的检查。无改动结果必须与基线树相同，并保留明确的满足要求证据。

hook 产生内容变更时，工单保持未完成。只有尚未使用的单票修复机会且原始覆盖充分时，才能移除过早标记，并通过针对性闭合解决 hook 差异。闭合后重新授权标记。次数已用尽、证据不足，或再次发生需要修复的内容变更时，保留状态并暂停。标记或 hook 成功本身都不能构成验收。

## 验收工单提交

标记操作后暂停写入。Controller 独立证明：

- 从 `ticket_base` 起的第一父级范围恰好包含一个提交，以该基线为唯一父提交，且唯一工单 trailer 包含规范 ID；
- 完整结果属于该工单，此前已验收提交未变，最终 tree/diff 已绑定到原始审查及任何 Controller 修复闭合证据；
- 必需检查和全部 `review.md` 验收条件在结果状态上成立，工作树干净，且 Worker 已停止活动；以及
- 工作树与目标绑定，以及冻结来源、阻塞、状态和认领仍有效。

将该提交作为 `completed-in-batch` 返回。它满足后续工单的选定依赖，但既不证明跟踪器完成，也不证明交付。验收后该提交固定；之后任何更正都由整批关卡在其剩余次数范围内负责。
