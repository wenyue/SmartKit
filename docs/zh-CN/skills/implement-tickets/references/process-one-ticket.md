# 处理一张工单

进入时，已有一张冻结且依赖就绪的工单，以及归属明确的批次工作树。派发前读取 [Worker 边界](worker-transaction.md)。Worker 产出候选结果；只有 Controller 能验收为 `completed-in-batch`。

## 确立工单并选择审查路径

使用[跟踪器边界](tracker.md)重新验证工单、完整的已接受来源、阻塞项、状态和认领。使用已证明的初始认领、执行受支持的即时认领，或证明当前无需认领时的执行资格。将 `ticket_base` 及其树冻结在前一个已验收 HEAD。恢复时，通过[暂停与恢复](resume.md)找回该边界和归属明确的当前状态，不另选基线。

向一个新的 Worker 提供规范工单 ID、完整要求和来源版本、适用项目规则、依赖结果、相关研究指针、确切工作树及批次和工单基线、先前已验收提交的身份、针对性检查，以及范围内的写入和提交权限。要求所有预期变更都属于该工单。运行工单验收和后续安全工作所需的检查；确属非关键且延后至整批验证阶段的覆盖范围应明确披露。

选择提交与审查顺序前，先确定满足工单是否需要代码变更。如果无需变更，使用[独立空差异验收](review.md#independently-accept-an-empty-difference)证明现有实现已满足要求，并创建其已获授权的空工单提交，然后进入下方的**验收工单提交**。非空结果先执行**审查并标记非空候选提交**。任何分支都不得遗漏预期变更来制造空结果。

## 审查并标记非空候选提交

Worker 通过正常 hooks 创建一个候选提交，其唯一父提交是 `ticket_base`。提交消息使用配置的跟踪器可发现的引用语法标识工单，但不包含 `SmartKit-Ticket` trailer。暂停 Worker 写入，独立验证 HEAD 包含全部预期结果、索引和工作树满足项目的干净状态判定，且所有重要的未跟踪或已忽略状态都有明确负责人。遗漏变更或检查失败时，在审查前交回同一个 Worker。

从确切的 `ticket_base` 调用公共 `code-review`，审查冻结的候选状态。提供完整的已接受工单和规格输入，即使通过提交消息只发现了一个组成部分，也要保留每个来源的身份和版本。要求独立的 Standards 和 Spec subagent 都覆盖这个确切的基线、HEAD/tree 和 diff。Standards 保留该依赖完整的标准与代码异味基线契约；启发式异味仅作建议，除非项目权威使其成为阻塞项。跳过或不完整的 Spec 维度不能让本工作流通过。

保留完整报告及其原始被审提交身份。阻塞发现交回同一个 Worker，由它通过正常 hooks 修复并 amend 当前未发布、未验收的候选提交。再次暂停写入，重复适用检查，并在得到的不可变状态上重新运行公共审查的两个维度。先前报告可为新 Reviewer 提供参考，但不能作为变更后代码的通过结论。如果修复得到的结果确实为空，在添加标记前转入独立空差异验收。能力缺失、证据含糊或修复无法取得进展时，进入 `resume.md`。

必需检查和两个维度都通过后，Controller 授权一次受限的、经过正常 hooks 的当前候选提交消息 amend，追加唯一完成 trailer：

```text
SmartKit-Ticket: <canonical-id>
```

该授权仅覆盖这个确切候选和消息变更。Worker 无权标记另一张工单或 amend 已验收历史。仅元数据变化的 amend，只有在全部审查输入仍等价时才能复用审查证据。保留原报告的被审提交，并明确记录与新提交的绑定，不改写其出处。重新运行依赖提交身份或 hooks 的检查。如果 hooks 产生内容变更，通过结论失效：候选继续保持未完成，在受支持的修复中移除过早加入的完成标记，并在再次标记前重走候选、检查和审查顺序。

## 验收工单提交

任一审查路径及其已授权提交操作完成后，Controller 暂停写入并独立证明：

- 从 `ticket_base` 开始的第一父级范围内恰好有一个提交，其唯一父提交是 `ticket_base`，唯一工单 trailer 是规范 ID；
- 整个已接受结果都属于这张工单，此前已验收提交未变，最终树和已接受 diff 与完整审查或空差异验收的输入一致；
- 必需检查在结果状态上通过，完整的 Standards 和 Spec 证据仍有效，工作树干净，Worker 已停止活动；以及
- 工作树与目标的绑定，以及冻结的来源、阻塞项、状态和认领仍然有效。

即使 hook 成功，trailer 本身也不是验收证据。将独立验收通过的提交作为 `completed-in-batch` 返回。它满足后续工单在本次选择中的这项依赖，但既不证明跟踪器已完成，也不证明已交付。
