# 处理一个工单

进入时，应持有一个已冻结且依赖就绪的工单、仅由本单元控制的批次工作树，以及没有执行者尝试或其持久交接。唯一的成功结果是`completed-in-batch`。

## 确认资格、认领并定义单元

如果尚未加载[`tracker.md`](tracker.md)的冻结契约，请先读取该文件。重新观察工单、认领、完整契约、验收来源和阻断项。

在执行认领效果之前，读取[`worker-transaction.md`](worker-transaction.md)，并让其通过本工单的只读资格门：必须证明已冻结的运行时身份与路径、全新尝试容量、权限，以及任何必需的静止状态和已保留交接。该门不会分配或派发执行者，也不会持久化尝试。只有通过后，跟踪器所有者才能通过其操作契约执行或接受认领增量。保留该认领，直到权威交付和跟踪器闭环。

对于新工单，将当前`HEAD`和树冻结为`ticket_base`。恢复时，重建原始基准，并将之后的每个提交以及暂存、未暂存和未跟踪项全部归入本工单的状态；所有权混杂或含糊时停止。

向该事务提供一个**工单单元**，其中包含规范工单与完整来源、阻断项证明、批次/工作树身份、不可变基准、`ticket_base`、更早的工单提交、已有恢复状态、限定范围的写入和提交权限，以及项目要求的验证。其成功谓词为：

- 只实施本工单，并且每个自有项都已说明；
- 定向验证和要求的完整验证均通过，且整个单元已对照所有工单来源完成自审；
- 工作树干净；并且
- 第一父单元范围以恰好一个工单提交结束，该提交恰好带有规范 trailer，而之前的每个检查点都不含工单 trailer。如果净变更已经包含在检查点中，工单提交可以为空。

**完成条件：**认领、单元边界、成功谓词、自有恢复状态和执行者权限均准确无误。

## 获取并证明结果

仅由`worker-transaction.md`判定现有尝试是完整、不完整、含糊还是可派发。每次获授权的尝试都使用一名全新执行者。重建或返回的完整结果直接进入独立证明；只有已证明静止的不完整结果才可以获得全新替代执行者。其他所有结果都停止在该事务的交接处。

独立地重新推导并证明完整工单单元结果：执行者身份与静止状态、从`ticket_base`开始的第一父祖先关系、每个提交与本地项的所有权、验证与自审、干净的最终`HEAD`和树、未变化的权威目标，以及唯一且准确的工单提交/trailer 边界。接受前重新观察工单和阻断项。

任何不匹配、残留、来源变化或未证明要求，都通过`stop.md`返回准确的执行者或单元交接。否则，通过持久化契约转换批次交接，将工单提交记录为本工单的持久依赖边界，然后返回`completed-in-batch`。这既不是跟踪器完成，也不是批次交付。

**完成条件：**已为该工单记录一个独立证明的工单提交边界。
