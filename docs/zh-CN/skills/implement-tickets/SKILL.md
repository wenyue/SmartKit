# 实施工单

在一个隔离的**批次工作树**中，依次运行一个非空的**工单批次**。执行者尝试必须串行且互斥；每次获授权的尝试都使用一个全新身份，绝不能跨尝试或单元复用。一个工单可以包含**检查点**提交，但必须以恰好一个**工单提交**结束，并且该提交恰好带有下列 trailer：

```text
SmartKit-Ticket: <canonical-id>
```

检查点和修复提交均不得带有工单 trailer。控制器保留可恢复的第一父边界，但执行者仅拥有分配给自己的单元。选定批次只进行一次整个批次的审查和一次收尾；修复后的完整验证与审查重放仍属于同一批次。

使用项目所有的跟踪器、工单/Spec 来源、仓库规则和验证。通过当前公开契约调用公开的`create-worktree`、`code-review`和`finish-worktree` Skill。这些依赖项保留各自的判断权：尤其是，只有`create-worktree`决定就绪性，只有`finish-worktree`决定交付、**Already Delivered**和非整合分类。除了调用者及这些所有者提供的权限外，本 Skill 不授予任何跟踪器、Git、执行者、网络、发布、留存或清理效果。

在执行任何批次效果前，调用者或环境必须冻结一份**持久化契约**。该契约应指定仓库候选状态或缓存状态之外的一个持久路径和存储区；存储区所有者和获准角色；批次与执行者交接、`create-worktree` Create/Reuse 调用尝试及原始响应、收尾器尝试及原始响应、收尾后进度标记和操作游标的现有记录身份；每个角色准确的读取、写入、留存和删除能力与权限；前后证明；恢复所有者；以及每个消费者、生命周期、留存和删除处置。只使用这些记录和所提供的机制——不得创建仓库文件、缓存、独立适配器或全局锁。

每次记录转换都是一项具有唯一身份且获授权的持久化尝试。观察其准确前状态，写入一次，然后重新读取并证明准确后状态。能力或权限不可用时，应在尝试前停止；无法获得可验证的后状态时，应在受保护效果前停止。含糊的转换保持进行中且不得重复；在冻结的恢复所有者协调同一次尝试之前，其受保护效果不得运行。保留恢复记录，直到其冻结的消费者和生命周期所有者证明处置完成。删除遵循同一转换规则，并要求准确的删除权限和后状态证明。之后所有关于记录、转换、推进或保留持久状态的指令，都指这份契约。

公开`create-worktree`的每次 Create 或 Reuse 调用，都通过使用这些现有尝试与响应记录的一项**工作树调用边界**。调用前，转换一个唯一尝试，绑定模式、准确输入与前状态、权限，以及原始角色/效果恢复所有者；证明其后状态，然后调用一次。收到可归属的返回后，转换完整原始响应并证明其后状态，之后才能消费。响应缺失或含糊时，该调用保持进行中，并将其未改变的身份、输入、证据和不确定性交给冻结依赖契约确定的原始所有者。在该所有者返回可归属响应，或者准确协调原始效果、残留项和当前状态，并得到冻结依赖契约证明其处置允许下一次调用之前，新的 Create 或 Reuse 调用均不符合资格。此边界不假定存在恢复接口，也绝不推断`ready`或`non-ready`。只有在两项记录证明都通过，并立即重新检查公开的模式专属就绪快照后，才能消费`ready`。

通过该契约，在第一个非持久化批次效果前冻结一份持久的**批次交接**。它绑定规范范围与来源、选择和依赖顺序、不可变目标/基准提交与树、结果与历史政策、批次工作树身份与生命周期所有者、跟踪器操作与认领、执行者运行时/留存权限、验证与审查来源、工单提交边界、收尾器尝试、每项相关授权与效果，以及准确的当前阶段和下一所有者。在每个可恢复边界保持其最新。不可变字段发生漂移时停止本批次。

对于收尾后恢复，现有进度标记恰好有三种状态：

- `result-awaiting-consumption`在公开结果路径运行前绑定准确的原始响应；
- `delivery-consumed`在结果路径消费权威交付分类后，绑定该响应及当前跟踪器/生命周期游标；或者
- `non-delivery-consumed`在任何其他结果路径运行后，绑定该响应、选定的公开结果分支、保留的交接、下一所有者/操作，以及生命周期/留存处置。

每次进度标记转换都包含当前批次交接，并证明两者准确且彼此一致的后状态。消费路径必须在任何分支效果、返回或交接前完成转换。转换不可用或含糊时，`result-awaiting-consumption`保持进行中并阻断该分支。这些已证明状态使首次消费、交付闭环和非交付处置互斥。

在第一个未完成边界——无论由所有者返回，还是控制器发现路径含糊、冲突、无效因果链或其他未证明边界——先读取[`references/stop.md`](references/stop.md)，再分类或返回。根据原始边界选择其中的入口。其批次前和未解决持久化入口只返回证据，不执行另一次持久转换；其已建立入口会更新现有批次或执行者交接。把原始证据交给该所有者；不要在此重现其状态映射，也不要推断可以继续。

## 路由入口

最初只观察非跟踪器的持久批次、Git、已保留执行者和收尾器证据，不进行变更。在观察任何工单、阻断项、状态、认领、选择或跟踪器残留前，读取[`references/tracker.md`](references/tracker.md)，并把该观察委托给其所有者。如果选择路径需要此类证据，应在选择路径前加载它；完全不需要此类证据的仅收尾器路径则不加载。选择一个路径：

- **新建：**非跟踪器证据允许成为新建候选项。通过跟踪器首次使用门后，只有控制器将一个非空冻结选择结果与跟踪器自身的工单、认领、残留和操作游标观察组合起来，并证明它与可归属的未完成批次或进行中跟踪器操作均不重叠时，才允许建立。如果跟踪器与非跟踪器的组合证据唯一绑定一个现有批次或操作，则路由到该现有所有者。归属含糊或冲突时进入`stop.md`。
- **收尾之前：**重建准确批次、第一父边界、至多一个当前单元范围，以及全部本地状态。每一项都必须只有一个批次单元所有者。对于工单前沿，加载[`references/process-one-ticket.md`](references/process-one-ticket.md)；对于修复或审查前沿，加载[`references/complete-run.md`](references/complete-run.md)。如果可能已派发执行者，其路径必须先加载[`references/worker-transaction.md`](references/worker-transaction.md)并证明执行者边界。完成任何必需的静止证明后，冻结观察到的当前`HEAD`和树，并针对该调用者冻结的快照，通过工作树调用边界以 Reuse 模式调用一次。只有获得可归属的原始`ready`交接，并立即重新检查就绪快照后才能继续。
- **返回的收尾器结果等待消费：**存在持久的原始响应，并且收尾后标记和批次交接在`result-awaiting-consumption`状态上一致，同时证明其结果路径尚未运行。读取`complete-run.md`，仅带该未修改响应进入其仅结果入口。
- **已消费的非交付结果：**标记与批次交接在`non-delivery-consumed`状态上一致，并绑定收尾器尝试及准确原始响应、选定的公开结果分支、阶段、保留的交接、下一所有者/操作，以及生命周期/留存处置。只返回或恢复该绑定的所有者/操作；绝不重新进入结果消费、跟踪器闭环或收尾器效果。
- **丢失或进行中的收尾器响应：**尝试已经存在，但没有可归属的持久响应或已消费结果标记。读取[`references/recover-finalizer.md`](references/recover-finalizer.md)并返回其路径。
- **已消费交付但闭环不完整：**标记绑定准确的`finish-worktree`权威交付分类和当前跟踪器或生命周期游标。对于跟踪器游标，读取`tracker.md`；否则从已绑定游标恢复冻结的`finish-worktree`/生命周期清理所有者。

目标状态、工单状态、不存在本地变化或缺少清理，均不能替代持久的因果证据。身份、所有权、阶段含糊或存在多个可能路径时，通过上述首次使用门进入`stop.md`。

**完成条件：**已建立恰好一条权威路径及下一所有者。

## 选择并建立新批次

解析一个有界范围，并让`tracker.md`提供其冻结的**选择结果**。消费其中的选定工单、完整来源、依赖图与顺序、排除项、外部完成证明和漂移边界，不要重新解释。

在变更前，冻结批次交接，以及每个可达工单和修复所需的准确执行者/运行时能力。以不可变目标基准为起点，通过工作树调用边界以 Create 模式调用一次。如果响应丢失或建立过程含糊，绝不能重复 Create。只有原始所有者证明调用方和创建方均已静止，并将观察到的每个候选项准确协调到该次调用后，才能在同一边界下使用一次 Reuse 调用，针对调用者冻结的当前`HEAD`/树及不可变基准谱系验证该准确工作树。否则，停止并保留尝试与残留项。

只有在边界的尝试与响应证明通过后，才接受该公开 Skill 可归属的原始`ready`交接。在首次认领或变更工作树前，立即重新检查其模式专属就绪快照。保留规范检出目录及无关状态。

**完成条件：**闭合选择、不可变批次、空跟踪器操作前缀，以及处于不可变基准上的一个就绪批次工作树均已证明。

## 执行依赖前沿

消费冻结选择结果中的依赖顺序与就绪证据。对于其中指明的每个工单，在首次使用时读取`process-one-ticket.md`并遵循其流程，直至得到`completed-in-batch`；先把已证明边界交还给选择结果，再请求下一工单。如果尚有工单，但结果无法标识唯一的下一工单，则停止，不得授权重排或扩大批次。执行者替代和尝试资格仍完全由`worker-transaction.md`决定。

实施期间不要完成跟踪器工单或释放认领。保留证明每个工单提交边界的来源历史，包括收尾过程稍后收束这些历史的情况。

**完成条件：**每个选定工单都在依赖有效的第一父顺序中，恰好拥有一个独立证明的工单提交。

## 审查、收尾并闭环

正常审查前读取[`references/complete-run.md`](references/complete-run.md)，并遵循其中的验证、公开审查、修复、收尾器和结果路径。只有由`finish-worktree`分类的权威交付，才能进入`tracker.md`中的交付后路径。非整合结果会保留开放的工单、认领、工作树、历史和依赖项的准确交接。

跟踪器闭环后，将其证明提供给冻结的收尾器/生命周期清理所有者。完成需要证明每个保留的工作树、ref、边界历史项和恢复对象都已获得授权的移除、释放或保留处置。交付后恢复绝不重建工作树、派发执行者、重新运行验证或审查，也不启动另一项收尾器效果尝试。

返回批次选择/顺序、边界、执行者交接、验证和分开的审查维度、原始收尾器状态/分类/阶段结果、跟踪器操作游标、交付与清理证明、效果与保留状态，以及准确的下一所有者/操作。

**完成条件：**权威交付、按依赖顺序的跟踪器闭环和生命周期清理均已证明；或者返回准确的权威非整合、进行中、已停止或已失败交接，且不重新解释。
