# 实现工单

处理一个有界工单范围。已经证明的空选择是成功且无效果的结果。非空选择会在一个隔离的**批次工作树**中形成一个**工单批次**。

## 原则

- **Controller 负责编排。**当前 Agent 是 Controller，负责批次编排。配置的跟踪器负责工单、阻塞项、声明和完成的含义；`create-worktree` 负责工作树选择和就绪判断；`code-review` 负责 Standards 和 Spec 判断；`finish-worktree` 负责历史、交付、**已交付**、非集成交接、恢复和清理判断。
- **稳定批次。**冻结一个已明确确认合格且按依赖顺序排列的选择。任何时刻至多运行一个工单或修复 Worker，绝不悄然扩大范围或改变批次顺序。
- **提交边界。**每个选定工单都以恰好一个第一父级**工单提交**结束，其唯一工单 trailer 是 `SmartKit-Ticket: <canonical-id>`。检查点和修复提交不携带工单 trailer。即使最终化会合并提交，也要保留这些源历史边界。
- **一道最终屏障。**对整个批次验证并审查一次，然后最终化一次。任何修复都要在新的不可变状态上重新执行完整验证和两个审查维度。
- **明确效果。**只对确切的跟踪器、工作树、Worker、仓库、最终化和清理效果使用已接受权限。保留规范检出以及无关或用户所有状态。强制、变基、重置、清理、丢弃，以及隐式远程或跟踪器效果都不在授权内。
- **依据证据恢复。**从 Git 历史、当前跟踪器状态、保留的依赖交接，以及可观察的活动 Worker 或最终化状态中恢复。不保留批次日志，绝不只因当前状态看似等于预期结果就重试某项效果。

调用方提供已接受的范围、目标、结果、历史策略和确切效果权限。项目规则、工单和规格来源、仓库验证，以及当前公共依赖契约提供其余含义。

常规判断使用相称证据，但必须穷尽闭合工单选择和依赖、变更归因、仓库要求的验证，以及效果恢复。只有在归属和时效条件仍成立时才复用证据。缺少非关键证据会缩小声明并被报告；若安全、权限、所有权、外部效果或恢复存在不确定性，则在该效果前停止。

## 确立路径

首次观察跟踪器前，读取 [`references/tracker.md`](references/tracker.md)。观察有界范围和目标、仓库及已注册工作树、相关分支历史和本地状态、保留的公共 Skill 交接，以及任何活动 Worker 或最终化身份。选择恰好一条路径：

- **新批次。**没有证据表明存在未完成批次。让 `tracker.md` 选择批次。其 `nothing-to-do` 结果以无批次、无效果结束。对于非空选择，在要求 `create-worktree` 从确切目标基点建立批次工作树前，完成其初始声明门槛。只使用可归因且当前有效的 `ready` 结果；否则保留依赖结果并进入就绪前交接。
- **就绪前选择。**已存在冻结的非空选择结果和声明计划，但尚未使用当前 `ready` 结果。通过 [`references/stop.md`](references/stop.md) 恢复；该文件负责相互独立的声明分区和创建分区。只有记录的就绪快照仍与当前状态一致时，才使用就绪结果。
- **最终化前。**批次已使用初始就绪结果，并且不存在可能的最终化尝试、响应或已使用结果交接。重建不可变基点、依赖有效的工单提交前缀，以及至多一个当前工单或修复尾部，并核对每个提交和本地状态项。若持续具有可归因的控制权，在继续前重新检查当前 Git、跟踪器、工作树和 Worker 证据。控制或证据出现间断后，先使用 [`references/worker-transaction.md`](references/worker-transaction.md) 证明静止和归属。若间断后处于工单或保留修复边界，在另一项变更前要求 `create-worktree` 重新评估既有候选项。只对同一候选项使用其最新 `ready` 结果；保留任何 `non-ready` 或未解决结果及其所有者。通过 [`references/process-one-ticket.md`](references/process-one-ticket.md) 继续工单，通过 [`references/complete-run.md`](references/complete-run.md) 继续保留的修复，或者在证明每个工单提交后，冻结注册路径、分支、`HEAD`、树、索引、本地状态、基点和目标，再进入 `complete-run.md`。
- **保留的最终化结果。**不存在已使用的终止交接。将完整、可归因的原始响应交给 `complete-run.md` 的唯一结果路径，包括权威交付但跟踪器闭合不完整的情况。
- **最终化响应缺失或可能仍在运行。**将原始尝试交给 [`references/recover-finalizer.md`](references/recover-finalizer.md)。
- **已使用的终止交接。**保留已使用的 `non-integrating handoff`、`history finalized` 或 `no positive result` 结果，或者已经返回给依赖所有者的未解决分类。只恢复被点名的所有者和操作；不要再次使用该结果或重复效果。

尚未使用的 `ready` 结果仍属于就绪前状态，直到其快照和下方公共绑定通过。一旦最终化尝试存在或无法排除，最终化前路径便不再适用。

批次身份、范围、基点、路径、所有权或效果状态有歧义时，读取 [`references/stop.md`](references/stop.md)，并在该边界停止。

**路径完成条件：**已确立一条权威路径及下一位所有者，或已证明 `nothing-to-do`。

## 执行非空批次

新批次或就绪前选择产生可归因且当前有效的 `ready` 结果后，绑定冻结的跟踪器选择、不可变目标基点、已接受结果和历史策略、明确权限、生命周期所有者，以及记录的工作树身份。在待执行的即时声明前，以及就绪后的首次实现、工作树或 Worker 效果前，立即重新检查其物理路径、注册、分支、`HEAD`、树、索引和本地状态。使用初始声明和就绪结果，不重复执行它们。

通过 `process-one-ticket.md` 处理每个依赖已就绪的工单。将其独立证明的工单提交返回冻结选择，再选择下一边界。工单保持开启，受支持的声明保持持有，直到权威交付。

证明每个工单提交后，进入 `complete-run.md`。只有 `finish-worktree` 的权威交付分类——包括它自己的**已交付**结果——允许闭合跟踪器。保留其最强分类和原始状态：同时存在的 `stopped` 或 `failed` 状态不会抹去交付；每个非交付、不可用、有歧义或运行中结果都会保留其所有者所需的交接、工单、声明、工作树和源历史。

遇到第一个非完成边界时，读取 `stop.md`，保留原始所有者结果和观察到的效果，并阻止后续工单和阶段。

**调用完成条件：**已证明选择为空且没有效果；或交付、跟踪器闭合和生命周期处置均得到证明；或一份确切的非完成交接指出唯一安全的下一位所有者和操作。
