# 实施工单

处理一个有界工单范围。非空的符合条件选择会在一个隔离的**批次工作树**中构成一个**工单批次**；空选择不建立批次。控制器负责批次编排。已配置的跟踪器负责定义工单、阻断项、认领和完成的含义；`create-worktree`负责判定工作树是否就绪；`code-review`负责其两个审查维度；`finish-worktree`负责历史收尾、交付、**Already Delivered**、非整合交接、恢复和清理判断。

按稳定的依赖顺序执行工单，且同一时间最多只能有一个工单执行者或修复执行者使用批次工作树。每个选定工单最终都必须在第一父历史中恰好对应一个**工单提交**，且其中唯一的工单 trailer 为：

```text
SmartKit-Ticket: <canonical-id>
```

检查点提交和修复提交不得带有工单 trailer。即使收尾过程会合并最终交付历史，也要在来源历史中保留这些边界。整个批次只经过一次验证/审查屏障和一次收尾；发生修复时，必须完整重放该屏障。

使用调用者已接受的范围、目标、结果、历史政策和显式效果授权。项目规则、工单/Spec 来源、仓库验证以及各依赖项当前的公开契约提供其余约束。任何可见命令或能力都不构成效果授权。保留规范检出目录以及所有无关或用户所有的状态；不得强制操作、rebase、reset、clean、丢弃状态，也不得执行隐式的远程或跟踪器效果。

Git 历史、当前跟踪器状态、已保留的依赖交接，以及可观察的活跃执行者或收尾器状态，共同构成恢复证据。不得创建或要求独立的批次日志。当这些证据无法区分某项效果仍在进行还是从未开始时，应保留原始尝试并将其交还所属所有者，不得通过推断重试。

## 建立路径

首次观察跟踪器前，先读取[`references/tracker.md`](references/tracker.md)。观察有界范围、目标与仓库、已注册工作树、相关分支历史与本地状态、已保留的公开 Skill 交接，以及活跃执行者或收尾器身份。必须且只能选择以下一条路径：

- **新建：**没有证据指向未完成的批次。使用通过已配置跟踪器所有者及其路径取得的权威含义、操作和证据，执行`tracker.md`的批次选择。若已证明符合条件的选择为空，则返回其`nothing-to-do`结果，不产生认领、工作树、执行者或收尾器效果。对于非空选择，在从准确目标基准调用`create-worktree`之前，须完整消费`tracker.md`的认领计划门，包括规定的只读执行者资格检查，以及跟踪器授权的任何初始认领。只消费可归属的`ready`交接。`non-ready`、缺失或含糊的结果仍归该依赖项的原恢复所有者负责。
- **就绪前选择：**存在一份可归属的冻结非空选择结果和认领计划，但尚未消费当前`ready`工作树交接。重建彼此独立的认领分区和 Create 分区。认领分区包括零个或多个已证明的初始认领、一个可选的当前失败或进行中尝试、未触及的初始后缀，以及每项 JIT/无需认领处置。Create 分区则为`never-started`、原始`non-ready-or-in-flight`或可归属的`ready`之一。在不存在未解决认领且所有必需初始认领均已证明时，`never-started`可以调用一次 Create。`non-ready-or-in-flight`仍交由原依赖项所有者/操作处理。消费可归属的`ready`时不得再次调用 Create，并进入下方公共批次绑定。就绪交接的快照若已漂移，必须由公开`create-worktree`执行 Reuse 评估；不得将其视为`never-started`。初始`ready`交接一经消费，本路径即结束。
- **收尾之前：**一个活跃的批次工作树已经消费其来源公开`ready`交接，并完成公共批次绑定。不存在收尾器尝试、响应或已消费结果交接，也没有任何此类状态尚未排除。重建不可变基准、依赖有效的工单提交前缀，以及至多一个当前工单或修复尾部，并说明每项提交和本地状态。控制权连续且因果归属明确时，应在继续前重新检查当前 Git、跟踪器、工作树和执行者证据。若执行、身份、控制或证据出现任何间断，须先通过[`references/worker-transaction.md`](references/worker-transaction.md)处理每个已保留或可能已派发的执行者，并证明静止状态及其状态的完整归属。未解决的执行者返回其准确的进行中交接。否则，冻结观察到的`HEAD`、树、索引和本地状态，并以 Reuse 模式调用公开`create-worktree`一次。只有在立即重新检查当前就绪状态后，才能消费其可归属的`ready`交接；non-ready 或未解决的结果仍归该依赖项所有者负责。工单前沿进入[`references/process-one-ticket.md`](references/process-one-ticket.md)；已保留的修复或工单均已完成的前沿进入[`references/complete-run.md`](references/complete-run.md)。
- **已保留的收尾器结果：**不存在已消费的终态交接时，将完整且可归属的`finish-worktree`原始响应交给`complete-run.md`的唯一结果/闭环路径；这也包括权威交付已证明而跟踪器闭环尚未完成的情况。该路径会重新观察已证明的跟踪器效果，并只继续未解决的后缀。
- **收尾器响应缺失或可能仍在运行：**读取[`references/recover-finalizer.md`](references/recover-finalizer.md)。
- **已消费的终态交接：**当准确的结果路径交接证明以下任一情况时，应保留完整原始响应和分类状态：`non-integrating handoff`、`history finalized`或`no positive result`分类已被消费，或者不可用或含糊的分类已作为未解决项返回给依赖项所有者。仅在获得授权时恢复其返回的所有者/操作；绝不能再次消费响应，也不能重复收尾器或跟踪器效果。

尚未消费或刚恢复的`ready`交接，在公共绑定和就绪复查通过前仍属于就绪前状态。一旦观察到收尾器尝试或无法排除其存在，收尾前路径就不再适用；只能进入与之匹配的已保留结果路径、缺失响应恢复路径或已消费结果路径。

如果批次身份、范围、基准、路径、所有权或效果状态含糊，应读取[`references/stop.md`](references/stop.md)并停止在该边界。

**完成条件：**已经确定一条权威路径及下一所有者，或者证明了无效果的`nothing-to-do`结果。

## 执行非空批次

当新建路径或就绪前选择产生可归属的`ready`交接时，绑定跟踪器所有的选择、不可变目标基准、已接受的结果和历史政策、显式授权、生命周期所有者以及该交接。在执行任何待处理的即时认领，以及首次就绪后实施、工作树或执行者效果之前，立即重新检查其物理路径、注册状态、分支、`HEAD`、树、索引和本地状态。消费初始认领和就绪交接，不得再次调用。

按选定的依赖顺序执行。对于每个已就绪工单，执行`process-one-ticket.md`直到得到`completed-in-batch`；在选择下一前沿前，把其已证明的工单提交交回跟踪器选择。不得重排或扩大冻结批次。实施期间跟踪器工单保持开放，每个受支持的认领都保留到权威交付为止。

所有工单提交均已证明后，执行`complete-run.md`。只有`finish-worktree`将结果分类为权威交付时——包括其自身给出的**Already Delivered**结果——才允许完成跟踪器工单。按照该依赖项最强的分类进行路由，同时保留原始状态：`stopped`或`failed`不会覆盖已保留的权威交付。任何非交付分类、不可用分类、含糊结果或进行中的收尾器，都须保留其所有者所需的准确公开交接、工单、受支持认领、工作树和来源历史。

遇到第一个未完成边界时，读取`stop.md`，保留原始所有者结果和已观察效果，并阻断之后的工单与阶段。

**完成条件：**满足以下任一情况：证明符合条件的选择为空且没有效果；证明权威交付、跟踪器闭环和生命周期处置；或者准确的未完成交接指明唯一安全的下一所有者/操作。
