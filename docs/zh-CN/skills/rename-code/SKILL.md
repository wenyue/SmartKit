# 重命名代码

将一个既有代码符号或受跟踪仓库路径从 `old` 重命名为 `new`。变更由身份界定，而不是由相同拼写界定。

## 原则

- **身份优先。**搜索引用前，先解析声明或受跟踪路径。将其与无关同名项，以及重载、遮蔽、继承或生成的身份区分开来。
- **兼容性优先。**外部可观察名称是一项契约。编辑前，必须获得已批准的破坏性重命名、分阶段迁移、别名、适配器或不变更决策。
- **相称的完整性。**跟进该身份的每个已确认用法；只有当仓库证据表明可能还存在相关表面时，才扩大探索范围。
- **单一目的变更。**保持行为不变，不把相邻重构、清理和无关重命名带入变更。
- **以证据完成。**出现新拼写并不能证明重命名完成。通过重新进行身份感知探索和执行所有必要的所有者检查来闭合工作。

## 1. 确立重命名

记录一个旧名称、一个新名称、目标身份、预期范围，以及每项必要效果的确切权限。定位承载身份的声明或受跟踪路径；排除与其他符号或路径冲突；识别生成内容的所有者和受支持生成器；确定所有者要求的检查及其可执行路径。

对于公共 API，或任何通过调用方、持久化数据、配置、协议或已发布接口观察到的名称，写入前先确定已批准的兼容性决策。除非获批的重命名明确包含它们，否则保持序列化键、协议字段、数据库列、持久化名称和配置键不变。不得自行发明兼容策略。

根据目标按比例探索引用：

- 对符号而言，当语义引用覆盖相关语言和构建上下文时优先使用它；否则，将词法搜索与导入、调用点、类型用法、继承、注册、反射和其他承载身份结构的检查结合起来。
- 当证据将动态字符串、生成代码、跨语言用法、脚本、测试、文档以及构建或配置文件与目标相连时，检查这些表面。
- 对路径而言，同时检查仓库树、索引、导入、清单、链接和区分大小写的引用。单靠文本搜索无法证明路径覆盖完整。

从承载身份的表面和必要集成上下文开始。只有当未解决引用、仓库结构、构建元数据、生成所有权或检查失败表明该身份可能触达更远位置时，才扩大范围。仅有相同拼写不足以证明需要盘点无关仓库表面。

若目标、范围或权限未解决；可观察名称没有获批的兼容性决策；目标名称冲突；生成表面没有既定规范所有者或可用的受支持生成器；无法建立安全移动或必要检查路径；或者兼容性决策要求不变更，则在写入前停止。报告阻塞事实或决策及其所有者。

## 2. 重命名身份

重命名声明或受跟踪路径，以及该身份所有已确认的范围内引用。当语义重命名的覆盖可信时使用它；否则明确执行由证据支持的编辑。

适用时：

- 只通过规范来源和受支持生成器更改生成表面；
- 使用仓库的版本控制机制移动受跟踪路径；在不区分大小写的文件系统上进行仅大小写重命名时，使用唯一的临时名称；
- 只通过其所属接口或模块应用已批准的兼容措施；
- 只有当测试、注释、文档、示例、用户可见文本和与身份绑定的文件名确实指向被重命名身份时，才更新它们。

只有安全性或仓库工具有要求时才安排操作顺序，例如在重新生成前先更新生成器，或在仅大小写重命名的目标路径前先建立临时路径。

所有读取、写入和命令均由目标项目治理和已接受请求授权。本 Skill 只授权重命名及其必要的同一身份引用、生成内容、测试和文档变更。它不授权丢弃、暂存、重置或覆盖用户工作；直接编辑规范生成输出；提交、推送、发布、发行、部署、创建工作树、使用网络或执行远程操作。

## 3. 验证结果

编辑后重复相关的身份感知探索。在受影响表面和必要集成上下文中搜索旧名称；只有当证据表明覆盖不完整时才扩大范围。对路径，再次检查仓库树、索引和路径引用。将每个可能表示目标的剩余出现项分类为：

- 有意保留的契约；
- 无关身份；
- 遗漏的范围内引用；
- 未解决。

当共同证据支持时，可以将无关同名项分组；逐个盘点低信号匹配并不能证明正确性。只有当前证据唯一确定某项范围内编辑时，才修正遗漏引用，然后重复受影响的探索和检查。当证据不再带来进展、不再确定唯一修复，或需要更大范围、另一项兼容性决策或另一位所有者时，停止修正。

运行变更表面和实质重命名风险所适用的每项所有者要求检查，包括格式化、静态分析、构建、生成输出验证和必要测试。只有当仓库治理或当前证据使更广泛检查具有相关性时才添加。必要检查无法运行或失败都会阻止完成。若缺少非必要证据，但没有留下实质性的身份或兼容性风险，则缩小完成声明，并报告确切的未测试表面。若兼容性同时保留两个名称，验证两者的受支持行为。

## 结果与交接

- 当目标使用获批名称、每个已确认引用都使用该名称或由获批兼容措施保留、不存在未解决的可能目标出现项，且每项适用的必要检查均通过时，返回 `COMPLETE`。记录任何会缩小此结果的非关键未测试表面。
- 仅当某项确立要求在写入前缺失时返回 `BLOCKED`。
- 发生任何写入后，若无法安全完成或验证重命名，则返回 `FAILED`，包括必要检查失败或无法运行、出现项未解决、修正已穷尽，或新发现需要更大范围或所有者操作。写入后，`FAILED` 优先于原本会产生 `BLOCKED` 的条件；保留有用的部分状态和证据，不擅自取得回滚权限。

报告映射和身份；兼容性决策；探索方法和覆盖范围；变更、生成、移动和保留的表面；剩余旧名称出现项的分类和无关同名身份摘要；检查及退出状态；修正；结果；以及未解决或未测试表面。当共同证据支持时，将同类已解决出现项分组，但要定位每个未解决、混合或实质例外的出现项。对于非完成结果，还要报告确切的部分状态、停止证据，以及下一位所有者或所需决策。
