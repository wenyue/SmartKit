# 重命名代码

在已批准的兼容性边界内执行一次 `old -> new` 重命名。变更单位是身份，而不是拼写。

## 原则

- 先识别目标，再匹配其拼写。区分无关的同名项，以及重载、遮蔽、继承或生成的身份。
- 当外部调用方、持久化数据、配置、协议或已发布 API 能观察到名称时，将重命名视为契约变更。
- 优先使用仓库的语义重命名、版本控制移动、生成器和验证工具。工具选择应基于充分判断，而不是遵循预设顺序。
- 使变更只围绕重命名展开，不要顺带进行相邻重构或清理。
- 除非已批准范围另有明确要求，否则保持行为不变。

## 确立重命名

明确恰好一个目标、它的旧名称和新名称、预期范围，以及每项必要影响的授权。找到能够确立其身份的声明或受跟踪路径。检查目标位置是否与其他符号或路径冲突。确定归属方要求的受影响检查及其可执行入口。

根据目标按比例发现引用：

- 当语义引用能够覆盖相关语言和构建上下文时，用它们查找符号。否则，将词法搜索与对 import、调用点、类型使用、继承、注册、反射及其他承载身份的结构的检查结合起来。
- 当证据表明动态字符串、生成代码、跨语言使用、脚本、测试、文档、构建文件或配置文件与目标相关时，检查这些位置。
- 对于路径，除 import、清单、链接和区分大小写的引用外，还应检查仓库树和索引。仅凭文本搜索不能证明路径发现完整。

对于公共 API 或其他外部可观察名称，应在编辑前确定兼容性决策：破坏性重命名、分阶段迁移、别名、适配器或不作改动。不要擅自制定兼容性策略。除非序列化键、协议字段、数据库列、持久化名称和配置键明确属于已批准的重命名范围，否则保持不变。

出现以下任一情况时，在编辑前停止：无法确立或使用目标、范围、授权、兼容性决策、生成内容的规范归属方或受支持生成器；无法确立安全移动方式或必要验证入口；目标位置存在冲突且名称映射尚未改变或其归属方尚未解决冲突；或者已批准的兼容性决策不允许重命名。报告造成阻塞的事实或决策及其归属方。

## 实施改动

重命名声明或受跟踪路径，并更新每处已确认属于同一身份的引用。语义重命名的覆盖范围可靠时使用它；否则，明确进行有证据支持的编辑。

相关情况下还应遵循以下做法：

- 只通过规范源和受支持生成器更改每个生成表面。
- 使用仓库的版本控制机制移动受跟踪路径。在不区分大小写的文件系统上进行纯大小写重命名时，使用唯一的临时名称，以便安全记录两个移动步骤。
- 只应用已批准的兼容措施，并通过其归属接口或模块实施。
- 仅当测试、注释、文档、示例和用户可见文本确实指向被重命名的身份时才更新它们。与该身份绑定的文件名可以在经过相同路径检查后随之移动。

只有安全性或仓库工具需要时才安排这些操作的先后顺序，例如先更新生成器再重新生成输出，或者先建立临时路径再完成纯大小写目标名称。

目标项目治理与已接受请求共同决定所有读取、写入和命令的权限。本 Skill 只授予重命名以及必要的同身份引用、生成内容、测试和文档变更权限。它不授予以下权限：丢弃、贮藏（stash）、重置或覆盖用户工作；直接编辑规范生成输出；提交、推送、发布、发行、部署、创建工作树、使用网络或执行远程操作。

## 验证结果

编辑后重复相关的语义发现和文本发现。对于路径，还应检查仓库树、索引和路径引用。将每处剩余的旧名称归类为：

- 有意保留的契约；
- 无关身份；
- 范围内遗漏的引用；或者
- 尚未解决。

只有当前证据能唯一确定范围内的修正时，才修正遗漏，然后重复受影响的发现和检查。如果同一问题再次出现、证据不再能确定修正，或者继续处理需要扩大范围、作出不同的兼容性决策或由另一归属方采取行动，则停止。运行归属方要求的每项受影响格式化、静态检查、构建、生成输出检查和测试。兼容性措施保留两个名称时，同时验证受支持的旧行为和新行为。

## 结束

- **Complete**：目标使用已批准名称，每处已确认引用都使用该名称或因已批准的兼容性措施而被有意保留，剩余出现位置均已查明，且受影响检查全部通过。
- **Blocked**：仅适用于写入前缺少上述确立条件的情况。
- **Failed**：适用于任何写入之后无法安全完成或验证重命名的情况，包括必要检查不可用或未通过、存在未解决的出现位置、修正尝试已经用尽，或者新发现需要扩大范围或由其他归属方采取行动。它优先于同时存在的 Blocked 事实。保留确切且有用的部分状态和证据，不要擅自设定回滚权限。

报告名称映射和目标身份、兼容性决策、发现方法及覆盖范围、已变更、生成、移动和保留的表面、每处仍标识目标的残留项及其位置和分类、无关同名身份的摘要、确切的检查及退出状态、修正、结果，以及未解决或未经测试的表面。结果不是 Complete 时，还要报告确切的部分状态、停止依据，以及下一归属方或所需决策。
