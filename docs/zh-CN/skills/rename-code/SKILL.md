# 重命名代码

将一个已确定的代码符号或受版本控制的仓库路径从 `old` 重命名为 `new`。沿着实际使用追踪该身份；仅仅拼写相同，并不会让另一个符号成为本次重命名的一部分。保持行为不变，将相邻重构、清理和无关重命名留在范围之外。

已接受的请求和目标项目治理决定所有读取、写入和命令的权限。本 Skill 覆盖重命名及其必要的同一身份引用、生成内容、测试和文档修改。它不授予以下权限：丢弃、暂存搁置、重置或覆盖用户工作；直接编辑由规范源生成的输出；提交、推送、发布、发行、部署、创建工作树、使用网络或执行远程操作。

## 确定身份和兼容性决定

记录一个旧名称、一个新名称、目标身份、预期范围，以及每项必要效果的确切权限。定位能确定身份的声明或受版本控制的路径。将它与无关同名项以及重载、遮蔽、继承或生成的身份区分开。排除目标位置与不同符号或路径发生冲突的可能。

外部可观察的名称是一种契约。对于公开 API，或可通过调用者、持久化数据、配置、协议或已发布接口观察到的名称，在写入前确定已批准的破坏性重命名、分阶段迁移、别名、适配器或不变更决定。不要自行制定兼容性策略。

除非已批准的重命名明确包含它们，否则保持序列化键、协议字段、数据库列、持久化名称和配置键不变。代码符号的新拼写本身并不授权修改这些契约。

## 追踪引用并确定写入途径

从能体现身份的表面及其必要集成上下文开始。根据什么能确定绑定关系来选择发现方法：

- 对符号，如果语义引用能覆盖相关语言和构建上下文，优先使用它。否则，将词法搜索与导入、调用点、类型使用、继承、注册、反射及其他体现身份的结构检查结合起来。
- 当证据将动态字符串、生成代码、跨语言使用、脚本、测试、文档以及构建或配置文件与目标关联起来时，检查这些表面。
- 对路径，结合仓库树和索引检查导入、清单、链接及区分大小写的引用。单靠文本搜索无法确定路径覆盖完整。

追踪每一处已确认的使用。当未解决的引用、仓库结构、构建元数据、生成内容所有权或检查失败表明身份可能延伸得更远时，扩大查找范围。仅仅拼写相同，不足以要求清点仓库中无关的表面。

在任何写入前，为受影响的生成内容确定规范所有者和可用的受支持生成器。为路径重命名确定安全的版本控制移动方式，并确定适用的所有者必需检查及其可执行途径。

如果身份、范围、权限或可观察名称的兼容性决定尚未解决；目标位置发生冲突；所需的生成内容所有者、受支持生成器、安全移动方式或必需检查途径不可用；或兼容性决定要求不变更，就在写入前停止。报告实际阻碍继续的事实或决定及其所有者。已确定的不变更决定表示此次重命名不会执行，而不是缺少决定。

## 通过各自所有者实施重命名

重命名声明或受版本控制的路径，以及每一处已确认的范围内引用。语义重命名的覆盖可信时使用它；否则，明确实施有证据支持的编辑。

遵守每个受影响表面的所有权约束：

- 通过规范源和受支持生成器修改生成内容。
- 使用仓库的版本控制机制移动受版本控制的路径。在不区分大小写的文件系统上进行仅大小写变化的重命名时，先使用唯一临时名称，再移动到目标名称。
- 仅通过拥有接口或模块的所有者实施已批准的兼容性措施。
- 只有在测试、注释、文档、示例、用户可见文本和绑定身份的文件名引用被重命名身份时，才更新它们。

在安全性或仓库工具有要求时安排操作顺序，例如先更新生成器再重新生成，或先建立临时路径再进行仅大小写变化的移动。在这些约束内，自行选择普通编辑细节。

## 验证覆盖并修正有依据的遗漏

出现新拼写并不能证明重命名已经完整完成。编辑后重复相关的身份感知查找，在受影响表面及必要集成上下文中搜索旧名称。只有证据表明覆盖不完整时，才扩大范围。对路径，重新检查仓库树、索引和路径引用。

将每一处仍可能指向目标的剩余匹配归为：

- 有意保留的契约；
- 无关身份；
- 遗漏的范围内引用；或
- 尚未解决。

当共同证据支持分类时，可以合并报告无关同名项。逐项清点低信号匹配并不能证明正确性。

运行所有适用于变更表面和重要重命名风险的所有者必需检查，包括要求的格式、静态分析、构建、生成输出验证和测试。只有仓库治理或当前证据使更广检查相关时，才增加它们。兼容性要求保留两个名称时，验证两者各自支持的行为。

当当前证据能将遗漏明确关联到已批准的身份，并支持有权实施、保持行为和兼容性决定的范围内修正时，修正该遗漏。运用通常的工程判断在可靠方法中选择，然后重复受影响的查找和检查。

例如，假设某个导入函数的新名称在一个已知调用者处被遮蔽。如果已确定的范围允许修复该调用者的引用，而且模块限定名和无歧义的导入别名都能保留已批准的绑定关系和行为，那么两者都可以是可靠的修复。选择哪种方法，与不确定调用者使用哪个函数，是不同的问题。未解决的重载或动态绑定仍需要身份依据。

当证据不再改进、已没有有依据且安全的范围内修正，或继续处理需要扩大范围、另一项兼容性决定或另一所有者采取行动时，停止修正。选择方法无法弥补缺失的身份、权限或重要行为证据。

必需检查不可用或失败时，不能完成。当不可用的非必需证据没有留下重要的身份或兼容性风险时，收窄完成结论，并报告确切的未测试表面。

## 报告结果和剩余状态

- `COMPLETE`：目标使用已批准的名称，每一处已确认引用都使用该名称或由已批准的兼容性保留，不存在仍可能指向目标而尚未解决的匹配，且所有适用的必需检查通过。记录任何收窄此结果的非关键未测试表面。
- `BLOCKED`：写入前，无法满足安全且有权实施重命名的某项要求，或已批准的兼容性决定要求不变更。说明实际原因；已确定的不变更决定不是请求补充缺失输入。
- `FAILED`：任何写入之后，无法安全完成或验证重命名。包括必需检查失败或不可用、未解决的匹配、修正无法继续，或新出现的范围或所有者行动需求。写入后，`FAILED` 优先于本来会归为 `BLOCKED` 的情况。保留有用的部分状态和证据，不要自行推定回滚权限。

报告映射和身份；兼容性决定；查找方法和覆盖；已修改、生成、移动和保留的表面；剩余旧名称的分类及无关同名身份；检查和退出结果；修正；最终结果；以及未解决或未测试表面。当共同证据支持时，合并同质且已解决的匹配，但明确定位每一个未解决、混合或具有重要例外的匹配。对于未完成结果，包含确切的部分状态、停止依据，以及确有需要时的下一责任方或决定。
