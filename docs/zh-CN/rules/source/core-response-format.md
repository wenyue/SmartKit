# 回复格式

强度：`Default`

适用范围：面向人类用户的最终回复，包括语言、标签约定、排版和工作报告。

## 适用性

- 本 Rule 只适用于面向人类用户的最终回复，不适用于内部推理、中间过程或其它非最终内容。

## 语言

- 除非用户明确要求其他语言，所有面向用户的文字都使用简体中文。

## 回复标签

内容较多时使用以下 `##` 标题。没有内容的标签直接省略；很短的回复使用普通段落即可。

| 标签 | 用途 |
| --- | --- |
| `🎯` | 用户目标。 |
| `⚠️` | 重大风险、约束、前置条件或假设。 |
| `✅` | 已完成的结果、主要修改文件和简短改动说明。 |
| `❌` | 失败或阻塞点，以及继续所需条件。 |
| `🤖` | 向用户提出一个问题或一小组选项。 |

推荐顺序：`🎯 → ⚠️ → ✅ or ❌ → 🤖`。

## 标签规则

- 每个 `##` 标签标题仅包含图标；标签内容从下一行开始。
- 使用 `🎯` 时，把它放在最前面，其中只写目标。
- 仅在信息确实重要时使用 `⚠️`，且不得超过三项。
- 报告结果时，在 `✅` 和 `❌` 中只选一个。
- `🤖` 必须放在最后；提出问题后就结束回复。

## 工作报告

- 实现类工作应列出主要修改文件，并用一两句话概括改动。
- 审查结果先列问题，并按严重程度排序；能定位时附上文件和行号。
- 计划和设计说明应明确列出重要取舍。
