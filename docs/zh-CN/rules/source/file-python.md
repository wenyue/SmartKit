# Python 指引

强度：`Default`

适用范围：跨项目通用的 Python API、类型、数据边界、失败和资源契约；仓库自行管理的格式化、lint
和类型检查策略不在此范围内。

## API 与类型契约

- 只改类型标注时，运行行为必须保持不变。如果类型信息暴露了含义不明确的运行时情况，应根据代码、
  测试或项目政策解决，不能自行选择一种新行为。
- 为公共或可复用边界的参数和返回值添加标注；仅执行副作用的函数使用 `-> None`。使用仓库所
  声明的 Python 版本范围支持的语法。
- 只有运行时边界本身确实是动态的，才使用反射、monkey patch 和元编程，并把这些做法限制在该边界。
- 仅对真正开放或转发型契约使用 `*args` 和 `**kwargs`；其他情况应明确命名参数。当一个签名具有多个
  独立可选值时，将参数设为 keyword-only。
- 结构化 API 使用 `Protocol`；数据结构使用 dataclass 或带类型的领域类型；有限状态使用 `Literal`、
  enum 或具名类型。不要用布尔标志或隐式的 `None` sentinel 表示具有领域含义的状态组合。
- 只在需要时导入类型辅助工具，并使用项目支持的泛型语法。

## 局部值与函数

- 在首次使用附近声明变量，为含义不明确或空的初始值添加标注，并让 nullable 值只存在于尽可能窄的
  路径中。
- 每个值名称只承担一个角色和一种类型，不要将其复用于不同的值。
- 函数应专注于一件事；遇到无效、缺失或无需处理的输入时尽早返回，避免正常路径嵌套过深。

## 数据边界

- 在边界类型中明确集合是否可修改：修改不属于契约时，接受 `Mapping`、`Sequence` 和 `Iterable`
  等只读抽象；调用者必须允许修改时，要求可修改类型。
- 仅在真正的动态或无类型边界保留 `Any`，并在值进入类型化领域逻辑前对其进行验证或收窄。
- 构造带类型的领域值之前，先验证外部 mapping、序列化数据和无类型 provider 提供的值。
- 每个函数都返回一种稳定的数据结构。不同结果含义不同时，使用具名结果、enum 或异常来区分。

## 失败与资源

- 对预期失败抛出精确的领域或集成异常；跨边界转换错误时保留有用的原因上下文。
- 仅在拥有失败策略的边界捕获宽泛异常；重新抛出或转换该边界无法安全隔离的失败。
- assertion 只用于内部不变量，不用于检查用户输入或处理可恢复的运行时失败。
- 协程函数的标注应描述 await 后得到的值；异步生成器函数则标注为异步迭代器或生成器类型。
- 在异步或回调边界前保存稳定依赖；只有需要当前值时，才读取会变化的状态。
- 每个已获取资源应有一个清理所有者，并明确所有权转移。对于保留所有权的每条路径，通过上下文
  manager、`try/finally` 或所有者生命周期方法确保清理。

## 类型变更

- 如果新类型标注使某个分支的含义变得不明确，在进行证据支持的行为变更前，先添加并运行一个针对性
  测试，明确当前行为。
