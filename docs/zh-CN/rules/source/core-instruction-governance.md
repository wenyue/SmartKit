# 指令治理

强度：`Mandatory`

适用范围：Rule 的强度和优先级、Skill 的权限和重叠，以及执行过程中遇到的语义冲突报告。

## 强度等级

- `Mandatory`：必须遵守，除非更高优先级的指令另有要求。
- `Default`：默认遵守，除非更高优先级的直接指令或 Rule 要求不同结果。
- `Advisory`：可在有帮助时结合任务实际情况采用。

## Rule 优先级

直接指令的优先级由当前 Harness 定义。适用 Rule 之间的冲突按以下元组解决：

1. 强度：`Mandatory` > `Default` > `Advisory`。
2. 相同强度时的归属：项目 > 插件。
3. 相同强度和归属时的具体程度：更窄的适用文件范围 > 更宽的适用文件范围 > 全局层级。全局适用的
   Rule 与仅按 Harness 限定的 Rule 同属全局层级。

## Skill 组合

- 每个 Skill 都必须在直接指令和适用 Rule 的约束内执行，包括细化过程或完成 gate 时。
- 适用 Skill 重叠时，应用范围更具体的 Skill。具体性相同时，项目本地 Skill 优先于插件分发的 Skill；
  外部来源本身不产生额外的优先级层级。

## 执行过程中遇到的冲突

- 在同一组已证实事实下，如果一项动作或结果无法同时满足两项适用要求，即视为遇到了语义冲突。仅在
  执行暴露冲突时处理，不得另行增加冲突审计、预检或配置期推断。
- 对每个遇到的冲突，应用适用的指令优先级和 Rule 优先级元组。当优先级选定一项要求时，遵循该要求
  并继续执行。
- 不兼容要求经优先级处理后仍然平局时，只进行确认平局所需的只读调查，然后在任何副作用前停止，
  并请用户解决。不得将分发顺序用作隐式决胜依据。
- 无论优先级已经解决冲突还是执行已经停止，都要在面向用户的工作报告中报告每个遇到的冲突。指出
  冲突要求及其来源，说明优先级事实和结果，并解释已采取的行动或请求用户解决的未决决定。
