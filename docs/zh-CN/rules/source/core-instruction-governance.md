# 指令治理

强度：`Mandatory`

适用范围：直接指令权限、Rule 和 Skill 优先级，以及对执行过程中遇到的冲突发出警告。

## 强度等级

- `Mandatory`：必须遵守，除非更高优先级的指令另有要求。
- `Default`：默认遵守，除非更高优先级的直接指令或 Rule 要求不同结果。
- `Advisory`：可在有帮助时结合任务实际情况采用。

## 优先级

直接指令的优先级由当前 Harness 定义。应用每个适用 Rule 和 Skill 中相容的要求。不兼容要求按下述
Rule 和 Skill 优先级解决。适用优先级处理后仍然平局时，只进行确认平局所需的只读调查，然后在任何
副作用前停止，并请用户解决。分发顺序不用于打破平局。对于 Rule，依次比较：

1. 强度：`Mandatory` > `Default` > `Advisory`。
2. 相同强度时的归属：项目 > 插件。
3. 相同强度和归属时的具体程度：更窄的适用文件范围 > 更宽的适用文件范围 > 全局层级。Harness
   选择器只控制激活，不控制具体性。

## Skill 组合

- 每个 Skill 都必须在直接指令和适用 Rule 的约束内执行。
- 对于冲突的 Skill 要求，只有当一个 Skill 声明的触发条件和所拥有的结果在当前任务中构成另一个
  Skill 对应范围的严格子集时，前者才更具体。更具体的 Skill 只控制冲突部分。
- 具体性无法解决 Skill 冲突时，项目本地 Skill 优先于插件分发的 Skill。外部来源不增加优先级层级。

## 冲突警告

- 当正常执行暴露语义冲突——在同一组已证实事实下，一项动作或结果无法同时满足两项适用要求——在
  面向用户的工作报告中给出警告。不得另行执行冲突审计或预检。
- 仅使用可向用户披露的细节，指出冲突要求及其来源，说明优先级结果，并解释已采取的行动或请求用户
  作出的决定。
