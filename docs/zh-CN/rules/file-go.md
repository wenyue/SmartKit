# Go 指引

强度：`Default`

适用范围：工具配置未覆盖的 Go 包归属、API 设计、错误、上下文、并发和日志约束。

## 代码形态

- 代码保持直接，作用域尽量小，正常执行路径不要嵌套过深。
- 公共 API 应由产品需求驱动；测试需求不应导致名称被导出、接口被添加，或引入只服务于测试或臆测
  复用的接缝。
- 只有当辅助函数或私有类型能表达真实概念、理清数据流或明显降低复杂度时，才把它提取出来。
- 从构造函数、`main` 或包自有的初始化函数中显式初始化，不使用 `init()`。

## 错误

- 检查每个返回的错误，并将错误绑定到具名变量而不是空白标识符。
- 类型断言可能失败时使用 `value, ok := x.(T)`；只有调用点能够直接看出类型由不变量保证时，
  才使用 `x.(T)`。
- 错误跨越包边界时，使用 `%w` 包装并提供有用上下文；通过 `errors.Is` 或 `errors.As`
  检查。
- 创建动态错误前，优先复用已有的 sentinel error。
- 除非处于无法继续运行的顶层启动路径，否则避免使用 `panic`、`logger.Fatal` 和
  `os.Exit`。

## Context 与并发

- 符合 Go 常规模式时，将 `context.Context` 放在首个参数，并在循环和长时间运行的工作中
  响应取消。
- 使用归属包的同步原语保护共享可变状态。
- 包级全局变量必须用途明确、行为稳定，并集中在一个位置初始化。

## 日志

- 运行时信息使用归属包的日志约定，不引入 `fmt.Print*` 或标准库 `log`。
- 日志消息要写明正在执行的操作，并包含排查失败所需的值。

## 工具归属

- 布局、命名、限制、导入、注释和屏蔽语法交给仓库的格式化工具和 linter。
- 配置阈值应在负责它的配置中修改，不要在本规则中重复。
