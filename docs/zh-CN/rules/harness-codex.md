# Codex Harness 适配

在 `wait_agent` 提供事件驱动邮箱更新的 Codex 会话中，应用本等待指导。当前任务或 Skill 决定委派方式和所需结果；本 Rule 不改变用户授权、Rule 优先级或完成标准。

## 没有有用的父智能体工作时再等待

还有有用的父智能体工作可做时，继续推进。确实空闲且仍有待接收的子智能体结果时，将 `wait_agent` 用作事件等待。邮箱有更新时可以提前唤醒等待，因此延长等待上限未必会推迟收到子智能体更新。

选择当前工具支持、且符合适用的等待限制和进度汇报要求的有界等待时长。在这些约束内，优先选择能避免不必要频繁轮询的时长；单凭超时，不足以成为缩短下一次等待的理由。

等待超时仅表示在该时段内没有收到邮箱更新。单凭超时既不能认定子智能体失败或受阻，也不足以支持中断子智能体。应依据子智能体的实际消息或状态证据，判断是否需要干预。
