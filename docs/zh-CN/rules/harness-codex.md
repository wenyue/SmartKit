# Codex 智能体宿主适配

强度：`Default`

适用范围：Codex 专用的子智能体工具、`functions.exec` 编排方式，以及仍有智能体运行时的有界等待。

## 权限边界

- 由当前 Skill 或任务决定为什么委派智能体，以及必须产出什么结果；本 Rule 不改变用户授权、Rule
  优先级或完成标准。

## 子智能体工具映射

- 使用 `spawn_agent` 启动一项具体、能够独立产生价值的任务。后续子智能体工具使用它返回的任务名或
  智能体标识符。
- 使用 `send_message` 补充上下文，但不启动新一轮。需要让空闲的子智能体执行新的有界任务时，使用
  `followup_task`。
- 仅在确实应停止当前工作时使用 `interrupt_agent`。仅为有意的状态检查使用 `list_agents`，不得形成
  轮询循环。

## JavaScript 编排

- 在 `functions.exec` 中编排已经选定的独立并发调用：允许部分调用失败且其它结果仍有价值时使用
  `Promise.allSettled`；必须拿到所有结果时使用 `Promise.all`。如果当前工具 schema 或适用 Skill
  禁止并发，就按顺序调用。

## 等待智能体

- 把 `wait_agent` 当作事件订阅，而不是轮询。父智能体还有其它工作可做时就继续推进；已完成智能体的
  消息会在父智能体的下一轮送达。
- 确实无事可做但仍有智能体在运行时，如果当前智能体宿主和运行时允许，就以 300000–600000 毫秒为一个
  有界区间调用 `wait_agent`。长订阅收到消息后同样会立即唤醒，延迟与短订阅没有区别；缩短等待只会
  增加调用次数，不会更快得到结果。
- `wait_agent` 超时只说明这段时间没有新消息。不要仅因为上一次超时就缩短下一次等待。
