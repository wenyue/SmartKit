# Codex Harness 适配

使用 Codex 操作执行当前任务或 Skill 的决策。由该工作流决定为何委派智能体，以及它必须产出什么结果。本 Rule 提供工具适配，不改变用户授权、Rule 优先级或完成标准。

## 协调委派工作

根据智能体当前需要开展的工作选择操作：

| 需要 | 操作 |
| --- | --- |
| 启动一项具体、可独立产生价值的任务 | `spawn_agent` |
| 补充上下文，不启动新一轮执行 | `send_message` |
| 给空闲智能体分配一项有明确边界的新任务 | `followup_task` |
| 停止智能体当前的工作 | 仅在这项工作应当停止时使用 `interrupt_agent`。 |
| 检查当前状态 | 使用 `list_agents` 进行有明确目的的检查，不要循环轮询。 |

在后续子智能体操作中，使用 `spawn_agent` 返回的任务名称或智能体标识符。

### 没有有用的父智能体工作时再等待

还有有用的父智能体工作可做时，继续推进；已完成智能体的邮箱更新会在父智能体下一轮到达。确实空闲且仍有活跃智能体时，将 `wait_agent` 用作事件订阅。长短订阅都会在邮箱有活动时以相同延迟唤醒，因此缩短轮询只会增加调用次数，不会降低响应时间。

在当前 Harness 和运行时允许的范围内，分段等待，每段 300000–600000 ms。当前限制要求更短时段时，使用该限制内受支持的时长。超时仅表示该时段内没有收到邮箱更新；不要仅因上一时段超时，就缩短下一次等待。

## 编排并发工具调用

在 `functions.exec` 中，为已经选定并发执行的独立调用选择结果收集方式：部分结果仍有价值时，使用 `Promise.allSettled`；需要全部结果时，使用 `Promise.all`。当前工具模式或适用 Skill 禁止并行执行时，保持顺序调用。
