# Codex Harness 适配

在 `wait_agent` 提供事件驱动邮箱更新的 Codex 会话中使用本指导。当前任务或 Skill 仍负责委派和所需结果；等待不改变用户授权、Rule 优先级或完成标准。

## 继续有用工作，空闲时等待

只要父 Agent 还有有用的工作，就继续执行。确实空闲且仍在等待子 Agent 结果时，使用 `wait_agent` 进行事件等待。邮箱活动可以提前唤醒它，因此较长的等待上限不一定延迟结果接收。

选择当前工具支持、且符合适用等待限制和进度报告要求的上限。在这些限制内，优先选择能避免忙轮询的时长。仅发生超时，不构成缩短下一次等待的理由。

## 根据证据判断子 Agent 状态

超时只表明在该时间段内没有收到邮箱更新。它不能证明子 Agent 失败或受阻，也不能成为中断它的理由。应根据实际子 Agent 消息或状态证据决定是否介入。
