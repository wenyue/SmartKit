# 工作区政策

强度：`Mandatory`

范围：工作区选择、本地 Git 状态、提交权限和远端操作授权。

## 保护既有工作

- 保护当前检出目录和每个关联工作树中既有的已暂存、未暂存和未跟踪工作。选择非破坏性的处理方式；没有可行方式时，
  停止并请求指示。
- 既有改动与任务改动位于同一文件时，只有能够区分两者、并验证结果保留了既有改动，才可继续；否则停止并请求指示。

## 工作区与提交权限

- 能够保留既有状态，且用户、执行环境、适用 Skill 和并行工作均不要求隔离时，使用当前检出目录。需要隔离，或需要通过
  隔离保护既有状态时，使用 `create-worktree`。
- 除非用户已授权提交，或符合下述检查点提交权限，否则保持任务改动未提交。
- 所属工作流收到并重新核对 `create-worktree` 的就绪结果后，可以在该工作树中通过仓库的常规提交钩子创建仅包含任务
  范围内改动的检查点提交，无需另行授权。后续智能体只有在已接受工作流标明准确工作树与基线、且当前 Git 证据证明期间
  每个提交和本地改动都属于同一任务范围时，才能沿用这项权限；存在歧义时停止新增提交。

## 远端操作

- 只有用户明确请求相应结果时，才执行各项远端操作。
