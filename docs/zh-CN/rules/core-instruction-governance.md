# 指令治理

在当前 Harness 的指令权限范围内应用 SmartKit Rules 和 Skills。确定优先级不能替代操作本身的权限要求。

## 解决实际冲突

兼容的要求共同适用。当两个条款在同一决定下无法同时满足时，依次比较以下因素，并在首个差异处确定优先级：

| 优先次序 | 比较项 | 优先适用的要求 |
| --- | --- | --- |
| 1 | 来源 | 直接对话指令 > 项目 > 插件 |
| 2 | 来源相同时比较类型 | Task Skill > Rule Skill > Rule |
| 3 | 来源和类型均相同时比较具体程度 | 适用条件或约束对象更窄的要求 |

类型顺序反映任务聚焦程度：Rule 提供一般策略，Rule Skill 提供某个领域或条件下的策略，Task Skill 指导具体任务或结果。Rule Skill 是名称为 `rule-<domain>` 的规则主导 Skill；其领域或条件必须限制适用范围。仅延迟加载并不能提供这种限制。

根据规范来源以及含义的所有者，判断要求属于项目还是插件。在项目或对话中安装、复制或加载它，不改变其归属。项目明确委托插件时，委托仅在声明的结果和约束内适用。

比较冲突条款，而非整份文档。更窄的条件可以打破平局，仅有重叠则不行。只替换冲突中失去优先级的要求，保留所有兼容要求。建议和示例帮助判断，但不另行产生要求。

如果冲突仍未解决，报告条款及其来源，暂停受影响的操作，并请用户裁决。可以时继续无关工作。

## 在决策前加载相关指导

根据发现描述和当前任务，识别相关 Rules、Rule Skills 及必读参考资料。在它们约束的决策前加载；如果不确定 Rule 是否适用，就阅读它。

仅在声明的条件成立时应用要求。阅读所属规范性参考资料时，连同入口的条件和例外一起理解；独立所有者的策略保留自己的契约。加载或显式调用指导，不扩大适用范围、任务范围或权限。

只要没有变化或过时的证据，就复用上下文中完整且适用的内容。补读缺失内容，包括上下文压缩后缺失的部分；按需刷新受影响内容，并遵守明确要求重新阅读的规定。如果必需内容不可用，报告缺口并暂停依赖工作，同时继续无关工作。
