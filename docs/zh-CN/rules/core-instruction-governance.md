# 指令治理

所有 SmartKit Rule 和 Skill 都在当前 Harness 规定的指令权限范围内，按下述优先级执行。每个行动还必须满足相应的操作权限要求。

## 解决要求之间的冲突

同时应用所有相容的要求。当两个要求无法在同一决策中同时满足时，按以下顺序比较，在首次分出高下时停止：

1. **来源：**会话中的直接指令 > 项目 > 插件。
2. **来源相同时比较类型：**Task Skill > Rule Skill > Rule。
3. **来源和类型都相同时比较具体性：**适用条件或约束对象范围更窄的要求优先。

类型顺序体现对任务的聚焦程度：Rule 提供通用政策；Rule Skill 提供针对某个领域或条件的政策；Task Skill 指导特定任务或结果。Rule Skill 即采用 `rule-<domain>` 命名的规则导向 Skill。其领域或条件必须限定实际适用范围；仅延迟加载并不构成这种限定。

根据规范来源以及谁拥有其含义，确定项目或插件归属。将插件工件安装、复制到项目中，或在项目、会话中加载它，都不会改变其归属。项目对插件的明确委托只在声明的结果范围和约束内生效。

比较实际冲突的条款。更窄的条件可以打破平局；仅有范围重叠则不能。胜出的要求只替代冲突要求，所有相容要求继续有效。建议和示例辅助判断，不构成要求。

如果冲突仍未解决，报告冲突要求及其来源，暂停受影响的行动，并请用户解决。不相关工作可以继续。

## 加载适用的指导

根据发现描述和当前任务，在作出相关决策之前加载适用的 Rule、Rule Skill 及必需的参考资料。无法确定某条 Rule 是否适用时，先阅读它。在声明的条件成立时应用要求。自有规范性参考资料与其入口的条件和例外一起应用；独立所有的政策保留各自契约。加载或显式调用不会扩大适用范围、任务范围或权限。

复用上下文中已有的完整适用内容，除非存在变更或过时的证据。加载缺失内容，包括上下文压缩后缺失的内容；需要时刷新受影响的内容，并遵守明确要求重新读取的规定。如果必需内容不可用，报告情况并暂停依赖它的工作；不相关工作可以继续。
