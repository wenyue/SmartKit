# 指令治理

强度：`Mandatory`

适用范围：直接指令的权限、Rule 与 Skill 的优先级，以及执行过程中出现冲突时的警告。

## 强度等级

- `Mandatory`：必须遵守，除非更高优先级的指令另有要求。
- `Default`：默认遵守，除非更高优先级的直接指令或 Rule 要求不同结果。
- `Advisory`：可根据任务情况酌情采用。

## 优先级

直接指令的优先级由当前智能体宿主定义。所有适用 Rule 和 Skill 中互不冲突的要求都要执行；发生冲突时，
按下述优先级处理。如果比较后仍无法分出高低，只进行确认冲突所需的只读调查，然后在产生任何副作用
前停止，并请用户决定。不得用交付顺序打破平局。Rule 按以下顺序比较：

1. 强度：`Mandatory` > `Default` > `Advisory`。
2. 相同强度时的归属：项目 > 插件。
3. 强度和归属都相同时：适用文件范围更窄 > 适用文件范围更宽 > 全局层级。智能体宿主选择器只决定
   是否激活，不影响具体程度。

## Skill 组合

- 每个 Skill 都必须在直接指令和适用 Rule 的约束内执行。
- 两个 Skill 的要求冲突时，只有当其中一个 Skill 声明的触发条件和负责的结果，在当前任务中严格包含
  于另一个 Skill 的对应范围时，前者才算更具体。它只在冲突部分占优。
- 仍无法按具体程度解决冲突时，项目本地 Skill 优先于插件分发的 Skill。来自外部本身不会增加新的
  优先级层级。

## 冲突警告

- 正常执行中如果发现语义冲突——同一组已证实事实下，一个动作或结果无法同时满足两项适用要求——
  应在面向用户的工作报告中发出警告，但不另做冲突审计或预检。
- 只使用可以向用户披露的信息，指出冲突的要求及其来源，说明优先级判定，并解释已经采取的行动或
  需要用户作出的决定。
