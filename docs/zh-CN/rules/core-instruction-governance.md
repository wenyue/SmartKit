# 指令治理

强度：`Mandatory`

适用范围：Rule 的适用性与加载、直接指令的权限、Rule 与 Skill 的优先级，以及执行过程中出现冲突时的警告。

所有 SmartKit Skill 都在已安装的 SmartKit 核心治理下运行。以 `rule-<domain>` 命名的规则导向 Skill
是通过原生 Skill 发现机制提供的 Rule，在入口中声明 `Scope` 和默认 `Strength`。
它们约束相关工作，而不作为任务工作流参与竞争。

## Rule 的适用性与加载

根据原生发现机制中的描述和当前任务，在作出相关决策前加载适用 Rule。无法确定是否适用时，先阅读 Rule。
所有相关政策都应在其声明的范围内生效，显式调用时也一样；调用不会扩大该范围。
无论强度如何，适用 Rule 都必须加载；加载本身不会启动独立任务、要求单独交付物或扩大权限。

在作出依赖配套引用内容的决策前，先加载该 Rule 自身负责的必要引用内容。所需 Rule 或引用内容不可用时，
说明缺失内容并停止依赖它的工作；无关工作可以依据已有指令继续。

## 强度等级

- `Mandatory`：必须遵守，除非更高优先级的指令另有要求。
- `Default`：默认遵守，除非更高优先级的直接指令或 Rule 要求不同结果。
- `Advisory`：可根据任务情况酌情采用。

Rule 自身负责的规范性引用内容继承入口的默认强度和范围，不受引用所在章节影响。
这些内容可以显式覆盖强度、缩小范围。由独立所有者负责的政策保留自身契约；链接到示例材料不会使其成为规范性政策。

在 Rule 入口或其自身负责的规范性引用文档中，每项要求采用所在章节或上级章节中最近的 `Strength` 声明；
均无声明时，采用该文档的默认强度。章节声明写在 Markdown 标题后的第一个非空行，例如 ``Strength: `Mandatory` ``，
可使用上述任一等级。章节包含其子章节，范围止于下一个同级或更高级标题之前，或文件末尾。

章节强度不改变 Rule 的适用性、归属或文件范围的具体程度；标题深度不增加优先级。

## 优先级

直接指令的优先级由当前智能体宿主定义。所有适用 Rule 和 Skill 中互不冲突的要求都要执行；发生冲突时，
按下述优先级处理。如果比较后仍无法分出高低，只进行确认冲突所需的只读调查，然后在产生任何副作用
前停止，并请用户决定。交付顺序、加载顺序和名称都不赋予优先级。Rule 按以下顺序比较：

1. 每项要求的实际生效强度：`Mandatory` > `Default` > `Advisory`。
2. 相同强度时的归属：项目 > 插件。
3. 强度和归属都相同时：适用文件范围更窄 > 适用文件范围更宽 > 全局层级。智能体宿主选择器只决定
   是否激活，不影响具体程度。

## 任务型 Skill 组合

- 每个任务型 Skill 都必须在直接指令和适用 Rule 的约束内执行。
- 两个任务型 Skill 的要求冲突时，只有当其中一个 Skill 声明的触发条件和负责的结果，在当前任务中严格包含
  于另一个 Skill 的对应范围时，前者才算更具体。它只在冲突部分占优。
- 仍无法按具体程度解决任务型 Skill 的冲突时，项目本地 Skill 优先于插件分发的 Skill。来自外部本身不会增加新的
  优先级层级。

## 冲突警告

- 正常执行中如果发现语义冲突——同一组已证实事实下，一个动作或结果无法同时满足两项适用要求——
  应在面向用户的工作报告中发出警告，但不另做冲突审计或预检。
- 只使用可以向用户披露的信息，指出冲突的要求及其来源，说明优先级判定，并解释已经采取的行动或
  需要用户作出的决定。
