# Dart 与 Flutter 指引

强度：`Default`

适用范围：Dart 与 Flutter 的公共接口、records、文件系统操作、组件生命周期、异步上下文使用、由 Navigator 管理的路由和生成源文件。

## 公共接口与归属

- 所有者内部行为默认使用实例成员。
- 顶层函数只用于框架入口、文件级声明、共享算法，或确实没有明确所有者的逻辑。

## Records

- record 只用于小型、局部的元组返回；如果命名类型更清楚，就使用命名类型。

## 文件系统操作

- 在支持 `dart:io` 的环境中，通常直接执行所需的文件系统操作，包括读取、写入、创建和删除。
  让操作将自身的失败交给既有的恢复或错误报告责任方；后续操作未必会重现先前短暂的路径查询错误。
- 只有预先查询文件系统（例如调用 `existsSync` 或 `typeSync`）能带来具体收益时，才直接或通过
  包装方法进行查询。应将否定结果（如 `false` 或 `notFound`）视为无法区分对象不存在与路径查询
  失败；它也可能表示类型不符。只有当查询失败与对象不存在对调用方等价，且任何可能的类型不符
  都可接受时，才能据此跳过操作或采用默认值。肯定结果只反映检查当时的状态，不能保证权限或
  后续操作成功；状态可能变化。
- 初始化和覆盖写入所需的数据保证，应由实际操作的语义保障，不能依赖存在性预检查；默认写入可能
  截断已有数据。

## Flutter 生命周期

- 由 `State` 负责的控制器、订阅和监听器，应在其 `dispose()` 方法中释放；由项目生命周期机制管理的资源仍由该机制负责。
- 经过异步间隔后，使用捕获的 `BuildContext` 前，应确认它仍处于 mounted 状态。
  稳定的组件依赖应在间隔前解析，会变化的状态只在 mounted 检查之后读取。

## Navigator 路由

- 由 Navigator 管理的对话框、底部面板和浮层，应通过其路由所属的 Navigator 关闭，并传递返回结果；
  选择该 Navigator 时，应考虑 Navigator 的嵌套关系。

## 生成源文件

- 生成的文件都是输出。应修改其源声明，然后运行项目既有的所属生成器。
  如果代码生成受阻，应报告缺失的前提条件，不要手工修改输出。
