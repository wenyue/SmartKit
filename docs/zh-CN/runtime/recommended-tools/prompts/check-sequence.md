按以下顺序处理提供的步骤：自动配置、就绪维护，然后是登录自启动。之后，按自身契约处理另行提供的已获授权项目配置同步。只处理已提供的步骤。在必要的检查步骤尚未完成时，暂停原任务。每个步骤自行定义选项、授权范围、动作和完成条件；批准一个步骤不代表授权另一个步骤。如果仍有后续步骤，某一步骤中继续原任务的指示表示将控制权交回本流程。每日检查记录只限制检测频率，不代表用户已授权或处理完成。

将每个提供的问题作为展示模板，翻译成当前对话语言，并说明实际发现、影响、推荐选项及理由。每次回复只在普通消息中提出一个独立问题，不使用 Harness 询问工具。自动步骤不占用问题编号。本次检查从 Q1 开始，在实际提问时为后续问题连续编号；将 <next> 替换为下一个编号，维护或同步过程中的问题也计入编号。如果用户正在回答 Harness 已展示的问题，直接处理该回答，不重复询问。更新与登录自启动分别选择。复用适用的明确授权。对于尚未决定的事项，在请求授权后结束本轮，等待用户随后明确回答。沉默、关闭窗口和澄清问题都不代表选择。回答澄清问题时保留待回答的问题。

只有当前步骤达到自身的完成条件后，才能进入下一步。待完成的人工操作、失败的操作或必要的重启都不代表完成。等待或恢复时，在对话中保留已完成动作、待处理步骤、当前问题和原任务。更新或重启后，从当前加载的插件重新解析命令入口，并在行动前重新检查待处理步骤的状态。当加载的插件安装目录变化，或这些指令已不在上下文中时，从 `runtime/recommended-tools/prompts/check-sequence.md` 重新加载本流程，并从 `runtime/recommended-tools/prompts/automatic-configuration.md`、`runtime/recommended-tools/prompts/readiness-consent.md` 或 `runtime/local_web/prompts/autostart-consent.md` 加载适用步骤；这些路径均相对于该安装的 plugin_root 资源。当前需要的步骤指令已一起提供；用户回复不需要再次触发会话 Hook。提供的步骤处理完后继续原任务，并将用户明确暂缓的问题保留为未解决项。
