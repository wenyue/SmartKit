# 项目契约

强度：`Mandatory`

适用范围：用于目标仓库持久变更有效性政策的 Setup Authoring Contract，覆盖 API、能力所有权、
安装、文档、评估、契约演进、分发、硬依赖和暴露。

## 契约框架

当 `setup-project-agents` 请求 `.agents/rules/01-project-contracts.md` 时，编写这一份由目标拥有、
标题为 `Project Contracts` 的 Mandatory Rule。目标仓库的变更影响本契约适用范围内的任何关注点时，
该 Rule 即适用，并负责规定使变更有效的持久条件。

使用已接受的项目意图，以及根据目标仓库所有者和证据来源判定合格的证据。相关证据包括入口指引和范围
更窄的 Rule；已接受的 Issue、Spec 和 ADR；公共 API、schema、事件、领域模型、实现和行为测试；
以及注册表、synchronizer、manifest、所有权记录、package、loader 和文档路径中的规范源与交付关系。
目标中现有的 Rule 是保留证据和回归证据，而不是设计权威。不能仅凭可见性、历史文本、仅限本机的状态
或写入权限确立语义或取得许可。

将每项继承或拟议的义务分类为保留、变更、新增、废止或非目标。变更、新增、废止、例外或兼容性要求
必须有已接受的意图和合格证据；否则保留有依据的当前行为，或者在其处置会改变结果时停止。

## 必需政策

对于每个有依据的条件及其最接近的纳入和排除情形，陈述激活谓词、必需的可观察结果、准确例外、
优先级和决策所有者。纳入以下各项中所有有证据支持的映射：

- 面向使用方的契约，包括状态、兼容性、生命周期、并发、取消、迁移、持久化和清理行为；
- 规范输入的所有权，以及该输入发生变化时随之产生且彼此有别的转换、adapter、传输、安装和交付结果；
- setup 所管理文件、结构化字段、摘要和受管状态的认领、保留、冲突、替换和废止结果；
- 文档权威和暴露，包括公共材料与贡献者材料，以及规范语言与派生语言；
- 结构化、可执行和自然语言评估的边界，包括会使既有 verdict 失效的证据变化；
- 实现、文档、测试、验证、持久化状态和调用方之间一致的契约演进；仅在当前正确性要求时保留兼容或
  恢复行为；以及
- 分发方向、硬依赖、可见性以及公开/私有暴露边界。

有依据的冲突由范围最窄的当前权威管辖。如果有实质不同且有依据的激活方式、适用性、结果、例外、
优先级、所有权、保留或废止政策，则必须停止并请求决策；不得凭无依据的事实暗中选择或省略政策。

命令发现、setup 机制、修改、同步、测试过程和验证过程继续由各自所属的工具和 Skill 负责。放置建议
继续由项目结构所有者负责。排除清单、实现操作步骤、通用架构指引和可从当前所有者处获取的事实，
但省略会改变政策结果的除外。

## Author 授权与终态

未来的 Author 可以检查目标证据，运行所有者支持的只读或非修复性检查，并且只能创建或替换
`GENERATED/.agents/rules/01-project-contracts.md`；其中 `GENERATED` 是 `setup-project-agents`
提供的请求根目录。没有另行接受的授权，Author 不得删除或移动该 Candidate、写入实际目标、修改
无关的目标状态或产生外部效果。

必须只返回一个终态；按以下顺序，以第一个匹配的判别条件为准：

1. `ACCESS_REQUIRED`：授权范围内无法访问必要证据或执行必要验证。
2. `CONTEXT_REQUIRED`：具备访问权限，但无法从合格证据中查明必要事实。
3. `HUMAN_DECISION_REQUIRED`：合格证据允许存在实质不同的政策，或者必需的操作、效果、所有者、
   比较点、例外或义务处置缺少已接受的权威决定。
4. `VALIDATION_FAILED`：某项必需检查仍然失败，或者任何有依据的谓词、义务、受影响表面或 Author
   操作缺少一个有证据支持的结果或授权。
5. `READY`：Candidate 包含每项必需映射，每个有依据的输入都只选择一个可观察的政策结果，任何结论
   都不依赖无依据的项目事实，并且所有适用且由所有者支持的确定性检查均已通过或记录为
   `NOT_REQUIRED`。

每次停止都要指出阻碍因素、所有者、后果，以及开始新尝试所需满足的条件。`READY` 报告 Candidate、
目标所有者、证据所有者、义务处置、检查、保留的约束，以及不确定或未经测试的表面。它仅可作为
`setup-project-agents` 的就绪输入，不授予后续安装、发布、提交或推送权限。
