# 项目契约

强度：`Mandatory`

适用范围：用于规定持久条件的 Setup Authoring Contract；这些条件使目标仓库变更在能力所有权、
安装、文档、评估、契约演进、分发，以及硬依赖或暴露边界方面有效。

## 目标含义

未来目标是一个由目标拥有、标题为 `Project Contracts` 的
`.agents/rules/01-project-contracts.md`，它是由其仓库直接使用的 Mandatory Rule。它陈述使项目
变更有效的持久条件。未来 Author 的专属写入边界是该目标 Rule；仓库证据仍是只读输入。

其范围、适用条件、谓词到结果映射、例外、优先级和所有权边界来自权威的当前仓库证据。只有有依据
的政策簇才属于本 Rule，并由覆盖这些政策簇的一个激活条件组统一激活。保留有依据的现有义务，除非
已接受意图和权威证据选择变更或废止它们。如果有实质不同且有依据的激活、适用范围、结果、例外、
优先级或保留政策，则因歧义停止。缺乏权威依据或依赖无依据事实的行为变更义务同样会导致停止，而
不是作为有证据支持的省略项处理。

## 证据和条件式政策

受支持的证据包括现有 Rule 及其发现入口、更具体的 Rule、已接受规范、可观察的实现和所有权关系，
以及行为测试。现有陈述是保留证据，而不是大纲。每个纳入的政策簇都具有激活事实、可观察结果、准确
例外、优先级和决策所有者。冲突时由最窄的当前权威负责；缺失、冲突、历史遗留或仅限本机的事实不能
确立仓库政策。

证据可能支持以下政策簇：

- 可通过 API、schema、事件、领域模型和实现观察的使用方、状态、兼容性、生命周期、并发、取消、迁移、
  持久化或清理边界；
- 可通过注册表、synchronizer、renderer、manifest 和 catalog 观察的规范源权威，以及不同的转换、
  adapter、传输和交付责任；
- 可通过所有权 manifest、摘要、结构化字段和受管状态观察的 setup 认领、保留、冲突、替换和废止结果；
- 公开文档与贡献者文档、规范语言与派生语言，以及文档与运行时或交付之间的边界；
- 不同的结构化、可执行和自然语言证明边界，以及管辖要求或依赖内容变更时先前 verdict 的失效；
- 实现、文档、测试、验证、持久化状态和调用方之间一致的废止，包括作为当前正确性保留的兼容或恢复行为；
  以及
- 可通过 import、loader、调用路径、package 和插件 manifest 观察的单向分发、硬依赖、可见性和
  公开/私有暴露约束。

## 所有权边界

命令发现、setup 机制、同步、修改、测试和验证过程仍由其所属工具和 Skill 负责。可发现的清单仍由
环境拥有。本 Rule 只负责持久关系和有效性边界。建议性放置和架构启发式规则仍由其目标本地政策所有者
负责；有依据的硬依赖、分发和暴露条件属于本 Rule。

## 合格的编写输入

提供给目标编写所有者的合格输入，会将每项政策映射到权威证据，并涵盖最接近的纳入与排除情形、
所有者边界、Rule 冲突、打包、发现机制以及受影响的结构化或可执行表面。它包含要保留的义务、已接受
变更、有证据支持的省略项、未解决表面和验证计划。
