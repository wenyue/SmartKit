# 项目工具

强度：`Mandatory`

范围：目标仓库的工具、MCP、运行时、同步、变更和完整变更验证策略所对应的 Setup Authoring Contract。

## 目的与证据

当 `setup-project-agents` 请求生成 `.agents/rules/00-project-tools.md` 时，Author 编写一份归目标仓库所有的 Mandatory Rule，规定工具选择、规范来源同步、变更权限、完整变更验证，以及向既有 Skill 的交接。

Setup 必须提供相关目标证据：入口指引、清单和运行时要求、仓库脚本及其当前帮助、任务运行器和 CI、Git 状态、既有 Rules 和 Skills，以及已接受的 Issues、Specs 或 ADRs。按所有者和来源评定每项资料。已接受的项目意图具有决定权；既有 Rule 文本提供保留和回归证据。将义务分类为保留、变更、新增、停用或非目标；除非已接受意图要求变更或停用，否则保留受支持策略。可见性和访问权限不授予权威。

## 需要确立的策略

Rule 将每个会影响结果的条件与其要求的结果关联起来：

- **调用：**决定工具能否正常工作的工作目录和运行时要求。
- **同步：**规范来源的变更、所需同步、受支持的只读漂移检查，以及需要审查的生成效果。
- **变更：**每项操作所需的权限，以及缺少权限时允许采用的只读、限定范围、试运行或停止结果。
- **验证：**从声明的比较点出发核对完整变更，包括已跟踪、已暂存、未暂存和未跟踪状态、生成效果、受影响表面，以及每项适用的非修复检查。
- **交接：**当既有 Skill 负责某项工作时，明确它的可观察触发条件和有界结果。

API、能力、生成来源、交付、安装、依赖、契约演进和放置策略仍归既有所有者负责。脚本保留确定性机制，Skills 保留流程。只有省略会改变策略结果时，才纳入可从当前所有者获取的事实；清单、命令目录、快照和 setup 机制留给这些所有者。

## Author 边界与结果

Author 可以查看目标证据，运行所有者支持的只读或非修复检查，并创建或替换 `GENERATED/.agents/rules/00-project-tools.md`。`GENERATED` 是 setup 提供的请求根目录。删除、移动、写入实际目标、无关变更和外部效果都需要单独的已接受授权。

首个适用条件决定唯一的编写结果：

| 结果 | 判别条件 |
| --- | --- |
| `ACCESS_REQUIRED` | 必要证据或验证在授权范围内无法访问。 |
| `CONTEXT_REQUIRED` | 已有访问权限，但无法从合格证据中发现必要事实。 |
| `HUMAN_DECISION_REQUIRED` | 仍存在实质性策略分歧，或必要的变更、效果、所有者、比较点、例外或义务处置缺少已接受授权。 |
| `VALIDATION_FAILED` | 必要检查失败、确切命令不受支持，或必要映射、受影响表面或受支持输入缺少有证据支持的结果。 |
| `READY` | 每项必要映射均已具备，每个受支持条件都无需虚构事实便能选出一个可观察策略结果，且所有适用的确定性检查均通过或有证据支持记为 `NOT_REQUIRED`。 |

停止时指出阻塞项、所有者、后果和重新尝试的条件。就绪交接说明 Candidate、目标及证据所有者、义务处置、检查、保留约束，以及不确定或未测试表面。它是 `setup-project-agents` 的输入，不授予下游生成、安装、发布、提交或推送权限。
