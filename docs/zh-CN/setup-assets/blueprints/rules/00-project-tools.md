# 项目工具

强度：`Mandatory`

范围：面向目标仓库项目工具、MCP、运行时、同步、修改以及完整变更验证政策的 Setup Authoring Contract。

## 契约框架

当 `setup-project-agents` 请求 `.agents/rules/00-project-tools.md` 时，编写且仅编写这一条归目标所有的 Mandatory Rule。它适用于项目工具、MCP、运行时或验证，并且只负责为以下事项选择安全工具结果所需的持久政策：同步规范源变更、授权修改、验证完整变更，或将工作交接给已有 Skill。

使用已接受的项目意图，以及由目标仓库所有者和来源证明其有效性的证据。相关证据包括入口指导；清单和运行时声明；仓库脚本及当前帮助；任务运行器和 CI 配置；版本控制状态；已有 Rule 和 Skill；以及已接受的 Issue、Spec 或 ADR。目标中已有的 Rule 是需要保留和防止回归的证据，而不是设计权威。除非已接受的意图明确变更或废止其政策，否则应保留其中有依据的政策；可见、工具可用或具有写入权限都不会自行赋予含义或许可。

## 必需政策

要求纳入由有效证据支持的每一项重要映射：

- 会改变调用能否成功的工作目录或运行时谓词，以及由此产生的要求；
- 每项规范源谓词、其必需的同步结果、任何受支持的只读漂移检查，以及必须审查的生成影响；
- 每项修改操作、准许它的确切权限，以及缺少该权限时应采取的只读、限定范围、试运行或停止结果；
- 从已声明的比较点出发，对已跟踪、已暂存和未跟踪状态、生成影响、受影响表面以及所有适用非修复检查进行完整变更验证；以及
- 仅当已有 Skill 的可观察触发条件和有界结果负责该工作时，才交接给它。

目标本地的 API、生成源、能力、交付、安装、依赖、契约演进及放置政策仍由其现有所有者负责；确定性机制仍留在仓库脚本中，流程仍留在所调用的 Skill 中。排除清单、快照、命令目录、设置机制以及能够从当前所有者处获取的事实，除非省略它们会改变结果。

## 编写授权和终态结果

未来的 Author 可以检查目标证据，运行所有者支持的只读或非修复检查，并且只能创建或替换 `GENERATED/.agents/rules/00-project-tools.md`；其中 `GENERATED` 是由 `setup-project-agents` 提供的请求根目录。Author 不得删除或移动该候选文件、写入实际目标、修改不相关的目标状态，也不得在没有另行接受授权的情况下产生外部影响。

只返回一个终态结果；首个匹配的判别条件优先：

1. 当授权范围内无法访问必要证据或验证时，返回 `ACCESS_REQUIRED`。
2. 当访问条件具备，但无法从有效证据中发现必要事实时，返回 `CONTEXT_REQUIRED`。
3. 当有效证据允许实质不同的政策，或所需修改、影响、所有权、比较点或例外缺少已接受授权时，返回 `HUMAN_DECISION_REQUIRED`。
4. 当某项检查仍失败、某条精确命令不受支持，或某项必需映射、受影响表面或受支持输入没有由证据支持的结果时，返回 `VALIDATION_FAILED`。
5. 当这一份候选文件包含每项必需映射、每个受支持谓词都选择了一个可观察政策结果，并且所有适用且由所有者支持的确定性检查均通过或记录为 `NOT_REQUIRED` 时，返回 `READY`。

每次停止都要指出阻塞因素、所有者、后果，以及重新尝试所需的条件。`READY` 要报告候选文件、证据所有者、各项义务的处置结果、检查和未经测试的表面；它只能作为 `setup-project-agents` 的输入，不授权任何下游生成、安装、发布、提交或推送。
