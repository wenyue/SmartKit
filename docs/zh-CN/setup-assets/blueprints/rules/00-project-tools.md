# 项目工具

强度：`Mandatory`

适用范围：用于目标仓库安全执行命令、同步、修改、完整变更验证和已有 Skill 交接的 Setup Authoring
Contract。

## 目标含义

未来目标是一个由目标拥有的 `.agents/rules/00-project-tools.md` Mandatory Rule，由其仓库直接使用。
其持久政策只涵盖安全执行仓库工具、源文件变更同步、修改权限、完整变更验证，以及交接给其触发条件
负责某项工作的已有 Skill。

Rule 的适用范围、谓词到结果映射、例外、优先级和所有权边界来自当前目标证据。保留有依据的现有语义，
除非已接受意图选择变更或废止它们。其写入边界是这一个目标 Rule。任何会实质性改变结果的歧义都会
导致停止，包括冲突或无依据的适用范围、谓词或同步映射、例外、优先级、所有者边界、修改权限、比较点、
保留要求或必需检查。

## 证据和必需映射

受支持的证据包括仓库入口指导；workspace 和 package manifest；运行时和工具链声明；仓库 script
及其帮助；task runner 和 CI 配置；版本控制状态；以及可发现的 Skill 契约。

生成的 Rule 只包含由这些证据确立的映射：

- 当工作目录或运行时前置条件会改变调用能否成功时，包含该条件，并指向其当前所有者而不缓存可发现值；
- 包含每项会产生后果的规范源变更及其必需同步结果、存在时的只读替代方案，以及需要检查的生成影响；
- 包含每项会产生后果的修改及允许该修改的权限，并说明没有权限时必需的只读、限定范围或 dry-run 结果；
- 包含来自已声明比较点、已跟踪和未跟踪变更、生成影响、受影响表面及其适用非修复检查的完整变更证据；
  以及
- 仅当已有 Skill 的可观察触发条件和有界结果负责该工作时，才交接给它。

存在未覆盖的受影响路径或表面，或者必需检查未通过时，不得声称完整验证。工具清单、环境快照、命令目录、
setup 过程，以及已由活动配置、script、命令帮助或 Skill 拥有的行为，均不属于本 Rule。

## 所有权边界

目标本地政策所有者继续负责硬性 API、生成源、能力所有权、交付、安装、依赖、契约演进和建议性放置决定。
本 Rule 可以在这些关注点选择工具结果时引用它们，但不复述这些政策。确定性机制仍留在仓库自有 script 中。

## 合格的编写输入

提供给目标编写所有者的合格输入，会将纳入的每个谓词和准确命令映射到权威目标证据。它包含要保留的
义务、已接受变更、有证据支持的省略项、未解决表面，以及覆盖受影响结构化和可执行表面的验证计划，
其中包括决定机器验证或可执行 Acceptance 是否适用所需的证据。
