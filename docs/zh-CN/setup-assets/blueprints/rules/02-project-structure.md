# 项目结构

强度：`Advisory`

适用范围：用于目标仓库基于证据的放置建议的 Setup Authoring Contract。

## 目标含义

未来目标是一个由目标拥有的 `.agents/rules/02-project-structure.md` Advisory Rule，由其仓库直接
使用。它只回答在应用 Mandatory 有效性政策后，变更应放在哪里，以及如何对合理的放置方案排序。
每项结果都是以证据为条件的建议，例如 `prefer`、`favors`、`points toward` 或 `ranks higher`，
绝不是所有权、有效性、交付或依赖约束。

其写入边界是这一个目标 Rule。其放置范围、适用条件、证据到建议映射、例外和所有权边界来自当前
仓库证据。保留有依据的现有义务，除非已接受意图和权威证据选择变更或废止它们。

## 证据与建议

受支持的证据包括现有目标 Rule 和发现入口、更具体的 Rule、已接受规范、直接调用和 import、注册表
和 schema 关系、generator 流程、运行时入口点、使用方和行为测试。这些信号的优先级高于目录名称、
共置关系、命名以及仅凭 package 或插件边界得出的判断。

生成的建议只表达由这些证据支持的关系：

- 当一个使用方能让一项决定、落实它的机制和观察它的测试保持内聚，且只需要很少的跨所有者知识时，
  本地放置排名更高；
- 当多个独立使用方需要同一项稳定决定，或本地副本反复产生跨所有者耦合时，既有共享接缝排名更高；
- 对于适配上游意图而不决定该意图的表征，面向使用方的边界排名更高；
- 对于稳定且重复的下游政策或机制，最早具有足够上下文的既有所有者排名更高；而当上移会抹去选择所需
  上下文时，本地性排名更高；以及
- 只有直接证据确立本地例外的范围、谓词和原因时，才在较宽泛的建议旁附带该例外。

## 所有权边界

目标本地 Mandatory 政策所有者继续负责规范源和生成源、安装、交付、依赖、暴露、fixture 和其他
有效性边界的硬性要求。本 Rule 可以按关注点引用这些所有者，但不把其约束复述为结构指导。命令执行、
编写工作流和验证过程仍由其当前所有者负责。

排除目录清单、package 导览、通用分层建议、对未来架构的臆测和无依据的放置断言。只有位置会改变真实
的放置方案比较时，才提及该位置。

## 歧义和合格的编写输入

有实质不同且有依据的所有者、强度、范围、优先级、适用条件、例外、保留要求或建议映射时，应因歧义
停止。缺失、冲突、历史遗留、仅限本机或无依据的证据不能在这些选项中作出选择，编写或资格认定失败
也不能解决它们。

提供给目标编写所有者的合格输入，会将每项建议追溯到权威目标证据、回答一个真实的放置方案比较，
并且不重复 Mandatory 有效性政策。它包含要保留的义务、已接受变更、有证据支持的省略项、未解决
表面和验证计划。
