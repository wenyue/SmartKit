# 项目结构

强度：`Advisory`

范围：目标仓库的结构、放置、职责和导航建议所对应的 Setup Authoring Contract。

## 目的与证据

当 `setup-project-agents` 请求生成 `.agents/rules/02-project-structure.md` 时，Author 编写一份归目标仓库所有、标题为 `Project Structure` 的 Advisory Rule。它在更窄范围策略或 Mandatory 策略之后，对位置、职责边界或导航入口的有效选择排序。所有权、依赖许可、交付、安装和暴露仍归相应策略所有者负责。

Setup 必须提供相关目标证据：入口指引和更窄范围的 Rules；已接受的 Issues、Specs 和 ADRs；调用方、导入、消费者、测试、模式、注册表、生成器、运行时入口和规范文档路径。按所有者和来源评定资料。名称、共同放置、目录与包边界和机器本地状态只是线索，不是权威；既有 Rule 文本是回归证据，不是设计权威。

将每条建议分类为保留、变更、新增、停用或非目标。变更、新增、停用和例外需要已接受意图与合格证据；否则保留受支持建议或停止。

## 需要指导的选择

每条建议都解决一个真实的竞争选择。说明其条件、排序结果和证据所有者，并说明任何例外的范围、判别条件和理由。保留有证据支持、倾向以下选择的建议：

- 当一个消费者保有决定性上下文，且能让策略、实现和测试保持内聚时，优先**局部性**。
- 当独立消费者需要一个稳定决策，或重复副本造成跨所有者耦合时，优先**既有共享边界**。
- 对适配上游意图而不决定上游意图的表示，优先放在**面向消费者的边界**。
- 对下游重复的策略或机制，优先交给**最早具备充分上下文的既有所有者**，前提是上移仍保留作出选择所需的上下文。
- 优先使用能引向所属来源、且不重复维护清单的**规范导航入口**。

Mandatory 所有者保留硬性所有权、规范来源、依赖、生成、安装、交付、暴露和验证策略。建议应针对受支持选择；包结构导览、缓存布局、通用分层、推测性架构，以及 setup 或编写流程都不属于本 Rule。

## Author 边界与结果

Author 可以查看目标证据，运行所有者支持的只读或非修复检查，并在 setup 的请求根目录下创建或替换 `GENERATED/.agents/rules/02-project-structure.md`。删除、移动、写入实际目标、无关变更和外部效果都需要单独的已接受授权。

首个适用条件决定唯一的编写结果：

| 结果 | 判别条件 |
| --- | --- |
| `ACCESS_REQUIRED` | 必要证据或验证在授权范围内无法访问。 |
| `CONTEXT_REQUIRED` | 已有访问权限，但无法从合格证据中发现必要事实。 |
| `HUMAN_DECISION_REQUIRED` | 仍存在实质性排序分歧，或必要的所有者、例外、义务处置、操作或效果缺少已接受授权。 |
| `VALIDATION_FAILED` | 必要检查失败，或受支持选择、义务、操作或边界缺少有证据支持的结果或授权。 |
| `READY` | 每条建议都解决一个受支持选择，每个受支持输入都无需虚构事实便能选出一个可观察结果，且所有适用的确定性检查均通过或有证据支持记为 `NOT_REQUIRED`。 |

停止时指出阻塞项、所有者、后果和重新尝试的条件。就绪交接说明 Candidate、目标及证据所有者、义务处置、检查、保留约束，以及不确定或未测试表面。它是 `setup-project-agents` 的输入，不授予下游生成、安装、发布、提交或推送权限。
