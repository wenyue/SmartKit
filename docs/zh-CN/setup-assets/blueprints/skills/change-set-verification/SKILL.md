# 变更集验证

## 目的与证据

当 `setup-project-agents` 请求生成 `.agents/skills/change-set-verification/SKILL.md` 时，Author 编写一份归目标仓库所有、由模型调用的 Skill，供 Agent（包括仓库的 `change-set-verifier`）在交接前验证一个连贯完整的实现检查点。它负责机械规范化、充分验证和有证据支持的结论。实现和调试仍归当前所有者负责，直到形成新的完整检查点。

使用 `name: change-set-verification`，省略 `disable-model-invocation`，并在 `description` 中表达完整检查点触发条件和验证结果。完整运行时契约放在 `SKILL.md` 中；仓库所有者保留确定性命令和映射。

Setup 必须提供相关目标证据：Rules 和 Skills、已接受任务和比较点、Git 状态、清单、锁文件、工具链、脚本及其当前帮助、测试和 CI，以及生成来源、依赖和直接测试的所有者。按所有者和来源评定资料。将义务分类为保留、变更、新增、停用或非目标。既有 Skill 文本提供保留和回归证据；已接受意图授权变更或停用。可见性、可执行性、写入访问权限和 Author 权限都不授予 Candidate 运行时权限。

## 验证契约

### 范围与效果

Skill 从已接受任务上下文和当前 Git 状态确立完整变更与比较点：生产代码、测试、配置、支持文件、生成效果，以及已跟踪、已暂存、未暂存和未跟踪状态。它保留 `HEAD`、索引、无关工作和用户所有文件。

选择当前所有者支持的、最小而充分的格式化、静态、测试、构建、运行时和差异完整性验证表面。仅当依赖、共享契约、生成接口、工具限制、修复器变更、缺失测试归属或未解决范围使较窄证据不可靠时，才扩大验证。发现或修复既有问题不是扩大范围的理由。按范围保真度、效果边界、诊断质量和可信最终证据选择仓库、原生或 MCP 工具；从当前所有者解析命令。

运行时授权仅允许所有者支持的证据生成检查，以及对选定项目所有来源的规范化；检查声明的输出必须留在所有者声明的项目路径内。规范化使用所有者支持的格式化工具，或获准处理已知机械诊断或已接受机械迁移的自动修复器。生成输出只能通过其声明的所有者改变。每项变更和临时检查输出均须限定范围并报告；超出授权的任何效果都需要单独的已接受授权。

必要效果缺少可用授权时，在产生效果前返回 `inconclusive`。尝试或观察到越权效果即构成安全违规：停止进一步效果、保留证据，并在路由诊断前返回 `failed`。

### 证据顺序

要求能够保护状态、保持证据有效的顺序：

- 在变更前确立范围、检查点、所有权、前提和必要验证表面。
- 适用的所有者支持格式化先于检查。获准的修复器在每个检查点内按其最小支持范围运行一次；必要的重新格式化和每个工具修改文件都纳入选定变更。
- 对结果状态先运行最小受支持非变更静态检查，再运行直接所属测试，最后运行由风险或所有权证明必要的更广表面。除非后续变更使证据失效，每个唯一表面只运行一次。
- 剩余语义诊断连同确切证据返回实现所有者。该所有者的下一次变更建立新检查点，并从当前仓库状态重新验证。

当 Harness 保留选择条件和证据时，独立非变更检查可以并行。对变更敏感的检查和生成输出消费者保留其依赖顺序。对可能先于本次变更存在的失败，只在失败表面上与可信基线对照分类；基线工作不得超过分类所需范围。

### 结果与交接

报告每个选定表面的所有者支持调用、范围、选择理由、结果（`passed`、`failed`、`inconclusive` 或 `not applicable`）和缺口。包括规范化调用与变更、重复及其原因、语义诊断和未测试表面。

先应用安全违规保护条件，再由首个适用条件选择唯一总体结果：

| 结果 | 判别条件 |
| --- | --- |
| `semantic_fix_required` | 可信的已完成证据指出实现所有者必须作出的语义变更。同时报告机制失败或缺口，但它们不替代此结论。 |
| `failed` | 尚未确立需要语义修复，且可信证据证明必要机制、工具或运行时失败。 |
| `inconclusive` | 前两种结果均未确立，且必要证据、所有权、前提、比较点、仓库状态或基线分类不充分。 |
| `passed` | 每个必要表面均通过，每项选定变更均有归属且纳入已验证变更，并且不存在必要证据缺口。 |

每次退出都保留观察到的状态和证据。业务实现、语义修复、工作树创建或集成、依赖安装、Agent 同步、Git 历史变更、交付和破坏性清理仍处于本 Skill 的所有权和运行时授权之外。

## Author 边界

Author 可以查看合格目标证据，运行所有者支持的只读或非修复检查，并在 setup 的请求根目录下创建或替换 `GENERATED/.agents/skills/change-set-verification/SKILL.md`。唯一的支持文件例外是下述确定性选择器。不允许删除、移动、写入实际目标或无关变更；外部效果限于 Acceptance 授权。Author 权限不会转化为运行时权限。

仅当合格证据证明所有者工具无法表达必要的重复确定性选择或聚合，且来自获授权来源的已接受输入提供确切的 Candidate 相对路径和目标所有者时，才允许一个辅助脚本。Author 验证并使用这些值，而不自行选择。权限缺失、含糊或与所有者不匹配时，必须在任何 Candidate 写入前返回 `HUMAN_DECISION_REQUIRED`。通配符、目录授权或运行时选择的路径均不足以授权。

脚本契约确立输入输出模式、允许的文件系统和进程效果、失败行为、所有者支持的运行时、代表性与边界验证，以及被所有者工具取代后的移除。脚本实现既有映射；策略、范围、所有权、权限、扩大验证和结论仍留在 `SKILL.md`。脚本失败时停止并报告确切调用和错误；修正需要新的已审阅 Candidate。

## 编写证据与结果

就绪依赖同一 Candidate 的机器证据、质量与正确性审阅，以及 Acceptance。机器检查使用所有者支持的确定性非修复验证，覆盖结构、frontmatter、引用、路径和任何脚本。审阅覆盖调用、范围、效果、检查映射、顺序、扩大验证、基线分类、结论优先级、脚本例外、退出和交接；未解决或不受支持的映射阻止 PASS。

Acceptance 要求机器证据通过，且质量与正确性审阅均为 PASS。在该关口冻结 Candidate 指纹、受保护目标状态（`HEAD`、索引、无关及用户所有状态），以及确切可变路径和预期效果。任何其他审阅结果都在 Acceptance 前停止。

Acceptance 仅可在目标仓库内一个已确定的、具有代表性的连贯完整变更上执行声明的运行时效果，且须得到合格目标所有者允许。覆盖该变更和一个安全、适用的失败或停止路径，证明规范化范围、必要检查、结论优先级、报告和状态保留。记录确切目标、选定文件、调用、预期与观察到的效果、诊断，以及前后状态。不包括依赖安装、历史变更、交付、破坏性清理，以及无关仓库或外部效果。必要效果超出此授权，或缺少目标所有者权限时，必须在执行前返回 `HUMAN_DECISION_REQUIRED`；Author 写入权限不能替代该授权。

Acceptance 后，Candidate 和受保护目标状态必须与各自的 Review PASS 指纹一致。依据冻结的效果计划核对可变路径变更：记录预期且获准的变更；其他任何变更都使审阅和 Acceptance 失效。记录未测试表面。

首个适用条件决定唯一的编写结果：

| 结果 | 判别条件 |
| --- | --- |
| `ACCESS_REQUIRED` | 必要证据或验证在授权范围内无法访问。 |
| `CONTEXT_REQUIRED` | 已有访问权限，但无法从合格证据中发现必要事实。 |
| `HUMAN_DECISION_REQUIRED` | 仍存在实质性语义分歧，或必要的所有者、比较点、权限、效果、例外或停用缺少已接受授权。 |
| `VALIDATION_FAILED` | 验证仍然失败，或必要运行时输入缺少一个受支持的可观察结果。 |
| `READY` | 最终边界证明已审阅并验收的 Candidate 保持不变、每项义务均已覆盖、每个受支持运行时输入恰好对应一个结果，且所有适用检查均通过或有证据支持记为 `NOT_REQUIRED`。 |

停止时指出阻塞项、所有者、后果和重新尝试的条件。就绪交接报告确切 Candidate 路径、证据所有者、义务处置、检查、审阅和 Acceptance 证据，以及未测试表面。它是 `setup-project-agents` 的输入，不授予下游生成、安装、发布、提交或推送权限。
