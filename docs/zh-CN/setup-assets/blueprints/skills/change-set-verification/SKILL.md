# 变更集验证

## 目的与证据

对于独立创建或修订 `.agents/skills/change-set-verification/SKILL.md` 的请求，使用 `write-rules-and-skills` 编写一份归目标仓库所有、由模型调用的 Skill，供 Agent（包括仓库的 `change-set-verifier`）在交接前验证一个连贯完整的实现检查点。它负责机械规范化、充分验证和有证据支持的结论。实现和调试仍归当前所有者负责，直到形成新的完整检查点。

使用 `name: change-set-verification`，省略 `disable-model-invocation`。将 [fixed-content.json](../../../../../../setup-assets/blueprints/skills/change-set-verification/fixed-content.json) 和本目录的来源文件作为固定内容输入交给公共 writer：蓝图的 `description` 原样复制到目标 Skill，[目标元数据](../../../../../../setup-assets/blueprints/skills/change-set-verification/target/agents/openai.yaml) 提供六个界面字段，[图标](../../../../../../setup-assets/blueprints/skills/change-set-verification/target/assets/icon.svg) 提供打包资源。保留独立元数据字段和有效项目补充。蓝图及这些来源可以独立于 Setup 与 writer 配合使用。

共享权限、分支选择、结果语义，以及每条路径都需要的内容放在 `SKILL.md` 中。仅当按需加载能提升清晰度或避免加载大量无关内容时，才将分支专属契约或映射拆入配套引用。每份引用都有明确的加载条件，每条选定路径都能读取完整契约。仓库所有者保留确定性命令和映射；仓库特定的选择细节放在正文中，不放在固定的发现描述里。

根据已接受请求和当前证据确立目标仓库。Author 主动发现并核实相关目标证据：Rules 和 Skills、已接受任务和比较点、Git 状态、清单、锁文件、工具链、脚本及其当前帮助、测试和 CI，以及生成来源、依赖和直接测试的所有者。复用调用方提供的合格证据，直接发现缺失事实；调用方无需事先准备证据包。按所有者和来源评定资料。将义务分类为保留、变更、新增、停用或非目标。既有 Skill 文本提供保留和回归证据；已接受意图授权变更或停用。可见性、可执行性、写入访问权限和 Author 权限都不授予 Candidate 运行时权限。

## 更新重点

除非项目策略或受支持的工具行为发生变化，否则保持已接受的验证顺序、效果边界和结果含义稳定。根据当前脚本、清单、CI 任务和生成器所有者，重新核对工具选择及受影响表面的映射。更换测试运行器可能改变检查路径，但不改变 Skill 何时可以报告成功或交还工作。

为读者提供具体方向，说明如何选择最小充分检查并解读结果。原位更新过时映射，保留仍然有效的项目特定检查和例外，删除重复操作配方。未变化的正文和支持引用仍然完整时予以复用；既有内容是需要评估的证据，不是跳过评估的理由。

## 验证契约

### 范围与效果

Skill 从已接受任务上下文和当前 Git 状态确立完整变更与比较点：生产代码、测试、配置、支持文件、生成效果，以及已跟踪、已暂存、未暂存和未跟踪状态。它保留 `HEAD`、索引、无关工作和用户所有文件。

选择当前所有者支持的、最小而充分的格式化、静态、测试、构建、运行时和差异完整性验证表面，始终包含适用于本次变更的项目强制检查。仅当依赖、共享契约、生成接口、工具限制、修复器变更、缺失测试归属或未解决范围使较窄证据不可靠时，才扩大验证。发现或修复既有问题不是扩大范围的理由。按范围保真度、效果边界、诊断质量和可信最终证据选择仓库、原生或 MCP 工具；使用前对照当前所有者核对文档中的调用。

编写出的 Skill 必须为每个选定验证表面教授一条可执行路径。明确工具或仓库入口、所需运行时和工作目录、前提及依赖顺序、包含参数与文件或测试选择条件的确切调用、允许的效果、权威完成证据、结果解释，以及工具不可用或调用失败时的处置。提供有项目证据支持的 CLI 示例；原生和 MCP 操作则给出具体工具名称和参数形式。说明如何根据变更推导可变选择条件。明确的所有者入口或帮助查找可以解决变化中的细节，但泛泛要求寻找并运行适当检查，不能替代调用路径，也不能迫使运行时读者重新发现整个流程。

前提满足时，在现有环境中运行检查。仅位于 linked worktree 中或准备记录过时，并不触发环境准备。有证据表明选定检查所需前提缺失或过时时，可能需要环境所有者介入，但必须遵守其调用条件和效果权限；验证不会因这个缺口获得环境准备或依赖安装权限。

运行时授权仅允许所有者支持的证据生成检查，以及对选定项目所有来源的规范化；检查声明的输出必须留在所有者声明的项目路径内。规范化使用所有者支持的格式化工具，或获准处理已知机械诊断或已接受机械迁移的自动修复器。生成输出只能通过其声明的所有者改变。每项变更和临时检查输出均须限定范围并报告；超出授权的任何效果都需要单独的已接受授权。

必要效果缺少可用授权时，在产生效果前返回 `inconclusive`。尝试或观察到越权效果即构成安全违规：停止进一步效果、保留证据，并在路由诊断前返回 `failed`。

### 证据顺序

要求能够保护状态、保持证据有效的顺序：

1. 在变更前确立范围、检查点、所有权、前提和必要验证表面。将变更映射到项目强制检查和直接受影响检查，并提供选择理由及可用调用路径。
2. 在检查前运行适用的所有者支持格式化工具。获准的修复器在每个检查点内按其最小支持范围运行一次；必要的重新格式化和每个工具修改文件都纳入选定变更。
3. 对结果状态运行最小受支持非变更静态检查。
4. 运行直接所属测试，随后运行由风险或所有权证明必要的更广测试、构建、运行时或差异完整性验证表面，以及所有适用的项目强制检查。每个选定表面运行一次；仅当相关变更使其证据失效，或先前失败的原因已解决时，才重新运行。
5. 解释权威完成证据，核对规范化及其他效果，并产出下述结果和交接。缺少工具、前提、权限或证据时，走适用的失败或无法确定路径，不悄然跳过必要表面。
6. 将剩余语义诊断连同确切证据返回实现所有者。该所有者的下一次变更建立新检查点，并从当前仓库状态重新验证。

当 Harness 保留选择条件和证据时，独立非变更检查可以并行。对变更敏感的检查和生成输出消费者保留其依赖顺序。对可能先于本次变更存在的失败，只在失败表面上与可信基线对照分类；基线工作不得超过分类所需范围。

### 结果与交接

将完整命令输出保存在运行时授权范围内可访问、范围明确且受所有者支持的位置。记录每个选定表面的调用、范围、选择理由、退出状态、结果（`passed`、`failed`、`inconclusive` 或 `not applicable`）和证据缺口，包括规范化效果、重跑及其原因。通过的检查简要说明范围、结果和可用的测试数量；失败的检查给出可操作的诊断及完整输出位置。最终交接报告总体结果、行为变化、实质性缺口和证据位置，无需重放命令输出。

先应用安全违规保护条件，再由首个适用条件选择唯一总体结果：

| 结果 | 判别条件 |
| --- | --- |
| `semantic_fix_required` | 可信的已完成证据指出实现所有者必须作出的语义变更。同时报告机制失败或缺口，但它们不替代此结论。 |
| `failed` | 尚未确立需要语义修复，且可信证据证明必要机制、工具或运行时失败。 |
| `inconclusive` | 前两种结果均未确立，且必要证据、所有权、前提、比较点、仓库状态或基线分类不充分。 |
| `passed` | 每个必要表面均通过，每项选定变更均有归属且纳入已验证变更，并且不存在必要证据缺口。 |

每次退出都保留观察到的状态和证据。业务实现、语义修复、工作树创建或集成、依赖安装、Agent 同步、Git 历史变更、交付和破坏性清理仍处于本 Skill 的所有权和运行时授权之外。

## Author 边界

Author 可以查看合格目标证据，运行所有者支持的只读或非修复检查，并在获准 Candidate 根目录下创建或替换 Skill 入口、目标元数据与图标。目标目录为 `.agents/skills/change-set-verification/`，包含 `SKILL.md`、`agents/openai.yaml` 和 `assets/icon.svg`。不要求固定的暂存目录。由合格目标证据决定是否需要配套 Markdown 引用，以及如何组织其内容和命名。每份引用仅承载入口指针所指向的、本 Skill 必要的契约或映射，并保留其含义与约束力。

在任何 Candidate 写入前，通过公共 writer 的布局过程，在已有权限内确定并冻结每个文件的确切 Candidate 相对路径、目标所有者及允许的创建或替换操作。Author 根据项目证据作出普通设计选择；调用方预先提供确切路径不是前提。调查可发现的事实，并通过 writer 报告尚未解决的访问、证据或授权缺口。所有 Candidate 文件都必须位于获准根目录下。下述确定性选择器是唯一允许的可执行支持文件。不允许删除、移动、写入实际目标或无关变更；外部效果限于验收授权。Author 权限不会转化为运行时权限。

仅当合格证据证明所有者工具无法表达必要的重复确定性选择或聚合时，才允许一个辅助脚本。Author 根据已接受任务和证据确定其确切 Candidate 相对路径及目标所有者，写入前通过公共 writer 冻结路径和操作。在依赖这些条件的工作开始前解决所有者或权限缺口；授权内的普通接口设计不需要额外决策。

脚本契约确立输入输出模式、允许的文件系统和进程效果、失败行为、所有者支持的运行时、代表性与边界验证，以及被所有者工具取代后的移除。脚本实现既有映射；策略、范围、所有权、权限、扩大验证和结论仍留在 Skill 的 Markdown 契约中。脚本失败时停止并报告确切调用和错误；修正需要新的已审阅 Candidate。

## 目标 Skill 的验收

公共 writer 负责编写角色、审查、Candidate 证据和终止结果。以下要求为编写出的目标 Skill 提供任务特定的验收条件。验证调用、范围、效果、检查映射、顺序、扩大验证、基线分类、结论优先级、脚本例外、退出和交接。每个受支持的运行时输入必须恰好选出一个结果，每项已接受义务和映射都需要证据。运行适用、由所有者支持的确定性非修复检查，包括任何脚本的验证；省略检查需要有证据证明其不适用。

在产生效果的验收前，在 writer 授权的运行边界内冻结 Candidate 指纹、受保护目标状态（`HEAD`、索引、无关及用户所有状态），以及确切可变路径和预期效果。

验收仅可在目标仓库内一个已确定的、具有代表性的连贯完整变更上执行声明的运行时效果，且须得到合格目标所有者允许。覆盖该变更和一个安全、适用的失败或停止路径，证明规范化范围、必要检查、结论优先级、报告和状态保留。记录确切目标、选定文件、调用、预期与观察到的效果、诊断，以及前后状态。不包括依赖安装、历史变更、交付、破坏性清理，以及无关仓库或外部效果。必要效果超出此授权，或缺少目标所有者权限时，必须在执行前通过 writer 解决；Author 写入权限不能替代该授权。

验收后，证明 Candidate 和受保护目标状态均未变化。依据冻结的效果计划核对可变路径变更：记录预期且获准的变更；其他任何变更都使证据失效。记录未测试表面。

在 writer 交接中说明证据所有者、义务处置、验收证据、效果和未测试表面。对于尚未解决的缺口，指出阻塞项、所有者、后果和继续所需的条件。交接必须能由调用方独立使用，且不授予下游生成、安装、发布、提交或推送权限。
