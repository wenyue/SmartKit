# 准备工作树环境

## 目的与证据

对于独立创建或修订 `.agents/skills/prepare-worktree-environment/SKILL.md` 的请求，使用 `write-rules-and-skills` 编写一份归目标仓库所有、由模型调用的 Skill，供 Agent 准备所属工作流已经选定的确切 linked worktree。它提供仓库特定的环境准备和仅针对环境的结果。`create-worktree` 将此证据与当前选择及工作空间状态结合，判断即时就绪；它不运行项目基线检查。后续生命周期所有者重建当前状态，并在自身明确授权下行动。

使用 `name: prepare-worktree-environment`，保持模型调用启用。将 [fixed-content.json](../../../../../../setup-assets/blueprints/skills/prepare-worktree-environment/fixed-content.json) 和本目录的来源文件作为固定内容输入交给公共 writer：蓝图的 `description` 原样复制到目标 Skill，[目标元数据](../../../../../../setup-assets/blueprints/skills/prepare-worktree-environment/target/agents/openai.yaml) 提供六个界面字段，[图标](../../../../../../setup-assets/blueprints/skills/prepare-worktree-environment/target/assets/icon.svg) 提供打包资源。保留独立元数据字段和有效项目补充。蓝图及这些来源可以独立于 Setup 与 writer 配合使用。

`SKILL.md` 负责运行时判断；仓库所有者保留命令、依赖清单、生成映射和服务配置。仓库特定的选择与准备细节放在正文中，供 Agent 在发现触发条件适用后读取。

根据已接受请求和当前证据确立目标仓库。Author 主动发现并核实相关目标证据：Rules 和 Skills、清单和锁文件、工具链与运行时配置、所属准备和生成入口、CI、必要输入输出、不含秘密值的凭据要求、服务生命周期，以及功能性就绪检查。复用调用方提供的合格证据，直接发现缺失事实；调用方无需事先准备证据包。按所有者和来源评定资料。既有文本是回归证据，不是设计权威；可见性、可执行性和写入访问权限不授予权威。

保留最小准备、已接受可选分支、主检出拒绝、功能性就绪、安全重跑、部分效果恢复和有界报告。以当前所有者查找和确切根目录绑定替换缓存步骤；要求事先授权的效果范围和完整尝试后核查。按下文要求将稳定、可重复的准备脚本化，脚本形式依据项目证据决定，并停用固定等待和调用方编排。在运行时，资源置备、工作树生命周期、基线或完整变更验证、实现、历史、集成、清理和 Agent 同步均为非目标；`change-set-verification` 负责完整变更验证。目标 Skill 的验收通过生命周期所有者执行，不将这些职责转交给环境 Skill。

## 更新重点

已接受的根目录身份检查、Git 保护、效果边界、恢复和就绪含义仍然有效时予以保留。环境变化时，重新查看当前依赖清单、锁文件、准备入口、必要生成输出和服务就绪条件的所有者。采用新的准备命令时，应更新其所有者查找方式和效果，不削弱周围的保留契约。

说明哪些证据区分已经就绪的工作树与仍需准备的工作树，以及哪个失败条件会阻止就绪。保留有效的项目特定可选分支及其理由，原位更新过时的准备事实，删除被替代的操作配方，不累积多个替代方案。当前证据仍然支持时，保留未变化的完整内容。

## 环境契约

### 调用与证据复用

在新建 linked worktree 首次使用、有证据表明当前任务所需环境前提缺失或过时，或用户明确请求准备选定工作树时调用。前提满足时，普通实现和验证使用现有环境。

仅位于 linked worktree 中或缓存准备记录失效，并不能确立准备需要。准备指令或脚本变化可能使其旧证据失效，但不能据此证明当前环境存在缺口。在已有充分理由的调用中，只有根目录、输入、准备来源、选定分支和观察到的就绪状态仍然适用时，才复用旧证据；证据失效时，在该调用内重新评估。

### 身份与保留

选定根目录和调用方对准备效果的权限是前提。变更前证明字面路径、实际物理根目录、注册状态、仓库身份和 Git 公共目录。拒绝主检出以及含糊、未注册或不同的根目录。从当前目标所有者证据解析命令，将其工作目录或显式仓库参数绑定到该物理根目录。

**Git 保留不变量** 保护效果前的 `HEAD`、附着状态、当前提交树和完整索引状态；附着分支的名称／ref 及指向也必须保持完全一致。不创建提交，不创建、删除或改变任何 ref 的指向。任何效果前捕获基线，在每次尝试效果的紧邻前后及最终核查时证明该不变量。效果范围不能授权改变受保护 Git 状态。

### 准备与效果

确立每个受支持新工作树所需的最小准备，并仅纳入已接受上下文选定的可选、平台或任务分支。通过当前最窄且可靠的项目所属脚本执行稳定、可重复的准备，保留锁定入口。缺少可靠入口时，由 Author 按下述脚本契约提供必要的确定性编排。一次性操作可以直接使用所有者支持的命令，并以证据说明不将其脚本化的理由。必要的底层操作缺少目标所有者支持时必须停止，不能自行发明命令、依赖、映射、降级结果或平台承诺。

每项效果前，冻结其所有者支持调用和 **效果范围** ：文件系统目标、持久 Git 公共状态变更，以及外部或持久效果，包括凭据访问和服务。将调用方对每项变更的权限绑定到此工作树。权限缺失、含糊或无归属时，在效果前停止；准备只能改变效果范围内获准的状态，同时保留 Git 不变量。

允许的准备包括选定且有证据支持的依赖安装、输入初始化、所属生成和必要服务。每次尝试前后均核查工作树、Git 公共状态和每个效果目标，包括不可用、失败和中断的尝试。将每个差异归属到其所有者和授权，并保留部分输出和进程证据。

会终止的操作需要所有者声明的成功退出；持久服务需要其声明的生命周期、存活和就绪证据。长时间运行的操作保留其进程和输出，截止时间以声明时长为依据。失去控制或无法确定是否完成时，需要观察原操作及其效果。只有操作已结束，且其所有者支持从观察到的部分状态重复执行时，才可重试；否则保留证据并停止。等待和报告间隔不能证明完成。

就绪要求必要配置、输出、工具和服务的当前功能证据。只有所有者将版本探测声明为就绪检查时，它才足够。最终核查证明每项效果均在范围内、每个选定分支均已就绪，且 Git 状态得到保留。

### 结果与交接

首个适用条件决定唯一环境结果并结束运行：

| 结果 | 判别条件 |
| --- | --- |
| `environment-non-ready` | 身份或绑定无效；必要证据、输入、命令、权限或就绪缺失或含糊；获准恢复后操作仍失败、中断或不确定；出现意外或越界效果；即使在效果范围内 Git 保留仍失败；或最终核查不完整。 |
| `environment-ready` | 必要准备已满足或已完成，包括获准恢复；每个选定可选分支均满足要求，每项效果均获准且在范围内，功能性就绪通过，且 Git 状态得到保留。 |

报告根目录、准备和可选分支处置、调用与结果、效果、就绪证据、Git 保留结论，以及其他所有者保留的工作。非就绪结果还说明阻塞项、保留的部分状态、恢复条件，以及何时可以安全发起新调用。就绪结果向调用方提供当前环境证据。完整变更验证及后续生命周期效果的权限仍归各自所有者负责。

## Author 边界

Author 可以查看合格目标证据，运行所有者支持的只读或非修复检查，并在本次请求授权的 Candidate 根目录下创建或替换 Skill 入口、目标元数据与图标，以及必要的 Skill 所属脚本。目标目录为 `.agents/skills/prepare-worktree-environment/`，包含 `SKILL.md`、`agents/openai.yaml`、`assets/icon.svg` 和任何必要的 `scripts/` 文件。不要求固定的暂存目录。Candidate 删除或移动、实际目标写入、无关变更和外部效果需要区别于 Candidate 写入的已接受授权。

复用可靠的仓库所属准备脚本。合格证据表明稳定、可重复的确定性准备缺少可靠入口时，编写能完成该准备的最小脚本。根据已接受任务和项目证据，确定其确切路径、目标支持的运行时、接口、效果范围、验证，以及保留、更新和移除所有者。写入前，通过公共 writer 的布局过程冻结确切 Candidate 路径和创建或替换操作。Author 可以在已有权限内作出这些工程选择；调用方无需提供每个字段。调查可发现的事实，并通过 writer 报告尚未解决的访问、证据或授权缺口。

记录每个脚本的调用、根目录绑定、输入输出、失败和部分效果行为、安全重跑及功能检查。意图、权限、可选分支选择、恢复决策和就绪解释保留在 `SKILL.md` 中；脚本承载确定性执行和探测。创建脚本本身不构成验证。

## 目标 Skill 的验收

公共 writer 负责编写角色、审查、Candidate 证据和终止结果。以下要求为编写出的目标 Skill 提供任务特定的验收条件。每个受支持的运行时输入必须恰好选出一个环境结果，每项已接受义务都需要证据。运行每项适用、由所有者支持的确定性非修复检查；省略某项检查需要合格证据证明其不适用。

将产生效果的验收绑定到覆盖实际根目录、创建和清理损失及准备效果范围的已接受权限；复用已覆盖这些效果的权限。对于新增或修改的目标准备脚本，验收必须执行真实目标仓库的完整生命周期。让冻结的 Candidate 及其脚本在真实目标仓库中一个获准隔离测试来源内可被 `create-worktree` 发现，并记录该调用如何绑定到此指纹。调用 `create-worktree` 创建专用测试工作树，并实际调用此 Candidate 的环境 Skill。观察创建过程、准备调用和功能性就绪，以及 `create-worktree` 对同一根目录返回的最终 `ready` 结果。随后，在已接受的明确丢弃权限覆盖测试所属状态的前提下调用 `finish-worktree`，验证工作树和临时分支已移除，并通过所有者支持的方式清理测试所属进程和资源。保留损失边界外的共享缓存和资源。工作树创建和结束仍归对应 Skills 负责，环境资源清理仍归其声明的所有者负责。

模拟命令、脚本语法检查、手动准备的工作树，或创建后单独调用准备流程，都不能替代完整调用链证据。脚本未变化时，在有代表性的 linked worktree 中执行默认环境路径，或复用仍然适用且绑定到已审查 Candidate 的证据。每种情形都必须证明在变更前拒绝主检出。记录指纹、真实仓库和测试来源、确切调用与结果、效果前基线、功能证据、环境 Git 保留、生命周期效果、清理和保留状态。证明测试未改变原检出的 HEAD、分支、完整索引，以及已跟踪、未跟踪和 ignored 内容。生命周期失败、中断、不确定或清理不完整时，验收不能通过；保留诊断和部分状态，只完成安全且获准的清理，不掩盖原始失败。

每个在行为、效果或风险上具有实质差异的已接受可选分支，都需要自己的验收，或所有者支持的确定性证明，覆盖其控制路径、效果范围、保留和结果。只有等价分支才能依据合格证据共享证明。未接受或不可达分支作为已接受能力之外的内容报告；未证明的已接受差异分支阻止就绪。

在 writer 交接中说明证据所有者、义务处置、验收覆盖与效果、Git 保留、排除或不可达分支，以及未测试的非能力。对于尚未解决的缺口，指出阻塞项及边界、后果、保留证据、解决所有者、已尝试的发现，以及继续所需的可观察条件和权限；重要选择还应说明替代方案及后果。交接必须能由调用方独立使用。生成和下游效果仍归其所属工作流及明确授权负责。
