# Worktree 环境准备

## 目标含义

当 `setup-project-agents` 请求
`GENERATED/.agents/skills/worktree-environment-setup/SKILL.md` 时，只编写这一份归目标项目所有、
由模型调用的 Skill。它的执行者是负责准备所属工作流已准确选定的关联工作树的 Agent；触发条件是该工作树在
开始实现前需要完成仓库特定的准备。此 Skill 负责环境设置证据和仅限环境的结果。
`create-worktree` 将该结果与当前选择和工作区状态证据结合，用于判断整个工作树是否就绪；它不运行项目基线检查。
后续生命周期和收尾责任方根据当前证据重建当前状态，并在明确授权下执行影响。

目标使用 `name: worktree-environment-setup`，保持由模型调用，并在 `description` 中写明触发条件和环境结果。
将运行时判断保留在 `SKILL.md` 中；实际仓库的责任方继续负责命令、依赖清单、生成映射和服务配置。

使用已接受的项目意图，以及经目标仓库责任方及来源资质确认的证据。相关证据包括适用的 Rule 和 Skill；
清单、锁文件、工具链和运行时配置；仓库自有的设置与生成入口；CI；必需的输入和输出；不含秘密值的凭据要求；
服务生命周期声明；以及功能就绪检查。现有目标只能作为回归证据，不能作为设计权威。可见、可执行和可写
均不赋予含义或权限。

## 义务处置

- 保留最少准备、已接受的可选分支、主检出目录拒绝、功能就绪、安全重跑、部分影响恢复和有界报告。
- 将缓存的操作配方改为查询当前目标责任方，并准确绑定选定根目录。
- 将预先授权的影响范围和每次尝试后的完整清点纳入就绪判定。
- 仅为其他方式无法支持的重复确定性编排保留一项范围狭窄、归 Skill 所有的脚本例外；淘汰指定的脚本形态、
  固定等待配方和设置编写机制。
- 排除资源配置、工作树生命周期、基线或完成变更后的验证、实现、历史、集成、清理和 Agent 同步；
  完成变更后的验证仍由 `change-set-verification` 负责。

## 必需的运行时契约

### 选定目标与权限

要求提供准确的已选定根目录，以及调用方对其设置影响的权限。在修改前，证明其词法路径、实际物理根目录、
注册状态、仓库身份和 Git 公共目录；拒绝主检出目录，以及任何含糊、未注册或指向不同位置的根目录。所有命令都
必须根据目标责任方的当前证据解析，并将其工作目录或显式仓库参数绑定到该物理根目录。

根据产生影响前的基线定义**Git 保持不变量**：选定工作树的 `HEAD` 和附着状态、当前提交树以及完整索引状态
保持完全不变；处于附着状态时，其具名分支或引用及其目标也保持完全不变。不得创建提交，不得创建、删除引用，
也不得改变引用目标。任何影响发生前先捕获该基线，并在每次尝试产生影响的紧前与紧后以及最终清点时证明此不变量。

确定每个受支持的新工作树所需的最少准备，并且只采用已接受上下文选中的可选、平台或任务分支。优先使用
范围最小的当前锁定入口。如果目标责任方不支持某项必要操作，应停止，而不是虚构命令、依赖、映射、
降级结果或跨平台承诺。

每次产生影响前，冻结由责任方支持的调用和影响范围：文件系统目标、持久的 Git 公共状态变更，以及凭据访问
或服务等外部或持久影响。将调用方对每项修改的权限绑定到此工作树。权限缺失、含糊或没有责任方时，
必须在产生影响前结束。设置只能改变这些范围内已获授权的状态，并且必须保持 Git 保持不变量；
影响范围绝不授权改变受保护的 Git 身份、索引或引用状态。

### 准备与恢复

只运行已选中且有证据支持的依赖安装、输入初始化、自有生成或必需服务准备。在每次尝试前后观察工作树、
Git 公共状态和每个影响目标，包括无法执行、失败或中断的尝试。将每项差异映射到其责任方和授权；
保留部分输出和进程证据。

会终止的操作必须取得其责任方声明的成功退出结果；持久服务必须满足其声明的生命周期、存活和就绪证据。
保留长时间运行操作的进程和输出，并依据其声明的持续时间设置期限。失去控制或完成状态不确定后，检查该操作
及其影响。只有在证明操作已经结束，并且其责任方声明可以根据观察到的部分状态安全重复时，才可重试；
否则保留证据并停止。报告或等待间隔不代表进程已经完成。

根据当前功能证据，确认必需配置、输出、工具和服务均已就绪。只有责任方将版本探测声明为就绪检查时，
版本探测才足够。最后完成清点，证明每项影响都位于其影响范围内、每个已选分支的就绪条件均已满足，
并且 Git 保持不变量成立。

### 可观察结果与退出

只返回一个结果；首个匹配的判别条件具有决定权，并结束本次运行：

1. 当目标身份或绑定无效；必需的证据、输入、命令、权限或就绪状态缺失或含糊；操作在获授权恢复后仍然失败、
   中断或完成状态不确定；出现意外或超出范围的影响；Git 保持不变量失效，即使该影响位于已授权范围内；
   或者最终清点不完整时，返回 `environment-non-ready`。
2. 当所有必需准备均已满足或成功完成，包括任何获授权的恢复；每个已选可选分支均已满足；每项实际影响均已
   授权且位于范围内；每项功能就绪检查均通过；并且 Git 保持不变量成立时，返回 `environment-ready`。

报告根目录；准备工作和可选分支的处置；调用及结果；影响；就绪证据；Git 保持判定；以及留给其他责任方的工作。
`environment-non-ready` 还要报告阻碍、保留的部分状态、恢复条件，以及何时可以安全地开始全新调用。任一结果
返回后，已完成变更的验证和后续生命周期操作仍由其所属工作流在明确授权下负责。`environment-ready` 是
提供给 `create-worktree` 的当前设置证据；后者将其与其他当前证据结合，并返回即时就绪结果。

## 未来 Author 的授权与验证

未来 Author 可以检查符合资质的目标证据，运行目标责任方支持的只读或非修复性检查，并且只能创建或替换
`GENERATED/.agents/skills/worktree-environment-setup/SKILL.md`。如果符合资质的目标证据证明必要的重复
确定性编排没有可靠的仓库自有入口，则只有对每项脚本字段均有授权的责任方所提供的已接受输入，才能授予这项
狭窄例外。任何写入发生前，该输入必须无歧义地指定授权责任方；Skill 的 `scripts/` 目录下的每个准确路径及其
`create` 或 `replace` 操作；目标确定的运行时；输入；输出；完整影响范围；必需的验证；以及包括保留、更新和
移除责任在内的生命周期。未来 Author 只能使用该授权，不得推断、补充或扩大授权。字段缺失、含糊、未经授权
或与证据不符时，必须以适用的 `ACCESS_REQUIRED`、`CONTEXT_REQUIRED` 或
`HUMAN_DECISION_REQUIRED` 交接结束。此类最小脚本只负责确定性排序，不作任何判断；`SKILL.md` 继续负责
调用、前置条件、分支、就绪、恢复和结果。没有另行接受的授权时，不得创建其他支持资源、执行其他脚本操作、
删除或移动 Candidate、写入实际目标、修改无关状态或造成外部影响。

将 Machine、Review 和 Acceptance 证据绑定到全部 Candidate 文件的同一个不可变指纹；任何变更都会使三者
全部失效。首先通过责任方支持的每项适用、确定性、非修复性 Machine 检查。只有符合资质的责任方证据确认没有
适用的 Machine 检查时，才可记录 `NOT_REQUIRED`；它不能替代适用检查，也不能替代适用检查的失败。随后为
完整 Candidate 取得 Quality 和 Correctness Review 的 `PASS`：Quality 覆盖精简性、层次结构、调用和完成
边界；Correctness 覆盖目标绑定、命令及任何脚本、影响、可选分支、恢复、结果、保持不变量和所有权。
任一前置条件缺失或未通过时，不得开始 Acceptance。

只有越过这一屏障后，Acceptance 才可以执行 Candidate。每次产生影响的调用都需要一项独立的已接受授权，
其中指定其根目录和影响范围。在一个具有代表性且已经创建的关联工作树中，演练默认路径，证明主检出目录在
修改前即被拒绝，并确定环境结果。记录指纹、调用、影响前基线、最终 Git 保持证明、影响、功能证据和停止证据。

每个具有实质不同的行为、影响或风险的已接受可选分支，都需要自己的 Acceptance，或者由责任方支持的确定性
证明，用以证明其独特控制路径、影响范围、保持不变量和结果。只有对等价分支，符合资质的证据才可共享同一份证明。
未接受或无法到达的分支无需演练，应报告在已接受能力之外。已接受且实质不同的分支如果未经证明，
验证即失败，并阻止 `READY` 编写结果。

只返回一个编写结果；首个匹配的判别条件优先：

1. 必要证据或验证在授权范围内无法访问时，返回 `ACCESS_REQUIRED`。
2. 能够访问，但无法从符合资质的证据中发现必要事实时，返回 `CONTEXT_REQUIRED`。
3. 符合资质的证据允许实质不同的语义，或者必需的责任方、权限、影响、例外或淘汰事项缺少已接受的授权时，
   返回 `HUMAN_DECISION_REQUIRED`。
4. Machine 检查或 Review 未通过、Acceptance 失败、任何已接受且实质不同的可选分支缺少充分证明、
   任何影响未被清点、Git 保持不变量失效，或者任何受支持的运行时输入不能恰好得到一个可观察结果时，
   返回 `VALIDATION_FAILED`。
5. 唯一 Candidate 包含所有必需义务、每个受支持的运行时输入都选择且仅选择一个可观察环境结果、Machine 和
   两项 Review 门槛均通过，并且 Acceptance 在准确授权下证明每项必需的已接受能力时，返回 `READY`。

每个非 `READY` 结果都会结束当前运行。其交接要报告准确的阻碍和边界、后果、保留的证据、解决责任方、
可观察的重试谓词，以及在全新运行中重试所需的准确权限。此外：

- `ACCESS_REQUIRED` 指明缺失的访问、获授权的发现或验证为何无法取得该访问、谁能授予该访问，
  以及全新运行所需的准确访问和重试权限。
- `CONTEXT_REQUIRED` 指明缺失的事实、已尝试的获授权发现，以及尽管具有访问权限仍无法发现该事实的原因、
  事实责任方，以及全新运行所需的准确合格事实和重试权限。
- `HUMAN_DECISION_REQUIRED` 指明决策责任方、现有选择、每项选择的证据和后果，
  以及全新运行所需的已接受选择和权限。

`READY` 报告 Candidate 指纹、证据责任方、义务处置、Machine 和 Review 决定、Acceptance 覆盖范围和影响、
Git 保持判定、已排除或无法到达的分支，以及未经测试的非能力。它是 `setup-project-agents` 的就绪输入；
生成及后续影响仍由其所属工作流在明确授权下负责。
