# 工作树环境准备

## 目的与证据

当 `setup-project-agents` 请求生成 `.agents/skills/worktree-environment-setup/SKILL.md` 时，Author 编写一份归目标仓库所有、由模型调用的 Skill，供 Agent 准备所属工作流已经选定的确切 linked worktree。它提供仓库特定的环境准备和仅针对环境的结果。`create-worktree` 将此证据与当前选择及工作空间状态结合，判断即时就绪；它不运行项目基线检查。后续生命周期所有者重建当前状态，并在自身明确授权下行动。

使用 `name: worktree-environment-setup`，保持模型调用启用，并在 `description` 中表达准备触发条件和环境结果。`SKILL.md` 负责运行时判断；仓库所有者保留命令、依赖清单、生成映射和服务配置。

Setup 必须提供相关目标证据：Rules 和 Skills、清单和锁文件、工具链与运行时配置、所属 setup 和生成入口、CI、必要输入输出、不含秘密值的凭据要求、服务生命周期，以及功能性就绪检查。按所有者和来源评定资料。既有文本是回归证据，不是设计权威；可见性、可执行性和写入访问权限不授予权威。

保留最小准备、已接受可选分支、主检出拒绝、功能性就绪、安全重跑、部分效果恢复和有界报告。以当前所有者查找和确切根目录绑定替换缓存步骤；要求事先授权的效果范围和完整尝试后核查。保留下述狭窄脚本例外，同时停用指定脚本形态、固定等待和 setup 编写机制。资源置备、工作树生命周期、基线或完整变更验证、实现、历史、集成、清理和 Agent 同步均为非目标；`change-set-verification` 负责完整变更验证。

## 环境契约

### 身份与保留

选定根目录和调用方对 setup 效果的权限是前提。变更前证明字面路径、实际物理根目录、注册状态、仓库身份和 Git 公共目录。拒绝主检出以及含糊、未注册或不同的根目录。从当前目标所有者证据解析命令，将其工作目录或显式仓库参数绑定到该物理根目录。

**Git 保留不变量**保护效果前的 `HEAD`、附着状态、当前提交树和完整索引状态；附着分支的名称／ref 及指向也必须保持完全一致。不创建提交，不创建、删除或改变任何 ref 的指向。任何效果前捕获基线，在每次尝试效果的紧邻前后及最终核查时证明该不变量。效果范围不能授权改变受保护 Git 状态。

### 准备与效果

确立每个受支持新工作树所需的最小准备，并仅纳入已接受上下文选定的可选、平台或任务分支。优先使用当前最窄的锁定入口。必要操作缺少目标所有者支持时必须停止，不能自行发明命令、依赖、映射、降级结果或平台承诺。

每项效果前，冻结其所有者支持调用和**效果范围**：文件系统目标、持久 Git 公共状态变更，以及外部或持久效果，包括凭据访问和服务。将调用方对每项变更的权限绑定到此工作树。权限缺失、含糊或无归属时，在效果前停止；准备只能改变效果范围内获准的状态，同时保留 Git 不变量。

允许的准备包括选定且有证据支持的依赖安装、输入初始化、所属生成和必要服务。每次尝试前后均核查工作树、Git 公共状态和每个效果目标，包括不可用、失败和中断的尝试。将每个差异归属到其所有者和授权，并保留部分输出和进程证据。

会终止的操作需要所有者声明的成功退出；持久服务需要其声明的生命周期、存活和就绪证据。长时间运行的操作保留其进程和输出，截止时间以声明时长为依据。失去控制或无法确定是否完成时，需要观察原操作及其效果。只有操作已结束，且其所有者支持从观察到的部分状态重复执行时，才可重试；否则保留证据并停止。等待和报告间隔不能证明完成。

就绪要求必要配置、输出、工具和服务的当前功能证据。只有所有者将版本探测声明为就绪检查时，它才足够。最终核查证明每项效果均在范围内、每个选定分支均已就绪，且 Git 状态得到保留。

### 结果与交接

首个适用条件决定唯一环境结果并结束运行：

| 结果 | 判别条件 |
| --- | --- |
| `environment-non-ready` | 身份或绑定无效；必要证据、输入、命令、权限或就绪缺失或含糊；获准恢复后操作仍失败、中断或不确定；出现意外或越界效果；即使在效果范围内 Git 保留仍失败；或最终核查不完整。 |
| `environment-ready` | 必要准备已满足或已完成，包括获准恢复；每个选定可选分支均满足要求，每项效果均获准且在范围内，功能性就绪通过，且 Git 状态得到保留。 |

报告根目录、准备和可选分支处置、调用与结果、效果、就绪证据、Git 保留结论，以及其他所有者保留的工作。非就绪结果还说明阻塞项、保留的部分状态、恢复条件，以及何时可以安全发起新调用。就绪结果是提供给 `create-worktree` 的当前环境证据，不是完整变更验证，也不授权后续生命周期效果。

## Author 边界

Author 可以查看合格目标证据，运行所有者支持的只读或非修复检查，并在 setup 的请求根目录下创建或替换 `GENERATED/.agents/skills/worktree-environment-setup/SKILL.md`。除这里描述的狭窄脚本授权外，支持资源、脚本操作、Candidate 删除或移动、实际目标写入、无关变更和外部效果都需要单独的已接受授权。

仅当合格目标证据证明必要的重复确定性编排缺少可靠的仓库所属入口时，才允许 Skill 所属脚本。任何写入前，来自对每个字段均有授权权力的所有者的已接受输入，必须指定授权所有者；Skill 的 `scripts/` 目录下每个确切路径及其 `create` 或 `replace` 操作；目标已确立的运行时；输入输出；完整效果范围；必要验证；以及保留、更新和移除所有权。Author 只使用该授权，不推断、补充或扩大它。字段缺失、含糊、未获授权或与证据不匹配时，产生下述适用的访问、上下文或决策停止结果。

使用能提供所需确定性顺序的最小脚本。调用、前提、分支、就绪、恢复和结果仍作为判断保留在 `SKILL.md` 中。

## 编写证据与结果

机器、审阅和 Acceptance 证据绑定到每个 Candidate 文件的同一个不可变指纹；Candidate 变化使三者全部失效。机器证据要求每项适用、由所有者支持的确定性非修复检查。只有合格所有者证据证明没有检查适用时，`NOT_REQUIRED` 才有效；它不能替代适用检查或其失败。

质量审阅覆盖精简程度、层次、调用和完成边界。正确性审阅覆盖目标绑定、命令和脚本、效果、可选分支、恢复、结果、保留和所有权。Acceptance 要求完整 Candidate 的机器检查成功，且两项审阅均为 PASS。

每次产生效果的 Acceptance 调用都需要单独的已接受授权，指明根目录和效果范围。在一个具有代表性、已经创建的 linked worktree 中，Acceptance 执行默认路径，证明变更前拒绝主检出，并确立环境结果。记录指纹、调用、效果前基线、最终 Git 保留证明、效果、功能证据和停止证据。

每个在行为、效果或风险上具有实质差异的已接受可选分支，都需要自己的 Acceptance，或所有者支持的确定性证明，覆盖其控制路径、效果范围、保留和结果。只有等价分支才能依据合格证据共享证明。未接受或不可达分支作为已接受能力之外的内容报告；未证明的已接受差异分支阻止就绪。

首个适用条件决定唯一的编写结果：

| 结果 | 判别条件 |
| --- | --- |
| `ACCESS_REQUIRED` | 必要证据或验证在授权范围内无法访问。 |
| `CONTEXT_REQUIRED` | 已有访问权限，但无法从合格证据中发现必要事实。 |
| `HUMAN_DECISION_REQUIRED` | 仍存在实质性语义分歧，或必要的所有者、权限、效果、例外或停用缺少已接受授权。 |
| `VALIDATION_FAILED` | 机器检查或审阅为非 PASS、Acceptance 失败、已接受差异分支缺少证明、效果未核对、Git 保留失败，或受支持运行时输入未恰好对应一个结果。 |
| `READY` | 每项义务均已具备，每个受支持运行时输入恰好选出一个环境结果，机器和两项审阅关口均通过，且 Acceptance 在确切权限下证明每项必要的已接受能力。 |

每次停止都结束运行，并指出阻塞项及边界、后果、保留证据、解决所有者、可观察重试条件，以及新运行的确切权限。访问停止还说明获准探索或验证为何未能取得访问权限，以及谁可授予权限。上下文停止说明缺失事实及其所有者、已尝试的探索，以及为何已有访问权限仍无法发现该事实。决策停止说明所有者、当前选择、证据和后果；恢复需要已接受的选择和权限。

就绪交接报告 Candidate 指纹、证据所有者、义务处置、机器和审阅决策、Acceptance 覆盖与效果、Git 保留结论、排除或不可达分支，以及未测试的非能力。它是 `setup-project-agents` 的输入；生成和下游效果仍归其所属工作流及明确授权负责。
