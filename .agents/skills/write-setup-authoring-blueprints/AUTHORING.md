# Authoring Decisions

## Blueprint content directs judgment; runtime owns execution

A blueprint must tell a future Author what evidence and distinctions matter without becoming a second scheduling or retry protocol. Keeping future-target procedures separate from authoring invocation mechanics preserves the public writer's authority and lets different project evidence produce different valid documents.

## Refresh facts and durable intent differently

Tool mappings can become wrong while a project's accepted process remains sound. One blanket rewrite-or-preserve rule would either retain stale facts or erase valid decisions. Explicit content-sensitive refresh preferences protect both accuracy and project ownership.

## An incomplete handoff can still permit discovery

The future Author is responsible for finding and qualifying recoverable project evidence within granted access. Treating every absent supplied fact as a stop would turn useful investigation into repeated user questions; unsupported material facts after that discovery remain genuine stopping conditions.
