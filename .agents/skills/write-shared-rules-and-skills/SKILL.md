# Write Shared Rules and Skills

Qualify one portable cross-project SmartKit Rule or Skill, then author it through the public
[`write-rules-and-skills`](../../../skills/write-rules-and-skills/SKILL.md) workflow. This Skill
owns only the portability delta. Read
[`references/portability.md`](references/portability.md) completely when qualifying the request.

## Qualify and close the shared input

Resolve the artifact owner before assessing portability. Follow the reference's terminal route for
every project-local, Setup, split, environment-owned, nonshared, or ambiguous request. Continue
only when one cross-project SmartKit Rule or Skill has supported ownership and provenance.

Build one closed task/spec input containing the accepted portable meaning, Candidate surface,
qualified evidence, complete dependency routes, representative seams and targets, accepted
permissions and effects under the public workflow's grant model, validation duties, and completion
conditions. Facts derived from representative targets count as evidence only after qualification.
The target resources may be read or used in public Acceptance only under separately accepted
permissions and never receive Candidate mutation authority. If any material choice remains open,
return the public `ALIGNMENT_REQUIRED` payload before invoking the public workflow.

**Complete when:** every portability obligation has an accepted answer, evidence qualification,
pass condition, and authorized route.

## Invoke the public workflow unchanged

Supply the closed shared input unchanged as ordinary accepted task/spec input at the public
workflow's entry. The public workflow exclusively owns its Candidate model, freeze and
fingerprints, runtime and roles, evidence selection, proof stages, correction, exits, and
finalization. This Skill adds none of those mechanisms and preserves every public terminal result
unchanged.

For a self-hosting change to this Skill, the frozen pre-Author public and private contracts remain
authoritative for the entire run; edited bytes take effect only in a later invocation.

**Complete when:** the public workflow returns its handoff or terminal result.

## Project portable success

Apply the reference's final-fingerprint closure test without reinterpreting any public verdict.
Portable success requires both public success and current closure of every portability obligation
against the public workflow's final Candidate fingerprint. Preserve the public handoff and add the
closure account or, when incomplete, the uncovered obligations and missing evidence.

Keep qualification and coverage evidence transient. This Skill grants no publication,
installation, commit, push, release, or other downstream effect.

**Complete when:** the public result is preserved and every portability obligation is accounted
for at handoff.
